# Gately: техническое решение и дорожная карта

## Цель

Открытый, поддающийся аудиту инструмент сетевого шлюза, развиваемый сообществом: он покрывает самые востребованные у пользователей домашних сетей, NAS и серверов функции — DDNS, STUN-обход NAT, проброс портов, обратный прокси, управление сертификатами — и умеет импортировать существующие конфигурации Lucky.

Принципы проектирования:

1. **Прозрачность**: по умолчанию никаких подключений к серверам проекта; все внешние адреса видны, изменяемы и отключаемы.
2. **Переносимость**: импорт конфигураций Lucky `.lkcf`.
3. **Проверяемая конфигурация**: конфигурация хранится в открытом JSON (права на файл 0600) и может напрямую храниться в git для сравнения и отката.
4. **Развёртывание одним файлом**: один статический бинарный файл со встроенным фронтендом, поддержка Docker, systemd и OpenWrt; необязательные модули и языки интерфейса можно исключить при компиляции и получить более компактную пользовательскую сборку.

## Технологический стек

| Уровень | Выбор | Обоснование |
| --- | --- | --- |
| Бэкенд | Go 1.26+ | Можно напрямую использовать зрелые библиотеки: lego, pion/stun, frp, cloudflared, coraza, rclone и другие; статическая компиляция, кросс-компиляция под маршрутизаторы и NAS на arm/arm64/mips/riscv |
| HTTP | Стандартная библиотека `net/http` (синтаксис маршрутов Go 1.22) | Минимум зависимостей, проще аудит |
| Хранение | Один открытый JSON-файл на модуль, атомарная запись | Удобно импортировать, делать резервные копии и сравнивать через git diff |
| Аутентификация | Пароли bcrypt + сеансовые токены с подписью HMAC, ограничение неудачных попыток входа, двухэтапная проверка TOTP и Passkey | Без внешних зависимостей |
| Журналы | Кольцевой буфер в памяти для каждого модуля + пакетная запись в файлы JSON Lines (ротация по размеру, восстановление после перезапуска; журналы веб-доступа ежедневно архивируются со сжатием) + интерфейс инкрементального получения | Простой интерфейс опроса журналов, инкрементальное обновление во фронтенде |
| Фронтенд | Vue 3 + TypeScript + Vite + Element Plus, упаковка через `go:embed` | Богатый набор компонентов, высокая скорость разработки |
| Выпуск | Бинарные файлы GoReleaser для нескольких архитектур + мультиархитектурные Docker-образы | — |

## Структура каталогов

```
cmd/gately/            Точка входа программы
internal/app/          Сборка: загрузка конфигурации, запуск модулей, HTTP-сервис
internal/config/       Модульное хранилище конфигурации в JSON
internal/auth/         Аутентификация администратора и сеансы
internal/logbuf/       Кольцевой буфер журналов модулей
internal/httpx/        HTTP-утилиты и промежуточное ПО
internal/module/       Интерфейс модуля и реестр
internal/modules/*/    Функциональные модули
internal/modules/registry/  Регистрация модулей: у каждого необязательного модуля свой mod_<модуль>.go (build-тег no_<модуль>), межмодульные возможности предоставляются через внедрение
tools/custombuild/     Пользовательская сборка: по modules.json вычисляет build-теги, языки и аргументы сборки Docker и упаковывает
modules.json           Необязательные модули, зависимости, оценка размера, уровни языков, цели сборки и пресеты (читается build.gately.cn)
internal/luckyimport/  Расшифровка Lucky .lkcf и сопоставление полей
web/                   Проект фронтенда, результат сборки встраивается через web/embed.go
```

## Проектные решения

- Онлайн-обновление доступно только для бинарных установок Linux и запускается только администратором вручную: после загрузки SHA-256 сверяется с checksums.txt, новая программа проходит пробный запуск, а при замене сохраняется старая версия; Docker, fnOS и пакеты OpenWrt по-прежнему обновляются через образ, центр приложений и менеджер пакетов. Пользовательские сборки не обновляются онлайн (это вернуло бы полную версию): соберите их заново на build.gately.cn с теми же параметрами и загрузите пакет обновления.
- Никакой удалённой рассылки конфигурации и никакой передачи сведений об устройстве.
- Конфигурация хранится в открытом виде; чувствительные поля маскируются в ответах API.
