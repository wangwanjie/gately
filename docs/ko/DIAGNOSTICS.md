# 진단 패키지

Gately에 문제가 생기면 **설정 → 진단**에서 진단 패키지를 내보내 [GitHub issue](https://github.com/wangwanjie/gately/issues/new)에 첨부하세요. 관리자가 스크린샷이나 복사한 로그를 따로 요청하지 않고도 원인을 찾을 수 있습니다.

진단 패키지는 사용자 자신의 기기에서 생성되며 어디에도 업로드되지 않습니다. 내려받기 전에 **내용 미리 보기**를 누르면 내보낼 내용을 정확히 확인할 수 있습니다. zip에는 일반 텍스트와 JSON만 들어 있으므로 압축을 풀어 파일을 하나하나 검토할 수도 있습니다.

## 내보내는 내용

| 파일 | 내용 |
| --- | --- |
| `README.txt` | 진단 패키지 설명(중국어·영어 병기) |
| `summary.json` | Gately 버전과 빌드 정보, OS와 아키텍처, CPU 모델과 코어 수, 메모리 / 디스크 용량, 가동 시간, Go 런타임 통계, 관리 UI 포트 번호, 네트워크 인터페이스 **이름**과 주소 **분류**(예: `private: 1, public: 2`) |
| `modules.json` | 모듈 목록과 개요 페이지에 표시되는 상태 요약 |
| `config/*.json` | 설정 **구조**: 필드 이름, 숫자, 스위치, 프로토콜·모드 같은 열거 값 |
| `logs/*.log` | 시스템과 각 모듈의 최근 실행 로그, 재시작 전에 디스크에 저장된 부분 포함(끌 수 있음) |
| `logs/crash.log` | 비정상 종료 기록: Go 런타임 충돌(panic, fatal error)의 메시지와 스택, 프로세스가 강제 종료된(예: 메모리 부족으로 OOM) 대략적인 시각. 비정상 종료가 있었을 때만 포함(끌 수 있음) |

## 절대 내보내지 않는 내용

- 비밀번호, 비밀번호 해시, API 토큰, TOTP 시크릿, 세션 키, OAuth 클라이언트 시크릿, DNS 제공자 키, SSH 비밀번호와 개인 키, 인증서와 개인 키. `account.json`과 `tokens.json`은 아예 읽지 않습니다.
- 도메인, 호스트 이름, 실제 IP 주소와 MAC 주소. `<domain>`, `<ipv4:private>`, `<ipv4:public>`, `<mac>` 같은 자리 표시자로 바뀌며 포트는 유지됩니다.
- 설정 디렉터리 경로와 홈 디렉터리(`<config-dir>`, `<home>`으로 대체).
- 설정에 직접 입력한 이름, 메모 등의 텍스트: 알려진 열거 값이 아닌 문자열은 모두 `<redacted>`로 바뀝니다.
- 파일 내용, Docker 컨테이너·이미지·환경 변수, 터미널 세션, 트래픽 내용.

## 마스킹 방식

- **설정**: 기본적으로 값을 모두 제거합니다. 필드 이름, 숫자, 불리언, 정해진 열거 필드(`protocol`, `mode`, `provider` 등), 타임스탬프만 남습니다. 주소 필드는 포트와 IP 분류만 남깁니다.
- **로그**: IP 주소, 도메인, 이메일, URL, `password=…` 형식의 키-값, `Bearer` 토큰, 토큰처럼 보이는 긴 문자열, MAC 주소, 사용자 디렉터리를 마스킹합니다. `github.com`, `letsencrypt.org` 같은 공용 서비스 도메인은 장애가 네트워크 문제인지 판단하는 데 필요하므로 유지합니다.
- 직접 입력한 이름(예: 규칙 메모)이 IP나 도메인처럼 보이지 않으면 로그 줄에 그대로 남을 수 있습니다. 게시하기 전에 `logs/*.log`를 훑어보고 공유하고 싶지 않은 내용은 지우세요.

## 비정상 종료 조사

Gately는 실행 중 충돌 정보를 설정 디렉터리의 `crash.log`에 기록합니다. 프로세스가 예기치 않게 종료되면 다음 시작 시 시스템 로그에 지난 실행이 충돌로 종료되었는지 강제 종료되었는지 표시됩니다.

- **충돌 종료**: `crash.log`에 원인과 모든 고루틴의 스택이 있습니다. 진단 패키지를 내보내 issue에 첨부하세요. `concurrent map writes` 같은 치명적 오류의 `fatal error: …` 줄은 Go가 표준 오류에만 출력하므로 `docker logs`에서 확인할 수 있습니다.
- **예기치 않은 종료**: 프로세스가 아무 정보도 남기지 않았습니다. 보통 메모리 부족으로 시스템이 종료했거나(OOM), `kill -9` / `docker kill`로 종료되었거나 정전입니다. 호스트에서 `dmesg -T | grep -i -E "oom|killed process"`로 OOM 여부를 확인할 수 있습니다.

## API

`GET /api/system/diagnostics`(로그인 세션 전용, API 토큰은 거부됨). `?logs=0`이면 로그를 제외하고 `?preview=1`이면 파일을 JSON으로 반환합니다.
