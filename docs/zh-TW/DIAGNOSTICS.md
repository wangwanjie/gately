# 診斷包

遇到問題時，在 **設定 → 診斷** 中匯出診斷包，附在 [GitHub issue](https://github.com/wangwanjie/gately/issues/new) 裡，維護者就能直接找出原因，不必再向你索取截圖和日誌。

診斷包在你自己的機器上產生，不會上傳到任何地方。下載前點擊 **預覽內容**，可以看到將要匯出的全部檔案；zip 內只有純文字和 JSON，解壓縮後也能逐一檢查。

## 會匯出什麼

| 檔案 | 內容 |
| --- | --- |
| `README.txt` | 診斷包說明（中英對照） |
| `summary.json` | Gately 版本與建置資訊、系統與架構、CPU 型號與核心數、記憶體與磁碟容量、執行時間、Go 執行階段統計、管理介面連接埠、網路介面**名稱**及其位址**類別**（如 `private: 1, public: 2`） |
| `modules.json` | 模組清單與總覽頁的狀態摘要 |
| `config/*.json` | 設定的**結構**：欄位名稱、數字、開關，以及協定、模式等列舉值 |
| `logs/*.log` | 系統與各模組最近的執行日誌，包括重新啟動前已落盤的部分（可在匯出時關閉） |
| `logs/crash.log` | 異常結束紀錄：Go 執行階段當機（panic、fatal error）的資訊與堆疊，以及處理程序被強制結束（如記憶體不足被 OOM 終止）的大致時間；只有發生過異常結束才有（可在匯出時關閉） |

## 絕不會匯出什麼

- 密碼、密碼雜湊、API 權杖、兩步驟驗證金鑰、工作階段金鑰、OAuth 金鑰、DNS 服務商金鑰、SSH 密碼與私鑰、憑證與私鑰。`account.json` 與 `tokens.json` 不會被讀取。
- 網域、主機名稱、真實 IP 與 MAC 位址，統一替換為 `<domain>`、`<ipv4:private>`、`<ipv4:public>`、`<mac>` 等預留位置，連接埠予以保留。
- 設定目錄與使用者家目錄的路徑（替換為 `<config-dir>`、`<home>`）。
- 你在設定裡填寫的名稱、備註等文字：凡不是已知列舉值的字串，一律替換為 `<redacted>`。
- 檔案內容、Docker 容器 / 映像檔 / 環境變數、終端機工作階段與流量內容。

## 遮蔽方式

- **設定**：預設移除所有取值，只保留欄位名稱、數字、開關、固定的列舉欄位（`protocol`、`mode`、`provider` 等）與時間戳記。位址類欄位只保留連接埠和 IP 類別。
- **日誌**：替換 IP、網域、電子郵件、URL、`password=…` 形式的鍵值、`Bearer` 權杖、疑似金鑰的長字串、MAC 位址與使用者目錄。`github.com`、`letsencrypt.org` 等公共服務網域予以保留，用來判斷故障是否為網路問題。
- 你自行填寫的名稱（如規則備註）若出現在日誌裡，且不像 IP 或網域，仍可能留在日誌行中。發布前請快速瀏覽 `logs/*.log`，刪掉不想公開的內容。

## 排查異常結束

Gately 執行時會把當機資訊寫進設定目錄的 `crash.log`。處理程序意外結束後，下次啟動時系統日誌會出現一條提示，說明上次是當機結束還是被強制結束：

- **當機結束**：`crash.log` 中有當機原因與各協程堆疊，匯出診斷包附在 issue 裡即可。`concurrent map writes` 這類致命錯誤的 `fatal error: …` 一行 Go 只輸出到標準錯誤，可在 `docker logs` 中查看。
- **意外結束**：處理程序沒有留下任何資訊，通常是記憶體不足被系統終止（OOM）、被 `kill -9` / `docker kill` 結束或斷電。可以在主機上用 `dmesg -T | grep -i -E "oom|killed process"` 確認是否為 OOM。

## 介面

`GET /api/system/diagnostics`，僅登入工作階段可用，API 權杖無權存取。`?logs=0` 不含日誌，`?preview=1` 以 JSON 回傳各檔案內容。
