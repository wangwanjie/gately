# Gately 技術設計とロードマップ

## 目標

オープンソースで監査可能、コミュニティ主導のネットワークゲートウェイツールを作ります。家庭内ネットワーク、NAS、サーバーのユーザーが最もよく使う DDNS、STUN 穿孔、ポート転送、リバースプロキシ、証明書管理をカバーし、既存の Lucky 設定のインポートにも対応します。

設計原則：

1. **透明性**：デフォルトではプロジェクト運営側のサーバーに一切接続しません。外部へのアドレスはすべて確認・変更・無効化できます。
2. **移行しやすさ**：Lucky `.lkcf` 設定のインポートを提供します。
3. **監査可能な設定**：設定は平文の JSON（ファイル権限 0600）で、そのまま git に入れて diff やロールバックができます。
4. **単一ファイルでのデプロイ**：フロントエンドを内蔵した 1 つの静的バイナリで、Docker、systemd、OpenWrt に対応します。オプションのモジュールと画面の言語はコンパイル時に取り除け、より小さなカスタムビルドを生成できます。

## 技術スタック

| 層 | 採用技術 | 理由 |
| --- | --- | --- |
| バックエンド | Go 1.26+ | lego、pion/stun、frp、cloudflared、coraza、rclone などの成熟したライブラリをそのまま再利用できる。静的ビルドで arm/arm64/mips/riscv のルーターや NAS 向けにクロスコンパイルできる |
| HTTP | 標準ライブラリ `net/http`（Go 1.22 のルーティング構文） | 依存が最小で監査しやすい |
| ストレージ | モジュールごとに 1 つの平文 JSON ファイル、アトミック書き込み | インポート、バックアップ、git diff がしやすい |
| 認証 | bcrypt パスワード + HMAC 署名付きセッショントークン、ログイン失敗のレート制限、TOTP による 2 段階認証と Passkey | 外部依存なし |
| ログ | モジュールごとのメモリ内リングバッファ + JSON Lines ファイルへのまとめ書き（サイズでローテーション、再起動後に復元。Web アクセスログは日ごとに圧縮アーカイブ）+ 差分取得 API | ログのポーリング API がシンプルで、フロントエンドは差分更新 |
| フロントエンド | Vue 3 + TypeScript + Vite + Element Plus、`go:embed` で同梱 | コンポーネントが豊富で開発効率が高い |
| リリース | GoReleaser によるマルチアーキテクチャバイナリ + マルチアーキテクチャ Docker イメージ | — |

## ディレクトリ構成

```
cmd/gately/            プログラムのエントリポイント
internal/app/          組み立て：設定の読み込み、モジュールの起動、HTTP サーバー
internal/config/       モジュール単位の JSON 設定ストレージ
internal/auth/         管理者認証とセッション
internal/logbuf/       モジュールログのリングバッファ
internal/httpx/        HTTP ユーティリティとミドルウェア
internal/module/       モジュールインターフェースとレジストリ
internal/modules/*/    各機能モジュール
internal/modules/registry/  モジュール登録：オプションのモジュールごとに mod_<モジュール>.go（ビルドタグ no_<モジュール>）、モジュール間の機能は注入で提供
tools/custombuild/     カスタムビルド：modules.json に従ってビルドタグ、言語、Docker のビルド引数を換算してパッケージ化
modules.json           オプションのモジュール、依存関係、サイズ見積もり、言語レベル、ビルドターゲットとプリセット（build.gately.cn が読み込む）
internal/luckyimport/  Lucky .lkcf の復号とフィールドマッピング
web/                   フロントエンドプロジェクト、ビルド成果物は web/embed.go で埋め込み
```

ユーザーの実際の利用規模の順に並べています（STUN 18、ポート転送 25、リバースプロキシ 27、証明書 5、DDNS 75 件のレコード）。

| フェーズ | 内容 | 受け入れ基準 |
| --- | --- | --- |
| ✅ **M0 骨組み** | 設定ストレージ、管理者ログイン、モジュールフレームワーク、ログバッファ、管理 UI の外枠、Dockerfile | ログイン後に概要とモジュールメニューが表示される |
| ✅ **M1 ポート転送** | TCP/UDP、v4/v6、複数ポートとポート範囲、複数ターゲット、接続数制限、起動・停止とログ。Lucky のポート転送ルールのインポート | ユニットテストで TCP/UDP 転送をカバー。実サンプルの 25/25 件がインポートに成功 |

| ✅ **M3 STUN 穿孔** | STUN によるパブリックマッピングの取得、TCP キープアライブ、UPnP/NAT-PMP、内蔵フォワーディング、Webhook とスクリプト変数。インポート | ローカルでのエンドツーエンドテスト + 家庭内ネットワークでの実際の穿孔。実サンプルの 18/18 件がインポートに成功 |

## 設計上のトレードオフ

- オンラインアップグレードは Linux バイナリでのデプロイにのみ提供し、管理者が手動で実行した場合に限ります。ダウンロード後に checksums.txt の SHA-256 と照合して新しいプログラムを試験実行し、置き換え時には旧バージョンを残します。Docker、fnOS、OpenWrt パッケージのアップグレードは、引き続きイメージ、アプリセンター、パッケージマネージャーが担います。カスタムビルドにはオンラインアップグレードがなく（完全版に戻ってしまうため）、build.gately.cn で同じオプションのまま生成し直してアップグレードパッケージをアップロードします。
- リモートからの設定配信やデバイス情報の送信は行いません。
- 設定は平文で保存し、機密フィールドは API の出力でマスクします。
