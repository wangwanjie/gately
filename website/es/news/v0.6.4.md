# Gately v0.6.4 publicado

3 de noviembre de 2026

[Descargar v0.6.4](/es/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4) · [Compilación personalizada en línea](https://build.gately.cn)

## Compilación personalizada

Salvo los tres módulos principales (Reenvío de puertos, Servicios web y Certificados SSL), los otros 22 módulos pueden quitarse al compilar, y los idiomas de la interfaz pueden reducirse a chino simplificado, o a chino simplificado, chino tradicional e inglés:

- Abra [build.gately.cn](https://build.gately.cn), marque los módulos e idiomas (o parta de los preajustes "Core only", "Router" o "NAS"); la página estima el tamaño al momento y genera en línea binarios para Linux / Windows / macOS / FreeBSD, paquetes para OpenWrt y fnOS, o una imagen Docker multiarquitectura para amd64, arm64 y arm/v7; los artefactos con las mismas opciones se reutilizan sin volver a compilar;
- En linux/arm64, por ejemplo: la edición completa ocupa 33,6 MB, solo el núcleo unos 19,9 MB y el preajuste Router con chino simplificado unos 21,2 MB; la imagen Docker del preajuste Router con chino simplificado descarga unos 18,7 MB (imagen completa: 51,9 MB), y una imagen sin la gestión de Docker no incluye docker-cli ni compose, y una sin la Prevención de intrusiones ni STUN no incluye nftables;
- Para los módulos no compilados, los archivos de configuración se conservan intactos, sus interruptores en Ajustes y los permisos de los tokens de API siguen siendo válidos, sus API responden 404 indicando que el módulo no está incluido en esta compilación y la interfaz oculta sus páginas y opciones; al volver a la edición completa todo se recupera;
- La página Acerca de enumera los módulos que faltan en esta compilación, con un enlace que abre el generador con las mismas opciones. Las compilaciones personalizadas no ofrecen actualización en línea (esta descarga la edición completa); cuando salga una nueva versión, vuelva a generarla con las mismas opciones y use "Subir paquete de actualización";
- Para compilar por su cuenta, use las build tags `no_<módulo>` y `lang_zh` / `lang_cjken`, `GATELY_LOCALES` para el frontend o argumentos de compilación del Dockerfile como `GATELY_TAGS`; `tools/custombuild` traduce una selección a estos parámetros.

Consulte [Resumen de módulos · Compilación personalizada](/es/docs/modules/#custom-build) y [Compilar desde el código fuente](/es/download#custom-build).

## Ocultar el puerto de administración

"Ajustes → Control de acceso" añade "Respuesta no autorizada", que se aplica a los orígenes bloqueados, al acceso desde Internet con el acceso solo desde la red local activado y a las solicitudes que no pasan por la entrada segura:

- Puede elegir la página de aviso predeterminada, una página 404 simple, una página en blanco, cerrar la conexión, no responder hasta agotar el tiempo o una página HTML personalizada (con el código de estado que indique);
- Cerrar la conexión y no responder se deciden por origen al establecerse la conexión, de modo que HTTPS no envía certificado; las solicitudes reenviadas por un proxy de confianza reciben automáticamente un 404 simple para que el proxy frontal no muestre su propia página de error; las conexiones retenidas tienen límites de duración y número;
- En los modos de ocultación, las respuestas ya no llevan las cabeceras de seguridad propias de la consola de administración, y las páginas personalizadas se muestran en un sandbox que bloquea scripts y recursos externos.

El puerto en sí todavía puede descubrirse con un escaneo; para ocultarlo por completo hace falta un cortafuegos. Consulte la [Guía de refuerzo](/es/docs/guide/hardening).

## Páginas de error de los sitios

- La pestaña "Páginas de error" de un sitio de Servicios web permite elegir, para las páginas 404 y 5xx que genera Gately, el estilo predeterminado, uno de los 10 estilos integrados (Minimalista, Terminal, Neón, Cielo estrellado, Periódico, Brutalista, Aurora, Píxel, Plano, Cadena de estado) o una página personalizada de la biblioteca de páginas; cada estilo tiene miniatura y vista previa de escritorio / móvil;
- La biblioteca de páginas admite subir o pegar HTML, o hacer referencia a un archivo `.html` del servidor; al guardar se revisan y eliminan scripts, atributos de eventos, formularios y contenido similar, se admiten marcadores como `{code}`, `{title}`, `{host}` y `{path}`, y las páginas se sirven con una CSP que bloquea scripts y recursos externos;
- Los sitios de proxy inverso pueden interceptar códigos de estado concretos del backend (como `404, 500-599`) y reemplazar solo las solicitudes de navegadores que abren una página, dejando intactas las solicitudes de API;
- La configuración del sitio predeterminado también se aplica a las solicitudes que no coinciden con ningún sitio, y "Ordenar y lotes" permite fijar el estilo de página de error de varios sitios a la vez.

Consulte [Servicios web · Páginas de error](/es/docs/modules/web#error-pages).

## Otras mejoras

- La búsqueda de DNS dinámico filtra por registro: si coinciden el nombre, el grupo, la nota o el proveedor de la tarea se muestran todos sus registros; si no, solo los registros que coinciden, y durante la búsqueda se despliegan las tareas y grupos contraídos; la búsqueda de Servicios web despliega automáticamente los listeners contraídos;
- Las etiquetas largas de la página de Ajustes se ajustan automáticamente y ya no se superponen a los campos en idiomas como el alemán o el ruso;
- Cuando una solicitud de la consola recibe una respuesta que no es JSON (por ejemplo, bloqueada por la entrada segura tras caducar la sesión), se indica que recargue o vuelva a abrir la entrada segura;
- "Recargar" en la página de error predeterminada es ahora un enlace normal, así que también funciona con una CSP que bloquea scripts;
- Los paquetes de diagnóstico, `GET /api/status` y `GET /api/system/info` incluyen información de la compilación (si es personalizada y qué módulos e idiomas contiene);
- La CI comprueba las combinaciones de build tags de los preajustes.

## Notas de actualización

- Docker: descargue la nueva imagen y vuelva a crear el contenedor; con el socket de Docker montado, Gately también puede actualizarse a sí mismo desde su página de Docker. OpenWrt: instale el nuevo `.apk` / `.ipk` sobre el anterior. fnOS: instale el nuevo `.fpk` manualmente en el Centro de aplicaciones. Otros despliegues pueden actualizarse en línea desde la página Acerca de.
- Los usuarios de la edición completa no tienen que hacer nada; el formato de configuración no cambia.
