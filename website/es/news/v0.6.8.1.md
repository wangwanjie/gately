# Gately v0.6.8.1 publicado

17 de noviembre de 2026

[Descargar v0.6.8.1](/es/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.1)

## Servicios web

- **Fallaba añadir o editar un sitio**: en v0.6.8, añadir, editar, copiar, activar o desactivar un sitio en la página Servicios web, o editar un listener HTTPS, fallaba con un error de formato de `siteCerts`. La causa era la información de certificado del sitio añadida en v0.6.8 (los días restantes del certificado que se muestran en la fila del sitio), que la interfaz enviaba junto con la configuración y que la API de guardado no reconocía. Ahora la interfaz la elimina antes de enviar; la API de guardado también ignora los campos de solo lectura que genera la propia API de listado (estado de ejecución, estadísticas, coincidencia de certificados, etc.), de modo que las páginas antiguas que sigan abiertas tras actualizar y los scripts que leen la configuración y la devuelven completa también pueden guardar. Los demás campos desconocidos se siguen rechazando. El asistente rápido de sitios no se veía afectado.
- **«Sitio no encontrado» con una conexión reutilizada**: cuando varios dominios resuelven a la misma IP y un certificado cubre todos (por ejemplo, un certificado comodín `*.example.com`), el navegador envía las peticiones de un dominio nuevo por una conexión HTTP/2 que ya está abierta. Si un enrutamiento por protocolo basado en SNI situado delante envía algunos de esos dominios a otro Gately, esa conexión lleva en realidad al otro, y el acceso muestra «Sitio no encontrado» (o cae en el sitio por defecto de esa instancia) hasta cerrar y reabrir el navegador. Ahora, cuando el dominio de una petición HTTP/2 o HTTP/3 difiere del SNI de TLS y este listener no tiene un sitio para ese dominio, se devuelve `421 Misdirected Request`; el navegador abre una conexión nueva para ese dominio y reintenta automáticamente. HTTP/1.1 y las peticiones sin SNI (acceso por IP) se tratan como antes.

## Notas de actualización

- Docker: descarga la nueva imagen y recrea el contenedor; OpenWrt: instala el nuevo `.apk` / `.ipk` sobre el anterior; fnOS: instala el nuevo `.fpk` en el Centro de aplicaciones; las demás instalaciones pueden actualizarse en línea desde los ajustes del sistema.
- El problema de la conexión reutilizada solo se resuelve por completo si se actualizan ambos extremos del enrutamiento por SNI: el Gately que recibe la petición es el que debe devolver el 421.
