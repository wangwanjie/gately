## Wake-on-LAN: apagado remoto

Elige para un dispositivo una conexión SSH del terminal web y escribe un comando de apagado, y la tarjeta del dispositivo mostrará el botón «Apagar» (API `POST /api/wol/devices/{key}/shutdown`).

- El formulario ofrece comandos habituales para Linux (`shutdown -h now`), Windows (`shutdown /s /t 0`, con el servidor OpenSSH activado) y macOS (`sudo -n shutdown -h now`);
- La conexión debe haberse abierto una vez en el terminal web para registrar la clave del host; los hosts desconocidos nunca se aceptan sin supervisión;
- Cada apagado abre una conexión SSH nueva y la cierra al terminar, así que nunca se usa una conexión caducada de antes de reiniciar el dispositivo; el comando dura como máximo 30 segundos y solo se ejecuta uno a la vez por dispositivo; si la conexión se corta antes de devolver el código de salida, se considera que el apagado empezó;
- Los tokens de API necesitan `webterminal:write` además de `wol:write` para crear, editar o copiar dispositivos o iniciar un apagado, y `webterminal:read` para listar las conexiones SSH disponibles.

## Wake-on-LAN: control por voz con Bemfa

Con [Bemfa](https://cloud.bemfa.com) conectado, asistentes de voz como Xiao AI, Xiaodu o Google Assistant pueden encender y apagar dispositivos: crea en la consola de Bemfa un tema que termine en `001` (enchufe) o `006` (interruptor), escribe el mismo tema en el dispositivo, introduce la clave privada de usuario en «Wake-on-LAN → Bemfa» y actívalo, y después vincula tu cuenta de Bemfa en apps como Mi Home o Xiaodu.

«Encender» despierta el dispositivo y «apagar» lo apaga de forma remota; tras una acción correcta el estado se escribe de vuelta en Bemfa, y despertar o apagar desde la interfaz o la API también lo escribe. Gately se conecta a `bemfa.com:9503` con MQTT 3.1.1 sobre TLS y verifica el certificado, y la clave privada aparece enmascarada en la API; el estado anterior que el servidor reenvía al suscribirse no se ejecuta, y la misma orden repetida en 10 segundos se ejecuta una vez. Solo puede haber un cliente en línea por clave privada.

## Servicio web: puerto HTTP adicional en un listener

Un listener puede añadir un puerto HTTP sin cifrar (por ejemplo 80 junto a un listener HTTPS en 443) que comparte todos los sitios y ajustes con el puerto principal, de modo que HTTP usa el mismo listener sin volver a introducir los sitios. Con HTTPS activado se elige «Redirigir a HTTPS» (predeterminado; conserva el dominio, la ruta y la cadena de consulta, cambia el puerto al de la dirección de acceso y usa 301 para GET/HEAD y 308 para los demás métodos) o «Servir».

- Las validaciones ACME HTTP-01, el protocolo PROXY y la apertura automática del firewall también se aplican a este puerto; si el puerto está ocupado, el principal sigue funcionando y el estado del listener muestra el motivo;
- Los dominios sin sitio correspondiente se quedan sin redirección: reciben el 404 de dominio desconocido o pasan al sitio predeterminado (un sitio predeterminado «cerrar conexión» la cierra), igual que por HTTPS; la redirección HTTP del mismo puerto ahora sigue la misma regla;
- Al guardar se comprueba que el puerto HTTP no choque con los puertos de otros listeners; cuando a un listener se llega por Enrutamiento por protocolo o Reenvío de puertos y no tiene puerto de acceso, el editor recuerda indicar el puerto de entrada.

## Paneles de navegación: temas

Los paneles de navegación usan las mismas paletas que la interfaz de administración (originales de Gately y paletas clásicas), y el editor del panel define el tema predeterminado. Los visitantes cambian el tema con el botón de paleta arriba a la derecha, que funciona igual que en la interfaz de administración: modo claro, oscuro o del sistema, paletas con vista previa al pasar el ratón que se expanden desde el punto del clic al elegirlas, y color de acento y redondeo personalizados; en el móvil el selector se abre desde abajo. La elección se guarda en el navegador del visitante y se comparte entre el panel y la interfaz de administración cuando ambos están en el mismo dominio. Consulta [Servicio web · Paneles de navegación](/es/docs/modules/web#nav-panel).
