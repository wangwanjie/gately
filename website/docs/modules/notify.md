# 通知中心

通知中心订阅 Gately 内部的事件总线，按规则把 DDNS 变更、证书到期、WAF 拦截、进程异常等事件推送到 Webhook、Telegram、Bark、ntfy、Gotify、Pushover、Discord、Slack、Server酱、PushPlus、企业微信、钉钉、飞书和邮件。管理界面位于侧边栏「系统」分组 → 「通知中心」。

## 工作方式

1. 各模块在状态变化时向进程内事件总线发布事件，发布不会阻塞业务。
2. 通知中心收到事件后逐条匹配规则：规则已启用、事件级别不低于规则的最低级别、事件类型匹配规则的事件列表。
3. 命中的规则经过静默去重后，把消息投递到规则选择的已启用渠道。同一事件命中多条规则时，同一渠道只发送一次。
4. 每次投递的结果（成功或失败原因）写入「最近投递」，内存中保留最近 200 条；失败同时写入模块日志。

单次投递的超时为 45 秒。

## 通知语言

通知内容与日志使用「系统设置」中的服务端语言。服务端语言为「跟随系统」时，依次取环境变量 `GATELY_LANG`、`LANG` 指定的语言；Docker、飞牛与 OpenWrt 的服务通常没有设置这两个变量，此时跟随管理员最近一次登录或在顶栏切换时的界面语言，都没有时使用英文。只读账号登录不改变这一语言。通知中的「来源」为程序生成的名称（如「管理后台」）时会被翻译，用户填写的任务名等保持原样。

## 渠道

点击「添加渠道」，选择类型并填写字段。所有渠道都有名称（必填）、备注和启用开关。密钥类字段保存后不再回显，编辑时留空表示保持原值。

| 类型 | 必填字段 | 可选字段 |
| --- | --- | --- |
| Webhook | 请求地址 | 请求方法（默认 GET，可选 GET、POST、PUT、PATCH）、请求头（每行 `Key: Value`）、请求体、成功判定内容、超时（秒，默认 20）、跳过证书校验 |
| Telegram | Bot Token、Chat ID | API 地址（留空使用 `https://api.telegram.org`） |
| Bark | 设备 Key | 服务地址（留空使用 `https://api.day.app`） |
| 企业微信 | 机器人地址 | 无 |
| 钉钉 | 机器人地址 | 签名密钥（机器人启用「加签」时填写） |
| 飞书 | 机器人地址 | 签名密钥（机器人启用「签名校验」时填写） |
| 邮件 | 服务器、收件人，以及发件人或用户名至少填写一项 | 加密方式、端口、用户名、密码 |
| ntfy | 主题 | 服务地址（留空使用 `https://ntfy.sh`）、访问令牌 |
| Gotify | 服务地址、应用令牌 | 无 |
| Pushover | 应用令牌、用户 Key | 无 |
| Discord | Webhook 地址 | 无 |
| Slack | Webhook 地址 | 无 |
| Server酱 | SendKey | 无 |
| PushPlus | Token | 无 |

地址类字段需要以 `http://` 或 `https://` 开头的完整地址。

### Webhook 模板变量

请求地址与请求体中可以使用以下变量，写法为花括号包住变量名（也兼容 `#` 前缀写法）：

| 变量 | 内容 |
| --- | --- |
| `title` | 标题，格式为 `[Gately] 事件标题` |
| `message` | 事件的详细描述 |
| `text` | 完整正文，含描述、来源、级别、时间 |
| `type` | 事件类型，如 `ddns.changed` |
| `source` | 事件来源 |
| `level` | 级别 `info`、`warn` 或 `error` |
| `time` | RFC 3339 格式的时间 |

事件自带的附加字段（如 `ip`、`container`）也可以作为变量使用，名称与上表重复时以上表为准。地址中的变量值会做 URL 转义。

### 邮件

| 加密方式 | 取值 | 默认端口 |
| --- | --- | --- |
| STARTTLS | `starttls` | 587 |
| SSL/TLS | `tls` | 465 |
| 无加密 | `none` | 25 |

端口填 0 时按加密方式取默认端口。收件人可以填多个，用逗号分隔。邮件使用 UTF-8 编码的纯文本，服务器支持 AUTH 且填写了用户名时使用 PLAIN 认证；发件人留空时使用用户名。

### 签名与返回码

- 钉钉：填写签名密钥后，请求自动附带 `timestamp` 与 `sign`。
- 飞书：填写签名密钥后，请求体自动附带 `timestamp` 与 `sign`。
- 企业微信、钉钉、飞书、Bark 会检查响应中的业务返回码，HTTP 200 但业务失败时同样记为投递失败。

### 代理 {#proxy}

通知服务直连不通、只能经代理访问时（例如 Telegram、Discord、Slack），可以让通知走代理：

- **全局代理**：页头「通知设置」中设置各渠道默认使用的代理，可选「不使用代理」「使用全局更新代理」（复用[系统设置](/docs/guide/configuration)中检查更新用的代理，修改后立即生效；更新代理为空时等同不使用代理）或「自定义代理」。
- **渠道代理**：每个渠道编辑窗口中的「代理」默认「跟随通知设置」，也可以单独选择「直连（不使用代理）」「使用全局更新代理」或自定义代理，覆盖全局设置。局域网内自建的 ntfy、Gotify 等服务可以设为直连。
- 代理地址支持 `http://`、`https://`、`socks5://` 与 `socks5h://`，可带用户名与密码，如 `http://user:pass@127.0.0.1:7890`；渠道卡片上显示代理时隐藏密码。
- 「不使用代理」时 HTTP 类渠道遵循 `HTTPS_PROXY`、`NO_PROXY` 等环境变量，邮件直连，与之前的行为相同；「直连」连环境变量也不读取。
- 邮件同样支持代理：经 `http(s)://` 代理时使用 CONNECT 方法建立到邮件服务器端口的隧道（代理需允许连接该端口，Clash 等常见代理默认允许），经 `socks5://` 代理时由代理解析服务器域名。之后的 STARTTLS / SSL 与认证在隧道内完成，代理看不到邮件内容。
- 代理连接失败时，投递记录与测试提示中显示「经代理 … 连接失败」，代理密码以 `xxxxx` 代替。

## 规则

点击「添加规则」：

| 字段 | 说明 |
| --- | --- |
| 名称 | 必填 |
| 事件 | 至少一项。可选具体事件类型，`*` 表示全部事件，也可以输入通配，如 `ddns.*`。通配采用 Go `path.Match` 语法 |
| 最低级别 | `info`（信息）、`warn`（警告）、`error`（错误），留空为信息。事件级别低于该值时不推送 |
| 渠道 | 至少一个 |
| 静默（秒） | 同一规则下，同一来源的同类型事件在该时间内只推送一次，期间的重复事件被丢弃。0 表示不去重 |
| 启用 | 开关 |

::: tip 提示
WAF 拦截和上游状态变化可能频繁发生，建议为这类规则设置 300 秒以上的静默时间。
:::

## 规则模板

新建规则时可以点击模板预填事件、级别与静默时间，再选择渠道保存：

| 模板 | 事件 |
| --- | --- |
| 关键故障 | DDNS 更新失败、证书续期失败、上游不可用、子进程异常退出、备份失败、容器退出 |
| 证书到期 | 证书即将到期、续期失败（静默 24 小时） |
| 地址变化 | DDNS 解析更新、STUN 地址变化 |
| 服务健康 | 上游不可用与恢复、容器退出、子进程退出 |
| 安全与登录 | 登录失败、IP 封禁、登录成功、访问敏感内容 |
| 性能告警 | 性能监控的告警触发与恢复（不静默） |
| 配置变更 | 管理后台的每一次配置变更 |
| 版本更新 | Gately 的安全更新与新版本、托管程序有新版本、容器镜像有新版本（不静默） |

## 事件类型

| 事件类型 | 名称 | 级别 | 触发条件 |
| --- | --- | --- | --- |
| `ddns.changed` | 动态域名：解析已更新 | 信息 | DDNS 任务成功更新解析 |
| `ddns.failed` | 动态域名：更新失败 | 错误 | DDNS 任务更新失败 |
| `stun.changed` | STUN：穿透地址变化 | 信息 | STUN 规则的穿透地址变化 |
| `ssl.expiring` | 证书：即将到期 | 警告 | 证书剩余有效期不足 7 天，同一证书每 24 小时最多提醒一次 |
| `ssl.renew_failed` | 证书：续期失败 | 错误 | 证书签发或续期失败 |
| `waf.blocked` | WAF：拦截请求 | 警告 | WAF 拦截了一个请求，附带 `ip`、`host`、`path` 字段 |
| `upstream.down` | 反向代理：上游不可用 | 错误 | Web 服务的某个后端被判定不可用 |
| `upstream.up` | 反向代理：上游恢复 | 信息 | 不可用的后端恢复 |
| `docker.exited` | Docker：容器退出 | 警告或错误 | 容器以非零退出码退出（警告），或因内存不足被终止（错误） |
| `process.exited` | 子进程异常退出 | 错误 | 由 Gately 托管的子进程异常退出并将自动重启，来源为该进程的日志名称 |
| `backup.done` | 备份：完成 | 信息 | 定时或手动备份全部目的地成功，见[配置备份](/docs/modules/backup) |
| `backup.failed` | 备份：失败 | 错误 | 备份打包失败，或任一目的地写入失败 |
| `auth.failed` | 认证：连续失败 | 警告 | 管理后台登录失败，附带 `ip` 字段 |
| `auth.banned` | 认证：IP 已被封禁 | 警告 | Web 服务认证连续失败触发自动封禁 |
| `login.success` | 管理后台：登录成功 | 信息 | 管理后台登录成功，附带 `ip`、`user` 字段 |
| `audit.change` | 管理后台：配置变更 | 信息 | 管理后台中的任意变更操作，附带 `actor`、`ip`、`method`、`path` 字段，见[审计与配置历史](/docs/guide/audit) |
| `audit.access` | 管理后台：访问敏感内容 | 警告 | 下载备份、诊断包、证书私钥或打开终端等，字段同上 |
| `perf.alert` | 性能监控：触发告警 | 警告或错误 | 性能告警规则的条件持续满足到设定时长，级别取规则设置，附带 `rule`、`metric`、`target`、`value`、`condition` 字段，见[性能监控](/docs/modules/perf) |
| `perf.recovered` | 性能监控：告警恢复 | 信息 | 已触发的性能告警条件解除，字段同上 |
| `system.update` | Gately：发现新版本 | 信息 | 自动或手动检查更新发现新版本，附带 `current`、`latest`、`url` 字段，同一版本只通知一次，见[自动检查更新](/docs/guide/install#update-check) |
| `system.security` | Gately：安全更新 | 错误 | 当前版本受已公开的安全公告影响，或有更新的版本带有安全修复，附带 `current`、`latest`、`url`、`advisories`、`securityReleases` 字段，出现新的安全问题时再次通知 |
| `program.update` | 托管程序：发现新版本 | 信息 | 自动检查发现已安装的 frp、cloudflared、Tailscale、NetBird 或 File Browser 有新版本，来源为程序名，附带 `program`、`current`、`latest` 字段 |
| `docker.update` | Docker：镜像有新版本 | 信息 | Docker 定时检查发现容器镜像有新版本，一次检查汇总为一条，同一个新镜像只通知一次，附带 `count` 字段 |
| `notify.test` | 测试通知 | 信息 | 渠道的「测试」按钮产生，不参与规则匹配 |

## 测试发送

渠道卡片上的「测试」按钮会向该渠道直接发送一条标题为「测试通知」的消息，不经过规则，也不要求渠道已启用。发送成功提示「测试通知已发送」，失败时显示具体错误。测试结果同样出现在「最近投递」中，规则列显示为「测试」。

对应接口为 `POST /api/notify/channels/{key}/test`，可通过 [API 令牌](/docs/reference/api) 的 `notify:write` 权限调用。
