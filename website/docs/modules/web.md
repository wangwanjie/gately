# Web 服务

按域名提供反向代理、重定向、静态文件与固定文本，是 Gately 的统一 Web 入口。菜单位置：侧边栏「Web → Web 服务」。

## 结构：监听、站点与默认站点

配置分三层：

1. 监听：一个监听端口。字段包括网络（`tcp` 双栈、`tcp4`、`tcp6`）、监听地址（留空为所有地址）、端口、HTTPS 开关、最低 TLS 版本（1.0 / 1.1 / 1.2 / 1.3）、是否接收 PROXY 协议。
2. 站点：监听下按域名匹配的一个站点。域名支持精确域名、`*.example.com`（匹配任意级子域名）、`api-*.example.com`（首段内的一个 `*` 匹配该段中零个或多个字符，不跨越 `.`）与 `*`（匹配所有）；匹配优先级为精确域名、通配、`*`。多个通配同时命中时较长的规则优先，长度相同时以列表中靠前的站点为准。首段内通配同样支持导入、批量编辑与重定向变量 `{1}`。HTTPS 站点需要覆盖实际访问域名的证书，例如 `*.example.com`，证书机构只签发 `*.example.com` 形式的通配证书。
3. 默认站点：没有站点匹配时使用，未启用时返回 404。也可以把默认站点设为「断开连接」，让未知域名的请求得不到任何响应。默认站点配置后显示在站点列表最后；尚未配置时，点击监听卡片上的「设置默认站点」进行配置。

修改站点或默认站点并保存时，站点列表会原地替换：监听保持运行，已建立的连接（含 WebSocket）不会断开，各站点的统计数据也会保留。新配置无效时继续使用原来的站点。修改监听自身的设置（网络、地址、端口、HTTPS、最低 TLS、HTTP/3、PROXY 协议）会重启该监听。

站点列表中的每个具体域名都是可点击的完整地址，在新标签页打开，旁边的按钮可复制该地址；通配域名（`*.example.com`、`*`）照常显示为文本。地址按监听推算：开启 HTTPS 用 `https`，否则用 `http`，端口为监听端口，443 与 80 这类默认端口省略，例如 `https://example.com:8443`。监听未填访问端口时，若有启用的协议分流或端口转发规则转入本监听，站点链接自动使用规则的入口（监听）端口，例如监听 8443 由协议分流在 443 转入时链接用 443。规则的目标地址需能到达本监听：监听全部地址时为回环或未指定地址，监听具体地址时为同一地址。协议分流按域名以分流时的顺序匹配（精确域名、最具体的通配域名、`*`、默认目标），跳过已停用的路由和只接受 `acme-tls/1` 等非浏览器 ALPN 的路由；只转发 UDP 的端口转发规则不计入；端口区间按一一对应换算；多条规则命中时取第一条启用的规则。监听标题显示识别出的端口及来源规则，「访问地址」输入框以它为占位提示，手动填写的访问端口仍优先。经路由器端口映射、frp 或 CDN 访问（或规则转发到本机的局域网地址）时，对外的协议或端口可能与监听不同，需在监听的「访问地址」中手动指定协议与端口（例如 CDN 回源到 http 8080 时选 https 并填 443）。访问地址只用于生成链接，修改后不重启监听。保存时域名统一为浏览器请求中的形式：转为小写，IPv6 去掉方括号，中文等国际化域名转为 punycode（如 `中文.com` 保存为 `xn--fiq228c.com`）；带端口、路径、`@` 等永远匹配不上的写法会被拒绝。从 Lucky 或 nginx 导入时只跳过写错的域名并给出提示。

站点可以填写「分组」（最长 64 个字符，默认站点不能分组）。列表在每个监听下按分组显示可折叠的区块：分组按首次出现的顺序排列，未分组的站点排在后面，默认站点始终在最后；各分组的折叠状态保存在浏览器中。点击「排序与批量」进入排序模式，可以上移、下移站点，在分组内拖动站点，整组移动，以及调整监听的顺序。顺序只影响列表显示，域名匹配按上面的优先级进行，与站点顺序无关；保存排序同样原地替换站点列表，不会断开连接。页头的搜索框可按域名、名称、分组、后端或备注过滤站点，搜索期间折叠的监听卡片会自动展开。

排序模式下还可以勾选多个站点（分组标题的复选框可选中整组）：拖动其中任一项会一起移动，拖到其他分组的站点或分组标题上即加入该分组；工具栏可以把选中的站点批量移到指定分组，留空则移出分组。跨监听的选中站点批量设置分组时，各监听分别保存。

鼠标移到分组标题上，点铅笔按钮可以重命名分组：组内条目一起改为新名称，位置和顺序不变；改成已有分组的名称时，确认后两个分组合并。

### 移动站点 {#move-sites}

站点可以连同全部设置移到其他监听：

- 编辑站点时修改「所属监听」，保存时先保存修改再移动；新建站点时用它选择建在哪个监听下。
- 排序模式下勾选站点（可跨监听），点工具栏的「移到监听」，选择目标监听与分组（默认保持各站点原有分组），站点排在目标监听末尾或所选分组末尾；已在目标监听中的站点不动。
- 排序模式下把站点拖到其他监听的站点上方或下方，即插入该位置并加入其分组；拖到分组标题上即放入该分组末尾。没有普通站点的监听在拖动时显示放置区。放下后需要确认。

每次移动一次提交，源监听与目标监听各重载一次，原地替换站点列表，其他站点的连接不会断开。目标监听已有相同域名的站点时拒绝移动，任何监听都不修改；默认站点属于所在监听，不能移动。站点标识在目标监听中已被占用时换用新的标识，性能监控告警规则中引用的站点会同步改写。登录会话按监听与站点隔离，移动后已登录的访客需要重新登录；分享链接的已兑换次数随站点迁移，限次链接不会因移动而重新可用；站点的统计与实时连接从零开始。把开启了认证的站点从 HTTPS 监听移到明文 HTTP 监听时会提醒密码与登录 Cookie 将以明文传输。

### 批量操作

在排序模式下勾选站点（可跨监听），工具栏提供以下批量操作。每次操作一次提交：全部站点校验通过才保存，任一站点失败都不做修改并提示是哪个站点；每个受影响的监听只重载一次，原地替换站点列表，不会断开连接。

- **启用 / 停用**：已是目标状态的站点不受影响。
- **删除**：确认后删除选中的站点；默认站点不能删除。
- **批量域名**：
  - 增加域名：每行一个（也可用逗号分隔），站点已有的域名会跳过，新域名追加在末尾；
  - 移除域名：按完整域名匹配，站点没有的域名会忽略，不能把站点的域名全部删光；
  - 替换主域名：把域名后缀换成新的后缀，原域名本身及其子域名（含 `*.原域名` 通配）都会替换，例如 `old.com` 换成 `new.com` 后 `www.old.com` 变为 `www.new.com`；替换后重复的域名会合并，不匹配的站点保持不变。

  新加入的域名如果同时出现在同一监听的多个站点中会被拒绝，因为同一监听内只有第一个站点能匹配到它；不同监听可以使用相同域名。
- **批量选项**：可以批量开启或关闭压缩、访问日志、CORS、转发头、拒绝时断开连接，以及设置或取消 WAF；选「不修改」的项保持各站点原有设置。认证、访问控制、后端地址等影响访问的设置需要在站点中逐个修改。
- **移到监听**：把选中的站点移到其他监听，见 [移动站点](#move-sites)。

对应接口为 `POST /api/webservice/sites/batch`，请求体 `{"sites": [{"listener": "监听 key", "site": "站点 key"}], "action": "...", ...}`，`action` 取 `enable`、`disable`、`delete`、`addDomains`、`removeDomains`（配合 `domains`）、`replaceDomain`（配合 `from`、`to`）或 `set`（配合 `options`，只接受上述选项字段），返回实际修改与无需修改的站点数。一次最多 500 个站点、100 个域名。监听本身也支持通用的 `PUT /api/webservice/listeners-enable` 与 `POST /api/webservice/listeners-delete`。`action` 为 `move` 时用 `move` 指定目标，例如 `{"listener": "目标监听 key"}`，可加 `group`（放入的分组，空字符串为未分组，不填保留原分组）或 `before` / `after`（目标监听中的站点 key，插到它前后并加入它的分组），返回中的 `moved` 列出每个站点移动前后的标识。

## 站点类型

| 类型 | 说明 |
| --- | --- |
| 反向代理 | 转发到一个或多个后端，后端地址格式为 `http(s)://主机:端口`，支持 WebSocket |
| 重定向 | 跳转到完整 URL，状态码 301 / 302 / 307 / 308（默认 302），可选保留原路径与查询串。URL 中可以写 `{host}`，会替换为访客使用的域名：`https://{host}` 加上「保留路径」，就能把所有 HTTP 请求跳到同一域名的 HTTPS。还可以使用 `{path}`、`{1}`、`{STUN_规则名_PORT}` 等变量，见 [重定向变量](#redirect-vars) |
| 静态文件 | 目录需为绝对路径；关闭「目录列表」时，目录请求只在存在 `index.html` 时返回。「无扩展名地址」在文件不存在时再尝试 `路径.html` 与 `路径/index.html`（适用于 VitePress 等生成器，相当于 nginx 的 `try_files $uri $uri.html $uri/index.html`）；「404 页面」填写目录内的路径，如 `404.html`，以 404 状态返回 |
| 导航面板 | 输出 [导航面板](#nav-panel) 库中的一个面板：把常用服务的链接按分组汇总成一页，内网访客自动使用内网地址 |
| 固定文本 | 自定义内容、`Content-Type`（默认 `text/plain; charset=utf-8`）与状态码（100-599，默认 200） |
| 断开连接 | 不返回任何内容，直接断开连接，相当于 nginx 的 `return 444`。常用作默认站点，让扫描未知域名的请求得不到响应；访问日志记为 444；不经过认证、访问控制、WAF 与重写，站点的其他设置都不生效 |

所有类型的站点均可设置访问日志、跨域（CORS）、自定义请求头与响应头（每行 `Key: Value`，Value 留空表示删除该头），并可引用一个 [WAF 防火墙](/docs/modules/waf) 实例（实例不存在或停用时放行）。请求头、响应头与 Content-Type 的编辑方式见 [请求头与响应头](#headers)。

访问日志会记录客户端 IP、方法、域名与路径、状态码、耗时、站点名称，行尾按 nginx 的格式附上 Referer 与 User-Agent（缺失时为 `-`），同一出口 IP 后面的不同设备可以通过 User-Agent 区分。可在日志中按站点、状态码、来源 IP 等条件筛选，见 [运行日志的查看与筛选](/docs/guide/configuration#log-filter)。

### 重定向变量 {#redirect-vars}

重定向站点的目标地址可以使用以下变量：

| 变量 | 含义 |
| --- | --- |
| `{host}` | 访客请求的域名，不含端口；IPv6 地址带方括号，如 `[2001:db8::1]` |
| `{port}` | 访问端口 |
| `{hostAndPort}` | 域名加端口，与请求的 Host 一致 |
| `{path}` / `{PATH}` | 请求路径，`{PATH}` 不含开头的 `/` |
| `{args}` / `{Args}` | 查询串，`{args}` 带开头的 `?`（没有查询串时为空），`{Args}` 不带 |
| `{domainPartN}` / `{pathPartN}` | 域名（以 `.` 分隔）或路径（以 `/` 分隔）的第 N 段，N 从 1 开始 |
| `{ClientIP}` / `{RemoteIP}` | 客户端 IP |
| `{time}` | 当前时间，格式 `2006-01-02 15:04:05`，其中空格写成 `%20`（即 `2006-01-02%2015:04:05`），保证跳转地址是合法 URL |
| `{1}` | 站点域名 `*.example.com` 中 `*` 匹配到的部分；命中精确域名时为空，命中 `*` 或默认站点时为完整域名 |
| `{STUN_规则名_PORT}` / `{STUN_规则名_IP}` / `{STUN_规则名_ADDR}` | [STUN 穿透](/docs/modules/stun) 规则当前的公网端口、IP、`IP:端口`；规则名即列表中的名称，可以含下划线 |

- 开启「保留路径」时，目标中写了 `{path}`、`{PATH}` 或 `{pathPartN}` 就不再追加原路径，写了 `{args}`、`{Args}` 或目标自带查询串就不再追加原查询串，另一部分照常追加；
- STUN 端口变化后无需修改站点，下一次请求就跳到新端口。引用的规则不存在、未启用、还没有穿透成功或正在自动重试时，站点返回 503，运行日志中会记录原因；
- 变量展开后跳转地址缺少主机（例如命中精确域名时 `{1}` 为空，目标却只写了 `https://{1}`）时返回 503；访客域名含 `&`、`=`、`/`、`@` 等域名中不会出现的字符时返回 400，不会代入跳转地址；目标使用 `{host}`、`{hostAndPort}`、`{1}` 或 `{domainPartN}` 时，没有 Host 头的请求（HTTP/1.0 探测等）同样返回 400；
- 站点域名只支持一个 `*`，所以只有 `{1}`；
- 路径重写规则中的重定向目标仍只支持 `{host}`；未知的 `{xxx}` 原样保留。

例：Cloudflare CDN 把 `*.example.com` 回源到本机 2053 端口，这个监听上有一个域名为 `*.example.com` 的重定向站点，目标填 `https://{1}.v4.example.com:{STUN_web_PORT}{path}{args}`。访问 `zly.example.com/a?b=1` 会跳到 `https://zly.v4.example.com:<STUN 端口>/a?b=1`；STUN 规则 web 转发到另一个监听，在那里为 `*.v4.example.com` 下的各个域名建反向代理站点。

### 反向代理选项 {#proxy-options}

位于站点编辑框「基本」页的「选项」，旁边的问号图标可在界面中查看简要说明并跳转到本节。

| 选项 | 作用 | 什么时候开启 |
| --- | --- | --- |
| 跳过后端证书校验 | 连接 HTTPS 后端时不验证证书 | 后端使用自签名或过期证书，如 NAS、路由器管理页的 https 端口。关闭校验后无法确认后端身份，只建议用于内网后端 |
| Host 使用后端地址 | 发往后端的 Host 头改为后端地址；关闭时（默认）保留访客请求的 Host | 后端只认自己的地址，例如返回 400 / 403、跳转到错误地址或提示 Host 不匹配；反代到公网网站或 CDN 时通常需要。后端按域名区分站点，或需要用访问域名生成链接时保持关闭 |
| 禁用连接复用 | 每个请求都新建到后端的连接（关闭 Keep-Alive） | 后端偶尔出现连接被重置、请求卡住，或不支持长连接。会增加一些延迟，正常情况保持关闭 |
| 添加 X-Forwarded-* | 写入 `X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host` / `X-Forwarded-Port` 与 `X-Real-IP`，告诉后端访客的真实 IP、原始协议、域名和端口；访客源端口写入 `X-Real-Port` 与 `X-Forwarded-For-Port`（`X-Forwarded-Port` 是访客访问 Gately 用的端口） | 后端需要记录真实 IP，或要知道外部是 HTTPS 才能生成正确链接（否则可能跳回 http 或登录后循环跳转）。多数应用建议开启 |
| 向后端发送 PROXY v2 | 在 TCP 连接开头附加 PROXY 协议 v2 头，传递真实客户端 IP。开启后每个请求都新建连接，也不再用 HTTP/2 连接后端。后端是 Gately 时，需在其监听上开启接收 PROXY 协议，并把本机加入可信 PROXY 来源。 | 后端不读 HTTP 头但支持 PROXY 协议，如另一层 Gately、haproxy、开启 `proxy_protocol` 的 nginx。后端未配置接收时所有请求都会失败，不确定时保持关闭 |
| 使用访问域名作为 SNI | 仅 HTTPS 后端：握手时发送访客使用的域名并按它校验证书，相当于 nginx 的 `proxy_ssl_server_name on; proxy_ssl_name $host` | 后端在同一端口按域名选择证书或分流，如 frp 的 `vhost_https`、托管多个 HTTPS 站点的 nginx。每个后端使用独立的连接池，不同域名的连接不会互相复用 |
| http:// 后端使用明文 HTTP/2（h2c） | 仅 http:// 后端：以不加密的 HTTP/2（h2c）连接后端，gRPC 流式传输与尾部元数据原样透传；多个访客的请求共用一条后端连接。HTTPS 后端会自动协商 HTTP/2，无需此选项；健康检查同样使用 h2c | 后端是只讲 h2c 的 gRPC 服务，如 NetBird 管理/信令、只开 gRPC 的 xray。后端不支持 h2c 时请求返回 502，且该连接上不能使用 WebSocket 升级 |
| 转发 Gately 登录 Cookie | 把 Gately 自己的登录 Cookie（单点登录 `gately_sso`、站点会话、第三方登录随机数）原样转发给后端；关闭时（默认）这些 Cookie 不发给后端，避免泄露登录凭据 | 后端是另一台负责认证的 Gately，本站点不开认证。例如公网 Gately 只做 WAF 与访问控制、反代到内网 Gately，由内网 Gately 负责网页认证与单点登录。本站点启用认证时不能开启；只在后端是自己的 Gately 时使用 |

常见组合：

- 反代内网的 Web 应用（如 `http://192.168.1.10:5000`）：只开「添加 X-Forwarded-*」；
- 后端是自签名证书的 https 地址：再开「跳过后端证书校验」；
- 反代公网网站或第三方服务：开「Host 使用后端地址」；
- 后端前面还有按 SNI 分流的服务（如 frp `vhost_https`）：开「使用访问域名作为 SNI」。
- 后端是明文端口上的 gRPC 服务（如 NetBird）：勾选“http:// 后端使用明文 HTTP/2（h2c）”，健康检查选 TCP 模式。
- 公网 Gately 只做 WAF、内网 Gately 负责登录：公网站点不开认证，开「转发 Gately 登录 Cookie」，需要真实 IP 时再开「向后端发送 PROXY v2」，并在内网 Gately 上接收 PROXY 协议、把公网 Gately 加入可信来源。

### 请求头与响应头 {#headers}

在站点编辑框的「请求头」页配置。请求头发往后端，只对反向代理站点生效；响应头返回给客户端，对所有类型的站点生效。

- 逐行编辑：点击名称框会列出常用头及其用途，选中后自动填入常用值，值框也可以改选其他常用值；两者都可以直接手输。值留空表示删除该头，在名称框粘贴整行 `Key: Value` 会自动拆开；
- 「添加常用安全头」补齐 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN` 与 `Referrer-Policy: strict-origin-when-cross-origin`，已有的头不会重复添加；
- 「文本模式」可一次粘贴多行 `Key: Value`，切回逐行编辑时保留内容；
- 「分路径后端」中每个路径的附加请求头使用同样的编辑方式，在站点请求头之后应用，同名时以路径的为准。

每一行下方会实时给出反馈。红色表示保存会失败或该头无法生效，如缺少名称、名称含空格或冒号等非法字符、文本模式中缺少冒号；橙色表示可以保存但结果可能不符合预期：

- 请求头里设置 `Host` 不会生效，需要改写时开启「Host 使用后端地址」；
- `X-Forwarded-For`、`X-Real-IP` 写固定值会覆盖真实客户端 IP，传递客户端 IP 请开启「添加 X-Forwarded-*」；
- `Content-Length`、`Connection`、`Transfer-Encoding` 等由连接自动管理，手动设置会被忽略或导致传输异常；
- 值按原样发送，不支持 nginx 的 `$host` 等变量；预设值中的 `<token>` 等占位内容需要替换；
- 同名头按顺序设置，后面的覆盖前面的。

「固定文本」站点的 `Content-Type` 可从常用类型中选择或手输，界面会检查 `类型/子类型; 参数=值` 格式；`text/*` 未声明 `charset` 时提示中文等内容可能乱码，留空时使用 `text/plain; charset=utf-8`。

### 导航面板 {#nav-panel}

左侧菜单「Web → 导航面板」（`#/webpanels`）管理面板库。每个面板是一组按分组排列的链接，再在 Web 服务中添加类型为「导航面板」的站点并选择面板，访问站点域名的根路径（`/` 或 `/index.html`）就会打开导航页；其他路径返回 404。站点的认证、IP 访问控制、国家过滤与 WAF 照常生效，导航页通常只给自己人看，建议开启网页认证或 IP 白名单。面板修改保存后立即生效，不需要重启监听。

- **链接**：每个链接有名称、分组、描述、外网地址与可选的内网地址、图标与颜色，可以设为在当前页打开或在页面中隐藏。分组按链接列表中首次出现的顺序显示，编辑框中可以整组上移、下移。「从 Web 服务站点添加」列出能拼出具体地址的站点（取第一个非通配域名，按监听的访问协议与端口，经协议分流或端口转发进入的监听使用转发的入口端口），勾选后作为链接加入，站点分组沿用为链接分组。
- **其他访问方式**：同一个服务常常有多个入口，例如 IPv6 直连、frp、STUN 穿透、Cloudflare 隧道。每个链接最多可以再填 8 个访问方式（名称不超过 20 个字符，地址写法与可用变量同上），显示为卡片上的小链接，在新标签页打开，内网与外网访客都会显示；变量暂无值的访问方式显示为划线的不可用状态。主地址不可用时，卡片上的其他访问方式仍可点击，搜索也会匹配访问方式的名称。
- **地址**：支持 `http`、`https`、`ftp`、`ftps`、`sftp`、`ssh`、`smb`、`afp`、`nfs`、`vnc`、`rdp` 与 `mailto`，不能带密码。可以使用变量 `{host}`、`{port}`、`{hostAndPort}`（访客打开面板所用的域名与端口）、`{1}`、`{domainPartN}` 与 `{STUN_规则名_PORT}`、`{STUN_规则名_IP}`、`{STUN_规则名_ADDR}`，写法同 [重定向变量](#redirect-vars)，例如 `https://{host}:8443` 或 `http://{STUN_web_ADDR}/`；STUN 规则还没有公网地址时，该链接显示为「暂不可用」。取自请求路径与查询串的 `{path}`、`{args}` 等变量不能使用，否则别人构造一个带查询串的面板地址就能改变链接指向。`{1}` 没有值时（面板站点的域名不是通配域名，或在预览中），用到它的链接显示为「暂不可用」；用 IPv6 地址访问面板时，`{host}` 展开为带方括号的写法，例如 `[2001:db8::1]`。
- **内网与外网**：访客地址是回环、私有（10/8、172.16/12、192.168/16、fc00::/7）或链路本地地址，或在面板的「额外内网地址」中（例如 Tailscale 的 `100.64.0.0/10`）时，链接使用内网地址，没有填写内网地址的链接仍用外网地址。经 CDN 或反向代理访问时请配置 [可信代理](#real-ip)，否则访客地址是代理的地址。有链接填写了内网地址时，页面右上角可以手动切换内网或外网，选择保存在 Cookie 中，点「自动识别」恢复。
- **内网判定与可见性**：内外网按访客的直连地址判断。外网访客经本机的 frpc、cloudflared 或 Docker 端口映射转发进来时，直连地址是本机或容器网段，会被当作内网访客；这种部署请让转发方发送 PROXY 头并在监听上开启 PROXY 协议，或经 HTTP 代理时配置 [可信代理](#real-ip)。内网地址对所有能打开面板的访客可见，访客也可以用 `?net=lan` 手动切换到内网视图；需要隐藏内网地址时，请为站点开启认证或 IP 访问控制。
- **图标**：可以填 emoji 或不超过 8 个字符的文字、`http(s)` 图片地址，或上传图片（PNG、JPEG、GIF、WebP 缩放到 128 像素后保存，SVG 与 ICO 原样保存，单个不超过 96 KB，一个面板合计不超过 3 MB），留空显示名称首字；文字图标的底色可以自选，留空按名称挑选。也可以点「选择」使用内置图标：Gately 各模块与 frp、Tailscale、NetBird、Cloudflare 等周边，Jellyfin、Home Assistant、qBittorrent 等常用应用，OpenWrt、群晖、Proxmox 等系统，以及路由器、服务器等通用图标（品牌图标来自 Simple Icons，通用图标来自 Lucide），写为 `builtin:编号`；内置图标画在图标自带颜色的方块上，底色可以改，底色较浅时图形自动改为深色。
- **页面**：标题（留空用面板名称）、副标题、页面图标与主题（跟随系统、浅色、深色）。页面支持搜索：按 `/` 聚焦搜索框，空格分隔多个关键词，按名称、描述、地址与分组匹配，回车打开第一个结果，`Esc` 清空。编辑框的「预览」按外网或内网访客生成页面，其中 `{host}` 按管理后台的域名展开。
- **皮肤**：与管理界面右上角「主题配色」相同的色系（Gately 原创与经典配色），默认翠绿，编辑框中可选面板的默认皮肤。访客可点页面右上角的调色板按钮换肤：切换亮色、暗色或跟随系统，选择色系（鼠标悬停时预览，点击后从点击处展开新配色），自定义主色与圆角；手机上换肤面板从底部弹出。选择保存在访客的浏览器中，没有选择过时使用面板设置；面板与管理界面在同一域名下时两边的选择互通。编辑框的预览按面板设置显示，不含换肤按钮。
- **安全**：页面由服务端生成，名称、描述等内容全部转义，只运行带随机 nonce 的内置样式与脚本（`Content-Security-Policy`），不能被其他网站嵌入；链接图片以 `no-referrer` 加载。页面随访客地址变化，响应带 `Cache-Control: no-store`。

一个实例最多 50 个面板，每个面板最多 500 个链接；仍被站点引用的面板不能删除。只读账号与只读令牌可以查看。接口见 `GET|POST /api/webservice/panels`、`PUT|DELETE /api/webservice/panels/{key}`、`PUT /api/webservice/panels/{key}/enable` 与 `POST /api/webservice/panels/preview`。

## 传输与协议

- HTTPS：使用 [SSL 证书](/docs/modules/ssl) 模块中覆盖该域名的证书；
- 同端口 HTTP：开启 HTTPS 的监听可同时接受明文 HTTP，按连接的第一个字节区分协议。「跳转到 HTTPS」把 `http://地址:端口` 重定向到 `https://地址:端口`（GET/HEAD 用 301，其他方法用 308），适合只能用一个端口、又希望输错协议也能打开的场景；「直接服务」按 HTTP 提供站点，不加密。ACME HTTP-01 验证请求照常应答，修改此项会重启该监听；
- HTTP 端口：监听可以再填一个明文 HTTP 端口（例如 HTTPS 监听 443 时再开 80），与主端口共用全部站点与设置，不必为 HTTP 另建监听、重复填写站点。开启 HTTPS 时可选「跳转到 HTTPS」（默认）或「直接服务」：跳转保留访客请求的域名、路径与查询串，端口换成「访问地址」中的端口（未填写时用监听端口，443 时省略），GET/HEAD 用 301，其他方法用 308；「直接服务」按 HTTP 提供站点，适合需要在 `http://` 与 `https://` 之间切换的场景。没有对应站点的域名不跳转：没有默认站点时按未知域名返回 404，默认站点为「断开连接」时直接断开，与 HTTPS 上的处理一致（同端口 HTTP 的跳转同样如此）。ACME HTTP-01 验证请求照常应答，PROXY 协议与自动放行防火墙同样作用于这个端口。HTTP 端口被占用时主端口照常运行，监听状态中显示原因；
- HTTP/3（QUIC）：在开启 HTTPS 的监听中打开，同一端口号的 UDP 上同时提供 HTTP/3，并通过 `Alt-Svc` 响应头通告浏览器；需要在防火墙与端口映射中放行该 UDP 端口；
- WebSocket：反向代理自动支持；
- PROXY 协议：监听可接收上游（如 haproxy、frp）发送的 PROXY 头，仅信任「全局设置 → 可信 PROXY 来源」中列出的 IP 或网段，留空表示不信任任何来源；反向代理可向后端发送 PROXY 头。经可信来源进入的连接带的 `X-Forwarded-Proto: https` 同样被采信：会话 Cookie 带 Secure、开启明文跳转的端口不再跳转，开启「添加 X-Forwarded-*」时也向后端如实传递 https。

### 访客真实 IP（CDN / WAF 之后） {#real-ip}

站点放在 Cloudflare、阿里云 CDN、腾讯云 CDN 等 HTTP 代理后面时，连接来自代理的回源地址。在「全局设置 → 访客真实 IP」中填写可信代理（代理的回源 IP 或网段，可填多家）并选择真实 IP 请求头后，Gately 从请求头取得访客地址，访问日志、IP 黑白名单、仅内网访问、国家过滤、认证失败封禁、访问统计、路径探测，以及转发给后端的 `X-Real-IP` / `X-Forwarded-For` 都使用该地址。

- 只在原始对端位于可信代理中时读取请求头。原始对端指 PROXY 协议处理后的地址：经可信 PROXY 来源进入时是 PROXY 头中的地址，否则是 TCP 对端。直接访问时客户端自带的请求头一律忽略；
- 请求头按选择的顺序查找，第一个能给出有效地址的头生效，未选择时为 `X-Forwarded-For`。`X-Forwarded-For` 等多项头自右向左跳过可信代理，取第一个不可信的地址，客户端在左侧伪造的值不会被采用；
- 只选择你的代理会覆盖写入的头。例如 Cloudflare 覆盖写入 `CF-Connecting-IP`，其他代理通常原样转发客户端自带的同名头，这时选 `X-Forwarded-For` 更安全；
- 使用 Cloudflare 时建议把真实 IP 请求头设为 `CF-Connecting-IP`，它由 Cloudflare 直接写入访客地址。`X-Forwarded-For` 自右向左跳过可信代理，可信代理填了整段 Cloudflare 地址时，经 Cloudflare 自身出口（如 Workers）发来的请求可以在左侧带上伪造的地址；
- 不能填写 `0.0.0.0/0`、`::/0`，保存时会被拒绝；
- 协议分流把连接经回环转给 Web 服务时，请在协议分流中开启发送 PROXY 头、在监听上开启接收 PROXY 协议，不要把 `127.0.0.1` 填进可信代理，否则直接连到协议分流的访客也能伪造请求头。协议分流的透传路由仍是纯 TCP 转发，不受此设置影响；
- 经可信代理进入、带 `X-Forwarded-Proto: https` 的请求按 HTTPS 处理；
- 访客源端口：从请求头取得访客地址时，源端口只来自「真实端口请求头」中配置的头（如代理以 `proxy_set_header X-Real-Port $remote_port` 写入的 `X-Real-Port`，有多项时取最右一项）。未配置或取不到时端口未知，开启「添加 X-Forwarded-*」的站点不向后端发送 `X-Real-Port` / `X-Forwarded-For-Port`，实时连接中只显示地址。只填你的代理会覆盖写入的头，否则访客可以伪造端口；
- 未填写可信代理时保持原有行为。连接层面的封禁（入侵防护写入防火墙的规则）针对的是 TCP 来源，在 CDN 之后对访客不起作用，Web 服务自身的封禁按真实地址生效。

## 认证

在站点编辑框的「安全」页配置：

- 网页认证：浏览器显示登录页；
- 基本认证：HTTP Basic；
- 用户：每行 `用户名:密码`，密码可填 bcrypt 哈希。启用基本认证时至少需要一个用户；启用网页认证时至少需要一个用户或第三方登录身份；
- 第三方登录：支持 GitHub、Google、QQ、OIDC，使用自己的 OAuth 应用。允许的身份每行一条，格式 `提供方标识:账号`，例如 `github:octocat`、`google:me@gmail.com`，行尾可用 `#` 加备注，`github:*` 表示该提供方的任意账号。

第三方登录的提供方在「全局设置」中配置：填写自己的 Client ID / Secret 并启用，同时设置回调地址（需由 Gately 的某个监听提供，例如 `https://auth.example.com`）。登记到 GitHub / Google / QQ 的回调 URL 为：

```text
https://auth.example.com/__gately_auth/oauth/callback
```

管理后台自身的第三方登录在「设置 → 账号与安全」中单独配置。

### 转发认证（Authelia 等）

把认证交给外部服务，相当于 nginx 的 `auth_request` 或 Traefik 的 `forwardAuth`。在「安全」页勾选「转发认证」；同一站点不能同时启用基本认证或网页认证。

| 字段 | 说明 |
| --- | --- |
| `url` | 校验接口，例如 Authelia 的 `http://127.0.0.1:9091/api/authz/auth-request` |
| `loginUrl` | 接口返回 401 时把访客跳转到的地址，例如 `https://auth.example.com/?rd={url}&rm={method}`；`{url}` 为原始地址（已编码），`{method}` 为请求方法。留空时原样返回接口的响应 |
| `loginFromLocation` | 未填 `loginUrl` 时，接口返回 401 且 `Location` 为唯一的 http(s) 绝对地址时把访客 302 跳转到该地址，并传递 `Set-Cookie` 与 `Cache-Control`，适用于在 401 中给出动态登录地址的服务（如 Casdoor 原生 `/api/forward-auth`）；其他形式的 `Location` 不跳转，按 401 原样返回。默认关闭 |
| `copyHeaders` | 校验通过后从接口响应复制到后端请求的身份头，默认 `Remote-User`、`Remote-Groups`、`Remote-Email`、`Remote-Name` |

工作方式：

- 每个请求先以不带请求体的 GET 发到 `url`，带上访客的请求头（Cookie、`Authorization` 等），以及 `X-Original-Method`、`X-Original-URL`、`X-Original-URI`、`X-Forwarded-Method`、`X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-Uri`、`X-Forwarded-For` 与 `X-Real-Ip`，超时 10 秒；
- 返回 2xx 即放行，并带上身份头；返回 401 时跳转到 `loginUrl`（状态码 302）；其他结果（如 403 或跳转）原样返回给访客；接口无法连接时返回 502；
- 访客自带的身份头一律删除，无法伪造；
- 可与路径规则和「认证范围」配合，只让部分路径（如 `/admin`）需要登录，也可与临时分享链接配合。

### 共享用户：TOTP 与单点登录 {#shared-users}

账号只需定义一次，就能用于多个站点，并可选启用 TOTP 二次验证，覆盖了很多人使用 Authelia 的主要目的。

在侧边栏「Web → 认证用户」页面中（Web 服务的全局设置对话框只显示摘要和入口）：

- 添加用户名与密码；密码以 bcrypt 哈希保存，接口不会返回。要启用 TOTP，点「启用 TOTP」，用验证器 App（Google Authenticator、1Password 等）扫描二维码并保存；重新生成会使旧密钥失效；
- 可选填写邮箱、显示名和分组，[OIDC 单点登录](/docs/modules/oidc) 会把它们作为 `email`、`name`、`groups` 声明提供给应用，OIDC 客户端的允许用户可用 `group:分组名` 按分组授权；
- 单点登录域，例如 `example.com`：在该域或其子域名下的任一站点登录后，其他站点无需再登录。它使用父域 Cookie（`gately_sso`，有效期 7 天），不会转发给后端。留空则每个站点单独登录。

在站点的「安全」页，在网页认证或基本认证旁勾选「使用共享用户」；站点自有的用户仍然可用。也可以在「认证用户」页面的站点列表中按监听查看、筛选并批量勾选：未开启认证的站点勾选后会同时开启网页认证；只通过共享用户认证的站点取消勾选后会标记「保存后关闭认证」，保存时列出这些站点确认，确认后站点的认证一并关闭、变为无需登录即可访问；使用转发认证的站点不能使用共享用户。页面上的用户、OIDC 与站点修改点底部的「保存」后一起生效，任一项校验失败时都不保存，有未保存的修改时离开页面会先确认。

行为说明：

- 只要有共享用户启用了 TOTP，登录页就会显示验证码输入框，每个验证码只能使用一次；
- 修改用户的密码或 TOTP 密钥后，该用户已有的会话立即失效；
- 基本认证只接受未启用 TOTP 的共享用户，因为浏览器的密码弹窗没有地方输入验证码；
- 失败次数与其他登录共用同一套限流与自动封禁。

要让 Gitea、OpenList、Grafana 等应用识别登录的是哪个用户，可以把共享用户通过 [OIDC 单点登录](/docs/modules/oidc) 提供给应用。

### 自助修改密码 {#self-service-password}

在「认证用户」页面打开「自助修改密码」后，共享用户可以自己修改密码，不必找管理员：

- 在开启了「使用共享用户」的站点访问 `https://站点域名/__gately_auth/password`，登录页也会显示「修改密码」入口；使用 [OIDC 单点登录](/docs/modules/oidc) 的用户在签发者域名访问 `/__gately_oidc/password`；
- 输入用户名、当前密码和两次新密码（8～128 个字符，且与当前密码不同）；启用了 TOTP 的用户还需填写动态验证码；
- 修改后该用户在各站点的会话立即失效，需要用新密码重新登录；已签发的 OIDC 刷新令牌作废，旧 Access Token 也不能再读取用户信息，但应用自行校验的令牌在到期前仍有效，应用自己的登录会话也不受影响；
- 同一账号修改成功后 1 分钟内不能再次修改，避免反复修改让 FTP、SMB 不停重新载入、断开其他人的连接；保存时被服务检查拒绝的详细原因只写入 Web 服务日志，页面只提示联系管理员；
- 当前密码或验证码错误与登录失败共用同一套限流与自动封禁，其他网站代为提交的表单会被拒绝；Web 服务日志会记录修改的用户与来源 IP；
- 同一页面也可以修改[文件服务共享用户](/docs/modules/tools#shared-users)的密码，两种账号分别开关，都打开时页面上可切换账号类型；同名的两种账号互不影响。

## 访问控制

### IP 黑白名单

站点「安全」页的「IP 访问控制」可选关闭、白名单、黑名单，列表每行一个 IP 或网段（如 `192.168.1.0/24`），还可以同时引用订阅的 IP 列表。

站点「安全」页的「优先拒绝名单」（`ipDenyList` / `ipDenySets`）与访问控制模式无关：命中的来源一律拒绝，先于白名单、黑名单判断，路径规则也无法覆盖，同时在白名单中的地址同样被拒绝。要“先黑后白”时，把订阅的恶意 IP 情报列表放进优先拒绝名单，再用白名单放行自家网段。

### 拒绝方式

站点「安全」页的「拒绝方式」决定被封禁、IP 访问控制（含路径规则）或国家过滤拒绝的请求如何处理：默认「返回 403」；选择「断开连接」时不返回任何内容直接断开，访问日志记为 444，与断开连接站点相同。配合白名单即可实现“自家 IP 正常访问、其余一律断开”。限流（429）与 WAF 拦截不受影响。

默认站点同样可以这样配：类型选「反向代理」并填写后端，IP 访问控制选白名单或黑名单（可引用下文的订阅 IP 列表），拒绝方式选「断开连接」。白名单命中或黑名单未命中的请求代理到后端，其余直接断开；订阅列表刷新后立即生效。「断开连接」站点类型没有后端，对所有请求一律断开。

断开连接（无论是站点类型还是拒绝方式）只是不返回 HTTP 内容，无法隐藏服务存活：

- TCP 握手已经完成，对方能确认端口在监听；
- HTTP/1.x 下关闭连接，HTTP/2、HTTP/3 下只重置这个请求，连接保持，对方可以继续复用；
- HTTPS 下，未配置证书的域名在 TLS 握手阶段就会失败，能到达默认站点的请求已经拿到证书，证书中的域名已经暴露。

要让扫描者之后只看到超时，需由[入侵防护](/docs/modules/guard)封禁其地址，开启防火墙同步后在内核层丢弃其流量。

### 订阅 IP 列表

在「全局设置 → 订阅 IP 列表」添加列表：填写下载地址与刷新间隔（默认 24 小时），下载地址（如 GitHub）直连不通时可在「下载代理」中选择全局更新代理或填写代理地址，Gately 会定时下载并缓存到配置目录，重启后无需联网即可使用。内容每行一个 IP、CIDR 或 `起始-结束` 范围，`#`、`;`、`//` 之后为注释。例如省市 IP 段可使用 [metowolf/iplist](https://github.com/metowolf/iplist) 的 `https://metowolf.github.io/iplist/data/cncity/440000.txt`（广东省）。

- 站点与路径规则的白名单、黑名单可以引用多个列表，与手填的 IP 段一起判断，命中任意一项即视为在名单中；
- 下载内容无法识别（例如返回了错误页面）时保留上次的列表，并在列表上显示原因，一小时后重试；
- 列表下载成功前按空列表处理：白名单因此拒绝访问，黑名单不额外拦截；
- 停用仍被引用的列表后，引用它的白名单拒绝全部来源，黑名单不再拦截任何来源；
- 删除仍被引用的列表会被拒绝。

### 路径规则

在「安全」页的「路径规则」中，按路径前缀覆盖站点的认证与 IP 设置：

| 字段 | 取值 |
| --- | --- |
| `prefix` | 以 `/` 开头的路径前缀，如 `/admin` |
| `auth` | 沿用站点（空）、`off`（无需认证）、`on`（必须认证） |
| `ipMode` / `ipList` | 沿用站点（空）、`whitelist`、`blacklist`，并附 IP 或网段列表 |

匹配规则：

- 最长前缀优先；
- 按路径段边界匹配，`/admin` 匹配 `/admin` 与 `/admin/x`，`/administrator` 不匹配；
- 请求路径先规范化（消除 `.`、`..` 与重复斜杠）再匹配，`/public/../admin` 按 `/admin` 处理；
- 同一前缀只能配置一条规则。

「认证范围」选项（`authOptional`）：勾选后，认证只作用于规则中标记为「必须认证」的路径，其余路径公开。该选项需要先启用基本认证或网页认证。

「后台登录免认证」选项（`adminPass`）：勾选后，已登录 Gately 管理后台的管理员访问本站点（基本认证或网页认证）不再需要认证。前提是在[共享用户](#shared-users)中设置了单点登录域，并且管理员通过该域下的站点访问后台（直接用 IP 与端口访问后台不会产生凭据）：管理员访问后台时，站点向单点登录域写入 `gately_admin` 凭据，它只在站点认证处使用，不转发给后端应用，也不能调用管理接口。凭据绑定那一次后台会话，登出、退出所有设备、修改密码或会话过期后立即失效，只读账号不会获得。放行的访客身份记为 `gately:用户名`，站点自己的账号照常可用。

站点与后台不在同一个父域时（例如后台在 `vanjay.cn`，站点在 `thevast.uk`），单点登录域覆盖不到，可在全局设置里填写「后台入口地址」（如 `https://admin.vanjay.cn:4433`，协议加域名，可带端口，不带路径；该域名必须是本实例某个站点的域名，后台经它访问）。开启「后台登录免认证」的站点（精确域名）在浏览器打开页面且没有认证时，会先跳到入口确认后台登录态，再带一张一次性票据跳回，站点据此写入只属于自己域名的凭据，之后的访问不再跳转。票据只含 128 位随机编号（凭据本体不出现在网址里），60 秒有效、只能使用一次，并绑定来源站点与发起握手的浏览器；入口只接受本实例开启该选项的站点作为跳转目标，通配域名与默认站点不参与。没有登录后台的访客打开这些站点时也会被跳转到入口，能看到后台域名；每个浏览器两分钟内最多跳转一次。脚本、API 客户端等非页面访问不跳转，仍使用站点自己的认证。

「信任已登录用户」选项（`trustAuthUsers`）：勾选后，已通过本站点 Gately 认证的访客不经过 WAF，请求也不计入入侵防护的 Web 路径探测，用于 WAF 或 404、诱饵路径规则误拦自己人的情况。只认 Gately 自己签发的凭据：网页认证与第三方登录的会话、共享用户的单点登录、基本认证（基本认证的凭据在首次验证通过后才被信任，修改密码或删除用户后立即失效）；转发认证、分享链接不算。第三方登录只信任允许列表中逐个列出的身份（按账号或其别名匹配，如 GitHub 数字 ID、OIDC 的 sub）；经 `github:*` 这类通配允许的身份照常登录访问，请求仍经过 WAF 与路径探测，因为通配允许的是任何能在该提供方注册账号的人。已封禁的地址、IP 与国家访问控制、限流照常生效，登录失败照常计数。该选项需要先启用基本认证或网页认证；开启后登录用户的请求不再受 WAF 保护，只在用户可信时开启。

双层 Gately（外层如 VPS 上的 Gately 只做 WAF 并反向代理，内层 Gately 负责登录）时，外层无法校验内层签发的会话，可改用认证标记：两端在 Web 服务全局设置中填写相同的「认证标记密钥」（至少 16 个字符，可点「生成」后复制到另一端）；内层站点开启「信任已登录用户」，外层反向代理站点勾选「转发 Gately 登录 Cookie」与「信任后端认证标记」（`trustBackendAuth`，本站点不启用认证时可用）。内层对受信任的已登录用户在响应头 `X-Gately-Auth` 中返回签名标记，标记绑定该请求所用凭据（会话 Cookie 或 Authorization 头）的哈希，5 分钟有效、每次响应续签；外层校验签名并确认绑定的正是本次请求的凭据后，该凭据之后的请求不经过外层 WAF、不计入路径探测。同一凭据的第一个请求仍经过外层 WAF（WAF 在请求转给后端之前检查）。配置了密钥的 Gately 会去掉后端应用写出的同名头，标记也不会返回给访客；标记被截获或被缓存重放无法给别的凭据放行。修改或清空密钥后，外层之前的放行立即失效；内层的会话失效后，外层最多在 5 分钟内仍对该凭据跳过 WAF，请求本身仍由内层认证拦下。

### 临时分享链接

启用基本认证或网页认证后，可为站点创建分享链接，让访客免账号访问：

| 字段 | 说明 |
| --- | --- |
| 名称 | 备注名，如「给张三」 |
| 过期时间 | 留空为不过期 |
| 可用次数 `maxUses` | 最多可被兑换的次数，0 为不限；重启后计数清零 |
| 路径限制 `pathPrefix` | 非空时，链接只能访问该前缀下的路径，需以 `/` 开头 |

访客访问 `https://域名/任意路径?_gs=令牌` 即可兑换会话。兑换成功后服务端设置免登录 Cookie 并跳转到去掉 `_gs` 参数的地址，会话最长 24 小时，且不超过链接的过期时间。令牌无效时按普通访问处理，不透露失败原因。删除链接后已发出的会话立即失效。令牌在保存后生成（至少 16 位），可在界面复制完整链接。

### 认证失败限流与自动封禁

- 同一来源 IP 在 15 分钟内认证失败累计 10 次后，暂时拒绝继续尝试；
- 「全局设置 → 自动封禁 → 认证失败封禁」填写分钟数（0 至 43200），达到 10 次失败时封禁来源 IP；填 0 表示不封禁，仅限流；
- 自动封禁触发时发布 `AuthBanned` 事件，可经 [通知中心](/docs/modules/notify) 推送；
- IPv6 地址按 /64 网段聚合计数与封禁。

### 封禁列表

「全局设置」中的封禁列表显示当前被封禁的 IP、原因（认证连续失败或手动封禁）和到期时间，可点击「解除」。也可手动封禁：填写 IP 与小时数（1 至 720，即最长 30 天），接口默认时长为 24 小时。回环地址与可信代理中的地址不能手动封禁，原因见下文「断开并封禁」。勾选「永久」则不设到期时间（接口 seconds 为 -1）。

封禁列表与[入侵防护](/docs/modules/guard)共用同一张表：开启入侵防护模块时，这里只显示封禁数量，并跳转到入侵防护页面管理。封禁同样对端口转发、STUN 等服务生效，开启防火墙同步后会在系统防火墙中丢弃；开启「忽略内网地址」时，内网地址不会被自动封禁。

### GeoIP 国家过滤

站点「国家过滤」有三种模式：关闭、仅允许、拒绝，并填写两位 ISO 国家代码（逗号分隔，如 `CN, HK, US`）。启用时至少填写一个国家。

- 过滤依赖 GeoIP 数据库，需先在「全局设置 → GeoIP 数据库」导入：上传 `.mmdb` 文件，或填写下载地址（「下载代理」默认使用全局更新代理，未设置更新代理时直连）。支持 MaxMind GeoLite2、DB-IP 等国家库或城市库；上传限制 129 MB；
- 数据库未加载时过滤不生效（放行所有访客），界面会提示；
- 内网地址始终放行；
- 「拒绝」模式下，库中查不到国家的地址放行。

## 按路径分流后端

为反向代理站点把某个路径前缀下的请求发到其他后端，相当于 nginx 的 `location /api/ { proxy_pass ...; }`。在站点编辑框「基本」页的「分路径后端」中添加。

| 字段 | 说明 |
| --- | --- |
| `prefix` | 路径前缀，如 `/api/`。按路径段边界匹配：`/api` 与 `/api/` 都匹配 `/api` 和 `/api/x`，不匹配 `/apix` |
| `targets` | 该路径的后端，写法与站点后端相同；留空时使用站点后端，只追加下面的请求头 |
| `requestHeaders` | 该路径追加的请求头，每行 `Key: Value`；在站点请求头之后应用，同名时以路径的为准 |
| `stripPrefix` | 开启后转发时去掉路径前缀：`/api/zyqd/abc` 发往后端为 `/abc`，相当于 nginx 的 `proxy_pass http://后端/;`。后端地址自带的路径会接在去掉前缀后的路径前面；查询串原样保留。默认关闭 |

- 最长前缀优先；默认路径原样转发，开启 `stripPrefix` 后去掉前缀再转发（路径先按 `//`、`.`、`..` 规范化再去前缀，不能借点段越过前缀）；
- 导入 nginx 时，`location /api/ { proxy_pass http://后端/; }` 这类带 URI 的 `proxy_pass` 会转换为开启 `stripPrefix` 的规则，URI 与前缀相同或没有 URI 时保持原样转发；
- 站点的其他设置，如 Host 选项、证书校验、转发头、PROXY 协议、负载均衡策略与健康检查，对每个路径后端同样生效；
- 压缩、限流、缓存与重写作用于整个站点。

## 按认证用户分流 {#user-routes}

为反向代理站点把不同登录用户的请求发到各自的后端，相当于 nginx 的 `map $remote_user $backend`。站点需要先启用基本认证、网页认证或转发认证，然后在站点编辑框「安全」页的「按用户分流」中添加规则：每条规则填写一组用户和这些用户的后端，后端写法与站点后端相同。

重定向、静态文件、导航面板与固定文本站点同样可以按用户分流：命中规则的用户反向代理到规则的后端，未列出的用户和公开路径上的未登录访客照常按站点类型处理，例如管理员进入后台、其他登录用户跳转到说明页或看到「无权访问」的固定文本。这时「基本」页的后端选项与「流量」页的负载均衡、后端超时、健康检查作用于分流到的后端，响应缓存仍只用于反向代理站点；断开连接站点不经过认证，不能按用户分流。

用户按以下标识匹配：

- 站点用户或[共享用户](#shared-users)的用户名；
- 第三方登录身份写 `提供方key:ID`，例如 `github:octocat`，该身份的其他标识同样能匹配；
- 转发认证从认证服务响应复制回来的 `Remote-User`。

转发规则：

- 未列出的用户，以及公开路径（无需认证的路径）上未登录的访客，使用站点后端；公开路径上已通过网页认证登录的访客同样按身份分流，同一应用的页面会落到同一后端；
- 填写了后端的分路径规则（见上一节）优先；只追加请求头的分路径规则改用该用户的后端；
- 启用内存响应缓存时，缓存键包含所选的用户路由，配置了[传递身份信息](#identity-headers)时还包含传出的身份信息，不同后端、不同用户的响应不会串用。

保存时检查：站点已启用认证；每条规则至少有一个用户和有效的后端；同一用户不能出现在两条规则中。站点列表中，配置了用户路由的站点显示规则条数标签。

### 传递身份信息 {#identity-headers}

「传递身份信息」把认证用户的身份写入请求头传给后端，适合按请求头识别用户的应用，例如 Firefly III 用 `Remote-Email` 识别账号。每行选择一个字段并填写请求头名：

| 字段 | 常用请求头 | 来源 |
|---|---|---|
| 用户名 | `Remote-User` | 站点用户或共享用户的用户名；第三方登录为 `提供方key:ID`；转发认证为 `Remote-User` |
| 邮箱 | `Remote-Email` | 共享用户的邮箱，或转发认证复制回来的 `Remote-Email` |
| 显示名 | `Remote-Name` | 共享用户的显示名，或转发认证复制回来的 `Remote-Name` |
| 分组 | `Remote-Groups` | 共享用户的分组（逗号分隔），或转发认证复制回来的 `Remote-Groups` |

- 「添加常用 Remote-* 请求头」按上表一次补齐当前认证方式可传的字段；
- 邮箱、显示名、分组只有使用[共享用户](#shared-users)或转发认证的站点可选，站点用户与第三方登录只有用户名；共享用户修改信息后，已登录的会话立即传新值；与共享用户同名的站点用户按站点用户密码登录时只传用户名；
- 转发认证只认复制回来的头：复制头列表中没有 `Remote-Email` 等时，访客自带的同名头不会被当作身份信息；认证服务没有返回 `Remote-User` 时，其他信息也不传；
- 访客自己发送的同名请求头总是被删除，包括用下划线代替连字符的写法（如 `Remote_Email`），无法伪造；未登录或经分享链接访问时不传任何身份信息，某项信息为空时不传该请求头；
- 保存时检查：请求头名合法且不重复（不区分大小写，`-` 与 `_` 视为相同）；不能是 `Host`、`Cookie`、`Authorization`、`X-Forwarded-For` 等影响转发或认证的请求头；不能与站点或分路径规则的请求头设置同名，否则这些设置会覆盖认证结果；最多 16 条；
- 旧版本的「传递用户名」在编辑站点时显示为一行用户名，保存后并入此列表。

## 反向代理增强

这些选项位于站点编辑框的「流量」页。

### 后端、权重与备用

后端列表每行一个地址，地址后可附参数：

```text
http://10.0.0.2:8080 weight=3
http://10.0.0.3:8080 backup
```

- `weight=N`：权重，1 至 100 的整数，默认 1；
- `backup`：备用后端，仅在所有非备用后端都不可用时启用；全部后端都不可用时回退到所有非备用后端继续尝试。
- 连不上某个后端（连接被拒绝、不可达或连接超时）时，同一请求立即换下一个后端重试，先试其他主后端再试备用后端，最多尝试 3 个后端；这时请求尚未发出，POST 等请求重发也安全。连接建立后的失败不重试，失败的后端照常计入被动检查。

### 负载均衡策略

| 界面选项 | `lbPolicy` | 说明 |
| --- | --- | --- |
| 轮询（按权重） | 空 | 默认 |
| 随机（按权重） | `random` | |
| IP 哈希（会话保持） | `ip_hash` | 同一客户端 IP 落到同一后端 |
| 最少连接 | `least_conn` | 按「连接数 / 权重」选择最小者 |

### 健康检查

主动检查开关默认关闭。启用后的字段与默认值：

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| 方式 `mode` | `http` | `http`（请求检查路径，状态码小于 400 视为健康）或 `tcp`（只测试连接） |
| 路径 `path` | `/` | 以 `/` 开头，仅 http 方式 |
| 间隔 `interval` | 10 秒 | 1 至 3600 |
| 超时 `timeout` | 3 秒 | 1 至 60 |
| 连续失败 `fails` | 3 次判不可用 | 1 至 20 |
| 连续成功 `passes` | 2 次恢复 | 1 至 20 |

启用向后端发送 PROXY 协议时，HTTP 检查自动改用 TCP。

被动检查始终生效：多个后端中，连续 3 次连接失败的后端暂停 30 秒后再试探（只有一个后端且未启用主动检查时不摘除）。启用主动检查后，恢复完全由检查结果决定。后端状态变化时发布上游不可用 / 已恢复事件，可经 [通知中心](/docs/modules/notify) 推送。

### 后端超时 {#backend-timeouts}

反向代理站点连接后端的超时，单位为秒，填 0 使用默认值。分路径后端与按用户分流的后端使用同一组设置。

| 字段 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| 连接 `timeouts.connect` | 10 秒 | 1 至 300 | 与后端建立 TCP 连接 |
| TLS 握手 `timeouts.tlsHandshake` | 10 秒 | 1 至 300 | 与 HTTPS 后端完成 TLS 握手 |
| 等待响应头 `timeouts.responseHeader` | 不限 | 1 至 86400 | 请求（含请求体）发完后等待后端返回响应头 |

- 等待响应头只限制响应头到达之前的时间，之后的响应体传输、文件下载以及 WebSocket、SSE 等长连接不受影响；上传大文件时从请求体发完才开始计时；
- 超时返回 504（网关超时），连接被拒绝等其他错误返回 502；超时与连接失败一样计入被动检查；
- 后端启动慢或经慢速链路访问时调大连接超时；希望卡住的后端尽快报错时设置等待响应头超时。

### 访客超时 {#client-timeouts}

对访客的读写空闲超时，单位为秒，填 0 使用默认值 60 秒（与 nginx 的 `client_body_timeout`、`send_timeout` 默认值相同），断开连接以外的站点类型都可设置。

| 字段 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| 读取请求体 `clientTimeouts.readIdle` | 60 秒 | 1 至 3600 | 一次读取请求体最多等待的时间 |
| 写出响应 `clientTimeouts.writeIdle` | 60 秒 | 1 至 3600 | 一次写出响应最多等待的时间 |

- 只在一次读取或写出卡住时计时：数据持续传输的大文件上传下载、等待后端处理的时间以及 WebSocket 等长连接都不受影响；
- 用于断开极慢地发送请求体或读取响应的访客（slowloris、slow read），避免它们长期占住连接；
- 读取请求体超时返回 408 并关闭连接，不计入后端的被动检查；写出超时直接断开连接；
- HTTP/1、HTTP/2 与 HTTP/3 都生效。

### 压缩

对反向代理、静态文件、固定文本站点可启用压缩（重定向站点除外）。按 `Accept-Encoding` 优先选择 `br`，其次 `gzip`。

- 仅压缩文本类内容：`text/*`、JSON、JavaScript、XML、XHTML、RSS / Atom、WebAssembly、SVG；`text/event-stream` 排除在外；
- 声明的 `Content-Length` 小于 256 字节的响应保持原样；
- 已有 `Content-Encoding` 的响应保持原样；WebSocket 升级请求直接放行；
- 压缩后强校验 ETag 改为弱校验。

### 按 IP 限流

按客户端 IP 的令牌桶限流，字段：

| 字段 | 说明 |
| --- | --- |
| `rate` | 每秒允许的请求数 |
| `burst` | 突发容量；设置了 `rate` 而 `burst` 为 0 时自动取 `rate` 取整加 1 |
| `maxConns` | 单个 IP 的并发请求上限，0 为不限 |

启用限流时 `rate` 与 `maxConns` 至少设置一项。

### 内存响应缓存

仅对反向代理站点生效，缓存存放在内存中，LRU 淘汰。

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `ttl` 默认时长 | 0 | 0 至 30 天（秒）。上游未声明缓存指令时，200 响应缓存这么久；0 表示只缓存上游明确允许的响应 |
| `maxMb` 缓存容量 | 64 | 1 至 4096 MB |

缓存规则：

- 仅缓存 GET 请求，且请求不含 `Range` 头与 `Cache-Control: no-cache`；
- 带凭据的请求不缓存：请求头含 `Authorization`、`Proxy-Authorization`、`Cookie`、`X-Api-Key`、`X-Auth-Token`、`X-Access-Token`、`X-CSRF-Token`、`X-Emby-Token`、`X-Emby-Authorization`、`X-MediaBrowser-Token`、`X-Plex-Token`、`X-Jellyfin-Token` 之一，或查询串含 `api_key`、`X-Plex-Token`、`token`、`access_token` 参数（参数名不区分大小写）；
- 原始请求路径含 `;`、`\`、`%2F` 或 `%5C`（不区分大小写）的请求不缓存，这类路径经规范化后与后端的理解可能不同；
- 仅缓存状态码 200 的响应；响应含 `Set-Cookie`、`Vary: *`，或 `Cache-Control` 为 `no-store` / `private` / `no-cache` 时跳过；
- 响应的 `Vary` 只能包含 `Accept-Encoding`，站点开启跨域时还可以包含 `Origin`，含其他请求头时不缓存；后端自己返回的 `Access-Control-Allow-Origin` 不是 `*` 时不缓存；
- 站点开启跨域时，缓存的条目不保存 Gately 按访客来源写入的跨域头，命中时按本次请求的 `Origin` 重新生成；
- 遵循 `s-maxage`，其次 `max-age`；
- 单个条目上限为 4 MB，同时不超过总容量的四分之一；
- 命中时返回头 `X-Cache: HIT` 与 `Age`，未命中为 `X-Cache: MISS`；
- 缓存键包含 Host、完整请求 URI 与 `Accept-Encoding`；配置了[按认证用户分流](#user-routes)时还包含所选的用户路由，配置了[传递身份信息](#identity-headers)时还包含传出的身份信息。

按路径缓存（`rules`，站点编辑框「流量」页签的「按路径缓存」，最多 200 条）：

| 字段 | 说明 |
| --- | --- |
| `path` | 匹配的路径，以 `/` 开头，不含空格、`?`、`#`，也不含 `.`、`..` 路径段、连续的 `/` 或 `%`（请直接填写解码后的路径，如 `/中文/*`），同一站点内不能重复，区分大小写。不含 `*` 时按路径段前缀匹配：`/api` 匹配 `/api` 与 `/api/x`，不匹配 `/apix`；含 `*` 时整条路径通配，`*` 匹配任意字符（包括 `/`），如 `/api/products/*`、`/static/*.js` |
| `noCache` | 开启即「不缓存」：该路径不读也不写缓存 |
| `ttl` | 缓存时长，0 至 30 天（秒）；0 为沿用站点默认时长 |
| `override` | 开启即「强制缓存」：忽略后端 `Cache-Control` 中的 `no-store`、`no-cache` 与 `max-age`，200 响应按缓存时长缓存，后端声明 `private` 时仍不缓存；规则与站点的时长至少一处大于 0 |

- 界面提供三种模式：「缓存」遵循后端的 `Cache-Control`，后端未声明时按时长缓存；「强制缓存」对应 `override`；「不缓存」对应 `noCache`；
- 更具体的规则优先：去掉 `*` 后字符更多的规则先匹配，相同时按配置顺序；未命中任何规则的路径使用站点默认设置。只想缓存指定路径时，可把 `/` 设为不缓存；
- 规则按规范化后的请求路径匹配，`//api`、`/x/../api` 等写法按 `/api` 处理；
- 任何模式下，上面列出的带凭据请求、路径含 `;` 等字符的请求，以及带 `Set-Cookie`、`Vary: *` 或 `Cache-Control: private` 的响应都不缓存；
- 强制缓存的响应由所有访客共用，只用于与访客身份无关的内容，例如静态资源；后端按来源 IP 免认证（例如内网访问不需要登录）时不要使用，否则内网访客看到的内容会被缓存给外网访客。

查看与清空缓存：编辑已保存的站点时，「流量」页签显示该站点运行中的缓存条目数与占用（「当前缓存」），可「刷新」「清空全部」，也可在某条规则上清空此路径的缓存。对应接口：

- `GET /api/webservice/cache?listener=&site=`：返回 `enabled`、`entries`、`bytes`、`maxBytes`；`site` 为站点标识，默认站点为 `default`；站点不存在或所属监听未运行时返回 404；
- `POST /api/webservice/cache/purge`，请求体 `{"listener", "site", "path"}`：`path` 留空清空整个站点的缓存，否则只清空路径命中的条目，写法与匹配方式同规则的 `path`；返回删除的条数 `removed` 与清空后的状态；站点未启用缓存时返回 400。

### 路径重写与重定向

规则按顺序匹配，命中第一条即停止。

| 字段 | 说明 |
| --- | --- |
| `pattern` | 匹配请求路径的正则表达式，如 `^/old/(.*)$` |
| `to` | 替换结果，可用 `$1` 引用分组 |
| `redirect` | 关闭为内部重写（重写后的路径发往后端，目标需以 `/` 开头）；开启为重定向 |
| `code` | 重定向状态码 301 / 302 / 307 / 308，默认 302 |

重定向会保留原查询参数。重定向目标中可以写 `{host}`，表示访客使用的域名。重定向规则先于认证执行，相当于 nginx 的 `location = / { return 302 ...; }`，所以 `/` 这类路径可以直接把访客送走，不要求先登录。

## 错误页 {#error-pages}

站点编辑框的「错误页」页签决定访客看到的 404 与 5xx 页面。默认使用 Gately 自带的样式，可以换成 10 种内置风格之一（极简、终端、霓虹、星空、报刊、粗野、极光、像素、蓝图、状态链路），也可以使用自己的页面。所有风格都适配手机屏幕，文案按访客浏览器的语言显示，卡片右下角的眼睛按钮可按不同状态码与桌面、手机尺寸预览。

- 作用范围：Gately 为站点生成的 404 与 5xx 页面，例如连不上后端时的 502、静态文件不存在时的 404、重定向目标暂不可用时的 503、转发认证服务不可用时的错误。静态站点填写了「404 页面」时，找不到文件仍优先使用它。访问控制拒绝时的 403 与限流的 429 不受影响。
- 默认站点：其设置同时用于没有任何站点匹配访问域名时的 404，默认站点未启用时同样生效。
- 浏览器以外的客户端（`curl`、接口调用等）仍得到纯文本错误，与原来一致。

### 拦截后端错误 {#intercept-errors}

反向代理站点可以开启「拦截后端错误」，把后端返回的指定状态码换成上面选择的页面，相当于 nginx 的 `proxy_intercept_errors on` 加 `error_page`。状态码用逗号分隔，支持范围与简写，例如 `404, 500-599` 或 `5xx`，只能填写 400~599。

- 只替换浏览器打开页面的请求（`Accept` 含 `text/html`），接口、图片、脚本等请求保持后端原样，单页应用的 JSON 404 不会被换成网页。
- 状态码与 `Set-Cookie`、`Retry-After` 等响应头保留，描述原响应体的头（压缩编码、`ETag` 等）去掉；`HEAD` 请求只返回响应头。
- 「批量选项」可以一次修改多个站点的错误页样式，各站点的拦截设置保持不变。

### 自定义页面 {#custom-error-pages}

自定义页面保存在页面库中，在「全局设置 → 自定义错误页面」或站点「错误页」页签的「管理自定义页面」中维护，多个站点可以共用同一个页面。页面有两种来源：

- 上传或粘贴：选择 `.html` / `.htm` 文件（UTF-8 编码，不超过 256 KB）或直接粘贴代码，内容保存在配置中，可继续修改。
- 服务器文件：填写 `.html` / `.htm` 文件的绝对路径（Docker 中为容器内路径），每次使用时检查文件是否变化。符号链接指向的也必须是 HTML 文件，内容不像 HTML 的文件会被拒绝；文件被删除或内容无效时访客看到默认样式，页面库中标为不可用。

页面中可以使用占位符，输出时替换为本次错误的信息，并做 HTML 转义：

| 占位符 | 内容 |
| --- | --- |
| `{code}` | 状态码，如 502 |
| `{status}` | 英文状态短语，如 Bad Gateway |
| `{title}`、`{detail}` | 错误标题与说明，按访客语言 |
| `{host}`、`{path}` | 访问的域名与路径 |
| `{time}` | 发生时间（UTC） |

保存前会自动检查安全性与可用性，并显示预览：

- 错误页与站点同源，为防止页面被用来窃取 Cookie 或伪造操作，保存时会去掉脚本、`onclick` 等事件属性、`javascript:` 链接、内嵌框架、插件对象、表单、`<base>`、`<meta http-equiv>`（自动跳转等）与危险的样式写法，检查结果中列出去掉的内容。
- 输出时附加 `Content-Security-Policy: sandbox; default-src 'none'; ...`：页面运行在独立的沙箱中，即使混入脚本也无法执行；除内联样式与 `data:` 内嵌的图片、字体外不加载任何资源，访客的地址不会泄露给第三方。外部样式表、图片、字体以及站内的相对地址都不会加载，检查时会提示，请把样式写进 `<style>`、图片与字体改为 `data:` 内嵌。
- 内容为空、不是 UTF-8、超过大小或不是 HTML 时拒绝保存；缺少 `viewport`、编码声明不是 UTF-8、没有使用占位符时给出提示。

## 访问统计与监控

### 站点统计 {#site-stats}

运行中的监听，在站点行点击「统计」打开统计窗口，可选最近 1 小时、6 小时、24 小时：

- 分钟级访问统计：每分钟一个点，保留最近 24 小时，包含请求数曲线与 4xx / 5xx 错误曲线；
- 首字节延迟：每分钟的 P50 / P95 曲线与所选时段的最高 P95。延迟为请求到达到响应头发出的时间，不含响应体传输，WebSocket 等协议升级请求、被断开的请求不计入；每档内取平均耗时估算分位数。阈值告警见[性能监控](/docs/modules/perf)；
- 状态码分布 2xx / 3xx / 4xx / 5xx，累计响应流量；
- 来源 IP Top 10 与国家 Top 10（国家统计需要已导入 GeoIP 数据库）；
- 反向代理站点显示每个后端（含分路径与按用户分流的后端，标注路径或用户）的健康状态、权重、是否备用、当前连接数与累计转发请求数；
- 有请求被拦截时，按原因列出累计拦截次数：已封禁、IP 名单、国家过滤、限流、WAF（认证失败不计入）。

统计保存在内存中，重启或修改该监听自身的设置后重新计数；修改站点会保留其计数。排行榜最多统计 5000 个不同来源。

### 实时连接 {#connections}

运行中的监听，站点行（含默认站点）的统计后面显示「进行中 N」，即该站点正在处理的请求数，随页面刷新。点击「连接」打开连接窗口，窗口每 2 秒自动刷新，可按 IP 搜索：

- **实时连接**：来源地址与端口、协议（h1 / h2 / h3，WebSocket 标记为 WS）、请求（方法、域名与路径，不含查询串）、开始时间、已持续时间与流量（下行；有请求体或 WebSocket 时还有上行）。按已持续时间从长到短排列，最多显示 500 条。配置了[可信代理](#real-ip)时来源为访客真实地址，并注明经由的代理地址。
- **历史记录**：最近结束的连接，含开始与结束时间、持续时间、流量与结果（已完成 / 已断开）。只记录持续 1 秒以上或被手动断开的连接，每个站点保留最近 200 条，重启后清空；短请求请查看访问日志。

列表按进行中的请求统计：HTTP/1.1 长连接在两次请求之间不属于任何站点，HTTP/2、HTTP/3 的一条连接可以同时承载多个请求，所以以请求为单位才能准确归属到站点；已升级的 WebSocket 会一直列出，直到连接关闭。

每行的「断开」在确认后立即结束这个请求：HTTP/1.x 关闭整条连接，HTTP/2、HTTP/3 只重置这个请求，同一连接上的其他请求不受影响；已升级的 WebSocket 连同后端连接一起关闭。访客不读取数据导致发送阻塞时同样立即生效。被断开的请求在访问日志中记为 444（已开始响应时保留原状态码），不计入后端错误与路径探测。访客可以马上重新连接，需要阻止时使用「断开并封禁」：把来源地址（IPv6 为所在 /64 网段）加入[封禁列表](#封禁列表)，并断开它在全部监听、全部站点上进行中的请求。回环地址（经 frp、未带 PROXY 协议的本机转发进来的请求都显示为它）和可信代理中的地址（IPv6 按 /64 判断）不能封禁，这类地址封禁后会拦截一大批无关访客；只断开不封禁不受此限制。封禁时长可填 1 至 720 小时，或勾选「永久」。

只读账号与只读令牌可以查看连接列表，断开与封禁需要写权限，并记入审计日志。

### 网络拓扑 {#topology}

左侧菜单「Web → 网络拓扑」是单独的页面（`#/webtopology`），Web 服务页页头的「网络拓扑」按钮也可以进入。图中按 互联网 → Gately → 监听 → 站点 / 监听级动作 → 后端 / 去向 展开，每 2 秒刷新，页面切到后台时暂停，画布配色跟随当前皮肤的亮暗：

- **节点**：监听显示地址与运行状态，启动失败标红；站点显示匹配方式（精确、通配、任意域名、默认站点）、QPS 与进行中请求数；反向代理站点展开为全部后端，包括分路径与按用户分流的后端（标注路径或用户），不可用的后端标红；重定向、静态文件、固定文本与断开连接站点各有一个去向节点。默认站点断开连接、HTTPS 端口收到明文请求时跳转（301 / 308）、没有站点匹配且未启用默认站点时返回 404，这几类是预期配置，以灰色显示。停用的监听与站点同样列出，显示为未运行。
- **连线**：粗细随 QPS 增长，有流量的连线播放流动动画。连线超过 120 条时只有高亮链路播放动画；系统开启「减少动态效果」时不播放。
- **高亮**：悬停或点击节点，它所在的整条链路（向上到互联网、向下到后端）高亮，并在连线上标出 QPS 与流量，其余节点变暗；点击空白处恢复。
- **详情面板**：所选节点的 QPS（最近 10 秒均值）、60 秒均值、下行流量、进行中请求、累计请求、后端错误、按原因的拦截次数、响应状态分布、近 60 秒每秒请求数与流量曲线，以及经过该节点的活动 IP。每项指标旁的 ⓘ 说明口径。站点可以从面板直接打开统计、连接、访问日志与编辑窗口，后端可以打开所属站点的访问日志与编辑窗口，监听可以直接编辑。
- **查看访问日志**：选中站点或后端节点后点「访问日志」，打开只含该站点的访问日志（按站点名称完整匹配，不会混入名称相近的站点）；已在顶部按某个 IP 筛选时按钮变为「该 IP 的访问日志」，同时按这个地址过滤。详情面板活动 IP 每行右侧的日志图标直接查看该地址在所选站点的访问日志，选中的不是站点类节点时查看该地址在全部站点的访问日志。日志窗口中的过滤条件可以继续修改，站点条件显示为可移除的「站点：…」标签。窗口同时按该站点所在的监听过滤，另一个监听上的同名站点（例如分别监听 IPv4 与 IPv6、都名为 HTTPS 的两个监听上的站点）不会混入，监听条件显示为可移除的「监听：…」标签。只有开启了访问日志的站点才有完整记录，未开启时窗口顶部给出提示；没有名称的站点按第一个域名过滤。Web 服务页每个站点行的「日志」按钮打开同样的窗口。
- **活动 IP**：最近 60 秒内有请求的访客地址，加上仍有进行中请求的地址。画布上只显示个数，完整地址列在详情面板。在顶部输入或选择一个地址（也可以点击面板中的地址），图中只高亮它走过的链路，精确到具体后端；「清除筛选」恢复。每个站点、后端与监听级动作最多记录 1024 个近期地址，接口一次最多返回 500 个，来源过多时面板提示列表不完整。配置了[可信代理](#real-ip)时这里是访客真实地址。
- **打码**：开关打开后按勾选的类别把地址显示为 `*`，便于截图分享，只影响拓扑页的显示，搜索仍按完整内容匹配。可选：访客 IP（活动 IP 列表与筛选框，IPv4 末段、IPv6 后 64 位）、后端地址（后端与跳转目标中的 IP 与主机名）、监听地址（监听 IP、监听错误信息、以 IP 为域名的站点）、域名（站点域名与站点名称中的域名，只保留第一段与后缀，如 `nas.***.com`）。默认勾选前三项，选择会被记住。
- **打码方式**：打码菜单顶部可选「星号」或「代号」。星号只遮住部分内容，保留网段与首尾；代号把整个值换成本页内一致的编号，访客 IP 显示为 `Visitor-01`，后端与跳转目标中的 IP 显示为 `Backend-01`，监听地址显示为 `Listen-01`，域名只保留后缀，可注册部分与主机部分分别编号，如 `nas.home.example.com` 显示为 `host-01.domain-01.com`，同一域名下的子域名共用 `domain` 编号。相同的值始终得到相同的代号，不同的值代号不同，图中仍能看出哪些节点相同。编号按出现顺序分配，只保存在当前页面，刷新后重新编号。
- **筛选**：右上角的「筛选」可以只看部分监听；「只看异常」只显示启动失败的监听（保留其全部站点）、已启用却未运行的站点与有后端不健康的站点，停用的监听与站点属于预期状态，不算异常；「有过拦截」按原因（封禁、IP 名单、国家过滤、限流、WAF）只显示自 Gately 启动以来出现过该原因拦截的站点。各条件同时生效，与页头搜索也可以组合；按异常或拦截筛选时隐藏监听级动作，没有剩余站点的监听一并隐藏。筛选只在本页有效，离开页面后恢复显示全部。
- **聚焦活动**：服务很多时点击右上角的「聚焦活动」，只显示最近 60 秒有请求、有进行中请求或有活动 IP 经过的站点与监听级动作，代理站点只保留活动中的后端（后端都没有请求时站点作为末端显示，如请求被访问控制拦截），没有活动的监听隐藏。此时监听折叠与「还有 N 个」收起不生效，画布自动适应让这些节点完整显示（树形、竖向与桑基最小 50%），服务开始或停止活动时随之更新。按钮上的数字是当前活动中的站点数，随筛选与搜索变化，未开启时也显示。可与筛选、搜索、按 IP 高亮和各种布局同时使用，开启状态按设备记住；最近 60 秒都没有请求时画布给出提示，点「显示全部」退出。
- **回放**：点击右上角的「回放」打开时间轴，回看过去某一时刻的拓扑。录制默认关闭，管理员在时间轴上点「开启录制」或在「录制设置」中开启。开启后每 5 秒把整张拓扑（速率、计数、后端健康、活动 IP）录成一帧，压缩后只保存在内存中，按「内存上限」（默认 8 MiB，可设 1–256）保留，超出时丢弃最旧的帧；内容不变的连续帧（如没有流量时）合并存储，所以流量小时能回看很久，流量大时回看的时间变短。时间轴按流量画出面积图，底部红色标出有监听启动失败或后端不健康的时段，深色为没有录制的时段（模块停用或没有运行中的监听）。点击或拖动时间轴定位，悬停查看当时的 QPS 与活动 IP 数；用按钮或键盘 ← → 逐帧移动，空格播放或暂停，播放速度 1×–60×，勾选「跳过空闲」后播放时越过没有流量和访客的时段；时间轴范围可选全部录制或最近 15 分钟到 24 小时，选择按设备记住。回放时七种布局、筛选、聚焦活动、打码与按 IP 高亮照常可用，详情面板的曲线为所选时刻之前 60 秒（每 5 秒一个点）；「连接」反映的是当前状态，回放时不显示。点「回到实时」退出。录制的数据含访客 IP，重启 Gately 或关闭录制后清空；采一帧约 0.4 毫秒（40 个站点、200 个活动 IP 实测），压缩后约 1–2 KB。
- **布局**：右上角的布局菜单有七种，选择会被记住，切换时淡入淡出并自动适应画布。「树形」从左到右排成五列，信息最完整；「竖向」从上到下展开，像组织结构图，打开时以 Gately 为中心，左右拖动查看；「径向」以 Gately 为圆心，监听、站点、后端依次分布在三层同心圆上，名称沿半径方向显示；「桑基」各节点是竖条，连线是流量带，父节点按子节点 QPS 的占比切分，竖条高度与带宽随流量变化，节点位置保持不动；「旭日」以 Gately 为圆心，监听、站点、后端是三层环形扇区；「矩形树图」与「气泡」把 Gately、监听、站点、后端逐层嵌套成方块或圆形，每个后端（或去向）面积相同。旭日、矩形树图与气泡没有连线，颜色越深流量越大，适合站点很多时总览。桑基、旭日、矩形树图与气泡的画布上没有折叠按钮，在监听的详情面板中折叠或展开。
- **收起多余节点**：每个监听默认显示前 8 个站点、每个站点前 6 个后端，其余合并为「还有 N 个站点 / 后端」节点，显示它们合计的 QPS 与进行中请求数；点击展开全部，展开后末尾的「收起」节点恢复。被收起节点上的活动 IP 计入这个汇总节点，按 IP 高亮时链路停在它上面。最近 60 秒有请求或有进行中请求的站点与后端不会被收起，超出上限也按原顺序直接显示，汇总节点里只剩空闲的，副标题显示「最近 60 秒无请求」。
- **平移、缩放与画布大小**：拖动画布平移，滚轮上下滚动（到达边缘后滚动页面）；按住 Ctrl/⌘ 滚动、触控板捏合或触屏双指捏合缩放（15%–250%），以指针或双指中点为中心。右下角可放大、缩小、恢复 100%、适应画布（显示全部，定位图标）；最右侧的按钮让画布铺满当前浏览器窗口，按 Esc 或再点一次恢复。拖动画布下方的横条可调整画布高度（触屏同样可用），设定的高度按设备记住，双击横条或点「自动高度」恢复按内容自动调整。
- 页头的搜索框筛选拓扑中的站点（名称、域名、分组、后端地址）；监听可以单独折叠，也可以全部收起。详情面板中的「编辑」「编辑监听」直接在本页打开与 Web 服务页相同的编辑窗口，保存后拓扑立即刷新，不离开当前页面；统计、连接与访问日志窗口也在本页打开。

图中数字全部来自本实例内存中的计数：重启后清零，修改站点保留计数，修改端口等监听设置后该监听重新计数，不汇总其他 Gately 实例。拓扑视图读取 `GET /api/webservice/topology`，只读账号与只读令牌可以查看。回放读取 `GET /api/webservice/topology/replay`（概览与时间轴）与 `GET /api/webservice/topology/replay/frame`（某一时刻的快照），只读账号可以回看；修改录制设置为 `PUT /api/webservice/topology/replay/settings`，需要写权限。

### 访客审计 {#visitor-audit}

左侧菜单「Web → 访客审计」（`#/webvisitors`）按访客地址汇总全部站点的访问，回答「谁在什么时候访问了哪些站点和路径、以什么身份、被拦截了多少次」。全部站点都会统计，包括默认站点与没有站点匹配的请求，与站点是否开启访问日志无关；配置了[可信代理](#real-ip)时记录的是访客真实地址。

- **汇总与趋势**：页头选择统计范围（今天、7 天、30 天、全部保留期）。上方卡片显示访客数（含新访客）、请求数、被拦截数与占比、通过站点认证的访客数、当前封禁中的访客数与扫描类地址数；点卡片按该条件筛选，再点一次取消。每日柱状图的柱高为请求数，红色部分为被拦截，点击或悬停某一天显示当天的访客、请求与拦截数。
- **列表**：每位访客显示国家代码（导入了 [GeoIP](#geoip-国家过滤) 时，内网与本机地址显示「内网」）、统计范围内的请求与拦截数、访问最多的站点、身份、首次与最近访问、最近一次请求（状态码、方法、路径、域名与 User-Agent）。可按地址、身份、站点、域名、路径或 User-Agent 搜索，按「有被拦截」「认证访客」「管理员」「封禁中」「扫描类」与站点筛选，按最近访问、请求最多、拦截最多或首次访问排序。两个监听上的同名站点附上监听名称区分。
- **身份**：站点认证（网页认证、基本认证、共享用户、第三方登录、转发认证）通过后记录用户名；带本实例管理后台登录态的请求记为「管理员」。密码错误的尝试与被拦截的请求不会记录身份。
- **扫描类**：只被拦截、或只访问未匹配站点、且从未通过认证的地址。
- **详情**：点一行打开访客详情：首次与最近访问、请求总数、被拦截数、下行流量、断开连接（444）次数，保留期内每天的请求柱状图，响应状态分布与拦截原因（封禁、IP 名单、国家过滤、限流、WAF），访问过的站点、请求最多的路径（最多 10 个）、身份与 User-Agent。可以从这里封禁或解除封禁（与[封禁列表](#封禁列表)相同，IPv6 按 /64 封禁）、按该地址查看访问日志，或删除这位访客的记录。

**记录范围与存储**：只保存按访客聚合的计数，不保存逐条请求；路径只记录路径部分，查询串、请求体、Cookie 与凭据一律不记录。每位访客最多保留 12 个站点、10 个路径、6 个身份与 4 个 User-Agent，超出时替换请求最少的一项；逐条请求请开启站点的访问日志。数据保存在配置目录下的 `visitors/visitors.jsonl.gz`（权限 0600），有变化后约 10 分钟写盘一次，退出时立即写盘，配置备份不包含它。

**设置**：页头「设置」可以停用记录（已有数据保留）、设置保留天数（1~180，默认 30）与最多访客数（100~100000，默认 10000），也可以清空全部数据。最近一次访问早于保留天数的访客自动删除；调小保留天数会立即删除超出的数据，保存前会确认。访客数超过上限时先淘汰扫描类地址，再淘汰最久未出现的。只读账号与只读令牌可以查看，封禁、删除与修改设置需要写权限。接口见 `GET /api/webservice/visitors`、`GET /api/webservice/visitors/detail`、`POST /api/webservice/visitors/delete` 与 `GET|PUT /api/webservice/visitors/settings`。

### Prometheus 指标

全局指标端点 `GET /api/metrics` 汇总了全部模块的指标，见 [监控指标](/docs/reference/monitoring)。下面的模块端点只包含 Web 服务的指标。

指标端点为 `GET /api/webservice/metrics`，Prometheus 文本格式，需携带登录凭据或 [API 令牌](/docs/reference/api-reference)。

```bash
curl -H "Authorization: Bearer gtl_xxxx" http://localhost:16680/api/webservice/metrics
```

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| `gately_site_requests_total` | counter | 站点累计请求数 |
| `gately_site_errors_total` | counter | 站点后端错误数 |
| `gately_site_active_requests` | gauge | 进行中的请求数 |
| `gately_site_response_bytes_total` | counter | 累计响应字节数 |
| `gately_site_responses_total` | counter | 按状态类别（标签 `class`：`2xx` 至 `5xx`）统计的响应数 |
| `gately_site_blocked_total` | counter | 按原因（标签 `reason`：`ban` 已封禁、`ip` IP 名单、`country` 国家过滤、`rateLimit` 限流、`waf`）统计的拦截次数 |
| `gately_upstream_up` | gauge | 后端是否健康，1 健康、0 不可用（附标签 `upstream`） |
| `gately_upstream_requests_total` | counter | 转发到后端的累计请求数（附标签 `upstream`） |
| `gately_upstream_response_bytes_total` | counter | 后端返回的累计响应体字节数，不含 WebSocket 升级后的数据（附标签 `upstream`） |
| `gately_listener_requests_total` | counter | 监听层直接处理、不经过站点的请求，标签 `action` 为 `https_redirect`（HTTPS 端口的明文请求跳转）或 `not_found`（未匹配站点的 404）；只带 `listener` 标签 |

除 `gately_listener_requests_total` 外，指标带标签 `listener`（监听名称#监听 key）与 `site`（站点名称，未命名时取第一个域名）。分路径与按用户分流的后端在 `gately_upstream_*` 中另带标签 `route`：路径前缀，或 `@` 加用户列表。`upstream` 标签为后端地址，去掉其中的用户名、密码与查询串。

## 导入 nginx 配置 {#import-nginx}

页面顶部的「导入 nginx」可以把现有 nginx 站点转换为 Gately 的监听与站点。推荐在 nginx 所在主机执行 `nginx -T`，把完整输出粘贴进来：输出中包含 include 的所有文件，Gately 会像 nginx 一样展开 include。

- 先预览：按监听端口分组列出每个站点的类型、后端或目录、来源文件与行号，以及需要注意的地方（使用了变量的指令、正则 location、缺少证书的域名等），无法转换的站点会说明原因；
- 相同端口的站点合并到已有监听，否则新建监听；已存在的域名会跳过，可以重复导入；
- 默认导入为停用状态，便于与 nginx 并行逐个核对后再启用；勾选「导入后立即启用」则立即生效（nginx 仍占用同一端口时新建的监听会启动失败）；
- 能转换的内容：`proxy_pass`（含 upstream 的权重、备用与负载均衡策略）、`root` / `alias` 静态目录（`autoindex`、`try_files $uri.html`、`error_page 404`）、`return` 跳转与固定内容、整站 `rewrite` 跳转、`add_header`、`proxy_set_header`、`gzip`、`allow` / `deny`、location 级的分路径后端、访问控制与跳转、`listen ... proxy_protocol` 与 `quic`；
- `proxy_connect_timeout` 与 `proxy_read_timeout` 转换为站点的[连接超时与等待响应头超时](#backend-timeouts)，location / 中的值优先于 server 级，超过上限时按上限导入；其他 location 中不同的值不会导入，预览中会提示；
- `client_body_timeout` 与 `send_timeout` 转换为站点的[访客超时](#client-timeouts)，各类站点都适用；
- `auth_request` 会转换为转发认证：认证地址取自认证子请求 location 的 `proxy_pass`（支持 `set` 变量），登录跳转取自 `error_page 401 =302`，Authelia 的常见写法可以直接转换；只在部分 location 启用时转换为「仅对指定路径认证」；
- `auth_basic` 转换为使用共享用户的基本认证，nginx 的用户文件不会被读取，补齐用户前任何人都无法通过；
- `stream` 中的 TCP/UDP 转发请在[端口转发](/docs/modules/portforward)中配置；证书不会导入，HTTPS 站点缺少证书时预览会列出 nginx 使用的证书文件，可在[证书](/docs/modules/ssl)页按文件路径添加。

## 替换 haproxy 与 nginx

协议分流加 Web 服务可以替代 haproxy + nginx 的组合。常见布局是：在 443 上放一条[协议分流](/docs/modules/protoroute)规则，把 VPN 等 TLS 服务直接送到各自的后端，其余域名送到一个接收 PROXY 协议的 Web 服务监听；再在 80 端口放一个 Web 服务监听，用重定向站点（`https://{host}`）跳转到 HTTPS。

nginx 配置的对应关系：

| nginx | Gately |
| --- | --- |
| 带 `server_name` 的 `server` | 使用这些域名的站点 |
| `proxy_pass` 不同的 `location` | 分路径后端 |
| `auth_request`（Authelia） | 转发认证，或带 TOTP 的共享用户 |
| `proxy_ssl_name $host` | 使用访问域名作为 SNI |
| `return 301 https://$host$request_uri` | 重定向站点，`https://{host}` 并勾选「保留路径」 |
| `location = /` 里的 `return 302 /admin` | 重写规则，开启「重定向」，pattern 为 `^/$` |
| `try_files $uri $uri.html $uri/index.html` 与 `error_page 404` | 静态文件的无扩展名地址与 404 页面 |
| `error_page 502 503 504 /50x.html` 与 `proxy_intercept_errors on` | 站点的[错误页](#error-pages)设置与拦截后端错误 |
| `add_header` | 响应头 |
| `return 444` | 断开连接站点 |
| HTTPS server 中的 `error_page 497 https://$host:$server_port$request_uri` | 新建监听的「同端口 HTTP」设为「跳转到 HTTPS」；合并到已有监听时只提示，不改动其设置 |

## 自动放行防火墙 {#auto-firewall}

Gately 运行在 OpenWrt 等路由器上，或运行在开启了防火墙的 Linux 主机上时，系统防火墙默认拦截从外网发往本机的连接，监听端口放行后才能访问。监听开启「自动放行防火墙」后，Gately 在本机防火墙只放行这个监听的端口：

- 只放行监听成功的端口：端口被其他程序占用导致监听失败时不放行，占用端口的程序（例如路由器管理页面）保持不对外；
- 按监听的网络放行：「仅 IPv6」只放行 IPv6，「仅 IPv4」只放行 IPv4，双栈两者都放行；填写了监听地址时只放行发往该地址的连接；只监听 127.0.0.1、::1 时无需放行；
- 开启 HTTP/3 时同时放行同号 UDP 端口；
- 监听停用、删除、启动失败或关闭开关时撤销，Gately 退出时一并移除；
- nftables（OpenWrt fw4、firewalld 等）在 input 过滤链最前面插入规则，iptables / ip6tables（OpenWrt fw3、ufw 等）在 INPUT 链最前面插入；规则带 `gately-open:` 注释，防火墙重新加载后 30 秒内补回；
- 内核没有 nf_tables（如群晖 DSM）时改用 iptables（legacy）：放行规则写在 Gately 专用的 filter 链（`GTLY_OPEN_` 开头）中，INPUT 的第一条规则跳到这条链；系统防火墙把自己的规则插到前面时 30 秒内挪回第一位。Docker 镜像已自带 iptables（legacy）；
- 只支持 Linux；Docker 部署需要 host 网络与 `cap_add: NET_ADMIN`。监听卡片显示放行结果，放行失败时「防火墙」标签显示为橙色。

[端口转发](/docs/modules/portforward#auto-firewall)与[协议分流](/docs/modules/protoroute#auto-firewall)的规则有同样的开关，[STUN 穿透](/docs/modules/stun#auto-firewall)的规则放行通道端口。

### 手动放行 {#manual-firewall}

手动放行时只为需要对外的端口添加放行规则，wan 区域的入站保持拒绝；把整个 wan 区域的入站改为接受会让路由器管理页面（80 / 443）、SSH 等服务一起暴露在公网。OpenWrt 在「网络 → 防火墙 → 通信规则」中添加，或写入 `/etc/config/firewall`：

```
config rule
	option name 'Allow-Gately-HTTPS'
	option src 'wan'
	option family 'ipv6'
	option proto 'tcp'
	option dest_port '50663'
	option target 'ACCEPT'
```

- Gately 以 Docker bridge 网络运行时，容器内看不到路由器的防火墙，需要在宿主机或路由器上放行映射端口；
- Gately 运行在内网另一台设备上（例如以 macvlan 获得独立 IPv6 地址的容器）时，流量经路由器转发，需要在路由器上添加转发规则：目标区域选 lan，填写设备地址与用到的端口。运营商下发的 IPv6 前缀会变化，地址可按后缀匹配，例如 `option dest_ip '::1234/::ffff:ffff:ffff:ffff'`。

## 部署提示

Web 服务需要监听宿主机的 80 / 443 等端口，Docker 部署推荐使用 `--network host`。
