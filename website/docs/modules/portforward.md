# 端口转发

把本机监听的端口转发到另一台设备或服务。

## 能力

- TCP 与 UDP；
- IPv4 与 IPv6，v4 / v6 之间可互相转发；
- 端口段与多端口；
- 多目标与故障转移；
- 连接数限制；
- 流量统计与运行日志；
- 向目标发送 PROXY 协议（v1 / v2），把真实客户端地址交给下游；
- 来源 IP 访问控制（白名单 / 黑名单），可引用 Web 服务的订阅 IP 列表；
- 多个服务按域名或协议共用 443 等同一个端口请使用[协议分流](/docs/modules/protoroute)。

## PROXY 协议

端口转发只做 TCP 中转，下游默认只能看到 Gately 自身的地址。在规则中把「PROXY 协议」设为 v1 或 v2 后，Gately 连上目标后会先发送 PROXY 头，下游即可取得真实客户端地址，用于日志、限流与访问控制。

目标必须开启对应的接收选项，否则连接会被拒绝，例如：

- haproxy：`bind 192.168.1.8:4434 accept-proxy`；
- nginx：`listen 4435 ssl proxy_protocol;`；
- Gately Web 服务：监听中开启「接收 PROXY 协议」，并把来源加入可信 PROXY 来源。

该选项只作用于 TCP，UDP 转发不受影响。

## 来源 IP 访问控制

每条规则可以设置白名单或黑名单，按来源 IP 决定是否转发。名单由手填的 IP / 网段和 Web 服务中的订阅 IP 列表组成，命中任意一项即视为在名单中；订阅列表由 Web 服务模块定时下载，刷新后立即生效，下载成功前按空列表处理。每条规则还可以设置「优先拒绝名单」（`ipDenyList` / `ipDenySets`），与白名单、黑名单模式无关：命中的来源一律拒绝，先于白名单、黑名单判断，同时在白名单中的地址也会被拒绝。可手填 IP / 网段或引用订阅列表，用于“先黑后白”，例如订阅恶意 IP 情报后只放行自家网段。

- 判断在连接目标之前进行：TCP 不满足名单的连接直接关闭，UDP 按数据包判断，不满足的数据包直接丢弃，名单变化后已有会话的上行数据包也立即按新名单处理；
- 入侵防护的封禁优先于名单：被封禁的地址即使落在白名单网段内也会被拒绝；
- 修改名单不会中断监听，已建立的 TCP 连接不受影响；
- 规则卡片显示 Gately 启动以来的拒绝次数（TCP 按连接、UDP 按数据包计数），运行日志的调试级别记录每次拒绝；
- 规则前面还有反向代理或其它转发时，Gately 看到的来源是它们的地址；
- 可以再选择一条端口敲门规则作为“需要敲门”：来源地址必须先用 fwknop 敲门成功，在放行时长内才能建立新连接，与名单同时设置时两者都要满足，不需要防火墙权限，详见[端口敲门](/docs/modules/knock#gately-entries)。

从 Lucky 导入时，规则的安全模式会一并转换：白名单模式取 Lucky IP 过滤中「白名单」的 IP / 网段，黑名单模式取「黑名单」与「全局黑名单」。需要同时上传 `lucky_ipfilter.lkcf`（或整站备份）；IP 库、自动记录与地址范围类条目无法导入，导入结果会给出提示。安全模式为「关闭」时不设置名单；选择的是自建 IP 过滤规则时，按规则动作导入：放行导入为白名单，拒绝导入为黑名单（同样合并全局黑名单）。

## 典型场景

- 把 NAS 的服务端口暴露到统一入口；
- 在 IPv6 与 IPv4 之间做互通转发；
- 为一个服务配置主备两个后端。

## 自动放行防火墙 {#auto-firewall}

规则开启「自动放行防火墙」后，Gately 在本机防火墙只放行本规则监听成功的端口：连续端口合并为一条规则，按规则的协议放行 TCP / UDP 与 IPv4 / IPv6，填写了监听地址时只放行发往该地址的连接；规则停用或删除时撤销。适用场景、支持的防火墙与手动放行的做法见 [Web 服务 · 自动放行防火墙](/docs/modules/web#auto-firewall)。

## 部署提示

端口转发直接监听宿主机端口，Docker 部署推荐使用 `--network host`。

## 分组与排序

规则可以填写「分组」（最长 64 个字符）。列表按分组显示可折叠的区块：分组按首次出现的顺序排列，未分组的规则排在最后，折叠状态保存在浏览器中；页头的搜索框可按名称、分组、监听端口或目标过滤。

点击「排序」进入排序模式：用箭头上移、下移规则或整组移动；勾选多个规则后拖动其中任一项会一起移动，拖到其他分组的规则或分组标题上即加入该分组；工具栏可以把选中的规则批量移到指定分组，留空则移出分组。顺序和分组只影响列表显示，修改后不会重启转发，已建立的连接不受影响。

鼠标移到分组标题上，点铅笔按钮可以重命名分组：组内条目一起改为新名称，位置和顺序不变；改成已有分组的名称时，确认后两个分组合并。
