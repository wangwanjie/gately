# Tailscale / NetBird / EasyTier / frp / cloudflared

五个模块以进程托管方式集成官方程序：自动重启、日志汇总到界面、配置在界面中完成。Gately 本体不内置这些程序，可以在页面中在线安装、更新与回滚。

## 在线安装、更新与回滚 {#install}

frp、Cloudflare 隧道、Tailscale、NetBird、EasyTier 与 [File Browser](/docs/modules/tools#filebrowser) 页面下方都有「在线安装」卡片：

- **下载安装 / 更新到最新版**：从上游下载最新正式版，按上游记录的 SHA-256 校验，确认能在本机运行后安装到配置目录的 `bin/`，完成后自动重启使用该程序的进程。已经是最新版时不会重复下载；
- **检查更新**：只查询上游最新正式版，不下载；有新版本时卡片标题旁显示「新版本」。开启[自动检查更新](/docs/guide/install#update-check)时，Gately 每 12 小时为已安装的程序检查一次，发现新版本时发布 `program.update` 通知；
- **安装指定版本**：填写版本号（例如 frp 的 `v0.65.0`、cloudflared 的 `2025.8.0`、Tailscale 的 `1.90.2`），可用于降级；
- **下载代理**：每个程序可以单独设置，支持 http、https 与 socks5，开始安装时保存；留空时使用「设置」中的更新代理；
- **旧版本与回滚**：被更新或回滚替换下来的版本保存在 `bin/.versions/` 下，最多保留 3 个。新版本有问题时在列表中点「回滚」即可切回，当前版本同样会保留，之后还能再切回来；
- **卸载**：删除 `bin/` 下安装的程序与全部旧版本，模块配置保留。之后使用该程序的进程会重启，`PATH` 中有同名程序时改用它，没有时无法运行。

| 程序 | 来源 | 安装的文件 |
| --- | --- | --- |
| frp | GitHub fatedier/frp | `frpc`、`frps` |
| cloudflared | GitHub cloudflare/cloudflared | `cloudflared` |
| Tailscale | pkgs.tailscale.com 静态包，仅 Linux | `tailscale`、`tailscaled` |
| NetBird | GitHub netbirdio/netbird，Linux、macOS、Windows | `netbird` |
| EasyTier | GitHub EasyTier/EasyTier，Linux（amd64、arm64、armv7、armhf、arm、mips、mipsel、riscv64、loongarch64）、macOS、Windows、FreeBSD | `easytier-core`、`easytier-cli`（发布包里的 zip，安装 SHA-256 取自 GitHub 记录的摘要） |
| FileBrowser Quantum | GitHub gtsteffaniak/filebrowser | `filebrowser` |

Tailscale 在 macOS 与 Windows 上没有可直接运行的程序包，请使用官方安装程序，再在设置中填写路径。卡片会提示当前平台不支持的情况。

## 恢复默认配置 {#reset}

页头的「恢复默认配置」与卸载分开处理：停止该模块的全部进程，把设置（包括程序路径与下载代理）恢复为默认值，并删除 Gately 为它生成的文件，安装的程序保留。

| 模块 | 清除的内容 |
| --- | --- |
| frp | 全部 frpc / frps 实例、代理与程序设置，`frp/` 下生成的配置文件 |
| Cloudflare 隧道 | 全部隧道与程序设置 |
| Tailscale | 全部实例与程序设置，默认状态目录中的登录状态；使用默认状态目录的托管 tailscaled 运行中时先退出登录。自定义的状态目录与系统已有的 tailscaled 不处理 |
| NetBird | 全部实例与程序设置，默认状态目录中的登录状态与密钥；使用默认状态目录的托管守护进程运行中时先退出登录，本机从组网中删除。自定义的状态目录与系统已有的 NetBird 服务不处理 |
| EasyTier | 全部实例与程序设置（含网络密钥）；EasyTier 不在配置目录保存其他状态 |
| File Browser | 全部实例与程序设置，各实例的用户、分享链接与缓存；共享目录中的文件不受影响 |

旧配置保存在 [配置历史](/docs/guide/audit) 中，误操作时可以恢复。要彻底移除，先卸载程序，再恢复默认配置。接口为 `DELETE /api/{module}/install`（卸载）与 `POST /api/{module}/reset`（恢复默认配置）。

## 程序放置

按以下顺序查找可执行文件：

1. 模块设置中填写的路径；
2. 配置目录下的 `bin/` 子目录（在线安装的位置）；
3. `PATH`。

填写了路径时在线安装的版本不会生效，卡片会提示。也可以自行把二进制放进配置目录，Docker 部署时例如 `./gately-data/bin/frpc`。Tailscale 需要同时提供 `tailscale` 与 `tailscaled`；使用系统已有的 tailscaled 时，安装的 `tailscale` 命令最好与守护进程版本一致。

令牌与密钥以 0600 权限保存，cloudflared 的令牌通过环境变量传递，不会出现在进程列表中。

## Tailscale

支持多个实例：每个实例运行一个独立的 tailscaled（状态目录、控制套接字、WireGuard 端口与进程互不相同），可以把同一台机器分别加入不同的 tailnet，例如一个内核 TUN 实例连远端 Headscale、一个用户态实例连本地 Headscale。

- 新实例的状态目录默认为配置目录下的 `tailscale/<实例 key>`；也可以填写已有的状态目录（例如原先 tailscale 容器挂载的目录），沿用原节点身份，无需重新注册；
- 同时启用的内核模式（托管且未开启用户态网络）实例最多一个：tailscaled 的路由表与防火墙标记是固定的，两个内核实例会互相覆盖。控制套接字、状态目录与固定的 WireGuard 端口也不能被两个实例共用，保存或启用时会提示冲突；
- 修改、启停一个实例只重启它自己的 tailscaled，日志来源带实例名（如 `tailscaled:家里`）；
- 从 0.6.4 及更早版本升级时，原来的单个配置自动迁移为名为 `tailscale` 的实例，状态目录、控制套接字与启动参数保持不变；
- 程序路径（tailscaled、tailscale）与在线安装为所有实例共用。

每个实例支持：

- 托管 `tailscaled`（用户态网络，容器友好）或接入系统已有的守护进程；
- 认证密钥或登录链接，支持 Headscale；
- 子网路由与出口节点；
- 节点列表与 SOCKS5 代理。该代理没有认证，监听地址不限于本机（如 `0.0.0.0` 或局域网 IP）时界面会提示，建议只监听 `127.0.0.1`；
- 固定 WireGuard UDP 端口，便于在防火墙放行直连；
- tailscaled 额外参数与环境变量。宿主机 iptables 是 nf_tables 后端时，在环境变量中加入 `TS_DEBUG_FIREWALL_MODE=nftables`，子网转发才会生效。

## NetBird

支持多个实例：每个实例运行一个独立的 NetBird 守护进程（状态目录、控制地址、WireGuard 端口与进程互不相同），可以把同一台机器分别加入不同的 NetBird 网络，例如一个内核模式实例连官方云、一个用户态实例连自建管理服务。

- 新实例的状态目录默认为配置目录下的 `netbird/<实例 key>`，控制地址默认为状态目录下的 `netbird.sock`；也可以填写已有的状态目录（例如原先 NetBird 容器挂载的 `/var/lib/netbird`），沿用原节点身份，无需重新注册；
- 同时启用的内核模式（托管且未开启用户态网络）实例最多一个：NetBird 内核模式使用固定的路由表、防火墙标记与 nftables 表，默认网卡名都是 `wt0`，两个内核实例会互相覆盖。状态目录与控制地址不能被两个实例共用；托管实例的 WireGuard 端口不能相同（0 视为默认的 51820，端口被占用时 NetBird 会悄悄换成随机端口）；托管的用户态实例的 SOCKS5 地址不能相同（留空视为 `127.0.0.1:1080`）；保存、启用、批量启用与复制时都会提示冲突，手动改出冲突的配置中，排在后面的冲突实例不会启动并显示原因；
- 系统中另装的 NetBird 服务也受这条限制：启用或启动托管的内核模式实例前，Gately 会查询已启用的外部实例与系统默认控制套接字 `/var/run/netbird.sock`（存在时），并检查本机是否已有 `wt` 加数字的 NetBird 网卡（不属于 Gately 托管的实例时）。发现另一个已连接的内核模式 NetBird 时，保存或启用会提示冲突，实例不启动并显示原因；停止对方或为本实例开启用户态网络后重启实例即可。残留网卡可用 `ip link delete wt0` 删除。外部服务改了网卡名且控制套接字不可见（例如 Docker 未挂载）时无法发现，这种组合不受支持；
- 修改、启停一个实例只重启它自己的守护进程，日志来源带实例名（如 `daemon:家里`、`netbird:家里`）；登录链接、设备码、节点列表与退出登录也按实例显示；
- 删除实例时，使用默认状态目录的托管实例会先退出登录再删除该目录；自定义状态目录与迁移来的旧目录保留，便于新建实例时沿用；
- 从 0.6.4 及更早版本升级时，原来的单个配置自动迁移为名为 `netbird` 的实例，状态目录（配置目录下的 `netbird`）、控制地址、启动参数与环境变量保持不变；
- 程序路径与在线安装为所有实例共用。

每个实例支持：

- 加入 NetBird 官方云或自建管理服务（填写管理服务地址）的组网；
- 设置密钥或登录链接认证。Linux 下的登录链接是设备码登录，可以在任意设备上打开；macOS 与 Windows 上通常只能在运行 Gately 的这台电脑上用浏览器完成登录，远程管理时请使用设置密钥。链接过期后自动更新；
- 托管 `netbird` 守护进程（用户态网络，容器友好）或接入系统已安装的 NetBird 服务；
- 用户态网络下默认允许其他节点访问本机服务（包括只监听 127.0.0.1 的服务，仍受管理端访问策略限制），本机程序通过 SOCKS5 代理（默认 `127.0.0.1:1080`）访问组网内的设备；
- SOCKS5 代理没有认证，监听地址不限于本机时界面会提示。0.75 之前的 NetBird 在用户态网络下会忽略设置的地址，总是在 `0.0.0.0` 上提供无认证的 SOCKS5 代理，其他设备可以经它访问组网；Gately 托管守护进程时检测到这类版本会在日志中警告，请升级到 0.75 或更高版本；
- 网络路由、出口节点与访问策略在 NetBird 管理端配置，Gately 中可以选择是否接受路由、是否作为路由节点、是否接受 DNS 以及拒绝入站；
- 节点列表显示直连或中继、延迟与网络路由；
- 固定 WireGuard 端口，守护进程额外参数与环境变量（NetBird 文档中 `NB_` 开头的高级选项）；
- 关闭用户态网络时使用内核 WireGuard：需要 root 与 TUN 设备，会创建 `wt0` 网卡并自行添加防火墙规则（OpenWrt 的 fw4 中也会放行 `wt0` 入站），本机服务要监听在所有地址或组网地址上才能被其他节点访问；
- `netbird` 程序约 41 MB，运行时内存约 60 MB，在线安装还会在 `bin/.versions/` 保留最多 3 个旧版本。闪存较小的路由器请留意剩余空间，可在安装卡片中删除旧版本，或把程序放在外部存储上并在设置中填写路径；
- 恢复默认配置与 `POST /api/netbird/instances/{key}/logout` 会从管理服务注销本机，节点从组网中删除，再次加入需要重新认证。

## EasyTier

支持多个实例：每个实例运行一个独立的 `easytier-core` 进程，可以把同一台机器分别加入不同的组网。组网名称与网络密钥相同的节点互通；优先 P2P 打洞，打不通时经公共节点或自建节点中继，连接协议支持 tcp / udp / ws / wss / quic / wg 等。

- **网络密钥**：通过环境变量 `ET_NETWORK_SECRET` 传给进程，不出现在命令行，日志中也会打码；界面里是带「显示 / 隐藏」的密码框，列表与接口返回的是脱敏值。没有密钥时，知道组网名称的人就能加入组网，所以共享本地网段或允许作为出口节点时必须设置密钥；密钥不能写在额外参数里（会出现在进程命令行中）；
- **节点地址（peers）**：每行一个，例如 `tcp://public.easytier.cn:11010`；
- **监听地址（listeners）**：必须写成 `协议://地址:端口`，留空则不监听任何端口，只主动连接。作为中继或公网节点时，需要自行在防火墙放行这些端口；
- **虚拟 IP**：自动分配（DHCP）或填写固定 IPv4；两者都没有时只转发数据，不创建网卡；
- **运行方式**：TUN 网卡需要 root 与 `/dev/net/tun`，Docker 需要 `NET_ADMIN` 与 `/dev/net/tun`；创建失败时实例会显示原因，进程不会退出。「用户态网络」无需特权，适合容器，通过「端口转发」访问组网内的服务；
- **不提供 SOCKS5 选项**：EasyTier 的 SOCKS5 监听全部地址且没有认证。端口转发的绑定地址由你填写，建议 `127.0.0.1`；绑定到非回环地址时界面会提示（转发入口没有认证）；
- **其他选项**：子网代理（`proxyNetworks`，可写 `192.168.1.0/24->10.1.0.0/24` 映射）、出口节点（作为出口 / 使用出口）、延迟优先、KCP / QUIC 代理（在 UDP 丢包的网络上降低延迟）、网卡名，以及额外参数与环境变量（`ET_` 开头的选项见 EasyTier 文档；只读账号与只读令牌只能看到环境变量名，看不到额外参数）；
- **管理端口**：Gately 在 `127.0.0.1` 上为每个实例随机分配并限定本机访问，状态（本机虚拟 IP、NAT 类型、公网地址、监听地址、节点的直连 / 中继、延迟、丢包、流量）通过 `easytier-cli` 读取；`easytier-core` 与 `easytier-cli` 一起安装；
- **冲突检查**：同时启用的实例不能监听同一个端口（TCP 与 UDP 分别判断），不能绑定同一个本机转发端口，使用 TUN 时网卡名不能相同；实例名称不能重复。保存、启用与复制时都会检查；
- 修改某个实例只重启它自己；只改分组或备注不重启；
- **OpenWrt / iStoreOS / ImmortalWrt**：EasyTier 的 TUN 网卡（默认名 `tun0`，可用“网卡名”固定）不属于任何防火墙区域，fw4 的 input 默认丢弃，其他节点主动访问本机的虚拟 IP 会不通（本机访问别人没问题）。需要把网卡加入 lan 区域：`uci add_list firewall.@zone[0].device='tun0'`、`uci commit firewall`、`/etc/init.d/firewall reload`（`@zone[0]` 通常是 lan，请按实际区域调整；网卡名改过时用改后的名字）。已在 iStoreOS 24.10 与 ImmortalWrt 25.12 上验证加入后三台互通。另外 ImmortalWrt 等精简固件默认没有 `/dev/net/tun`，需要先安装 `kmod-tun`（`apk add kmod-tun` 或 `opkg install kmod-tun`），否则 `easytier-core` 会启动失败并被反复重启，实例上会显示原因；也可以改用“用户态网络”；
- **Windows**：在线安装会把 `easytier-core.exe`、`easytier-cli.exe` 与同目录依赖的 `wintun.dll`、`Packet.dll`、`WinDivert64.sys` 一并安装（缺少这些 DLL 程序无法启动）；使用 TUN 网卡需要以管理员身份运行 Gately（作为服务运行时即为 SYSTEM）；
- 程序体积随平台不同：Linux x86_64 上 `easytier-core` 约 7.5 MB、`easytier-cli` 约 3 MB，macOS arm64 上分别约 21 MB 与 9 MB；Windows x86_64 的完整发布包（含依赖库）约 32 MB。

在 UDP 打洞困难（NAT 类型严格、与中继之间 UDP 丢包高）的网络里，可以对比 EasyTier 与 Tailscale 的直连效果；EasyTier 的中继节点可自选，包括国内节点。

## frp

- **frpc 客户端**：可添加多个 frpc 实例，每个实例连接一台 frps，独立运行、单独启停与重启；代理归属某个实例，支持 tcp / udp / http / https / stcp / xtcp，增删改后只重启所属实例；
- **代理访问地址**：frpc 不知道 frps 的 HTTP / HTTPS 端口和子域名根域名，可在 frpc 实例的「访问地址」中填写（本机也有 frps 实例时可一键填入；frps 前面还有反向代理或 CDN 时填访客实际使用的协议和端口）。填写后 http / https 代理的域名（含子域名拼出的完整域名）可点击打开、可复制完整地址，未填写时照常显示文本。访问地址只用于生成链接，修改后 frpc 不重启。自定义域名保存时与 Web 服务一样统一为小写和 punycode，带端口、路径的写法会被拒绝；子域名只能填一级名称（如 `nas`），与 frps 的要求一致；
- **frps 服务端**：可添加多个 frps 实例（使用不同端口），每个实例有端口白名单、子域名、控制台；
- **从旧版本升级**：0.5.9 及更早版本的单个 frpc / frps 设置会自动迁移为名为 `frpc` / `frps` 的实例，原有代理归属该 frpc 实例，程序路径移到页面下方的「程序」卡片；
- **frps 监听地址**：「监听地址」决定 frpc 连接端口监听在哪，「代理监听地址」决定 HTTP / HTTPS 端口和 tcp / udp 代理的远程端口监听在哪，留空都监听所有地址。frps 放在 Gately 等反向代理之后时，把监听地址填 `127.0.0.1`，在 Web 服务中把一个站点反代到 `127.0.0.1:<绑定端口>`，frpc 的传输协议选 websocket 或 wss 并连接该站点；代理监听地址保持留空，tcp 代理的远程端口照常对外开放。导入 frps 配置时，原配置未写 `proxyBindAddr` 会沿用 `bindAddr`，与 frps 的行为一致；
- **frps 来源 IP 访问控制**：每个 frps 实例可设置白名单或黑名单，按来源 IP 决定 frpc 能否登录（连接绑定端口）。名单由手填的 IP / 网段和 Web 服务中的订阅 IP 列表组成，命中任意一项即视为在名单中；订阅列表由 Web 服务模块定时下载，刷新后立即生效，frps 不必重启，下载成功前按空列表处理。判断在 frps 校验令牌之前进行：Gately 在本机回环地址开一个检查端点，并在生成的 frps 配置末尾写入 `[[httpPlugins]]`（`ops = ["Login"]`），因此只对 frpc 登录生效，tcp / udp 代理的远程端口与 HTTP / HTTPS 端口照常对外开放。入侵防护的封禁优先于名单：被封禁的地址即使落在白名单网段内也无法登录，未设置访问控制的实例同样遵守封禁表，与是否开启防火墙同步无关。被拒绝的 frpc 会收到 `gately: client address ... is not in the allowlist` 之类的错误，实例卡片显示 Gately 启动以来的拒绝次数。名单在 frpc 登录时检查，作用于 frpc 连接 frps 的绑定端口：名单收紧或地址被封禁后，已登录的 frpc 保持连接，下次登录时才被拒绝，需要立即生效时重启该 frps 实例；stcp / xtcp 的 visitor 连接不经过登录检查，需要限制时配合[入侵防护](/docs/modules/guard)的防火墙同步。frps 放在反向代理之后（监听地址填 `127.0.0.1`）时，frps 看到的来源是代理的地址，请改在 Web 服务站点上做 IP 访问控制；放在协议分流或端口转发后面时，frps 看到的来源是本机地址，名单无法按访客判断，请在分流或转发规则上设置来源 IP 访问控制；
- **frps 优先拒绝名单**：每个 frps 实例还可以设置「优先拒绝名单」（`ipDenyList` / `ipDenySets`），与白名单、黑名单模式无关：命中的来源一律拒绝，先于白名单、黑名单判断，同时在白名单中的地址也会被拒绝；可手填 IP / 网段或引用订阅列表，登录检查的时机与限制与上一条相同，拒绝原因为 `client address ... is in the deny list`；
- **导入已有配置**：页头的「导入配置」支持旧版 `frpc.ini` / `frps.ini`（含 `[common]` 段）和 frp 0.52+ 的 `toml`，可选择文件或粘贴内容，并选择导入到已有实例或新建实例。先预览解析结果与被忽略的字段，再确认导入；导入到已有 frpc 实例时可选择追加（同名代理保持不变）或替换该实例的全部代理。导入到已有实例时沿用其启用状态，新建的实例默认停用；也可通过接口 `POST /api/frp/import` 调用。从 Lucky 迁移时，Lucky 中的每个 frpc / frps 实例都会导入为 Gately 的实例。

## Cloudflare 隧道

- 令牌隧道与 trycloudflare 临时隧道；
- 多隧道、自动重启；
- 展示公网地址。

### 路由规则 {#cloudflared-ingress}

令牌隧道的公网主机名与回源服务（路由规则）保存在 Cloudflare 上，运行中的 cloudflared 会自动拉取。在隧道设置中填写可选的 **API 令牌** 后，卡片上的「路由规则」可以直接编辑这些规则：

- 令牌需要「Cloudflare Tunnel：编辑」权限；要自动创建 DNS 记录，还需要对应域名的「DNS：编辑」权限。账号与隧道 ID 从隧道令牌中解析，无需另外填写。
- 每条规则包含主机名、可选的路径正则与服务（如 `http://localhost:8080`、`ssh://localhost:22`、`http_status:404`），按顺序匹配，命中第一条即转发；可设置「不校验回源证书」和回源 Host 头，其他回源设置原样保留。所有规则都未命中时使用兜底服务，默认 `http_status:404`。
- 保存后立即生效，无需重启隧道。若规则在此期间被 Cloudflare 控制台或其他地方修改，保存会提示并显示「重新加载」，避免覆盖别人的修改。HTTP 类服务不能带路径，末尾单独的 `/`（如 `http://nas:5000/`）保存时会自动去掉，否则 cloudflared 会拒绝整份配置。
- 隧道由本地配置文件管理时（界面会提示远程规则不生效），保存前需要再确认一次：写入远程配置后隧道改为远程管理，本地配置文件中的路由规则不再生效。
- 打开「同步 DNS」时，为每个主机名创建开启代理、指向 `<隧道ID>.cfargotunnel.com` 的 CNAME 记录；主机名已有其他记录，或已有指向隧道但未开启代理的 CNAME（这时流量不会进入隧道）时保持原样并在结果中列出。只在隧道所属账号下查找域名。删除规则时 DNS 记录保留，需要时在 Cloudflare 中删除。

## 如何选择

| 场景 | 推荐 |
| --- | --- |
| 在多台设备之间组成私有网络 | Tailscale |
| 组网，并希望客户端与管理端都开源、可以自建 | NetBird |
| 在 UDP 打洞困难或需要自选中继节点的网络里组网 | EasyTier |
| 自己有公网服务器，把内网服务映射出去 | frp |
| 没有公网 IP 也没有服务器，快速暴露 Web 服务 | Cloudflare 隧道 |
| 运营商给了可打洞的 NAT | [STUN 穿透](/docs/modules/stun) |
