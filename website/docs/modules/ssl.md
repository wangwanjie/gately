# SSL 证书

自动申请并续期证书，供 [Web 服务](/docs/modules/web) 使用，也可以导出给其他软件。

多张证书覆盖同一域名时，使用到期时间最晚的一张；证书列表的排序与分组只影响展示。

## 能力

- **ACME DNS-01** 自动签发与续期，复用 [动态域名](/docs/modules/ddns) 中的 DNS 服务商，无需开放 80 / 443 端口；
- **ACME HTTP-01**：不需要 DNS 服务商，要求公网能访问各域名的 80 端口，不支持通配符；
- 通配符证书与 EAB（如 ZeroSSL）；
- **短期证书与 IP 地址证书**：选择 Let's Encrypt 的短期证书配置（约 6 天有效期），可为公网 IP 地址签发证书；
- 上传已有证书，或从文件读取；
- 映射到目录：证书变化后写入指定目录并执行脚本，方便其他服务重载；
- 自动部署：证书变化后复制到多个本机目录、经 SSH 推送到其他主机并执行命令，或重启使用该证书的 Docker 容器。

## DNS-01 验证

在证书的「验证方式」中选择 DNS-01，并选择一个 DNS 服务商。签发时 Gately 通过服务商的 API 添加 `_acme-challenge` TXT 记录，验证完成后删除。

「主域名」即记录所在的 DNS 区域（zone）。留空时，Gately 用 SOA 查询找出验证记录的权威区域，因此子域名单独委派给另一个 DNS 服务商（例如 `web.example.com` 与 `example.com` 分开托管）以及 `example.com.cn` 这类多级后缀都能正确识别；查询失败时按域名推断主域名，并在日志中记录原因。也可以手动填写主域名，例如 `web.example.com`。

## 签发网络

证书的「网络」选项限定签发时的出站网络：「自动」按系统选择，「仅 IPv4」或「仅 IPv6」让访问 CA、调用 DNS 服务商接口以及检查 TXT 记录生效都只使用对应的地址族。主机有 IPv6 地址但 IPv6 实际不通时，自动模式下的生效检查可能在查询权威 DNS 服务器时超时，此时选择「仅 IPv4」。

## HTTP-01 验证

在证书的「验证方式」中选择 HTTP-01。签发时 CA 会访问 `http://<域名>/.well-known/acme-challenge/<token>`：

- [Web 服务](/docs/modules/web) 已在 80 端口监听时，由它直接应答，不影响现有站点；
- 80 端口空闲时，Gately 会在签发期间临时监听该端口，完成后立即关闭；
- 路由器把公网 80 端口转发到本机其他端口时，在「临时监听端口」中填写该端口。

国内家庭宽带通常封锁入站 80 端口，此时请使用 DNS-01。

## 短期证书与 IP 地址证书

「证书配置」对应 ACME 的 profile：

- **默认**：由 CA 决定，Let's Encrypt 为 90 天；
- **短期证书（IP 证书）**：即 Let's Encrypt 的 `shortlived` 配置，有效期约 6 天，Gately 在到期前按「续签设置」中的「短期证书提前小时数」（默认 24 小时）自动续签，失败后每小时重试一次；
- 也可以输入 CA 支持的其他配置名。

在域名中填写公网 IP 地址（IPv4 或 IPv6，如 `203.0.113.10`、`2001:db8::1`）即可申请 IP 地址证书，IP 与域名可以写在同一张证书里。要求：

- 使用 Let's Encrypt，证书配置选择短期证书，验证方式选择 HTTP-01，CA 会访问 `http://<IP>/.well-known/acme-challenge/<token>`，要求该 IP 的 80 端口可从公网访问。填写 IP 后编辑框会提示，点「一键设置」即可；
- 内网地址、回环地址与 `100.64.0.0/10` 无法通过公共 CA 验证；自定义 CA（如内网自建的 ACME 服务）不受这些限制；
- ZeroSSL、Google Trust Services 不通过 ACME 签发 IP 地址证书。

通过 IP 地址访问 HTTPS 时浏览器不发送域名（SNI），Gately 会按连接的本机地址选择对应的 IP 证书；经 NAT 或端口转发、本机地址不是证书中的公网 IP 时，使用到期时间最晚的 IP 证书。

把已签发证书的配置在默认与短期之间切换后，会立即按新配置重新签发。短期证书只在剩余时间不到提前小时数的一半（说明续签多次失败）时发出到期提醒。

## 证书映射

启用证书后，Gately 会把 `.crt`、`.key`、`.pem` 与 `_issuerCertificate.crt` 写入映射目录，并执行变化脚本。

## 自动部署

在证书的「自动部署」中可以添加多个部署目标，证书签发、续期或更新后自动执行：

- **复制到本机目录**：把证书写入本机的目录，再在本机执行「复制后执行」的命令，可以添加多个目录、每个目录使用不同的命令。目录中的证书文件被删除或改动后，下一次检查会重新复制。Gately 运行在 Docker 中时，目录与命令都在容器内；
- **上传到 SSH 主机**：选择 [Web 终端](/docs/modules/terminal) 中已有的 SSH 连接，复用它的地址、认证方式与代理。证书文件（`<备注>.crt`、`.key`、`.pem`、`_issuerCertificate.crt`，与证书映射相同，因此备注不能为空）写入远程目录后，在远程主机执行「上传后执行」的命令，例如 `systemctl reload nginx`，命令中可用 `$certName`、`$certDir`、`$certFile`、`$keyFile`。文件先写临时文件并设好权限再改名替换，私钥权限为 0600；
- **重启本机容器**：证书变化后依次重启所选的 Docker 容器，适合容器挂载了映射目录、需要重启才能加载新证书的服务。

「复制到本机目录」与「上传到 SSH 主机」可以填写证书（完整链）与私钥的文件名，例如 `fullchain.pem` 与 `privkey.pem`，两个都填写后只写入这两个文件，此时备注可以为空；留空时使用与证书映射相同的文件名。命令中的 `$certFile`、`$keyFile` 指向实际写入的文件。

自动部署不会信任未知主机：所选 SSH 连接需要先在 Web 终端中连接一次，记录主机密钥后才会推送。部署失败时每小时重试一次，并发出「证书：部署失败」事件，可在[通知中心](/docs/modules/notify)订阅。证书卡片上的「立即部署」会忽略重试间隔，马上部署到所有启用的目标并显示每个目标的结果。

编辑证书时，目标设置没有变化的部署不会重复执行；修改远程目录、命令或容器后会重新部署一次。

## 安全提示

私钥保存在配置目录的 `ssl.json` 中，请妥善保管该文件，纳入版本库时确认仓库为私有。
