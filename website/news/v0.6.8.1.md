# Gately v0.6.8.1 发布

2026 年 11 月 17 日

[下载 v0.6.8.1](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.1)

## Web 服务

- **添加或编辑站点失败**：v0.6.8 在 Web 服务页添加、编辑、复制或启停站点，以及编辑 HTTPS 监听时，会提示 `siteCerts` 格式不对而保存失败。原因是 v0.6.8 新增的站点证书信息（站点行显示的证书剩余天数）被界面随配置一起提交，保存接口不认识这个字段。现在界面提交前会去掉它；保存接口也会忽略列表接口自己输出的只读字段（运行状态、统计、证书匹配等），升级后仍开着的旧页面和「先读取再整体提交」的脚本同样能保存，其他未知字段照旧拒绝。快速建站向导不受影响。
- **复用连接时的「站点不存在」**：几个域名解析到同一 IP 且证书都能覆盖（例如 `*.example.com` 通配证书）时，浏览器会把新域名的请求放进已经打开的 HTTP/2 连接。若前面有按 SNI 分流的协议分流，把其中一些域名转给了另一台 Gately，这条连接实际通往另一台，访问就会显示「站点不存在」（或落到那台的默认站点），关掉浏览器重开才恢复。现在 HTTP/2、HTTP/3 请求的域名与 TLS SNI 不一致、且本监听没有这个域名的站点时，返回 `421 Misdirected Request`，浏览器会为该域名新建连接自动重试。HTTP/1.1 与不带 SNI 的请求（用 IP 访问）照旧处理。

## 升级提示

- Docker 拉取新镜像后重建容器；OpenWrt 覆盖安装新的 `.apk` / `.ipk`；飞牛在应用中心手动安装新版 `.fpk`；其他部署方式可在「系统设置」中在线升级。
- 「复用连接」问题要用 SNI 分流的两端都升级才完全解决：请求落在哪台 Gately，哪台就要返回 421。
