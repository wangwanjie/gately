# Gately v0.6.8.4 发布

2026 年 11 月 19 日

[下载 v0.6.8.4](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.4)

## 安全修复

- **通知渠道密钥可能出现在投递错误中（低）**：Telegram Bot Token、Bark 设备 Key、Server酱 SendKey 等放在请求地址中，连接失败时错误信息会带出完整地址，写入通知模块日志和「最近发送」记录，只读账号与只有通知读权限的 API 令牌也能看到。现在错误信息中的渠道密钥替换为 `***`。v0.6.8.2 及更早版本受影响；「最近发送」只保存在内存中，升级重启后即清除；运行日志中可能留有旧记录，曾经推送失败过的渠道建议更换密钥（GHSA-p368-wcp9-rv4q）。

## 改配置不再把自己关在门外

- **保存后确认，超时自动回滚**：在管理后台保存端口转发、协议分流、Web 服务或全局设置后，页面会用一条新连接确认后台仍能访问；确认不了（例如改错了管理后台所经过的监听端口），默认 90 秒后自动恢复改动前的配置。确认失败时弹出倒计时，可立即回滚；重启 3 次都没确认也会回滚。「系统设置 › 访问控制」可关闭此功能或调整等待秒数（30–600）。回滚会发出「配置变更」通知。
- **保存前提醒访问路径**：后台会追溯你当前这次访问经过了哪些端口转发、协议分流和 Web 站点，保存的改动会影响这条路径时（改端口、停用、删除、换到本机无法监听的地址等）先说明原因并高亮受影响的一跳。「系统设置 › 访问控制」可查看当前访问路径。
- **批量修改一起生效**：需要同时改好几处才能通的情况（例如先改协议分流再改 Web 监听），可以「暂存，稍后一起生效」，顶部横幅列出暂存的规则与监听，「全部生效」后整批确认、整批回滚，也可「放弃修改」。全部生效前会先列出无法启动的监听。
- **命令行回滚**：`gately rollback` 列出待确认的改动和最近 15 次配置保存，可按编号撤销，或用 `-last`、`-pending`、`-config` 配合 `-version`。Gately 运行中会在 2 秒内恢复并重启；未运行时直接改写配置文件。
- 删除配置文件前会先存一份到配置历史，删除也能从配置历史里撤销。

## 通知：失败重试与补推

- 推送失败后按 10、30、60 秒重试（默认 3 次，可设 0–10）；仍失败的消息进入补推队列，渠道恢复后按时间顺序补发，重启后继续（默认保留 24 小时，可设 0–168，0 为关闭；每个渠道最多 100 条）。
- 渠道已有待补推的消息时，新消息只尝试一次，失败后排在积压之后，不再逐条等待重试。
- 「最近发送」显示「等待补推」「已补推」与尝试次数，上方横幅按渠道统计待补推数量并可清空。

## 证书：使用飞牛系统证书（#105）

- 证书来源新增「飞牛系统证书」：从飞牛已管理的证书中选一个域名，Gately 每 30 分钟跟随飞牛的续期读取最新证书（有完整证书链时使用完整链），变化后自动加载并部署。
- 证书在飞牛「设置 → 安全性 → 证书」中管理。飞牛原生应用（fpk）可直接读取；Docker 部署需把 `/usr/trim/etc/network_cert_all.conf` 与 `/usr/trim/var/trim_connect/ssls` 按原路径只读挂载进容器，容器以 root 运行（官方镜像默认如此）。详见[SSL 证书](/docs/modules/ssl)。

## 存储占用

- 「系统设置 › 网络与运行」新增存储占用卡片：配置目录所在分区容量、配置目录总大小，以及运行日志、访客审计、配置历史、备份、证书、托管程序、通知补推队列、File Browser 数据等各类用途的占用和对应路径。

## 修复

- **入侵防护**：管理后台端口在模块启动前就登记为开放端口；此前诱饵端口范围包含管理端口时，Gately 自己的诱饵监听会先占住它，导致管理后台监听失败、每次重启都退出。启动各模块期间不再设置诱饵端口；frps、EasyTier、FTP 被动端口等模块登记的端口即使暂未监听也不作诱饵；诱饵端口随端口变化重新计算；申请证书时的临时 HTTP-01 监听不会被诱饵端口拦下。
- **Web 服务**：站点后端是本实例另一个 Web 监听（如 443 站点 → 本机 444 监听 → 管理后台）时，管理后台登录 Cookie 原样转发，不再登录后立即 401。

## 升级提示

- Docker 拉取新镜像后重建容器；OpenWrt 覆盖安装新的 `.apk` / `.ipk`；飞牛在应用中心手动安装新版 `.fpk`；其他部署方式可在「系统设置」中在线升级。
- 保存后确认默认开启。用脚本或 API 令牌保存配置不受影响，只有管理后台会话带确认请求头的保存才需要确认。
