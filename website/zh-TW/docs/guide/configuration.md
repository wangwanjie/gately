# 設定與執行參數

## 命令列參數

| 參數 | 說明 |
| --- | --- |
| `-c` | 設定目錄，也可以用環境變數 `GATELY_CONFIG_DIR` 指定 |
| `-listen` | 覆寫管理介面監聽位址，例如 `:16680` |
| `-apply` | 宣告式設定目錄，也可以用環境變數 `GATELY_APPLY_DIR` 指定，見下文 |
| `-gateway-socket` | 額外在該 Unix Socket 上提供管理介面，用於飛牛 fnOS 統一閘道等情境 |
| `-gateway-prefix` | 經閘道存取時使用的路徑前綴，例如 `/app/gately` |
| `-api-docs` | 把 API 文件（`openapi.json` 與 `API.md`）匯出到指定目錄後結束 |
| `-version` | 輸出版本資訊 |

| 環境變數 | 說明 |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | 首次啟動時的管理員初始密碼（至少 8 位），未設定時為預設密碼 `gately.cn`；帳號已存在時不起作用。短於 10 位或強度不足時，首次登入會被要求修改 |
| `GATELY_LANG` | 伺服器語言為「跟隨系統」時優先讀取的語言代碼，其後依序為 `LC_ALL`、`LC_MESSAGES`、`LANG` |
| `GATELY_LOG_LEVEL` | 執行日誌記錄的最低級別：`debug`、`info`、`warn`、`error`。設定裡的「日誌級別」為「預設」時生效，未設定時為 `info` |

## 設定目錄

所有設定都儲存在設定目錄中，每個模組一個 `<name>.json` 純文字檔案，原子寫入，檔案權限 0600。因此：

- 可以直接用文字編輯器檢視；
- 可以把目錄納入 git，用 diff 稽核每次變更並隨時回復；
- 備份只需複製目錄。

::: warning 注意
`ssl.json` 中含有憑證私鑰，納入版本庫前請確認儲存庫為私有，或把該檔案加入忽略清單。
:::

## 宣告式設定

指定 `-apply <目錄>` 後，每次啟動會把該目錄下的 `<名稱>.json` 覆寫到設定目錄，內容相同的檔案不會重寫。適合把設定放在 git 儲存庫、Kubernetes ConfigMap 或部署指令碼中統一下發。

- 寫入前驗證是否為合法 JSON，任一檔案無效則拒絕啟動；
- `account.json` 與 `tokens.json` 不允許覆寫，帳號與權杖只能在管理介面管理；
- 被覆寫的舊內容會保存在 [設定歷史](/zh-TW/docs/guide/audit) 中，可隨時還原。

## 外部程式目錄

Tailscale、frp、cloudflared 與 File Browser 託管官方的外部程式，依以下順序尋找可執行檔：

1. 模組設定中填寫的路徑；
2. 設定目錄下的 `bin/` 子目錄；
3. `PATH`。

各模組頁面可以線上安裝、更新與回滾，程式裝在 `bin/` 下，舊版本儲存在 `bin/.versions/`，詳見 [線上安裝、更新與回滾](/zh-TW/docs/modules/tunnels#install)。也可以自行把執行檔放進設定目錄，Docker 部署時例如 `./gately-data/bin/frpc`；Tailscale 需要同時提供 `tailscale` 與 `tailscaled`。

## 執行日誌

系統日誌與各模組的執行日誌預設寫入設定目錄下的 `logs/`，重新啟動或升級後仍可在「系統 → 日誌」頁的「系統日誌」分頁與各模組頁面查看：

- 每個來源一個 JSON Lines 檔案：`logs/<模組 ID>.log`，系統日誌為 `logs/gately.log`；啟動時依「日誌保留筆數」從檔案還原最近的日誌；
- 有新日誌時最多延遲 1 秒批次寫入；單一檔案超過上限（預設 2 MB）後輪替為 `.1`，只保留這一份歷史，每個來源最多占用兩倍上限；
- Web 服務的存取日誌量大、需要回看，單獨按天封存：目前檔案跨天（或超過總大小的四分之一，最大 16 MB）時改名為 `logs/webservice.<開始時間>.log` 並在背景壓縮為 `.log.gz`，依「存取日誌保留天數」（預設 7 天）與「存取日誌總大小 (MB)」（目前檔案與全部壓縮封存合計，預設 32 MB，且不超過日誌所在分割區容量的 5%）刪除最舊的封存；
- 每個模組記錄出現過的日誌來源（`logs/<模組 ID>.sources`），重新啟動後保留；
- 「設定 → 網路與執行 → 執行參數」中可以關閉「日誌落盤」，調整「日誌檔上限」「存取日誌保留天數」「存取日誌總大小 (MB)」，或把「日誌目錄」改到其他絕對路徑（例如外接硬碟上的目錄，不存在時自動建立為僅本使用者可存取），立即生效；修改日誌目錄後新日誌寫到新目錄，原目錄中的檔案保留不動；關閉落盤後日誌只保存在記憶體，重新啟動後清空；
- 「日誌級別」決定記錄哪些執行日誌，預設為「資訊及以上」：偵錯級別的日誌不記錄，不進入日誌頁、日誌檔與標準錯誤輸出。連接埠轉發與協定分流的每筆連線記錄、用戶端中斷與無關網域的 TLS 交握失敗等屬於偵錯級別；需要查看時把「日誌級別」改為「偵錯及以上（全部）」，儲存後立即生效，連線多時會明顯增加負擔。Web 服務存取日誌屬於資訊級別，改為「警告及以上」或「僅錯誤」後不再記錄。也可以用環境變數 `GATELY_LOG_LEVEL` 指定，設定裡選了具體級別時以設定為準；
- 執行日誌同時回顯到標準錯誤輸出（`docker logs`、`journalctl` 看到的內容），按伺服器語言顯示。回顯由背景批次寫出，程序正常結束或重新啟動前會寫完；標準錯誤輸出阻塞或過慢、積壓超過 1 MB 時捨棄新的回顯行並補一行說明，日誌頁與日誌檔不受影響。Docker 的預設日誌驅動不限制容器日誌大小，部署範例 [docker-compose.yml](https://github.com/wangwanjie/gately/blob/main/deploy/docker-compose.yml) 用 `logging.options` 的 `max-size`、`max-file` 設了上限；
- 在頁面上清空某個模組的日誌會同時刪除對應的檔案、歷史檔案、壓縮封存與來源記錄；
- 設定備份不包含 `logs/` 與操作稽核日誌 `audit.log`。

### 檢視與篩選 {#log-filter}

「日誌」頁的「系統日誌」分頁和各模組頁面底部的日誌卡片使用同一個日誌檢視器，可以組合以下條件篩選，修改後立即生效，新日誌也只追加符合條件的部分：

- 層級、來源（下拉列出模組設定中的全部來源與日誌中出現過的來源，例如 Web 服務的全部監聽器，包括還沒有存取紀錄或日誌只在檔案裡的；也可以直接輸入）；
- 關鍵字：空格分隔表示同時包含，雙引號包住短語，詞前加 `-` 表示排除，例如 `GET "timeout" -debug`，命中的部分會醒目標示；介面為其他語言時，按介面上看到的譯文搜尋即可；
- 「不包含」：包含其中任意一個詞的日誌不顯示，與關鍵字同時生效；寫法同關鍵字（空格分隔、雙引號包住短語），例如 `debug "health check"`。要排除本身以 `-` 開頭的詞，用雙引號包住，如 `"-v"`；
- 「更多篩選」中的 IP：可填完整位址、網段（如 `10.0.0.0/8`）或位址的一部分，多個以逗號分隔；日誌沒有單獨記錄 IP 時會從日誌內容中辨識位址，登入失敗、入侵防護等日誌同樣適用；前加 `!` 或 `-` 表示排除，如 `!1.2.3.4, !10.0.0.0/8` 不顯示這些來源，也可以與包含項組合（`10.0.0.0/8, !10.0.0.5`）；
- 「更多篩選」中的時間範圍：最近 15 分鐘到 7 天，或自訂起訖時間；
- Web 服務的工具列還有兩個顯示開關，只影響頁面顯示，日誌照常保存，選擇記在瀏覽器裡：「隱藏被封鎖來源」不顯示來源已被封鎖而被拒絕的請求（站點在 CDN 後面時，核心封鎖對回源連線不起作用，被封的訪客仍會在 Web 層被拒絕並留下 403 / 444 記錄），同時隱藏目前仍在封鎖中的來源的全部請求（包括封鎖前觸發封鎖的那些請求，解除封鎖或到期後重新顯示）；「隱藏後台自身請求」不顯示帶本執行個體管理後台登入狀態的請求，例如經 Web 服務站點存取後台時日誌頁的輪詢，預設開啟。這兩類日誌行尾分別帶「攔截原因=已封鎖」「後台使用者=…」標籤，對應介面參數 `hideBanned=1`、`hideAdmin=1`（只認管理員工作階段，唯讀帳號不算；被攔截的請求不帶後台使用者標記）；
- Web 服務還可依站點名稱或網域、狀態碼（`404`、`4xx`、`500-599`，多個以逗號分隔）篩選；WAF 防火牆可依網域篩選，命中日誌會記錄網域與規則 ID。

點擊日誌中的來源，或行尾的「站點=…」「網域=…」等標籤，可直接依該值篩選；Web 服務日誌中點「站點=…」會依站點名稱完整比對，工具列顯示可移除的「站點：…」標籤（介面參數 `site`），不會混入名稱相近的站點。介面還接受 `listener` 參數，依監聽器鍵精確比對；兩個監聽器同名時，日誌來源名稱附上監聽位址以便區分，例如 `HTTPS (0.0.0.0:443)` 與 `HTTPS ([::]:443)`，名稱唯一的監聽器保持原名。「載入更早的日誌」在記憶體中的日誌不夠時，會繼續查找日誌檔案中保留的歷史（包括 Web 服務的壓縮封存，依時間範圍篩選時略過範圍外的封存），因此開啟落盤後能篩選的範圍不受「日誌保留條數」限制。介面 `GET /api/logs` 與 `GET /api/<模組>/logs` 支援相同的篩選參數，見 [API 參考](/zh-TW/docs/reference/api-reference)。

日誌區高度可以調整：拖曳日誌區下方的橫條（觸控螢幕可直接按住拖曳），按兩下橫條恢復預設高度，橫條取得焦點後也可用方向鍵調整；頁面中的日誌卡片與站點日誌對話框分別記住各自的高度，儲存在目前的瀏覽器。工具列右側的全螢幕按鈕讓日誌占滿整個視窗，再按一次或按 Esc 退出。向上翻看歷史時，新日誌照常追加，目前位置保持不動，日誌區右下角顯示「回到最新」，期間到達的新日誌則數也顯示在按鈕上；捲回底部或點擊按鈕後恢復自動捲動。

### 匯出 {#log-export}

日誌工具列的「匯出」依目前篩選條件匯出全部日誌，包括日誌檔案與壓縮封存中保留的歷史，依時間從舊到新排列，由瀏覽器直接下載儲存：

- CSV（試算表軟體）：UTF-8 含 BOM，Excel 可直接開啟；欄位為時間、層級、來源、訊息與 IP、網域、站點、狀態碼等；以 `=`、`+`、`-`、`@` 開頭的儲存格前加單引號，防止試算表軟體把訪客提交的路徑當作公式執行；
- JSON Lines：每行一筆日誌，欄位與日誌介面相同；
- 訊息依介面語言匯出；唯讀帳號與只有讀取權限的 API 權杖也可以匯出，內容與檢視時一樣隱藏位址中的密碼與權杖；
- 介面為 `GET /api/logs/export` 與 `GET /api/<模組>/logs/export`，`format` 取 `csv` 或 `jsonl`，其餘篩選參數與檢視日誌相同；來源清單介面為 `GET /api/logs/sources` 與 `GET /api/<模組>/logs/sources`。

## 儲存後確認與自動回滾 {#confirm}

透過網域遠端管理時，修改連接埠轉發、協定分流、Web 服務或全域設定可能切斷管理介面自己的存取路徑。為此，管理介面儲存這幾類設定後會用一條新建立的連線確認仍能存取：

- 存取正常時在背景自動確認，不打擾操作；
- 無法確認時彈出倒數計時，存取恢復後自動確認；還能連上 Gately 時可以點「立即回滾」，連不上時這個請求同樣送不出去，只能等倒數結束，或在伺服器上執行 `gately rollback -pending`；
- 屆時仍未確認，Gately 重新啟動並在啟動時還原修改前的設定，修改後的版本保存在[設定歷史](/zh-TW/docs/guide/audit)中。頁面在服務恢復後自動重新整理，並提示哪些修改被回滾。

確認使用 WebSocket：瀏覽器總會為它建立新連線，經過的是修改後的轉發與監聽。修改前建立的長連線在熱更新後仍連著舊目標，不能證明新設定可用。

需要重新啟動才生效的設定（管理介面監聽位址、功能模組開關）在管理介面點重新啟動時登記，重新啟動後開始計時。連續啟動 3 次仍未確認（例如新設定讓程式無法正常執行）同樣回滾。在新位址開啟管理介面時，如有待確認的修改，會彈窗詢問「確認保留」或「立即回滾」。

時限在「設定 → 存取控制 → 管理介面監聽」的「儲存後確認」中調整（30~600 秒，預設 90 秒），也可以關閉。只對管理介面的儲存生效，API 權杖與腳本的修改不受影響；介面見 `GET /api/system/confirm`。

### 儲存前提醒：目前存取路徑 {#access-path}

Gately 能識別你目前存取管理介面經過了哪些自身的轉發：連接埠轉發與協定分流連到本機目標時會登記這一跳，Web 服務反代到管理介面時附帶簽章的路徑資訊（外部無法偽造）。「設定 → 存取控制」頂部的「目前存取路徑」卡片顯示這條路徑，例如 `訪客 → 協定分流「vps-443」 → Web 服務「main」 › 站點「admin.example.com」 → 管理介面`。frp、Cloudflare 隧道等本機程式顯示為「本機」。

儲存前，管理介面會先請伺服器判斷這次修改是否影響這條路徑，影響時彈窗列出原因並標出受影響的一跳，可以取消或「仍要儲存」：

- 修改路徑上規則、監聽或站點的轉發相關設定（只改名稱、分組、備註不算），停用或刪除它們，把站點移到其他監聽；
- 關閉路徑經過的模組（模組總開關或「功能模組」設定）；
- 修改正在使用的管理介面監聽位址；
- 從外網存取時開啟「僅限內網存取」，經 HTTP 存取時開啟「強制 HTTPS」。

提醒之外，上面的確認與自動回滾照常生效，沒有識別出的路徑（例如外層還有別的反向代理）同樣受保護。介面見 `GET /api/system/access-path` 與 `POST /api/system/access-path/check`。

### 批次修改：幾處一起改 {#changeset}

有些修改要幾處一起改才能用，例如把協定分流轉到 Web 服務的連接埠改成 18081，再把 Web 服務的監聽也改到 18081。只儲存第一處，目前存取就斷了，第二處再也改不了。這時用批次修改：

1. 在儲存前提醒中選「暫存，稍後一起生效」，或在「設定 → 存取控制」的「目前存取路徑」卡片中點「開始批次修改」；
2. 之後連接埠轉發、協定分流與 Web 服務的儲存只寫入設定，頁面上看到的是新內容，但執行中的規則與監聽不變，目前存取路徑繼續可用。頁面頂部的橫幅列出已暫存的規則與監聽，期間不再彈儲存前提醒；
3. 全部改好後點橫幅上的「全部生效」：暫存的修改按儲存順序一次性生效，隨後與單次儲存一樣經新連線確認，無法確認時整批回滾到開始批次修改前的設定；
4. 不想要了就點「放棄修改」：還原開始批次修改前的設定並重新啟動 Gately。

全域設定的修改不受批次修改影響，照常立即生效。批次修改期間 Gately 重新啟動時按新設定啟動，並像單次儲存一樣開始計時、等待確認。介面見 `POST /api/system/changeset/begin`、`/apply` 與 `/discard`。

### 命令列回滾 {#rollback-cli}

管理介面已經打不開時，在伺服器上執行 `gately rollback`（Docker 為 `docker exec -it gately gately rollback`）：列出待確認的變更與最近的設定儲存，輸入序號撤銷，或直接使用參數：

| 命令 | 作用 |
| --- | --- |
| `gately rollback -list` | 只列出，不做修改 |
| `gately rollback -last` | 撤銷最近一次儲存：把那份設定還原為儲存前的內容 |
| `gately rollback -pending` | 立即回滾待確認的設定變更 |
| `gately rollback -config portforward -version <版本>` | 把某份設定還原為指定的歷史版本（版本見 `-list`） |

執行前需輸入 `yes` 確認，腳本中加 `-y`。Gately 正在執行時由它處理並重新啟動，沒有執行時直接改寫設定檔、下次啟動生效。改寫前的內容同樣保存在[設定歷史](/zh-TW/docs/guide/audit)中，回滾本身也能撤銷。設定目錄不是預設位置時用 `-c` 指定。

## 備份與還原

「設定」中提供設定備份與還原，並承擔從 Lucky 匯入設定的入口。

還原時可勾選「保留目前管理員帳號」（介面參數 `keepAccount=1`）：備份中的 `account.json`、`tokens.json` 與系統設定裡的第三方登入會被忽略，目前帳號、密碼、兩步驟驗證、唯讀帳號、API 權杖與管理介面的第三方登入維持不變，其餘設定取自備份，備份裡沒有 `account.json` 也能還原，適合把另一台實例的設定遷移過來。仍使用預設密碼時還原會被拒絕，需要先修改密碼。
