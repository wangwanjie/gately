# 連接埠轉發

把本機監聽的連接埠轉發到另一台裝置或服務。

## 能力

- TCP 與 UDP；
- IPv4 與 IPv6，v4 / v6 之間可互相轉發；
- 連接埠範圍與多連接埠；
- 多目標與容錯移轉；
- 連線數限制；
- 流量統計與執行日誌；
- 向目標傳送 PROXY 協定（v1 / v2），把真實用戶端位址交給下游；
- 來源 IP 存取控制（白名單 / 黑名單），可引用 Web 服務的訂閱 IP 清單；
- 多個服務依網域或協定共用 443 等同一個連接埠請使用[協定分流](/zh-TW/docs/modules/protoroute)。

## PROXY 協定

連接埠轉發只做 TCP 中轉，下游預設只能看到 Gately 自身的位址。在規則中把「PROXY 協定」設為 v1 或 v2 後，Gately 連上目標後會先傳送 PROXY 標頭，下游即可取得真實用戶端位址，用於日誌、限流與存取控制。

目標必須開啟對應的接收選項，否則連線會被拒絕，例如：

- haproxy：`bind 192.168.1.8:4434 accept-proxy`；
- nginx：`listen 4435 ssl proxy_protocol;`；
- Gately Web 服務：在監聽中開啟「接收 PROXY 協定」，並把來源加入可信 PROXY 來源。

該選項只作用於 TCP，UDP 轉發不受影響。

## 來源 IP 存取控制

每條規則可以設定白名單或黑名單，依來源 IP 決定是否轉發。名單由手動填寫的 IP / 網段與 Web 服務中的訂閱 IP 清單組成，符合任一項即視為在名單中；訂閱清單由 Web 服務模組定時下載，重新整理後立即生效，下載成功前視為空清單。

- 判斷在連線目標之前進行：TCP 不符合名單的連線直接關閉，UDP 依封包判斷，不符合的封包直接丟棄，名單變更後既有工作階段的上行封包也立即依新名單處理；
- 入侵防護的封鎖優先於名單：被封鎖的位址即使落在白名單網段內也會被拒絕；
- 修改名單不會中斷監聽，已建立的 TCP 連線不受影響；
- 規則卡片顯示 Gately 啟動以來的拒絕次數（TCP 依連線、UDP 依封包計數），執行日誌的除錯層級記錄每次拒絕；
- 規則前面還有反向代理或其他轉發時，Gately 看到的來源是它們的位址。

從 Lucky 匯入時，規則的安全模式會一併轉換：白名單模式取 Lucky IP 過濾中「白名單」的 IP / 網段，黑名單模式取「黑名單」與「全域黑名單」。需要同時上傳 `lucky_ipfilter.lkcf`（或整站備份）；IP 庫、自動記錄與位址範圍類條目無法匯入，匯入結果會給出提示。安全模式為「關閉」時不設定名單；選擇的是自建 IP 過濾規則時，依規則動作匯入：放行匯入為白名單，拒絕匯入為黑名單（同樣合併全域黑名單）。

## 典型情境

- 把 NAS 的服務連接埠公開到統一入口；
- 在 IPv6 與 IPv4 之間做互通轉發；
- 為一個服務設定主備兩個後端。

## 部署提示

連接埠轉發直接監聽主機的連接埠，Docker 部署建議使用 `--network host`。

## 分組與排序

規則可以填寫「分組」（最長 64 個字元）。清單按分組顯示可摺疊的區塊：分組按首次出現的順序排列，未分組的規則排在最後，摺疊狀態儲存在瀏覽器中；頁首的搜尋框可按名稱、分組、監聽連接埠或目標篩選。

點選「排序」進入排序模式：用箭頭上移、下移規則或整組移動；勾選多個規則後拖動其中任一項會一起移動，拖到其他分組的規則或分組標題上即加入該分組；工具列可以把選中的規則批次移到指定分組，留空則移出分組。順序和分組只影響清單顯示，修改後不會重新啟動轉發，已建立的連線不受影響。

滑鼠移到分組標題上，點鉛筆按鈕可以重新命名分組：組內條目一起改為新名稱，位置和順序不變；改成已有分組的名稱時，確認後兩個分組合併。
