# 入侵防護

類似 fail2ban 的入侵防護：從日誌中辨識暴力破解，在沒有使用的連接埠上設誘餌，統計連接埠掃描，把惡意 IP 加入封鎖清單，並同步到系統防火牆（nftables），在核心層丟棄它的全部流量。

## 能力

- **日誌規則**：讀取日誌檔案、systemd 日誌、命令輸出（如 OpenWrt 的 `logread -f`）或 Docker 容器日誌，用正規表示式找出失敗記錄，同一 IP 在統計視窗內達到次數即封鎖；內建 SSH、Dropbear、Nginx、Vaultwarden、Home Assistant、Proxmox VE 等範本，編輯規則時可貼上日誌樣例直接測試；
- **Gately 事件**：管理後台登入失敗、WAF 攔截也可以作為規則來源，無需撰寫正規表示式；
- **Web 路徑探測**：直接統計 Web 服務處理的請求，依監聽、路徑與狀態碼計數，存取 `/.env`、`/.git` 等誘餌路徑或反覆掃描未知網域的來源會被封鎖，無需讀取日誌；
- **誘餌連接埠**：在本機沒有使用的連接埠上設下誘餌（預設 23、135、1433、3389、5900、6379 等），任何來源一連線就封鎖；
- **連接埠掃描偵測**：同一來源每分鐘連線本機未開放連接埠的次數超過閾值即封鎖；
- **統一封鎖清單**：手動封鎖（支援 CIDR 網段與永久封鎖）、Web 服務驗證失敗的自動封鎖都在這裡管理；手動封鎖不能包含回送位址（經本機轉送進來的連線都顯示為該位址）；封鎖會持久保存，重新啟動後恢復；
- **遞增封鎖**：同一位址 30 天內再次被封鎖時時長加倍，直到上限；
- **白名單**：預設忽略內網、迴環、100.64.0.0/10（Tailscale）與本機網卡所在的 IPv6 /64 網段（封鎖依 /64 進行，同一區域網路的公網 IPv6 裝置不會被連帶封鎖），可追加 IP 或網段；白名單中的單個 IPv6 位址會保護它所在的整個 /64。

## 生效範圍

| 環境 | 封鎖效果 | 誘餌連接埠 | 連接埠掃描偵測 |
| --- | --- | --- | --- |
| Linux（root 或 `CAP_NET_ADMIN`，已安裝 nftables） | 核心層丟棄全部流量，包括 SSH、其他程式與轉發給 Docker 容器、內網裝置的流量 | 由核心處理，能發現只發 SYN 的掃描 | 可用 |
| Docker（host 網路 + `cap_add: NET_ADMIN`） | 同上，規則寫入主機 | 同上 | 可用 |
| 飛牛 fnOS 安裝包、OpenWrt 22.03 以上 | 同上（以 root 執行，系統內建 nftables） | 同上 | 可用 |
| 其他情況（Windows、macOS、FreeBSD、沒有 nftables 或權限的 Linux、核心未啟用 nf_tables 的 Linux 如群暉 DSM） | 只對 Gately 自身的服務生效：連接埠轉發、Web 服務、STUN、WebDAV、FTP、SMB、frps 登入、管理後台 | 由 Gately 監聽，只能發現完成交握的連線 | 無法使用 |

頁面頂部會顯示防火牆同步狀態，無法使用時列出原因與處理方式。

## 防火牆規則

開啟「同步到系統防火牆」後，Gately 在 nftables 中建立獨立的 `inet gately` 表，不改動系統既有的規則（fw4、Docker、ufw 等）：

- `prerouting` 鏈（優先級 -190，在連線追蹤之後、目的位址轉換之前）丟棄被封鎖位址發來的封包，發往本機、轉發給容器或內網裝置的流量都會被丟棄；本機主動發起的連線（例如存取 DNS、軟體來源）的回應照常放行，即使對方位址被封鎖也不受影響；IPv6 依 /64 網段封鎖；
- `input` 鏈只統計發往本機的新連線，用於誘餌連接埠與掃描偵測，白名單位址不參與；
- 關閉同步或停止 Gately 時整張表會被刪除；表被其他程式清除後 10 秒內自動重寫。

頁面上的「檢視規則」可以看到目前寫入的完整規則。

::: tip Docker 部署
需要 `network_mode: host` 並授予 `NET_ADMIN`，規則才會寫入主機：

```yaml
    network_mode: host
    cap_add:
      - NET_ADMIN
```

未授予時封鎖仍對 Gately 自身的服務生效。讀取主機日誌需要把日誌目錄掛載進容器，例如 `- /var/log:/var/log/host:ro`，規則中填寫 `/var/log/host/auth.log`；systemd 日誌來源在容器中無法使用。
:::

## 日誌規則

| 來源 | 填寫 | 說明 |
| --- | --- | --- |
| 日誌檔案 | 檔案路徑，每行一個 | 從檔案末尾開始讀取新增內容，輪替（改名或截斷）後自動切換 |
| systemd 日誌 | 服務單元，如 `ssh.service` | 透過 `journalctl -f` 讀取 |
| 命令輸出 | 一條命令，如 `logread -f` | 命令結束後自動重新啟動 |
| Docker 容器 | 容器名稱 | 透過 Docker 管理模組連線的 Docker 讀取 |
| Gately 事件 | 管理後台登入失敗 / WAF 攔截 | 事件自帶來源 IP，不需要過濾規則 |
| Web 路徑探測 | 監聽（可留空）與路徑規則 | 統計 Web 服務的請求，見下文 |

過濾規則是 Go 正規表示式（RE2 語法），每行一條，用 `<HOST>` 表示來源位址，例如：

```
Failed password for (?:invalid user )?\S* ?from <HOST>
```

「排除規則」中相符的行不計數。統計視窗、失敗次數與封鎖時長可依規則設定，封鎖時長可選預設、自訂或永久。

## Web 路徑探測

來源選「Web 路徑探測」時，規則直接統計 Web 服務處理的請求，不讀取日誌：

- **監聽**：可選一個或多個，留空表示全部監聽；
- **路徑規則**：每行一條，留空表示全部路徑。`*` 匹配任意字元（含 `/`），整條路徑匹配，不區分大小寫，例如 `*/.env` 匹配 `/.env` 與 `/api/.env`；以 `~` 開頭為 Go 正規表示式。`//.env`、`/a/../.env` 這類寫法依正規化後的路徑同樣命中；
- **排除路徑**：寫法同上，命中的請求不計數；
- **統計口徑**：預設只統計 404 與 444（存取了不存在的內容，或被「中斷連線」站點直接中斷），存取正常頁面的請求不計數；開啟「任意狀態碼」後所有回應都計數，適合誘餌路徑，因為單頁應用對任意路徑都回傳 200。任意狀態碼需搭配路徑規則或「只統計未知網域」，否則儲存時會被拒絕；
- **存取控制拒絕**：站點的拒絕方式為「中斷連線」時，被封鎖、IP 存取控制或國家過濾拒絕的請求在一般站點上按 403 統計，避免名單外的正常訪客被誤封；在預設站點上按 444 統計，與「中斷連線」類型的預設站點一致，預設站點改用反向代理加白名單放行自家 IP 後，未知網域掃描仍會被統計；
- **只統計未知網域**：只統計網域沒有匹配任何站點的請求，即由預設站點處理、或沒有預設站點時由監聽直接回傳 404 的請求。

內建三個範本：

| 範本 | 條件 | 說明 |
| --- | --- | --- |
| Web 誘餌路徑 | `/.env`、`/.git`、`wp-login.php`、`phpinfo.php`、`phpmyadmin` 等，任意狀態碼 1 次 | 封鎖 1 天。站點本身是 WordPress、phpMyAdmin 等程式時先刪掉對應的行 |
| 未知網域掃描 | 只統計未知網域，1 分鐘 5 次 | 封鎖 1 天。與預設站點的「中斷連線」搭配：掃描器幾次 444 後被封鎖，開啟防火牆同步後之後的連線直接被丟棄 |
| Web 404 探測 | 全部路徑，1 分鐘 10 次 | 已排除 favicon、robots.txt、`.map` 等瀏覽器常請求的路徑。反向代理後端回傳的 404 同樣計數，圖庫縮圖缺失、應用輪詢不存在的介面等情況可能觸發，啟用前先看存取日誌，必要時調高次數或補充排除路徑 |

在 Web 服務的監聽卡片上點「路徑探測封鎖」會跳到這裡，預選該監聽並套用誘餌路徑範本；規則的儲存與執行都在入侵防護。編輯規則時可以貼上請求路徑測試路徑規則。

::: warning 封鎖範圍
無論哪個監聽觸發，封鎖都寫入同一張封鎖表，對全部監聽、站點與 Gately 的其他服務生效；開啟防火牆同步後，還會在系統防火牆層丟棄該位址的全部流量。
:::

來源位址與存取日誌一致，只經 PROXY 協定還原。站點經 CDN 回源、由請求標頭傳遞真實 IP 時，封鎖的會是 CDN 節點，這類監聽不要啟用路徑探測；Gately 位於本機其他反向代理之後時，來源是回環位址，開啟「忽略內網位址」後不會被封鎖，但規則也不起作用。

## 連接埠掃描偵測的取捨

掃描偵測統計的是連線**本機未在監聽的連接埠**的新連線：正在監聽的 TCP 連接埠每 10 秒自動重新整理，視為開放；由其他防火牆規則轉發出去的連接埠不經過 `input` 鏈，不會被統計。閾值預設每分鐘 12 次，正常用戶端重試一個關閉的連接埠每分鐘約 5 次，不建議設得低於 10。

誘餌連接埠中正在被監聽的連接埠會被自動排除，避免誤封正常訪客。

## IPv6 嚴格模式

IPv6 沒有 NAT，每台裝置都有公網位址，位址一旦出現在 DNS 或憑證透明日誌裡就會被掃描器直連。連接埠掃描偵測中的「IPv6 嚴格模式」把偵測改為白名單方式：IPv6 來源只能連接開放連接埠（正在監聽的連接埠加「額外開放連接埠」），第一次連接其他連接埠即被封鎖，不再依閾值計數；IPv4 仍依閾值偵測。

- 封鎖以 /64 網段為單位，同一網段的其他裝置一併被封；白名單位址與「忽略內網位址」涵蓋的位址不受影響；
- 新開始監聽的連接埠最長約 10 秒後才視為開放，開啟嚴格模式或重新啟動後約 15 秒才生效，這段時間內仍依閾值偵測；讀不到監聽連接埠時同樣依閾值偵測；
- 連接埠停止監聽後 30 秒內仍視為開放，frps 重連、程式或監聽重新啟動期間重試連線的訪客不會被封鎖；FTP 服務設定了被動連接埠範圍時，整個範圍自動計入開放連接埠；被動連接埠由系統隨機分配時無法事先列出，IPv6 訪客的資料連線會被當成掃描封鎖，執行日誌會給出提示，需要在 FTP 服務中設定被動連接埠範圍；
- 由其他程式透過防火牆規則使用的連接埠必須先加入「額外開放連接埠」，否則存取它們的來源會被封鎖；
- 只統計 TCP 的新連線，需要防火牆同步生效，並且要先啟用連接埠掃描偵測。

## 與 Web 服務的關係

Web 服務「驗證失敗封鎖」產生的封鎖寫入同一份封鎖清單，因此開啟防火牆同步後會對整台主機生效，不再只限於 Web 站點。開啟「忽略內網位址」時，內網位址不會被自動封鎖。

Web 服務與 WAF 只透過 PROXY 協定辨識真實用戶端位址。站點經 CDN 回源、以請求標頭傳遞真實 IP 時，驗證失敗封鎖與「WAF 攔截」規則封鎖的會是 CDN 節點，這類站點不要啟用它們。

## 通知

封鎖會產生「入侵防護：IP 已被封鎖」事件，可在[通知中心](/zh-TW/docs/modules/notify)訂閱；誘餌連接埠與掃描偵測在同一輪檢查中封鎖的多個位址合併為一則通知。

## 驗證

在飛牛 fnOS（Debian 12，nftables 1.0.6）與 iStoreOS 24.10（nftables 1.1.1）的獨立網路命名空間中驗證：誘餌連接埠與掃描偵測（IPv4 與 IPv6）在核心層封鎖並匯入封鎖清單，日誌檔案（含輪替）、systemd 日誌、Docker 容器日誌與管理後台登入失敗都能觸發封鎖；手動網段與永久封鎖、解除封鎖、遞增時長、重新啟動後恢復、規則被外部刪除後重寫、停止時清理規則皆符合預期；Docker 容器在沒有 `NET_ADMIN` 時判定為權限不足並改用使用者態誘餌連接埠。
