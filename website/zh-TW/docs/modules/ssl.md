# SSL 憑證

自動申請並續期憑證，供 [Web 服務](/zh-TW/docs/modules/web) 使用，也可以匯出給其他軟體。

多張憑證涵蓋同一網域時，使用到期時間最晚的一張；憑證列表的排序與分組只影響顯示。

## 能力

- **ACME DNS-01** 自動簽發與續期，重用 [動態網域](/zh-TW/docs/modules/ddns) 中的 DNS 服務商，無需開放 80 / 443 連接埠；
- **ACME HTTP-01**：不需要 DNS 服務商，要求公網能存取各網域的 80 連接埠，不支援萬用字元；
- 萬用字元憑證與 EAB（如 ZeroSSL）；
- **短期憑證與 IP 位址憑證**：選擇 Let's Encrypt 的短期憑證設定檔（約 6 天有效期），可為公網 IP 位址簽發憑證；
- 上傳既有憑證，或從檔案讀取；
- 對應到目錄：憑證變動後寫入指定目錄並執行指令碼，方便其他服務重新載入；
- 自動部署：憑證變動後複製到多個本機目錄、經 SSH 推送到其他主機並執行指令，或重新啟動使用該憑證的 Docker 容器。

## DNS-01 驗證

在憑證的「驗證方式」中選擇 DNS-01，並選擇一個 DNS 服務商。簽發時 Gately 透過服務商的 API 新增 `_acme-challenge` TXT 記錄，驗證完成後刪除。

「主網域」即記錄所在的 DNS 區域（zone）。留空時，Gately 以 SOA 查詢找出驗證記錄的權威區域，因此子網域單獨委派給另一家 DNS 服務商（例如 `web.example.com` 與 `example.com` 分開託管）以及 `example.com.cn` 這類多層後綴都能正確識別；查詢失敗時依網域名稱推斷主網域，並在日誌中記錄原因。也可以手動填寫主網域，例如 `web.example.com`。

## 簽發網路

憑證的「網路」選項限定簽發時的對外網路：「自動」由系統選擇，「僅 IPv4」或「僅 IPv6」讓存取 CA、呼叫 DNS 服務商 API 以及檢查 TXT 記錄生效都只使用對應的位址族。主機有 IPv6 位址但 IPv6 實際不通時，自動模式下的生效檢查可能在查詢權威 DNS 伺服器時逾時，此時選擇「僅 IPv4」。

## HTTP-01 驗證

在憑證的「驗證方式」中選擇 HTTP-01。簽發時 CA 會存取 `http://<網域>/.well-known/acme-challenge/<token>`：

- [Web 服務](/zh-TW/docs/modules/web) 已在 80 連接埠監聽時，由它直接回應，不影響現有站台；
- 80 連接埠閒置時，Gately 會在簽發期間臨時監聽該連接埠，完成後立即關閉；
- 路由器把公網 80 連接埠轉發到本機其他連接埠時，在「臨時監聽埠」中填寫該連接埠。

許多家用寬頻（例如中國大陸）會封鎖入站 80 連接埠，此時請使用 DNS-01。

## 短期憑證與 IP 位址憑證

「憑證設定檔」對應 ACME 的 profile：

- **預設**：由 CA 決定，Let's Encrypt 為 90 天；
- **短期憑證（IP 憑證）**：即 Let's Encrypt 的 `shortlived` 設定檔，有效期約 6 天，Gately 在到期前依「續簽設定」中的「短期憑證提前小時數」（預設 24 小時）自動續簽，失敗後每小時重試一次；
- 也可以輸入 CA 支援的其他設定檔名稱。

在網域名稱中填寫公網 IP 位址（IPv4 或 IPv6，如 `203.0.113.10`、`2001:db8::1`）即可申請 IP 位址憑證，IP 與網域可以寫在同一張憑證裡。要求：

- 使用 Let's Encrypt，憑證設定檔選擇短期憑證，「驗證方式」選擇 HTTP-01，CA 會存取 `http://<IP>/.well-known/acme-challenge/<token>`，要求該 IP 的 80 連接埠可從公網存取。填寫 IP 後編輯框會提示，點「一鍵設定」即可；
- 內網位址、回送位址與 `100.64.0.0/10` 無法通過公共 CA 驗證；自訂 CA（如內網自建的 ACME 服務）不受這些限制；
- ZeroSSL、Google Trust Services 不透過 ACME 簽發 IP 位址憑證。

透過 IP 位址存取 HTTPS 時瀏覽器不傳送網域名稱（SNI），Gately 會依連線的本機位址選擇對應的 IP 憑證；經 NAT 或連接埠轉發、本機位址不是憑證中的公網 IP 時，使用到期時間最晚的 IP 憑證。

把已簽發憑證的設定檔在預設與短期之間切換後，會立即依新設定檔重新簽發。短期憑證只在剩餘時間不到提前小時數的一半（代表續簽多次失敗）時發出到期提醒。

## 憑證對應

啟用憑證後，Gately 會把 `.crt`、`.key`、`.pem` 與 `_issuerCertificate.crt` 寫入對應目錄，並執行變更指令碼。

## 自動部署

在憑證的「自動部署」中可以新增多個部署目標，憑證簽發、續期或更新後自動執行：

- **複製到本機目錄**：把憑證寫入本機的目錄，再在本機執行「複製後執行」的指令，可以新增多個目錄、每個目錄使用不同的指令。目錄中的憑證檔案被刪除或改動後，下一次檢查會重新複製。Gately 在 Docker 中執行時，目錄與指令都在容器內；
- **上傳到 SSH 主機**：選擇 [Web 終端](/zh-TW/docs/modules/terminal) 中既有的 SSH 連線，沿用它的位址、驗證方式與代理。憑證檔案（`<備註>.crt`、`.key`、`.pem`、`_issuerCertificate.crt`，與憑證對應相同，因此備註不能為空）寫入遠端目錄後，在遠端主機執行「上傳後執行」的指令，例如 `systemctl reload nginx`，指令中可用 `$certName`、`$certDir`、`$certFile`、`$keyFile`。檔案先寫入暫存檔並設好權限再改名取代，私鑰權限為 0600；
- **重新啟動本機容器**：憑證變動後依序重新啟動所選的 Docker 容器，適合容器掛載了對應目錄、需要重新啟動才能載入新憑證的服務。

「複製到本機目錄」與「上傳到 SSH 主機」可以填寫憑證（完整鏈）與私鑰的檔名，例如 `fullchain.pem` 與 `privkey.pem`，兩個都填寫後只寫入這兩個檔案，此時備註可以為空；留空時使用與憑證映射相同的檔名。指令中的 `$certFile`、`$keyFile` 指向實際寫入的檔案。

自動部署不會信任未知主機：所選 SSH 連線需要先在 Web 終端中連線一次，記錄主機金鑰後才會推送。部署失敗時每小時重試一次，並發出「憑證：部署失敗」事件，可在 [通知中心](/zh-TW/docs/modules/notify) 訂閱。憑證卡片上的「立即部署」會忽略重試間隔，馬上部署到所有啟用的目標並顯示每個目標的結果。

編輯憑證時，目標設定沒有變動的部署不會重複執行；修改遠端目錄、指令或容器後會重新部署一次。

## 安全提示

私鑰儲存在設定目錄的 `ssl.json` 中，請妥善保管該檔案，納入版本庫時確認儲存庫為私有。
