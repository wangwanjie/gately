# Tailscale / NetBird / frp / cloudflared

四個模組以行程託管方式整合官方程式：自動重啟、日誌彙整到介面、設定在介面中完成。Gately 本體並未內建這些程式，可以在頁面中線上安裝、更新與回滾。

## 線上安裝、更新與回滾 {#install}

frp、Cloudflare 通道、Tailscale、NetBird 與 [File Browser](/zh-TW/docs/modules/tools#filebrowser) 頁面下方都有「線上安裝」卡片：

- **下載安裝 / 更新到最新版**：從上游下載最新正式版，依上游記錄的 SHA-256 校驗，確認能在本機執行後安裝到設定目錄的 `bin/`，完成後自動重啟使用該程式的行程。已經是最新版時不會重複下載；
- **檢查更新**：只查詢上游最新正式版，不下載；有新版本時卡片標題旁顯示「新版本」。開啟[自動檢查更新](/zh-TW/docs/guide/install#update-check)時，Gately 每 12 小時為已安裝的程式檢查一次，發現新版本時發布 `program.update` 通知；
- **安裝指定版本**：填寫版本號（例如 frp 的 `v0.65.0`、cloudflared 的 `2025.8.0`、Tailscale 的 `1.90.2`），可用於降級；
- **下載代理**：每個程式可以單獨設定，支援 http、https 與 socks5，開始安裝時儲存；留空時使用「設定」中的更新代理；
- **舊版本與回滾**：被更新或回滾替換下來的版本儲存在 `bin/.versions/` 下，最多保留 3 個。新版本有問題時在清單中點「回滾」即可切回，目前版本同樣會保留，之後還能再切回來；
- **解除安裝**：刪除 `bin/` 下安裝的程式與全部舊版本，模組設定保留。之後使用該程式的行程會重啟，`PATH` 中有同名程式時改用它，沒有時無法執行。

| 程式 | 來源 | 安裝的檔案 |
| --- | --- | --- |
| frp | GitHub fatedier/frp | `frpc`、`frps` |
| cloudflared | GitHub cloudflare/cloudflared | `cloudflared` |
| Tailscale | pkgs.tailscale.com 靜態套件，僅 Linux | `tailscale`、`tailscaled` |
| NetBird | GitHub netbirdio/netbird，Linux、macOS、Windows | `netbird` |
| FileBrowser Quantum | GitHub gtsteffaniak/filebrowser | `filebrowser` |

Tailscale 在 macOS 與 Windows 上沒有可直接執行的程式套件，請使用官方安裝程式，再於設定中填寫路徑。卡片會提示目前平台不支援的情況。

## 恢復預設設定 {#reset}

頁首的「恢復預設設定」與解除安裝分開處理：停止該模組的全部行程，把設定（包括程式路徑與下載代理）恢復為預設值，並刪除 Gately 為它產生的檔案，安裝的程式保留。

| 模組 | 清除的內容 |
| --- | --- |
| frp | 全部 frpc / frps 實例、代理與程式設定，`frp/` 下產生的設定檔 |
| Cloudflare 通道 | 全部通道與程式設定 |
| Tailscale | 全部設定，預設狀態目錄中的登入狀態；Gately 託管的 tailscaled 執行中時先登出。自訂的狀態目錄與系統既有的 tailscaled 不處理 |
| NetBird | 全部設定，預設狀態目錄中的登入狀態與金鑰；Gately 託管的常駐程式執行中時先登出，本機從組網中刪除。自訂的狀態目錄與系統既有的 NetBird 服務不處理 |
| File Browser | 全部實例與程式設定，各實例的使用者、分享連結與快取；共享目錄中的檔案不受影響 |

舊設定保存在 [設定歷史](/zh-TW/docs/guide/audit) 中，誤操作時可以還原。要徹底移除，先解除安裝程式，再恢復預設設定。介面為 `DELETE /api/{module}/install`（解除安裝）與 `POST /api/{module}/reset`（恢復預設設定）。

## 程式放置

依以下順序尋找可執行檔：

1. 模組設定中填寫的路徑；
2. 設定目錄下的 `bin/` 子目錄（線上安裝的位置）；
3. `PATH`。

填寫了路徑時線上安裝的版本不會生效，卡片會提示。也可以自行把執行檔放進設定目錄，Docker 部署時例如 `./gately-data/bin/frpc`。Tailscale 需要同時提供 `tailscale` 與 `tailscaled`；使用系統既有的 tailscaled 時，安裝的 `tailscale` 指令最好與常駐程式版本一致。

權杖與金鑰以 0600 權限儲存，cloudflared 的權杖透過環境變數傳遞，不會出現在行程清單中。

## Tailscale

- 託管 `tailscaled`（使用者空間網路，對容器友善）或接入系統既有的常駐程式；
- 驗證金鑰或登入連結，支援 Headscale；
- 子網路由與出口節點；
- 節點清單與 SOCKS5 代理。該代理沒有認證，監聽位址不限於本機（如 `0.0.0.0` 或區域網路 IP）時介面會提示，建議只監聽 `127.0.0.1`；
- 固定 WireGuard UDP 連接埠，方便在防火牆放行直連；
- tailscaled 額外參數與環境變數。主機 iptables 是 nf_tables 後端時，在環境變數中加入 `TS_DEBUG_FIREWALL_MODE=nftables`，子網轉發才會生效。

## NetBird

- 加入 NetBird 官方雲或自建管理服務（填寫管理服務位址）的組網；
- 設定金鑰或登入連結認證。Linux 下的登入連結是裝置碼登入，可以在任意裝置上開啟；macOS 與 Windows 上通常只能在執行 Gately 的這台電腦上用瀏覽器完成登入，遠端管理時請使用設定金鑰。連結過期後自動更新；
- 託管 `netbird` 常駐程式（使用者態網路，容器友善）或接入系統已安裝的 NetBird 服務；
- 使用者態網路下預設允許其他節點存取本機服務（包括只監聽 127.0.0.1 的服務，仍受管理端存取策略限制），本機程式透過 SOCKS5 代理（預設 `127.0.0.1:1080`）存取組網內的裝置；
- SOCKS5 代理沒有認證，監聽位址不限於本機時介面會提示。0.75 之前的 NetBird 在使用者態網路下會忽略設定的位址，總是在 `0.0.0.0` 上提供無認證的 SOCKS5 代理，其他裝置可以經由它存取組網；Gately 託管守護行程時偵測到這類版本會在日誌中警告，請升級到 0.75 或更新版本；
- 網路路由、出口節點與存取策略在 NetBird 管理端設定，Gately 中可以選擇是否接受路由、是否作為路由節點、是否接受 DNS 以及拒絕入站；
- 節點清單顯示直連或中繼、延遲與網路路由；
- 固定 WireGuard 連接埠，常駐程式額外參數與環境變數（NetBird 文件中以 `NB_` 開頭的進階選項）；
- 關閉使用者態網路時使用核心 WireGuard：需要 root 與 TUN 裝置，會建立 `wt0` 網路介面並自行加入防火牆規則（OpenWrt 的 fw4 中也會放行 `wt0` 入站），本機服務要監聽在所有位址或組網位址上才能被其他節點存取；
- `netbird` 程式約 41 MB，執行時記憶體約 60 MB，線上安裝還會在 `bin/.versions/` 保留最多 3 個舊版本。快閃記憶體較小的路由器請留意剩餘空間，可在安裝卡片中刪除舊版本，或把程式放在外部儲存並在設定中填寫路徑；
- 恢復預設設定與 `POST /api/netbird/logout` 會從管理服務註銷本機，節點從組網中刪除，再次加入需要重新認證。

## frp

- **frpc 用戶端**：可新增多個 frpc 實例，每個實例連線一台 frps，獨立執行、單獨啟停與重新啟動；代理歸屬某個實例，支援 tcp / udp / http / https / stcp / xtcp，增刪改後只重新啟動所屬實例；
- **代理存取位址**：frpc 不知道 frps 的 HTTP / HTTPS 連接埠和子網域根網域，可在 frpc 實例的「存取位址」中填寫（本機也有 frps 實例時可一鍵填入；frps 前面還有反向代理或 CDN 時填訪客實際使用的協定和連接埠）。填寫後 http / https 代理的網域（含子網域拼出的完整網域）可點擊開啟、可複製完整位址，未填寫時照常顯示文字。存取位址只用於產生連結，修改後 frpc 不重新啟動。自訂網域儲存時與 Web 服務一樣統一為小寫和 punycode，帶連接埠、路徑的寫法會被拒絕；子網域只能填一級名稱（如 `nas`），與 frps 的要求一致；
- **frps 伺服器端**：可新增多個 frps 實例（使用不同連接埠），每個實例有連接埠白名單、子網域、控制台；
- **從舊版本升級**：0.5.9 及更早版本的單一 frpc / frps 設定會自動遷移為名為 `frpc` / `frps` 的實例，原有代理歸屬該 frpc 實例，程式路徑移到頁面下方的「程式」卡片；
- **frps 監聽位址**：「監聽位址」決定 frpc 連線連接埠監聽在哪，「代理監聽位址」決定 HTTP / HTTPS 連接埠和 tcp / udp 代理的遠端連接埠監聽在哪，留空都監聽所有位址。frps 放在 Gately 等反向代理之後時，把監聽位址填 `127.0.0.1`，在 Web 服務中把一個站點反代到 `127.0.0.1:<綁定連接埠>`，frpc 的傳輸協定選 websocket 或 wss 並連線該站點；代理監聽位址保持留空，tcp 代理的遠端連接埠照常對外開放。匯入 frps 設定時，原設定未寫 `proxyBindAddr` 會沿用 `bindAddr`，與 frps 的行為一致；
- **frps 來源 IP 存取控制**：每個 frps 實例可設定白名單或黑名單，依來源 IP 決定 frpc 能否登入（連線綁定連接埠）。名單由手填的 IP / 網段和 Web 服務中的訂閱 IP 清單組成，符合任一項即視為在名單中；訂閱清單由 Web 服務模組定時下載，更新後立即生效，frps 不必重新啟動，下載成功前視為空清單。判斷在 frps 驗證權杖之前進行：Gately 在本機迴環位址開一個檢查端點，並在產生的 frps 設定末尾寫入 `[[httpPlugins]]`（`ops = ["Login"]`），因此只對 frpc 登入生效，tcp / udp 代理的遠端連接埠與 HTTP / HTTPS 連接埠照常對外開放。入侵防護的封鎖優先於名單：被封鎖的位址即使落在白名單網段內也無法登入，未設定存取控制的實例同樣遵守封鎖表，與是否開啟防火牆同步無關。被拒絕的 frpc 會收到 `gately: client address ... is not in the allowlist` 之類的錯誤，實例卡片顯示 Gately 啟動以來的拒絕次數。名單在 frpc 登入時檢查，作用於 frpc 連線 frps 的綁定連接埠：名單收緊或位址被封鎖後，已登入的 frpc 保持連線，下次登入時才被拒絕，需要立即生效時重新啟動該 frps 實例；stcp / xtcp 的 visitor 連線不經過登入檢查，需要限制時搭配[入侵防護](/zh-TW/docs/modules/guard)的防火牆同步。frps 放在反向代理之後（監聽位址填 `127.0.0.1`）時，frps 看到的來源是代理的位址，請改在 Web 服務站點上做 IP 存取控制；放在協定分流或連接埠轉發後面時，frps 看到的來源是本機位址，名單無法依訪客判斷，請在分流或轉發規則上設定來源 IP 存取控制；
- **匯入既有設定**：頁首的「匯入設定」支援舊版 `frpc.ini` / `frps.ini`（含 `[common]` 段）與 frp 0.52+ 的 `toml`，可選擇檔案或貼上內容，並選擇匯入到既有實例或新增實例。先預覽解析結果與被忽略的欄位，再確認匯入；匯入到既有 frpc 實例時可選擇附加（同名代理保持不變）或取代該實例的全部代理。匯入到既有實例時沿用其啟用狀態，新增的實例預設停用；也可透過介面 `POST /api/frp/import` 呼叫。從 Lucky 遷移時，Lucky 中的每個 frpc / frps 實例都會匯入為 Gately 的實例。

## Cloudflare 通道

- 權杖通道與 trycloudflare 臨時通道；
- 多通道、自動重啟；
- 顯示公網位址。

### 路由規則 {#cloudflared-ingress}

權杖通道的公網主機名稱與回源服務（路由規則）儲存在 Cloudflare 上，執行中的 cloudflared 會自動拉取。在通道設定中填寫選填的 **API 權杖** 後，卡片上的「路由規則」可以直接編輯這些規則：

- 權杖需要「Cloudflare Tunnel：編輯」權限；要自動建立 DNS 記錄，還需要對應網域的「DNS：編輯」權限。帳號與通道 ID 從通道權杖中解析，無需另外填寫。
- 每條規則包含主機名稱、選填的路徑正規表示式與服務（如 `http://localhost:8080`、`ssh://localhost:22`、`http_status:404`），依序比對，符合第一條即轉送；可設定「不驗證回源憑證」和回源 Host 標頭，其他回源設定原樣保留。所有規則都未符合時使用預設服務，預設 `http_status:404`。
- 儲存後立即生效，無需重新啟動通道。若規則在此期間被 Cloudflare 控制台或其他地方修改，儲存會提示並顯示「重新載入」，避免覆蓋別人的修改。HTTP 類服務不能帶路徑，結尾單獨的 `/`（如 `http://nas:5000/`）儲存時會自動去掉，否則 cloudflared 會拒絕整份設定。
- 通道由本機設定檔管理時（介面會提示遠端規則不生效），儲存前需要再確認一次：寫入遠端設定後通道改為遠端管理，本機設定檔中的路由規則不再生效。
- 開啟「同步 DNS」時，為每個主機名稱建立開啟代理、指向 `<通道ID>.cfargotunnel.com` 的 CNAME 記錄；主機名稱已有其他記錄，或已有指向通道但未開啟代理的 CNAME（這時流量不會進入通道）時保持原樣並在結果中列出。只在通道所屬帳號下尋找網域。刪除規則時 DNS 記錄保留，需要時在 Cloudflare 中刪除。

## 如何選擇

| 情境 | 建議 |
| --- | --- |
| 在多台裝置之間組成私有網路 | Tailscale |
| 組網，並希望用戶端與管理端都開源、可以自建 | NetBird |
| 自己有公網伺服器，把內網服務對應出去 | frp |
| 沒有公網 IP 也沒有伺服器，快速公開 Web 服務 | Cloudflare 通道 |
| 電信業者提供了可打洞的 NAT | [STUN 穿透](/zh-TW/docs/modules/stun) |
