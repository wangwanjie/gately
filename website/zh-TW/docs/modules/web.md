# Web 服務

依網域提供反向代理、重新導向、靜態檔案與固定文字，是 Gately 的統一 Web 入口。選單位置：側邊欄「Web → Web 服務」。

## 結構：監聽、站台與預設站台

設定分三層：

1. 監聽：一個監聽連接埠。欄位包括網路（`tcp` 雙堆疊、`tcp4`、`tcp6`）、監聽位址（留空為所有位址）、連接埠、HTTPS 開關、最低 TLS 版本（1.0 / 1.1 / 1.2 / 1.3）、是否接收 PROXY 協定。
2. 站台：監聽下依網域比對的一個站台。網域支援精確網域、`*.example.com`（比對任意層級子網域）與 `*`（比對全部）；比對優先順序為精確網域、萬用字元、`*`。
3. 預設站台：沒有站台符合時使用，未啟用時回傳 404。也可以把預設站台設為「中斷連線」，讓未知網域的請求得不到任何回應。預設站台設定後顯示在站台清單最後；尚未設定時，點擊監聽卡片上的「設定預設站台」進行設定。

修改站台或預設站台並儲存時，站台清單會原地替換：監聽保持執行，已建立的連線（含 WebSocket）不會中斷，各站台的統計資料也會保留。新設定無效時繼續使用原來的站台。修改監聽自身的設定（網路、位址、連接埠、HTTPS、最低 TLS、HTTP/3、PROXY 協定）會重新啟動該監聽。

站台清單中的每個具體網域都是可點擊的完整位址，在新分頁開啟，旁邊的按鈕可複製該位址；萬用字元網域（`*.example.com`、`*`）照常顯示為文字。位址依監聽推算：開啟 HTTPS 用 `https`，否則用 `http`，連接埠為監聽連接埠，443 與 80 這類預設連接埠省略，例如 `https://example.com:8443`。經協定分流、路由器連接埠對映、frp 或 CDN 存取時，對外的協定或連接埠可能與監聽不同，可在監聽的「存取位址」中指定協定與連接埠（例如監聽 8443 由協定分流在 443 轉入時填 443；CDN 回源到 http 8080 時選 https 並填 443）。存取位址只用於產生連結，修改後不重新啟動監聽。儲存時網域統一為瀏覽器請求中的形式：轉為小寫，IPv6 去掉方括號，中文等國際化網域轉為 punycode（如 `中文.com` 儲存為 `xn--fiq228c.com`）；帶連接埠、路徑、`@` 等永遠比對不到的寫法會被拒絕。從 Lucky 或 nginx 匯入時只略過寫錯的網域並給出提示。

站台可以填寫「分組」（最長 64 個字元，預設站台不能分組）。清單在每個監聽下依分組顯示可摺疊的區塊：分組依首次出現的順序排列，未分組的站台排在後面，預設站台始終在最後；各分組的摺疊狀態保存在瀏覽器中。點擊「排序」進入排序模式，可以上移、下移站台，在分組內拖曳站台，整組移動，以及調整監聽的順序。順序只影響清單顯示，網域比對依上面的優先順序進行，與站台順序無關；儲存排序同樣原地替換站台清單，不會中斷連線。頁首的搜尋框可依網域、名稱、分組、後端或備註篩選站台。

排序模式下還可以勾選多個站點（分組標題的核取方塊可選中整組）：拖動其中任一項會一起移動，拖到其他分組的站點或分組標題上即加入該分組；工具列可以把選中的站點批次移到指定分組，留空則移出分組。跨監聽的選中站點批次設定分組時，各監聽分別儲存。

滑鼠移到分組標題上，點鉛筆按鈕可以重新命名分組：組內條目一起改為新名稱，位置和順序不變；改成已有分組的名稱時，確認後兩個分組合併。

## 站台類型

| 類型 | 說明 |
| --- | --- |
| 反向代理 | 轉發到一個或多個後端，後端位址格式為 `http(s)://主機:連接埠`，支援 WebSocket |
| 重新導向 | 跳轉到完整 URL，狀態碼 301 / 302 / 307 / 308（預設 302），可選保留原路徑與查詢字串。URL 中可以寫 `{host}`，會替換為訪客使用的網域：`https://{host}` 加上「保留路徑」，就能把所有 HTTP 請求跳轉到同一網域的 HTTPS。還可以使用 `{path}`、`{1}`、`{STUN_規則名_PORT}` 等變數，見 [重新導向變數](#redirect-vars) |
| 靜態檔案 | 目錄需為絕對路徑；關閉「目錄列表」時，目錄請求只在存在 `index.html` 時回傳。「無副檔名網址」在檔案不存在時再嘗試 `路徑.html` 與 `路徑/index.html`（適用於 VitePress 等產生器，相當於 nginx 的 `try_files $uri $uri.html $uri/index.html`）；「404 頁面」填寫目錄內的路徑，如 `404.html`，以 404 狀態回傳 |
| 固定文字 | 自訂內容、`Content-Type`（預設 `text/plain; charset=utf-8`）與狀態碼（100-599，預設 200） |
| 中斷連線 | 不回傳任何內容，直接中斷連線，相當於 nginx 的 `return 444`。常用作預設站台，讓掃描未知網域的請求得不到回應；存取日誌記為 444；不經過認證、存取控制、WAF 與重寫，站台的其他設定都不生效 |

所有類型的站台都可設定存取日誌、跨來源（CORS）、自訂請求標頭與回應標頭（每行 `Key: Value`，Value 留空表示刪除該標頭），並可引用一個 [WAF 防火牆](/zh-TW/docs/modules/waf) 實例（實例不存在或停用時放行）。請求標頭、回應標頭與 Content-Type 的編輯方式見 [請求標頭與回應標頭](#headers)。

存取日誌會記錄用戶端 IP、方法、網域與路徑、狀態碼、耗時、站點名稱，行尾依 nginx 的格式附上 Referer 與 User-Agent（缺少時為 `-`），同一個對外 IP 後面的不同裝置可以透過 User-Agent 區分。可在日誌中依站點、狀態碼、來源 IP 等條件篩選，見 [執行日誌的檢視與篩選](/zh-TW/docs/guide/configuration#log-filter)。

### 重新導向變數 {#redirect-vars}

重新導向站台的目標位址可以使用以下變數：

| 變數 | 意義 |
| --- | --- |
| `{host}` | 訪客請求的網域，不含連接埠 |
| `{port}` | 存取連接埠 |
| `{hostAndPort}` | 網域加連接埠，與請求的 Host 一致 |
| `{path}` / `{PATH}` | 請求路徑，`{PATH}` 不含開頭的 `/` |
| `{args}` / `{Args}` | 查詢字串，`{args}` 帶開頭的 `?`（沒有查詢字串時為空），`{Args}` 不帶 |
| `{domainPartN}` / `{pathPartN}` | 網域（以 `.` 分隔）或路徑（以 `/` 分隔）的第 N 段，N 從 1 開始 |
| `{ClientIP}` / `{RemoteIP}` | 用戶端 IP |
| `{time}` | 目前時間，格式 `2006-01-02 15:04:05`，其中空格寫成 `%20`（即 `2006-01-02%2015:04:05`），確保跳轉位址是合法 URL |
| `{1}` | 站台網域 `*.example.com` 中 `*` 比對到的部分；命中精確網域時為空，命中 `*` 或預設站台時為完整網域 |
| `{STUN_規則名_PORT}` / `{STUN_規則名_IP}` / `{STUN_規則名_ADDR}` | [STUN 穿透](/zh-TW/docs/modules/stun) 規則目前的公網連接埠、IP、`IP:連接埠`；規則名即清單中的名稱，可以含底線 |

- 開啟「保留路徑」時，目標中寫了 `{path}`、`{PATH}` 或 `{pathPartN}` 就不再附加原路徑，寫了 `{args}`、`{Args}` 或目標自帶查詢字串就不再附加原查詢字串，另一部分照常附加；
- STUN 連接埠變化後無需修改站台，下一次請求就跳到新連接埠。引用的規則不存在、未啟用、尚未穿透成功或正在自動重試時，站台回傳 503，執行日誌中會記錄原因；
- 變數展開後跳轉位址缺少主機（例如命中精確網域時 `{1}` 為空，目標卻只寫了 `https://{1}`）時回傳 503；訪客網域含 `&`、`=`、`/`、`@` 等網域中不會出現的字元時回傳 400，不會代入跳轉位址；
- 站台網域只支援一個 `*`，所以只有 `{1}`；
- 路徑重寫規則中的重新導向目標仍只支援 `{host}`；未知的 `{xxx}` 原樣保留。

例：Cloudflare CDN 把 `*.example.com` 回源到本機 2053 連接埠，這個監聽上有一個網域為 `*.example.com` 的重新導向站台，目標填 `https://{1}.v4.example.com:{STUN_web_PORT}{path}{args}`。存取 `zly.example.com/a?b=1` 會跳到 `https://zly.v4.example.com:<STUN 連接埠>/a?b=1`；STUN 規則 web 轉發到另一個監聽，在那裡為 `*.v4.example.com` 下的各個網域建立反向代理站台。

### 反向代理選項 {#proxy-options}

位於站點編輯框「基本」頁的「選項」，旁邊的問號圖示可在介面中查看簡要說明並跳到本節。

| 選項 | 作用 | 什麼時候開啟 |
| --- | --- | --- |
| 略過後端憑證驗證 | 連線 HTTPS 後端時不驗證憑證 | 後端使用自簽或過期憑證，如 NAS、路由器管理頁的 https 連接埠。關閉驗證後無法確認後端身分，只建議用於內網後端 |
| Host 使用後端位址 | 送往後端的 Host 標頭改為後端位址；關閉時（預設）保留訪客請求的 Host | 後端只認自己的位址，例如回傳 400 / 403、跳到錯誤位址或提示 Host 不符；反向代理到公網網站或 CDN 時通常需要。後端按網域區分站點，或需要用造訪網域產生連結時保持關閉 |
| 停用連線重用 | 每個請求都建立新的後端連線（關閉 Keep-Alive） | 後端偶爾出現連線被重設、請求卡住，或不支援長連線。會增加一些延遲，正常情況保持關閉 |
| 新增 X-Forwarded-* | 寫入 `X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host` / `X-Forwarded-Port` 與 `X-Real-IP`，告訴後端訪客的真實 IP、原始協定、網域和連接埠 | 後端需要記錄真實 IP，或要知道外部是 HTTPS 才能產生正確連結（否則可能跳回 http 或登入後循環跳轉）。多數應用建議開啟 |
| 向後端傳送 PROXY v2 | 在 TCP 連線開頭附加 PROXY 協定 v2 標頭，傳遞真實用戶端 IP。開啟後每個請求都新建連線，也不再用 HTTP/2 連線後端。後端是 Gately 時，需在其監聽上開啟接收 PROXY 協定，並把本機加入可信 PROXY 來源。 | 後端不讀 HTTP 標頭但支援 PROXY 協定，如另一層 Gately、haproxy、開啟 `proxy_protocol` 的 nginx。後端未設定接收時所有請求都會失敗，不確定時保持關閉 |
| 使用造訪網域作為 SNI | 僅 HTTPS 後端：交握時傳送訪客使用的網域並據此驗證憑證，相當於 nginx 的 `proxy_ssl_server_name on; proxy_ssl_name $host` | 後端在同一連接埠按網域選擇憑證或分流，如 frp 的 `vhost_https`、託管多個 HTTPS 站點的 nginx。每個後端使用獨立的連線池，不同網域的連線不會互相重用 |
| 轉發 Gately 登入 Cookie | 把 Gately 自己的登入 Cookie（單一登入 `gately_sso`、站點工作階段、第三方登入隨機數）原樣轉發給後端；關閉時（預設）這些 Cookie 不發給後端，避免洩露登入憑據 | 後端是另一台負責認證的 Gately，本站點不開認證。例如公網 Gately 只做 WAF 與存取控制、反代到內網 Gately，由內網 Gately 負責網頁認證與單一登入。本站點啟用認證時不能開啟；只在後端是自己的 Gately 時使用 |

常見組合：

- 反向代理內網的 Web 應用（如 `http://192.168.1.10:5000`）：只開「新增 X-Forwarded-*」；
- 後端是自簽憑證的 https 位址：再開「略過後端憑證驗證」；
- 反向代理公網網站或第三方服務：開「Host 使用後端位址」；
- 後端前面還有按 SNI 分流的服務（如 frp `vhost_https`）：開「使用造訪網域作為 SNI」。
- 公網 Gately 只做 WAF、內網 Gately 負責登入：公網站點不開認證，開「轉發 Gately 登入 Cookie」，需要真實 IP 時再開「向後端傳送 PROXY v2」，並在內網 Gately 上接收 PROXY 協定、把公網 Gately 加入可信來源。

### 請求標頭與回應標頭 {#headers}

在站點編輯框的「請求標頭」頁設定。請求標頭送往後端，只對反向代理站點生效；回應標頭回傳給用戶端，對所有類型的站點生效。

- 逐行編輯：點擊名稱框會列出常用標頭及其用途，選中後自動填入常用值，值框也可以改選其他常用值；兩者都可以直接手動輸入。值留空表示刪除該標頭，在名稱框貼上整行 `Key: Value` 會自動拆開；
- 「新增常用安全標頭」補齊 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN` 與 `Referrer-Policy: strict-origin-when-cross-origin`，已有的標頭不會重複新增；
- 「文字模式」可一次貼上多行 `Key: Value`，切回逐行編輯時保留內容；
- 「分路徑後端」中每個路徑的附加請求標頭使用同樣的編輯方式，在站點請求標頭之後套用，同名時以路徑的為準。

每一行下方會即時給出回饋。紅色表示儲存會失敗或該標頭無法生效，如缺少名稱、名稱含空格或冒號等非法字元、文字模式中缺少冒號；橙色表示可以儲存但結果可能不符預期：

- 請求標頭裡設定 `Host` 不會生效，需要改寫時開啟「Host 使用後端位址」；
- `X-Forwarded-For`、`X-Real-IP` 寫固定值會覆蓋真實用戶端 IP，傳遞用戶端 IP 請開啟「新增 X-Forwarded-*」；
- `Content-Length`、`Connection`、`Transfer-Encoding` 等由連線自動管理，手動設定會被忽略或導致傳輸異常；
- 值按原樣送出，不支援 nginx 的 `$host` 等變數；預設值中的 `<token>` 等占位內容需要替換；
- 同名標頭按順序設定，後面的覆蓋前面的。

「固定文字」站點的 `Content-Type` 可從常用類型中選擇或手動輸入，介面會檢查 `類型/子類型; 參數=值` 格式；`text/*` 未宣告 `charset` 時提示中文等內容可能亂碼，留空時使用 `text/plain; charset=utf-8`。

## 傳輸與協定

- HTTPS：使用 [SSL 憑證](/zh-TW/docs/modules/ssl) 模組中涵蓋該網域的憑證；
- 同埠 HTTP：開啟 HTTPS 的監聽可同時接受明文 HTTP，依連線的第一個位元組區分協定。「跳轉到 HTTPS」把 `http://位址:埠` 重新導向到 `https://位址:埠`（GET/HEAD 用 301，其他方法用 308），適合只能使用一個埠、又希望輸錯協定也能開啟的情境；「直接服務」以 HTTP 提供站台，不加密。ACME HTTP-01 驗證請求照常回應，修改此項會重啟該監聽；
- HTTP/3（QUIC）：在開啟 HTTPS 的監聽中啟用，相同埠號的 UDP 上同時提供 HTTP/3，並透過 `Alt-Svc` 回應標頭通告瀏覽器；需要在防火牆與連接埠映射中放行該 UDP 埠；
- WebSocket：反向代理自動支援；
- PROXY 協定：監聽可接收上游（如 haproxy、frp）送出的 PROXY 標頭，僅信任「全域設定 → 可信 PROXY 來源」中列出的 IP 或網段，留空表示不信任任何來源；反向代理可向後端送出 PROXY 標頭。經可信來源進入的連線帶的 `X-Forwarded-Proto: https` 同樣被採信：工作階段 Cookie 帶 Secure、開啟明文跳轉的連接埠不再跳轉，開啟「新增 X-Forwarded-*」時也向後端如實傳遞 https。

### 訪客真實 IP（CDN / WAF 之後） {#real-ip}

站點放在 Cloudflare、阿里雲 CDN、騰訊雲 CDN 等 HTTP 代理後面時，連線來自代理的回源位址。在「全域設定 → 訪客真實 IP」中填寫可信代理（代理的回源 IP 或網段，可填多家）並選擇真實 IP 請求標頭後，Gately 從請求標頭取得訪客位址，存取日誌、IP 黑白名單、僅內網存取、國家過濾、認證失敗封鎖、存取統計、路徑探測，以及轉發給後端的 `X-Real-IP` / `X-Forwarded-For` 都使用該位址。

- 只在原始對端位於可信代理中時讀取請求標頭。原始對端指 PROXY 協定處理後的位址：經可信 PROXY 來源進入時是 PROXY 標頭中的位址，否則是 TCP 對端。直接存取時用戶端自帶的請求標頭一律忽略；
- 請求標頭依選擇的順序查找，第一個能給出有效位址的標頭生效，未選擇時為 `X-Forwarded-For`。`X-Forwarded-For` 等多項標頭由右至左跳過可信代理，取第一個不可信的位址，用戶端在左側偽造的值不會被採用；
- 只選擇你的代理會覆寫的標頭。例如 Cloudflare 覆寫 `CF-Connecting-IP`，其他代理通常原樣轉發用戶端自帶的同名標頭，這時選 `X-Forwarded-For` 更安全；
- 使用 Cloudflare 時建議把真實 IP 請求標頭設為 `CF-Connecting-IP`，它由 Cloudflare 直接寫入訪客位址。`X-Forwarded-For` 由右至左跳過可信代理，可信代理填了整段 Cloudflare 位址時，經 Cloudflare 自身出口（如 Workers）發來的請求可以在左側帶上偽造的位址；
- 不能填寫 `0.0.0.0/0`、`::/0`，儲存時會被拒絕；
- 協定分流把連線經迴環轉給 Web 服務時，請在協定分流中開啟傳送 PROXY 標頭、在監聽上開啟接收 PROXY 協定，不要把 `127.0.0.1` 填進可信代理，否則直接連到協定分流的訪客也能偽造請求標頭。協定分流的透傳路由仍是純 TCP 轉發，不受此設定影響；
- 經可信代理進入、帶 `X-Forwarded-Proto: https` 的請求按 HTTPS 處理；
- 未填寫可信代理時保持原有行為。連線層面的封鎖（入侵防護寫入防火牆的規則）針對的是 TCP 來源，在 CDN 之後對訪客不起作用，Web 服務自身的封鎖依真實位址生效。

## 驗證

在站台編輯視窗的「安全」頁設定：

- 網頁驗證：瀏覽器顯示登入頁；
- 基本驗證：HTTP Basic；
- 使用者：每行 `使用者名稱:密碼`，密碼可填 bcrypt 雜湊。啟用基本驗證時至少需要一位使用者；啟用網頁驗證時至少需要一位使用者或第三方登入身分；
- 第三方登入：支援 GitHub、Google、QQ、OIDC，使用自己的 OAuth 應用程式。允許的身分每行一條，格式 `提供方識別碼:帳號`，例如 `github:octocat`、`google:me@gmail.com`，行尾可用 `#` 加備註，`github:*` 表示該提供方的任意帳號。

第三方登入的提供方在「全域設定」中設定：填寫自己的 Client ID / Secret 並啟用，同時設定回呼位址（需由 Gately 的某個監聽提供，例如 `https://auth.example.com`）。登錄到 GitHub / Google / QQ 的回呼 URL 為：

```text
https://auth.example.com/__gately_auth/oauth/callback
```

管理後台自身的第三方登入在「設定 → 帳號與安全」中單獨設定。

### 轉發認證（Authelia 等）

把認證交給外部服務，相當於 nginx 的 `auth_request` 或 Traefik 的 `forwardAuth`。在「安全」頁勾選「轉發認證」；同一站台不能同時啟用基本驗證或網頁驗證。

| 欄位 | 說明 |
| --- | --- |
| `url` | 驗證介面，例如 Authelia 的 `http://127.0.0.1:9091/api/authz/auth-request` |
| `loginUrl` | 介面回傳 401 時把訪客跳轉到的位址，例如 `https://auth.example.com/?rd={url}&rm={method}`；`{url}` 為原始位址（已編碼），`{method}` 為請求方法。留空時原樣回傳介面的回應 |
| `copyHeaders` | 驗證通過後從介面回應複製到後端請求的身分標頭，預設 `Remote-User`、`Remote-Groups`、`Remote-Email`、`Remote-Name` |

運作方式：

- 每個請求先以不帶請求本文的 GET 送到 `url`，帶上訪客的請求標頭（Cookie、`Authorization` 等），以及 `X-Original-Method`、`X-Original-URL`、`X-Forwarded-Method`、`X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-Uri`、`X-Forwarded-For` 與 `X-Real-Ip`，逾時 10 秒；
- 回傳 2xx 即放行，並帶上身分標頭；回傳 401 時跳轉到 `loginUrl`（狀態碼 302）；其他結果（如 403 或跳轉）原樣回傳給訪客；介面無法連線時回傳 502；
- 訪客自帶的身分標頭一律刪除，無法偽造；
- 可與路徑規則和「驗證範圍」搭配，只讓部分路徑（如 `/admin`）需要登入，也可與臨時分享連結搭配。

### 共用使用者：TOTP 與單一登入 {#shared-users}

帳號只需定義一次，就能用於多個站台，並可選擇啟用 TOTP 二次驗證，涵蓋了很多人使用 Authelia 的主要目的。

在側邊欄「Web → 認證使用者」頁面中（Web 服務的全域設定對話框只顯示摘要和入口）：

- 新增使用者名稱與密碼；密碼以 bcrypt 雜湊儲存，API 不會回傳。要啟用 TOTP，點「啟用 TOTP」，用驗證器 App（Google Authenticator、1Password 等）掃描 QR Code 並儲存；重新產生會使舊金鑰失效；
- 可選填電子郵件、顯示名稱和群組，[OIDC 單一登入](/zh-TW/docs/modules/oidc) 會把它們作為 `email`、`name`、`groups` 聲明提供給應用程式，OIDC 用戶端的允許使用者可用 `group:群組名` 按群組授權；
- 單一登入網域，例如 `example.com`：在該網域或其子網域下的任一站台登入後，其他站台無需再登入。它使用父網域 Cookie（`gately_sso`，有效期 7 天），不會轉發給後端。留空則每個站台單獨登入。

在站台的「安全」頁，於網頁驗證或基本驗證旁勾選「使用共用使用者」；站台自有的使用者仍然可用。也可以在「認證使用者」頁面的站台清單中按監聽檢視、篩選並批次勾選：未開啟驗證的站台勾選後會同時開啟網頁驗證；只透過共用使用者驗證的站台取消勾選後會標示「儲存後關閉驗證」，儲存時列出這些站台確認，確認後站台的驗證一併關閉、變成無需登入即可存取；使用轉發認證的站台不能使用共用使用者。頁面上的使用者、OIDC 與站台修改按下底部的「儲存」後一起生效，任一項校驗失敗時都不儲存，有未儲存的修改時離開頁面會先確認。

行為說明：

- 只要有共用使用者啟用了 TOTP，登入頁就會顯示驗證碼輸入框，每個驗證碼只能使用一次；
- 修改使用者的密碼或 TOTP 金鑰後，該使用者既有的工作階段立即失效；
- 基本驗證只接受未啟用 TOTP 的共用使用者，因為瀏覽器的密碼彈出視窗沒有地方輸入驗證碼；
- 失敗次數與其他登入共用同一套限流與自動封鎖。

要讓 Gitea、OpenList、Grafana 等應用程式識別登入的是哪個使用者，可以把共用使用者透過 [OIDC 單一登入](/zh-TW/docs/modules/oidc) 提供給應用程式。

### 自助修改密碼 {#self-service-password}

在「認證使用者」頁面開啟「自助修改密碼」後，共用使用者可以自己修改密碼，不必找管理員：

- 在開啟了「使用共用使用者」的站點造訪 `https://站點網域/__gately_auth/password`，登入頁也會顯示「修改密碼」入口；使用 [OIDC 單一登入](/zh-TW/docs/modules/oidc) 的使用者在簽發者網域造訪 `/__gately_oidc/password`；
- 輸入使用者名稱、目前密碼和兩次新密碼（8～128 個字元，且與目前密碼不同）；啟用了 TOTP 的使用者還需填寫動態驗證碼；
- 修改後該使用者在各站點的工作階段立即失效，需要用新密碼重新登入；已簽發的 OIDC 重新整理權杖作廢，舊 Access Token 也不能再讀取使用者資訊，但應用程式自行驗證的權杖在到期前仍有效，應用程式自己的登入工作階段也不受影響；
- 同一帳號修改成功後 1 分鐘內不能再次修改，避免反覆修改讓 FTP、SMB 不停重新載入、中斷其他人的連線；儲存時被服務檢查拒絕的詳細原因只寫入 Web 服務日誌，頁面只提示聯絡管理員；
- 目前密碼或驗證碼錯誤與登入失敗共用同一套限流與自動封鎖，其他網站代為提交的表單會被拒絕；Web 服務日誌會記錄修改的使用者與來源 IP；
- 同一頁面也可以修改[檔案服務共用使用者](/zh-TW/docs/modules/tools#shared-users)的密碼，兩種帳號分別開關，都開啟時頁面上可切換帳號類型；同名的兩種帳號互不影響。

## 存取控制

### IP 黑白名單

站台「安全」頁的「IP 存取控制」可選關閉、白名單、黑名單，清單每行一個 IP 或網段（如 `192.168.1.0/24`），還可以同時引用訂閱的 IP 清單。

### 拒絕方式

站台「安全」頁的「拒絕方式」決定被封鎖、IP 存取控制（含路徑規則）或國家過濾拒絕的請求如何處理：預設「傳回 403」；選擇「中斷連線」時不傳回任何內容直接中斷，存取日誌記為 444，與中斷連線站台相同。搭配白名單即可實現「自家 IP 正常存取、其餘一律中斷」。限流（429）與 WAF 攔截不受影響。

預設站台同樣可以這樣設定：類型選「反向代理」並填寫後端，IP 存取控制選白名單或黑名單（可引用下文的訂閱 IP 清單），拒絕方式選「中斷連線」。白名單命中或黑名單未命中的請求代理到後端，其餘直接中斷；訂閱清單更新後立即生效。「中斷連線」站台類型沒有後端，對所有請求一律中斷。

中斷連線（無論是站台類型還是拒絕方式）只是不傳回 HTTP 內容，無法隱藏服務存活：

- TCP 交握已經完成，對方能確認連接埠在監聽；
- HTTP/1.x 下關閉連線，HTTP/2、HTTP/3 下只重設這個請求，連線保持，對方可以繼續重複使用；
- HTTPS 下，未設定憑證的網域在 TLS 交握階段就會失敗，能到達預設站台的請求已經拿到憑證，憑證中的網域已經曝光。

要讓掃描者之後只看到逾時，需由[入侵防護](/zh-TW/docs/modules/guard)封鎖其位址，開啟防火牆同步後在核心層丟棄其流量。

### 訂閱 IP 清單

在「全域設定 → 訂閱 IP 清單」新增清單：填寫下載網址與重新整理間隔（預設 24 小時），Gately 會定時下載並快取到設定目錄，重新啟動後無需連網即可使用。內容每行一個 IP、CIDR 或 `起始-結束` 範圍，`#`、`;`、`//` 之後為註解。例如省市 IP 段可使用 [metowolf/iplist](https://github.com/metowolf/iplist) 的 `https://metowolf.github.io/iplist/data/cncity/440000.txt`（廣東省）。

- 站台與路徑規則的白名單、黑名單可以引用多個清單，與手動填寫的 IP 段一起判斷，符合任一項即視為在名單中；
- 下載內容無法辨識（例如回傳了錯誤頁面）時保留上次的清單，並在清單上顯示原因，一小時後重試；
- 清單下載成功前視為空清單：白名單因此拒絕存取，黑名單不額外攔截；
- 停用仍被引用的清單後，引用它的白名單拒絕全部來源，黑名單不再攔截任何來源；
- 刪除仍被引用的清單會被拒絕。

### 路徑規則

在「安全」頁的「路徑規則」中，依路徑前綴覆寫站台的驗證與 IP 設定：

| 欄位 | 取值 |
| --- | --- |
| `prefix` | 以 `/` 開頭的路徑前綴，如 `/admin` |
| `auth` | 沿用站台（空）、`off`（無需驗證）、`on`（必須驗證） |
| `ipMode` / `ipList` | 沿用站台（空）、`whitelist`、`blacklist`，並附 IP 或網段清單 |

比對規則：

- 最長前綴優先；
- 依路徑段邊界比對，`/admin` 符合 `/admin` 與 `/admin/x`，`/administrator` 不符合；
- 請求路徑先正規化（消除 `.`、`..` 與重複斜線）再比對，`/public/../admin` 以 `/admin` 處理；
- 同一前綴只能設定一條規則。

「驗證範圍」選項（`authOptional`）：勾選後，驗證只作用於規則中標記為「必須驗證」的路徑，其餘路徑公開。此選項需要先啟用基本驗證或網頁驗證。

### 臨時分享連結

啟用基本驗證或網頁驗證後，可為站台建立分享連結，讓訪客免帳號存取：

| 欄位 | 說明 |
| --- | --- |
| 名稱 | 備註名，如「給小明」 |
| 到期時間 | 留空為不過期 |
| 可用次數 `maxUses` | 最多可被兌換的次數，0 為不限；重新啟動後計數歸零 |
| 路徑限制 `pathPrefix` | 非空時，連結只能存取該前綴下的路徑，需以 `/` 開頭 |

訪客造訪 `https://網域/任意路徑?_gs=權杖` 即可兌換工作階段。兌換成功後伺服器端設定免登入 Cookie 並跳轉到去掉 `_gs` 參數的位址，工作階段最長 24 小時，且不超過連結的到期時間。權杖無效時按一般存取處理，不透露失敗原因。刪除連結後已發出的工作階段立即失效。權杖在儲存後產生（至少 16 位），可在介面複製完整連結。

### 驗證失敗限流與自動封鎖

- 同一來源 IP 在 15 分鐘內驗證失敗累計 10 次後，暫時拒絕繼續嘗試；
- 「全域設定 → 自動封鎖 → 驗證失敗封鎖」填寫分鐘數（0 至 43200），達到 10 次失敗時封鎖來源 IP；填 0 表示不封鎖，僅限流；
- 自動封鎖觸發時發布 `AuthBanned` 事件，可經 [通知中心](/zh-TW/docs/modules/notify) 推送；
- IPv6 位址依 /64 網段彙整計數與封鎖。

### 封鎖清單

「全域設定」中的封鎖清單顯示目前被封鎖的 IP、原因（驗證連續失敗或手動封鎖）和到期時間，可點擊「解除」。也可手動封鎖：填寫 IP 與小時數（1 至 720，即最長 30 天），介面預設時長為 24 小時。

封鎖清單與[入侵防護](/zh-TW/docs/modules/guard)共用同一份：開啟入侵防護模組時，這裡只顯示封鎖數量，並連到入侵防護頁面管理。封鎖同樣對連接埠轉發、STUN 等服務生效，開啟防火牆同步後會在系統防火牆中丟棄；開啟「忽略內網位址」時，內網位址不會被自動封鎖。

### GeoIP 國家過濾

站台「國家過濾」有三種模式：關閉、僅允許、拒絕，並填寫兩位 ISO 國家代碼（以逗號分隔，如 `CN, HK, US`）。啟用時至少填寫一個國家。

- 過濾依賴 GeoIP 資料庫，需先在「全域設定 → GeoIP 資料庫」匯入：上傳 `.mmdb` 檔案，或填寫下載位址。支援 MaxMind GeoLite2、DB-IP 等國家庫或城市庫；上傳限制 129 MB；
- 資料庫未載入時過濾不生效（放行所有訪客），介面會提示；
- 內網位址一律放行；
- 「拒絕」模式下，庫中查不到國家的位址放行。

## 依路徑分流後端

為反向代理站台把某個路徑前綴下的請求送到其他後端，相當於 nginx 的 `location /api/ { proxy_pass ...; }`。在站台編輯視窗「基本」頁的「分路徑後端」中新增。

| 欄位 | 說明 |
| --- | --- |
| `prefix` | 路徑前綴，如 `/api/`。依路徑段邊界比對：`/api` 與 `/api/` 都符合 `/api` 和 `/api/x`，不符合 `/apix` |
| `targets` | 該路徑的後端，寫法與站台後端相同；留空時使用站台後端，只追加下面的請求標頭 |
| `requestHeaders` | 該路徑追加的請求標頭，每行 `Key: Value`；在站台請求標頭之後套用，同名時以路徑的為準 |

- 最長前綴優先，路徑原樣轉發（不會去掉前綴）；
- 站台的其他設定，如 Host 選項、憑證驗證、轉發標頭、PROXY 協定、負載平衡策略與健康檢查，對每個路徑後端同樣生效；
- 壓縮、限流、快取與改寫作用於整個站台。

## 依使用者分流 {#user-routes}

為反向代理站台把不同登入使用者的請求送到各自的後端，相當於 nginx 的 `map $remote_user $backend`。站台需要先啟用基本驗證、網頁驗證或轉發認證，然後在站台編輯視窗「安全」頁的「依使用者分流」中新增規則：每條規則填寫一組使用者和這些使用者的後端，後端寫法與站台後端相同。

使用者依以下識別方式比對：

- 站台使用者或[共用使用者](#shared-users)的使用者名稱；
- 第三方登入身分寫 `提供方key:識別碼`，例如 `github:octocat`，該身分的其他識別碼同樣能比對；
- 轉發認證從認證服務回應複製回來的 `Remote-User`。

轉發規則：

- 未列出的使用者，以及公開路徑（無需驗證的路徑）上未登入的訪客，使用站台後端；公開路徑上已透過網頁驗證登入的訪客同樣依身分分流，同一應用程式的頁面會落到同一後端；
- 填寫了後端的分路徑規則（見上一節）優先；只追加請求標頭的分路徑規則改用該使用者的後端；
- 「傳遞使用者名稱」填寫一個請求標頭名稱（如 `X-Remote-User`）後，驗證通過的使用者名稱會寫入該請求標頭傳給後端；訪客自行送出的同名請求標頭一律刪除，無法偽造；
- 啟用記憶體回應快取時，快取鍵包含所選的使用者路由，開啟「傳遞使用者名稱」時還包含使用者名稱，不同後端、不同使用者的回應各自獨立快取。

儲存時檢查：站台已啟用驗證；每條規則至少有一位使用者和有效的後端；同一使用者不能出現在兩條規則中；請求標頭名稱合法，且不能是 `Host`、`Cookie`、`Authorization`、`X-Forwarded-For` 等影響轉發或驗證的請求標頭。站台清單中，設定了使用者路由的站台會顯示規則條數標籤。

## 反向代理進階

這些選項位於站台編輯視窗的「流量」頁。

### 後端、權重與備用

後端清單每行一個位址，位址後可附參數：

```text
http://10.0.0.2:8080 weight=3
http://10.0.0.3:8080 backup
```

- `weight=N`：權重，1 至 100 的整數，預設 1；
- `backup`：備用後端，僅在所有非備用後端都無法使用時啟用；全部後端都無法使用時回退到所有非備用後端繼續嘗試。

### 負載平衡策略

| 介面選項 | `lbPolicy` | 說明 |
| --- | --- | --- |
| 輪詢（依權重） | 空 | 預設 |
| 隨機（依權重） | `random` | |
| IP 雜湊（工作階段保持） | `ip_hash` | 同一用戶端 IP 落到同一後端 |
| 最少連線 | `least_conn` | 依「連線數 / 權重」選擇最小者 |

### 健康檢查

主動檢查開關預設關閉。啟用後的欄位與預設值：

| 欄位 | 預設值 | 範圍 |
| --- | --- | --- |
| 方式 `mode` | `http` | `http`（請求檢查路徑，狀態碼小於 400 視為健康）或 `tcp`（只測試連線） |
| 路徑 `path` | `/` | 以 `/` 開頭，僅 http 方式 |
| 間隔 `interval` | 10 秒 | 1 至 3600 |
| 逾時 `timeout` | 3 秒 | 1 至 60 |
| 連續失敗 `fails` | 3 次判定無法使用 | 1 至 20 |
| 連續成功 `passes` | 2 次恢復 | 1 至 20 |

啟用向後端送出 PROXY 協定時，HTTP 檢查自動改用 TCP。

被動檢查一律生效：多個後端中，連續 3 次連線失敗的後端暫停 30 秒後再試探（只有一個後端且未啟用主動檢查時不摘除）。啟用主動檢查後，恢復完全由檢查結果決定。後端狀態變動時發布上游無法使用 / 已恢復事件，可經 [通知中心](/zh-TW/docs/modules/notify) 推送。

### 壓縮

對反向代理、靜態檔案、固定文字站台可啟用壓縮（重新導向站台除外）。依 `Accept-Encoding` 優先選擇 `br`，其次 `gzip`。

- 僅壓縮文字類內容：`text/*`、JSON、JavaScript、XML、XHTML、RSS / Atom、WebAssembly、SVG；`text/event-stream` 排除在外；
- 宣告的 `Content-Length` 小於 256 位元組的回應保持原樣；
- 已有 `Content-Encoding` 的回應保持原樣；WebSocket 升級請求直接放行；
- 壓縮後強驗證 ETag 改為弱驗證。

### 依 IP 限流

依用戶端 IP 的權杖桶限流，欄位：

| 欄位 | 說明 |
| --- | --- |
| `rate` | 每秒允許的請求數 |
| `burst` | 突發容量；設定了 `rate` 而 `burst` 為 0 時自動取 `rate` 取整後加 1 |
| `maxConns` | 單一 IP 的並行請求上限，0 為不限 |

啟用限流時 `rate` 與 `maxConns` 至少設定一項。

### 記憶體回應快取

僅對反向代理站台生效，快取存放在記憶體中，以 LRU 淘汰。

| 欄位 | 預設值 | 範圍 |
| --- | --- | --- |
| `ttl` 預設時長 | 0 | 0 至 30 天（秒）。上游未宣告快取指令時，200 回應快取這麼久；0 表示只快取上游明確允許的回應 |
| `maxMb` 快取容量 | 64 | 1 至 4096 MB |

快取規則：

- 僅快取 GET 請求，且請求不含 `Authorization`、`Cookie`、`Range` 標頭，也不含 `Cache-Control: no-cache`；
- 僅快取狀態碼 200 的回應；回應含 `Set-Cookie`、`Vary: *`，或 `Cache-Control` 為 `no-store` / `private` / `no-cache` 時略過；
- 遵循 `s-maxage`，其次 `max-age`；
- 單一項目上限為 4 MB，同時不超過總容量的四分之一；
- 命中時回傳標頭 `X-Cache: HIT` 與 `Age`，未命中為 `X-Cache: MISS`；
- 快取鍵包含 Host、完整請求 URI 與 `Accept-Encoding`；設定了[依使用者分流](#user-routes)時還包含所選的使用者路由，開啟「傳遞使用者名稱」時還包含使用者名稱。

### 路徑改寫與重新導向

規則依順序比對，命中第一條即停止。

| 欄位 | 說明 |
| --- | --- |
| `pattern` | 比對請求路徑的正規表示式，如 `^/old/(.*)$` |
| `to` | 取代結果，可用 `$1` 引用群組 |
| `redirect` | 關閉為內部改寫（改寫後的路徑送往後端，目標需以 `/` 開頭）；開啟為重新導向 |
| `code` | 重新導向狀態碼 301 / 302 / 307 / 308，預設 302 |

重新導向會保留原查詢參數。重新導向目標中可以寫 `{host}`，表示訪客使用的網域。重新導向規則先於驗證執行，相當於 nginx 的 `location = / { return 302 ...; }`，所以 `/` 這類路徑可以直接把訪客送走，不要求先登入。

## 存取統計與監控

### 站台統計

執行中的監聽，在站台列點擊「統計」開啟統計視窗，可選最近 1 小時、6 小時、24 小時：

- 分鐘級存取統計：每分鐘一個點，保留最近 24 小時，包含請求數曲線與 4xx / 5xx 錯誤曲線；
- 狀態碼分布 2xx / 3xx / 4xx / 5xx，累計回應流量；
- 來源 IP Top 10 與國家 Top 10（國家統計需要已匯入 GeoIP 資料庫）；
- 反向代理站台顯示每個後端（含依路徑分流與依使用者分流的後端，標註路徑或使用者）的健康狀態、權重、是否備用、目前連線數與累計轉發請求數；
- 有請求被攔截時，依原因列出累計攔截次數：已封鎖、IP 名單、國家過濾、限流、WAF（認證失敗不計入）。

統計保存在記憶體中，重新啟動或修改該監聽自身的設定後重新計數；修改站台會保留其計數。排行榜最多統計 5000 個不同來源。

### 即時連線 {#connections}

執行中的監聽，站點列（含預設站點）的統計後面顯示「進行中 N」，即該站點正在處理的請求數，隨頁面重新整理。點擊「連線」開啟連線視窗，視窗每 2 秒自動重新整理，可依 IP 搜尋：

- **即時連線**：來源位址與連接埠、協定（h1 / h2 / h3，WebSocket 標記為 WS）、請求（方法、網域與路徑，不含查詢字串）、開始時間、已持續時間與流量（下行；有請求本文或 WebSocket 時還有上行）。依已持續時間由長到短排列，最多顯示 500 筆。設定了[可信代理](#real-ip)時來源為訪客真實位址，並註明經由的代理位址。
- **歷史紀錄**：最近結束的連線，含開始與結束時間、持續時間、流量與結果（已完成 / 已中斷）。只紀錄持續 1 秒以上或被手動中斷的連線，每個站點保留最近 200 筆，重新啟動後清空；短請求請查看存取日誌。

列表以進行中的請求計算：HTTP/1.1 長連線在兩次請求之間不屬於任何站點，HTTP/2、HTTP/3 的一條連線可同時承載多個請求，所以以請求為單位才能準確歸屬到站點；已升級的 WebSocket 會一直列出，直到連線關閉。

每列的「中斷」在確認後立即結束這個請求：HTTP/1.x 關閉整條連線，HTTP/2、HTTP/3 只重設這個請求，同一連線上的其他請求不受影響；已升級的 WebSocket 連同後端連線一起關閉。訪客不讀取資料導致傳送阻塞時同樣立即生效。被中斷的請求在存取日誌中記為 444（已開始回應時保留原狀態碼），不計入後端錯誤與路徑探測。訪客可以馬上重新連線，需要阻止時使用「中斷並封鎖」：把來源位址（IPv6 為所在 /64 網段）加入[封鎖清單](#封鎖清單)，並中斷它在全部監聽、全部站點上進行中的請求。迴環位址（經 frp、未帶 PROXY 協定的本機轉發進來的請求都顯示為它）和可信代理中的位址（IPv6 按 /64 判斷）不能封鎖，這類位址封鎖後會攔截一大批無關訪客；只中斷不封鎖不受此限制。

唯讀帳號與唯讀權杖可以查看連線列表，中斷與封鎖需要寫入權限，並記入稽核日誌。

### 網路拓撲 {#topology}

左側選單「Web → 網路拓撲」是獨立的頁面（`#/webtopology`），Web 服務頁頁首的「網路拓撲」按鈕也可以進入。圖中依 網際網路 → Gately → 監聽 → 站點 / 監聽層級動作 → 後端 / 去向 展開，每 2 秒重新整理，頁面切到背景時暫停，畫布配色跟隨目前外觀的亮暗：

- **節點**：監聽顯示位址與執行狀態，啟動失敗標紅；站點顯示匹配方式（精確、萬用字元、任意網域、預設站點）、QPS 與進行中請求數；反向代理站點展開為全部後端，包括依路徑分流與依使用者分流的後端（標註路徑或使用者），無法使用的後端標紅；重新導向、靜態檔案、固定文字與中斷連線站點各有一個去向節點。預設站點中斷連線、HTTPS 連接埠收到明文請求時跳轉（301 / 308）、沒有站點匹配且未啟用預設站點時回傳 404，這幾類是預期設定，以灰色顯示。停用的監聽與站點同樣列出，顯示為未運行。
- **連線**：粗細隨 QPS 增加，有流量的連線播放流動動畫。連線超過 120 條時只有醒目顯示的鏈路播放動畫；系統開啟「減少動態效果」時不播放。
- **醒目顯示**：游標停在節點上或點擊節點時，它所在的整條鏈路（向上到網際網路、向下到後端）醒目顯示，並在連線上標出 QPS 與流量，其餘節點變暗；點擊空白處恢復。
- **詳情面板**：所選節點的 QPS（最近 10 秒平均）、60 秒平均、下行流量、進行中請求、累計請求、後端錯誤、依原因的攔截次數、回應狀態分布、近 60 秒每秒請求數與流量曲線，以及經過該節點的活動 IP。每項指標旁的 ⓘ 說明計算方式。站點可以從面板直接開啟統計、連線與編輯視窗。
- **活動 IP**：最近 60 秒內有請求的訪客位址，加上仍有進行中請求的位址。畫布上只顯示個數，完整位址列在詳情面板。在頂部輸入或選擇一個位址（也可以點擊面板中的位址），圖中只醒目顯示它經過的鏈路，精確到具體後端；「清除篩選」恢復。每個站點、後端與監聽層級動作最多記錄 1024 個近期位址，介面一次最多回傳 500 個，來源過多時面板提示列表不完整。設定了[可信代理](#real-ip)時這裡是訪客真實位址。
- **遮蔽**：開關開啟後依勾選的類別把位址顯示為 `*`，方便截圖分享，只影響拓撲頁的顯示，搜尋仍依完整內容比對。可選：訪客 IP（活動 IP 清單與篩選框，IPv4 末段、IPv6 後 64 位）、後端位址（後端與跳轉目標中的 IP 與主機名稱）、監聽位址（監聽 IP、監聽錯誤訊息、以 IP 為網域的站點）、網域（站點網域與站點名稱中的網域，只保留第一段與尾碼，如 `nas.***.com`）。預設勾選前三項，選擇會被記住。
- **版面**：右上角的版面選單有七種，選擇會被記住，切換時淡入淡出並自動適應畫布。「樹狀」由左到右排成五欄，資訊最完整；「直向」由上到下展開，像組織圖，開啟時以 Gately 為中心，左右拖曳查看；「放射狀」以 Gately 為圓心，監聽、站點、後端依序分布在三層同心圓上，名稱沿半徑方向顯示；「桑基」各節點是直條，連線是流量帶，父節點依子節點 QPS 的占比切分，直條高度與帶寬隨流量變化，節點位置保持不動；「旭日」以 Gately 為圓心，監聽、站點、後端是三層環形扇區；「矩形樹狀圖」與「泡泡」把 Gately、監聽、站點、後端逐層巢狀成方塊或圓形，每個後端（或去向）面積相同。旭日、矩形樹狀圖與泡泡沒有連線，顏色越深流量越大，適合站點很多時總覽。桑基、旭日、矩形樹狀圖與泡泡的畫布上沒有摺疊按鈕，在監聽的詳情面板中摺疊或展開。
- **收合多餘節點**：每個監聽預設顯示前 8 個站點、每個站點前 6 個後端，其餘合併為「還有 N 個站點 / 後端」節點，顯示它們合計的 QPS 與進行中請求數；點擊展開全部，展開後末尾的「收合」節點可恢復。被收合節點上的活動 IP 計入這個彙總節點，依 IP 醒目提示時鏈路停在它上面。
- **平移、縮放與畫布大小**：拖曳畫布平移，滾輪上下捲動（到達邊緣後捲動頁面）；按住 Ctrl/⌘ 捲動、觸控板捏合或觸控螢幕雙指捏合縮放（15%–250%），以指標或雙指中點為中心。右下角可放大、縮小、恢復 100%、適應畫布（顯示全部，定位圖示）；最右側的按鈕讓畫布鋪滿目前瀏覽器視窗，按 Esc 或再按一次恢復。拖曳畫布下方的橫條可調整畫布高度（觸控螢幕同樣可用），設定的高度依裝置記住，按兩下橫條或點「自動高度」恢復依內容自動調整。
- 頁首的搜尋框篩選拓撲中的站點（名稱、網域、分組、後端位址）；監聽可以個別摺疊，也可以全部收合。詳情面板中站點的「編輯」會跳到 Web 服務頁並開啟該站點的編輯視窗，統計與連線視窗直接在本頁開啟。

圖中數字全部來自本執行個體記憶體中的計數：重新啟動後歸零，修改站點保留計數，修改連接埠等監聽設定後該監聽重新計數，不彙總其他 Gately 執行個體。拓撲視圖讀取 `GET /api/webservice/topology`，唯讀帳號與唯讀權杖可以查看。

### Prometheus 指標

全域指標端點 `GET /api/metrics` 彙總了全部模組的指標，見 [監控指標](/zh-TW/docs/reference/monitoring)。下面的模組端點只包含 Web 服務的指標。

指標端點為 `GET /api/webservice/metrics`，Prometheus 文字格式，需攜帶登入憑據或 [API 權杖](/en/docs/reference/api-reference)。

```bash
curl -H "Authorization: Bearer gtl_xxxx" http://localhost:16680/api/webservice/metrics
```

| 指標 | 類型 | 說明 |
| --- | --- | --- |
| `gately_site_requests_total` | counter | 站台累計請求數 |
| `gately_site_errors_total` | counter | 站台後端錯誤數 |
| `gately_site_active_requests` | gauge | 進行中的請求數 |
| `gately_site_response_bytes_total` | counter | 累計回應位元組數 |
| `gately_site_responses_total` | counter | 依狀態類別（標籤 `class`：`2xx` 至 `5xx`）統計的回應數 |
| `gately_site_blocked_total` | counter | 依原因（標籤 `reason`：`ban` 已封鎖、`ip` IP 名單、`country` 國家過濾、`rateLimit` 限流、`waf`）統計的攔截次數 |
| `gately_upstream_up` | gauge | 後端是否健康，1 健康、0 無法使用（附標籤 `upstream`） |
| `gately_upstream_requests_total` | counter | 轉發到後端的累計請求數（附標籤 `upstream`） |
| `gately_upstream_response_bytes_total` | counter | 後端回傳的累計回應主體位元組數，不含 WebSocket 升級後的資料（附標籤 `upstream`） |
| `gately_listener_requests_total` | counter | 監聽層直接處理、不經過站台的請求，標籤 `action` 為 `https_redirect`（HTTPS 連接埠的明文請求跳轉）或 `not_found`（未匹配站台的 404）；只帶 `listener` 標籤 |

除 `gately_listener_requests_total` 外，指標帶有標籤 `listener`（監聽名稱#監聽 key）與 `site`（站台名稱，未命名時取第一個網域）。依路徑分流與依使用者分流的後端在 `gately_upstream_*` 中另帶標籤 `route`：路徑前綴，或 `@` 加使用者列表。`upstream` 標籤為後端位址，去掉其中的使用者名稱、密碼與查詢字串。

## 匯入 nginx 設定 {#import-nginx}

頁面頂端的「匯入 nginx」可以把現有的 nginx 站台轉換為 Gately 的監聽與站台。建議在 nginx 所在主機執行 `nginx -T`，把完整輸出貼上：輸出中包含 include 的所有檔案，Gately 會像 nginx 一樣展開 include。

- 先預覽：依監聽連接埠分組列出每個站台的類型、後端或目錄、來源檔案與行號，以及需要留意的地方（使用了變數的指令、正規表示式 location、缺少憑證的網域等），無法轉換的站台會說明原因；
- 相同連接埠的站台合併到既有監聽，否則新增監聽；已存在的網域會略過，可以重複匯入；
- 預設匯入為停用狀態，方便與 nginx 並行逐一核對後再啟用；勾選「匯入後立即啟用」則立即生效（nginx 仍佔用相同連接埠時，新增的監聽會啟動失敗）；
- 可轉換的內容：`proxy_pass`（含 upstream 的權重、備用與負載平衡策略）、`root` / `alias` 靜態目錄（`autoindex`、`try_files $uri.html`、`error_page 404`）、`return` 跳轉與固定內容、整站 `rewrite` 跳轉、`add_header`、`proxy_set_header`、`gzip`、`allow` / `deny`、location 層級的分路徑後端、存取控制與跳轉、`listen ... proxy_protocol` 與 `quic`；
- `auth_request` 會轉換為轉發認證：驗證位址取自驗證子請求 location 的 `proxy_pass`（支援 `set` 變數），登入跳轉取自 `error_page 401 =302`，Authelia 的常見寫法可以直接轉換；只在部分 location 啟用時，轉換為只對指定路徑驗證（「驗證範圍」）；
- `auth_basic` 轉換為使用共用使用者的基本驗證，nginx 的使用者檔案不會被讀取，補齊使用者之前任何人都無法通過；
- `stream` 中的 TCP/UDP 轉發請在 [連接埠轉發](/zh-TW/docs/modules/portforward) 中設定；憑證不會匯入，HTTPS 站台缺少憑證時，預覽會列出 nginx 使用的憑證檔案，可在 [憑證](/zh-TW/docs/modules/ssl) 頁依檔案路徑新增。

## 取代 haproxy 與 nginx

協定分流加上 Web 服務可以取代 haproxy + nginx 的組合。常見配置是：在 443 上放一條[協定分流](/zh-TW/docs/modules/protoroute)規則，把 VPN 等 TLS 服務直接送到各自的後端，其餘網域送到一個接收 PROXY 協定的 Web 服務監聽；再在 80 連接埠放一個 Web 服務監聽，用重新導向站台（`https://{host}`）跳轉到 HTTPS。

nginx 設定的對應關係：

| nginx | Gately |
| --- | --- |
| 帶 `server_name` 的 `server` | 使用這些網域的站台 |
| `proxy_pass` 不同的 `location` | 分路徑後端 |
| `auth_request`（Authelia） | 轉發認證，或帶 TOTP 的共用使用者 |
| `proxy_ssl_name $host` | 使用造訪網域作為 SNI |
| `return 301 https://$host$request_uri` | 重新導向站台，`https://{host}` 並勾選「保留路徑」 |
| `location = /` 裡的 `return 302 /admin` | 改寫規則，開啟「重新導向」，pattern 為 `^/$` |
| `try_files $uri $uri.html $uri/index.html` 與 `error_page 404` | 靜態檔案的無副檔名網址與 404 頁面 |
| `add_header` | 回應標頭 |
| `return 444` | 中斷連線站台 |
| HTTPS server 中的 `error_page 497 https://$host:$server_port$request_uri` | 新建監聽的「同埠 HTTP」設為「跳轉到 HTTPS」；合併到已有監聽時只提示，不改動其設定 |

## 部署提示

Web 服務需要監聽主機的 80 / 443 等連接埠，Docker 部署建議使用 `--network host`。
