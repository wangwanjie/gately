# Web 服務

依網域提供反向代理、重新導向、靜態檔案與固定文字，是 Gately 的統一 Web 入口。選單位置：側邊欄「Web → Web 服務」。

## 結構：監聽、站台與預設站台

設定分三層：

1. 監聽：一個監聽連接埠。欄位包括網路（`tcp` 雙堆疊、`tcp4`、`tcp6`）、監聽位址（留空為所有位址）、連接埠、HTTPS 開關、最低 TLS 版本（1.0 / 1.1 / 1.2 / 1.3）、是否接收 PROXY 協定。
2. 站台：監聽下依網域比對的一個站台。網域支援精確網域、`*.example.com`（比對任意層級子網域）、`api-*.example.com`（首段內的一個 `*` 比對該段中零個或多個字元，不跨越 `.`）與 `*`（比對全部）；比對優先順序為精確網域、萬用字元、`*`。多個萬用字元同時命中時較長的規則優先，長度相同時以清單中靠前的站台為準。首段內萬用字元同樣支援匯入、批次編輯與重新導向變數 `{1}`。HTTPS 站台需要涵蓋實際存取網域的憑證，例如 `*.example.com`，憑證機構只簽發 `*.example.com` 形式的萬用字元憑證。
3. 預設站台：沒有站台符合時使用，未啟用時回傳 404。也可以把預設站台設為「中斷連線」，讓未知網域的請求得不到任何回應。預設站台設定後顯示在站台清單最後；尚未設定時，點擊監聽卡片上的「設定預設站台」進行設定。

修改站台或預設站台並儲存時，站台清單會原地替換：監聽保持執行，已建立的連線（含 WebSocket）不會中斷，各站台的統計資料也會保留。新設定無效時繼續使用原來的站台。修改監聽自身的設定（網路、位址、連接埠、HTTPS、最低 TLS、HTTP/3、PROXY 協定）會重新啟動該監聽。

站台清單中的每個具體網域都是可點擊的完整位址，在新分頁開啟，旁邊的按鈕可複製該位址；萬用字元網域（`*.example.com`、`*`）照常顯示為文字。位址依監聽推算：開啟 HTTPS 用 `https`，否則用 `http`，連接埠為監聽連接埠，443 與 80 這類預設連接埠省略，例如 `https://example.com:8443`。監聽未填存取連接埠時，若有啟用的協定分流或連接埠轉發規則轉入本監聽，站台連結自動使用規則的入口（監聽）連接埠，例如監聽 8443 由協定分流在 443 轉入時連結用 443。規則的目標位址需能到達本監聽：監聽全部位址時為回環或未指定位址，監聽具體位址時為同一位址。協定分流依網域以分流時的順序比對（精確網域、最具體的萬用字元網域、`*`、預設目標），略過已停用的路由和只接受 `acme-tls/1` 等非瀏覽器 ALPN 的路由；只轉發 UDP 的連接埠轉發規則不計入；連接埠區間依一一對應換算；多條規則命中時取第一條啟用的規則。監聽標題顯示識別出的連接埠及來源規則，「存取位址」輸入框以它為預留位置提示，手動填寫的存取連接埠仍優先。經路由器連接埠對映、frp 或 CDN 存取（或規則轉發到本機的區域網路位址）時，對外的協定或連接埠可能與監聽不同，需在監聽的「存取位址」中手動指定協定與連接埠（例如 CDN 回源到 http 8080 時選 https 並填 443）。存取位址只用於產生連結，修改後不重新啟動監聽。儲存時網域統一為瀏覽器請求中的形式：轉為小寫，IPv6 去掉方括號，中文等國際化網域轉為 punycode（如 `中文.com` 儲存為 `xn--fiq228c.com`）；帶連接埠、路徑、`@` 等永遠比對不到的寫法會被拒絕。從 Lucky 或 nginx 匯入時只略過寫錯的網域並給出提示。

站台可以填寫「分組」（最長 64 個字元，預設站台不能分組）。清單在每個監聽下依分組顯示可摺疊的區塊：分組依首次出現的順序排列，未分組的站台排在後面，預設站台始終在最後；各分組的摺疊狀態保存在瀏覽器中。點擊「排序與批次」進入排序模式，可以上移、下移站台，在分組內拖曳站台，整組移動，以及調整監聽的順序。順序只影響清單顯示，網域比對依上面的優先順序進行，與站台順序無關；儲存排序同樣原地替換站台清單，不會中斷連線。頁首的搜尋框可依網域、名稱、分組、後端或備註篩選站台，搜尋期間摺疊的監聽卡片會自動展開。

排序模式下還可以勾選多個站點（分組標題的核取方塊可選中整組）：拖動其中任一項會一起移動，拖到其他分組的站點或分組標題上即加入該分組；工具列可以把選中的站點批次移到指定分組，留空則移出分組。跨監聽的選中站點批次設定分組時，各監聽分別儲存。

滑鼠移到分組標題上，點鉛筆按鈕可以重新命名分組：組內條目一起改為新名稱，位置和順序不變；改成已有分組的名稱時，確認後兩個分組合併。

### 移動站點 {#move-sites}

站點可以連同全部設定移到其他監聽：

- 編輯站點時修改「所屬監聽」，儲存時先儲存修改再移動；新增站點時用它選擇建在哪個監聽下。
- 排序模式下勾選站點（可跨監聽），點工具列的「移到監聽」，選擇目標監聽與群組（預設保持各站點原有群組），站點排在目標監聽最後或所選群組最後；已在目標監聽中的站點不動。
- 排序模式下把站點拖到其他監聽的站點上方或下方，即插入該位置並加入其群組；拖到群組標題上即放入該群組最後。沒有一般站點的監聽在拖曳時顯示放置區。放下後需要確認。

每次移動一次提交，來源監聽與目標監聽各重新載入一次，原地替換站點列表，其他站點的連線不會中斷。目標監聽已有相同網域的站點時拒絕移動，任何監聽都不修改；預設站點屬於所在監聽，不能移動。站點識別碼在目標監聽中已被占用時改用新的識別碼，效能監控告警規則中引用的站點會同步改寫。登入工作階段按監聽與站點隔離，移動後已登入的訪客需要重新登入；分享連結的已兌換次數隨站點遷移，限次連結不會因移動而重新可用；站點的統計與即時連線從零開始。把開啟了驗證的站點從 HTTPS 監聽移到明文 HTTP 監聽時會提醒密碼與登入 Cookie 將以明文傳輸。

### 批次操作

在排序模式下勾選站台（可跨監聽），工具列提供以下批次操作。每次操作一次提交：全部站台驗證通過才儲存，任一站台失敗都不做修改並提示是哪個站台；每個受影響的監聽只重新載入一次，原地替換站台清單，不會中斷連線。

- **啟用 / 停用**：已是目標狀態的站台不受影響。
- **刪除**：確認後刪除選取的站台；預設站台不能刪除。
- **批次網域**：
  - 新增網域：每行一個（也可用逗號分隔），站台已有的網域會略過，新網域附加在末尾；
  - 移除網域：依完整網域比對，站台沒有的網域會忽略，不能把站台的網域全部刪光；
  - 取代主網域：把網域後綴換成新的後綴，原網域本身及其子網域（含 `*.原網域` 萬用字元）都會取代，例如 `old.com` 換成 `new.com` 後 `www.old.com` 變為 `www.new.com`；取代後重複的網域會合併，不相符的站台保持不變。

  新加入的網域如果同時出現在同一監聽的多個站台中會被拒絕，因為同一監聽內只有第一個站台能比對到它；不同監聽可以使用相同網域。
- **批次選項**：可以批次開啟或關閉壓縮、存取記錄、CORS、轉發標頭、拒絕時中斷連線，以及設定或取消 WAF；選「不修改」的項目保持各站台原有設定。認證、存取控制、後端位址等影響存取的設定需要在站台中逐一修改。
- **移到監聽**：把選取的站點移到其他監聽，見 [移動站點](#move-sites)。

對應介面為 `POST /api/webservice/sites/batch`，請求主體 `{"sites": [{"listener": "監聽 key", "site": "站台 key"}], "action": "...", ...}`，`action` 取 `enable`、`disable`、`delete`、`addDomains`、`removeDomains`（搭配 `domains`）、`replaceDomain`（搭配 `from`、`to`）或 `set`（搭配 `options`，只接受上述選項欄位），回傳實際修改與無需修改的站台數。一次最多 500 個站台、100 個網域。監聽本身也支援通用的 `PUT /api/webservice/listeners-enable` 與 `POST /api/webservice/listeners-delete`。`action` 為 `move` 時用 `move` 指定目標，例如 `{"listener": "目標監聽 key"}`，可加 `group`（放入的群組，空字串為未分組，不填保留原群組）或 `before` / `after`（目標監聽中的站點 key，插到它前後並加入它的群組），回應中的 `moved` 列出每個站點移動前後的識別碼。

## 站台類型

| 類型 | 說明 |
| --- | --- |
| 反向代理 | 轉發到一個或多個後端，後端位址格式為 `http(s)://主機:連接埠`，支援 WebSocket |
| 重新導向 | 跳轉到完整 URL，狀態碼 301 / 302 / 307 / 308（預設 302），可選保留原路徑與查詢字串。URL 中可以寫 `{host}`，會替換為訪客使用的網域：`https://{host}` 加上「保留路徑」，就能把所有 HTTP 請求跳轉到同一網域的 HTTPS。還可以使用 `{path}`、`{1}`、`{STUN_規則名_PORT}` 等變數，見 [重新導向變數](#redirect-vars) |
| 靜態檔案 | 目錄需為絕對路徑；關閉「目錄列表」時，目錄請求只在存在 `index.html` 時回傳。「無副檔名網址」在檔案不存在時再嘗試 `路徑.html` 與 `路徑/index.html`（適用於 VitePress 等產生器，相當於 nginx 的 `try_files $uri $uri.html $uri/index.html`）；「404 頁面」填寫目錄內的路徑，如 `404.html`，以 404 狀態回傳 |
| 導覽面板 | 輸出 [導覽面板](#nav-panel) 庫中的一個面板：把常用服務的連結依分組彙整成一頁，內網訪客自動使用內網位址 |
| 固定文字 | 自訂內容、`Content-Type`（預設 `text/plain; charset=utf-8`）與狀態碼（100-599，預設 200） |
| 中斷連線 | 不回傳任何內容，直接中斷連線，相當於 nginx 的 `return 444`。常用作預設站台，讓掃描未知網域的請求得不到回應；存取日誌記為 444；不經過認證、存取控制、WAF 與重寫，站台的其他設定都不生效 |

所有類型的站台都可設定存取日誌、跨來源（CORS）、自訂請求標頭與回應標頭（每行 `Key: Value`，Value 留空表示刪除該標頭），並可引用一個 [WAF 防火牆](/zh-TW/docs/modules/waf) 實例（實例不存在或停用時放行）。請求標頭、回應標頭與 Content-Type 的編輯方式見 [請求標頭與回應標頭](#headers)。

存取日誌會記錄用戶端 IP、方法、網域與路徑、狀態碼、耗時、站點名稱，行尾依 nginx 的格式附上 Referer 與 User-Agent（缺少時為 `-`），同一個對外 IP 後面的不同裝置可以透過 User-Agent 區分。可在日誌中依站點、狀態碼、來源 IP 等條件篩選，見 [執行日誌的檢視與篩選](/zh-TW/docs/guide/configuration#log-filter)。

### 重新導向變數 {#redirect-vars}

重新導向站台的目標位址可以使用以下變數：

| 變數 | 意義 |
| --- | --- |
| `{host}` | 訪客請求的網域，不含連接埠；IPv6 位址帶方括號，如 `[2001:db8::1]` |
| `{port}` | 存取連接埠 |
| `{hostAndPort}` | 網域加連接埠，與請求的 Host 一致 |
| `{path}` / `{PATH}` | 請求路徑，`{PATH}` 不含開頭的 `/` |
| `{args}` / `{Args}` | 查詢字串，`{args}` 帶開頭的 `?`（沒有查詢字串時為空），`{Args}` 不帶 |
| `{domainPartN}` / `{pathPartN}` | 網域（以 `.` 分隔）或路徑（以 `/` 分隔）的第 N 段，N 從 1 開始 |
| `{ClientIP}` / `{RemoteIP}` | 用戶端 IP |
| `{time}` | 目前時間，格式 `2006-01-02 15:04:05`，其中空格寫成 `%20`（即 `2006-01-02%2015:04:05`），確保跳轉位址是合法 URL |
| `{1}` | 站台網域 `*.example.com` 中 `*` 比對到的部分；命中精確網域時為空，命中 `*` 或預設站台時為完整網域 |
| `{STUN_規則名_PORT}` / `{STUN_規則名_IP}` / `{STUN_規則名_ADDR}` | [STUN 穿透](/zh-TW/docs/modules/stun) 規則目前的公網連接埠、IP、`IP:連接埠`；規則名即清單中的名稱，可以含底線 |

- 開啟「保留路徑」時，目標中寫了 `{path}`、`{PATH}` 或 `{pathPartN}` 就不再附加原路徑，寫了 `{args}`、`{Args}` 或目標自帶查詢字串就不再附加原查詢字串，另一部分照常附加；
- STUN 連接埠變化後無需修改站台，下一次請求就跳到新連接埠。引用的規則不存在、未啟用、尚未穿透成功或正在自動重試時，站台回傳 503，執行日誌中會記錄原因；
- 變數展開後跳轉位址缺少主機（例如命中精確網域時 `{1}` 為空，目標卻只寫了 `https://{1}`）時回傳 503；訪客網域含 `&`、`=`、`/`、`@` 等網域中不會出現的字元時回傳 400，不會代入跳轉位址；目標使用 `{host}`、`{hostAndPort}`、`{1}` 或 `{domainPartN}` 時，沒有 Host 標頭的請求（HTTP/1.0 探測等）同樣回傳 400；
- 站台網域只支援一個 `*`，所以只有 `{1}`；
- 路徑重寫規則中的重新導向目標仍只支援 `{host}`；未知的 `{xxx}` 原樣保留。

例：Cloudflare CDN 把 `*.example.com` 回源到本機 2053 連接埠，這個監聽上有一個網域為 `*.example.com` 的重新導向站台，目標填 `https://{1}.v4.example.com:{STUN_web_PORT}{path}{args}`。存取 `zly.example.com/a?b=1` 會跳到 `https://zly.v4.example.com:<STUN 連接埠>/a?b=1`；STUN 規則 web 轉發到另一個監聽，在那裡為 `*.v4.example.com` 下的各個網域建立反向代理站台。

### 反向代理選項 {#proxy-options}

位於站點編輯框「基本」頁的「選項」，旁邊的問號圖示可在介面中查看簡要說明並跳到本節。

| 選項 | 作用 | 什麼時候開啟 |
| --- | --- | --- |
| 略過後端憑證驗證 | 連線 HTTPS 後端時不驗證憑證 | 後端使用自簽或過期憑證，如 NAS、路由器管理頁的 https 連接埠。關閉驗證後無法確認後端身分，只建議用於內網後端 |
| Host 使用後端位址 | 送往後端的 Host 標頭改為後端位址；關閉時（預設）保留訪客請求的 Host | 後端只認自己的位址，例如回傳 400 / 403、跳到錯誤位址或提示 Host 不符；反向代理到公網網站或 CDN 時通常需要。後端按網域區分站點，或需要用造訪網域產生連結時保持關閉 |
| 停用連線重用 | 每個請求都建立新的後端連線（關閉 Keep-Alive） | 後端偶爾出現連線被重設、請求卡住，或不支援長連線。會增加一些延遲，正常情況保持關閉 |
| 新增 X-Forwarded-* | 寫入 `X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host` / `X-Forwarded-Port` 與 `X-Real-IP`，告訴後端訪客的真實 IP、原始協定、網域和連接埠 | 後端需要記錄真實 IP，或要知道外部是 HTTPS 才能產生正確連結（否則可能跳回 http 或登入後循環跳轉）。多數應用建議開啟 |
| 向後端傳送 PROXY v2 | 在 TCP 連線開頭附加 PROXY 協定 v2 標頭，傳遞真實用戶端 IP。開啟後每個請求都新建連線，也不再用 HTTP/2 連線後端。後端是 Gately 時，需在其監聽上開啟接收 PROXY 協定，並把本機加入可信 PROXY 來源。 | 後端不讀 HTTP 標頭但支援 PROXY 協定，如另一層 Gately、haproxy、開啟 `proxy_protocol` 的 nginx。後端未設定接收時所有請求都會失敗，不確定時保持關閉 |
| 使用造訪網域作為 SNI | 僅 HTTPS 後端：交握時傳送訪客使用的網域並據此驗證憑證，相當於 nginx 的 `proxy_ssl_server_name on; proxy_ssl_name $host` | 後端在同一連接埠按網域選擇憑證或分流，如 frp 的 `vhost_https`、託管多個 HTTPS 站點的 nginx。每個後端使用獨立的連線池，不同網域的連線不會互相重用 |
| 轉發 Gately 登入 Cookie | 把 Gately 自己的登入 Cookie（單一登入 `gately_sso`、站點工作階段、第三方登入隨機數）原樣轉發給後端；關閉時（預設）這些 Cookie 不發給後端，避免洩露登入憑據 | 後端是另一台負責認證的 Gately，本站點不開認證。例如公網 Gately 只做 WAF 與存取控制、反代到內網 Gately，由內網 Gately 負責網頁認證與單一登入。本站點啟用認證時不能開啟；只在後端是自己的 Gately 時使用 |

常見組合：

- 反向代理內網的 Web 應用（如 `http://192.168.1.10:5000`）：只開「新增 X-Forwarded-*」；
- 後端是自簽憑證的 https 位址：再開「略過後端憑證驗證」；
- 反向代理公網網站或第三方服務：開「Host 使用後端位址」；
- 後端前面還有按 SNI 分流的服務（如 frp `vhost_https`）：開「使用造訪網域作為 SNI」。
- 公網 Gately 只做 WAF、內網 Gately 負責登入：公網站點不開認證，開「轉發 Gately 登入 Cookie」，需要真實 IP 時再開「向後端傳送 PROXY v2」，並在內網 Gately 上接收 PROXY 協定、把公網 Gately 加入可信來源。

### 請求標頭與回應標頭 {#headers}

在站點編輯框的「請求標頭」頁設定。請求標頭送往後端，只對反向代理站點生效；回應標頭回傳給用戶端，對所有類型的站點生效。

- 逐行編輯：點擊名稱框會列出常用標頭及其用途，選中後自動填入常用值，值框也可以改選其他常用值；兩者都可以直接手動輸入。值留空表示刪除該標頭，在名稱框貼上整行 `Key: Value` 會自動拆開；
- 「新增常用安全標頭」補齊 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN` 與 `Referrer-Policy: strict-origin-when-cross-origin`，已有的標頭不會重複新增；
- 「文字模式」可一次貼上多行 `Key: Value`，切回逐行編輯時保留內容；
- 「分路徑後端」中每個路徑的附加請求標頭使用同樣的編輯方式，在站點請求標頭之後套用，同名時以路徑的為準。

每一行下方會即時給出回饋。紅色表示儲存會失敗或該標頭無法生效，如缺少名稱、名稱含空格或冒號等非法字元、文字模式中缺少冒號；橙色表示可以儲存但結果可能不符預期：

- 請求標頭裡設定 `Host` 不會生效，需要改寫時開啟「Host 使用後端位址」；
- `X-Forwarded-For`、`X-Real-IP` 寫固定值會覆蓋真實用戶端 IP，傳遞用戶端 IP 請開啟「新增 X-Forwarded-*」；
- `Content-Length`、`Connection`、`Transfer-Encoding` 等由連線自動管理，手動設定會被忽略或導致傳輸異常；
- 值按原樣送出，不支援 nginx 的 `$host` 等變數；預設值中的 `<token>` 等占位內容需要替換；
- 同名標頭按順序設定，後面的覆蓋前面的。

「固定文字」站點的 `Content-Type` 可從常用類型中選擇或手動輸入，介面會檢查 `類型/子類型; 參數=值` 格式；`text/*` 未宣告 `charset` 時提示中文等內容可能亂碼，留空時使用 `text/plain; charset=utf-8`。

### 導覽面板 {#nav-panel}

左側選單「Web → 導覽面板」（`#/webpanels`）管理面板庫。每個面板是一組依分組排列的連結，再在 Web 服務中新增類型為「導覽面板」的站點並選擇面板，造訪站點網域的根路徑（`/` 或 `/index.html`）就會開啟導覽頁；其他路徑回傳 404。站點的認證、IP 存取控制、國家過濾與 WAF 照常生效，導覽頁通常只給自己人看，建議開啟網頁認證或 IP 白名單。面板修改儲存後立即生效，不需要重新啟動監聽。

- **連結**：每個連結有名稱、分組、描述、外網位址與選填的內網位址、圖示與顏色，可以設為在目前頁面開啟或在頁面中隱藏。分組依連結清單中首次出現的順序顯示，編輯框中可以整組上移、下移。「從 Web 服務站點新增」列出能組出具體位址的站點（取第一個非萬用網域，依監聽的存取協定與連接埠，經協定分流或連接埠轉發進入的監聽使用轉發的入口連接埠），勾選後作為連結加入，站點分組沿用為連結分組。
- **其他存取方式**：同一個服務常常有多個入口，例如 IPv6 直連、frp、STUN 穿透、Cloudflare 通道。每個連結最多可以再填 8 個存取方式（名稱不超過 20 個字元，位址寫法與可用變數同上），顯示為卡片上的小連結，在新分頁開啟，內網與外網訪客都會顯示；變數暫無值的存取方式顯示為劃線的不可用狀態。主位址不可用時，卡片上的其他存取方式仍可點選，搜尋也會比對存取方式的名稱。
- **位址**：支援 `http`、`https`、`ftp`、`ftps`、`sftp`、`ssh`、`smb`、`afp`、`nfs`、`vnc`、`rdp` 與 `mailto`，不能帶密碼。可以使用變數 `{host}`、`{port}`、`{hostAndPort}`（訪客開啟面板所用的網域與連接埠）、`{1}`、`{domainPartN}` 與 `{STUN_規則名_PORT}`、`{STUN_規則名_IP}`、`{STUN_規則名_ADDR}`，寫法同 [重新導向變數](#redirect-vars)，例如 `https://{host}:8443` 或 `http://{STUN_web_ADDR}/`；STUN 規則還沒有公網位址時，該連結顯示為「暫時無法使用」。取自請求路徑與查詢字串的 `{path}`、`{args}` 等變數不能使用，否則別人構造一個帶查詢字串的面板位址就能改變連結指向。`{1}` 沒有值時（面板站點的網域不是萬用網域，或在預覽中），用到它的連結顯示為「暫時無法使用」；用 IPv6 位址存取面板時，`{host}` 展開為帶方括號的寫法，例如 `[2001:db8::1]`。
- **內網與外網**：訪客位址是迴環、私有（10/8、172.16/12、192.168/16、fc00::/7）或鏈路本地位址，或在面板的「額外內網位址」中（例如 Tailscale 的 `100.64.0.0/10`）時，連結使用內網位址，沒有填寫內網位址的連結仍用外網位址。經 CDN 或反向代理存取時請設定 [可信代理](#real-ip)，否則訪客位址是代理的位址。有連結填寫了內網位址時，頁面右上角可以手動切換內網或外網，選擇儲存在 Cookie 中，點「自動識別」恢復。
- **內網判定與可見性**：內外網依訪客的直連位址判斷。外網訪客經本機的 frpc、cloudflared 或 Docker 連接埠對應轉發進來時，直連位址是本機或容器網段，會被當作內網訪客；這種部署請讓轉發方傳送 PROXY 標頭並在監聽上開啟 PROXY 協定，或經 HTTP 代理時設定 [可信代理](#real-ip)。內網位址對所有能開啟面板的訪客可見，訪客也可以用 `?net=lan` 手動切換到內網檢視；需要隱藏內網位址時，請為站點開啟認證或 IP 存取控制。
- **圖示**：可以填 emoji 或不超過 8 個字元的文字、`http(s)` 圖片位址，或上傳圖片（PNG、JPEG、GIF、WebP 縮放到 128 像素後儲存，SVG 與 ICO 原樣儲存，單個不超過 96 KB，一個面板合計不超過 3 MB），留空顯示名稱首字；文字圖示的底色可以自選，留空依名稱挑選。也可以點「選擇」使用內建圖示：Gately 各模組與 frp、Tailscale、NetBird、Cloudflare 等周邊，Jellyfin、Home Assistant、qBittorrent 等常用應用，OpenWrt、群暉、Proxmox 等系統，以及路由器、伺服器等通用圖示（品牌圖示來自 Simple Icons，通用圖示來自 Lucide），寫為 `builtin:編號`；內建圖示畫在圖示自帶顏色的方塊上，底色可以改，底色較淺時圖形自動改為深色。
- **頁面**：標題（留空用面板名稱）、副標題、頁面圖示與主題（跟隨系統、淺色、深色）。頁面支援搜尋：按 `/` 聚焦搜尋框，空格分隔多個關鍵字，依名稱、描述、位址與分組比對，Enter 開啟第一個結果，`Esc` 清空。編輯框的「預覽」依外網或內網訪客產生頁面，其中 `{host}` 依管理後台的網域展開。
- **外觀**：與管理介面右上角「主題配色」相同的色系（Gately 原創與經典配色），預設翠綠，編輯框中可選面板的預設外觀。訪客可點頁面右上角的調色盤按鈕換膚：切換亮色、暗色或跟隨系統，選擇色系（滑鼠懸停時預覽，點擊後從點擊處展開新配色），自訂主色與圓角；手機上換膚面板從底部彈出。選擇保存在訪客的瀏覽器中，沒有選擇過時使用面板設定；面板與管理介面在同一網域下時兩邊的選擇互通。編輯框的預覽依面板設定顯示，不含換膚按鈕。
- **安全**：頁面由伺服器產生，名稱、描述等內容全部跳脫，只執行帶隨機 nonce 的內建樣式與腳本（`Content-Security-Policy`），不能被其他網站嵌入；連結圖片以 `no-referrer` 載入。頁面隨訪客位址變化，回應帶 `Cache-Control: no-store`。

一個實例最多 50 個面板，每個面板最多 500 個連結；仍被站點引用的面板不能刪除。唯讀帳號與唯讀權杖可以檢視。介面見 `GET|POST /api/webservice/panels`、`PUT|DELETE /api/webservice/panels/{key}`、`PUT /api/webservice/panels/{key}/enable` 與 `POST /api/webservice/panels/preview`。

## 傳輸與協定

- HTTPS：使用 [SSL 憑證](/zh-TW/docs/modules/ssl) 模組中涵蓋該網域的憑證；
- 同埠 HTTP：開啟 HTTPS 的監聽可同時接受明文 HTTP，依連線的第一個位元組區分協定。「跳轉到 HTTPS」把 `http://位址:埠` 重新導向到 `https://位址:埠`（GET/HEAD 用 301，其他方法用 308），適合只能使用一個埠、又希望輸錯協定也能開啟的情境；「直接服務」以 HTTP 提供站台，不加密。ACME HTTP-01 驗證請求照常回應，修改此項會重啟該監聽；
- HTTP 埠：監聽可以再填一個明文 HTTP 埠（例如 HTTPS 監聽 443 時再開 80），與主埠共用全部站點與設定，不必為 HTTP 另建監聽、重複填寫站點。開啟 HTTPS 時可選「跳轉到 HTTPS」（預設）或「直接服務」：跳轉保留訪客請求的網域、路徑與查詢字串，埠換成「存取位址」中的埠（未填寫時用監聽埠，443 時省略），GET/HEAD 用 301，其他方法用 308；「直接服務」以 HTTP 提供站點，適合需要在 `http://` 與 `https://` 之間切換的情境。沒有對應站點的網域不跳轉：沒有預設站點時按未知網域回傳 404，預設站點為「斷開連線」時直接斷開，與 HTTPS 上的處理一致（同埠 HTTP 的跳轉同樣如此）。ACME HTTP-01 驗證請求照常應答，PROXY 協定與自動放行防火牆同樣作用於這個埠。HTTP 埠被佔用時主埠照常運行，監聽狀態中顯示原因；
- HTTP/3（QUIC）：在開啟 HTTPS 的監聽中啟用，相同埠號的 UDP 上同時提供 HTTP/3，並透過 `Alt-Svc` 回應標頭通告瀏覽器；需要在防火牆與連接埠映射中放行該 UDP 埠；
- WebSocket：反向代理自動支援；
- PROXY 協定：監聽可接收上游（如 haproxy、frp）送出的 PROXY 標頭，僅信任「全域設定 → 可信 PROXY 來源」中列出的 IP 或網段，留空表示不信任任何來源；反向代理可向後端送出 PROXY 標頭。經可信來源進入的連線帶的 `X-Forwarded-Proto: https` 同樣被採信：工作階段 Cookie 帶 Secure、開啟明文跳轉的連接埠不再跳轉，開啟「新增 X-Forwarded-*」時也向後端如實傳遞 https。

### 訪客真實 IP（CDN / WAF 之後） {#real-ip}

站點放在 Cloudflare、阿里雲 CDN、騰訊雲 CDN 等 HTTP 代理後面時，連線來自代理的回源位址。在「全域設定 → 訪客真實 IP」中填寫可信代理（代理的回源 IP 或網段，可填多家）並選擇真實 IP 請求標頭後，Gately 從請求標頭取得訪客位址，存取日誌、IP 黑白名單、僅內網存取、國家過濾、認證失敗封鎖、存取統計、路徑探測，以及轉發給後端的 `X-Real-IP` / `X-Forwarded-For` 都使用該位址。

- 只在原始對端位於可信代理中時讀取請求標頭。原始對端指 PROXY 協定處理後的位址：經可信 PROXY 來源進入時是 PROXY 標頭中的位址，否則是 TCP 對端。直接存取時用戶端自帶的請求標頭一律忽略；
- 請求標頭依選擇的順序查找，第一個能給出有效位址的標頭生效，未選擇時為 `X-Forwarded-For`。`X-Forwarded-For` 等多項標頭由右至左跳過可信代理，取第一個不可信的位址，用戶端在左側偽造的值不會被採用；
- 只選擇你的代理會覆寫的標頭。例如 Cloudflare 覆寫 `CF-Connecting-IP`，其他代理通常原樣轉發用戶端自帶的同名標頭，這時選 `X-Forwarded-For` 更安全；
- 使用 Cloudflare 時建議把真實 IP 請求標頭設為 `CF-Connecting-IP`，它由 Cloudflare 直接寫入訪客位址。`X-Forwarded-For` 由右至左跳過可信代理，可信代理填了整段 Cloudflare 位址時，經 Cloudflare 自身出口（如 Workers）發來的請求可以在左側帶上偽造的位址；
- 不能填寫 `0.0.0.0/0`、`::/0`，儲存時會被拒絕；
- 協定分流把連線經迴環轉給 Web 服務時，請在協定分流中開啟傳送 PROXY 標頭、在監聽上開啟接收 PROXY 協定，不要把 `127.0.0.1` 填進可信代理，否則直接連到協定分流的訪客也能偽造請求標頭。協定分流的透傳路由仍是純 TCP 轉發，不受此設定影響；
- 經可信代理進入、帶 `X-Forwarded-Proto: https` 的請求按 HTTPS 處理；
- 未填寫可信代理時保持原有行為。連線層面的封鎖（入侵防護寫入防火牆的規則）針對的是 TCP 來源，在 CDN 之後對訪客不起作用，Web 服務自身的封鎖依真實位址生效。

## 驗證

在站台編輯視窗的「安全」頁設定：

- 網頁驗證：瀏覽器顯示登入頁；
- 基本驗證：HTTP Basic；
- 使用者：每行 `使用者名稱:密碼`，密碼可填 bcrypt 雜湊。啟用基本驗證時至少需要一位使用者；啟用網頁驗證時至少需要一位使用者或第三方登入身分；
- 第三方登入：支援 GitHub、Google、QQ、OIDC，使用自己的 OAuth 應用程式。允許的身分每行一條，格式 `提供方識別碼:帳號`，例如 `github:octocat`、`google:me@gmail.com`，行尾可用 `#` 加備註，`github:*` 表示該提供方的任意帳號。

第三方登入的提供方在「全域設定」中設定：填寫自己的 Client ID / Secret 並啟用，同時設定回呼位址（需由 Gately 的某個監聽提供，例如 `https://auth.example.com`）。登錄到 GitHub / Google / QQ 的回呼 URL 為：

```text
https://auth.example.com/__gately_auth/oauth/callback
```

管理後台自身的第三方登入在「設定 → 帳號與安全」中單獨設定。

### 轉發認證（Authelia 等）

把認證交給外部服務，相當於 nginx 的 `auth_request` 或 Traefik 的 `forwardAuth`。在「安全」頁勾選「轉發認證」；同一站台不能同時啟用基本驗證或網頁驗證。

| 欄位 | 說明 |
| --- | --- |
| `url` | 驗證介面，例如 Authelia 的 `http://127.0.0.1:9091/api/authz/auth-request` |
| `loginUrl` | 介面回傳 401 時把訪客跳轉到的位址，例如 `https://auth.example.com/?rd={url}&rm={method}`；`{url}` 為原始位址（已編碼），`{method}` 為請求方法。留空時原樣回傳介面的回應 |
| `loginFromLocation` | 未填 `loginUrl` 時，介面回傳 401 且 `Location` 為唯一的 http(s) 絕對位址時把訪客 302 跳轉到該位址，並傳遞 `Set-Cookie` 與 `Cache-Control`，適用於在 401 中給出動態登入位址的服務（如 Casdoor 原生 `/api/forward-auth`）；其他形式的 `Location` 不跳轉，按 401 原樣傳回。預設關閉 |
| `copyHeaders` | 驗證通過後從介面回應複製到後端請求的身分標頭，預設 `Remote-User`、`Remote-Groups`、`Remote-Email`、`Remote-Name` |

運作方式：

- 每個請求先以不帶請求本文的 GET 送到 `url`，帶上訪客的請求標頭（Cookie、`Authorization` 等），以及 `X-Original-Method`、`X-Original-URL`、`X-Forwarded-Method`、`X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-Uri`、`X-Forwarded-For` 與 `X-Real-Ip`，逾時 10 秒；
- 回傳 2xx 即放行，並帶上身分標頭；回傳 401 時跳轉到 `loginUrl`（狀態碼 302）；其他結果（如 403 或跳轉）原樣回傳給訪客；介面無法連線時回傳 502；
- 訪客自帶的身分標頭一律刪除，無法偽造；
- 可與路徑規則和「驗證範圍」搭配，只讓部分路徑（如 `/admin`）需要登入，也可與臨時分享連結搭配。

### 共用使用者：TOTP 與單一登入 {#shared-users}

帳號只需定義一次，就能用於多個站台，並可選擇啟用 TOTP 二次驗證，涵蓋了很多人使用 Authelia 的主要目的。

在側邊欄「Web → 認證使用者」頁面中（Web 服務的全域設定對話框只顯示摘要和入口）：

- 新增使用者名稱與密碼；密碼以 bcrypt 雜湊儲存，API 不會回傳。要啟用 TOTP，點「啟用 TOTP」，用驗證器 App（Google Authenticator、1Password 等）掃描 QR Code 並儲存；重新產生會使舊金鑰失效；
- 可選填電子郵件、顯示名稱和群組，[OIDC 單一登入](/zh-TW/docs/modules/oidc) 會把它們作為 `email`、`name`、`groups` 聲明提供給應用程式，OIDC 用戶端的允許使用者可用 `group:群組名` 按群組授權；
- 單一登入網域，例如 `example.com`：在該網域或其子網域下的任一站台登入後，其他站台無需再登入。它使用父網域 Cookie（`gately_sso`，有效期 7 天），不會轉發給後端。留空則每個站台單獨登入。

在站台的「安全」頁，於網頁驗證或基本驗證旁勾選「使用共用使用者」；站台自有的使用者仍然可用。也可以在「認證使用者」頁面的站台清單中按監聽檢視、篩選並批次勾選：未開啟驗證的站台勾選後會同時開啟網頁驗證；只透過共用使用者驗證的站台取消勾選後會標示「儲存後關閉驗證」，儲存時列出這些站台確認，確認後站台的驗證一併關閉、變成無需登入即可存取；使用轉發認證的站台不能使用共用使用者。頁面上的使用者、OIDC 與站台修改按下底部的「儲存」後一起生效，任一項校驗失敗時都不儲存，有未儲存的修改時離開頁面會先確認。

行為說明：

- 只要有共用使用者啟用了 TOTP，登入頁就會顯示驗證碼輸入框，每個驗證碼只能使用一次；
- 修改使用者的密碼或 TOTP 金鑰後，該使用者既有的工作階段立即失效；
- 基本驗證只接受未啟用 TOTP 的共用使用者，因為瀏覽器的密碼彈出視窗沒有地方輸入驗證碼；
- 失敗次數與其他登入共用同一套限流與自動封鎖。

要讓 Gitea、OpenList、Grafana 等應用程式識別登入的是哪個使用者，可以把共用使用者透過 [OIDC 單一登入](/zh-TW/docs/modules/oidc) 提供給應用程式。

### 自助修改密碼 {#self-service-password}

在「認證使用者」頁面開啟「自助修改密碼」後，共用使用者可以自己修改密碼，不必找管理員：

- 在開啟了「使用共用使用者」的站點造訪 `https://站點網域/__gately_auth/password`，登入頁也會顯示「修改密碼」入口；使用 [OIDC 單一登入](/zh-TW/docs/modules/oidc) 的使用者在簽發者網域造訪 `/__gately_oidc/password`；
- 輸入使用者名稱、目前密碼和兩次新密碼（8～128 個字元，且與目前密碼不同）；啟用了 TOTP 的使用者還需填寫動態驗證碼；
- 修改後該使用者在各站點的工作階段立即失效，需要用新密碼重新登入；已簽發的 OIDC 重新整理權杖作廢，舊 Access Token 也不能再讀取使用者資訊，但應用程式自行驗證的權杖在到期前仍有效，應用程式自己的登入工作階段也不受影響；
- 同一帳號修改成功後 1 分鐘內不能再次修改，避免反覆修改讓 FTP、SMB 不停重新載入、中斷其他人的連線；儲存時被服務檢查拒絕的詳細原因只寫入 Web 服務日誌，頁面只提示聯絡管理員；
- 目前密碼或驗證碼錯誤與登入失敗共用同一套限流與自動封鎖，其他網站代為提交的表單會被拒絕；Web 服務日誌會記錄修改的使用者與來源 IP；
- 同一頁面也可以修改[檔案服務共用使用者](/zh-TW/docs/modules/tools#shared-users)的密碼，兩種帳號分別開關，都開啟時頁面上可切換帳號類型；同名的兩種帳號互不影響。

## 存取控制

### IP 黑白名單

站台「安全」頁的「IP 存取控制」可選關閉、白名單、黑名單，清單每行一個 IP 或網段（如 `192.168.1.0/24`），還可以同時引用訂閱的 IP 清單。

### 拒絕方式

站台「安全」頁的「拒絕方式」決定被封鎖、IP 存取控制（含路徑規則）或國家過濾拒絕的請求如何處理：預設「傳回 403」；選擇「中斷連線」時不傳回任何內容直接中斷，存取日誌記為 444，與中斷連線站台相同。搭配白名單即可實現「自家 IP 正常存取、其餘一律中斷」。限流（429）與 WAF 攔截不受影響。

預設站台同樣可以這樣設定：類型選「反向代理」並填寫後端，IP 存取控制選白名單或黑名單（可引用下文的訂閱 IP 清單），拒絕方式選「中斷連線」。白名單命中或黑名單未命中的請求代理到後端，其餘直接中斷；訂閱清單更新後立即生效。「中斷連線」站台類型沒有後端，對所有請求一律中斷。

中斷連線（無論是站台類型還是拒絕方式）只是不傳回 HTTP 內容，無法隱藏服務存活：

- TCP 交握已經完成，對方能確認連接埠在監聽；
- HTTP/1.x 下關閉連線，HTTP/2、HTTP/3 下只重設這個請求，連線保持，對方可以繼續重複使用；
- HTTPS 下，未設定憑證的網域在 TLS 交握階段就會失敗，能到達預設站台的請求已經拿到憑證，憑證中的網域已經曝光。

要讓掃描者之後只看到逾時，需由[入侵防護](/zh-TW/docs/modules/guard)封鎖其位址，開啟防火牆同步後在核心層丟棄其流量。

### 訂閱 IP 清單

在「全域設定 → 訂閱 IP 清單」新增清單：填寫下載網址與重新整理間隔（預設 24 小時），下載網址（如 GitHub）直連不通時可在「下載代理」中選擇全域更新代理或填寫代理位址，Gately 會定時下載並快取到設定目錄，重新啟動後無需連網即可使用。內容每行一個 IP、CIDR 或 `起始-結束` 範圍，`#`、`;`、`//` 之後為註解。例如省市 IP 段可使用 [metowolf/iplist](https://github.com/metowolf/iplist) 的 `https://metowolf.github.io/iplist/data/cncity/440000.txt`（廣東省）。

- 站台與路徑規則的白名單、黑名單可以引用多個清單，與手動填寫的 IP 段一起判斷，符合任一項即視為在名單中；
- 下載內容無法辨識（例如回傳了錯誤頁面）時保留上次的清單，並在清單上顯示原因，一小時後重試；
- 清單下載成功前視為空清單：白名單因此拒絕存取，黑名單不額外攔截；
- 停用仍被引用的清單後，引用它的白名單拒絕全部來源，黑名單不再攔截任何來源；
- 刪除仍被引用的清單會被拒絕。

### 路徑規則

在「安全」頁的「路徑規則」中，依路徑前綴覆寫站台的驗證與 IP 設定：

| 欄位 | 取值 |
| --- | --- |
| `prefix` | 以 `/` 開頭的路徑前綴，如 `/admin` |
| `auth` | 沿用站台（空）、`off`（無需驗證）、`on`（必須驗證） |
| `ipMode` / `ipList` | 沿用站台（空）、`whitelist`、`blacklist`，並附 IP 或網段清單 |

比對規則：

- 最長前綴優先；
- 依路徑段邊界比對，`/admin` 符合 `/admin` 與 `/admin/x`，`/administrator` 不符合；
- 請求路徑先正規化（消除 `.`、`..` 與重複斜線）再比對，`/public/../admin` 以 `/admin` 處理；
- 同一前綴只能設定一條規則。

「驗證範圍」選項（`authOptional`）：勾選後，驗證只作用於規則中標記為「必須驗證」的路徑，其餘路徑公開。此選項需要先啟用基本驗證或網頁驗證。

### 臨時分享連結

啟用基本驗證或網頁驗證後，可為站台建立分享連結，讓訪客免帳號存取：

| 欄位 | 說明 |
| --- | --- |
| 名稱 | 備註名，如「給小明」 |
| 到期時間 | 留空為不過期 |
| 可用次數 `maxUses` | 最多可被兌換的次數，0 為不限；重新啟動後計數歸零 |
| 路徑限制 `pathPrefix` | 非空時，連結只能存取該前綴下的路徑，需以 `/` 開頭 |

訪客造訪 `https://網域/任意路徑?_gs=權杖` 即可兌換工作階段。兌換成功後伺服器端設定免登入 Cookie 並跳轉到去掉 `_gs` 參數的位址，工作階段最長 24 小時，且不超過連結的到期時間。權杖無效時按一般存取處理，不透露失敗原因。刪除連結後已發出的工作階段立即失效。權杖在儲存後產生（至少 16 位），可在介面複製完整連結。

### 驗證失敗限流與自動封鎖

- 同一來源 IP 在 15 分鐘內驗證失敗累計 10 次後，暫時拒絕繼續嘗試；
- 「全域設定 → 自動封鎖 → 驗證失敗封鎖」填寫分鐘數（0 至 43200），達到 10 次失敗時封鎖來源 IP；填 0 表示不封鎖，僅限流；
- 自動封鎖觸發時發布 `AuthBanned` 事件，可經 [通知中心](/zh-TW/docs/modules/notify) 推送；
- IPv6 位址依 /64 網段彙整計數與封鎖。

### 封鎖清單

「全域設定」中的封鎖清單顯示目前被封鎖的 IP、原因（驗證連續失敗或手動封鎖）和到期時間，可點擊「解除」。也可手動封鎖：填寫 IP 與小時數（1 至 720，即最長 30 天），介面預設時長為 24 小時。迴環位址與可信代理中的位址不能手動封鎖，原因見下文「中斷並封鎖」。勾選「永久」則不設到期時間（介面 seconds 為 -1）。

封鎖清單與[入侵防護](/zh-TW/docs/modules/guard)共用同一份：開啟入侵防護模組時，這裡只顯示封鎖數量，並連到入侵防護頁面管理。封鎖同樣對連接埠轉發、STUN 等服務生效，開啟防火牆同步後會在系統防火牆中丟棄；開啟「忽略內網位址」時，內網位址不會被自動封鎖。

### GeoIP 國家過濾

站台「國家過濾」有三種模式：關閉、僅允許、拒絕，並填寫兩位 ISO 國家代碼（以逗號分隔，如 `CN, HK, US`）。啟用時至少填寫一個國家。

- 過濾依賴 GeoIP 資料庫，需先在「全域設定 → GeoIP 資料庫」匯入：上傳 `.mmdb` 檔案，或填寫下載位址（「下載代理」預設使用全域更新代理，未設定更新代理時直連）。支援 MaxMind GeoLite2、DB-IP 等國家庫或城市庫；上傳限制 129 MB；
- 資料庫未載入時過濾不生效（放行所有訪客），介面會提示；
- 內網位址一律放行；
- 「拒絕」模式下，庫中查不到國家的位址放行。

## 依路徑分流後端

為反向代理站台把某個路徑前綴下的請求送到其他後端，相當於 nginx 的 `location /api/ { proxy_pass ...; }`。在站台編輯視窗「基本」頁的「分路徑後端」中新增。

| 欄位 | 說明 |
| --- | --- |
| `prefix` | 路徑前綴，如 `/api/`。依路徑段邊界比對：`/api` 與 `/api/` 都符合 `/api` 和 `/api/x`，不符合 `/apix` |
| `targets` | 該路徑的後端，寫法與站台後端相同；留空時使用站台後端，只追加下面的請求標頭 |
| `requestHeaders` | 該路徑追加的請求標頭，每行 `Key: Value`；在站台請求標頭之後套用，同名時以路徑的為準 |

- 最長前綴優先，路徑原樣轉發（不會去掉前綴）；
- 站台的其他設定，如 Host 選項、憑證驗證、轉發標頭、PROXY 協定、負載平衡策略與健康檢查，對每個路徑後端同樣生效；
- 壓縮、限流、快取與改寫作用於整個站台。

## 依使用者分流 {#user-routes}

為反向代理站台把不同登入使用者的請求送到各自的後端，相當於 nginx 的 `map $remote_user $backend`。站台需要先啟用基本驗證、網頁驗證或轉發認證，然後在站台編輯視窗「安全」頁的「依使用者分流」中新增規則：每條規則填寫一組使用者和這些使用者的後端，後端寫法與站台後端相同。

重新導向、靜態檔案、導覽面板與固定文字站台同樣可以依使用者分流：符合規則的使用者反向代理到規則的後端，未列出的使用者與公開路徑上的未登入訪客照常依站台類型處理，例如管理員進入後台、其他登入使用者跳轉到說明頁或看到「無權存取」的固定文字。此時「基本」頁的後端選項與「流量」頁的負載平衡、後端逾時、健康檢查作用於分流到的後端，回應快取仍只用於反向代理站台；中斷連線站台不經過認證，不能依使用者分流。

使用者依以下識別方式比對：

- 站台使用者或[共用使用者](#shared-users)的使用者名稱；
- 第三方登入身分寫 `提供方key:識別碼`，例如 `github:octocat`，該身分的其他識別碼同樣能比對；
- 轉發認證從認證服務回應複製回來的 `Remote-User`。

轉發規則：

- 未列出的使用者，以及公開路徑（無需驗證的路徑）上未登入的訪客，使用站台後端；公開路徑上已透過網頁驗證登入的訪客同樣依身分分流，同一應用程式的頁面會落到同一後端；
- 填寫了後端的分路徑規則（見上一節）優先；只追加請求標頭的分路徑規則改用該使用者的後端；
- 啟用記憶體回應快取時，快取鍵包含所選的使用者路由，設定了[傳遞身分資訊](#identity-headers)時還包含傳出的身分資訊，不同後端、不同使用者的回應不會混用。

儲存時檢查：站台已啟用驗證；每條規則至少有一位使用者和有效的後端；同一使用者不能出現在兩條規則中。站台清單中，設定了使用者路由的站台會顯示規則條數標籤。

### 傳遞身分資訊 {#identity-headers}

「傳遞身分資訊」把驗證通過的使用者身分寫入請求標頭傳給後端，適合依請求標頭識別使用者的應用，例如 Firefly III 用 `Remote-Email` 識別帳號。每行選擇一個欄位並填寫請求標頭名稱：

| 欄位 | 常用請求標頭 | 來源 |
|---|---|---|
| 使用者名稱 | `Remote-User` | 站台使用者或共享使用者的名稱；第三方登入為 `提供方key:ID`；轉發認證為 `Remote-User` |
| 電子郵件 | `Remote-Email` | 共享使用者的電子郵件，或轉發認證複製回來的 `Remote-Email` |
| 顯示名稱 | `Remote-Name` | 共享使用者的顯示名稱，或轉發認證複製回來的 `Remote-Name` |
| 群組 | `Remote-Groups` | 共享使用者的群組（逗號分隔），或轉發認證複製回來的 `Remote-Groups` |

- 「新增常用 Remote-* 請求標頭」依上表一次補齊目前驗證方式可傳的欄位；
- 電子郵件、顯示名稱、群組只有使用[共享使用者](#shared-users)或轉發認證的站台可選，站台使用者與第三方登入只有使用者名稱；共享使用者修改資訊後，已登入的工作階段立即傳新值；與共享使用者同名的站台使用者以站台使用者密碼登入時只傳使用者名稱；
- 轉發認證只採信複製回來的標頭：複製標頭清單中沒有 `Remote-Email` 等時，訪客自帶的同名標頭不會被當作身分資訊；驗證服務沒有回傳 `Remote-User` 時，其他資訊也不傳；
- 訪客自行送出的同名請求標頭一律刪除，包括以底線代替連字號的寫法（如 `Remote_Email`），無法偽造；未登入或經分享連結存取時不傳任何身分資訊，某項資訊為空時不傳該請求標頭；
- 儲存時檢查：請求標頭名稱合法且不重複（不分大小寫，`-` 與 `_` 視為相同）；不能是 `Host`、`Cookie`、`Authorization`、`X-Forwarded-For` 等影響轉發或驗證的請求標頭；不能與站台或分路徑規則的請求標頭設定同名，否則這些設定會覆蓋驗證結果；最多 16 條；
- 舊版本的「傳遞使用者名稱」在編輯站台時顯示為一行使用者名稱，儲存後併入此清單。

## 反向代理進階

這些選項位於站台編輯視窗的「流量」頁。

### 後端、權重與備用

後端清單每行一個位址，位址後可附參數：

```text
http://10.0.0.2:8080 weight=3
http://10.0.0.3:8080 backup
```

- `weight=N`：權重，1 至 100 的整數，預設 1；
- `backup`：備用後端，僅在所有非備用後端都無法使用時啟用；全部後端都無法使用時回退到所有非備用後端繼續嘗試。
- 連不上某個後端（連線被拒、無法到達或連線逾時）時，同一請求立即換下一個後端重試，先試其他主後端再試備用後端，最多嘗試 3 個後端；這時請求尚未送出，POST 等請求重送也安全。連線建立後的失敗不重試，失敗的後端照常計入被動檢查。

### 負載平衡策略

| 介面選項 | `lbPolicy` | 說明 |
| --- | --- | --- |
| 輪詢（依權重） | 空 | 預設 |
| 隨機（依權重） | `random` | |
| IP 雜湊（工作階段保持） | `ip_hash` | 同一用戶端 IP 落到同一後端 |
| 最少連線 | `least_conn` | 依「連線數 / 權重」選擇最小者 |

### 健康檢查

主動檢查開關預設關閉。啟用後的欄位與預設值：

| 欄位 | 預設值 | 範圍 |
| --- | --- | --- |
| 方式 `mode` | `http` | `http`（請求檢查路徑，狀態碼小於 400 視為健康）或 `tcp`（只測試連線） |
| 路徑 `path` | `/` | 以 `/` 開頭，僅 http 方式 |
| 間隔 `interval` | 10 秒 | 1 至 3600 |
| 逾時 `timeout` | 3 秒 | 1 至 60 |
| 連續失敗 `fails` | 3 次判定無法使用 | 1 至 20 |
| 連續成功 `passes` | 2 次恢復 | 1 至 20 |

啟用向後端送出 PROXY 協定時，HTTP 檢查自動改用 TCP。

被動檢查一律生效：多個後端中，連續 3 次連線失敗的後端暫停 30 秒後再試探（只有一個後端且未啟用主動檢查時不摘除）。啟用主動檢查後，恢復完全由檢查結果決定。後端狀態變動時發布上游無法使用 / 已恢復事件，可經 [通知中心](/zh-TW/docs/modules/notify) 推送。

### 後端逾時 {#backend-timeouts}

反向代理站台連線後端的逾時，單位為秒，填 0 使用預設值。分路徑後端與依使用者分流的後端使用同一組設定。

| 欄位 | 預設值 | 範圍 | 說明 |
| --- | --- | --- | --- |
| 連線 `timeouts.connect` | 10 秒 | 1 至 300 | 與後端建立 TCP 連線 |
| TLS 交握 `timeouts.tlsHandshake` | 10 秒 | 1 至 300 | 與 HTTPS 後端完成 TLS 交握 |
| 等待回應標頭 `timeouts.responseHeader` | 不限 | 1 至 86400 | 請求（含請求本文）送完後等待後端回傳回應標頭 |

- 等待回應標頭只限制回應標頭到達之前的時間，之後的回應本文傳輸、檔案下載以及 WebSocket、SSE 等長連線不受影響；上傳大檔案時從請求本文送完才開始計時；
- 逾時回傳 504（閘道逾時），連線被拒等其他錯誤回傳 502；逾時與連線失敗一樣計入被動檢查；
- 後端啟動慢或經慢速鏈路存取時調大連線逾時；希望卡住的後端盡快報錯時設定等待回應標頭逾時。

### 訪客逾時 {#client-timeouts}

對訪客的讀寫閒置逾時，單位為秒，填 0 使用預設值 60 秒（與 nginx 的 `client_body_timeout`、`send_timeout` 預設值相同），中斷連線以外的站台類型都可設定。

| 欄位 | 預設值 | 範圍 | 說明 |
| --- | --- | --- | --- |
| 讀取請求本文 `clientTimeouts.readIdle` | 60 秒 | 1 至 3600 | 一次讀取請求本文最多等待的時間 |
| 寫出回應 `clientTimeouts.writeIdle` | 60 秒 | 1 至 3600 | 一次寫出回應最多等待的時間 |

- 只在一次讀取或寫出卡住時計時：資料持續傳輸的大檔案上傳下載、等待後端處理的時間以及 WebSocket 等長連線都不受影響；
- 用於中斷極慢地傳送請求本文或讀取回應的訪客（slowloris、slow read），避免它們長期佔住連線；
- 讀取請求本文逾時回傳 408 並關閉連線，不計入後端的被動檢查；寫出逾時直接中斷連線；
- HTTP/1、HTTP/2 與 HTTP/3 都生效。

### 壓縮

對反向代理、靜態檔案、固定文字站台可啟用壓縮（重新導向站台除外）。依 `Accept-Encoding` 優先選擇 `br`，其次 `gzip`。

- 僅壓縮文字類內容：`text/*`、JSON、JavaScript、XML、XHTML、RSS / Atom、WebAssembly、SVG；`text/event-stream` 排除在外；
- 宣告的 `Content-Length` 小於 256 位元組的回應保持原樣；
- 已有 `Content-Encoding` 的回應保持原樣；WebSocket 升級請求直接放行；
- 壓縮後強驗證 ETag 改為弱驗證。

### 依 IP 限流

依用戶端 IP 的權杖桶限流，欄位：

| 欄位 | 說明 |
| --- | --- |
| `rate` | 每秒允許的請求數 |
| `burst` | 突發容量；設定了 `rate` 而 `burst` 為 0 時自動取 `rate` 取整後加 1 |
| `maxConns` | 單一 IP 的並行請求上限，0 為不限 |

啟用限流時 `rate` 與 `maxConns` 至少設定一項。

### 記憶體回應快取

僅對反向代理站台生效，快取存放在記憶體中，以 LRU 淘汰。

| 欄位 | 預設值 | 範圍 |
| --- | --- | --- |
| `ttl` 預設時長 | 0 | 0 至 30 天（秒）。上游未宣告快取指令時，200 回應快取這麼久；0 表示只快取上游明確允許的回應 |
| `maxMb` 快取容量 | 64 | 1 至 4096 MB |

快取規則：

- 僅快取 GET 請求，且請求不含 `Range` 標頭與 `Cache-Control: no-cache`；
- 帶憑證的請求不快取：請求標頭含 `Authorization`、`Proxy-Authorization`、`Cookie`、`X-Api-Key`、`X-Auth-Token`、`X-Access-Token`、`X-CSRF-Token`、`X-Emby-Token`、`X-Emby-Authorization`、`X-MediaBrowser-Token`、`X-Plex-Token`、`X-Jellyfin-Token` 之一，或查詢字串含 `api_key`、`X-Plex-Token`、`token`、`access_token` 參數（參數名不區分大小寫）；
- 原始請求路徑含 `;`、`\`、`%2F`、`%5C`（不區分大小寫）的請求不快取，這類路徑經正規化後與後端的理解可能不同；
- 僅快取狀態碼 200 的回應；回應含 `Set-Cookie`、`Vary: *`，或 `Cache-Control` 為 `no-store` / `private` / `no-cache` 時略過；
- 回應的 `Vary` 只能包含 `Accept-Encoding`，站點開啟跨域時還可以包含 `Origin`，含其他請求標頭時不快取；後端自己回傳的 `Access-Control-Allow-Origin` 不是 `*` 時不快取；
- 站點開啟跨域時，快取的項目不保存 Gately 依訪客來源寫入的跨域標頭，命中時依本次請求的 `Origin` 重新產生；
- 遵循 `s-maxage`，其次 `max-age`；
- 單一項目上限為 4 MB，同時不超過總容量的四分之一；
- 命中時回傳標頭 `X-Cache: HIT` 與 `Age`，未命中為 `X-Cache: MISS`；
- 快取鍵包含 Host、完整請求 URI 與 `Accept-Encoding`；設定了[依使用者分流](#user-routes)時還包含所選的使用者路由，設定了[傳遞身分資訊](#identity-headers)時還包含傳出的身分資訊。

依路徑快取（`rules`，站點編輯框「流量」頁籤的「依路徑快取」，最多 200 條）：

| 欄位 | 說明 |
| --- | --- |
| `path` | 比對的路徑，以 `/` 開頭，不含空白、`?`、`#`，也不含 `.`、`..` 路徑段或連續的 `/`，同一站點內不能重複。不能含 `%`（請直接填寫解碼後的路徑，如 `/中文/*`），區分大小寫。不含 `*` 時依路徑段前綴比對：`/api` 比對 `/api` 與 `/api/x`，不比對 `/apix`；含 `*` 時整條路徑萬用比對，`*` 比對任意字元（包括 `/`），如 `/api/products/*`、`/static/*.js` |
| `noCache` | 開啟即「不快取」：該路徑不讀也不寫快取 |
| `ttl` | 快取時長，0 至 30 天（秒）；0 為沿用站點預設時長 |
| `override` | 開啟即「強制快取」：忽略後端 `Cache-Control` 中的 `no-store`、`no-cache` 與 `max-age`，200 回應依快取時長快取，後端宣告 `private` 時仍不快取；規則與站點的時長至少一處大於 0 |

- 介面提供三種模式：「快取」遵循後端的 `Cache-Control`，後端未宣告時依時長快取；「強制快取」對應 `override`；「不快取」對應 `noCache`；
- 更具體的規則優先：去掉 `*` 後字元更多的規則先比對，相同時依設定順序；未命中任何規則的路徑使用站點預設設定。只想快取指定路徑時，可把 `/` 設為不快取；
- 規則依正規化後的請求路徑比對，`//api`、`/x/../api` 等寫法依 `/api` 處理；
- 任何模式下，上面列出的帶憑證請求、路徑含 `;` 等字元的請求，以及帶 `Set-Cookie`、`Vary: *` 或 `Cache-Control: private` 的回應都不快取；
- 強制快取的回應由所有訪客共用，只用於與訪客身分無關的內容，例如靜態資源；後端依來源 IP 免認證（例如內網存取不需要登入）時不要使用，否則內網訪客看到的內容會被快取給外網訪客。

查看與清空快取：編輯已儲存的站點時，「流量」頁籤顯示該站點執行中的快取項目數與佔用（「目前快取」），可「重新整理」「全部清空」，也可在某條規則上清空此路徑的快取。對應介面：

- `GET /api/webservice/cache?listener=&site=`：回傳 `enabled`、`entries`、`bytes`、`maxBytes`；`site` 為站點識別碼，預設站點為 `default`；站點不存在或所屬監聽未執行時回傳 404；
- `POST /api/webservice/cache/purge`，請求本文 `{"listener", "site", "path"}`：`path` 留空清空整個站點的快取，否則只清空路徑命中的項目，寫法與比對方式同規則的 `path`；回傳刪除的條數 `removed` 與清空後的狀態；站點未啟用快取時回傳 400。

### 路徑改寫與重新導向

規則依順序比對，命中第一條即停止。

| 欄位 | 說明 |
| --- | --- |
| `pattern` | 比對請求路徑的正規表示式，如 `^/old/(.*)$` |
| `to` | 取代結果，可用 `$1` 引用群組 |
| `redirect` | 關閉為內部改寫（改寫後的路徑送往後端，目標需以 `/` 開頭）；開啟為重新導向 |
| `code` | 重新導向狀態碼 301 / 302 / 307 / 308，預設 302 |

重新導向會保留原查詢參數。重新導向目標中可以寫 `{host}`，表示訪客使用的網域。重新導向規則先於驗證執行，相當於 nginx 的 `location = / { return 302 ...; }`，所以 `/` 這類路徑可以直接把訪客送走，不要求先登入。

## 錯誤頁 {#error-pages}

站台編輯框的「錯誤頁」頁籤決定訪客看到的 404 與 5xx 頁面。預設使用 Gately 內建的樣式，可以換成 10 種內建風格之一（極簡、終端、霓虹、星空、報刊、粗獷、極光、像素、藍圖、狀態鏈路），也可以使用自己的頁面。所有風格都適配手機螢幕，文案依訪客瀏覽器的語言顯示，卡片右下角的眼睛按鈕可依不同狀態碼與桌面、手機尺寸預覽。

- 作用範圍：Gately 為站台產生的 404 與 5xx 頁面，例如連不上後端時的 502、靜態檔案不存在時的 404、跳轉目標暫時無法使用時的 503、轉發認證服務無法使用時的錯誤。靜態站台填寫了「404 頁面」時，找不到檔案仍優先使用它。存取控制拒絕時的 403 與限流的 429 不受影響。
- 預設站台：其設定同時用於沒有任何站台符合存取網域時的 404，預設站台未啟用時同樣生效。
- 瀏覽器以外的用戶端（`curl`、介面呼叫等）仍得到純文字錯誤，與原來一致。

### 攔截後端錯誤 {#intercept-errors}

反向代理站台可以開啟「攔截後端錯誤」，把後端回傳的指定狀態碼換成上面選擇的頁面，相當於 nginx 的 `proxy_intercept_errors on` 加 `error_page`。狀態碼以逗號分隔，支援範圍與簡寫，例如 `404, 500-599` 或 `5xx`，只能填寫 400~599。

- 只替換瀏覽器開啟頁面的請求（`Accept` 含 `text/html`），介面、圖片、腳本等請求保持後端原樣，單頁應用的 JSON 404 不會被換成網頁。
- 狀態碼與 `Set-Cookie`、`Retry-After` 等回應標頭保留，描述原回應內容的標頭（壓縮編碼、`ETag` 等）去掉；`HEAD` 請求只回傳回應標頭。
- 「批次選項」可以一次修改多個站台的錯誤頁樣式，各站台的攔截設定保持不變。

### 自訂頁面 {#custom-error-pages}

自訂頁面儲存在頁面庫中，在「全域設定 → 自訂錯誤頁面」或站台「錯誤頁」頁籤的「管理自訂頁面」中維護，多個站台可以共用同一個頁面。頁面有兩種來源：

- 上傳或貼上：選擇 `.html` / `.htm` 檔案（UTF-8 編碼，不超過 256 KB）或直接貼上程式碼，內容儲存在設定中，可繼續修改。
- 伺服器檔案：填寫 `.html` / `.htm` 檔案的絕對路徑（Docker 中為容器內路徑），每次使用時檢查檔案是否變動。符號連結指向的也必須是 HTML 檔案，內容不像 HTML 的檔案會被拒絕；檔案被刪除或內容無效時訪客看到預設樣式，頁面庫中標為無法使用。

頁面中可以使用佔位符，輸出時替換為本次錯誤的資訊，並做 HTML 跳脫：

| 佔位符 | 內容 |
| --- | --- |
| `{code}` | 狀態碼，如 502 |
| `{status}` | 英文狀態短語，如 Bad Gateway |
| `{title}`、`{detail}` | 錯誤標題與說明，依訪客語言 |
| `{host}`、`{path}` | 存取的網域與路徑 |
| `{time}` | 發生時間（UTC） |

儲存前會自動檢查安全性與可用性，並顯示預覽：

- 錯誤頁與站台同源，為防止頁面被用來竊取 Cookie 或偽造操作，儲存時會去掉腳本、`onclick` 等事件屬性、`javascript:` 連結、內嵌框架、外掛物件、表單、`<base>`、`<meta http-equiv>`（自動跳轉等）與危險的樣式寫法，檢查結果中列出去掉的內容。
- 輸出時附加 `Content-Security-Policy: sandbox; default-src 'none'; ...`：頁面執行在獨立的沙箱中，即使混入腳本也無法執行；除內嵌樣式與 `data:` 內嵌的圖片、字型外不載入任何資源，訪客的位址不會洩露給第三方。外部樣式表、圖片、字型以及站內的相對位址都不會載入，檢查時會提示，請把樣式寫進 `<style>`、圖片與字型改為 `data:` 內嵌。
- 內容為空、不是 UTF-8、超過大小或不是 HTML 時拒絕儲存；缺少 `viewport`、編碼宣告不是 UTF-8、沒有使用佔位符時給出提示。

## 存取統計與監控

### 站台統計 {#site-stats}

執行中的監聽，在站台列點擊「統計」開啟統計視窗，可選最近 1 小時、6 小時、24 小時：

- 分鐘級存取統計：每分鐘一個點，保留最近 24 小時，包含請求數曲線與 4xx / 5xx 錯誤曲線；
- 首位元組延遲：每分鐘的 P50 / P95 曲線與所選時段的最高 P95。延遲為請求到達至回應標頭送出的時間，不含回應內容傳輸，WebSocket 等協定升級請求、被中斷的請求不計入；以各檔內的平均耗時估算百分位。門檻告警見[效能監控](/zh-TW/docs/modules/perf)；
- 狀態碼分布 2xx / 3xx / 4xx / 5xx，累計回應流量；
- 來源 IP Top 10 與國家 Top 10（國家統計需要已匯入 GeoIP 資料庫）；
- 反向代理站台顯示每個後端（含依路徑分流與依使用者分流的後端，標註路徑或使用者）的健康狀態、權重、是否備用、目前連線數與累計轉發請求數；
- 有請求被攔截時，依原因列出累計攔截次數：已封鎖、IP 名單、國家過濾、限流、WAF（認證失敗不計入）。

統計保存在記憶體中，重新啟動或修改該監聽自身的設定後重新計數；修改站台會保留其計數。排行榜最多統計 5000 個不同來源。

### 即時連線 {#connections}

執行中的監聽，站點列（含預設站點）的統計後面顯示「進行中 N」，即該站點正在處理的請求數，隨頁面重新整理。點擊「連線」開啟連線視窗，視窗每 2 秒自動重新整理，可依 IP 搜尋：

- **即時連線**：來源位址與連接埠、協定（h1 / h2 / h3，WebSocket 標記為 WS）、請求（方法、網域與路徑，不含查詢字串）、開始時間、已持續時間與流量（下行；有請求本文或 WebSocket 時還有上行）。依已持續時間由長到短排列，最多顯示 500 筆。設定了[可信代理](#real-ip)時來源為訪客真實位址，並註明經由的代理位址。
- **歷史紀錄**：最近結束的連線，含開始與結束時間、持續時間、流量與結果（已完成 / 已中斷）。只紀錄持續 1 秒以上或被手動中斷的連線，每個站點保留最近 200 筆，重新啟動後清空；短請求請查看存取日誌。

列表以進行中的請求計算：HTTP/1.1 長連線在兩次請求之間不屬於任何站點，HTTP/2、HTTP/3 的一條連線可同時承載多個請求，所以以請求為單位才能準確歸屬到站點；已升級的 WebSocket 會一直列出，直到連線關閉。

每列的「中斷」在確認後立即結束這個請求：HTTP/1.x 關閉整條連線，HTTP/2、HTTP/3 只重設這個請求，同一連線上的其他請求不受影響；已升級的 WebSocket 連同後端連線一起關閉。訪客不讀取資料導致傳送阻塞時同樣立即生效。被中斷的請求在存取日誌中記為 444（已開始回應時保留原狀態碼），不計入後端錯誤與路徑探測。訪客可以馬上重新連線，需要阻止時使用「中斷並封鎖」：把來源位址（IPv6 為所在 /64 網段）加入[封鎖清單](#封鎖清單)，並中斷它在全部監聽、全部站點上進行中的請求。迴環位址（經 frp、未帶 PROXY 協定的本機轉發進來的請求都顯示為它）和可信代理中的位址（IPv6 按 /64 判斷）不能封鎖，這類位址封鎖後會攔截一大批無關訪客；只中斷不封鎖不受此限制。封鎖時長可填 1 至 720 小時，或勾選「永久」。

唯讀帳號與唯讀權杖可以查看連線列表，中斷與封鎖需要寫入權限，並記入稽核日誌。

### 網路拓撲 {#topology}

左側選單「Web → 網路拓撲」是獨立的頁面（`#/webtopology`），Web 服務頁頁首的「網路拓撲」按鈕也可以進入。圖中依 網際網路 → Gately → 監聽 → 站點 / 監聽層級動作 → 後端 / 去向 展開，每 2 秒重新整理，頁面切到背景時暫停，畫布配色跟隨目前外觀的亮暗：

- **節點**：監聽顯示位址與執行狀態，啟動失敗標紅；站點顯示匹配方式（精確、萬用字元、任意網域、預設站點）、QPS 與進行中請求數；反向代理站點展開為全部後端，包括依路徑分流與依使用者分流的後端（標註路徑或使用者），無法使用的後端標紅；重新導向、靜態檔案、固定文字與中斷連線站點各有一個去向節點。預設站點中斷連線、HTTPS 連接埠收到明文請求時跳轉（301 / 308）、沒有站點匹配且未啟用預設站點時回傳 404，這幾類是預期設定，以灰色顯示。停用的監聽與站點同樣列出，顯示為未運行。
- **連線**：粗細隨 QPS 增加，有流量的連線播放流動動畫。連線超過 120 條時只有醒目顯示的鏈路播放動畫；系統開啟「減少動態效果」時不播放。
- **醒目顯示**：游標停在節點上或點擊節點時，它所在的整條鏈路（向上到網際網路、向下到後端）醒目顯示，並在連線上標出 QPS 與流量，其餘節點變暗；點擊空白處恢復。
- **詳情面板**：所選節點的 QPS（最近 10 秒平均）、60 秒平均、下行流量、進行中請求、累計請求、後端錯誤、依原因的攔截次數、回應狀態分布、近 60 秒每秒請求數與流量曲線，以及經過該節點的活動 IP。每項指標旁的 ⓘ 說明計算方式。站點可以從面板直接開啟統計、連線、存取記錄與編輯視窗，後端可以開啟所屬站點的存取記錄與編輯視窗，監聽可以直接編輯。
- **檢視存取記錄**：選取站點或後端節點後點「存取記錄」，開啟只含該站點的存取記錄（依站點名稱完整比對，不會混入名稱相近的站點）；已在頂部依某個 IP 篩選時按鈕變為「此 IP 的存取記錄」，同時依這個位址過濾。詳情面板活動 IP 每列右側的記錄圖示直接檢視該位址在所選站點的存取記錄，選取的不是站點類節點時檢視該位址在全部站點的存取記錄。記錄視窗中的過濾條件可以繼續修改，站點條件顯示為可移除的「站點：…」標籤。視窗同時依該站點所在的監聽過濾，另一個監聽上的同名站點（例如分別監聽 IPv4 與 IPv6、都名為 HTTPS 的兩個監聽上的站點）不會混入，監聽條件顯示為可移除的「監聽：…」標籤。只有開啟了存取記錄的站點才有完整記錄，未開啟時視窗頂部給出提示；沒有名稱的站點依第一個網域過濾。Web 服務頁每個站點列的「記錄」按鈕開啟同樣的視窗。
- **活動 IP**：最近 60 秒內有請求的訪客位址，加上仍有進行中請求的位址。畫布上只顯示個數，完整位址列在詳情面板。在頂部輸入或選擇一個位址（也可以點擊面板中的位址），圖中只醒目顯示它經過的鏈路，精確到具體後端；「清除篩選」恢復。每個站點、後端與監聽層級動作最多記錄 1024 個近期位址，介面一次最多回傳 500 個，來源過多時面板提示列表不完整。設定了[可信代理](#real-ip)時這裡是訪客真實位址。
- **遮蔽**：開關開啟後依勾選的類別把位址顯示為 `*`，方便截圖分享，只影響拓撲頁的顯示，搜尋仍依完整內容比對。可選：訪客 IP（活動 IP 清單與篩選框，IPv4 末段、IPv6 後 64 位）、後端位址（後端與跳轉目標中的 IP 與主機名稱）、監聽位址（監聽 IP、監聽錯誤訊息、以 IP 為網域的站點）、網域（站點網域與站點名稱中的網域，只保留第一段與尾碼，如 `nas.***.com`）。預設勾選前三項，選擇會被記住。
- **遮蔽方式**：遮蔽選單頂部可選「星號」或「代號」。星號只遮住部分內容，保留網段與首尾；代號把整個值換成本頁內一致的編號，訪客 IP 顯示為 `Visitor-01`，後端與跳轉目標中的 IP 顯示為 `Backend-01`，監聽位址顯示為 `Listen-01`，網域只保留後綴，可註冊部分與主機部分分別編號，如 `nas.home.example.com` 顯示為 `host-01.domain-01.com`，同一網域下的子網域共用 `domain` 編號。相同的值始終得到相同的代號，不同的值代號不同，圖中仍能看出哪些節點相同。編號依出現順序分配，只保存在目前頁面，重新整理後重新編號。
- **篩選**：右上角的「篩選」可以只看部分監聽；「只看異常」只顯示啟動失敗的監聽（保留其全部站台）、已啟用卻未執行的站台與有後端不健康的站台，停用的監聽與站台屬於預期狀態，不算異常；「曾有攔截」依原因（封鎖、IP 名單、國家過濾、限流、WAF）只顯示自 Gately 啟動以來出現過該原因攔截的站台。各條件同時生效，也可以與頁首搜尋組合；依異常或攔截篩選時隱藏監聽層級動作，沒有剩餘站台的監聽一併隱藏。篩選只在本頁有效，離開頁面後恢復顯示全部。
- **聚焦活動**：服務很多時點擊右上角的「聚焦活動」，只顯示最近 60 秒有請求、有進行中請求或有活動 IP 經過的站點與監聽層級動作，代理站點只保留活動中的後端（後端都沒有請求時站點作為末端顯示，例如請求被存取控制攔截），沒有活動的監聽隱藏。此時監聽摺疊與「還有 N 個」收合不生效，畫布自動適應讓這些節點完整顯示（樹狀、直向與桑基最小 50%），服務開始或停止活動時隨之更新。按鈕上的數字是目前活動中的站點數，隨篩選與搜尋變化，未開啟時也顯示。可與篩選、搜尋、依 IP 醒目顯示和各種版面同時使用，開啟狀態依裝置記住；最近 60 秒都沒有請求時畫布會提示，點「顯示全部」退出。
- **回放**：點擊右上角的「回放」開啟時間軸，回看過去某一時刻的拓撲。錄製預設關閉，管理員在時間軸上點「開啟錄製」或在「錄製設定」中開啟。開啟後每 5 秒把整張拓撲（速率、計數、後端健康、活動 IP）錄成一幀，壓縮後只保存在記憶體中，依「記憶體上限」（預設 8 MiB，可設 1–256）保留，超出時捨棄最舊的幀；內容不變的連續幀（如沒有流量時）合併儲存，所以流量小時能回看很久，流量大時回看的時間變短。時間軸依流量畫出面積圖，底部紅色標出有監聽啟動失敗或後端不健康的時段，深色為沒有錄製的時段（模組停用或沒有執行中的監聽）。點擊或拖動時間軸定位，懸停檢視當時的 QPS 與活動 IP 數；用按鈕或鍵盤 ← → 逐幀移動，空白鍵播放或暫停，播放速度 1×–60×，勾選「略過閒置」後播放時越過沒有流量和訪客的時段；時間軸範圍可選全部錄製或最近 15 分鐘到 24 小時，選擇依裝置記住。回放時七種佈局、篩選、聚焦活動、打碼與依 IP 醒目提示照常可用，詳情面板的曲線為所選時刻之前 60 秒（每 5 秒一個點）；「連線」反映的是目前狀態，回放時不顯示。點「回到即時」結束。錄製的資料含訪客 IP，重新啟動 Gately 或關閉錄製後清空；錄一幀約 0.4 毫秒（40 個站點、200 個活動 IP 實測），壓縮後約 1–2 KB。
- **版面**：右上角的版面選單有七種，選擇會被記住，切換時淡入淡出並自動適應畫布。「樹狀」由左到右排成五欄，資訊最完整；「直向」由上到下展開，像組織圖，開啟時以 Gately 為中心，左右拖曳查看；「放射狀」以 Gately 為圓心，監聽、站點、後端依序分布在三層同心圓上，名稱沿半徑方向顯示；「桑基」各節點是直條，連線是流量帶，父節點依子節點 QPS 的占比切分，直條高度與帶寬隨流量變化，節點位置保持不動；「旭日」以 Gately 為圓心，監聽、站點、後端是三層環形扇區；「矩形樹狀圖」與「泡泡」把 Gately、監聽、站點、後端逐層巢狀成方塊或圓形，每個後端（或去向）面積相同。旭日、矩形樹狀圖與泡泡沒有連線，顏色越深流量越大，適合站點很多時總覽。桑基、旭日、矩形樹狀圖與泡泡的畫布上沒有摺疊按鈕，在監聽的詳情面板中摺疊或展開。
- **收合多餘節點**：每個監聽預設顯示前 8 個站點、每個站點前 6 個後端，其餘合併為「還有 N 個站點 / 後端」節點，顯示它們合計的 QPS 與進行中請求數；點擊展開全部，展開後末尾的「收合」節點可恢復。被收合節點上的活動 IP 計入這個彙總節點，依 IP 醒目提示時鏈路停在它上面。最近 60 秒有請求或有進行中請求的站點與後端不會被收合，超出上限也依原順序直接顯示，彙總節點裡只剩閒置的，副標題顯示「最近 60 秒無請求」。
- **平移、縮放與畫布大小**：拖曳畫布平移，滾輪上下捲動（到達邊緣後捲動頁面）；按住 Ctrl/⌘ 捲動、觸控板捏合或觸控螢幕雙指捏合縮放（15%–250%），以指標或雙指中點為中心。右下角可放大、縮小、恢復 100%、適應畫布（顯示全部，定位圖示）；最右側的按鈕讓畫布鋪滿目前瀏覽器視窗，按 Esc 或再按一次恢復。拖曳畫布下方的橫條可調整畫布高度（觸控螢幕同樣可用），設定的高度依裝置記住，按兩下橫條或點「自動高度」恢復依內容自動調整。
- 頁首的搜尋框篩選拓撲中的站點（名稱、網域、分組、後端位址）；監聽可以個別摺疊，也可以全部收合。詳情面板中的「編輯」「編輯監聽」直接在本頁開啟與 Web 服務頁相同的編輯視窗，儲存後拓撲立即重新整理，不離開目前頁面；統計、連線與存取記錄視窗也在本頁開啟。

圖中數字全部來自本執行個體記憶體中的計數：重新啟動後歸零，修改站點保留計數，修改連接埠等監聽設定後該監聽重新計數，不彙總其他 Gately 執行個體。拓撲視圖讀取 `GET /api/webservice/topology`，唯讀帳號與唯讀權杖可以查看。回放讀取 `GET /api/webservice/topology/replay`（概覽與時間軸）與 `GET /api/webservice/topology/replay/frame`（某一時刻的快照），唯讀帳號可以回看；修改錄製設定為 `PUT /api/webservice/topology/replay/settings`，需要寫入權限。

### 訪客稽核 {#visitor-audit}

左側選單「Web → 訪客稽核」（`#/webvisitors`）依訪客位址彙總全部站點的存取，回答「誰在什麼時候造訪了哪些站點和路徑、以什麼身分、被攔截了多少次」。全部站點都會統計，包括預設站點與沒有站點符合的請求，與站點是否開啟存取日誌無關；設定了[可信代理](#real-ip)時記錄的是訪客真實位址。

- **彙總與趨勢**：頁首選擇統計範圍（今天、7 天、30 天、全部保留期）。上方卡片顯示訪客數（含新訪客）、請求數、被攔截數與占比、通過站點認證的訪客數、目前封鎖中的訪客數與掃描類位址數；點卡片依該條件篩選，再點一次取消。每日長條圖的高度為請求數，紅色部分為被攔截，點擊或懸停某一天顯示當天的訪客、請求與攔截數。
- **清單**：每位訪客顯示國家代碼（匯入了 GeoIP 時，內網與本機位址顯示「內網」）、統計範圍內的請求與攔截數、造訪最多的站點、身分、首次與最近造訪、最近一次請求（狀態碼、方法、路徑、網域與 User-Agent）。可依位址、身分、站點、網域、路徑或 User-Agent 搜尋，依「有被攔截」「認證訪客」「管理員」「封鎖中」「掃描類」與站點篩選，依最近造訪、請求最多、攔截最多或首次造訪排序。兩個監聽上的同名站點附上監聽名稱區分。
- **身分**：站點認證（網頁認證、基本認證、共享使用者、第三方登入、轉發認證）通過後記錄使用者名稱；帶本執行個體管理後台登入狀態的請求記為「管理員」。密碼錯誤的嘗試與被攔截的請求不會記錄身分。
- **掃描類**：只被攔截、或只造訪未符合站點、且從未通過認證的位址。
- **詳情**：點一列開啟訪客詳情：首次與最近造訪、請求總數、被攔截數、下行流量、中斷連線（444）次數，保留期內每天的請求長條圖，回應狀態分布與攔截原因（封鎖、IP 名單、國家過濾、限流、WAF），造訪過的站點、請求最多的路徑（最多 10 個）、身分與 User-Agent。可以在這裡封鎖或解除封鎖（IPv6 依 /64 封鎖）、依該位址檢視存取日誌，或刪除這位訪客的記錄。

**記錄範圍與儲存**：只保存依訪客彙總的計數，不保存逐筆請求；路徑只記錄路徑部分，查詢字串、請求內容、Cookie 與憑證一律不記錄。每位訪客最多保留 12 個站點、10 個路徑、6 個身分與 4 個 User-Agent，超出時替換請求最少的一項；逐筆請求請開啟站點的存取日誌。資料保存在設定目錄下的 `visitors/visitors.jsonl.gz`（權限 0600），有變化後約 10 分鐘寫入磁碟一次，結束時立即寫入，設定備份不包含它。

**設定**：頁首「設定」可以停用記錄（既有資料保留）、設定保留天數（1~180，預設 30）與最多訪客數（100~100000，預設 10000），也可以清空全部資料。最近一次造訪早於保留天數的訪客自動刪除；調小保留天數會立即刪除超出的資料，儲存前會確認。訪客數超過上限時先淘汰掃描類位址，再淘汰最久未出現的。唯讀帳號與唯讀權杖可以檢視，封鎖、刪除與修改設定需要寫入權限。介面見 `GET /api/webservice/visitors`、`GET /api/webservice/visitors/detail`、`POST /api/webservice/visitors/delete` 與 `GET|PUT /api/webservice/visitors/settings`。

### Prometheus 指標

全域指標端點 `GET /api/metrics` 彙總了全部模組的指標，見 [監控指標](/zh-TW/docs/reference/monitoring)。下面的模組端點只包含 Web 服務的指標。

指標端點為 `GET /api/webservice/metrics`，Prometheus 文字格式，需攜帶登入憑據或 [API 權杖](/en/docs/reference/api-reference)。

```bash
curl -H "Authorization: Bearer gtl_xxxx" http://localhost:16680/api/webservice/metrics
```

| 指標 | 類型 | 說明 |
| --- | --- | --- |
| `gately_site_requests_total` | counter | 站台累計請求數 |
| `gately_site_errors_total` | counter | 站台後端錯誤數 |
| `gately_site_active_requests` | gauge | 進行中的請求數 |
| `gately_site_response_bytes_total` | counter | 累計回應位元組數 |
| `gately_site_responses_total` | counter | 依狀態類別（標籤 `class`：`2xx` 至 `5xx`）統計的回應數 |
| `gately_site_blocked_total` | counter | 依原因（標籤 `reason`：`ban` 已封鎖、`ip` IP 名單、`country` 國家過濾、`rateLimit` 限流、`waf`）統計的攔截次數 |
| `gately_upstream_up` | gauge | 後端是否健康，1 健康、0 無法使用（附標籤 `upstream`） |
| `gately_upstream_requests_total` | counter | 轉發到後端的累計請求數（附標籤 `upstream`） |
| `gately_upstream_response_bytes_total` | counter | 後端回傳的累計回應主體位元組數，不含 WebSocket 升級後的資料（附標籤 `upstream`） |
| `gately_listener_requests_total` | counter | 監聽層直接處理、不經過站台的請求，標籤 `action` 為 `https_redirect`（HTTPS 連接埠的明文請求跳轉）或 `not_found`（未匹配站台的 404）；只帶 `listener` 標籤 |

除 `gately_listener_requests_total` 外，指標帶有標籤 `listener`（監聽名稱#監聽 key）與 `site`（站台名稱，未命名時取第一個網域）。依路徑分流與依使用者分流的後端在 `gately_upstream_*` 中另帶標籤 `route`：路徑前綴，或 `@` 加使用者列表。`upstream` 標籤為後端位址，去掉其中的使用者名稱、密碼與查詢字串。

## 匯入 nginx 設定 {#import-nginx}

頁面頂端的「匯入 nginx」可以把現有的 nginx 站台轉換為 Gately 的監聽與站台。建議在 nginx 所在主機執行 `nginx -T`，把完整輸出貼上：輸出中包含 include 的所有檔案，Gately 會像 nginx 一樣展開 include。

- 先預覽：依監聽連接埠分組列出每個站台的類型、後端或目錄、來源檔案與行號，以及需要留意的地方（使用了變數的指令、正規表示式 location、缺少憑證的網域等），無法轉換的站台會說明原因；
- 相同連接埠的站台合併到既有監聽，否則新增監聽；已存在的網域會略過，可以重複匯入；
- 預設匯入為停用狀態，方便與 nginx 並行逐一核對後再啟用；勾選「匯入後立即啟用」則立即生效（nginx 仍佔用相同連接埠時，新增的監聽會啟動失敗）；
- 可轉換的內容：`proxy_pass`（含 upstream 的權重、備用與負載平衡策略）、`root` / `alias` 靜態目錄（`autoindex`、`try_files $uri.html`、`error_page 404`）、`return` 跳轉與固定內容、整站 `rewrite` 跳轉、`add_header`、`proxy_set_header`、`gzip`、`allow` / `deny`、location 層級的分路徑後端、存取控制與跳轉、`listen ... proxy_protocol` 與 `quic`；
- `proxy_connect_timeout` 與 `proxy_read_timeout` 轉換為站台的[連線逾時與等待回應標頭逾時](#backend-timeouts)，location / 中的值優先於 server 級，超過上限時按上限匯入；其他 location 中不同的值不會匯入，預覽中會提示；
- `client_body_timeout` 與 `send_timeout` 轉換為站台的[訪客逾時](#client-timeouts)，各類站台都適用；
- `auth_request` 會轉換為轉發認證：驗證位址取自驗證子請求 location 的 `proxy_pass`（支援 `set` 變數），登入跳轉取自 `error_page 401 =302`，Authelia 的常見寫法可以直接轉換；只在部分 location 啟用時，轉換為只對指定路徑驗證（「驗證範圍」）；
- `auth_basic` 轉換為使用共用使用者的基本驗證，nginx 的使用者檔案不會被讀取，補齊使用者之前任何人都無法通過；
- `stream` 中的 TCP/UDP 轉發請在 [連接埠轉發](/zh-TW/docs/modules/portforward) 中設定；憑證不會匯入，HTTPS 站台缺少憑證時，預覽會列出 nginx 使用的憑證檔案，可在 [憑證](/zh-TW/docs/modules/ssl) 頁依檔案路徑新增。

## 取代 haproxy 與 nginx

協定分流加上 Web 服務可以取代 haproxy + nginx 的組合。常見配置是：在 443 上放一條[協定分流](/zh-TW/docs/modules/protoroute)規則，把 VPN 等 TLS 服務直接送到各自的後端，其餘網域送到一個接收 PROXY 協定的 Web 服務監聽；再在 80 連接埠放一個 Web 服務監聽，用重新導向站台（`https://{host}`）跳轉到 HTTPS。

nginx 設定的對應關係：

| nginx | Gately |
| --- | --- |
| 帶 `server_name` 的 `server` | 使用這些網域的站台 |
| `proxy_pass` 不同的 `location` | 分路徑後端 |
| `auth_request`（Authelia） | 轉發認證，或帶 TOTP 的共用使用者 |
| `proxy_ssl_name $host` | 使用造訪網域作為 SNI |
| `return 301 https://$host$request_uri` | 重新導向站台，`https://{host}` 並勾選「保留路徑」 |
| `location = /` 裡的 `return 302 /admin` | 改寫規則，開啟「重新導向」，pattern 為 `^/$` |
| `try_files $uri $uri.html $uri/index.html` 與 `error_page 404` | 靜態檔案的無副檔名網址與 404 頁面 |
| `error_page 502 503 504 /50x.html` 與 `proxy_intercept_errors on` | 站台的[錯誤頁](#error-pages)設定與攔截後端錯誤 |
| `add_header` | 回應標頭 |
| `return 444` | 中斷連線站台 |
| HTTPS server 中的 `error_page 497 https://$host:$server_port$request_uri` | 新建監聽的「同埠 HTTP」設為「跳轉到 HTTPS」；合併到已有監聽時只提示，不改動其設定 |

## 自動放行防火牆 {#auto-firewall}

Gately 執行在 OpenWrt 等路由器上，或執行在開啟了防火牆的 Linux 主機上時，系統防火牆預設攔截從外網發往本機的連線，監聽連接埠放行後才能存取。監聽開啟「自動放行防火牆」後，Gately 在本機防火牆只放行這個監聽的連接埠：

- 只放行監聽成功的連接埠：連接埠被其他程式佔用導致監聽失敗時不放行，佔用連接埠的程式（例如路由器管理頁面）保持不對外；
- 依監聽的網路放行：「僅 IPv6」只放行 IPv6，「僅 IPv4」只放行 IPv4，雙堆疊兩者都放行；填寫了監聽位址時只放行發往該位址的連線；只監聽 127.0.0.1、::1 時無需放行；
- 開啟 HTTP/3 時同時放行同號 UDP 連接埠；
- 監聽停用、刪除、啟動失敗或關閉開關時撤銷，Gately 結束時一併移除；
- nftables（OpenWrt fw4、firewalld 等）在 input 過濾鏈最前面插入規則，iptables / ip6tables（OpenWrt fw3、ufw 等）在 INPUT 鏈最前面插入；規則帶 `gately-open:` 註解，防火牆重新載入後 30 秒內補回；
- 核心沒有 nf_tables（如群暉 DSM）時改用 iptables（legacy）：放行規則寫在 Gately 專用的 filter 鏈（`GTLY_OPEN_` 開頭）中，INPUT 的第一條規則跳到這條鏈；系統防火牆把自己的規則插到前面時 30 秒內挪回第一位。Docker 映像已內建 iptables（legacy）；
- 只支援 Linux；Docker 部署需要 host 網路與 `cap_add: NET_ADMIN`。監聽卡片顯示放行結果，放行失敗時「防火牆」標籤顯示為橘色。

[連接埠轉發](/zh-TW/docs/modules/portforward#auto-firewall)與[協定分流](/zh-TW/docs/modules/protoroute#auto-firewall)的規則有同樣的開關，[STUN 穿透](/zh-TW/docs/modules/stun#auto-firewall)的規則放行通道連接埠。

### 手動放行 {#manual-firewall}

手動放行時只為需要對外的連接埠新增放行規則，wan 區域的傳入保持拒絕；把整個 wan 區域的傳入改為接受會讓路由器管理頁面（80 / 443）、SSH 等服務一起暴露在公網。OpenWrt 在「網路 → 防火牆 → 通訊規則」中新增，或寫入 `/etc/config/firewall`：

```
config rule
	option name 'Allow-Gately-HTTPS'
	option src 'wan'
	option family 'ipv6'
	option proto 'tcp'
	option dest_port '50663'
	option target 'ACCEPT'
```

- Gately 以 Docker bridge 網路執行時，容器內看不到路由器的防火牆，需要在主機或路由器上放行映射連接埠；
- Gately 執行在內網另一台裝置上（例如以 macvlan 取得獨立 IPv6 位址的容器）時，流量經路由器轉發，需要在路由器上新增轉發規則：目標區域選 lan，填寫裝置位址與用到的連接埠。電信業者下發的 IPv6 前綴會變化，位址可依後綴比對，例如 `option dest_ip '::1234/::ffff:ffff:ffff:ffff'`。

## 部署提示

Web 服務需要監聽主機的 80 / 443 等連接埠，Docker 部署建議使用 `--network host`。
