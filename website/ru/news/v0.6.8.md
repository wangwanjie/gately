# Вышел Gately v0.6.8

17 ноября 2026 г.

[Скачать v0.6.8](/ru/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8)

## Исправления безопасности

В этой версии исправлены следующие проблемы, затрагивающие v0.6.6.6 и более ранние версии; рекомендуем обновиться как можно скорее.

- **Токены записи могли читать каталог конфигурации (высокая)**: токены вроде `storage:write` или `webservice:write` позволяли подключить каталог конфигурации как хранилище или статический сайт, прочитать `account.json` и подделать сессию администратора. Теперь подключения хранилищ, статические сайты и WebDAV/FTP/SMB отклоняют каталог конфигурации и всё внутри него; каталоги, содержащие его, по-прежнему можно открывать, при этом каталог конфигурации скрыт. Пути управляемых программ (EasyTier/Tailscale/NetBird) и пароль резервных копий меняются только из сессии с входом, а редактор токенов отмечает модули, запись в которых доступна к файлам сервера.
- **Адрес возврата сторонней авторизации на сайтах можно было подменить через Host (высокая)**: на сайтах с подстановочным доменом или по умолчанию билет входа мог уйти на хост злоумышленника. Теперь вход начинается только с адресов, указывающих на этот экземпляр.
- **Сбой SMB до аутентификации на 32-разрядных сборках от одного пакета (высокая)**: смещения и длины проверяются в 64-разрядной арифметике, panic обрывает только своё соединение, а для неавторизованных соединений добавлены тайм-ауты, ограничение размера запроса и лимиты числа соединений.
- **Прочее (средняя/низкая)**: в режиме шлюза fnOS страницы на других портах того же хоста могли отправлять запросы с cookie администратора; cookie консоли передавались сайтам с тем же именем хоста; учётные записи только для чтения видели часть учётных данных; WebDAV/FTP следовали за символическими ссылками за пределы общей папки; блокировки по приманочным портам и обнаружению сканирования срабатывали от одного поддельного SYN; Webhook/PushPlus вставляли неэкранированный текст посетителей; пароли пользователей сайтов хранились открытым текстом (теперь bcrypt); CSP для интерфейса управления и cookie Secure при HTTPS; междоменный доступ ограничен собственными доменами сайта; вызовы входа по Passkey ограничены по источнику; расширена маскировка данных в диагностических пакетах.
- **Подпись релизов**: `checksums.txt` подписывается minisign (`checksums.txt.minisig`); онлайн-обновление сначала проверяет подпись, затем SHA-256, а релизы v0.6.8 и новее без файла подписи отклоняются.

## Интерфейс управления

- **Компактная навигация**: связанные страницы объединены в страницы с вкладками, боковое меню сократилось с 39 до 27 пунктов; старые адреса перенаправляются. Группы бокового меню сворачиваются в мобильной выдвижной панели.
- **Глобальный поиск**: Ctrl/⌘+K ищет страницы, вкладки, домены сайтов, правила перенаправления портов, записи DDNS и сертификаты.
- **Первый запуск**: после смены пароля новая установка спрашивает, для чего будет использоваться Gately (публикация сайтов, перенаправление портов / пробивка NAT, динамический DNS, объединение сетей, общий доступ к файлам, точка входа на VPS или всё сразу), и включает нужные модули; список «Начало работы» на обзорной странице отмечает шаги по реальной конфигурации.
- **Мастер быстрого создания сайта**: публикация сайта за три шага: домен, адрес бэкенда (с проверкой доступности и шаблонами для Home Assistant, Jellyfin, Emby, Vaultwarden, Nextcloud, Immich, Proxmox VE, Synology и fnOS), затем HTTP или HTTPS с выпуском сертификата на месте.
- **Шаблоны для пустых списков**: пустые списки перенаправления портов и DDNS предлагают шаблоны типичных сценариев.
- **Прочее**: строки HTTPS-сайтов показывают оставшиеся дни подходящего сертификата; формы проверяют обязательные поля перед сохранением; списки показывают причину ошибки загрузки и кнопку повтора; улучшены кнопки и верхняя панель на телефоне, в панели отображается название текущей страницы; заголовки страниц ссылаются на документацию; улучшены контраст и доступность.

## Импорт

- **Nginx Proxy Manager**: импорт nginx напрямую читает конфигурации NPM, подставляет переменные `set` в `proxy_pass` и цели перенаправления, а Force SSL, Cache Assets и другие параметры NPM сопоставляет с настройками Gately.
- **Sun-Panel**: навигационные панели импортируют экспорт Sun-Panel 1.x (.sun-panel.json) и 2.x (.zip) в новую или уже существующую панель.

## Навигационная панель

- **Раскладка**: для каждой панели ссылки можно показывать карточками или значками десктопных приложений; настраиваются размер значков, число ссылок в строке (отдельно для широких экранов и телефонов), отступы и ширина содержимого, а посетители могут менять стиль.
- **Выбор адреса**: ссылки с другими способами доступа по клику открывают выбор адреса (всплывающее окно на компьютере, нижняя панель на телефоне, управление с клавиатуры); недоступные адреса зачёркнуты.
- **Переключатели**: счётчики групп и значок количества адресов (оба по умолчанию выключены); подсказка «войдите, чтобы увидеть больше ссылок» показывается только на иначе пустой странице.

## Защита от вторжений и контроль доступа

- Приманочные порты и обнаружение сканирования учитывают только источники, завершившие TCP-рукопожатие, поэтому поддельные SYN больше не приводят к блокировкам.
- Успешный вход администратора освобождает адрес только от блокировок по приманочным портам и сканированию портов; блокировки по правилам журнала, зондированию веб-путей, TLS, стук и файловым службам продолжают действовать.
- Ошибки входа WebDAV/FTP/SMB публикуют событие `fileauth.failed` с шаблоном правила.
- Таблица блокировок ограничена 32768 записями; при заполнении сначала вытесняются истёкшие и самые старые временные автоматические блокировки, постоянные и ручные не вытесняются никогда.

## Перенаправление портов и разделение протоколов

- Каждый TCP-порт ограничивает число одновременных соединений от одного источника (адрес IPv4 или IPv6 /64); по умолчанию это половина лимита порта, значение настраивается для каждого правила и глобально; источники с loopback и из частных сетей не ограничиваются.
- TCP-соединения, в которых обе стороны не передают данные в течение тайм-аута первых данных (по умолчанию 60 секунд), закрываются.
- Форма сразу предупреждает, если целевой адрес записан как host:port.

## frp, DNS и WAF

- frps может принимать KCP и QUIC на UDP-портах, у frpc/frps появились параметры QUIC, а frps умеет автоматически открывать брандмауэр.
- Собственный DNS: если предпочтительный сервер не ответил за 1 секунду или завершился ошибкой, параллельно опрашивается следующий, и побеждает первый ответ.
- Динамический DNS: имена хостов приводятся к нижнему регистру, а при отсутствии записи Porkbun переходит к получению списка записей всего домена (#99); значения A/AAAA сравниваются как адреса, поэтому развёрнутая запись IPv6 больше не считается изменением.
- WAF: предварительный фильтр на регулярных выражениях включён по умолчанию (его можно отключить).

## Журналы и производительность

- Новая настройка уровня журнала (по умолчанию info, также через `GATELY_LOG_LEVEL`); записи по каждому соединению для перенаправления портов и разделения протоколов по умолчанию больше не пишутся.
- Меньше выделений памяти и конкуренции за блокировки на горячих путях журналирования, перевода, обратного прокси, таблицы блокировок, DNS и перенаправления портов; интерфейс управления подгружает компоненты и языковые пакеты по мере необходимости, поэтому первая загрузка меньше.

## Прочее

- Демо-режим: `-demo` / `GATELY_DEMO=1` запускает публичный экземпляр только для чтения с входом в режиме чтения в один клик и ежечасным сбросом данных (`deploy/demo`).
- Вопросы по использованию сначала задавайте в разделе Q&A на GitHub Discussions; группа в Telegram предназначена для живого общения.

## Заметки об обновлении

- Docker: загрузите новый образ и пересоздайте контейнер; OpenWrt: установите новый `.apk` / `.ipk` поверх прежнего; fnOS: установите новый `.fpk` в Центре приложений; остальные установки можно обновить онлайн в системных настройках.
- Пароли пользователей сайтов хранятся как хэши bcrypt, а API возвращает только маски; пароли открытым текстом, сохранённые прежними версиями, продолжают работать и преобразуются при следующем сохранении их слушателя.
- Уровень журнала по умолчанию info; чтобы получать записи по каждому соединению для перенаправления портов, установите debug в настройках.
- Подключения хранилищ, статические сайты и каталоги файловых служб, указывающие на сам каталог конфигурации или на пути внутри него, после обновления перестают отдаваться и перечисляются в журналах.
