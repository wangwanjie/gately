# Вышел Gately v0.6.8.1

17 ноября 2026 г.

[Скачать v0.6.8.1](/ru/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.1)

## Веб-службы

- **Не удавалось добавить или изменить сайт**: в v0.6.8 добавление, редактирование, копирование, включение и отключение сайта на странице «Веб-службы», а также редактирование HTTPS-слушателя завершались ошибкой формата `siteCerts`. Причина: сведения о сертификате сайта, добавленные в v0.6.8 (оставшиеся дни сертификата в строке сайта), интерфейс отправлял вместе с конфигурацией, а API сохранения не знал этого поля. Теперь интерфейс убирает его перед отправкой; API сохранения также игнорирует поля только для чтения, которые выдаёт сам API списка (состояние работы, статистику, сопоставление сертификатов и т. д.), поэтому старые страницы, оставшиеся открытыми после обновления, и скрипты, которые сначала читают конфигурацию, а затем отправляют её целиком, тоже могут сохранять. Остальные неизвестные поля по-прежнему отклоняются. Мастер быстрого создания сайта не затрагивался.
- **«Сайт не найден» при повторном использовании соединения**: если несколько доменов указывают на один IP и один сертификат покрывает их все (например, wildcard-сертификат `*.example.com`), браузер отправляет запросы нового домена по уже открытому HTTP/2-соединению. Если стоящая впереди маршрутизация по протоколу на основе SNI направляет часть этих доменов на другой Gately, это соединение на самом деле ведёт к другому серверу, и при обращении показывается «Сайт не найден» (или открывается сайт по умолчанию того экземпляра), пока браузер не будет закрыт и открыт заново. Теперь, если домен HTTP/2- или HTTP/3-запроса отличается от TLS SNI, а у этого слушателя нет сайта для такого домена, возвращается `421 Misdirected Request`: браузер открывает для домена новое соединение и автоматически повторяет запрос. HTTP/1.1 и запросы без SNI (обращение по IP) обрабатываются как раньше.

## Заметки об обновлении

- Docker: загрузите новый образ и пересоздайте контейнер; OpenWrt: установите новый `.apk` / `.ipk` поверх прежнего; fnOS: установите новый `.fpk` в Центре приложений; остальные установки можно обновить онлайн в системных настройках.
- Проблема повторного использования соединения полностью решается, только если обновлены оба конца SNI-маршрутизации: 421 должен вернуть тот Gately, на который попал запрос.
