# Частые вопросы

## Нужно ли подключение к серверам проекта?

Нет. Gately не обращается ни к каким серверам проекта и не отправляет данные об устройстве; по умолчанию он анонимно запрашивает у GitHub список выпусков и бюллетени безопасности — это можно выключить, см. [Автоматическая проверка обновлений](/ru/docs/guide/install#update-check). Для внешних адресов, например для определения публичного IP, используются сторонние публичные сервисы; их можно изменить в соответствующем задании.

## Какие учётная запись и пароль по умолчанию?

Учётная запись по умолчанию — `admin`, пароль по умолчанию — `gately.cn`. Этот пароль общеизвестен, поэтому сразу после входа смените его в разделе «Настройки → Аккаунт и безопасность»; до этого вверху интерфейса управления будет постоянно отображаться предупреждение. Если при развёртывании задана переменная окружения `GATELY_INITIAL_PASSWORD`, действует указанный в ней пароль.

## Что делать, если забыт пароль администратора?

Выполните на сервере `gately reset-password` (в Docker — `docker exec -it gately gately reset-password`) и подтвердите вводом `yes`: пароль сбросится на пароль по умолчанию `gately.cn`, а запущенный экземпляр применит это в течение нескольких секунд. Подробнее — в разделе [Сброс пароля и двухфакторной аутентификации](/ru/docs/guide/install#reset).

## Что делать, если потерян аутентификатор двухфакторной аутентификации?

Выполните на сервере `gately reset-totp` (в Docker — `docker exec -it gately gately reset-totp`). После подтверждения двухфакторная аутентификация отключится; войдите по паролю и включите её снова.

## Поддерживается ли fnOS?

Да. К каждому релизу прилагаются офлайн-пакеты для fnOS (`.fpk`), которые устанавливаются вручную через Центр приложений. Gately подключается к единому шлюзу fnOS, поэтому открывается значком на рабочем столе и работает также через удалённый домен fnOS. Включите «Вход через fnOS» в разделе «Настройки → Контроль доступа», и администраторы, уже вошедшие в fnOS, сразу попадают в Gately без пароля и кода двухэтапной проверки. Подробнее — в разделе [Нативное приложение для fnOS](/ru/docs/guide/install#fnos).

## Поддерживаются ли OpenWrt / iStoreOS?

Да. В каждый релиз входят пакеты для OpenWrt: `.ipk` для OpenWrt 24.10 и более ранних версий (включая iStoreOS) устанавливается командой `opkg install`, `.apk` для OpenWrt 25.12 и новее — командой `apk add --allow-untrusted`. Служба запускается сразу после установки и хранит настройки в `/etc/gately`; для обновления достаточно установить новый пакет. Программа занимает около 32 МБ, поэтому подходит для программных роутеров с достаточным объёмом памяти. Подробнее — [OpenWrt](/ru/docs/guide/install#openwrt).

## Почему рекомендуется `--network host`?

Проброс портов, STUN и веб-службы должны напрямую слушать порты хоста. В режиме bridge каждый используемый порт придётся пробрасывать вручную.

## Откуда берутся программы Tailscale, frp и cloudflared?

Эти модули управляют официальными внешними программами, Gately их не содержит. В карточке «Онлайн-установка» на странице каждого модуля можно скачать последнюю или указанную версию, задать отдельный прокси загрузки и, если после обновления возникли проблемы, откатиться на предыдущую версию, а также удалить программу или сбросить настройки; подробнее — в разделе [Онлайн-установка, обновление и откат](/ru/docs/modules/tunnels#install). Для Tailscale онлайн-установка доступна только в Linux. Программы можно также разместить самостоятельно, место описано в разделе [Конфигурация и параметры запуска](/ru/docs/guide/configuration).

## STUN-правило включено, но снаружи доступа нет?

Если WAN-порт роутера находится за NAT уровня оператора (100.64.0.0/10), внешние клиенты не смогут подключиться к пробитому порту: это ограничение самой сети. Используйте [Tailscale / frp / Cloudflare Tunnel](/ru/docs/modules/tunnels).
