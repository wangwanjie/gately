# Конфигурация и параметры запуска

## Параметры командной строки

| Параметр | Описание |
| --- | --- |
| `-c` | Каталог конфигурации; можно также задать переменной окружения `GATELY_CONFIG_DIR` |
| `-listen` | Переопределяет адрес, на котором слушает интерфейс управления, например `:16680` |
| `-apply` | Каталог декларативной конфигурации; можно также задать переменной окружения `GATELY_APPLY_DIR`, см. ниже |
| `-gateway-socket` | Дополнительно отдаёт интерфейс управления через этот сокет Unix, например для единого шлюза fnOS |
| `-gateway-prefix` | Префикс пути при доступе через шлюз, например `/app/gately` |
| `-api-docs` | Экспортирует документацию API (`openapi.json` и `API.md`) в указанный каталог и завершает работу |
| `-version` | Выводит сведения о версии |

| Переменная окружения | Описание |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | Начальный пароль администратора при первом запуске (не короче 8 символов), если не задан — используется пароль по умолчанию `gately.cn`; не действует, если учётная запись уже существует |
| `GATELY_LANG` | Код языка, который читается первым, когда язык сервера — «Как в системе»; затем по порядку читаются `LC_ALL`, `LC_MESSAGES` и `LANG` |

## Каталог конфигурации

Вся конфигурация хранится в каталоге конфигурации: по одному открытому файлу `<name>.json` на модуль, запись атомарная, права на файлы 0600. Поэтому:

- файлы можно просматривать в любом текстовом редакторе;
- каталог можно вести в git, проверять каждое изменение через diff и в любой момент откатываться;
- для резервной копии достаточно скопировать каталог.

::: warning Внимание
`ssl.json` содержит закрытые ключи сертификатов. Перед добавлением в репозиторий убедитесь, что он приватный, или внесите этот файл в список игнорируемых.
:::

## Декларативная конфигурация

С параметром `-apply <каталог>` при каждом запуске файлы `<имя>.json` из этого каталога копируются поверх файлов в каталоге конфигурации; файлы с тем же содержимым не перезаписываются. Это удобно, когда конфигурация хранится в git-репозитории, Kubernetes ConfigMap или скриптах развёртывания и раздаётся централизованно.

- Перед записью проверяется, что каждый файл — корректный JSON; если хотя бы один файл некорректен, запуск отменяется;
- `account.json` и `tokens.json` перезаписывать нельзя: учётные записи и токены управляются только в интерфейсе управления;
- Перезаписанное старое содержимое сохраняется в [истории конфигурации](/ru/docs/guide/audit), и к нему можно откатиться в любой момент.

## Каталог внешних программ

Tailscale, frp, cloudflared и File Browser управляют официальными внешними программами и ищут исполняемый файл в таком порядке:

1. путь, указанный в настройках модуля;
2. подкаталог `bin/` в каталоге конфигурации;
3. `PATH`.

На странице каждого модуля программу можно установить, обновить и откатить онлайн: она устанавливается в `bin/`, предыдущие версии хранятся в `bin/.versions/`. Подробнее — в разделе [Онлайн-установка, обновление и откат](/ru/docs/modules/tunnels#install). Бинарный файл можно также положить в каталог конфигурации самостоятельно, при развёртывании в Docker — например, `./gately-data/bin/frpc`; для Tailscale нужны оба файла: `tailscale` и `tailscaled`.

## Журналы работы

Журналы работы системы и всех модулей по умолчанию записываются в `logs/` в каталоге конфигурации, поэтому после перезапуска или обновления они по-прежнему доступны на странице системных журналов и на страницах модулей:

- Один файл JSON Lines на источник: `logs/<ID модуля>.log`, системные журналы — `logs/gately.log`. При запуске из файла восстанавливаются последние записи, не больше значения «Строк журнала в памяти»;
- Новые записи пишутся пакетами с задержкой не более 1 секунды. Файл, превысивший предел (по умолчанию 2 МБ), ротируется в `.1`, и хранится только этот предыдущий файл, так что каждый источник занимает не более двойного предела;
- Журналы доступа веб-сервиса объёмны и их часто просматривают позже, поэтому они архивируются по дням: когда текущий файл переходит на новый день (или превышает четверть общего размера, максимум 16 МБ), он переименовывается в `logs/webservice.<время начала>.log` и в фоне сжимается в `.log.gz`; самые старые архивы удаляются согласно «Хранение журналов доступа (дней)» (по умолчанию 7) и «Общий размер журналов доступа (МБ)» (текущий файл вместе со всеми сжатыми архивами, по умолчанию 32 МБ и не более 5 % раздела, где лежат журналы);
- Каждый модуль записывает встречавшиеся источники журнала в `logs/<ID модуля>.sources`; список сохраняется после перезапуска;
- В разделе «Настройки → Сеть и работа → Параметры работы» можно отключить «Сохранять журналы на диск», изменить «Предел файла журнала», «Хранение журналов доступа (дней)» и «Общий размер журналов доступа (МБ)» или перенести «Каталог журналов» в другой абсолютный путь (например, каталог на внешнем диске; если его нет, он создаётся с доступом только для пользователя, от имени которого работает Gately); изменения применяются сразу. После смены каталога новые журналы пишутся в новый каталог, файлы в старом остаются на месте. Если сохранение выключено, журналы хранятся только в памяти и очищаются при перезапуске;
- Очистка журналов модуля в интерфейсе удаляет и его файлы, ротированный файл, сжатые архивы и список источников;
- Резервные копии конфигурации не включают `logs/` и журнал аудита `audit.log`.

### Просмотр и фильтрация {#log-filter}

Страница «Системные журналы» и карточка журнала внизу каждой страницы модуля используют один и тот же просмотрщик. Условия можно сочетать; изменения применяются сразу, а новые записи добавляются, только если подходят под условия:

- уровень и источник (в списке есть все источники из конфигурации модуля и встречавшиеся в журналах, например все слушатели веб-сервиса, включая те, к которым ещё не обращались или чьи журналы есть только на диске; источник также можно ввести вручную);
- ключевые слова: слова через пробел должны совпасть все, двойные кавычки объединяют фразу, `-` в начале исключает слово, например `GET "timeout" -debug`; совпадения подсвечиваются. Если интерфейс на другом языке, ищите по переводу, который видите на экране;
- «Исключить»: записи, содержащие любое из слов, скрываются, вместе с ключевыми словами; запись та же (через пробел, двойные кавычки для фразы), например `debug "health check"`. Чтобы исключить слово, которое само начинается с `-`, возьмите его в двойные кавычки, например `"-v"`;
- IP в разделе «Другие фильтры»: полный адрес, диапазон (например, `10.0.0.0/8`) или часть адреса, несколько через запятую; если у записи нет отдельного поля IP, адреса распознаются в тексте, поэтому фильтр работает и для неудачных входов, и для журналов защиты от вторжений; префикс `!` или `-` исключает, например `!1.2.3.4, !10.0.0.0/8` скрывает эти источники, его можно сочетать с включаемыми элементами (`10.0.0.0/8, !10.0.0.5`);
- диапазон времени в разделе «Другие фильтры»: от последних 15 минут до последних 7 дней или произвольные начало и конец;
- На панели инструментов веб-сервиса есть ещё два переключателя отображения, которые влияют только на показ (журналы сохраняются, выбор запоминается в браузере): «Скрыть заблокированные источники» скрывает запросы, отклонённые из-за блокировки источника (за CDN блокировки в ядре не действуют на соединения CDN, поэтому заблокированные посетители отклоняются на веб-уровне и оставляют записи 403 / 444), а также все запросы от источников, которые всё ещё заблокированы, включая запросы, вызвавшие блокировку (они снова появляются после снятия или истечения блокировки); «Скрыть запросы панели» скрывает запросы с сессией панели управления этого экземпляра, например опрос страницы журналов, когда панель открыта через сайт веб-сервиса, и включён по умолчанию. Такие записи помечаются тегами «Причина блокировки=Заблокирован» или «Пользователь панели=…», параметры API — `hideBanned=1` и `hideAdmin=1` (учитываются только сессии администратора, но не учётные записи только для чтения; заблокированные запросы никогда не получают тег пользователя панели);
- журналы веб-сервиса дополнительно фильтруются по имени сайта или домену и коду состояния (`404`, `4xx`, `500-599`, несколько через запятую); журналы WAF — по домену, а записи о срабатываниях содержат домен и ID правила.

Нажмите на источник в журнале или на метку вроде «Сайт=…» или «Домен=…» в конце строки, чтобы отфильтровать по этому значению; в журналах веб-сервиса клик по «Сайт=…» сравнивает имя сайта целиком, на панели инструментов появляется удаляемая метка «Сайт: …» (параметр API `site`), и сайты со схожими именами не попадают в выборку. API также принимает параметр `listener` (ключ слушателя, точное совпадение); если у двух слушателей одинаковое имя, к именам их источников в журнале добавляется адрес прослушивания, например `HTTPS (0.0.0.0:443)` и `HTTPS ([::]:443)`, уникальные имена не меняются. Если записей в памяти не хватает, «Загрузить более ранние журналы» продолжает поиск по истории в файлах журнала (включая сжатые архивы веб-сервиса; при фильтре по времени архивы вне диапазона пропускаются), поэтому при включённом сохранении журналов на диск фильтрация не ограничена числом хранимых строк. `GET /api/logs` и `GET /api/<модуль>/logs` принимают те же параметры фильтра, см. [справочник API](/ru/docs/reference/api-reference).

Высоту области журналов можно менять: перетащите полосу под ней (на сенсорном экране — нажмите и тяните), двойной щелчок по полосе возвращает высоту по умолчанию, а когда полоса в фокусе, работают и клавиши со стрелками. Карточки журналов на страницах и диалог журналов сайта запоминают высоту отдельно, в текущем браузере. Кнопка полноэкранного режима справа на панели инструментов разворачивает журнал на всё окно; повторное нажатие или Esc возвращает обратно. Пока вы листаете историю вверх, новые записи продолжают добавляться, но больше не возвращают просмотр вниз; в правом нижнем углу области появляется кнопка «К последним» с числом поступивших записей. Прокрутка до конца или нажатие кнопки возобновляет автопрокрутку.

### Экспорт {#log-export}

«Экспорт» на панели инструментов журнала выгружает все записи, подходящие под текущие фильтры, включая историю в файлах журнала и сжатых архивах, от старых к новым; браузер сразу скачивает файл:

- CSV (электронная таблица): UTF-8 с BOM, открывается напрямую в Excel; столбцы — время, уровень, источник, сообщение и поля вроде IP, домена, сайта и кода состояния; к ячейкам, начинающимся с `=`, `+`, `-` или `@`, спереди добавляется одинарная кавычка, чтобы табличная программа никогда не выполняла присланные посетителями пути как формулы;
- JSON Lines: одна запись на строку, поля те же, что в API журналов;
- сообщения экспортируются на языке интерфейса; экспортировать могут и учётные записи только для чтения, и API-токены только с правом чтения, а пароли и токены в адресах скрыты так же, как при просмотре;
- API: `GET /api/logs/export` и `GET /api/<модуль>/logs/export`, `format` — `csv` или `jsonl`, остальные параметры фильтра те же, что при просмотре журналов; список источников — `GET /api/logs/sources` и `GET /api/<модуль>/logs/sources`.
