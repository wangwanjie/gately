# Быстрый старт

Развёртывание, вход и первое правило за пять минут.

## 1. Запуск

```bash
docker run -d --name gately --network host --cap-add NET_ADMIN \
  -v ./gately-data:/etc/gately \
  ghcr.io/wangwanjie/gately:latest
```

Чтобы управлять Docker из Gately, добавьте в команду `-v /var/run/docker.sock:/var/run/docker.sock`. `--cap-add NET_ADMIN` позволяет защите от вторжений записывать блокировки в брандмауэр хоста. Проброс портов, STUN и веб-службы слушают порты хоста, поэтому рекомендуется `--network host`.

Если GHCR работает медленно, используйте `vanjayak/gately:latest` с Docker Hub — это тот же образ.

::: tip Пользователям fnOS
Установите вместо этого нативное приложение: оно открывается значком на рабочем столе через единый шлюз fnOS и может пускать администраторов fnOS по их сеансу fnOS. Подробнее — в разделе [Нативное приложение для fnOS](/ru/docs/guide/install#fnos).
:::

## 2. Вход

Откройте в браузере `http://<IP устройства>:16680`, имя пользователя `admin`, пароль по умолчанию `gately.cn`. Пароль по умолчанию общеизвестен, поэтому после входа откроется окно смены пароля: продолжить работу можно после смены на новый трудноугадываемый пароль не короче 10 символов.

При новой установке после смены пароля Gately сначала спрашивает «Для чего вы будете использовать Gately?»: можно выбрать несколько вариантов из «Публикация домашних сервисов на домене», «Проброс портов / пробивка NAT», «Динамический DNS», «Объединение сетей», «Общий доступ к файлам», «Точка входа на VPS» или «Все функции». Остаются только модули выбранных сценариев, остальные отключаются (их настройки сохраняются), и Gately один раз перезапускается; включить их можно в любой момент в разделе «Настройки → Модули» или пунктом «Добавить функции» внизу боковой панели. «Пропустить» оставляет всё включённым. Обновлённые экземпляры этот шаг не показывают. Список «Начало работы» вверху обзора перечисляет следующие шаги для выбранных сценариев и отмечает их по фактической конфигурации; его можно свернуть или закрыть.

Боковая панель интерфейса управления показывает все страницы по группам. Глобальный поиск открывается сочетанием Ctrl+K (в macOS — ⌘K) или полем поиска вверху боковой панели: он переходит к страницам и их вкладкам по названию, а также находит домены сайтов, правила проброса портов, записи DDNS и домены сертификатов. На телефоне нажмите значок поиска в верхней панели.

## 3. Базовая защита

Сразу после входа в разделе «Настройки»:

1. включите двухфакторную аутентификацию (TOTP) или зарегистрируйте passkey;
2. при необходимости задайте секретный путь входа, доступ только из локальной сети или HTTPS для интерфейса управления;
3. проверьте оценку безопасности вверху раздела «Настройки → Аккаунт и безопасность» и устраните отмеченные пункты.

Дополнительные рекомендации: [Рекомендации по защите](/ru/docs/guide/hardening).

## 4. Первое правило

«Быстрый сайт» на странице «Веб-служба» публикует сайт в три шага: укажите домен, адрес бэкенда (с кнопкой «Проверить» или с предзаполнением по шаблонам Home Assistant, Jellyfin, Emby, Vaultwarden, Nextcloud, Immich, Proxmox VE, Synology DSM, fnOS), затем выберите HTTP или HTTPS. Прослушиватель повторно используется или создаётся автоматически; подробнее см. [Веб-служба · Быстрый сайт](/ru/docs/modules/web#quick-site).

Выберите модуль под вашу задачу:

| Задача | Модуль |
| --- | --- |
| Публичный IP дома часто меняется, нужен постоянный домен | [Динамический DNS](/ru/docs/modules/ddns) |
| Провайдер не выдаёт фиксированный публичный порт, нужен доступ к домашним сервисам извне | [STUN-обход NAT](/ru/docs/modules/stun) |
| Перенаправить порт на другое устройство в локальной сети | [Проброс портов](/ru/docs/modules/portforward) |
| Открыть несколько внутренних сервисов под одним доменом с HTTPS | [SSL-сертификаты](/ru/docs/modules/ssl) + [Веб-службы](/ru/docs/modules/web) |
| Объединить сети в разных местах | [Tailscale / frp](/ru/docs/modules/tunnels) |
