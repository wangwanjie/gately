# Динамический DNS (DDNS)

Публичный IP домашнего интернета меняется. DDNS автоматически обновляет DNS-записи после смены IP, чтобы домен всегда указывал на текущий адрес.

## Поддерживаемые провайдеры

Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod, Huawei Cloud, GoDaddy, Porkbun, dynv6, DuckDNS, Amazon Route 53, OVHcloud, Gandi, NS1, Bunny DNS, Namecheap, DynDNS2, а также пользовательский callback (для провайдеров без встроенной поддержки и собственных интерфейсов).

| Провайдер | Учётные данные | Подходит для DNS-проверки сертификатов |
| --- | --- | --- |
| Amazon Route 53 | Access Key ID / Secret Access Key, необязательно ID размещённой зоны | Да |
| OVHcloud | Application Key / Secret и Consumer Key, точка доступа ovh-eu / ovh-ca / ovh-us | Да |
| Gandi | Personal Access Token | Да |
| NS1 | API Key | Да |
| Bunny DNS | Account API Key | Да |
| Namecheap | Пароль Dynamic DNS для домена (только A-записи) | Нет |
| DynDNS2 | Имя пользователя, пароль и адрес обновления; подходит для No-IP, Dynu и других сервисов, совместимых с протоколом dyndns2 | Нет |

## Способы получения IP

- **URL**: запрос к адресу определения публичного IP (можно заменить на любой сервис или поднять свой);
- **Сетевой интерфейс**: чтение адреса напрямую с указанного интерфейса, подходит для устройств с публичным IP;
- **Команда**: выполнение команды и использование её вывода, подходит для нестандартных сетей.

Поддерживаются IPv4 и IPv6.

## Переменные в значении записи {#record-vars}

В значениях записей можно использовать эти переменные; при каждой синхронизации они заменяются текущими значениями:

- `{ipv4Addr}`, `{ipv6Addr}` — адреса IPv4 и IPv6, полученные задачей (используются по умолчанию, если значение записи A или AAAA пустое);
- `{STUN_имя правила_PORT}`, `{STUN_имя правила_IP}`, `{STUN_имя правила_ADDR}` — текущие публичный порт, IP и IP:порт правила STUN; в имени правила допустимы подчёркивания. Например, запись TXT `port={STUN_ssh_PORT}` или запись A `{STUN_ssh_IP}`.

Когда публичный адрес правила STUN меняется, задачи, которые на него ссылаются, синхронизируются сразу, не дожидаясь следующей проверки. Пока правило выключено или ещё не пробилось через NAT, запись в этом цикле пропускается, а в её состоянии указывается причина. Переменные STUN можно использовать и в Webhook задачи. Если они есть только в Webhook, после смены адреса Webhook всё равно вызывается один раз. Вместо имени правила можно указать его ключ (key).

## Добавление записей списком {#batch}

На вкладке записей в редакторе задания нажмите **Добавить списком** и введите по одному домену в строке:

- Полный домен или только хост (например, `emby`), который добавляется в **зону по умолчанию**;
- Полные домены сначала делятся по зоне по умолчанию и зонам существующих записей, иначе по публичному суффиксу (например, `example.com.cn`); результат видно в предпросмотре;
- После домена можно указать тип и значение. Без типа добавляется по записи на каждый отмеченный тип (A, AAAA) со значением `{ipv4Addr}` или `{ipv6Addr}`; одиночный IP-адрес добавляется как A или AAAA по виду адреса;
- TTL, линия и примечание применяются ко всем добавляемым записям. Пустые строки и строки с `#` в начале пропускаются, случайно вставленные `https://`, порт и путь удаляются.

```text
www.example.com
nas.example.com
emby
v6.example.com AAAA
cdn.example.com CNAME target.example.net
_ssh.example.com TXT port={STUN_ssh_PORT}
fix.example.com 203.0.113.10
```

Строки-дубликаты существующих записей пропускаются. Неверные строки выводятся с номерами, их нужно исправить перед добавлением. Записи появляются в таблице редактора и применяются после сохранения задания.

## Уведомления

При смене IP или ошибке синхронизации можно вызвать Webhook. Если адрес обратного вызова напрямую недоступен, в поле «Прокси» Webhook выберите глобальный прокси обновлений или укажите адрес прокси с `http://`, `https://` или `socks5://`; такая же опция есть у STUN-обхода и HTTP-запросов запланированных задач.

## Примечания {#remark}

У записей может быть примечание: при синхронизации оно записывается у DNS-провайдера и видно в списке записей в его консоли. Если примечание записи пустое, берётся примечание задания; если пусты оба, существующее примечание у провайдера не меняется. Изменение одного лишь примечания тоже запускает синхронизацию. Всё, что длиннее 100 символов, не записывается (лимит бесплатного тарифа Cloudflare). У Alibaba Cloud примечание ограничено 50 символами из китайских иероглифов, латинских букв, цифр и `_ - , . ，。`; пробелы и прочие символы заменяются подчёркиванием.

Провайдеры, которым передаются примечания: Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod (китайская и международная версии), Huawei Cloud. У остальных примечание хранится только в Gately.

## Удаление записей и заданий {#delete}

При удалении записи (значок корзины справа от записи в списке или удаление сохранённой записи в редакторе с последующим сохранением) или задания открывается окно подтверждения, в котором можно отметить «Удалить и у DNS-провайдера»:

- если флажок отмечен, сначала удаляются записи у провайдера, а конфигурация Gately удаляется, только если удалось удалить все; при ошибке показывается причина, конфигурация Gately не меняется, и можно повторить попытку или снять флажок;
- удаляется только запись, которую синхронизирует Gately: с тем же именем и типом (и линией) и со значением, совпадающим с последней синхронизацией Gately;
- ничего не удаляется, а причина показывается, если Gately ещё не синхронизировал эту запись (значение неизвестно), если значение у провайдера отличается от последней синхронизации (например, его изменили в консоли) или если у провайдера, управляющего наборами записей (Huawei Cloud, Route 53, Gandi, NS1, GoDaddy), в наборе есть другие значения; сначала выполните синхронизацию или разберитесь в консоли провайдера;
- если записи у провайдера уже нет, это считается успехом;
- если при редактировании задачи удалить запись и отметить этот флажок, сначала проверяется сохраняемая конфигурация, и при ошибке проверки записи у провайдера не удаляются;
- у DuckDNS, Namecheap, DynDNS2 и пользовательского обратного вызова нет API удаления, поэтому флажок не показывается, и запись у провайдера нужно удалить вручную.

Состояние флажка по умолчанию задаётся в глобальных настройках.

## Глобальные настройки {#settings}

Глобальные настройки в заголовке страницы содержат:

- **Включить модуль**: пока модуль выключен, IP не проверяется и DNS-записи не обновляются;
- **Удалять и у провайдера**: состояние по умолчанию флажка «Удалить и у DNS-провайдера» при удалении записи или задания. По умолчанию выключено и может меняться при каждом удалении.

## Рекомендации

- Создайте для DNS-провайдера ключ субаккаунта только с правом редактирования записей и не используйте ключ основного аккаунта;
- после создания задания нажмите «Принудительная синхронизация», чтобы убедиться, что запись обновилась;
- ненужную запись можно удалить значком корзины справа от неё в списке, не открывая редактор; в задании остаётся хотя бы одна запись, а как удалить и DNS-запись у провайдера, описано в разделе [Удаление записей и заданий](#delete);
- адрес определения публичного IP не зависит от сервисов проекта, и его можно в любой момент заменить в задании.

## Группы и порядок

Задачам можно задать «Группу» (до 64 символов). Список показывает группы сворачиваемыми разделами: группы идут в порядке первого появления, элементы без группы — в конце, состояние свёрнутости хранится в браузере. Поле поиска вверху страницы фильтрует задачи и записи: если с запросом совпадает имя, группа, примечание или провайдер задачи, показываются все её записи, иначе — только записи, у которых совпадает домен, тип, группа, примечание или текущее значение; на время поиска свёрнутые карточки задач и группы записей автоматически раскрываются.

Нажмите «Сортировка», чтобы перейти в режим сортировки. Стрелками элементы перемещаются вверх и вниз, а также целые группы. Отметьте несколько элементов и перетащите любой из них, чтобы переместить их вместе; если отпустить их на элементе или заголовке другой группы, они перейдут в эту группу. Панель инструментов сразу переносит отмеченные элементы в указанную группу, а при пустом имени убирает их из группы. Порядок и группы влияют только на список: при их изменении задачи не перезапускаются.

Наведите указатель на заголовок группы и нажмите карандаш, чтобы переименовать её: все элементы получают новое имя и сохраняют место и порядок. Если выбрать имя существующей группы, после подтверждения группы объединятся.
