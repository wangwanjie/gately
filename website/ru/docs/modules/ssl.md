# SSL-сертификаты

Автоматически выпускает и продлевает сертификаты для [веб-служб](/ru/docs/modules/web); их также можно экспортировать для другого ПО.

Если один домен покрывают несколько сертификатов, используется сертификат с самым поздним сроком действия; порядок и группы в списке сертификатов влияют только на отображение.

## Возможности

- Автоматический выпуск и продление по **ACME DNS-01** с использованием DNS-провайдеров из раздела [динамического DNS](/ru/docs/modules/ddns), без открытия портов 80 / 443;
- **ACME HTTP-01**: DNS-провайдер не нужен, но порт 80 каждого домена должен быть доступен из интернета; wildcard не поддерживается;
- wildcard-сертификаты и EAB (например, ZeroSSL);
- **краткосрочные сертификаты и сертификаты для IP-адресов**: с краткосрочным профилем Let's Encrypt (срок действия около 6 дней) можно выпускать сертификаты для публичных IP-адресов;
- загрузка существующего сертификата или чтение из файлов;
- вывод в каталог: после изменения сертификата файлы записываются в указанный каталог и запускается скрипт, чтобы другие сервисы могли перезагрузиться;
- автоматическое развёртывание: после изменения сертификат копируется в несколько локальных каталогов, отправляется по SSH на другие хосты с выполнением команды или перезапускаются Docker-контейнеры, которые его используют.

## Проверка DNS-01

Выберите DNS-01 в поле «Способ проверки» сертификата и укажите DNS-провайдера. При выпуске Gately добавляет TXT-запись `_acme-challenge` через API провайдера и удаляет её после проверки.

«Корневой домен» — это DNS-зона, в которой находится запись. Если поле пустое, Gately находит авторитетную зону проверочной записи SOA-запросом, поэтому поддомен, делегированный другому DNS-провайдеру (например, `web.example.com` размещён отдельно от `example.com`), и многоуровневые суффиксы вроде `example.com.cn` определяются правильно. Если запрос не удался, зона определяется по имени домена, а причина записывается в журнал. Корневой домен можно указать и вручную, например `web.example.com`.

## Сеть для выпуска

Параметр сертификата «Сеть» ограничивает исходящую сеть при выпуске: «Автоматически» оставляет выбор системе, а «Только IPv4» или «Только IPv6» заставляет обращение к ЦС, вызовы API DNS-провайдера и проверку распространения TXT-записи использовать только это семейство адресов. Если у хоста есть IPv6-адрес, но IPv6 фактически не работает, проверка распространения в автоматическом режиме может завершиться по тайм-ауту при запросе к авторитетным DNS-серверам; в этом случае выберите «Только IPv4».

## Проверка HTTP-01

Выберите HTTP-01 в поле «Способ проверки» сертификата. При выпуске CA обращается к `http://<домен>/.well-known/acme-challenge/<token>`:

- если [веб-служба](/ru/docs/modules/web) уже слушает порт 80, она отвечает сама, не затрагивая существующие сайты;
- если порт 80 свободен, Gately временно слушает его на время выпуска и сразу закрывает после завершения;
- если роутер пробрасывает публичный порт 80 на другой порт этого хоста, укажите этот порт в поле «Временный порт».

Домашние провайдеры нередко блокируют входящие соединения на порт 80 — в этом случае используйте DNS-01.

## Краткосрочные сертификаты и сертификаты для IP-адресов

«Профиль сертификата» соответствует profile в ACME:

- **По умолчанию**: выбирает CA, у Let's Encrypt — 90 дней;
- **Краткосрочный (IP-сертификат)**: профиль Let's Encrypt `shortlived` со сроком действия около 6 дней. Gately автоматически продлевает его до истечения согласно параметру «Запас в часах для краткосрочных сертификатов» в «Настройках продления» (по умолчанию 24 часа), а при неудаче повторяет попытку каждый час;
- можно также ввести другое имя профиля, которое поддерживает CA.

Чтобы запросить сертификат для IP-адреса, укажите в доменах публичный IP-адрес (IPv4 или IPv6, например `203.0.113.10` или `2001:db8::1`); IP-адреса и домены можно указать в одном сертификате. Требования:

- используйте Let's Encrypt, выберите краткосрочный профиль и HTTP-01 в поле «Способ проверки». CA обращается к `http://<IP>/.well-known/acme-challenge/<token>`, поэтому порт 80 этого IP должен быть доступен из интернета. После ввода IP редактор покажет подсказку — достаточно нажать «Настроить автоматически»;
- частные адреса, адреса loopback и `100.64.0.0/10` не проходят проверку публичным CA; для собственного CA (например, своего ACME-сервера в локальной сети) этих ограничений нет;
- ZeroSSL и Google Trust Services не выпускают сертификаты для IP-адресов по ACME.

При доступе к HTTPS по IP-адресу браузер не передаёт имя домена (SNI), поэтому Gately выбирает IP-сертификат по локальному адресу соединения; за NAT или пробросом портов, когда локальный адрес отличается от публичного IP в сертификате, используется IP-сертификат с самым поздним сроком действия.

После переключения профиля уже выпущенного сертификата между профилем по умолчанию и краткосрочным сертификат сразу перевыпускается с новым профилем. Для краткосрочных сертификатов напоминание об истечении срока отправляется, только когда оставшееся время меньше половины запаса в часах (это значит, что продление несколько раз завершилось ошибкой).

## Вывод сертификатов

После включения сертификата Gately записывает `.crt`, `.key`, `.pem` и `_issuerCertificate.crt` в каталог вывода и выполняет скрипт, срабатывающий при изменении.

## Автоматическое развёртывание

В блоке «Автоматическое развёртывание» сертификата можно добавить несколько целей развёртывания; они срабатывают после выпуска, продления или обновления сертификата:

- **Копировать в локальный каталог**: сертификат записывается в каталог на этой машине, после чего локально выполняется команда «Выполнить после копирования». Можно добавить несколько каталогов, у каждого своя команда. Если файлы сертификата в каталоге удалены или изменены, следующая проверка скопирует их снова. Если Gately работает в Docker, каталог и команда находятся внутри контейнера;
- **Загрузить на SSH-хост**: выберите существующее SSH-подключение из [веб-терминала](/ru/docs/modules/terminal) — используются его адрес, способ аутентификации и прокси. Файлы сертификата (`<примечание>.crt`, `.key`, `.pem`, `_issuerCertificate.crt` — как при сопоставлении сертификата, поэтому «Примечание» обязательно) записываются в «Удалённый каталог», после чего на удалённом хосте выполняется команда из поля «Выполнить после загрузки», например `systemctl reload nginx`; в команде доступны `$certName`, `$certDir`, `$certFile`, `$keyFile`. Файлы сначала записываются во временные с нужными правами, а затем переименовываются с заменой; права на закрытый ключ — 0600;
- **Перезапустить локальные контейнеры**: после смены сертификата выбранные Docker-контейнеры перезапускаются по очереди; подходит для сервисов, которые монтируют каталог сопоставления и загружают новый сертификат только после перезапуска.

«Копировать в локальный каталог» и «Загрузить на SSH-хост» позволяют задать имена файлов сертификата (полная цепочка) и закрытого ключа, например `fullchain.pem` и `privkey.pem`. Если заданы оба, записываются только эти два файла, а примечание может быть пустым; если поля пусты, используются имена из сопоставления сертификатов. `$certFile` и `$keyFile` в команде указывают на фактически записанные файлы.

Автоматическое развёртывание не доверяет неизвестным хостам: к выбранному SSH-подключению нужно один раз подключиться в веб-терминале, чтобы сохранить ключ хоста, и только после этого сертификат будет отправляться. При ошибке развёртывание повторяется каждый час и генерируется событие «Сертификат: ошибка развёртывания», на которое можно подписаться в [Центре уведомлений](/ru/docs/modules/notify). Кнопка «Развернуть сейчас» на карточке сертификата игнорирует интервал повтора, сразу развёртывает сертификат на все включённые цели и показывает результат по каждой из них.

При редактировании сертификата цели, настройки которых не изменились, повторно не выполняются; после изменения удалённого каталога, команды или контейнеров развёртывание выполняется заново один раз.

## Замечания по безопасности

Закрытые ключи хранятся в `ssl.json` в каталоге конфигурации. Берегите этот файл, а при добавлении в систему контроля версий убедитесь, что репозиторий закрытый.
