# Tailscale / frp / cloudflared

Три модуля интегрируют официальные программы как управляемые процессы: автоматический перезапуск, сводка журналов в интерфейсе, настройка из интерфейса. Сам Gately эти программы не содержит; их можно установить, обновить и откатить онлайн прямо на странице.

## Онлайн-установка, обновление и откат {#install}

Внизу страниц frp, Cloudflare Tunnel, Tailscale и [File Browser](/ru/docs/modules/tools#filebrowser) есть карточка «Онлайн-установка»:

- **Скачать и установить / Обновить до последней**: скачивает из upstream последнюю стабильную версию, проверяет её по SHA-256, опубликованному upstream, убеждается, что она запускается на этой машине, устанавливает в `bin/` каталога конфигурации и затем перезапускает процессы, использующие программу. Если уже установлена последняя версия, повторной загрузки нет;
- **Установить версию**: укажите номер версии (например, `v0.65.0` для frp, `2025.8.0` для cloudflared, `1.90.2` для Tailscale); подходит и для понижения версии;
- **Прокси загрузки**: задаётся отдельно для каждой программы, поддерживаются http, https и socks5, сохраняется при запуске установки; при пустом значении используется прокси обновлений из «Настроек»;
- **Предыдущие версии и откат**: версии, заменённые обновлением или откатом, хранятся в `bin/.versions/`, не более 3. Если с новой версией проблемы, нажмите «Откатить» в списке; текущая версия тоже сохраняется, так что позже можно переключиться обратно;
- **Удалить**: удаляет установленную в `bin/` программу и все предыдущие версии, настройки модуля сохраняются. Процессы, использующие программу, перезапускаются и берут одноимённую программу из `PATH`, если она там есть; иначе они не смогут работать.

| Программа | Источник | Устанавливаемые файлы |
| --- | --- | --- |
| frp | GitHub fatedier/frp | `frpc`, `frps` |
| cloudflared | GitHub cloudflare/cloudflared | `cloudflared` |
| Tailscale | статические пакеты pkgs.tailscale.com, только Linux | `tailscale`, `tailscaled` |
| FileBrowser Quantum | GitHub gtsteffaniak/filebrowser | `filebrowser` |

Для macOS и Windows готовых к запуску пакетов Tailscale нет: используйте официальный установщик и укажите путь в настройках. Карточка сообщает, если текущая платформа не поддерживается.

## Сброс настроек {#reset}

Кнопка «Сбросить настройки» в заголовке страницы работает отдельно от удаления: она останавливает все процессы модуля, возвращает настройки (включая путь к программе и прокси загрузки) к значениям по умолчанию и удаляет файлы, которые Gately создал для модуля. Установленные программы сохраняются.

| Модуль | Что удаляется |
| --- | --- |
| frp | Все экземпляры frpc / frps, прокси и настройки программ, конфигурационные файлы, созданные в `frp/` |
| Cloudflare Tunnel | Все туннели и настройки программы |
| Tailscale | Все настройки, состояние входа в каталоге состояния по умолчанию; если запущен tailscaled под управлением Gately, сначала выполняется выход. Пользовательские каталоги состояния и уже имеющийся в системе tailscaled остаются нетронутыми |
| File Browser | Все экземпляры и настройки программы, пользователи, ссылки общего доступа и кэши каждого экземпляра; файлы в общих каталогах остаются нетронутыми |

Прежняя конфигурация сохраняется в [истории конфигурации](/ru/docs/guide/audit), и после ошибочного сброса её можно восстановить. Чтобы удалить модуль полностью, сначала удалите программу, затем сбросьте настройки. API: `DELETE /api/{module}/install` (удаление) и `POST /api/{module}/reset` (сброс настроек).

## Размещение программ

Исполняемые файлы ищутся в таком порядке:

1. путь, указанный в настройках модуля;
2. подкаталог `bin/` в каталоге конфигурации (сюда устанавливает онлайн-установка);
3. `PATH`.

Если путь указан, версия, установленная онлайн, не используется; карточка об этом предупреждает. Бинарные файлы можно также положить в каталог конфигурации самостоятельно, при развёртывании в Docker — например, `./gately-data/bin/frpc`. Для Tailscale нужны оба файла: `tailscale` и `tailscaled`; при работе с уже имеющимся в системе tailscaled версия установленной команды `tailscale` должна по возможности совпадать с версией демона.

Токены и ключи хранятся с правами 0600, а токен cloudflared передаётся через переменную окружения и не появляется в списке процессов.

## Tailscale

- Запуск `tailscaled` под управлением Gately (пользовательский сетевой стек, удобно для контейнеров) или подключение к уже работающему в системе демону;
- ключ аутентификации или ссылка для входа, поддерживается Headscale;
- маршруты подсетей и exit-узлы;
- список узлов и прокси SOCKS5;
- фиксированный UDP-порт WireGuard, чтобы открыть его в файрволе для прямых соединений;
- дополнительные параметры tailscaled и переменные окружения. Если iptables на хосте работает на бэкенде nf_tables, добавьте в переменные окружения `TS_DEBUG_FIREWALL_MODE=nftables`, иначе переадресация подсетей не заработает.

## frp

- **Клиент frpc**: можно добавить несколько экземпляров frpc; каждый подключается к одному frps, работает, включается, останавливается и перезапускается независимо. Прокси принадлежат экземпляру и поддерживают tcp / udp / http / https / stcp / xtcp; при изменении прокси перезапускается только его экземпляр;
- **Сервер frps**: можно добавить несколько экземпляров frps на разных портах, у каждого свой белый список портов, поддомены и панель управления;
- **Обновление со старых версий**: единственные настройки frpc / frps из версии 0.5.9 и ранее автоматически переносятся в экземпляры с именами `frpc` / `frps`; существующие прокси принадлежат этому экземпляру frpc, а пути к программам переходят в карточку «Программы» внизу страницы;
- **Адреса прослушивания frps**: «Адрес прослушивания» задаёт, где слушает порт подключения frpc, а «Адрес прослушивания прокси» — где слушают порты HTTP / HTTPS и удалённые порты прокси tcp / udp; пустое значение означает все адреса. Чтобы поставить frps за обратный прокси, например Gately, укажите адрес прослушивания `127.0.0.1`, в веб-сервисе настройте сайт с обратным проксированием на `127.0.0.1:<порт привязки>` и выберите для frpc транспорт websocket или wss с подключением к этому сайту; адрес прослушивания прокси оставьте пустым, чтобы удалённые порты прокси tcp оставались доступны извне. При импорте конфигурации frps без `proxyBindAddr` используется `bindAddr`, как и в самом frps;
- **Контроль доступа frps по IP источника**: для каждого экземпляра frps можно задать белый или чёрный список, который по IP источника решает, может ли frpc войти (подключиться к порту привязки). Список складывается из введённых вручную IP / подсетей и подписных списков IP из веб-сервиса; совпадения с любым достаточно. Подписные списки периодически загружает модуль веб-сервиса; после обновления они действуют сразу, frps продолжает работать, а до первой успешной загрузки список считается пустым. Проверка выполняется до проверки токена во frps: Gately открывает точку проверки на loopback-адресе и дописывает `[[httpPlugins]]` (`ops = ["Login"]`) в конец генерируемой конфигурации frps, поэтому действует только на вход frpc; удалённые порты прокси tcp / udp и порты HTTP / HTTPS остаются открытыми, как раньше. Блокировки защиты от вторжений важнее списка: заблокированный адрес не сможет войти даже из разрешённой подсети, а экземпляры без контроля доступа тоже соблюдают список блокировок, независимо от синхронизации с брандмауэром. Отклонённый frpc получает ошибку вида `gately: client address ... is not in the allowlist`, а карточка экземпляра показывает число отклонённых входов с момента запуска Gately. Если frps стоит за обратным прокси (адрес прослушивания `127.0.0.1`), источником он видит адрес прокси; в этом случае настраивайте контроль доступа по IP на сайте веб-сервиса;
- **Импорт существующей конфигурации**: кнопка «Импорт конфигурации» в шапке страницы поддерживает старые `frpc.ini` / `frps.ini` (с секцией `[common]`) и `toml` из frp 0.52+. Можно выбрать файл или вставить содержимое и импортировать в существующий или новый экземпляр. Сначала показываются результат разбора и пропущенные поля, затем импорт подтверждается. При импорте в существующий экземпляр frpc можно добавить прокси (прокси с тем же именем не меняются) или заменить все прокси этого экземпляра. Существующий экземпляр сохраняет своё состояние, новый создаётся выключенным. Импорт также доступен через API `POST /api/frp/import`. При миграции из Lucky каждый экземпляр frpc / frps из Lucky импортируется как отдельный экземпляр Gately.

## Cloudflare Tunnel

- Туннели с токеном и временные туннели trycloudflare;
- несколько туннелей, автоматический перезапуск;
- отображение публичного адреса.

### Маршруты {#cloudflared-ingress}

Публичные имена хостов и исходные сервисы (маршруты) туннеля с токеном хранятся в Cloudflare, запущенный cloudflared получает их автоматически. Если указать необязательный **API-токен** в настройках туннеля, кнопка «Маршруты» на карточке позволяет редактировать их напрямую:

- Токену нужно право Cloudflare Tunnel: Edit, а для автоматического создания DNS-записей — ещё DNS: Edit для соответствующих зон. Аккаунт и ID туннеля берутся из токена туннеля.
- Каждое правило состоит из имени хоста, необязательного регулярного выражения пути и сервиса (например, `http://localhost:8080`, `ssh://localhost:22` или `http_status:404`). Правила проверяются по порядку, срабатывает первое совпавшее. Можно включить «Не проверять TLS-сертификат источника» и задать заголовок Host для источника; прочие настройки источника сохраняются. Сервис по умолчанию обрабатывает запросы, не подошедшие ни под одно правило; по умолчанию это `http_status:404`.
- Изменения действуют сразу после сохранения, перезапуск туннеля не нужен. Если за это время маршруты изменили в панели Cloudflare или в другом месте, при сохранении появится предупреждение и кнопка «Перезагрузить», чтобы сохранить эти изменения. У HTTP-сервисов не может быть пути: одиночный завершающий `/` (например, `http://nas:5000/`) при сохранении удаляется автоматически, иначе cloudflared отклонит всю конфигурацию.
- Если туннель управляется локальным файлом конфигурации (в окне указано, что удалённые маршруты не действуют), перед сохранением требуется ещё одно подтверждение: после записи удалённой конфигурации туннель переходит на удалённое управление, и маршруты из локального файла конфигурации перестают действовать.
- При включённой синхронизации DNS для каждого имени хоста создаётся проксируемая CNAME-запись на `<ID туннеля>.cfargotunnel.com`; имена хостов, у которых уже есть другие записи или CNAME на туннель без проксирования (трафик тогда не попадает в туннель), сохраняют их и перечисляются в результате. Домены ищутся только в аккаунте, которому принадлежит туннель. При удалении правила его DNS-запись остаётся; при необходимости удалите её в Cloudflare.

## Как выбрать

| Сценарий | Рекомендация |
| --- | --- |
| Частная сеть из нескольких устройств | Tailscale |
| Есть собственный публичный сервер, нужно вывести наружу внутренние сервисы | frp |
| Нет ни публичного IP, ни сервера, нужно быстро открыть веб-сервис | Cloudflare Tunnel |
| Провайдер выдал NAT, поддерживающий hole punching | [STUN-обход NAT](/ru/docs/modules/stun) |
