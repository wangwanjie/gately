# Tailscale / NetBird / frp / cloudflared

Четыре модуля интегрируют официальные программы как управляемые процессы: автоматический перезапуск, сводка журналов в интерфейсе, настройка из интерфейса. Сам Gately эти программы не содержит; их можно установить, обновить и откатить онлайн прямо на странице.

## Онлайн-установка, обновление и откат {#install}

Внизу страниц frp, Cloudflare Tunnel, Tailscale, NetBird и [File Browser](/ru/docs/modules/tools#filebrowser) есть карточка «Онлайн-установка»:

- **Скачать и установить / Обновить до последней**: скачивает из upstream последнюю стабильную версию, проверяет её по SHA-256, опубликованному upstream, убеждается, что она запускается на этой машине, устанавливает в `bin/` каталога конфигурации и затем перезапускает процессы, использующие программу. Если уже установлена последняя версия, повторной загрузки нет;
- **Проверить обновления**: только запрашивает последнюю стабильную версию у первоисточника, ничего не скачивая; если она новее, рядом с заголовком карточки появляется «Новая версия». При включённой [автоматической проверке обновлений](/ru/docs/guide/install#update-check) Gately раз в 12 часов проверяет установленные программы и при новой версии публикует уведомление `program.update`;
- **Установить версию**: укажите номер версии (например, `v0.65.0` для frp, `2025.8.0` для cloudflared, `1.90.2` для Tailscale); подходит и для понижения версии;
- **Прокси загрузки**: задаётся отдельно для каждой программы, поддерживаются http, https и socks5, сохраняется при запуске установки; при пустом значении используется прокси обновлений из «Настроек»;
- **Предыдущие версии и откат**: версии, заменённые обновлением или откатом, хранятся в `bin/.versions/`, не более 3. Если с новой версией проблемы, нажмите «Откатить» в списке; текущая версия тоже сохраняется, так что позже можно переключиться обратно;
- **Удалить**: удаляет установленную в `bin/` программу и все предыдущие версии, настройки модуля сохраняются. Процессы, использующие программу, перезапускаются и берут одноимённую программу из `PATH`, если она там есть; иначе они не смогут работать.

| Программа | Источник | Устанавливаемые файлы |
| --- | --- | --- |
| frp | GitHub fatedier/frp | `frpc`, `frps` |
| cloudflared | GitHub cloudflare/cloudflared | `cloudflared` |
| Tailscale | статические пакеты pkgs.tailscale.com, только Linux | `tailscale`, `tailscaled` |
| NetBird | GitHub netbirdio/netbird, Linux, macOS и Windows | `netbird` |
| FileBrowser Quantum | GitHub gtsteffaniak/filebrowser | `filebrowser` |

Для macOS и Windows готовых к запуску пакетов Tailscale нет: используйте официальный установщик и укажите путь в настройках. Карточка сообщает, если текущая платформа не поддерживается.

## Сброс настроек {#reset}

Кнопка «Сбросить настройки» в заголовке страницы работает отдельно от удаления: она останавливает все процессы модуля, возвращает настройки (включая путь к программе и прокси загрузки) к значениям по умолчанию и удаляет файлы, которые Gately создал для модуля. Установленные программы сохраняются.

| Модуль | Что удаляется |
| --- | --- |
| frp | Все экземпляры frpc / frps, прокси и настройки программ, конфигурационные файлы, созданные в `frp/` |
| Cloudflare Tunnel | Все туннели и настройки программы |
| Tailscale | Все экземпляры и настройки программ, а также состояние входа в каталогах состояния по умолчанию; работающий tailscaled под управлением Gately с каталогом состояния по умолчанию сначала выходит из учётной записи. Пользовательские каталоги состояния и системный tailscaled не затрагиваются |
| NetBird | Все экземпляры и настройки программы, состояние входа и ключи в каталогах состояния по умолчанию; если запущен демон под управлением Gately с каталогом состояния по умолчанию, сначала выполняется выход, и эта машина удаляется из сети. Пользовательские каталоги состояния и уже установленная в системе служба NetBird не затрагиваются |
| File Browser | Все экземпляры и настройки программы, пользователи, ссылки общего доступа и кэши каждого экземпляра; файлы в общих каталогах остаются нетронутыми |

Прежняя конфигурация сохраняется в [истории конфигурации](/ru/docs/guide/audit), и после ошибочного сброса её можно восстановить. Чтобы удалить модуль полностью, сначала удалите программу, затем сбросьте настройки. API: `DELETE /api/{module}/install` (удаление) и `POST /api/{module}/reset` (сброс настроек).

## Размещение программ

Исполняемые файлы ищутся в таком порядке:

1. путь, указанный в настройках модуля;
2. подкаталог `bin/` в каталоге конфигурации (сюда устанавливает онлайн-установка);
3. `PATH`.

Если путь указан, версия, установленная онлайн, не используется; карточка об этом предупреждает. Бинарные файлы можно также положить в каталог конфигурации самостоятельно, при развёртывании в Docker — например, `./gately-data/bin/frpc`. Для Tailscale нужны оба файла: `tailscale` и `tailscaled`; при работе с уже имеющимся в системе tailscaled версия установленной команды `tailscale` должна по возможности совпадать с версией демона.

Токены и ключи хранятся с правами 0600, а токен cloudflared передаётся через переменную окружения и не появляется в списке процессов.

## Tailscale

Поддерживается несколько экземпляров: каждый запускает собственный tailscaled (свой каталог состояния, управляющий сокет, порт WireGuard и процесс), поэтому одна машина может входить в разные tailnet, например экземпляр с TUN ядра для удалённого Headscale и экземпляр в пространстве пользователя для локального.

- Каталог состояния нового экземпляра по умолчанию — `tailscale/<ключ экземпляра>` в каталоге конфигурации; можно указать существующий каталог состояния (например, тот, что монтировал прежний контейнер tailscale), чтобы сохранить идентичность узла без повторной регистрации;
- Одновременно может быть включён не более одного экземпляра в режиме ядра (управляемого и без сети в пространстве пользователя): tailscaled использует фиксированные таблицу маршрутизации и метку брандмауэра, и два таких экземпляра перезаписывали бы друг друга. Управляющий сокет, каталог состояния и фиксированный порт WireGuard также не могут использоваться двумя экземплярами; при сохранении или включении сообщается о конфликте;
- Изменение, включение или выключение экземпляра перезапускает только его tailscaled, а источник в журнале содержит имя экземпляра (например, `tailscaled:home`);
- При обновлении с 0.6.4 и более ранних версий прежняя единственная конфигурация переносится в экземпляр с именем `tailscale`, каталог состояния, управляющий сокет и параметры запуска не меняются;
- Пути к программам (tailscaled, tailscale) и онлайн-установка общие для всех экземпляров.

Каждый экземпляр поддерживает:

- Запуск `tailscaled` под управлением Gately (пользовательский сетевой стек, удобно для контейнеров) или подключение к уже работающему в системе демону;
- ключ аутентификации или ссылка для входа, поддерживается Headscale;
- маршруты подсетей и exit-узлы;
- список узлов и прокси SOCKS5. У прокси нет аутентификации, поэтому интерфейс предупреждает, если адрес прослушивания доступен за пределами этой машины (например, `0.0.0.0` или IP в локальной сети); рекомендуется слушать только `127.0.0.1`;
- фиксированный UDP-порт WireGuard, чтобы открыть его в файрволе для прямых соединений;
- дополнительные параметры tailscaled и переменные окружения. Если iptables на хосте работает на бэкенде nf_tables, добавьте в переменные окружения `TS_DEBUG_FIREWALL_MODE=nftables`, иначе переадресация подсетей не заработает.

## NetBird

Поддерживается несколько экземпляров: каждый экземпляр запускает собственный демон NetBird (отдельные каталог состояния, адрес демона, порт WireGuard и процесс), поэтому одна машина может подключаться к разным сетям NetBird, например экземпляр в режиме ядра — к NetBird Cloud, а экземпляр в пространстве пользователя — к собственному серверу управления.

- Каталог состояния нового экземпляра по умолчанию — `netbird/<ключ экземпляра>` в каталоге конфигурации, адрес демона — `netbird.sock` в каталоге состояния; можно указать существующий каталог состояния (например, `/var/lib/netbird`, который монтировал прежний контейнер NetBird), чтобы сохранить идентичность узла без повторной регистрации;
- Одновременно может быть включён только один экземпляр в режиме ядра (управляемый, без сети в пространстве пользователя): режим ядра NetBird использует фиксированные таблицу маршрутизации, метку брандмауэра и таблицу nftables, а имя интерфейса по умолчанию всегда `wt0`, поэтому два экземпляра в режиме ядра перезаписывали бы друг друга. Два экземпляра не могут использовать общий каталог состояния или адрес демона; управляемые экземпляры не могут использовать один и тот же порт WireGuard (0 считается портом по умолчанию 51820, а при занятом порте NetBird молча переходит на случайный); управляемые экземпляры в пространстве пользователя не могут использовать один и тот же адрес SOCKS5 (пустое значение считается `127.0.0.1:1080`). При сохранении, включении, групповом включении и копировании сообщается о конфликте, а в вручную изменённой конфигурации с конфликтом последующий конфликтующий экземпляр не запускается и показывает причину;
- Изменение, включение или отключение экземпляра перезапускает только его собственный демон, а источники журнала содержат имя экземпляра (например, `daemon:дом` и `netbird:дом`); ссылка для входа, код устройства, список узлов и выход также показываются для каждого экземпляра;
- При удалении управляемого экземпляра с каталогом состояния по умолчанию сначала выполняется выход, затем этот каталог удаляется; пользовательские каталоги состояния и перенесённый старый каталог сохраняются, чтобы их мог использовать новый экземпляр;
- При обновлении с 0.6.4 и более ранних версий прежняя единая конфигурация переносится в экземпляр с именем `netbird`; каталог состояния (`netbird` в каталоге конфигурации), адрес демона, командная строка и переменные окружения не меняются;
- Путь к программе и онлайн-установка общие для всех экземпляров.

Каждый экземпляр поддерживает:

- Подключение к сети NetBird в NetBird Cloud или на собственном сервере управления (укажите его адрес);
- Аутентификация по ключу настройки или по ссылке входа. В Linux ссылка использует вход по коду устройства и открывается на любом устройстве; в macOS и Windows вход обычно можно завершить только в браузере на машине, где работает Gately, поэтому для удалённого управления используйте ключ настройки. По истечении срока ссылка обновляется автоматически;
- Управляемый демон `netbird` (сеть в пространстве пользователя, подходит для контейнеров) или подключение к уже установленной в системе службе NetBird;
- В сети пространства пользователя другие узлы по умолчанию могут обращаться к службам этой машины (включая службы, слушающие только 127.0.0.1; политики доступа сервера управления по-прежнему действуют), а локальные программы обращаются к устройствам сети через прокси SOCKS5 (по умолчанию `127.0.0.1:1080`);
- у прокси SOCKS5 нет аутентификации, и интерфейс предупреждает, если адрес прослушивания доступен за пределами этой машины. NetBird до версии 0.75 в сети пространства пользователя игнорирует заданный адрес и всегда открывает прокси SOCKS5 без аутентификации на `0.0.0.0`, через который другие устройства могут попасть в сеть; если Gately управляет демоном и обнаруживает такую версию, он пишет предупреждение в журнал. Обновитесь до 0.75 или новее;
- Сетевые маршруты, выходные узлы и политики доступа настраиваются в панели NetBird; в Gately выбирается, принимать ли маршруты, работать ли маршрутизирующим узлом, принимать ли DNS и блокировать ли входящие подключения;
- Список узлов с прямым подключением или через ретранслятор, задержкой и сетевыми маршрутами;
- Фиксированный порт WireGuard, дополнительные аргументы демона и переменные окружения (расширенные параметры `NB_` из документации NetBird);
- Без сети в пространстве пользователя используется WireGuard ядра: нужны root и устройство TUN, создаётся интерфейс `wt0` и добавляются собственные правила брандмауэра (в OpenWrt входящий трафик `wt0` также разрешается в fw4), а локальные службы должны слушать на всех адресах или на адресе NetBird, чтобы другие узлы могли к ним обращаться;
- Программа `netbird` занимает около 41 МБ и использует около 60 МБ памяти, а онлайн-установка хранит до 3 старых версий в `bin/.versions/`. На маршрутизаторах с небольшой флеш-памятью следите за свободным местом: удаляйте старые версии в карточке установки или разместите программу на внешнем накопителе и укажите путь в настройках;
- Сброс настроек и `POST /api/netbird/instances/{key}/logout` снимают эту машину с регистрации на сервере управления и удаляют её из сети; для повторного подключения нужна новая аутентификация.

## frp

- **Клиент frpc**: можно добавить несколько экземпляров frpc; каждый подключается к одному frps, работает, включается, останавливается и перезапускается независимо. Прокси принадлежат экземпляру и поддерживают tcp / udp / http / https / stcp / xtcp; при изменении прокси перезапускается только его экземпляр;
- **Адрес доступа прокси**: frpc не знает HTTP- / HTTPS-порты и корневой домен поддоменов frps, поэтому укажите их в поле **Адрес доступа** экземпляра frpc (одним щелчком можно взять их из локального экземпляра frps; если перед frps стоит обратный прокси или CDN, укажите схему и порт, которыми пользуются посетители). Тогда домены http / https-прокси, включая полное имя из поддомена, открываются по щелчку, а их полные ссылки можно скопировать; без этого они остаются текстом. Адрес доступа влияет только на ссылки, его изменение не перезапускает frpc. Пользовательские домены, как и в веб-сервисах, сохраняются в нижнем регистре и в punycode, значения с портом или путём отклоняются; поддомен, как требует frps, — один уровень, например `nas`;
- **Сервер frps**: можно добавить несколько экземпляров frps на разных портах, у каждого свой белый список портов, поддомены и панель управления;
- **Обновление со старых версий**: единственные настройки frpc / frps из версии 0.5.9 и ранее автоматически переносятся в экземпляры с именами `frpc` / `frps`; существующие прокси принадлежат этому экземпляру frpc, а пути к программам переходят в карточку «Программы» внизу страницы;
- **Адреса прослушивания frps**: «Адрес прослушивания» задаёт, где слушает порт подключения frpc, а «Адрес прослушивания прокси» — где слушают порты HTTP / HTTPS и удалённые порты прокси tcp / udp; пустое значение означает все адреса. Чтобы поставить frps за обратный прокси, например Gately, укажите адрес прослушивания `127.0.0.1`, в веб-сервисе настройте сайт с обратным проксированием на `127.0.0.1:<порт привязки>` и выберите для frpc транспорт websocket или wss с подключением к этому сайту; адрес прослушивания прокси оставьте пустым, чтобы удалённые порты прокси tcp оставались доступны извне. При импорте конфигурации frps без `proxyBindAddr` используется `bindAddr`, как и в самом frps;
- **Контроль доступа frps по IP источника**: для каждого экземпляра frps можно задать белый или чёрный список, который по IP источника решает, может ли frpc войти (подключиться к порту привязки). Список складывается из введённых вручную IP / подсетей и подписных списков IP из веб-сервиса; совпадения с любым достаточно. Подписные списки периодически загружает модуль веб-сервиса; после обновления они действуют сразу, frps продолжает работать, а до первой успешной загрузки список считается пустым. Проверка выполняется до проверки токена во frps: Gately открывает точку проверки на loopback-адресе и дописывает `[[httpPlugins]]` (`ops = ["Login"]`) в конец генерируемой конфигурации frps, поэтому действует только на вход frpc; удалённые порты прокси tcp / udp и порты HTTP / HTTPS остаются открытыми, как раньше. Блокировки защиты от вторжений важнее списка: заблокированный адрес не сможет войти даже из разрешённой подсети, а экземпляры без контроля доступа тоже соблюдают список блокировок, независимо от синхронизации с брандмауэром. Отклонённый frpc получает ошибку вида `gately: client address ... is not in the allowlist`, а карточка экземпляра показывает число отклонённых входов с момента запуска Gately. Список проверяется при входе frpc и действует на подключения frpc к порту привязки frps: после ужесточения списка или блокировки адреса уже вошедший frpc остаётся подключённым и получает отказ только при следующем входе; чтобы изменения подействовали сразу, перезапустите этот экземпляр frps. Подключения visitor для stcp / xtcp не проходят проверку входа; чтобы ограничить их, используйте синхронизацию с брандмауэром в [защите от вторжений](/ru/docs/modules/guard). Если frps стоит за обратным прокси (адрес прослушивания `127.0.0.1`), источником он видит адрес прокси; в этом случае настраивайте контроль доступа по IP на сайте веб-сервиса; за маршрутизацией по протоколу или пробросом портов frps видит локальный адрес и список не может различать посетителей, поэтому настраивайте контроль доступа по IP источника в правиле маршрутизации или проброса;
- **Импорт существующей конфигурации**: кнопка «Импорт конфигурации» в шапке страницы поддерживает старые `frpc.ini` / `frps.ini` (с секцией `[common]`) и `toml` из frp 0.52+. Можно выбрать файл или вставить содержимое и импортировать в существующий или новый экземпляр. Сначала показываются результат разбора и пропущенные поля, затем импорт подтверждается. При импорте в существующий экземпляр frpc можно добавить прокси (прокси с тем же именем не меняются) или заменить все прокси этого экземпляра. Существующий экземпляр сохраняет своё состояние, новый создаётся выключенным. Импорт также доступен через API `POST /api/frp/import`. При миграции из Lucky каждый экземпляр frpc / frps из Lucky импортируется как отдельный экземпляр Gately.

## Cloudflare Tunnel

- Туннели с токеном и временные туннели trycloudflare;
- несколько туннелей, автоматический перезапуск;
- отображение публичного адреса.

### Маршруты {#cloudflared-ingress}

Публичные имена хостов и исходные сервисы (маршруты) туннеля с токеном хранятся в Cloudflare, запущенный cloudflared получает их автоматически. Если указать необязательный **API-токен** в настройках туннеля, кнопка «Маршруты» на карточке позволяет редактировать их напрямую:

- Токену нужно право Cloudflare Tunnel: Edit, а для автоматического создания DNS-записей — ещё DNS: Edit для соответствующих зон. Аккаунт и ID туннеля берутся из токена туннеля.
- Каждое правило состоит из имени хоста, необязательного регулярного выражения пути и сервиса (например, `http://localhost:8080`, `ssh://localhost:22` или `http_status:404`). Правила проверяются по порядку, срабатывает первое совпавшее. Можно включить «Не проверять TLS-сертификат источника» и задать заголовок Host для источника; прочие настройки источника сохраняются. Сервис по умолчанию обрабатывает запросы, не подошедшие ни под одно правило; по умолчанию это `http_status:404`.
- Изменения действуют сразу после сохранения, перезапуск туннеля не нужен. Если за это время маршруты изменили в панели Cloudflare или в другом месте, при сохранении появится предупреждение и кнопка «Перезагрузить», чтобы сохранить эти изменения. У HTTP-сервисов не может быть пути: одиночный завершающий `/` (например, `http://nas:5000/`) при сохранении удаляется автоматически, иначе cloudflared отклонит всю конфигурацию.
- Если туннель управляется локальным файлом конфигурации (в окне указано, что удалённые маршруты не действуют), перед сохранением требуется ещё одно подтверждение: после записи удалённой конфигурации туннель переходит на удалённое управление, и маршруты из локального файла конфигурации перестают действовать.
- При включённой синхронизации DNS для каждого имени хоста создаётся проксируемая CNAME-запись на `<ID туннеля>.cfargotunnel.com`; имена хостов, у которых уже есть другие записи или CNAME на туннель без проксирования (трафик тогда не попадает в туннель), сохраняют их и перечисляются в результате. Домены ищутся только в аккаунте, которому принадлежит туннель. При удалении правила его DNS-запись остаётся; при необходимости удалите её в Cloudflare.

## Как выбрать

| Сценарий | Рекомендация |
| --- | --- |
| Частная сеть из нескольких устройств | Tailscale |
