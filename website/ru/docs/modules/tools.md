# Файлы и инструменты администрирования

## WebDAV

Настраивается в боковой панели: группа «Файловые сервисы» → «WebDAV-сервер».

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `enable` | выключено | Включить службу; при включении нужен хотя бы один пользователь |
| `listenIp` | пусто | Адрес прослушивания; если пусто, прослушиваются все адреса |
| `port` | 18800 | Порт прослушивания |
| `tls` | выключено | Включить HTTPS; сертификат выдаёт модуль [SSL-сертификаты](/ru/docs/modules/ssl) по SNI |
| `users` | нет | Несколько пользователей; у каждого есть `name`, `password`, `root` (каталог с абсолютным путём) и `readOnly`, либо несколько каталогов через `mounts` |
| `sharedUsers` | выключено | Разрешает [общим пользователям](#shared-users) входить в эту службу |

Каждому пользователю можно сопоставить один каталог или смонтировать несколько:

- **Один каталог**: заполните `root` и `readOnly`; после входа корнем служит этот каталог.
- **Несколько каталогов**: нажмите в интерфейсе «Смонтировать несколько каталогов» или заполните несколько элементов в `mounts`; каждый элемент содержит `name` (отображаемое имя, без `/`, уникальное в пределах пользователя), `path` (абсолютный путь) и `readOnly`. После входа в корне перечислены каталоги по именам; в сам корень писать нельзя, а файлы нельзя перемещать между разными каталогами.

## FTP

Настраивается в группе «Файловые сервисы» → «FTP-сервер»; поддерживаются FTP и FTPS.

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `enable` | выключено | Включить службу; при включении нужен хотя бы один пользователь |
| `listenIp` | пусто | Адрес прослушивания; если пусто, прослушиваются все адреса |
| `port` | 2121 | Порт прослушивания |
| `passiveStart` / `passiveEnd` | 0 | Диапазон портов данных пассивного режима; если оба равны 0, порты выбирает система случайным образом; при заполнении должно выполняться 1 ≤ начало ≤ конец ≤ 65535, а диапазон нужно открыть в файрволе и пробросе портов |
| `publicHost` | пусто | IP, который объявляется клиентам в пассивном режиме; за NAT укажите публичный или проброшенный IP, поддерживаются только IP-адреса, если оставить пустым, берётся адрес подключения |
| `tlsMode` | 0 | 0 — допускаются и открытый текст, и FTPS; 1 — обязателен явный FTPS (`AUTH TLS`); 2 — неявный FTPS (соединение шифруется сразу); при значении не 0 сертификат выдаёт модуль [SSL-сертификаты](/ru/docs/modules/ssl) по SNI |
| `idleTimeout` | 900 | Через сколько секунд простоя соединение закрывается |
| `connectionTimeout` | 30 | Таймаут установки соединения для данных, в секундах |
| `disableActiveMode` | выключено | Использовать только пассивный режим, лучше подходит для сред с NAT |
| `users` | нет | Несколько пользователей, поля как у WebDAV: `name`, `password`, `root`, `readOnly` или `mounts`; имена пользователей не должны повторяться |
| `sharedUsers` | выключено | Разрешает [общим пользователям](#shared-users) входить в эту службу |

## SMB

Настраивается в группе «Файловые сервисы» → «SMB-сервер» и открывает общий доступ к локальным каталогам для Проводника Windows, Finder в macOS, Linux, а также SMB-клиентов на телефонах и телевизорах. Реализация протокола встроена в Gately (на основе [gosamba](https://github.com/ahmetozer/gosamba)) и поддерживает SMB 2.0.2–3.1.1, аутентификацию NTLMv2 и подпись, а также обязательное шифрование SMB 3 по выбору; SMB 1 не поддерживается. Доступно только в Linux и macOS.

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `enable` | выключено | Включить службу; при включении нужен хотя бы один пользователь |
| `listenIp` | пусто | Адрес прослушивания; если пусто, прослушиваются все адреса |
| `port` | 445 | Порт прослушивания. Windows подключается только к 445; если порт 445 уже занят встроенным Samba на NAS вроде fnOS или Synology, выберите другой порт — macOS, Linux и большинство плееров позволяют указать его в адресе |
| `requireEncryption` | выключено | Требовать шифрование SMB 3 для всех подключений; старые устройства и некоторые телевизоры, поддерживающие только SMB 2, не смогут подключиться |
| `mdns` | выключено | Объявлять службу через Bonjour, чтобы она появилась в разделе «Сеть» Finder в macOS; в Docker работает только с сетью host |
| `users` | нет | Несколько пользователей с теми же полями, что и у WebDAV: `name`, `password`, `root`, `readOnly` или `mounts`; имена пользователей не зависят от регистра и не должны повторяться |
| `sharedUsers` | выключено | Разрешает [общим пользователям](#shared-users) входить в эту службу |

Общие ресурсы принадлежат пользователям; вошедший пользователь видит и подключает только свои ресурсы:

- **Один каталог**: ресурс называется именем пользователя, например `\\192.168.1.2\alice` для пользователя `alice`.
- **Несколько каталогов**: каждый каталог — отдельный ресурс с именем `name` (уникальным в пределах пользователя без учёта регистра), каждый можно сделать доступным только для чтения. У разных пользователей могут быть ресурсы с одинаковым именем, указывающие на их собственные каталоги.

Имена пользователей и ресурсов не могут содержать `" / \ [ ] : ; | = , + * ? < >`, а также начинаться или заканчиваться на `.`. Для аутентификации NTLM нужен пароль в открытом виде, поэтому пользователям, у которых пароль сохранён как хеш bcrypt, нужно задать его заново. Файлы читаются и записываются от имени процесса Gately.

Раздел «Адреса подключения» внизу страницы показывает адрес каждого ресурса по сохранённым настройкам:

- Windows: введите `\\узел\ресурс` в адресной строке Проводника или выполните `net use Z: \\узел\ресурс /user:пользователь`
- macOS: в Finder выберите «Переход → Подключение к серверу» и введите `smb://узел:порт/ресурс` (для 445 порт можно не указывать)
- Linux: `mount -t cifs //узел/ресурс /mnt -o username=пользователь,port=порт`

Если клиенты не подключаются или не проходят аутентификацию, задайте переменную окружения `GATELY_SMB_DEBUG=1` и перезапустите Gately: отладочные журналы протокола будут записываться в журнал работы. После диагностики уберите переменную.

## Общие пользователи {#shared-users}

WebDAV, FTP и SMB используют один список «общих пользователей» с теми же полями, что и у локальных пользователей каждой службы (имя, пароль, `root` и `readOnly` или `mounts`); он хранится в `fileusers.json` в каталоге конфигурации. Общие пользователи настраиваются на странице «Общие пользователи файлов» в группе «Файловые сервисы» боковой панели, и после сохранения изменения действуют во всех трёх службах; локальные пользователи служб не меняются. Вверху страницы видно, разрешает ли каждая служба общих пользователей, а также общие пользователи с тем же именем, что у локального, или непригодные для SMB.

- Каждая служба сама решает, принимать ли общих пользователей: включите «Разрешить общих пользователей» в карточке «Общие пользователи» на странице службы (поле `sharedUsers`) и сохраните, после чего общие пользователи смогут входить в эту службу; карточка также показывает сохранённых общих пользователей, а кнопка «Управлять общими пользователями» открывает страницу «Общие пользователи файлов»;
- Если есть локальный пользователь с таким же именем, проверяется только он (для SMB без учёта регистра);
- Имена общих пользователей не должны повторяться без учёта регистра и не могут содержать двоеточие;
- Изменения применяются сразу: WebDAV проверяет новые настройки со следующего запроса, FTP и SMB перезапускаются, и подключённым клиентам нужно переподключиться;
- Если переключатель включён и есть хотя бы один общий пользователь, службу можно включить без локальных пользователей;
- Если служба включена только с общими пользователями, после изменения у неё должен остаться общий пользователь, способный войти (для SMB — пригодный для SMB), иначе изменение отклоняется;
- Если `fileusers.json` испорчен вручную (например, пустой пароль или каталог не абсолютным путём), ни один общий пользователь не может войти, а на странице появляется предупреждение; исправьте и сохраните, чтобы восстановить доступ;
- SMB принимает только пароли в открытом виде, а имена пользователей и ресурсов должны соответствовать правилам SMB; общие пользователи, которые им не соответствуют, отмечаются на странице «Общие пользователи файлов», на странице SMB и в журнале работы и пропускаются, при этом WebDAV и FTP могут их использовать.

API — `GET` / `PUT /api/fileusers`; API-токену нужны права `fileusers:read` / `fileusers:write`, а поле `services` в ответе показывает, как их использует каждая служба. Прежние `GET` / `PUT /api/<служба>/shared-users` каждой службы устарели, но продолжают работать и читают и записывают тот же список: для чтения нужно право чтения этой службы, для изменения — одновременно `webdav:write`, `ftp:write` и `smb:write`.

**Самостоятельная смена пароля**: включите «Самостоятельная смена пароля» на странице «Общие пользователи файлов» и сохраните; общие пользователи смогут сменить пароль на странице `https://домен-сайта/__gately_auth/password` любого сайта веб-сервиса с веб-аутентификацией, указав имя пользователя, текущий и новый пароль (от 8 до 128 символов). WebDAV, FTP и SMB сразу используют новый пароль (FTP и SMB перезапускаются, подключённым клиентам нужно переподключиться). Пароли в открытом виде остаются в открытом виде, хэши bcrypt — хэшами; неверный текущий пароль учитывается в том же ограничении попыток и автоматической блокировке, что и веб-вход. Переключатель хранится в поле `selfService` файла `fileusers.json`, в API поле называется так же. Об общих пользователях веб-входа см. [самостоятельную смену пароля в веб-сервисе](/ru/docs/modules/web#self-service-password).

## File Browser {#filebrowser}

Настраивается в разделе «File Browser» группы «Файловые сервисы». Gately запускает [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser) — веб-файловый менеджер с предпросмотром изображений, видео и документов, загрузкой и скачиванием файлов, ссылками общего доступа и собственными пользователями и правами. Оригинальный filebrowser/filebrowser архивирован в 2026 году и больше не получает исправлений безопасности, поэтому Gately использует поддерживаемый форк Quantum.

Программа не входит в состав Gately. Карточка «Онлайн-установка» внизу страницы загружает FileBrowser Quantum с GitHub в `bin/filebrowser` каталога конфигурации и поддерживает обновление, установку указанной версии, отдельный прокси загрузки, откат и удаление; после обновления или отката включённые экземпляры перезапускаются автоматически. Подробнее — в разделе [Онлайн-установка, обновление и откат](/ru/docs/modules/tunnels#install). Кнопка «Сбросить настройки» в заголовке страницы удаляет все экземпляры вместе с их данными, см. [Сброс настроек](/ru/docs/modules/tunnels#reset). Программу можно также разместить самостоятельно и указать её путь. Поиск идёт в таком порядке: указанный путь, `bin/` каталога конфигурации, затем `PATH`; если найденная программа — не Quantum (например, оригинал в `PATH`), страница предупреждает об этом.

Каждый экземпляр — отдельный процесс File Browser:

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `listenIp` | пусто | Адрес прослушивания; пусто — все IPv4-адреса. Укажите `127.0.0.1`, если доступ идёт только через обратный прокси веб-службы |
| `port` | 8080 | Порт прослушивания |
| `baseUrl` | `/` | Базовый путь; при обратном проксировании по пути в веб-службе (например, `/files`) укажите тот же путь |
| `accessUrls` | пусто | Адреса доступа, можно несколько, например `https://files.example.com/` за обратным прокси веб-службы; показываются на карточке экземпляра. Если пусто, адрес определяется по адресу и порту прослушивания. Схема, хост и порт первого адреса записываются в `http.externalUrl` File Browser, его используют ссылки общего доступа |
| `sources` | нет | Общие каталоги, каждый с `path` (абсолютный путь), `name` (отображаемое имя, по умолчанию имя каталога) и `readOnly`; новые пользователи по умолчанию имеют доступ ко всем |
| `authMethod` | `password` | Вход: `password` по паролю, `proxy` — доверие заголовку с именем пользователя от обратного прокси, `noauth` — без входа |
| `proxyHeader` | `Remote-User` | Заголовок с именем пользователя для `proxy`; отсутствующие пользователи создаются автоматически |
| `adminUser` | `admin` | Имя администратора |
| `adminPassword` | нет | Пароль администратора, не менее 8 символов, обязателен для `password` |
| `trustProxyHeaders` | выкл. | Доверять `X-Forwarded-*` и `X-Real-IP`; включайте за обратным прокси |
| `disableWebDav` | выкл. | Отключает встроенный в File Browser интерфейс WebDAV |
| `locale` | пусто | Язык интерфейса для новых пользователей, например `ru`; пусто — английский |
| `tokenHours` | 2 | Срок действия сеанса в часах |

- Пароль администратора синхронизируется с File Browser при каждом запуске, поэтому действует значение из Gately; остальные пользователи, ссылки общего доступа и личные настройки управляются в File Browser и хранятся в базе данных экземпляра.
- Файл конфигурации, база данных и кэш хранятся в `filebrowser/<ключ экземпляра>/` каталога конфигурации, файл конфигурации — с правами 0600; пароль администратора передаётся процессу через переменную окружения и не записывается в файлы. При удалении экземпляра этот каталог удаляется, а файлы в общих каталогах остаются на месте.
- Экземпляр, общий каталог которого не существует, не запускается, а на карточке показана причина.
- Для доступа извне рекомендуется добавить в [веб-службе](/ru/docs/modules/web) сайт обратного прокси на `http://127.0.0.1:порт`, защитить его HTTPS и контролем доступа и включить «Доверять заголовкам прокси». Способ `proxy` требует внешней аутентификации веб-службы, которая передаёт имя пользователя в заголовке, а порт File Browser должен оставаться закрытым снаружи, иначе заголовок можно подделать для входа.
- Файлы читаются и записываются от имени процесса Gately.

## Монтирование хранилищ

В группе «Файловые сервисы» → «Монтирование хранилищ» добавляются точки монтирования, а файлами можно управлять прямо на странице.

| Поле | Описание |
| --- | --- |
| `name`, `remark`, `enable` | Название, заметка и переключатель включения |
| `type` | `local` (локальный каталог), `webdav` (удалённый WebDAV) или `smb` (общая папка SMB) |
| `path` | Локальный каталог, должен быть существующим абсолютным путём (для `local`) |
| `url`, `username`, `password` | Удалённый адрес и учётная запись; пароль в интерфейсе маскируется (для `webdav` и `smb`). Адрес WebDAV начинается с `http://` или `https://`; адрес SMB имеет вид `smb://хост[:порт]/папка[/подкаталог]`, поддерживается SMB2/3, без имени пользователя подключение выполняется как гость |
| `skipVerify` | Пропускать проверку сертификата HTTPS (для `webdav`) |
| `domain` | Домен или рабочая группа для аутентификации SMB, обычно пусто (для `smb`) |
| `readOnly` | Монтирование только для чтения, файловый менеджер отклоняет любые операции записи |

Онлайн-файловый менеджер позволяет просматривать каталоги, скачивать файлы, загружать файлы потоком (без загрузки всего файла в память), создавать каталоги, переименовывать и удалять. Точки монтирования можно использовать как назначение заданий резервного копирования: файлы копий записываются в указанный каталог точки монтирования, а старые удаляются согласно политике хранения.

## Wake-on-LAN

В разделе «Wake-on-LAN» управляются устройства; на устройство отправляется magic-пакет (6 байт `0xFF`, затем 16 повторов MAC).

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `name` | нет | Название устройства, обязательно |
| `macs` | нет | MAC-адреса, по одному в строке, минимум один; для одного устройства можно указать несколько |
| `broadcastIps` | пусто | Широковещательные адреса IPv4; если пусто, отправка идёт на `255.255.255.255` и на широковещательные адреса всех включённых сетевых интерфейсов |
| `port` | 9 | Целевой порт UDP |
| `repeat` | 3 | Сколько раз повторять отправку для каждого MAC, не более 20 |
| `checkAddr` | пусто | Адрес проверки доступности в формате `хост:порт`, например `192.168.1.10:3389`; если пусто, проверка не выполняется |
| `shutdownConn` | Пусто | SSH-подключение [веб-терминала](/ru/docs/modules/terminal) для удалённого выключения; пусто — без выключения |
| `shutdownCommand` | Нет | Команда выключения, обязательна при выбранном подключении, одна строка, например `shutdown -h now` или `shutdown /s /t 0` |
| `bemfaTopic` | Пусто | Топик Bemfa; пусто — без голосового управления; не может повторяться у разных устройств |
| `remark` | пусто | Заметка |

Нажатие кнопки пробуждения в списке устройств отправляет magic-пакет, а по `checkAddr` показывается, в сети ли устройство.

### Удалённое выключение

Выберите SSH-подключение из веб-терминала и укажите команду выключения — на карточке устройства появится кнопка *Выключить*; API: `POST /api/wol/devices/{key}/shutdown`.

- К подключению нужно один раз подключиться в веб-терминале, чтобы записать ключ хоста; без участия пользователя Gately не доверяет неизвестным хостам;
- Каждое выключение открывает новое SSH-подключение и закрывает его после выполнения, поэтому устаревшее подключение, оставшееся до перезагрузки устройства, не используется; команда выполняется не дольше 30 секунд и только одна одновременно для устройства;
- При выключении SSH-соединение часто обрывается до возврата кода завершения; это считается началом выключения;
- В форме есть типовые команды для Linux (`shutdown -h now`), Windows (`shutdown /s /t 0`) и macOS (`sudo -n shutdown -h now`). В Windows нужен включённый сервер OpenSSH; в Linux пользователь без root может использовать `sudo -n shutdown -h now` с sudo без пароля для этой команды.
- API-токенам для создания, изменения и копирования устройств или запуска выключения помимо `wol:write` нужно `webterminal:write` (эти действия задают или выполняют команды через SSH-подключение); для списка доступных SSH-подключений нужны `wol:read` и `webterminal:read`.

### Голосовое управление Bemfa {#bemfa}

После подключения [Bemfa](https://cloud.bemfa.com) голосовые помощники вроде Xiao AI, Xiaodu и Google Assistant могут включать и выключать устройства:

1. В консоли Bemfa создайте топик в облаке MQTT-устройств, имя которого оканчивается на `001` (розетка) или `006` (выключатель), например `pc001`;
2. Укажите тот же топик у устройства, а в разделе *Wake-on-LAN → Bemfa* — закрытый ключ пользователя из консоли, и включите интеграцию;
3. Привяжите аккаунт Bemfa в Mi Home (Xiao AI), Xiaodu или Google Home и синхронизируйте устройства.

После этого «включить» будит устройство, а «выключить» выключает его (нужно настроить удалённое выключение); после успешного действия состояние записывается обратно в Bemfa. Gately подключается к `bemfa.com:9503` по MQTT 3.1.1 поверх TLS с проверкой сертификата; закрытый ключ служит идентификатором клиента, используется только в этом зашифрованном соединении и маскируется в API. После обрыва повторные попытки идут с интервалом от 5 секунд до 5 минут; прошлое состояние, которое сервер повторяет при подписке (сохранённые сообщения и всё, что пришло в течение 3 секунд после подписки), не выполняется, а одна и та же команда в течение 10 секунд выполняется один раз; успешное включение или выключение из интерфейса или API тоже записывает состояние обратно. С одним закрытым ключом онлайн может быть только один клиент: если другая программа или другой Gately подключится с тем же ключом, они будут выбивать друг друга.

## Запланированные задачи

Выполняют команды или HTTP-запросы по cron-выражению.

- `spec` поддерживает стандартное выражение из 5 полей, необязательное поле секунд (6 полей, например `*/30 * * * * *`) и дескрипторы `@every 10m`, `@daily` и т. п.;
- при `type` равном `command` команда `command` выполняется через `sh -c` (в Windows — через временный `.bat`), в переменные окружения добавляются `taskName` и одноимённая переменная в верхнем регистре с префиксом `GATELY_`;
- при `type` равном `http` запрос выполняется согласно конфигурации `http`; поля: `url`, `method` (GET, POST, PUT, PATCH, DELETE), `headers` (каждый элемент в формате `Key: Value`), `body`, `successContent` (для успеха тело ответа должно содержать любой из элементов; если пусто, проверяется только 2xx), `timeout`, `insecureSkipVerify` и `proxy` (пусто — без прокси, `update` — глобальный прокси обновлений, либо адрес прокси с `http://`, `https://` или `socks5://`);
- Задания можно включать и отключать, на странице отображается время следующего запуска, задание можно немедленно запустить вручную;
- Если предыдущий запуск того же задания ещё не завершён, текущий пропускается;
- Для каждого задания хранятся последние 20 записей выполнения: время начала, длительность, успех, был ли запуск ручным, а также вывод (сводка до 4000 символов);
- Форма создания проверяет выражение при вводе.

## Обзор и системные журналы

- Страница «Обзор» показывает сведения о хосте: модель, загрузку и нагрузку CPU, память, диски, адреса сетевых интерфейсов и текущую скорость, публичные IPv4 и IPv6 (копируются по нажатию), состояние служб модулей, а также версию, коммит, время сборки, время запуска, PID, CPU, резидентную память, кучу Go и число горутин процесса Gately;
- Если Gately управляет внешними программами (frp, Tailscale, NetBird, туннель Cloudflare, File Browser), на странице «Обзор» есть ещё карточка «Управляемые процессы»: для каждого процесса показаны модуль и экземпляр, имя программы, PID, время работы, число перезапусков, CPU и резидентная память, а в заголовке карточки — суммы; нажатие на строку открывает модуль. Учитывается только сам процесс без запущенных им дочерних, пути и аргументы запуска не показываются;
- Страница «Системные журналы» собирает журналы всех модулей, в том числе записи Docker, FTP, запланированных задач и других модулей.

## Темы

В интерфейсе 15 палитр в двух группах — оригинальные Gately (Изумруд, Океан, Свежесть, Сакура, Закат, Полночь, Панк) и классические (GitHub, Nord, Dracula, Catppuccin, Tokyo Night, Gruvbox, Rosé Pine, Solarized), и у каждой палитры есть светлый и тёмный вариант. Режим можно выбрать светлый, тёмный или «Как в системе» — тогда используется светлый или тёмный вариант текущей палитры. Для любой палитры можно задать один из 10 готовых акцентных цветов или цвет из системной палитры, и логотип с градиентом страницы входа меняются вместе с ним; повторный выбор палитры сбрасывает свой акцент. Углы бывают прямыми, как в палитре или скруглёнными. Настройки темы хранятся локально в браузере.
