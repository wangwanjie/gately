## Wake-on-LAN : arrêt à distance

Choisissez pour un appareil une connexion SSH du terminal Web et saisissez une commande d’arrêt : la carte de l’appareil affiche alors un bouton « Éteindre » (API `POST /api/wol/devices/{key}/shutdown`).

- Le formulaire propose les commandes courantes pour Linux (`shutdown -h now`), Windows (`shutdown /s /t 0`, avec le serveur OpenSSH activé) et macOS (`sudo -n shutdown -h now`) ;
- La connexion doit avoir été ouverte une fois dans le terminal Web pour enregistrer la clé d’hôte ; un hôte inconnu n’est jamais approuvé sans supervision ;
- Chaque arrêt ouvre une nouvelle connexion SSH et la ferme ensuite : une connexion périmée d’avant le redémarrage de l’appareil n’est jamais utilisée ; la commande dure au plus 30 secondes, une seule à la fois par appareil ; une connexion coupée avant le retour du code de sortie compte comme un arrêt commencé ;
- Les jetons d’API ont besoin de `webterminal:write` en plus de `wol:write` pour créer, modifier ou copier des appareils ou déclencher un arrêt, et de `webterminal:read` pour lister les connexions SSH disponibles.

## Wake-on-LAN : commande vocale Bemfa

Une fois [Bemfa](https://cloud.bemfa.com) connecté, des assistants vocaux comme Xiao AI, Xiaodu ou Google Assistant peuvent allumer et éteindre les appareils : créez dans la console Bemfa un sujet se terminant par `001` (prise) ou `006` (interrupteur), saisissez le même sujet sur l’appareil, saisissez la clé privée utilisateur dans « Wake-on-LAN → Bemfa » et activez, puis associez votre compte Bemfa dans des applications comme Mi Home ou Xiaodu.

« Allumer » réveille l’appareil et « éteindre » l’arrête à distance ; après une action réussie, l’état est réécrit dans Bemfa, et un réveil ou un arrêt depuis l’interface ou l’API le réécrit aussi. Gately se connecte à `bemfa.com:9503` en MQTT 3.1.1 sur TLS et vérifie le certificat, et la clé privée reste masquée dans l’API ; l’état précédent renvoyé par le serveur à l’abonnement n’est pas exécuté, et la même commande répétée en moins de 10 secondes n’est exécutée qu’une fois. Un seul client peut être en ligne par clé privée.

## Service Web : port HTTP supplémentaire sur un écouteur

Un écouteur peut ajouter un port HTTP en clair (par exemple 80 à côté d’un écouteur HTTPS sur 443) qui partage tous les sites et réglages avec le port principal ; HTTP passe ainsi par le même écouteur, sans saisir les sites une seconde fois. Avec HTTPS activé, choisissez « Rediriger vers HTTPS » (par défaut ; garde le domaine, le chemin et la chaîne de requête, remplace le port par celui de l’adresse d’accès, et répond en 301 pour GET/HEAD et 308 pour les autres méthodes) ou « Servir ».

- Les validations ACME HTTP-01, le protocole PROXY et l’ouverture automatique du pare-feu s’appliquent aussi à ce port ; si le port est occupé, le port principal continue de fonctionner et l’état de l’écouteur en indique la raison ;
- Les domaines sans site correspondant restent sans redirection : ils reçoivent le 404 des domaines inconnus ou passent au site par défaut (un site par défaut « fermer la connexion » la ferme), comme en HTTPS ; la redirection HTTP sur le même port suit désormais la même règle ;
- L’enregistrement vérifie que le port HTTP n’entre pas en conflit avec les ports d’autres écouteurs ; quand un écouteur est atteint via le Routage par protocole ou la Redirection de ports sans port d’accès renseigné, l’éditeur rappelle de saisir le port d’entrée.

## Panneaux de navigation : thèmes

Les panneaux de navigation utilisent les mêmes palettes que l’interface d’administration (créations Gately et palettes classiques), et l’éditeur du panneau définit le thème par défaut. Les visiteurs changent de thème avec le bouton palette en haut à droite, qui fonctionne comme dans l’interface d’administration : mode clair, sombre ou système, palettes avec aperçu au survol et diffusion depuis le point de clic une fois choisies, couleur d’accent et arrondi personnalisés ; sur mobile, le sélecteur s’ouvre en bas de l’écran. Le choix est enregistré dans le navigateur du visiteur et partagé entre le panneau et l’interface d’administration lorsque les deux sont sur le même domaine. Voir [Service web · Panneaux de navigation](/fr/docs/modules/web#nav-panel).
