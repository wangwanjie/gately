# Gately v0.6.8.1 disponible

17 novembre 2026

[Télécharger v0.6.8.1](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.1)

## Services Web

- **Échec de l'ajout ou de la modification d'un site** : dans la v0.6.8, ajouter, modifier, copier, activer ou désactiver un site sur la page Services Web, ou modifier une écoute HTTPS, échouait avec une erreur de format `siteCerts`. La cause : les informations de certificat du site ajoutées en v0.6.8 (les jours restants du certificat affichés sur la ligne du site) étaient envoyées par l'interface avec la configuration, et l'API d'enregistrement ne reconnaissait pas ce champ. L'interface le retire désormais avant l'envoi ; l'API d'enregistrement ignore aussi les champs en lecture seule que l'API de liste produit elle-même (état d'exécution, statistiques, correspondance de certificat, etc.), si bien que les anciennes pages restées ouvertes après la mise à jour et les scripts qui lisent la configuration puis la renvoient en bloc peuvent aussi enregistrer. Les autres champs inconnus restent refusés. L'assistant rapide de site n'était pas concerné.
- **« Site introuvable » sur une connexion réutilisée** : lorsque plusieurs domaines pointent vers la même IP et qu'un seul certificat les couvre tous (par exemple un certificat générique `*.example.com`), le navigateur place les requêtes d'un nouveau domaine sur une connexion HTTP/2 déjà ouverte. Si un routage par protocole placé devant, basé sur le SNI, envoie certains de ces domaines vers un autre Gately, cette connexion mène en réalité à l'autre instance : la visite affiche alors « Site introuvable » (ou tombe sur le site par défaut de celle-ci) jusqu'à ce que le navigateur soit fermé puis rouvert. Désormais, lorsque le domaine d'une requête HTTP/2 ou HTTP/3 diffère du SNI TLS et que cette écoute n'a pas de site pour ce domaine, `421 Misdirected Request` est renvoyé et le navigateur ouvre une nouvelle connexion pour ce domaine et réessaie automatiquement. HTTP/1.1 et les requêtes sans SNI (accès par IP) sont traitées comme avant.

## Notes de mise à jour

- Docker : récupérez la nouvelle image et recréez le conteneur ; OpenWrt : installez le nouveau `.apk` / `.ipk` par-dessus l'ancien ; fnOS : installez le nouveau `.fpk` dans le Centre d'applications ; les autres installations peuvent se mettre à jour en ligne depuis les paramètres système.
- Le correctif de la connexion réutilisée n'est complet que si les deux extrémités du routage SNI sont mises à jour : le Gately qui reçoit la requête doit renvoyer le 421.
