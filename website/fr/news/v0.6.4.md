# Gately v0.6.4 publié

3 novembre 2026

[Télécharger v0.6.4](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4) · [Build personnalisé en ligne](https://build.gately.cn)

## Build personnalisé

En dehors des trois modules de base (Redirection de ports, Services Web et Certificats SSL), les 22 autres modules peuvent être retirés à la compilation, et les langues de l’interface peuvent se limiter au chinois simplifié, ou au chinois simplifié, au chinois traditionnel et à l’anglais :

- Ouvrez [build.gately.cn](https://build.gately.cn) et cochez les modules et les langues (ou partez des préréglages « Core only », « Router » ou « NAS ») ; la page estime la taille en direct et génère en ligne des binaires Linux / Windows / macOS / FreeBSD, des paquets OpenWrt et fnOS, ou une image Docker multi-architecture pour amd64, arm64 et arm/v7 ; les artefacts aux mêmes options sont réutilisés sans nouvelle compilation ;
- Sur linux/arm64 par exemple : l’édition complète pèse 33,6 Mo, le cœur seul environ 19,9 Mo et le préréglage Router avec le chinois simplifié environ 21,2 Mo ; l’image Docker du préréglage Router avec le chinois simplifié se télécharge en 18,7 Mo environ (image complète : 51,9 Mo), et une image sans la gestion Docker ni la Prévention d’intrusion n’embarque plus docker-cli, compose ni nftables ;
- Pour les modules non compilés, les fichiers de configuration restent intacts, leurs interrupteurs dans les Paramètres et les portées des jetons d’API restent valides, leurs API répondent 404 en indiquant que le module n’est pas inclus dans ce build, et l’interface masque leurs pages et options ; tout revient en repassant à l’édition complète ;
- La page À propos liste les modules retirés de ce build, avec un lien qui ouvre le générateur avec les mêmes options. Les builds personnalisés ne proposent pas de mise à niveau en ligne (celle-ci télécharge l’édition complète) ; à la sortie d’une nouvelle version, régénérez-la avec les mêmes options puis utilisez « Téléverser un paquet de mise à niveau » ;
- Pour compiler vous-même, utilisez les build tags `no_<module>` et `lang_zh` / `lang_cjken`, `GATELY_LOCALES` pour le frontend, ou les arguments de build du Dockerfile comme `GATELY_TAGS` ; `tools/custombuild` convertit une sélection en ces paramètres.

Voir [Vue d'ensemble des modules · Build personnalisé](/fr/docs/modules/#custom-build) et [Compiler depuis les sources](/fr/download#custom-build).

## Masquer le port d’administration

« Paramètres → Contrôle d'accès » ajoute « Réponse non autorisée », qui s’applique aux sources bannies, aux accès depuis Internet lorsque l’accès réseau local uniquement est activé, et aux requêtes qui ne sont pas passées par l’entrée sécurisée :

- Au choix : la page d’avertissement par défaut, une page 404 simple, une page vide, fermer la connexion, aucune réponse jusqu’au délai d’attente, ou une page HTML personnalisée (avec le code de statut de votre choix) ;
- La fermeture et l’absence de réponse sont décidées selon la source dès l’établissement de la connexion, si bien qu’en HTTPS aucun certificat n’est envoyé ; les requêtes relayées par un proxy de confiance reçoivent automatiquement une 404 simple, pour que le proxy frontal n’affiche pas sa propre page d’erreur ; les connexions en attente sont limitées en durée et en nombre ;
- Dans les modes de masquage, les réponses ne portent plus les en-têtes de sécurité propres à la console d’administration, et les pages personnalisées s’affichent dans un bac à sable qui bloque les scripts et les ressources externes.

Le port lui-même reste détectable par un scan ; pour le masquer complètement, il faut un pare-feu. Voir le [Guide de durcissement](/fr/docs/guide/hardening).

## Pages d’erreur des sites

- L’onglet « Pages d'erreur » d’un site des Services Web permet de choisir, pour les pages 404 et 5xx générées par Gately, le style par défaut, l’un des 10 styles intégrés (Minimal, Terminal, Néon, Ciel étoilé, Journal, Brutaliste, Aurore, Pixel, Plan, Chaîne d'état) ou une page personnalisée de la bibliothèque de pages ; chaque style dispose d’une miniature et d’un aperçu bureau / mobile ;
- La bibliothèque de pages accepte du HTML téléversé ou collé, ou la référence à un fichier `.html` du serveur ; l’enregistrement vérifie et retire scripts, attributs d’événement, formulaires et contenus similaires, les espaces réservés comme `{code}`, `{title}`, `{host}` et `{path}` sont pris en charge, et les pages sont servies avec une CSP qui bloque les scripts et les ressources externes ;
- Les sites en proxy inverse peuvent intercepter des codes de statut précis du backend (par exemple `404, 500-599`) et ne remplacer que les requêtes des navigateurs qui ouvrent une page, les requêtes d’API restant inchangées ;
- Les réglages du site par défaut s’appliquent aussi aux requêtes qui ne correspondent à aucun site, et « Tri et lot » permet de définir le style de page d’erreur de plusieurs sites à la fois.

Voir [Services Web · Pages d'erreur](/fr/docs/modules/web#error-pages).

## Autres améliorations

- La recherche du DNS dynamique filtre par enregistrement : si le nom, le groupe, la remarque ou le fournisseur d’une tâche correspond, tous ses enregistrements s’affichent, sinon seuls les enregistrements correspondants sont listés, et les tâches et groupes repliés se déplient pendant la recherche ; la recherche des Services Web déplie automatiquement les écouteurs repliés ;
- Les libellés longs de la page Paramètres passent automatiquement à la ligne et ne chevauchent plus les champs dans des langues comme l’allemand ou le russe ;
- Lorsqu’une requête de la console reçoit une réponse non JSON (par exemple bloquée par l’entrée sécurisée après expiration de la session), la console invite à actualiser ou à rouvrir l’entrée sécurisée ;
- « Actualiser » sur la page d’erreur par défaut est désormais un simple lien, qui fonctionne aussi sous une CSP bloquant les scripts ;
- Les paquets de diagnostic, `GET /api/status` et `GET /api/system/info` incluent les informations de build (personnalisé ou non, modules et langues inclus) ;
- La CI vérifie les combinaisons de build tags des préréglages.

## Notes de mise à niveau

- Docker : récupérez la nouvelle image et recréez le conteneur ; quand le socket Docker est monté, Gately peut aussi se mettre à niveau lui-même depuis sa page Docker. OpenWrt : installez le nouveau `.apk` / `.ipk` par-dessus l’ancien. fnOS : installez manuellement le nouveau `.fpk` dans le Centre d’applications. Les autres déploiements peuvent se mettre à niveau en ligne depuis la page À propos.
- Les utilisateurs de l’édition complète n’ont rien à faire ; le format de configuration ne change pas.
