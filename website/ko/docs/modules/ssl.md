# SSL 인증서

인증서를 자동으로 발급받고 갱신하여 [웹 서비스](/ko/docs/modules/web)에서 사용하며 다른 소프트웨어에도 내보낼 수 있습니다.

여러 인증서가 같은 도메인을 포함하면 만료가 가장 늦은 인증서를 사용합니다. 인증서 목록의 순서와 그룹은 표시에만 영향을 줍니다.

## 기능

- **ACME DNS-01** 자동 발급과 갱신: [동적 DNS](/ko/docs/modules/ddns)의 DNS 제공자를 재사용하므로 80 / 443 포트를 열 필요가 없습니다.
- **ACME HTTP-01**: DNS 제공자가 필요 없지만 인터넷에서 각 도메인의 80번 포트에 접속할 수 있어야 하며 와일드카드는 지원하지 않습니다.
- 와일드카드 인증서와 EAB(예: ZeroSSL)
- **단기 인증서와 IP 주소 인증서**: Let's Encrypt의 단기 인증서 프로필(유효 기간 약 6일)을 선택하면 공인 IP 주소에 인증서를 발급할 수 있습니다.
- 기존 인증서 업로드 또는 파일에서 읽기
- 디렉터리 매핑: 인증서가 바뀌면 지정한 디렉터리에 기록하고 스크립트를 실행하여 다른 서비스가 다시 로드하게 합니다.
- 자동 배포: 인증서가 바뀌면 여러 로컬 디렉터리에 복사하거나, SSH로 다른 호스트에 업로드하고 명령을 실행하거나, 이 인증서를 쓰는 Docker 컨테이너를 재시작합니다.

## DNS-01 검증

인증서의 「방식」에서 DNS-01을 선택하고 DNS 제공자를 고릅니다. 발급할 때 Gately가 제공자의 API로 `_acme-challenge` TXT 레코드를 추가하고 검증이 끝나면 삭제합니다.

「기본 도메인」은 레코드가 들어갈 DNS 영역(zone)입니다. 비워 두면 Gately가 SOA 조회로 검증 레코드의 권한 있는 영역을 찾습니다. 따라서 서브도메인을 다른 DNS 제공자에 따로 위임한 경우(예: `web.example.com`을 `example.com`과 별도로 호스팅)와 `example.com.cn` 같은 다단계 접미사도 올바르게 인식합니다. 조회에 실패하면 도메인 이름으로 기본 도메인을 추정하고 그 이유를 로그에 남깁니다. 기본 도메인을 직접 입력할 수도 있습니다. 예: `web.example.com`.

## 발급 네트워크

인증서의 「네트워크」 옵션은 발급할 때 사용하는 외부 네트워크를 제한합니다. 「자동」은 시스템이 선택하고, 「IPv4 전용」 또는 「IPv6 전용」을 선택하면 CA 접속, DNS 제공자 API 호출, TXT 레코드 전파 확인 모두 해당 주소 체계만 사용합니다. 호스트에 IPv6 주소가 있지만 IPv6가 실제로 통하지 않으면 자동 모드의 전파 확인이 권한 있는 DNS 서버를 조회하다가 시간 초과될 수 있으며, 이때는 「IPv4 전용」을 선택하세요.

## HTTP-01 검증

인증서의 「방식」에서 HTTP-01을 선택합니다. 발급할 때 CA가 `http://<도메인>/.well-known/acme-challenge/<token>`에 접속합니다.

- [웹 서비스](/ko/docs/modules/web)가 이미 80번 포트에서 수신 중이면 웹 서비스가 직접 응답하며 기존 사이트에는 영향이 없습니다.
- 80번 포트가 비어 있으면 Gately가 발급하는 동안 이 포트에서 임시로 대기하고 완료되면 즉시 닫습니다.
- 공유기가 공용 80번 포트를 이 호스트의 다른 포트로 전달한다면 「임시 대기 포트」에 그 포트를 입력합니다.

인바운드 80번 포트를 차단하는 가정용 회선(중국 본토의 가정용 광대역 등)에서는 DNS-01을 사용하세요.

## 단기 인증서와 IP 주소 인증서

「인증서 프로필」은 ACME의 profile에 해당합니다.

- **기본값**: CA가 결정하며 Let's Encrypt는 90일입니다.
- **단기 인증서 (IP 인증서)**: Let's Encrypt의 `shortlived` 프로필로 유효 기간은 약 6일입니다. Gately는 「갱신 설정」의 「단기 인증서 사전 갱신 시간」(기본 24시간)에 따라 만료 전에 자동 갱신하고, 실패하면 1시간마다 다시 시도합니다.
- CA가 지원하는 다른 프로필 이름을 입력할 수도 있습니다.

도메인에 공인 IP 주소(IPv4 또는 IPv6, 예: `203.0.113.10`, `2001:db8::1`)를 입력하면 IP 주소 인증서를 신청할 수 있으며, IP와 도메인을 한 인증서에 함께 넣을 수 있습니다. 요구 사항:

- Let's Encrypt를 사용하고 인증서 프로필은 단기 인증서, 「방식」은 HTTP-01을 선택합니다. CA가 `http://<IP>/.well-known/acme-challenge/<token>`에 접속하므로 해당 IP의 80번 포트에 인터넷에서 접속할 수 있어야 합니다. IP를 입력하면 편집 창에 안내가 표시되며 「자동 설정」을 누르면 됩니다.
- 사설 주소, 루프백 주소와 `100.64.0.0/10`은 공용 CA의 검증을 통과할 수 없습니다. 사용자 지정 CA(내부망에 직접 구축한 ACME 서버 등)에는 이런 제한이 없습니다.
- ZeroSSL과 Google Trust Services는 ACME로 IP 주소 인증서를 발급하지 않습니다.

IP 주소로 HTTPS에 접속하면 브라우저가 도메인 이름(SNI)을 보내지 않으므로 Gately는 연결의 로컬 주소에 맞는 IP 인증서를 선택합니다. NAT나 포트 포워딩을 거쳐 로컬 주소가 인증서의 공인 IP와 다르면 만료가 가장 늦은 IP 인증서를 사용합니다.

발급된 인증서의 프로필을 기본값과 단기 사이에서 바꾸면 새 프로필로 즉시 다시 발급합니다. 단기 인증서는 남은 시간이 사전 갱신 시간의 절반 미만일 때(갱신이 여러 번 실패했다는 뜻)에만 만료 알림을 보냅니다.

## 인증서 매핑

인증서를 활성화하면 Gately가 `.crt`, `.key`, `.pem`, `_issuerCertificate.crt`를 매핑 디렉터리에 기록하고 변경 스크립트를 실행합니다.

## 자동 배포

인증서의 「자동 배포」에서 배포 대상을 여러 개 추가할 수 있으며, 인증서가 발급·갱신·업데이트되면 자동으로 실행됩니다.

- **로컬 디렉터리에 복사**: 인증서를 이 머신의 디렉터리에 쓰고 "복사 후 실행" 명령을 로컬에서 실행합니다. 디렉터리를 여러 개 추가하고 각각 다른 명령을 쓸 수 있습니다. 디렉터리의 인증서 파일이 삭제되거나 바뀌면 다음 검사 때 다시 복사합니다. Gately가 Docker에서 실행 중이면 디렉터리와 명령은 컨테이너 안의 것입니다.
- **SSH 호스트에 업로드**: [웹 터미널](/ko/docs/modules/terminal)에 있는 SSH 연결을 선택하면 그 연결의 주소, 인증 방식, 프록시를 그대로 사용합니다. 인증서 파일(`<메모>.crt`, `.key`, `.pem`, `_issuerCertificate.crt`. 인증서 매핑과 같으므로 메모를 비워 둘 수 없습니다)을 원격 디렉터리에 기록한 뒤 원격 호스트에서 「업로드 후 실행」 명령(예: `systemctl reload nginx`)을 실행합니다. 명령에서는 `$certName`, `$certDir`, `$certFile`, `$keyFile`을 쓸 수 있습니다. 파일은 먼저 임시 파일에 쓰고 권한을 설정한 뒤 이름을 바꿔 교체하며, 개인 키 권한은 0600입니다.
- **로컬 컨테이너 재시작**: 인증서가 바뀌면 선택한 Docker 컨테이너를 차례로 재시작합니다. 매핑 디렉터리를 마운트했고 새 인증서를 읽으려면 재시작이 필요한 서비스에 적합합니다.

"로컬 디렉터리에 복사"와 "SSH 호스트에 업로드"에서는 인증서(전체 체인)와 개인 키의 파일 이름을 `fullchain.pem`, `privkey.pem`처럼 지정할 수 있습니다. 둘 다 입력하면 이 두 파일만 쓰며 메모는 비워도 됩니다. 비워 두면 인증서 매핑과 같은 파일 이름을 씁니다. 명령의 `$certFile`, `$keyFile`은 실제로 쓴 파일을 가리킵니다.

자동 배포는 알 수 없는 호스트를 신뢰하지 않습니다. 선택한 SSH 연결로 웹 터미널에서 먼저 한 번 접속해 호스트 키를 기록해야 업로드합니다. 배포에 실패하면 1시간마다 다시 시도하고 「인증서: 배포 실패」 이벤트를 보내며, 이 이벤트는 [알림 센터](/ko/docs/modules/notify)에서 구독할 수 있습니다. 인증서 카드의 「지금 배포」는 재시도 간격과 상관없이 활성화된 모든 대상에 즉시 배포하고 대상별 결과를 표시합니다.

인증서를 편집할 때 대상 설정이 그대로인 배포는 다시 실행하지 않으며, 원격 디렉터리, 명령, 컨테이너를 바꾸면 한 번 다시 배포합니다.

## 보안 안내

개인 키는 설정 디렉터리의 `ssl.json`에 저장됩니다. 이 파일을 안전하게 보관하고, 버전 저장소에 넣을 때는 저장소가 비공개인지 확인하세요.
