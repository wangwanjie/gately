# 침입 방지

fail2ban 방식의 침입 방지입니다. 로그에서 무차별 대입 공격을 찾고, 사용하지 않는 포트에 미끼를 두고, 포트 스캔을 집계해 악성 IP를 차단 목록에 추가하며, 이를 시스템 방화벽(nftables / iptables + ipset)에 동기화해 커널에서 해당 IP의 모든 트래픽을 버립니다.

## 기능

- **로그 규칙**: 로그 파일, systemd 저널, 명령 출력(OpenWrt의 `logread -f` 등), Docker 컨테이너 로그를 읽어 정규식으로 실패 기록을 찾고, 집계 기간 내에 횟수에 도달한 IP를 차단합니다. SSH, Dropbear, Nginx, Vaultwarden, Home Assistant, Proxmox VE 등의 템플릿이 들어 있으며, 규칙을 편집할 때 로그 샘플을 붙여 넣어 바로 테스트할 수 있습니다.
- **Gately 이벤트**: 관리 콘솔 로그인 실패와 WAF 차단도 규칙의 출처로 쓸 수 있으며 정규식이 필요 없습니다.
- **웹 경로 탐색**: 웹 서비스가 처리한 요청을 리스너, 경로, 상태 코드별로 직접 세며 로그를 읽지 않습니다. `/.env`, `/.git` 같은 미끼 경로에 접근하거나 알 수 없는 도메인을 반복해서 스캔하는 출발지를 차단합니다;
- **미끼 포트**: 이 호스트에서 쓰지 않는 포트(기본값 23, 135, 1433, 3389, 5900, 6379 등)에 미끼를 두고, 접속하는 출처를 즉시 차단합니다.
- **포트 스캔 탐지**: 같은 출처가 분당 임계값보다 많이 이 호스트의 열려 있지 않은 포트에 접속하면 차단합니다.
- **통합 차단 목록**: 수동 차단(CIDR 네트워크와 영구 차단 지원)과 웹 서비스 인증 실패에 따른 자동 차단을 여기서 관리합니다. 이 장비를 거쳐 전달된 연결은 모두 루프백 주소로 보이므로 수동 차단에는 루프백 주소를 포함할 수 없습니다. 차단은 저장되어 재시작 후에도 복원됩니다.
- **점진적 차단**: 같은 주소가 30일 안에 다시 차단되면 시간이 두 배가 되며 상한까지 늘어납니다.
- **화이트리스트**: LAN, 루프백, 100.64.0.0/10(Tailscale), 이 호스트 인터페이스가 속한 IPv6 /64는 기본적으로 무시합니다(차단이 /64 단위라 같은 LAN의 공인 IPv6 기기가 함께 차단되지 않도록). IP나 네트워크를 추가할 수 있으며, 화이트리스트의 단일 IPv6 주소는 그 /64 전체를 보호합니다.

## 적용 범위

| 환경 | 차단 효과 | 미끼 포트 | 포트 스캔 탐지 |
| --- | --- | --- | --- |
| Linux(root 또는 `CAP_NET_ADMIN`, nftables 설치됨) | SSH, 다른 프로그램, Docker 컨테이너와 LAN 기기로 전달되는 트래픽까지 모두 커널에서 삭제 | 커널에서 처리, SYN만 보내는 스캔도 감지 | 사용 가능 |
| Docker(host 네트워크 + `cap_add: NET_ADMIN`) | 위와 같음, 규칙은 호스트에 기록 | 위와 같음 | 사용 가능 |
| fnOS 패키지, OpenWrt 22.03 이상 | 위와 같음(root로 실행, nftables 기본 포함) | 위와 같음 | 사용 가능 |
| Synology DSM 등 커널에 nf_tables가 없는 Linux(Docker host 네트워크 + `NET_ADMIN`, 직접 설치 시 ipset과 iptables legacy 필요) | 위와 같음(iptables의 mangle 테이블과 ipset 사용) | 위와 같음 | 사용 가능(임계값은 분당 최대 255회) |
| 그 밖의 경우(Windows, macOS, FreeBSD, nftables도 iptables(legacy)와 ipset도 없거나 권한이 없는 Linux) | Gately 자체 서비스(포트 포워딩, 웹 서비스, STUN, WebDAV, FTP, SMB, frps 로그인, 관리 콘솔)에만 적용 | Gately가 직접 수신, 핸드셰이크를 완료한 연결만 감지 | 사용 불가 |

페이지 상단에 방화벽 동기화 상태가 표시되며, 사용할 수 없으면 원인과 해결 방법을 보여 줍니다.

## 방화벽 규칙

"시스템 방화벽에 동기화"를 켜면 Gately는 nftables에 별도의 `inet gately` 테이블을 만들며, 시스템의 기존 규칙(fw4, Docker, ufw 등)은 건드리지 않습니다.

- `prerouting` 체인(우선순위 -190, 연결 추적 이후·목적지 NAT 이전)에서 차단된 주소가 보낸 패킷을 버립니다. 이 호스트로 오는 트래픽도, 컨테이너나 LAN 기기로 전달되는 트래픽도 버려집니다. 이 호스트가 먼저 연 연결(DNS, 패키지 미러 접속 등)의 응답은 상대 주소가 차단되어 있어도 그대로 통과합니다. IPv6는 /64 단위로 차단합니다.
- `input` 체인은 이 호스트로 오는 새 연결만 보며, 미끼 포트와 스캔 탐지에 쓰입니다. 화이트리스트 주소는 제외됩니다.
- 동기화를 끄거나 Gately를 중지하면 테이블 전체가 삭제됩니다. 다른 프로그램이 테이블을 지우면 10초 안에 다시 기록합니다.

커널에 nf_tables가 없으면(예: Synology DSM) iptables(legacy)와 ipset을 대신 사용하며, 이 경우에도 기존 규칙은 건드리지 않습니다. mangle 테이블 `PREROUTING`과 `INPUT`의 첫 규칙이 각각 Gately 전용 `GATELY_PRE`, `GATELY_IN` 체인으로 점프하며 위의 두 체인과 같은 역할을 합니다. 차단된 단일 주소는 ipset 세트 `gately_ban4` / `gately_ban6`(IPv6는 /64 단위)에 넣고, 네트워크와 영구 차단은 `GATELY_DENY` 체인의 규칙으로 씁니다. Synology 방화벽 등이 자기 규칙을 앞에 끼워 넣으면 10초 안에 점프를 맨 앞으로 되돌리고, 체인이 지워지면 자동으로 다시 씁니다. 스캔 탐지는 recent 모듈로 세며 임계값은 분당 최대 255회로 처리합니다.

페이지의 "규칙 보기"에서 현재 기록된 전체 규칙을 볼 수 있습니다.

::: tip Docker 배포
규칙을 호스트에 기록하려면 `network_mode: host`와 `NET_ADMIN` 권한이 필요합니다.

```yaml
    network_mode: host
    cap_add:
      - NET_ADMIN
```

권한을 주지 않아도 차단은 Gately 자체 서비스에 적용됩니다. 호스트 로그를 읽으려면 로그 디렉터리를 컨테이너에 마운트하세요. 예를 들어 `- /var/log:/var/log/host:ro`로 마운트하고 규칙에 `/var/log/host/auth.log`를 입력합니다. systemd 저널 출처는 컨테이너에서 사용할 수 없습니다.
:::

## 로그 규칙

| 출처 | 입력 | 설명 |
| --- | --- | --- |
| 로그 파일 | 파일 경로, 한 줄에 하나 | 파일 끝에서부터 새 내용을 읽고 로테이션(이름 변경 또는 잘라내기)을 따라감 |
| systemd 저널 | `ssh.service` 같은 서비스 유닛 | `journalctl -f`로 읽음 |
| 명령 출력 | `logread -f` 같은 명령 하나 | 종료되면 자동으로 다시 시작 |
| Docker 컨테이너 | 컨테이너 이름 | Docker 관리 모듈이 연결한 Docker에서 읽음 |
| Gately 이벤트 | 관리 콘솔 로그인 실패 / WAF 차단 | 이벤트에 출처 IP가 포함되어 필터가 필요 없음 |
| 웹 경로 탐색 | 리스너(비워도 됨)와 경로 규칙 | 웹 서비스 요청을 셉니다. 아래 참고 |

필터는 Go 정규식(RE2 문법)이며 한 줄에 하나씩, `<HOST>`가 출처 주소를 나타냅니다. 예:

```
Failed password for (?:invalid user )?\S* ?from <HOST>
```

"제외"에 일치하는 줄은 세지 않습니다. 집계 기간, 실패 횟수, 차단 시간은 규칙마다 설정하며, 차단 시간은 기본값, 사용자 지정, 영구 중에서 고릅니다.

## 웹 경로 탐색

소스로 「웹 경로 탐색」을 고르면 규칙은 로그를 읽지 않고 웹 서비스가 처리한 요청을 직접 셉니다:

- **리스너**: 하나 이상 고를 수 있고, 비워 두면 모든 리스너입니다;
- **경로 규칙**: 한 줄에 하나, 비워 두면 모든 경로입니다. `*`는 `/`를 포함한 임의의 문자와 일치하며 경로 전체를 대소문자 구분 없이 비교합니다. 예를 들어 `*/.env`는 `/.env`와 `/api/.env`에 일치합니다. `~`로 시작하는 줄은 Go 정규식입니다. `//.env`, `/a/../.env` 같은 표기도 정규화된 경로로 일치합니다;
- **제외 경로**: 문법은 같고, 일치하는 요청은 세지 않습니다;
- **집계 대상**: 기본으로 404와 444(없는 내용 접근, 또는 「연결 끊기」 사이트에 의한 끊김)만 세므로 존재하는 페이지에 대한 요청은 세지 않습니다. 「모든 상태 코드」를 켜면 모든 응답을 세며, 단일 페이지 앱은 어떤 경로에도 200을 반환하므로 미끼 경로에 알맞습니다. 모든 상태 코드는 경로 규칙이나 「알 수 없는 도메인만」과 함께 써야 하며, 그렇지 않으면 저장이 거부됩니다;
- **접근 제어 거부**: 사이트의 거부 방식이 「연결 끊기」이면 차단, IP 접근 제어 또는 국가 필터로 거부된 요청은 일반 사이트에서는 403으로 집계해 목록 밖의 정상 방문자가 잘못 차단되지 않게 하고, 기본 사이트에서는 「연결 끊기」 유형의 기본 사이트와 같이 444로 집계합니다. 기본 사이트를 리버스 프록시와 허용 목록으로 바꿔 내 IP를 허용해도 알 수 없는 도메인 스캔은 계속 집계됩니다;
- **알 수 없는 도메인만**: 도메인이 어떤 사이트와도 일치하지 않는 요청, 즉 기본 사이트가 처리하거나 기본 사이트가 없을 때 리스너가 404로 응답한 요청만 셉니다.

템플릿은 세 가지입니다:

| 템플릿 | 조건 | 설명 |
| --- | --- | --- |
| 웹 미끼 경로 | `/.env`, `/.git`, `wp-login.php`, `phpinfo.php`, `phpmyadmin` 등, 모든 상태 코드 1회 | 1일 차단. 사이트가 실제로 WordPress, phpMyAdmin 등이라면 해당 줄을 먼저 지우세요 |
| 알 수 없는 도메인 스캔 | 알 수 없는 도메인만, 1분 안에 5회 | 1일 차단. 기본 사이트의 「연결 끊기」와 함께 쓰면 스캐너는 444 몇 번 뒤 차단되고, 방화벽 동기화를 켜 두면 이후 연결은 버려집니다 |
| 웹 404 탐색 | 모든 경로, 1분 안에 10회 | favicon, robots.txt, `.map` 등 브라우저가 스스로 요청하는 경로는 제외됨. 리버스 프록시 백엔드가 반환한 404도 세므로 갤러리 썸네일 누락이나 앱이 없는 API를 폴링하는 경우에도 발동할 수 있습니다. 켜기 전에 접근 로그를 확인하고 필요하면 횟수를 늘리거나 제외 경로를 추가하세요 |

웹 서비스의 리스너 카드에서 「탐색 차단」을 누르면 이 페이지가 열리고 해당 리스너가 선택된 채 미끼 경로 템플릿이 적용됩니다. 규칙의 저장과 실행은 침입 방지가 맡습니다. 규칙을 편집할 때 요청 경로를 붙여 넣어 경로 규칙을 테스트할 수 있습니다.

::: warning 차단 범위
어느 리스너에서 발동하든 차단은 같은 차단 목록에 들어가 모든 리스너, 사이트, Gately의 다른 서비스에 적용됩니다. 방화벽 동기화를 켜 두면 시스템 방화벽에서도 그 주소의 모든 트래픽을 버립니다.
:::

출발지 주소는 액세스 로그와 같으며 PROXY 프로토콜로만 복원됩니다. CDN을 거치고 실제 IP를 요청 헤더로 넘기는 사이트에서는 CDN 노드가 차단되므로, 그런 리스너에는 경로 탐색을 쓰지 마세요. Gately가 같은 호스트의 다른 리버스 프록시 뒤에 있으면 출발지는 루프백 주소이며, 「LAN 주소 무시」를 켜 두면 차단되지 않지만 규칙도 효과가 없습니다.

## 포트 스캔 탐지의 절충

스캔 탐지는 **이 호스트가 수신하지 않는 포트**로 오는 새 연결을 셉니다. 수신 중인 TCP 포트는 10초마다 갱신되어 열린 포트로 간주되며, 다른 방화벽 규칙으로 전달되는 포트는 `input` 체인을 거치지 않아 세지 않습니다. 기본 임계값은 분당 12회입니다. 일반 클라이언트가 닫힌 포트를 재시도하는 횟수는 분당 약 5회이므로 10 미만으로 낮추지 않는 것이 좋습니다.

미끼 포트 중 수신 중인 포트는 정상 방문자가 차단되지 않도록 자동으로 제외됩니다.

## IPv6 엄격 모드

IPv6에는 NAT가 없어 모든 기기가 공인 주소를 가지며, 주소가 DNS나 인증서 투명성 로그에 노출되면 스캐너가 직접 접속할 수 있습니다. 포트 스캔 탐지의 「IPv6 엄격 모드」는 IPv6를 허용 목록 방식으로 바꿉니다. IPv6 출처는 개방 포트(수신 중인 포트와 「추가 개방 포트」)에만 연결할 수 있고, 그 외 포트에 처음 연결하는 즉시 차단되며 임계값 집계는 하지 않습니다. IPv4는 계속 임계값으로 탐지합니다.

- 차단은 /64 대역 단위로 적용되어 같은 /64의 다른 기기도 함께 차단됩니다. 화이트리스트 주소와 「내부 주소 무시」에 해당하는 주소는 영향을 받지 않습니다.
- 새로 수신을 시작한 포트는 약 10초 후 개방으로 간주되고, 켜거나 재시작한 뒤 약 15초 후부터 적용되며 그때까지는 임계값이 적용됩니다. 수신 포트를 읽을 수 없을 때도 임계값이 적용됩니다.
- 수신을 멈춘 포트도 30초 동안은 열린 포트로 간주하므로, frps 재연결이나 프로그램·리스너 재시작 중에 다시 연결하는 방문자는 차단되지 않습니다. FTP 서비스에 패시브 포트 범위를 설정하면 범위 전체가 열린 포트에 포함됩니다. 패시브 포트를 시스템이 무작위로 할당하면 미리 나열할 수 없어 IPv6 데이터 연결이 스캔으로 차단되며 실행 로그에 경고가 표시되므로, FTP 서비스에서 패시브 포트 범위를 설정하세요.
- 다른 프로그램이 방화벽 규칙으로 사용하는 포트는 먼저 「추가 개방 포트」에 넣어야 하며, 그렇지 않으면 해당 포트에 접속하는 출처가 차단됩니다.
- TCP 신규 연결만 집계합니다. 방화벽 동기화가 켜져 있고 포트 스캔 탐지가 활성화되어 있어야 합니다.

## 웹 서비스와의 관계

웹 서비스의 "인증 실패 시 차단"으로 생긴 차단도 같은 차단 목록에 들어가므로, 방화벽 동기화를 켜면 웹 사이트뿐 아니라 호스트 전체에 적용됩니다. "LAN 주소 무시"를 켜면 LAN 주소는 자동으로 차단되지 않습니다.

웹 서비스와 WAF는 PROXY 프로토콜로만 실제 클라이언트 주소를 알 수 있습니다. 실제 IP를 헤더로 전달하는 CDN 뒤의 사이트에서는 인증 실패 차단과 "WAF 차단" 규칙이 CDN 노드를 차단하게 되므로 이런 사이트에서는 켜지 마세요.

## 알림

차단하면 "침입 방지: IP 차단됨" 이벤트가 발생하며 [알림 센터](/ko/docs/modules/notify)에서 구독할 수 있습니다. 미끼 포트와 스캔 탐지가 같은 점검에서 차단한 여러 주소는 하나의 알림으로 합쳐집니다.

## 검증

fnOS(Debian 12, nftables 1.0.6)와 iStoreOS 24.10(nftables 1.1.1)의 독립된 네트워크 네임스페이스에서 검증했습니다. 미끼 포트와 스캔 탐지(IPv4와 IPv6)가 커널에서 차단하고 차단 목록으로 가져오며, 로그 파일(로테이션 포함), systemd 저널, Docker 컨테이너 로그, 관리 콘솔 로그인 실패 모두 차단을 일으킵니다. 수동 네트워크·영구 차단, 차단 해제, 점진적 시간, 재시작 후 복원, 외부에서 삭제된 테이블의 재기록, 중지 시 규칙 정리도 기대대로 동작했고, `NET_ADMIN`이 없는 Docker 컨테이너는 권한 부족으로 판정되어 사용자 공간 미끼 포트로 전환됩니다.
