# 동적 DNS (DDNS)

가정용 인터넷 회선의 공인 IP는 바뀌곤 합니다. DDNS는 IP가 바뀌면 DNS 레코드를 자동으로 갱신하여 도메인이 항상 현재 주소를 가리키게 합니다.

## 지원하는 제공자

Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod, Huawei Cloud, GoDaddy, Porkbun, dynv6, DuckDNS, Amazon Route 53, OVHcloud, Gandi, NS1, Bunny DNS, Namecheap, DynDNS2, 그리고 사용자 정의 콜백(내장되지 않은 제공자나 자체 구축한 API용)을 지원합니다.

| 제공자 | 자격 증명 | 인증서 DNS 검증에 사용 가능 |
| --- | --- | --- |
| Amazon Route 53 | Access Key ID / Secret Access Key, 선택적으로 호스팅 영역 ID | 예 |
| OVHcloud | Application Key / Secret과 Consumer Key, 엔드포인트 ovh-eu / ovh-ca / ovh-us | 예 |
| Gandi | Personal Access Token | 예 |
| NS1 | API Key | 예 |
| Bunny DNS | Account API Key | 예 |
| Namecheap | 도메인의 Dynamic DNS 비밀번호(A 레코드만) | 아니요 |
| DynDNS2 | 사용자 이름, 비밀번호, 업데이트 주소. No-IP, Dynu 등 dyndns2 프로토콜 호환 서비스에 사용 | 아니요 |

## IP를 가져오는 방법

- **URL**: 공인 IP 조회 주소를 요청합니다(원하는 서비스로 바꾸거나 직접 구축할 수 있습니다).
- **네트워크 인터페이스**: 지정한 인터페이스의 주소를 직접 읽습니다. 공인 IP를 가진 장치에 적합합니다.
- **명령어**: 명령을 실행해 그 출력을 사용합니다. 특수한 네트워크 환경에 적합합니다.

IPv4와 IPv6를 지원합니다.

## 레코드 값 변수 {#record-vars}

레코드 값에 다음 변수를 사용할 수 있으며, 동기화할 때마다 현재 값으로 바뀝니다.

- `{ipv4Addr}`, `{ipv6Addr}`: 이 작업이 가져온 IPv4, IPv6 주소(A, AAAA 레코드 값을 비워 두면 기본으로 사용)
- `{STUN_규칙이름_PORT}`, `{STUN_규칙이름_IP}`, `{STUN_규칙이름_ADDR}`: STUN 규칙의 현재 공인 포트, IP, IP:포트이며 규칙 이름에 밑줄을 쓸 수 있습니다. 예: TXT 레코드에 `port={STUN_ssh_PORT}`, A 레코드에 `{STUN_ssh_IP}`

STUN 규칙의 공인 주소가 바뀌면 이를 참조하는 작업은 다음 확인 주기를 기다리지 않고 바로 동기화합니다. 규칙이 비활성화되었거나 아직 관통에 성공하지 않았으면 해당 레코드는 이번 회차를 건너뛰고 레코드 상태에 이유가 표시됩니다. STUN 변수는 작업의 Webhook에서도 사용할 수 있습니다. Webhook에서만 참조해도 주소가 바뀌면 Webhook을 한 번 호출합니다. 규칙 이름 대신 규칙 key를 써도 됩니다.

## 알림

IP가 바뀌거나 동기화에 실패하면 Webhook을 호출할 수 있습니다.

## 메모 {#remark}

레코드에 「메모」를 입력하면 동기화할 때 DNS 제공업체에 기록되어 제공업체 콘솔의 레코드 목록에서 확인할 수 있습니다. 레코드 메모가 비어 있으면 작업 메모를 사용하고, 둘 다 비어 있으면 제공업체의 기존 메모를 바꾸지 않습니다. 메모만 바꿔도 동기화가 한 번 실행됩니다. 100자를 넘는 부분은 기록되지 않습니다(Cloudflare 무료 요금제 한도). Alibaba Cloud 메모는 50자까지이며 중국어, 영문자, 숫자와 `_ - , . ，。`만 쓸 수 있고 공백과 기타 기호는 밑줄로 바뀝니다.

메모 기록을 지원하는 제공업체: Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod(중국·국제), Huawei Cloud. 다른 제공업체에서는 메모가 Gately에만 저장됩니다.

## 레코드와 작업 삭제 {#delete}

레코드(목록에서 레코드 오른쪽의 삭제 아이콘, 또는 편집 화면에서 저장된 레코드를 제거한 뒤 저장)나 작업을 삭제하면 확인 창이 열리고 「DNS 제공업체에서도 삭제」를 선택할 수 있습니다.

- 선택하면 먼저 제공업체의 레코드를 삭제하고, 모두 성공해야 Gately 설정을 삭제합니다. 하나라도 실패하면 원인을 표시하고 Gately 설정은 그대로 두므로 다시 시도하거나 선택을 해제하면 됩니다.
- Gately가 동기화한 레코드만 삭제합니다. 이름·유형(·회선)이 같고 값이 Gately의 마지막 동기화 결과와 같은 레코드가 대상입니다.
- Gately가 아직 이 레코드를 동기화한 적이 없거나(값을 모름), 제공업체의 값이 마지막 동기화 값과 다르거나(예: 콘솔에서 수정한 경우), 레코드 세트 단위로 관리하는 제공업체(Huawei Cloud, Route 53, Gandi, NS1, GoDaddy)의 레코드 세트에 다른 값이 남아 있으면 삭제하지 않고 이유를 알려 줍니다. 먼저 한 번 동기화하거나 제공업체 콘솔에서 처리하세요.
- 제공업체에 레코드가 이미 없으면 성공으로 처리합니다.
- 작업을 편집하면서 레코드를 지우고 이 항목을 선택하면 저장할 설정을 먼저 검증하며, 검증에 실패하면 제공업체의 레코드를 삭제하지 않습니다.
- DuckDNS, Namecheap, DynDNS2, 사용자 정의 콜백은 삭제 API가 없어 이 옵션이 표시되지 않으며, 제공업체의 레코드는 직접 삭제해야 합니다.

체크박스의 기본 상태는 「전역 설정」에서 정합니다.

## 전역 설정 {#settings}

페이지 상단의 「전역 설정」에는 다음 항목이 있습니다.

- **모듈 사용**: 꺼져 있는 동안에는 IP를 확인하지 않고 DNS 레코드도 업데이트하지 않습니다.
- **삭제 시 제공업체 레코드도 삭제**: 레코드나 작업을 삭제할 때 「DNS 제공업체에서도 삭제」 체크박스의 기본 상태입니다. 기본값은 꺼짐이며 삭제할 때마다 바꿀 수 있습니다.

## 사용 권장 사항

- DNS 제공자에서는 레코드 편집 권한만 있는 하위 계정 키를 만들어 사용하고, 주 계정 키는 쓰지 마세요.
- 작업을 새로 만든 뒤 「강제 동기화」를 눌러 레코드가 갱신되었는지 확인하세요.
- 더 이상 필요 없는 레코드는 목록에서 해당 레코드 오른쪽의 삭제 아이콘을 눌러 편집 화면을 열지 않고 바로 제거할 수 있습니다. 작업에는 레코드가 하나 이상 남아야 하며, 제공업체의 레코드도 함께 삭제하는 방법은 [레코드와 작업 삭제](#delete)를 참고하세요.
- 공인 IP 조회 주소는 프로젝트 측 서비스에 의존하지 않으며 작업에서 언제든 바꿀 수 있습니다.

## 그룹과 정렬

작업에 "그룹"(최대 64자)을 지정할 수 있습니다. 목록은 그룹별로 접을 수 있는 구역으로 표시되며, 그룹은 처음 나타난 순서대로, 그룹이 없는 작업은 맨 뒤에 놓입니다. 접힘 상태는 브라우저에 저장됩니다. 페이지 상단의 검색 상자로 이름, 그룹, 도메인 또는 제공업체을(를) 기준으로 거를 수 있습니다.

"정렬"을 눌러 정렬 모드로 들어갑니다. 화살표로 작업을 위아래로 옮기거나 그룹 전체를 옮길 수 있습니다. 여러 작업을 선택한 뒤 그중 하나를 끌면 함께 이동하고, 다른 그룹의 작업이나 그룹 제목에 놓으면 그 그룹으로 들어갑니다. 도구 모음에서 선택한 작업을 지정한 그룹으로 한 번에 옮길 수 있고, 이름을 비우면 그룹에서 뺍니다. 순서와 그룹은 목록 표시에만 영향을 주며, 바꿔도 작업은 다시 시작되지 않습니다.

그룹 제목에 마우스를 올리고 연필 버튼을 누르면 그룹 이름을 바꿀 수 있습니다. 그룹의 항목도 함께 새 이름으로 바뀌며 위치와 순서는 그대로입니다. 이미 있는 그룹 이름을 고르면 확인 후 두 그룹이 합쳐집니다.
