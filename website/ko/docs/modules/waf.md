# WAF 방화벽

[Coraza](https://coraza.io/)와 OWASP CRS v4를 기반으로 한 웹 애플리케이션 방화벽으로, [웹 서비스](/ko/docs/modules/web)의 사이트에 연결할 수 있습니다.

## 기능

- OWASP CRS v4 규칙 세트를 내장하며 규칙 파일 단위로 켤 수 있습니다.
- 사용자 정의 SecLang 규칙을 지원합니다.
- 규칙 그룹 순서를 바꿀 수 있습니다. 탐지 로그에 클라이언트 IP, 도메인, 경로, 규칙 ID가 기록되며 로그에서 도메인, IP, 키워드로 필터링할 수 있습니다;
- 차단 모드와 탐지 전용 모드를 제공합니다.
- 요청 본문 검사 한도를 조정할 수 있으며, 한도를 넘으면 요청을 거부하거나 앞부분만 검사합니다. 경로별로 요청 본문 검사를 건너뛸 수 있습니다.
- WebDAV 호환 모드: 클라우드 드라이브와 WebDAV가 사용하는 메서드, 요청 헤더, 모든 업로드 콘텐츠 유형을 허용합니다.
- 직접 구축한 SafeLine(雷池) 탐지 엔진을 연결할 수 있으며 규칙 그룹과 함께 사용할 수 있습니다.
- 인스턴스를 여러 개 만들 수 있으며 사이트가 필요에 따라 참조합니다.

## 사용 권장 사항

1. 새 사이트는 먼저 「탐지 전용」으로 시작하여 한동안 로그를 관찰하고 오탐이 없는지 확인합니다.
2. 오탐이 있으면 규칙 파일을 조정하거나 사용자 정의 예외를 추가합니다.
3. 그런 다음 「차단」으로 전환합니다.

## 관리 화면 요청

WAF를 연결한 사이트를 통해 관리 화면을 리버스 프록시하는 경우, 이 인스턴스의 유효한 관리자 세션을 가진 요청은 WAF(SafeLine 포함)를 거치지 않습니다. 설정을 저장하는 요청 본문에는 파일 경로(nginx 가져오기가 기록한 메모 등), HTML(사용자 지정 오류 페이지), 스크립트(인증서 배포) 등이 자주 들어 있어 CRS의 경로 탐색, XSS, 명령 주입 규칙에 403으로 오탐되기 때문입니다. 세션은 서버가 서명하며 관리자 역할만 해당합니다. 읽기 전용 계정, 방문자, 다른 인스턴스의 관리 화면 요청은 그대로 검사합니다.

## 로그인한 사용자

사이트에서 「로그인한 사용자 신뢰」를 켜면([웹 서비스](./web) 참고) 그 사이트의 Gately 인증을 통과한 방문자(웹 인증, 외부 로그인, 공유 사용자 SSO, 검증된 기본 인증)는 WAF를 거치지 않습니다. 로그인하지 않은 방문자, 로그인 페이지 자체로의 요청, 전달 인증과 공유 링크는 그대로 검사됩니다.

## 규칙 그룹 순서

인스턴스의 규칙 그룹은 위에서 아래로 로드되며 위로·아래로 버튼으로 순서를 바꿀 수 있습니다. 같은 단계에서는 앞에 있는 규칙이 먼저 실행됩니다.

- 차단 규칙(deny 등)은 어디에 두어도 동작합니다.
- 실행 시점의 허용·제외 규칙(`allow`, `ctl:ruleRemoveById`, `ctl:ruleRemoveTargetById` 등)은 OWASP CRS 그룹보다 위에 두어야 합니다. 아래에 두면 CRS가 먼저 요청을 차단할 수 있습니다.
- `SecRuleRemoveById`, `SecRuleUpdateTargetById` 같은 설정 시점 지시문은 이미 로드된 규칙에만 적용되므로 CRS 그룹 아래에 두어야 합니다. 위에 두면 효과가 없습니다.

## 큰 파일을 업로드하는 사이트

WAF는 기본적으로 12.5 MB 이하의 요청 본문만 검사하고 더 큰 요청은 거부(413)하므로, 클라우드 드라이브, WebDAV, 파일 관리 같은 사이트에서 큰 파일을 업로드할 수 없습니다. 인스턴스의 「요청 본문 검사」에서 조정할 수 있습니다.

- **검사 한도**: 0은 기본값 12.5 MB이며 최대 1024 MB입니다.
- **한도 초과 시**: 「요청 거부」는 이전과 같이 동작합니다. 「앞부분만 검사」는 한도 이내의 부분만 검사하고 나머지는 그대로 백엔드로 전달하므로 큰 파일을 업로드하는 사이트에 적합합니다.
- **WebDAV·업로드 호환**: OWASP CRS는 기본적으로 GET, HEAD, POST, OPTIONS만 허용하고 `Lock-Token`, `If`, `Content-Range` 요청 헤더와 허용 목록 밖의 콘텐츠 유형을 차단하므로, WebDAV 클라이언트가 디렉터리 목록 조회, 업로드, 잠금을 할 수 없습니다. 켜면 PUT, DELETE, PROPFIND, PROPPATCH, MKCOL, COPY, MOVE, LOCK, UNLOCK 등의 메서드와 이 헤더들을 허용하고 업로드 콘텐츠 유형을 더 이상 제한하지 않습니다. PUT과 `application/octet-stream`의 요청 본문은 파일 내용으로 보고 폼 파라미터로 검사하지 않습니다. 인젝션, 경로 탐색 등의 공격 검사는 그대로 적용됩니다.
- **본문 검사 제외 경로**: 한 줄에 경로 접두사 하나(예: `/api/upload`, `/remote.php/dav/`)를 씁니다. 일치하는 요청은 본문을 검사하지 않으며 헤더, URL, 파라미터는 그대로 검사합니다.

클라우드 드라이브, WebDAV 같은 사이트에는 인스턴스를 따로 만들어 「WebDAV·업로드 호환」을 켜고 「앞부분만 검사」를 선택하며, 필요하면 업로드 경로를 제외 경로에 추가하고, 다른 사이트는 기본 설정을 계속 쓰는 방식을 권장합니다.

curl, rclone 같은 클라이언트는 큰 내용을 업로드할 때 `Expect: 100-continue` 요청 헤더를 보내는데, CRS 4는 기본적으로 이를 차단합니다. Gately의 모든 인스턴스는 이 헤더를 허용하므로(100-continue는 Gately가 직접 처리) 별도 설정이 필요 없습니다.

## SafeLine(雷池) 연동

[SafeLine](https://waf.chaitin.com/)은 Chaitin Tech의 웹 애플리케이션 방화벽으로, 의미 분석 엔진으로 공격을 식별해 오탐이 적습니다. Gately는 요청을 직접 구축한 SafeLine 탐지 엔진(safeline-detector)으로 보내 결과에 따라 허용하거나 차단합니다. 진입점, 인증서, 인증, 차단 목록은 계속 Gately가 담당하므로 SafeLine을 리버스 프록시로 한 단계 더 둘 필요가 없습니다.

1. SafeLine 공식 문서에 따라 커뮤니티 버전을 설치합니다. 기본 설치 디렉터리는 `/data/safeline`입니다.
2. 탐지 엔진 연결 방식을 선택합니다.
   - **Unix 소켓**(Gately와 SafeLine이 같은 머신에 있는 경우): 탐지 엔진은 기본적으로 `/data/safeline/resources/detector/snserver.sock`에서 수신하므로 주소에 `unix:/data/safeline/resources/detector/snserver.sock`을 입력합니다. Gately를 Docker에서 실행한다면 `/data/safeline/resources/detector` 디렉터리를 Gately 컨테이너에 마운트하고 컨테이너 안의 경로를 입력합니다.
   - **TCP**: `/data/safeline/resources/detector/detector.yml`에 아래 두 줄을 추가한 뒤 `docker restart safeline-detector`를 실행합니다. TCP로 바꾸면 탐지 엔진은 더 이상 Unix 소켓에서 수신하지 않습니다.

     ```yaml
     bind_addr: 0.0.0.0
     listen_port: 8000
     ```

     주소에는 safeline-detector 컨테이너의 IP와 포트(예: `172.22.222.5:8000`)를 입력합니다. 컨테이너 IP는 `docker inspect safeline-detector | grep IPAddress`로 확인할 수 있습니다. Gately가 Docker bridge 네트워크에서 실행된다면 `docker network connect safeline-ce <Gately 컨테이너 이름>`으로 SafeLine 네트워크에 연결합니다. 탐지 엔진에는 인증이 없으므로 8000 포트를 인터넷에 노출하지 마세요.
3. WAF 인스턴스에서 "SafeLine 사용"을 켜고 주소를 입력한 뒤 "연결 테스트"를 클릭합니다. Gately는 하트비트를 보낸 다음 샘플 SQL 인젝션 요청을 검사로 보냅니다. "샘플 공격이 탐지되었습니다"가 표시되면 탐지 엔진이 정상입니다. 이 샘플 공격은 출발지 127.0.0.1, 도메인 gately-test.invalid로 SafeLine 콘솔의 공격 기록에 나타납니다.
4. 웹 서비스 사이트에서 이 인스턴스를 참조합니다.

참고:

- SafeLine을 연결하면 규칙 그룹을 비워 둘 수 있습니다. 규칙 그룹도 유지하면 요청은 먼저 SafeLine에서 탐지된 뒤 규칙 그룹으로 검사됩니다. "탐지만" 모드에서는 SafeLine이 탐지한 공격을 로그에만 기록하고 요청은 그대로 통과합니다.
- 차단된 요청: 브라우저에는 이벤트 ID가 포함된 차단 페이지가 표시되고, 다른 클라이언트는 SafeLine 공식 플러그인과 같은 JSON(`event_id` 포함)을 받습니다. 상태 코드는 탐지 엔진이 제시한 값으로, 보통 403입니다. 차단은 액세스 로그(`deny=waf`), 사이트 통계, WAF 차단 이벤트에 반영되며 침입 방지의 "WAF 차단" 프리셋도 그대로 동작합니다.
- 공격 기록은 SafeLine 콘솔에도 기록되며 이벤트 ID로 찾을 수 있습니다. 이 기록은 SafeLine의 어떤 사이트에도 속하지 않습니다.
- 검사로 보내는 요청 본문은 기본적으로 최대 1024 KB이며, 초과분은 검사하지 않고 그대로 백엔드로 전달합니다. "본문 검사 제외 경로"와 "WebDAV·업로드 호환"은 SafeLine에도 적용됩니다. HTTP/2로 전송되는 길이를 알 수 없는 gRPC 요청 본문은 검사로 보내지 않습니다.
- 탐지 시간 초과는 기본 1초입니다. 탐지 엔진을 사용할 수 없을 때(연결 실패, 시간 초과)는 기본적으로 요청을 허용하고, 인스턴스에 "SafeLine 중단"을 표시하며 오류 로그를 남깁니다. "요청 거부"를 선택하면 이런 요청에 503을 반환합니다. 탐지 엔진이 막 시작된 몇 초 동안은 인식할 수 없는 결과를 반환할 수 있으며, 이 역시 사용 불가로 처리합니다.
- 요청만 검사하며 응답은 보내지 않습니다.

## 검증

WAF는 실제 공격 페이로드로 테스트하며, 경로 탐색 등의 공격 차단을 확인했습니다.
