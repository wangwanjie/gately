# 파일 및 운영 도구

## WebDAV

사이드바 「파일 서비스」 그룹의 「WebDAV 서비스」에서 설정합니다.

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| `enable` | 꺼짐 | 서비스를 켭니다. 켜려면 사용자가 최소 한 명 필요합니다 |
| `listenIp` | 비어 있음 | 수신 주소이며 비우면 모든 주소에서 수신합니다 |
| `port` | 18800 | 수신 포트 |
| `tls` | 꺼짐 | HTTPS를 켭니다. 인증서는 [SSL 인증서](/ko/docs/modules/ssl) 모듈이 SNI에 따라 제공합니다 |
| `users` | 없음 | 다중 사용자. 사용자마다 `name`, `password`, `root`(절대 경로 디렉터리), `readOnly`를 지정하거나 `mounts`로 여러 디렉터리를 마운트합니다 |
| `sharedUsers` | 꺼짐 | [공유 사용자](#shared-users)가 이 서비스에 로그인하도록 허용 |

사용자마다 디렉터리 하나를 매핑하거나 여러 디렉터리를 마운트할 수 있습니다.

- **디렉터리 하나**: `root`와 `readOnly`를 입력하면 로그인 후의 루트 디렉터리가 해당 디렉터리가 됩니다.
- **디렉터리 여러 개**: UI에서 「여러 디렉터리 마운트」를 누르거나 `mounts`에 여러 항목을 입력합니다. 각 항목은 `name`(표시 이름, `/`를 포함할 수 없고 한 사용자 안에서 중복 불가), `path`(절대 경로), `readOnly`로 구성됩니다. 로그인하면 루트에 각 디렉터리가 이름별로 나열되며 루트 자체에는 쓸 수 없고 파일을 서로 다른 디렉터리 사이로 이동할 수도 없습니다.

**로그인 제한**: WebDAV, FTP, SMB는 접속 주소별로 비밀번호 오류 횟수를 제한합니다. 15분 안에 10번 실패하면 해당 주소의 로그인은 제한 시간이 끝날 때까지 올바른 비밀번호여도 거부됩니다(WebDAV는 `429`, FTP와 SMB는 로그인 실패를 반환하며, SMB는 실행 로그에도 "로그인 실패 횟수가 너무 많아 거부했습니다"를 기록). 로그인에 성공해도 실패 횟수는 초기화되지 않으며, IPv6는 /64 단위로 집계합니다. Gately 웹 서비스 같은 로컬 리버스 프록시를 거쳐 WebDAV에 접속하면 프록시가 전달한 방문자 주소로 집계합니다.

## FTP

「파일 서비스」 그룹의 「FTP 서비스」에서 설정하며 FTP와 FTPS를 지원합니다.

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| `enable` | 꺼짐 | 서비스를 켭니다. 켜려면 사용자가 최소 한 명 필요합니다 |
| `listenIp` | 비어 있음 | 수신 주소이며 비우면 모든 주소에서 수신합니다 |
| `port` | 2121 | 수신 포트 |
| `passiveStart` / `passiveEnd` | 0 | 패시브 모드 데이터 포트 범위. 둘 다 0이면 시스템이 무작위로 할당하고, 입력할 때는 1 ≤ 시작 ≤ 끝 ≤ 65535를 만족해야 하며 방화벽과 포트 매핑에서 이 범위를 열어 두어야 합니다 |
| `publicHost` | 비어 있음 | 패시브 모드에서 외부에 알리는 IP. NAT 뒤에 있을 때 공인 IP 또는 포워딩된 IP를 입력하며 IP 주소만 가능하고, 비우면 연결 주소를 자동으로 사용합니다 |
| `tlsMode` | 0 | 0은 평문과 FTPS 모두 허용, 1은 명시적 FTPS(`AUTH TLS`) 필수, 2는 암시적 FTPS(연결 즉시 암호화)입니다. 0이 아니면 인증서는 [SSL 인증서](/ko/docs/modules/ssl) 모듈이 SNI에 따라 제공합니다 |
| `idleTimeout` | 900 | 연결이 유휴 상태로 몇 초가 지나면 끊을지 |
| `connectionTimeout` | 30 | 데이터 연결을 맺는 타임아웃(초) |
| `disableActiveMode` | 꺼짐 | 패시브 모드만 사용하며 NAT 환경에 더 적합합니다 |
| `users` | 없음 | 다중 사용자이며 필드는 WebDAV와 같습니다: `name`, `password`, `root`, `readOnly` 또는 `mounts`. 사용자 이름은 중복될 수 없습니다 |
| `sharedUsers` | 꺼짐 | [공유 사용자](#shared-users)가 이 서비스에 로그인하도록 허용 |

## SMB

「파일 서비스」 그룹의 「SMB 서비스」에서 설정하며, 로컬 디렉터리를 Windows 파일 탐색기, macOS Finder, Linux, 휴대폰과 TV 의 SMB 클라이언트와 공유합니다. 프로토콜 구현은 Gately 에 내장되어 있으며([gosamba](https://github.com/ahmetozer/gosamba) 기반) SMB 2.0.2 ~ 3.1.1, NTLMv2 인증과 서명을 지원하고 SMB 3 암호화를 필수로 지정할 수 있습니다. SMB 1 은 지원하지 않습니다. Linux 와 macOS 에서만 사용할 수 있습니다.

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| `enable` | 꺼짐 | 서비스를 켭니다. 켜려면 사용자가 최소 한 명 필요합니다 |
| `listenIp` | 비어 있음 | 수신 주소이며 비우면 모든 주소에서 수신합니다 |
| `port` | 445 | 수신 포트. Windows 는 445 에만 연결합니다. fnOS, Synology 등 NAS 에 기본 탑재된 Samba 가 445 를 사용 중이면 다른 포트를 사용하세요. macOS, Linux 와 대부분의 플레이어는 주소에 포트를 지정할 수 있습니다 |
| `requireEncryption` | 꺼짐 | 모든 연결에 SMB 3 암호화를 요구합니다. SMB 2 만 지원하는 오래된 기기와 일부 TV 는 연결할 수 없습니다 |
| `mdns` | 꺼짐 | Bonjour 로 서비스를 알려 macOS Finder 의 '네트워크' 에 표시합니다. Docker에서는 host 네트워크일 때만 동작합니다 |
| `users` | 없음 | 다중 사용자이며 필드는 WebDAV 와 같은 `name`, `password`, `root`, `readOnly` 또는 `mounts` 입니다. 사용자 이름은 대소문자를 구분하지 않으며 중복될 수 없습니다 |
| `sharedUsers` | 꺼짐 | [공유 사용자](#shared-users)가 이 서비스에 로그인하도록 허용 |

공유는 사용자별로 나뉘며, 로그인한 사용자는 자신의 공유만 보고 연결할 수 있습니다.

- **단일 디렉터리**: 공유 이름은 사용자 이름입니다. 예를 들어 사용자 `alice` 의 주소는 `\\192.168.1.2\alice` 입니다.
- **여러 디렉터리**: 각 디렉터리가 하나의 공유이며 `name` 이 공유 이름입니다(같은 사용자 안에서 대소문자 구분 없이 중복 불가). 각각 읽기 전용으로 지정할 수 있습니다. 서로 다른 사용자가 같은 이름의 공유를 가지고 각자 자신의 디렉터리를 가리킬 수 있습니다.

사용자 이름과 공유 이름에는 `" / \ [ ] : ; | = , + * ? < >` 를 포함할 수 없고 `.` 로 시작하거나 끝날 수 없습니다. NTLM 인증에는 평문 비밀번호가 필요하므로 비밀번호가 bcrypt 해시로 저장된 사용자는 다시 설정해야 합니다. 파일은 Gately 프로세스 권한으로 읽고 씁니다.

페이지 아래의 '연결 주소' 에 저장된 설정을 바탕으로 각 공유의 주소가 표시됩니다.

- Windows: 파일 탐색기 주소 표시줄에 `\\호스트\공유이름` 을 입력하거나 `net use Z: \\호스트\공유이름 /user:사용자이름` 을 실행합니다
- macOS: Finder 의 '이동 → 서버에 연결' 에서 `smb://호스트:포트/공유이름` 을 입력합니다(445 포트는 생략 가능)
- Linux: `mount -t cifs //호스트/공유이름 /mnt -o username=사용자이름,port=포트`

클라이언트가 연결되지 않거나 인증에 실패하면 환경 변수 `GATELY_SMB_DEBUG=1`을 설정하고 Gately를 다시 시작하세요. 프로토콜 디버그 로그가 실행 로그에 기록됩니다. 확인이 끝나면 변수를 제거하세요.

## 공유 사용자 {#shared-users}

WebDAV, FTP, SMB는 '공유 사용자' 목록 하나를 함께 씁니다. 필드는 각 서비스의 로컬 사용자와 같고(사용자 이름, 비밀번호, `root`와 `readOnly` 또는 `mounts`) 설정 디렉터리의 `fileusers.json`에 저장됩니다. 공유 사용자는 사이드바 '파일 서비스' 그룹의 '파일 공유 사용자' 페이지에서 한곳에서 관리하며, 저장하면 세 서비스에 동시에 적용됩니다. 각 서비스의 로컬 사용자는 그대로입니다. 페이지 위쪽에는 서비스별 공유 사용자 허용 여부와 로컬 사용자와 이름이 같거나 SMB에서 쓸 수 없는 공유 사용자가 표시됩니다.

- 공유 사용자를 받을지는 서비스마다 정합니다. 서비스 페이지의 '공유 사용자' 카드에서 '공유 사용자 로그인 허용'(필드 `sharedUsers`)을 켜고 저장하면 공유 사용자가 그 서비스에 로그인할 수 있습니다. 카드에는 저장된 공유 사용자도 표시되며 '공유 사용자 관리'를 누르면 '파일 공유 사용자' 페이지로 이동합니다.
- 로컬 사용자와 이름이 같으면 로컬 사용자로만 확인합니다(SMB는 대소문자 구분 안 함).
- 공유 사용자 이름은 대소문자와 관계없이 중복될 수 없고 콜론을 포함할 수 없습니다.
- 공유 사용자 변경은 바로 적용됩니다. WebDAV는 다음 요청부터 새 설정으로 확인하고, FTP와 SMB는 서비스를 다시 시작하므로 연결된 클라이언트는 다시 연결해야 합니다.
- 스위치를 켜고 공유 사용자가 한 명 이상 있으면 로컬 사용자 없이도 서비스를 켤 수 있습니다.
- 공유 사용자만으로 켠 서비스는 변경 후에도 로그인할 수 있는 공유 사용자(SMB는 SMB에 쓸 수 있는 사용자)가 남아 있어야 하며, 그렇지 않으면 저장을 거부합니다.
- `fileusers.json`을 직접 고치다 잘못된 경우(빈 비밀번호, 절대 경로가 아닌 디렉터리 등) 공유 사용자는 모두 로그인할 수 없고 페이지에 경고가 표시됩니다. 수정 후 저장하면 복구됩니다.
- SMB는 평문 비밀번호만 받으며 사용자 이름과 공유 이름은 SMB 문자 규칙을 따라야 합니다. 맞지 않는 공유 사용자는 '파일 공유 사용자' 페이지, SMB 페이지, 실행 로그에 알리고 건너뛰며 WebDAV와 FTP에서는 계속 쓸 수 있습니다.

API는 `GET` / `PUT /api/fileusers`이며 API 토큰에는 `fileusers:read` / `fileusers:write` 권한이 필요합니다. 응답의 `services`에 서비스별 사용 현황이 들어 있습니다. 기존 서비스별 `GET` / `PUT /api/<서비스>/shared-users`는 더 이상 권장하지 않지만 계속 동작하며 같은 목록을 읽고 씁니다. 읽기는 해당 서비스의 읽기 권한을 쓰고, 변경에는 `webdav:write`, `ftp:write`, `smb:write`가 모두 필요합니다.

**비밀번호 직접 변경**: 「파일 공유 사용자」 페이지에서 「비밀번호 직접 변경」을 켜고 저장하면, 공유 사용자가 웹 인증이 켜진 아무 웹 서비스 사이트의 `https://사이트 도메인/__gately_auth/password`에서 사용자 이름, 현재 비밀번호, 새 비밀번호(8~128자)를 입력해 직접 비밀번호를 바꿀 수 있습니다. WebDAV, FTP, SMB는 바로 새 비밀번호를 사용합니다(FTP와 SMB는 서비스를 다시 시작하므로 연결된 클라이언트는 다시 연결해야 합니다). 평문 비밀번호는 평문으로, bcrypt 해시는 해시로 저장되며, 현재 비밀번호 오류는 웹 로그인과 같은 속도 제한·자동 차단에 포함됩니다. 스위치는 `fileusers.json`의 `selfService`에 저장되며 API 필드 이름도 같습니다. 웹 로그인 공유 사용자는 [웹 서비스의 비밀번호 직접 변경](/ko/docs/modules/web#self-service-password)을 참고하세요.

## File Browser {#filebrowser}

"파일 서비스" 그룹의 "File Browser"에서 설정합니다. Gately는 [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser)을 호스팅합니다. 이미지·동영상·문서 미리 보기, 업로드와 다운로드, 공유 링크 생성을 지원하고 자체 사용자와 권한 관리를 갖춘 웹 파일 관리자입니다. 원본 filebrowser/filebrowser는 2026년에 보관 처리되어 더 이상 보안 수정이 없으므로, 유지 관리가 계속되는 Quantum 포크를 호스팅합니다.

프로그램은 Gately에 포함되어 있지 않습니다. 페이지 아래 "온라인 설치" 카드는 GitHub에서 FileBrowser Quantum을 설정 디렉터리의 `bin/filebrowser`로 내려받으며, 업데이트, 버전 지정 설치, 별도 다운로드 프록시, 롤백, 제거를 지원합니다. 업데이트나 롤백 후에는 활성화된 인스턴스가 자동으로 다시 시작합니다. 자세한 내용은 [온라인 설치, 업데이트, 롤백](/ko/docs/modules/tunnels#install)을 참고하세요. 페이지 상단의 "기본 설정 복원"은 모든 인스턴스와 그 데이터를 삭제합니다. [기본 설정 복원](/ko/docs/modules/tunnels#reset)을 참고하세요. 프로그램을 직접 배치하고 경로를 입력할 수도 있습니다. 프로그램은 입력한 경로, 설정 디렉터리의 `bin/`, `PATH` 순서로 찾으며, 찾은 프로그램이 Quantum이 아니면(예: `PATH`의 원본) 페이지에 경고가 표시됩니다.

인스턴스마다 별도의 File Browser 프로세스가 실행됩니다.

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| `listenIp` | 비어 있음 | 수신 주소. 비우면 모든 IPv4 주소에서 수신. Web 서비스 리버스 프록시로만 접속할 때는 `127.0.0.1` |
| `port` | 8080 | 수신 포트 |
| `baseUrl` | `/` | 접속 경로. Web 서비스에서 경로별로 리버스 프록시할 때(예: `/files`) 같은 경로를 입력 |
| `accessUrls` | 비어 있음 | 접속 주소. 여러 개를 지정할 수 있으며 웹 서비스로 리버스 프록시한 `https://files.example.com/` 등을 인스턴스 카드에 표시합니다. 비워 두면 수신 주소와 포트로 추측합니다. 첫 번째 주소의 스킴, 호스트, 포트는 File Browser의 `http.externalUrl`에 기록되어 공유 링크에 사용됩니다 |
| `sources` | 없음 | 공유 디렉터리. 각 항목은 `path`(절대 경로), `name`(표시 이름, 비우면 디렉터리 이름), `readOnly`로 구성. 새 사용자는 기본적으로 모두 접근 가능 |
| `authMethod` | `password` | 로그인 방식: `password` 비밀번호, `proxy` 리버스 프록시가 전달한 사용자 이름 헤더 신뢰, `noauth` 로그인 없음 |
| `proxyHeader` | `Remote-User` | `proxy` 방식에서 사용자 이름을 읽는 헤더. 없는 사용자는 자동 생성 |
| `adminUser` | `admin` | 관리자 사용자 이름 |
| `adminPassword` | 없음 | 관리자 비밀번호. 8자 이상, `password` 방식에서 필수 |
| `trustProxyHeaders` | 꺼짐 | `X-Forwarded-*`와 `X-Real-IP`를 신뢰. 리버스 프록시 뒤에서 켬 |
| `disableWebDav` | 꺼짐 | File Browser 내장 WebDAV 인터페이스 끄기 |
| `locale` | 비어 있음 | 새 사용자의 기본 인터페이스 언어(예: `ko`). 비우면 영어 |
| `tokenHours` | 2 | 로그인 유효 시간(시간) |

- 관리자 비밀번호는 시작할 때마다 File Browser에 동기화되며 Gately의 설정이 우선합니다. 다른 사용자, 공유 링크, 개인 설정은 File Browser에서 관리하며 인스턴스 자체 데이터베이스에 저장됩니다.
- 설정 파일, 데이터베이스, 캐시는 설정 디렉터리의 `filebrowser/<인스턴스 key>/`에 저장되며 설정 파일 권한은 0600입니다. 관리자 비밀번호는 환경 변수로 프로세스에 전달되어 파일에 기록되지 않습니다. 인스턴스를 삭제하면 이 디렉터리도 삭제되고, 공유 디렉터리의 파일은 그대로 남습니다.
- 공유 디렉터리가 없는 인스턴스는 시작하지 않으며 카드에 이유가 표시됩니다.
- 외부 접속은 [Web 서비스](/ko/docs/modules/web)에서 `http://127.0.0.1:포트`를 가리키는 리버스 프록시 사이트를 추가해 HTTPS와 접근 제어로 보호하고 "프록시 헤더 신뢰"를 켜는 방식을 권장합니다. `proxy` 방식은 Web 서비스의 포워드 인증으로 사용자 이름을 헤더에 넣어야 하며, File Browser 포트를 외부에 열면 헤더를 위조해 로그인할 수 있으므로 열지 마세요.
- 파일은 Gately 프로세스의 권한으로 읽고 씁니다.

## 스토리지 마운트

「파일 서비스」 그룹의 「스토리지 마운트」에서 마운트 지점을 추가하고 페이지 안에서 파일을 온라인으로 관리합니다.

| 필드 | 설명 |
| --- | --- |
| `name`, `remark`, `enable` | 이름, 메모, 사용 스위치 |
| `type` | `local`(로컬 디렉터리), `webdav`(원격 WebDAV) 또는 `smb`(SMB 공유) |
| `path` | 로컬 디렉터리이며 이미 존재하는 절대 경로여야 합니다(`local`에서 사용) |
| `url`, `username`, `password` | 원격 주소와 계정. 비밀번호는 UI에서 마스킹됩니다(`webdav`, `smb`에서 사용). WebDAV 주소는 `http://` 또는 `https://`로 시작하고, SMB 주소는 `smb://호스트[:포트]/공유이름[/하위디렉터리]` 형식이며 SMB2/3를 지원합니다. 사용자 이름을 비우면 게스트로 접속합니다 |
| `skipVerify` | HTTPS 인증서 검증을 건너뜁니다(`webdav`에서 사용) |
| `domain` | SMB 인증에 사용할 도메인 또는 작업 그룹. 보통 비워 둡니다(`smb`에서 사용) |
| `readOnly` | 읽기 전용 마운트이며 파일 관리가 모든 쓰기 작업을 거부합니다 |

온라인 파일 관리는 디렉터리 탐색, 파일 다운로드, 스트리밍 업로드(파일 전체를 메모리에 올리지 않음), 디렉터리 생성, 이름 변경, 삭제를 지원합니다. 마운트 지점은 백업 작업의 대상 위치로 쓸 수 있으며 백업 파일은 마운트 지점의 지정한 디렉터리에 기록되고 보관 정책에 따라 오래된 파일이 정리됩니다.

## Wake-on-LAN

「Wake-on-LAN」에서 장치를 관리하며 장치로 매직 패킷(6바이트 `0xFF` 뒤에 MAC을 16번 반복)을 보냅니다.

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| `name` | 없음 | 장치 이름, 필수 |
| `macs` | 없음 | MAC 주소를 한 줄에 하나씩, 최소 하나이며 같은 장치에 여러 개 입력할 수 있습니다 |
| `broadcastIps` | 비어 있음 | IPv4 브로드캐스트 주소. 비우면 `255.255.255.255`와 활성화된 각 네트워크 인터페이스의 브로드캐스트 주소로 전송합니다 |
| `port` | 9 | 대상 UDP 포트 |
| `repeat` | 3 | MAC마다 반복 전송하는 횟수, 상한 20 |
| `checkAddr` | 비어 있음 | 온라인 점검 주소. 형식은 `호스트:포트`이며 예: `192.168.1.10:3389`, 비우면 점검하지 않습니다 |
| `shutdownMode` | 비어 있음 | 원격 종료 방식: `agent`(장치의 에이전트), `ssh`(SSH 명령), `http`(HTTP 요청). 비우면 종료를 지원하지 않음 |
| `shutdownConn` | 비어 있음 | `ssh` 방식에 쓰는 [웹 터미널](/ko/docs/modules/terminal) SSH 연결 |
| `shutdownCommand` | 없음 | `ssh` 방식의 종료 명령, 한 줄(예: `shutdown -h now`, `shutdown /s /t 0`) |
| `agentToken` | 자동 생성 | `agent` 방식의 에이전트 토큰. API에서는 마스킹되어 표시 |
| `shutdownHttp` | 비어 있음 | `http` 방식의 요청: `method`, `url`, `headers`, `body`, `insecure` |
| `bemfaTopic` | 비어 있음 | Bemfa 토픽. 비우면 음성 제어 없음, 다른 장치와 중복 불가 |
| `remark` | 비어 있음 | 메모 |

장치 목록에서 깨우기를 누르면 매직 패킷을 보내고 `checkAddr`에 따라 장치의 온라인 여부를 표시합니다.

### 원격 종료

장치의 "원격 종료"에서 방식을 고르면 장치 카드에 종료 버튼이 나타납니다. API는 `POST /api/wol/devices/{key}/shutdown`이며, 요청 본문은 생략할 수 있고 `{"action": "reboot"}`, `{"action": "sleep"}`으로 재부팅이나 절전도 할 수 있습니다(에이전트 방식만 지원). 같은 장치에서는 한 번에 하나만 실행하며 최대 30초입니다. 종료나 절전에 성공하면 Bemfa 스위치 상태를 꺼짐으로 기록합니다.

| 방식 | 적합한 경우 | 지원하는 작업 |
| --- | --- | --- |
| 에이전트 | Windows, Linux, macOS, OpenWrt. 장치에서 포트를 열거나 SSH를 켤 필요가 없음 | 종료, 재부팅, 절전 |
| SSH 명령 | SSH 서비스가 켜져 있고 웹 터미널에 저장해 둔 호스트 | 종료 |
| HTTP 요청 | Home Assistant, 스마트 플러그, 장치에 이미 있는 종료 도구 등 HTTP 인터페이스를 제공하는 서비스 | 종료 |

#### 에이전트 {#agent}

제어할 장치에서 에이전트 스크립트를 실행합니다. 에이전트가 스스로 Gately에 연결해 롱 폴링으로 지시를 가져오고, 지시를 받으면 해당 장치에서 종료, 재부팅, 절전을 실행합니다. 에이전트는 이 세 가지 고정된 작업만 받아들이며 Gately가 다른 명령을 실행하게 할 수 없습니다. 장치에서 포트를 열 필요가 없고 Gately도 장치의 로그인 자격 증명을 저장하지 않습니다.

1. 장치의 종료 방식을 "에이전트"로 설정하고 저장하면 Gately가 장치용 토큰을 생성하고 설치 안내를 엽니다(이후에는 장치 카드의 "에이전트"에서 다시 열 수 있습니다);
2. "Gately 주소"가 장치에서 접근할 수 있는 관리 페이지 주소인지 확인합니다(기본값은 브라우저의 현재 주소이며, fnOS 통합 게이트웨이로 접속할 때는 직접 접속 주소로 바꿔야 합니다). Gately가 자체 서명 인증서를 쓰면 "인증서 검증 안 함"을 켭니다;
3. 장치의 운영체제를 고르고 설치 명령을 복사해 장치에서 실행합니다:

| 운영체제 | 실행 위치 | 설치 형태 | 로그 |
| --- | --- | --- | --- |
| Windows | 관리자 권한으로 실행한 PowerShell | SYSTEM 계정의 부팅 시 작업 스케줄러 작업 "Gately Agent" | `C:\ProgramData\GatelyAgent\agent.log` |
| Linux | 터미널(sudo와 curl 또는 wget 필요) | systemd 또는 OpenRC 서비스 `gately-agent` | `journalctl -u gately-agent` 또는 `/var/log/gately-agent.log` |
| macOS | 터미널(관리자 비밀번호 필요) | launchd 데몬 `cn.gately.agent` | `/var/log/gately-agent.log` |
| OpenWrt | SSH(root), curl 또는 시스템 기본 wget 사용 가능 | procd 서비스 `gately-agent`, 시스템 업그레이드 시 설정 유지 | `logread -e gately-agent` |

설치 명령은 Gately에서 스크립트를 내려받고(설치 안내에서 직접 내려받을 수도 있습니다) 먼저 SHA-256을 검증합니다(Linux와 OpenWrt는 `sha256sum`, macOS는 `shasum -a 256`, Windows는 `Get-FileHash`). Gately가 제시한 체크섬과 다르면 `gately-agent: checksum mismatch`를 출력하고 중단하며, 일치하면 검증한 그 스크립트를 그대로 설치합니다. 토큰은 요청 본문과 환경 변수로 전달되며 URL에도, 어떤 프로세스의 명령줄 인수에도 나타나지 않습니다. curl과 wget은 `mktemp`로 만든 임시 파일에서 토큰을 읽고, sudo는 `--preserve-env`로 환경 변수를 넘깁니다. 따라서 평문 HTTP나 "인증서 검증 안 함"으로 내려받아도 변조된 스크립트는 실행되지 않습니다. 다만 토큰은 평문으로 전송되므로 HTTPS 주소를 쓰는 것을 권장합니다. 에이전트가 연결되면 장치 카드에 온라인으로 표시되고 에이전트가 보고한 호스트 이름, 운영체제, 접속 출처 주소도 표시됩니다. 에이전트 방식의 장치는 온라인 점검 주소를 입력할 필요가 없습니다.

- 토큰은 해당 장치의 전원 스위치와 같습니다. 설정 파일은 root(Windows에서는 SYSTEM과 관리자)만 읽을 수 있습니다. 같은 토큰은 한 장치에서만 쓸 수 있으며, 다른 기기가 같은 토큰으로 연결하면 거부되고 로그에 안내가 남습니다;
- 지시는 발행 후 10초 동안만 유효합니다. 에이전트가 먼저 확인하고 Gately가 응답한 뒤에 실행합니다. 에이전트가 오프라인이면 바로 오류를 반환하며, 다음에 온라인이 될 때까지 대기열에 쌓아 두었다가 실행하지 않습니다;
- 토큰을 "재생성"하거나 종료 방식을 다른 방식으로 바꾸면 기존 에이전트는 즉시 연결이 끊어지므로 새 명령으로 다시 설치해야 합니다;
- 에이전트는 25초마다 폴링하며, 연결이 끊기면 5초부터 최대 60초 간격으로 재시도합니다;
- 설치 위치: Linux는 `/usr/local/bin/gately-agent`, macOS는 `/Library/Gately/gately-agent`(`/usr/local/bin`은 Homebrew가 일반 사용자에게 넘겨 두는 경우가 많습니다), OpenWrt는 `/usr/bin/gately-agent`입니다. 설치 디렉터리는 root 소유이고 다른 사용자가 쓸 수 없어야 하며, 그렇지 않으면 설치를 거부합니다. Windows는 `C:\ProgramData\GatelyAgent`이며 디렉터리 권한을 SYSTEM과 관리자만 접근할 수 있도록 통째로 바꿉니다. 이 디렉터리가 이미 있는데 링크(정션 또는 심볼릭 링크)이거나 소유자가 SYSTEM·관리자가 아니면 설치를 거부하고, 확인한 뒤 디렉터리를 삭제하라고 안내합니다;
- 제거: 설치 안내에서 제거 명령을 복사합니다. Windows는 `powershell -ExecutionPolicy Bypass -File "$env:ProgramData\GatelyAgent\gately-agent.ps1" uninstall`, Linux는 `sudo sh /usr/local/bin/gately-agent uninstall`, macOS는 `sudo sh /Library/Gately/gately-agent uninstall`, OpenWrt는 `sh /usr/bin/gately-agent uninstall`입니다;
- 절전: Windows는 메모리로 일시 중단합니다(절전을 끈 기기는 실패하며 로그에 안내가 남습니다). Linux는 `systemctl suspend`, macOS는 `pmset sleepnow`를 사용합니다. 절전 중인 장치를 Wake-on-LAN으로 깨우려면 네트워크 어댑터나 시스템에서 Wake-on-LAN을 허용해야 합니다.

에이전트 인터페이스는 `/api/wol/public/agent/` 아래에 있으며 로그인이 필요 없고 장치 토큰만 확인합니다. 보안 진입 경로를 설정한 경우에도 유효한 토큰이 있는 요청은 접근할 수 있고, 「내부망 접근만 허용」과 차단 목록은 그대로 적용됩니다. 관리 인터페이스 `GET /api/wol/agent-scripts`는 각 에이전트 스크립트의 SHA-256을 파일 이름별로 반환합니다.

#### SSH 명령

웹 터미널의 SSH 연결을 고르고 종료 명령을 입력합니다:

- 해당 연결은 웹 터미널에서 한 번 연결해 호스트 키를 기록해 두어야 합니다. Gately는 무인 상태에서 알 수 없는 호스트를 신뢰하지 않습니다;
- 종료할 때마다 새 SSH 연결을 만들고 끝나면 닫으므로 장치가 재부팅되기 전의 끊긴 연결을 쓰지 않습니다;
- 종료하면서 종료 코드가 돌아오기 전에 SSH 연결이 끊기는 경우가 많으며, 이 경우 종료가 시작된 것으로 봅니다;
- 폼에서 Linux(`shutdown -h now`), Windows(`shutdown /s /t 0`), macOS(`sudo -n shutdown -h now`) 명령을 고를 수 있습니다. Windows는 OpenSSH 서버를 켜야 하며, Linux의 root가 아닌 사용자는 `sudo -n shutdown -h now`를 쓰고 이 명령에 비밀번호 없는 sudo를 설정하세요.

#### HTTP 요청

요청 주소(`http://` 또는 `https://`), 메서드, 헤더, 본문을 입력합니다. 응답 상태 코드가 2xx이면 성공으로 보며 응답 내용은 결과에 표시됩니다. 메서드를 "자동"으로 두면 본문이 있을 때 `POST`, 없으면 `GET`을 사용하고, 본문이 `{` 또는 `[`로 시작하고 `Content-Type`을 지정하지 않았으면 JSON으로 보냅니다. 자격 증명(`Authorization: Bearer …` 등)은 헤더에 넣습니다. 읽기 전용 계정에는 값이 마스킹되어 보이며 로그의 주소에는 쿼리 매개변수가 포함되지 않습니다. 대상이 자체 서명 인증서를 쓰면 "인증서 검증 안 함"을 켤 수 있습니다.

API 토큰으로 장치를 추가·수정·복사하거나 종료를 실행하려면 `wol:write` 외에 `webterminal:write`도 필요합니다(SSH 방식은 SSH 연결로 실행할 명령을 설정하거나 실행할 수 있습니다). 선택 가능한 SSH 연결 목록에는 `wol:read`와 `webterminal:read`가 필요하며, 에이전트 토큰 조회(`GET /api/wol/devices/{key}/secrets`)와 재생성(`POST /api/wol/devices/{key}/agent-token`)에는 `wol:write`가 필요합니다.

### Bemfa 음성 제어 {#bemfa}

[Bemfa](https://cloud.bemfa.com)를 연동하면 Xiao AI, Xiaodu, Google Assistant 같은 음성 비서로 장치를 켜고 끌 수 있습니다:

1. Bemfa 콘솔의 MQTT 장치 클라우드에서 이름이 `001`(콘센트) 또는 `006`(스위치)으로 끝나는 토픽을 만듭니다(예: `pc001`);
2. 장치에 같은 토픽을 입력하고 "Wake-on-LAN → Bemfa"에서 콘솔의 사용자 개인 키를 입력해 켭니다;
3. Mi Home(Xiao AI), Xiaodu 등의 앱에서 Bemfa 계정을 연결하고 장치를 동기화합니다.

이후 "켜기"는 장치를 깨우고 "끄기"는 원격 종료합니다(원격 종료 설정 필요). 성공하면 켜짐/꺼짐 상태를 Bemfa에 다시 기록합니다. Gately는 MQTT 3.1.1 over TLS로 `bemfa.com:9503`에 연결하고 인증서를 검증합니다. 개인 키는 클라이언트 ID로 이 암호화 연결에서만 쓰이며 API에서는 가려서 표시합니다. 연결이 끊기면 5초부터 최대 5분 간격으로 다시 연결합니다. 구독 시 서버가 다시 보내는 이전 상태(보존 메시지와 구독 후 3초 안에 받은 메시지)는 실행하지 않으며, 10초 안에 반복된 같은 명령은 한 번만 실행합니다. 화면이나 API에서 깨우기·종료에 성공해도 상태를 다시 기록합니다. 같은 개인 키로는 클라이언트 하나만 온라인일 수 있으며, 다른 프로그램이나 다른 Gately가 같은 키로 연결하면 서로 연결을 끊어 냅니다.

## 예약 작업

cron 표현식에 따라 정해진 시간에 명령을 실행하거나 HTTP 요청을 보냅니다.

- `spec`은 표준 5필드 표현식, 선택 사항인 초 필드(6필드, 예: `*/30 * * * * *`), `@every 10m`, `@daily` 같은 디스크립터를 지원합니다.
- `type`이 `command`이면 `sh -c`(Windows는 임시 `.bat`)로 `command`를 실행하며 환경 변수에 `taskName`과 `GATELY_` 접두사가 붙은 같은 이름의 대문자 변수를 주입합니다.
- `type`이 `http`이면 `http` 설정에 따라 요청을 보내며 필드는 `url`, `method`(GET, POST, PUT, PATCH, DELETE), `headers`(항목마다 `Key: Value`), `body`, `successContent`(응답 본문에 이 중 하나라도 포함되어야 성공이며 비우면 2xx만 확인), `timeout`, `insecureSkipVerify`, `proxy`(비우면 프록시를 지정하지 않고, `update`는 전역 업데이트 프록시를 사용하며, `http://`, `https://`, `socks5://` 프록시 주소도 쓸 수 있음)입니다.
- 작업을 켜거나 끌 수 있고 페이지에 다음 실행 시간이 표시되며 수동으로 즉시 실행할 수도 있습니다.
- 같은 작업의 이전 실행이 아직 끝나지 않았으면 이번 실행은 건너뜁니다.
- 작업마다 최근 20회의 실행 기록을 보관하며 시작 시간, 소요 시간, 성공 여부, 수동 실행 여부, 출력(최대 4000자 요약)이 포함됩니다.
- 생성 폼은 표현식 파싱 검증을 제공합니다.

## 개요와 시스템 로그

- 「개요」 페이지에는 호스트 정보(CPU 모델, 사용률과 부하, 메모리, 디스크, 네트워크 인터페이스 주소와 실시간 속도, 공인 IPv4와 IPv6(누르면 복사)), 각 모듈의 서비스 상태, Gately 프로세스의 버전, 커밋, 빌드 시간, 시작 시간, PID, CPU, 상주 메모리, Go 힙과 고루틴 수가 표시됩니다.
- Gately가 외부 프로그램(frp, Tailscale, NetBird, Cloudflare 터널, File Browser)을 관리할 때는 「개요」 페이지에 「관리 프로세스」 카드가 추가로 표시되어 각 프로세스의 모듈과 인스턴스, 프로그램 이름, PID, 실행 시간, 재시작 횟수, CPU, 상주 메모리를 나열하고 카드 머리글에 합계를 보여 줍니다. 행을 누르면 해당 모듈로 이동합니다. 프로세스 자체만 집계하며 그 프로세스가 시작한 하위 프로세스는 포함하지 않고, 경로와 실행 인수도 표시하지 않습니다.
- 「시스템 로그」 페이지에는 Docker, FTP, 예약 작업 등을 포함한 각 모듈의 실행 기록이 모여 표시됩니다.

## 테마

UI는 15개 팔레트를 Gately 오리지널(에메랄드, 오션, 프레시, 벚꽃, 노을, 미드나이트, 펑크)과 클래식(GitHub, Nord, Dracula, Catppuccin, Tokyo Night, Gruvbox, Rosé Pine, Solarized) 두 그룹으로 제공하며, 모든 팔레트에 라이트와 다크 버전이 있습니다. 모드는 라이트, 다크, 시스템 따라가기 중에서 고를 수 있고, 시스템 따라가기는 현재 팔레트의 라이트 또는 다크 버전을 사용합니다. 어느 팔레트든 강조색을 10가지 프리셋 중 하나나 시스템 색상 선택기로 바꿀 수 있으며, 로고와 로그인 페이지 그라데이션도 함께 바뀝니다. 팔레트를 다시 선택하면 사용자 강조색은 해제됩니다. 모서리는 직각, 팔레트 기본값, 둥글게 중에서 고를 수 있습니다. 테마 설정은 브라우저에 로컬로 저장됩니다.
