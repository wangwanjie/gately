# Tailscale / frp / cloudflared

세 모듈은 공식 프로그램을 프로세스로 관리하는 방식으로 통합되어 있습니다. 자동 재시작, 로그의 UI 집계, UI에서의 설정을 지원합니다. Gately 본체에는 이 프로그램들이 내장되어 있지 않으며, 페이지에서 온라인으로 설치, 업데이트, 롤백할 수 있습니다.

## 온라인 설치, 업데이트, 롤백 {#install}

frp, Cloudflare 터널, Tailscale, [File Browser](/ko/docs/modules/tools#filebrowser) 페이지 하단에는 모두 「온라인 설치」 카드가 있습니다.

- **다운로드 및 설치 / 최신 버전으로 업데이트**: 업스트림에서 최신 안정 버전을 내려받아 업스트림에 기록된 SHA-256으로 검증하고, 이 기기에서 실행되는지 확인한 뒤 설정 디렉터리의 `bin/`에 설치합니다. 완료되면 해당 프로그램을 사용하는 프로세스를 자동으로 다시 시작합니다. 이미 최신 버전이면 다시 내려받지 않습니다.
- **버전 지정 설치**: 버전 번호(예: frp `v0.65.0`, cloudflared `2025.8.0`, Tailscale `1.90.2`)를 입력합니다. 다운그레이드에도 쓸 수 있습니다.
- **다운로드 프록시**: 프로그램마다 따로 설정할 수 있고 http, https, socks5를 지원하며 설치를 시작할 때 저장됩니다. 비워 두면 「설정」의 업데이트 프록시를 사용합니다.
- **이전 버전과 롤백**: 업데이트나 롤백으로 교체된 버전은 `bin/.versions/`에 최대 3개까지 보관됩니다. 새 버전에 문제가 있으면 목록에서 「롤백」을 누르면 되돌아가며, 현재 버전도 함께 보관되므로 나중에 다시 전환할 수 있습니다.
- **제거**: `bin/`에 설치된 프로그램과 모든 이전 버전을 삭제하며, 모듈 설정은 유지됩니다. 이후 해당 프로그램을 사용하는 프로세스가 다시 시작되며, `PATH`에 같은 이름의 프로그램이 있으면 그것을 사용하고 없으면 실행할 수 없습니다.

| 프로그램 | 출처 | 설치되는 파일 |
| --- | --- | --- |
| frp | GitHub fatedier/frp | `frpc`, `frps` |
| cloudflared | GitHub cloudflare/cloudflared | `cloudflared` |
| Tailscale | pkgs.tailscale.com 정적 패키지, Linux 전용 | `tailscale`, `tailscaled` |
| FileBrowser Quantum | GitHub gtsteffaniak/filebrowser | `filebrowser` |

Tailscale은 macOS와 Windows용으로 바로 실행 가능한 패키지가 없으므로 공식 설치 프로그램을 사용한 뒤 설정에 경로를 입력하세요. 현재 플랫폼이 지원되지 않으면 카드에 안내가 표시됩니다.

## 기본 설정 복원 {#reset}

페이지 상단의 「기본 설정 복원」은 제거와 별개로 동작합니다. 해당 모듈의 모든 프로세스를 중지하고, 설정(프로그램 경로와 다운로드 프록시 포함)을 기본값으로 되돌리며, Gately가 생성한 파일을 삭제합니다. 설치된 프로그램은 유지됩니다.

| 모듈 | 삭제되는 내용 |
| --- | --- |
| frp | 모든 frpc / frps 인스턴스, 프록시와 프로그램 설정, `frp/`에 생성된 설정 파일 |
| Cloudflare 터널 | 모든 터널과 프로그램 설정 |
| Tailscale | 모든 설정, 기본 상태 디렉터리의 로그인 상태. Gately가 관리하는 tailscaled가 실행 중이면 먼저 로그아웃합니다. 사용자 지정 상태 디렉터리와 시스템에 이미 있는 tailscaled는 그대로 둡니다 |
| File Browser | 모든 인스턴스와 프로그램 설정, 각 인스턴스의 사용자, 공유 링크, 캐시. 공유 디렉터리의 파일은 그대로 유지됩니다 |

이전 설정은 [설정 기록](/ko/docs/guide/audit)에 보관되므로 실수로 초기화했을 때 복원할 수 있습니다. 완전히 정리하려면 먼저 프로그램을 제거한 뒤 기본 설정을 복원하세요. API는 `DELETE /api/{module}/install`(제거)과 `POST /api/{module}/reset`(기본 설정 복원)입니다.

## 프로그램 배치

다음 순서로 실행 파일을 찾습니다.

1. 모듈 설정에 입력한 경로
2. 설정 디렉터리 아래의 `bin/` 하위 디렉터리(온라인 설치 위치)
3. `PATH`

경로를 입력하면 온라인 설치한 버전은 적용되지 않으며 카드에 안내가 표시됩니다. 바이너리를 설정 디렉터리에 직접 넣을 수도 있으며, Docker 배포에서는 예를 들어 `./gately-data/bin/frpc`입니다. Tailscale은 `tailscale`과 `tailscaled`가 모두 필요합니다. 시스템에 이미 있는 tailscaled를 사용할 때는 설치한 `tailscale` 명령을 데몬과 같은 버전으로 맞추는 것이 좋습니다.

토큰과 키는 0600 권한으로 저장되며 cloudflared의 토큰은 환경 변수로 전달되어 프로세스 목록에 나타나지 않습니다.

## Tailscale

- `tailscaled`를 관리하거나(사용자 공간 네트워킹, 컨테이너 친화적) 시스템에 이미 있는 데몬에 연결합니다.
- 인증 키 또는 로그인 링크를 사용하며 Headscale을 지원합니다.
- 서브넷 라우트와 출구 노드
- 노드 목록과 SOCKS5 프록시
- WireGuard UDP 포트 고정: 방화벽에서 직접 연결을 허용하기 쉽습니다.
- tailscaled 추가 인자와 환경 변수. 호스트 iptables가 nf_tables 백엔드라면 환경 변수에 `TS_DEBUG_FIREWALL_MODE=nftables`를 추가해야 서브넷 포워딩이 동작합니다.

## frp

- **frpc 클라이언트**: frpc 인스턴스를 여러 개 추가할 수 있으며, 각 인스턴스는 frps 한 대에 연결되어 독립적으로 실행되고 따로 켜고 끄거나 재시작할 수 있습니다. 프록시는 인스턴스에 속하며 tcp / udp / http / https / stcp / xtcp를 지원하고, 프록시를 바꾸면 해당 인스턴스만 재시작됩니다
- **프록시 접속 주소**: frpc는 frps의 HTTP / HTTPS 포트와 서브도메인 루트 도메인을 알지 못하므로 frpc 인스턴스의 **접속 주소**에 입력합니다(이 기기에 frps 인스턴스가 있으면 한 번에 채울 수 있고, frps 앞에 리버스 프록시나 CDN이 있으면 방문자가 실제로 쓰는 프로토콜과 포트를 입력). 입력하면 http / https 프록시의 도메인(서브도메인으로 만든 전체 도메인 포함)을 클릭해 열고 전체 URL을 복사할 수 있으며, 입력하지 않으면 그대로 텍스트로 표시합니다. 접속 주소는 링크 생성에만 쓰이며 바꿔도 frpc는 재시작하지 않습니다. 사용자 지정 도메인은 웹 서비스와 마찬가지로 소문자와 punycode로 저장하고 포트나 경로가 들어간 값은 거부합니다. 서브도메인은 frps 요구대로 `nas`처럼 한 단계 이름만 쓸 수 있습니다.
- **frps 서버**: 서로 다른 포트로 frps 인스턴스를 여러 개 추가할 수 있으며, 각각 포트 허용 목록, 서브도메인, 대시보드를 가집니다
- **이전 버전에서 업그레이드**: 0.5.9 이하 버전의 단일 frpc / frps 설정은 `frpc` / `frps`라는 인스턴스로 자동 이전되며, 기존 프록시는 그 frpc 인스턴스에 속하고 프로그램 경로는 페이지 아래쪽 「프로그램」 카드로 옮겨집니다
- **frps 수신 주소**: '수신 주소'는 frpc 연결 포트가 수신할 주소, '프록시 수신 주소'는 HTTP / HTTPS 포트와 tcp / udp 프록시 원격 포트가 수신할 주소이며, 비워 두면 모든 주소에서 수신합니다. frps를 Gately 같은 리버스 프록시 뒤에 둘 때는 수신 주소를 `127.0.0.1`로 하고, 웹 서비스에서 사이트 하나를 `127.0.0.1:<바인드 포트>`로 리버스 프록시한 뒤 frpc 전송 프로토콜을 websocket 또는 wss로 골라 그 사이트에 연결합니다. 프록시 수신 주소를 비워 두면 tcp 프록시 원격 포트는 그대로 외부에 열립니다. frps 설정을 가져올 때 원래 설정에 `proxyBindAddr`가 없으면 frps와 마찬가지로 `bindAddr`를 따릅니다.
- **frps 출발지 IP 접근 제어**: frps 인스턴스마다 허용 목록이나 차단 목록을 설정해 출발지 IP로 frpc 로그인(바인드 포트 연결) 허용 여부를 정할 수 있습니다. 목록은 직접 입력한 IP / 대역과 웹 서비스의 구독 IP 목록으로 이루어지며, 하나라도 일치하면 목록에 있는 것으로 봅니다. 구독 목록은 웹 서비스 모듈이 주기적으로 내려받고, 갱신되면 frps를 재시작하지 않고 바로 적용되며, 첫 다운로드 전에는 빈 목록으로 처리됩니다. 판단은 frps가 토큰을 검증하기 전에 이루어집니다. Gately가 루프백 주소에 검사 엔드포인트를 열고 생성하는 frps 설정 끝에 `[[httpPlugins]]`(`ops = ["Login"]`)를 써 넣으므로 frpc 로그인에만 적용되고, tcp / udp 프록시 원격 포트와 HTTP / HTTPS 포트는 그대로 외부에 열립니다. 침입 방지 차단이 목록보다 우선합니다. 차단된 주소는 허용 목록 대역 안에 있어도 로그인할 수 없고, 접근 제어를 설정하지 않은 인스턴스도 차단 목록을 따르며, 방화벽 동기화 사용 여부와 관계없습니다. 거부된 frpc는 `gately: client address ... is not in the allowlist` 같은 오류를 받고, 인스턴스 카드에는 Gately 시작 이후 거부 횟수가 표시됩니다. 목록은 frpc가 로그인할 때 검사하며 frpc가 frps 바인드 포트에 연결하는 부분에 적용됩니다. 목록을 좁히거나 주소가 차단되어도 이미 로그인한 frpc는 연결을 유지하고 다음 로그인 때 거부되므로, 바로 적용하려면 해당 frps 인스턴스를 재시작하세요. stcp / xtcp의 visitor 연결은 로그인 검사를 거치지 않으므로, 제한하려면 [침입 방지](/ko/docs/modules/guard)의 방화벽 동기화를 함께 사용하세요. frps를 리버스 프록시 뒤에 둘 때(수신 주소 `127.0.0.1`)는 frps가 보는 출발지가 프록시 주소이므로 IP 접근 제어는 웹 서비스 사이트에서 설정하세요. 프로토콜 라우팅이나 포트 포워딩 뒤에 두면 frps가 보는 출발지가 로컬 주소가 되어 목록으로 방문자를 구분할 수 없으므로, 라우팅이나 포워딩 규칙에서 출발지 IP 접근 제어를 설정하세요.
- **기존 설정 가져오기**: 페이지 상단의 「설정 가져오기」는 이전 형식의 `frpc.ini` / `frps.ini`(`[common]` 섹션 포함)와 frp 0.52+의 `toml`을 지원하며, 파일을 선택하거나 내용을 붙여넣고 기존 인스턴스 또는 새 인스턴스로 가져올 수 있습니다. 먼저 해석 결과와 무시된 필드를 미리 본 뒤 가져오기를 확정합니다. 기존 frpc 인스턴스로 가져올 때는 추가(같은 이름의 프록시는 그대로 유지) 또는 해당 인스턴스의 모든 프록시 교체를 선택할 수 있습니다. 기존 인스턴스는 활성화 상태가 유지되고 새 인스턴스는 비활성 상태로 만들어집니다. API `POST /api/frp/import`로도 호출할 수 있습니다. Lucky에서 이전하면 Lucky의 각 frpc / frps 인스턴스가 각각 Gately 인스턴스로 가져와집니다.

## Cloudflare 터널

- 토큰 터널과 trycloudflare 임시 터널
- 다중 터널, 자동 재시작
- 공인 주소 표시

### 라우팅 규칙 {#cloudflared-ingress}

토큰 터널의 공개 호스트 이름과 원본 서비스(라우팅 규칙)는 Cloudflare에 저장되며 실행 중인 cloudflared가 자동으로 가져옵니다. 터널 설정에서 선택 사항인 **API 토큰**을 입력하면 카드의 '라우팅'에서 바로 편집할 수 있습니다.

- 토큰에는 'Cloudflare Tunnel: 편집' 권한이 필요하며, DNS 레코드를 자동으로 만들려면 해당 영역의 'DNS: 편집' 권한도 필요합니다. 계정과 터널 ID는 터널 토큰에서 읽어 옵니다.
- 각 규칙은 호스트 이름, 선택 사항인 경로 정규식, 서비스(`http://localhost:8080`, `ssh://localhost:22`, `http_status:404` 등)로 이루어지며, 순서대로 비교하여 처음 일치한 규칙으로 전달합니다. '원본 인증서 검증 건너뛰기'와 원본 Host 헤더를 설정할 수 있고, 기타 원본 설정은 그대로 유지됩니다. 일치하는 규칙이 없으면 기본 서비스를 사용하며 기본값은 `http_status:404`입니다.
- 저장하면 바로 적용되며 터널을 다시 시작할 필요가 없습니다. 그 사이 Cloudflare 콘솔 등에서 규칙이 변경되었다면 덮어쓰지 않도록 저장 시 알리고 '다시 불러오기'를 표시합니다. HTTP 계열 서비스에는 경로를 붙일 수 없으며, 끝에 단독으로 붙은 `/`(예: `http://nas:5000/`)는 저장할 때 자동으로 제거됩니다. 그대로 두면 cloudflared가 설정 전체를 거부합니다.
- 터널이 로컬 설정 파일로 관리되는 경우(화면에 원격 규칙이 적용되지 않는다고 표시됨) 저장 전에 한 번 더 확인합니다. 원격 설정을 쓰면 터널은 원격 관리로 바뀌고 로컬 설정 파일의 라우팅 규칙은 더 이상 적용되지 않습니다.
- 'DNS 동기화'를 켜면 호스트 이름마다 `<터널ID>.cfargotunnel.com`을 가리키는 프록시 CNAME 레코드를 만듭니다. 이미 다른 레코드가 있거나, 터널을 가리키지만 프록시가 꺼진 CNAME(이 경우 트래픽이 터널로 들어가지 않음)이 있는 호스트 이름은 그대로 두고 결과에 표시합니다. 도메인은 터널이 속한 계정에서만 찾습니다. 규칙을 삭제해도 DNS 레코드는 남으므로 필요하면 Cloudflare에서 삭제하세요.
