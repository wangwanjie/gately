# 보안 모델 및 개인정보 약속

Gately는 네트워크 경계에서 동작하며 DNS 제공자 키, 인증서 개인 키, 각종 자격 증명을 다룹니다. 따라서 보안과 투명성이 최우선 설계 목표입니다.

## 개인정보 약속

- **프로젝트 서버에 연결하지 않음**: 기기 정보를 보고하지 않고 원격 설정을 내려보내지 않습니다. 기본적으로 12시간마다 GitHub 의 릴리스 목록과 보안 공지를 익명으로 읽는데, 새 버전과 보안 업데이트를 알리는 용도로만 쓰이며 끌 수 있습니다. 자세한 내용은 [자동 업데이트 확인](/ko/docs/guide/install#update-check)을 참고하세요.
- **외부 주소를 확인하고 수정 가능**: 공인 IP 조회, STUN 서버 등의 주소가 모두 UI에 표시되며 수정하거나 끌 수 있습니다.
- **서드파티 로그인의 자율성**: GitHub, Google, QQ, OIDC 로그인은 직접 발급받은 OAuth 앱을 사용하며 어떤 중계도 거치지 않습니다.
- **직접 하는 업그레이드**: 프로그램이 백그라운드에서 스스로 내려받거나 교체하지 않습니다. Linux 바이너리 설치의 온라인 업그레이드는 관리자가 클릭한 뒤에만 실행되며 SHA-256을 대조하고 이전 버전을 보관합니다. 업그레이드 시점은 사용자가 정합니다.

## 데이터 보호

- 설정은 권한 0600의 일반 JSON이라 감사하고 롤백할 수 있습니다.
- 민감한 필드는 API 출력에서 마스킹됩니다. 화면의 눈 모양 버튼을 누르면 저장된 평문을 가져오며 쓰기 권한이 필요합니다. bcrypt 해시로 저장된 웹 사용자 비밀번호, OIDC 클라이언트 시크릿, 개인 키는 반환하지 않습니다. 2단계 인증을 켠 공유 사용자는 QR 코드를 다시 볼 수 있습니다. Docker 컨테이너의 환경 변수, 시작 명령, 프로세스 명령줄도 같은 방식으로 처리하며, Docker 쓰기 권한이 없으면 `********`로 표시합니다.
- cloudflared의 토큰은 환경 변수로 전달되어 프로세스 목록에 나타나지 않습니다. frp와 Tailscale의 토큰과 키는 0600 권한으로 저장됩니다.

## 인증 및 접근 제어

- bcrypt 비밀번호 해시와 HMAC 서명 세션 토큰
- 세션 폐기: 로그아웃하면 현재 세션 토큰이 서버에서 폐기되어 유출된 토큰도 즉시 무효가 됩니다. "설정 > 계정 및 보안 > 로그인 세션"의 "모든 기기에서 로그아웃"은 모든 관리 화면 세션을 무효화합니다(API 토큰은 영향받지 않음). 비밀번호 변경, 2단계 인증 켜기와 끄기, 비밀번호 재설정도 모든 세션을 무효화합니다. 폐기 기록은 계정 파일에 저장되어 재시작 후에도 유지되고, 토큰이 만료되면 정리되며, 개수에는 상한이 있습니다.
- 외부 요청 제한: "설정 > 네트워크 및 실행"의 "외부 요청 제한"은 기본적으로 꺼져 있습니다. 켜면 관리자가 설정한 외부 요청(웹훅, 알림, IP 목록 구독, DDNS 콜백 및 IP 조회 주소, 업데이트 확인과 프로그램 다운로드, 서드파티 로그인 등)이 루프백, 사설망, 링크 로컬(클라우드 메타데이터 주소 169.254.169.254 포함), ULA 주소로 연결하지 못하도록 거부하며, 도메인 해석 결과와 리디렉션에도 적용됩니다. 리버스 프록시 업스트림, Wake-on-LAN, 스토리지 마운트 등 내부망 대상 기능에는 영향이 없습니다.
- 느린 요청 방어: 관리 포트는 요청 본문을 읽는 속도를 제한합니다. 일반 엔드포인트는 60초 안에 본문을 받아야 하고, 대용량 파일 엔드포인트(백업 복원, 업그레이드 패키지, 파일 업로드)는 전체 시간 제한이 없지만 최소 평균 속도(초당 4 KiB)로 계속 전송해야 하며, 느리게 보내 연결을 붙잡는 클라이언트는 연결이 끊깁니다.
- 비밀번호 규칙: 관리자 비밀번호는 10~72바이트이며, 흔한 취약한 비밀번호(앞뒤에 숫자나 기호를 붙이거나 `p@ssw0rd`처럼 문자를 바꾼 변형 포함), gately나 사용자 이름을 포함한 비밀번호, 연속 문자(`123456`, `qwerty` 등), 반복 문자나 반복 구간, 한 종류의 문자로만 된 비밀번호를 거부합니다(16자 이상의 패스프레이즈는 문자 종류 요구를 완화). 입력하는 동안 강도를 실시간으로 표시합니다
- 비밀번호 강제 변경: 기본 비밀번호 `gately.cn`은 공개되어 있습니다. 관리자가 기본 비밀번호나 강도가 부족한 비밀번호를 계속 사용하고 있으면 로그인 후 닫을 수 없는 비밀번호 변경 대화 상자가 나타나며, 변경해야 계속 사용할 수 있습니다. 그 전까지 로그인 세션의 쓰기 작업은 비밀번호 변경, 화면 언어 전환, 모든 기기에서 로그아웃을 제외하고 모두 서버에서 거부됩니다. API 토큰은 계속 호출할 수 있지만 계정, 2단계 인증, 패스키, 추가 계정, API 토큰, 시스템 설정, 웹 터미널 보안 설정은 변경할 수 없습니다(백업 복원과 시스템 설정·웹 터미널의 이전 버전 롤백도 거부됩니다). 새 비밀번호로 기본 비밀번호를 쓸 수 없고, 변경한 뒤 다시 되돌릴 수도 없습니다
- 재설정: 비밀번호를 잊었거나 2단계 인증기를 잃어버렸을 때는 서버에서 `gately reset-password` / `gately reset-totp`로만 재설정할 수 있습니다(설정 디렉터리 읽기·쓰기 권한과 `yes` 입력 확인 필요). 재설정하면 모든 세션이 무효화되고 감사 로그에 기록됩니다. 자세한 내용은 [비밀번호와 2단계 인증 재설정](/ko/docs/guide/install#reset)을 참고하세요
- 패스키(WebAuthn) 로그인: 공개 키만 저장하고 사용자 확인(지문, 얼굴 인식 또는 PIN)을 강제하며 서명 카운터로 복제를 막습니다. 도메인과 HTTPS(또는 localhost)로 접속해야 합니다
- 2단계 인증(TOTP, RFC 6238 테스트 벡터로 검증)
- 읽기 전용 계정: 상태와 설정을 볼 수 있지만 수정, 백업 다운로드, 비밀 값 읽기, 터미널 열기는 할 수 없습니다. 비밀번호를 재설정하거나 계정을 삭제하면 세션이 즉시 무효화됩니다; 읽기 전용 계정과 읽기 권한만 있는 API 토큰이 설정을 읽을 때 사이트 공유 사용자 비밀번호, 공유 링크 토큰, 요청·응답 헤더 값, 각종 비밀 값, URL 안의 비밀번호와 쿼리 값은 `********`로 표시됩니다 「감사 로그」「설정 기록」「API 토큰」「설정」은 관리자 전용이며 읽기 전용 계정의 사이드바와 메뉴에는 표시되지 않고, 링크를 직접 열면 개요로 돌아갑니다;
- 읽기 전용 계정과 읽기 권한만 있는 API 토큰은 명령과 스크립트, 관리 대상 프로그램의 추가 시작 인수와 환경 변수, 웹훅 등 HTTP 요청의 본문, 그리고 DNS 제공업체 자격 증명에서 엔드포인트나 요청 메서드 같은 설정을 제외한 추가 필드(예: 사용자 지정 콜백의 헤더와 본문)도 볼 수 없습니다.
- 로그인 실패 제한과 점진적 잠금: 같은 출처가 연속으로 실패해 한도에 도달하면 잠기며, 반복해서 잠길 때마다 잠금 시간이 두 배로 늘어나 최대 24시간까지 길어집니다
- 낯선 출처 실패 예산: 10분 동안 로그인에 성공한 적 없는 모든 주소의 로그인 실패가 누적해서 예산(「설정 → 계정 및 보안」의 「낯선 주소 실패 예산」, 설정 항목 `loginGlobalLimit`, 기본값 20, -1이면 끔)에 도달하면 낯선 주소의 비밀번호 로그인이 일시적으로 429를 반환하고 「인증: 분산 무차별 대입 의심」 알림 이벤트가 발생합니다. 로그인에 성공한 적 있는 주소는 영향을 받지 않으며, 많은 주소에 분산된 무차별 대입을 막기 위한 장치입니다. 패스키 로그인은 출처별 제한을 별도로 사용하며 비밀번호 실패와 낯선 출처 예산의 영향을 받지 않습니다
- 비밀번호 로그인 끄기: 패스키를 등록하면 「설정 → 계정 및 보안」의 패스키 카드에서 비밀번호 로그인을 끌 수 있습니다. 그 뒤 관리자 계정은 패스키나 서드파티 로그인만 사용할 수 있어 비밀번호 무차별 대입이 불가능해집니다(읽기 전용 계정은 영향 없음). 꺼진 상태에서는 마지막 패스키를 삭제할 수 없으며, 패스키를 모두 잃어버렸을 때 서버에서 `gately reset-password`를 실행하면 비밀번호 로그인이 다시 켜집니다
- 보안 점수: 「설정 → 계정 및 보안」 상단의 보안 점수(`GET /api/system/security`)는 현재 설정을 기준으로 일곱 항목을 점검해 0~100점을 매깁니다. 관리자 비밀번호(35점), 2단계 인증(TOTP 또는 패스키, 20점), 보안 진입 경로(15점), 로그인 실패 잠금 정책(10점), HTTPS(10점), 낯선 주소 실패 예산(5점), admin 같은 흔한 이름을 쓰지 않는 관리자 사용자 이름(5점)입니다. 관리 화면이 공인망에 노출되지 않았을 때(내부망 전용 접근이거나 루프백 주소에서만 대기)는 보안 진입 경로, HTTPS, 사용자 이름 세 항목을 만점으로 처리합니다. 높은 위험이나 보안 강화 권장 사항이 있으면 관리 UI 상단에 안내가 표시되고(보안 강화 권장 안내는 7일 동안 미룰 수 있음), 「보안 강화」를 누르면 해당 설정으로 이동합니다
- 이 호스트의 리버스 프록시: 관리 UI를 이 호스트의 nginx, haproxy 또는 Gately 웹 서비스 뒤에 두면 이 호스트 주소에서 온 `X-Real-IP` / `X-Forwarded-For`만 신뢰합니다. 내부망 전용 접근, 로그인 제한, 감사 로그는 이를 바탕으로 실제 출처를 얻습니다. 「설정 → 접근 제어」에서 끄거나 추가 신뢰 프록시를 지정할 수 있습니다; 두 헤더가 서로 다르면 프록시가 덧붙인 `X-Forwarded-For`를 우선하며, 하나가 내부 주소이고 다른 하나가 공인 주소이면 공인 주소를 사용하므로 내부 주소를 위조해도 내부망 전용 접근을 우회할 수 없습니다. 프록시에서 두 헤더를 모두 설정하세요(nginx: `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`)
- 보안 진입 경로, 내부망 전용 접근, 관리 UI의 HTTPS. 로그인이 필요 없는 모듈 API(`/api/<모듈>/public`, 예: [Wake-on-LAN 에이전트](/ko/docs/modules/tools#agent))는 유효한 장치 자격 증명이 있으면 보안 진입 경로를 통과하며, 차단과 내부망 전용 접근 제한은 그대로 적용됩니다
- 미승인 접근 응답: 차단된 출처, 내부망 전용일 때의 외부 접근, 보안 진입 경로를 거치지 않은 요청에 대해 일반 404, 빈 페이지, 연결 끊기, 시간 초과까지 응답 안 함, 사용자 지정 페이지 중 하나로 응답하도록 바꿔 관리 포트의 특징을 숨길 수 있습니다. 자세한 내용은 [보안 강화 가이드](/ko/docs/guide/hardening)를 참고하세요.
- fnOS 통합 게이트웨이: fnOS 패키지를 fnOS 통합 게이트웨이로 접속하면 fnOS가 접근을 제어하며 fnOS 관리자만 열 수 있습니다. 「fnOS 로그인 상태로 자동 로그인」은 기본적으로 꺼져 있으며, 켜면 로그인한 fnOS 관리자가 Gately 관리자로 들어오고(2단계 인증 생략) 일반 fnOS 사용자는 여전히 로그인해야 합니다. 자세한 내용은 [fnOS 네이티브 앱](/ko/docs/guide/install#fnos)을 참고하세요.
- fnOS 통합 게이트웨이를 통해 접근할 때 상태를 변경하는 요청과 WebSocket 연결은 관리 화면 자체 페이지에서 보낸 것만 받습니다. 브라우저가 동일 출처라고 표시했거나(`Sec-Fetch-Site: same-origin`), 페이지 출처가 관리자 세션 또는 관리자의 비밀번호·Passkey 로그인으로 이미 확인된 경우입니다. 같은 NAS의 다른 포트에 있는 페이지는 관리자의 로그인 상태를 빌려 쓸 수 없습니다. 아주 오래된 브라우저는 `Sec-Fetch-Site`를 보내지 않으므로 처음 사용할 때 관리자 비밀번호로 한 번 로그인하세요. 게이트웨이를 통한 로그인 제한은 fnOS 사용자별로 계산합니다.
- 콘텐츠 보안 정책: 관리 화면의 페이지는 자체 스크립트만 불러오며 다른 사이트에 삽입될 수 없고, API 응답은 어떤 리소스도 불러오지 않습니다. 로그인 쿠키에는 `HttpOnly`와 `SameSite=Strict`가 붙고, HTTPS로 접근할 때(신뢰하는 프록시나 fnOS 통합 게이트웨이가 처리하는 HTTPS 포함)는 `Secure`도 붙습니다.
- 모듈 스위치: 「설정 → 기능 모듈」에서 끈 모듈은 서비스를 시작하지 않고 관리 API도 제공하지 않으므로 공격 표면이 줄어듭니다. [사용자 지정 빌드](/ko/docs/modules/#custom-build)로 쓰지 않는 모듈을 컴파일할 때 아예 뺄 수도 있습니다
- 다중 토큰 API: 각 토큰은 생성할 때 선택한 모듈의 읽기/쓰기 권한만 가지며 만료 시간을 지정할 수 있고 최근 사용한 출처 IP가 기록됩니다. 계정, 2단계 인증, 토큰 관리, 백업, 복원, 재시작, 시스템 설정 엔드포인트는 로그인 세션만 허용합니다. 자세한 내용은 [API 토큰 및 OpenAPI](/ko/docs/reference/api)를 참고하세요.
- 사이트 접근 제어: 인증 실패 시 자동 차단, GeoIP 국가 필터, 경로 규칙. 자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.
- 설정 백업은 암호화(scrypt + AES-GCM)를 지원합니다. 자세한 내용은 [설정 백업](/ko/docs/modules/backup)을 참고하세요.

## 감사와 추적

감사 로그는 로그인, 설정 변경, 민감한 접근을 기록합니다. 설정 기록은 각 설정 파일을 덮어쓰기 전의 버전을 보관하며 한 번에 되돌릴 수 있습니다. 자세한 내용은 [감사 로그와 설정 기록](/ko/docs/guide/audit)을 참고하세요. 릴리스 산출물에는 cosign 서명, 빌드 출처 증명(provenance), SBOM이 함께 제공되며 검증 방법은 [릴리스 검증](/ko/docs/guide/verify)을 참고하세요.

## 위험도가 높은 기능의 기본값

로컬 셸 터미널은 기본적으로 꺼져 있습니다. SSH 터미널은 「처음 접속 시 신뢰」 정책으로 호스트 키 지문을 기록합니다.
