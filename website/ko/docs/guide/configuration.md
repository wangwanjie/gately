# 설정 및 실행 옵션

## 명령줄 옵션

| 옵션 | 설명 |
| --- | --- |
| `-c` | 설정 디렉터리. 환경 변수 `GATELY_CONFIG_DIR`로도 지정할 수 있습니다 |
| `-listen` | 관리 UI 수신 주소를 덮어씁니다. 예: `:16680` |
| `-apply` | 선언적 설정 디렉터리. 환경 변수 `GATELY_APPLY_DIR`로도 지정할 수 있습니다. 아래 내용을 참고하세요 |
| `-gateway-socket` | 이 Unix 소켓에서도 관리 화면을 제공합니다(fnOS 통합 게이트웨이 등에서 사용) |
| `-gateway-prefix` | 게이트웨이를 통해 접속할 때 쓰는 경로 접두사. 예: `/app/gately` |
| `-api-docs` | API 문서(`openapi.json`과 `API.md`)를 지정한 디렉터리에 내보내고 종료합니다 |
| `-version` | 버전 정보를 출력합니다 |

| 환경 변수 | 설명 |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | 최초 실행 시 사용할 관리자 초기 비밀번호(8자 이상). 설정하지 않으면 기본 비밀번호 `gately.cn`을 사용합니다. 계정이 이미 있으면 적용되지 않습니다. 10자보다 짧거나 강도가 부족하면 첫 로그인 때 변경을 요구합니다 |
| `GATELY_LANG` | 서버 언어가 "시스템 따라가기"일 때 가장 먼저 읽는 언어 코드이며, 이어서 `LC_ALL`, `LC_MESSAGES`, `LANG` 순으로 읽습니다 |
| `GATELY_LOG_LEVEL` | 기록할 실행 로그의 최저 레벨: `debug`, `info`, `warn`, `error`. 설정의 「로그 레벨」이 「기본값」일 때 적용되며, 설정하지 않으면 `info`입니다 |

## 설정 디렉터리

모든 설정은 설정 디렉터리에 저장되며 모듈마다 `<name>.json` 일반 파일 하나를 사용합니다. 파일은 원자적으로 기록되고 권한은 0600입니다. 따라서 다음이 가능합니다.

- 텍스트 편집기로 바로 열어 볼 수 있습니다.
- 디렉터리를 git에 넣어 변경 사항을 diff로 감사하고 언제든 롤백할 수 있습니다.
- 백업은 디렉터리를 복사하는 것으로 끝납니다.

::: warning 주의
`ssl.json`에는 인증서 개인 키가 들어 있습니다. 버전 저장소에 넣기 전에 저장소가 비공개인지 확인하거나 이 파일을 무시 목록에 추가하세요.
:::

「설정 → 네트워크 및 실행 → 저장소 사용량」에는 설정 디렉터리가 있는 파티션의 용량, 설정 디렉터리의 전체 크기, 용도별 사용량(실행 로그, 방문자 감사, 작업 감사 로그, 설정 기록, 설정 백업, 보호 데이터, 알림 재전송 대기열(`notify/`), 네트워크 데이터, IP 목록, 인증서, GeoIP 데이터베이스, 관리 프로그램(`bin/`), File Browser 데이터(`filebrowser/`), 설정 파일(Docker Compose 프로젝트 `compose/` 포함), 기타)이 표시되어 디스크를 무엇이 차지하는지 확인할 수 있습니다. 크기만 집계하며 심볼릭 링크는 따라가지 않습니다. 「로그 디렉터리」가 설정 디렉터리 밖에 있으면 따로 표시하고 설정 디렉터리 사용량에는 포함하지 않습니다. 탭을 열 때 집계하며 「새로고침」을 누르면 다시 집계합니다.

## 선언적 설정

`-apply <디렉터리>`를 지정하면 실행할 때마다 해당 디렉터리의 `<이름>.json` 파일을 설정 디렉터리에 덮어씁니다. 내용이 같은 파일은 다시 쓰지 않습니다. git 저장소, Kubernetes ConfigMap, 배포 스크립트로 설정을 일괄 배포할 때 적합합니다.

- 기록하기 전에 올바른 JSON인지 검사하며, 하나라도 잘못된 파일이 있으면 실행을 거부합니다.
- `account.json`과 `tokens.json`은 덮어쓸 수 없습니다. 계정과 토큰은 관리 UI에서만 관리합니다.
- 덮어쓴 이전 내용은 [설정 기록](/ko/docs/guide/audit)에 저장되며 언제든 되돌릴 수 있습니다.

## 외부 프로그램 디렉터리

Tailscale, frp, cloudflared, File Browser는 공식 외부 프로그램을 관리하며 다음 순서로 실행 파일을 찾습니다.

1. 모듈 설정에 입력한 경로
2. 설정 디렉터리 아래의 `bin/` 하위 디렉터리
3. `PATH`

각 모듈 페이지에서 온라인으로 설치, 업데이트, 롤백할 수 있습니다. 프로그램은 `bin/`에 설치되고 이전 버전은 `bin/.versions/`에 보관됩니다. 자세한 내용은 [온라인 설치, 업데이트, 롤백](/ko/docs/modules/tunnels#install)을 참고하세요. 바이너리를 설정 디렉터리에 직접 넣을 수도 있으며, Docker 배포에서는 예를 들어 `./gately-data/bin/frpc`입니다. Tailscale은 `tailscale`과 `tailscaled`가 모두 필요합니다.

## 실행 로그

시스템과 각 모듈의 실행 로그는 기본적으로 설정 디렉터리의 `logs/`에 기록되므로, 재시작하거나 업그레이드한 뒤에도 「시스템 → 로그」 페이지의 「시스템 로그」 탭과 각 모듈 페이지에서 볼 수 있습니다.

- 출처마다 JSON Lines 파일 하나: `logs/<모듈 ID>.log`, 시스템 로그는 `logs/gately.log`. 시작할 때 「로그 보관 줄 수」만큼 최근 로그를 파일에서 복원합니다.
- 새 로그는 최대 1초 늦게 묶어서 기록합니다. 파일이 상한(기본 2 MB)을 넘으면 `.1`로 교체하고 그 하나만 보관하므로, 출처마다 최대 상한의 두 배를 사용합니다.
- 웹 서비스 접근 로그는 양이 많고 나중에 다시 볼 일이 많아 날짜별로 따로 보관합니다. 현재 파일이 날짜를 넘기거나 총 크기의 4분의 1(최대 16 MB)을 넘으면 `logs/webservice.<시작 시각>.log`로 이름을 바꾸고 백그라운드에서 `.log.gz`로 압축하며, 「접근 로그 보관 일수」(기본 7일)와 「접근 로그 총 크기 (MB)」(현재 파일과 모든 압축 보관 파일의 합계, 기본 32 MB, 로그가 있는 파티션 용량의 5% 이내)에 따라 가장 오래된 보관 파일부터 삭제합니다.
- 각 모듈은 나타난 로그 출처를 `logs/<모듈 ID>.sources`에 기록하며, 재시작 후에도 유지됩니다.
- 「설정 → 네트워크 및 실행 → 실행 매개변수」에서 「로그 영구 저장」을 끄거나, 「로그 파일 상한」「접근 로그 보관 일수」「접근 로그 총 크기 (MB)」를 바꾸거나, 「로그 디렉터리」를 다른 절대 경로(예: 외장 디스크의 디렉터리. 없으면 Gately 실행 사용자만 접근할 수 있게 자동으로 만듭니다)로 옮길 수 있으며 즉시 적용됩니다. 로그 디렉터리를 바꾸면 새 로그는 새 디렉터리에 기록되고 원래 디렉터리의 파일은 그대로 남습니다. 영구 저장을 끄면 로그는 메모리에만 보관되고 재시작하면 지워집니다.
- 「로그 레벨」은 어떤 실행 로그를 기록할지 정합니다. 기본값은 「정보 이상」이며, 디버그 레벨 로그는 기록하지 않아 로그 페이지, 로그 파일, 표준 오류 출력에 남지 않습니다. 포트 포워딩과 프로토콜 분기의 연결별 기록, 클라이언트 연결 끊김, 관련 없는 도메인의 TLS 핸드셰이크 실패 등이 디버그 레벨입니다. 확인하려면 「로그 레벨」을 「디버그 이상(전체)」로 바꿉니다. 저장하면 바로 적용되며 연결이 많으면 부하가 눈에 띄게 늘어납니다. 웹 서비스 액세스 로그는 정보 레벨이므로 「경고 이상」이나 「오류만」으로 바꾸면 더 이상 기록되지 않습니다. 환경 변수 `GATELY_LOG_LEVEL`로도 지정할 수 있으며, 설정에서 특정 레벨을 고르면 설정이 우선합니다.
- 실행 로그는 표준 오류 출력(`docker logs`, `journalctl`에서 보이는 내용)에도 서버 언어로 출력됩니다. 이 출력은 백그라운드에서 묶어서 기록하며, 프로세스가 정상 종료되거나 재시작하기 전에 모두 기록합니다. 표준 오류 출력이 막혔거나 너무 느려 대기 중인 내용이 1 MB를 넘으면 새 줄은 버리고 버린 줄 수를 알리는 한 줄을 남깁니다. 로그 페이지와 로그 파일에는 영향이 없습니다. Docker의 기본 로그 드라이버는 컨테이너 로그 크기를 제한하지 않으므로, 배포 예시 [docker-compose.yml](https://github.com/wangwanjie/gately/blob/main/deploy/docker-compose.yml)은 `logging.options`의 `max-size`와 `max-file`로 상한을 둡니다.
- 화면에서 모듈 로그를 지우면 해당 파일, 교체된 이전 파일, 압축 보관 파일과 출처 기록도 함께 삭제됩니다.
- 설정 백업에는 `logs/`와 작업 감사 로그 `audit.log`가 포함되지 않습니다.

### 보기와 필터 {#log-filter}

「로그」 페이지의 「시스템 로그」 탭과 각 모듈 페이지 하단의 로그 카드는 같은 로그 뷰어를 사용합니다. 다음 조건을 조합해 필터링할 수 있으며, 변경 즉시 적용되고 새 로그도 조건에 맞는 것만 추가됩니다.

- 수준과 소스(드롭다운에는 모듈 설정의 모든 소스와 로그에 나타난 소스가 표시됩니다. 예를 들어 웹 서비스의 모든 리스너가 표시되며, 아직 접근 기록이 없거나 로그가 파일에만 있는 리스너도 포함됩니다. 직접 입력도 가능)
- 키워드: 공백으로 구분하면 모두 포함, 큰따옴표로 구문 묶기, 앞에 `-`를 붙이면 제외(예: `GET "timeout" -debug`). 일치한 부분은 강조 표시됩니다. 인터페이스가 다른 언어일 때는 화면에 보이는 번역문으로 검색하면 됩니다
- 「제외」: 그중 어느 단어라도 포함한 로그를 숨기며 키워드와 함께 적용됩니다. 작성법은 키워드와 같습니다(공백 구분, 큰따옴표로 구문 묶기). 예: `debug "health check"`. `-`로 시작하는 단어 자체를 제외하려면 `"-v"`처럼 큰따옴표로 감쌉니다
- 「추가 필터」의 IP: 전체 주소, 대역(예: `10.0.0.0/8`) 또는 주소 일부, 여러 개는 쉼표로 구분. IP가 따로 기록되지 않은 로그는 본문에서 주소를 인식하므로 로그인 실패, 침입 방지 로그에도 쓸 수 있습니다. 앞에 `!` 또는 `-`를 붙이면 제외되며, `!1.2.3.4, !10.0.0.0/8`처럼 해당 출처를 숨길 수 있고 포함 항목과 함께 쓸 수도 있습니다(`10.0.0.0/8, !10.0.0.5`)
- 「추가 필터」의 시간 범위: 최근 15분부터 7일까지, 또는 시작·종료 시각 직접 지정
- Web 서비스 도구 모음에는 표시 스위치가 두 개 있으며 표시에만 영향을 줍니다(로그는 그대로 보관되고 선택은 브라우저에 저장됨). 「차단된 출처 숨기기」는 출처가 차단되어 거부된 요청을 숨깁니다(CDN 뒤에서는 커널 차단이 CDN 연결에 적용되지 않아 차단된 방문자가 Web 계층에서 거부되며 403 / 444 기록을 남김). 현재 차단 중인 출처의 요청은 차단을 일으킨 요청까지 모두 숨기며, 차단이 해제되거나 만료되면 다시 표시됩니다. 「콘솔 자체 요청 숨기기」는 이 인스턴스의 관리 콘솔 로그인 세션이 있는 요청(예: Web 서비스 사이트를 통해 콘솔을 열었을 때 로그 페이지의 폴링)을 숨기며 기본으로 켜져 있습니다. 이런 로그 줄 끝에는 「차단 사유=차단됨」「콘솔 사용자=…」 태그가 붙고, API 매개변수는 `hideBanned=1`, `hideAdmin=1`(관리자 세션만 해당하며 읽기 전용 계정은 제외됩니다. 차단된 요청에는 콘솔 사용자 태그가 붙지 않습니다)입니다
- 웹 서비스는 사이트 이름 또는 도메인, 상태 코드(`404`, `4xx`, `500-599`, 여러 개는 쉼표로 구분)로도 필터링할 수 있습니다. WAF 방화벽은 도메인으로 필터링할 수 있으며, 탐지 로그에는 도메인과 규칙 ID가 기록됩니다

로그의 소스나 줄 끝의 「사이트=…」「도메인=…」 같은 태그를 클릭하면 해당 값으로 필터링합니다. Web 서비스 로그에서 「사이트=…」를 클릭하면 사이트 이름이 완전히 일치하는 로그만 걸러내며, 도구 모음에 제거할 수 있는 「사이트: …」 태그가 표시됩니다(API 매개변수 `site`). 이름이 비슷한 다른 사이트의 로그는 포함되지 않습니다. API는 `listener` 매개변수(리스너 키, 정확히 일치)도 받습니다. 두 리스너의 이름이 같으면 로그 소스 이름에 수신 주소가 붙습니다(예: `HTTPS (0.0.0.0:443)`와 `HTTPS ([::]:443)`). 이름이 겹치지 않는 리스너는 그대로입니다. 메모리의 로그가 부족하면 「이전 로그 불러오기」가 로그 파일에 보관된 기록(웹 서비스의 압축 보관 파일 포함, 시간 범위로 필터링하면 범위 밖의 보관 파일은 건너뜀)까지 이어서 찾으므로, 로그 저장을 켜 두면 필터 범위가 「로그 보관 개수」에 제한되지 않습니다. `GET /api/logs`와 `GET /api/<모듈>/logs`도 같은 필터 매개변수를 지원합니다. [API 참조](/ko/docs/reference/api-reference)를 확인하세요.

로그 영역의 높이를 조절할 수 있습니다. 아래쪽 막대를 끌고(터치 화면에서는 누른 채 끌기), 막대를 두 번 클릭하면 기본 높이로 돌아가며, 막대에 포커스가 있을 때는 방향키로도 조절할 수 있습니다. 페이지의 로그 카드와 사이트 로그 대화 상자는 각자의 높이를 현재 브라우저에 따로 기억합니다. 도구 모음 오른쪽의 전체 화면 버튼을 누르면 로그가 창 전체를 채우며, 다시 누르거나 Esc를 누르면 종료됩니다. 위로 스크롤해 기록을 보는 동안에도 새 로그는 계속 추가되지만 보던 위치를 아래로 끌어내리지 않습니다. 로그 영역 오른쪽 아래에 「최신으로 이동」이 나타나고 그동안 도착한 새 로그 수도 표시됩니다. 맨 아래로 스크롤하거나 버튼을 누르면 자동 스크롤이 다시 시작됩니다.

### 내보내기 {#log-export}

로그 도구 모음의 「내보내기」는 현재 필터 조건에 맞는 모든 로그를 로그 파일과 압축 보관 파일에 남은 기록까지 포함해 오래된 순으로 내보내며, 브라우저에서 바로 내려받아 저장합니다.

- CSV(스프레드시트): BOM이 있는 UTF-8이라 Excel에서 바로 열 수 있습니다. 열은 시간, 수준, 소스, 메시지와 IP, 도메인, 사이트, 상태 코드 등의 필드입니다. `=`, `+`, `-`, `@`로 시작하는 셀 앞에는 작은따옴표를 붙여, 방문자가 보낸 경로를 스프레드시트 프로그램이 수식으로 실행하는 것을 막습니다.
- JSON Lines: 한 줄에 로그 하나이며, 필드는 로그 API와 같습니다.
- 메시지는 화면 언어로 내보냅니다. 읽기 전용 계정과 읽기 권한만 있는 API 토큰도 내보낼 수 있으며, 조회할 때와 마찬가지로 주소에 든 비밀번호와 토큰은 가려집니다.
- API는 `GET /api/logs/export`와 `GET /api/<모듈>/logs/export`이며, `format`은 `csv` 또는 `jsonl`이고 나머지 필터 매개변수는 로그 조회와 같습니다. 소스 목록 API는 `GET /api/logs/sources`와 `GET /api/<모듈>/logs/sources`입니다.

## 저장 후 확인과 자동 롤백 {#confirm}

도메인으로 원격 관리할 때 포트 포워딩, 프로토콜 라우팅, 웹 서비스, 전역 설정을 바꾸면 관리 화면 자신의 접속 경로가 끊길 수 있습니다. 그래서 이런 설정을 저장하면 관리 화면이 새로 연 연결로 여전히 접속되는지 확인합니다:

- 접속이 정상이면 백그라운드에서 조용히 확인합니다;
- 확인되지 않으면 카운트다운 대화상자가 나타나고 접속이 돌아오면 자동으로 확인됩니다. Gately에 아직 연결할 수 있을 때는 「지금 롤백」을 누를 수 있지만, 연결할 수 없을 때는 그 요청도 전달되지 않으므로 카운트다운이 끝나기를 기다리거나 서버에서 `gately rollback -pending`을 실행합니다;
- 시간이 다 될 때까지 확인되지 않으면 Gately가 재시작하고 시작할 때 변경 전 설정을 복원합니다. 변경된 버전은 [설정 기록](/ko/docs/guide/audit)에 보관됩니다. 서비스가 돌아오면 페이지가 자동으로 새로 고쳐지고 어떤 변경이 롤백되었는지 알려 줍니다.

확인에는 WebSocket을 씁니다. 브라우저는 항상 새 연결을 열기 때문에 변경된 포워딩과 수신을 거칩니다. 변경 전에 맺은 긴 연결은 핫 업데이트 후에도 이전 대상에 연결되어 있어 새 설정이 동작한다는 증거가 되지 않습니다.

재시작해야 적용되는 설정(관리 화면 수신 주소, 기능 모듈 켜기/끄기)은 관리 화면에서 재시작할 때 기록되며 재시작 후부터 시간을 잽니다. 확인 없이 3번 연속 시작되면(예: 새 설정 때문에 프로그램이 정상 동작하지 않음) 역시 롤백합니다. 확인 대기 중인 변경이 있을 때 새 주소로 관리 화면을 열면 「변경 유지」 또는 「지금 롤백」을 묻는 대화상자가 나타납니다.

제한 시간은 「설정 → 접근 제어 → 관리 화면 수신」의 「저장 후 확인」에서 조정하거나(30~600초, 기본 90초) 끌 수 있습니다. 관리 화면에서 저장할 때만 적용되며 API 토큰과 스크립트로 한 변경은 영향을 받지 않습니다. API는 `GET /api/system/confirm`입니다.

### 저장 전 경고: 현재 접속 경로 {#access-path}

Gately는 관리 화면 접속이 자신의 어떤 포워딩을 거치는지 알아낼 수 있습니다. 포트 포워딩과 프로토콜 라우팅은 이 기기의 대상에 연결할 때 홉을 기록하고, 웹 서비스는 관리 화면으로 프록시할 때 서명된 경로 정보를 붙입니다(외부에서 위조 불가). 「설정 → 접근 제어」 맨 위의 「현재 접속 경로」 카드에 예를 들어 `방문자 → 프로토콜 라우팅 "vps-443" → 웹 서비스 "main" › 사이트 "admin.example.com" → 관리 화면`처럼 표시됩니다. frp, Cloudflare 터널 등 이 기기의 프로그램은 「이 기기」로 표시됩니다.

저장하기 전에 관리 화면은 이번 변경이 이 경로에 영향을 주는지 서버에 확인합니다. 영향을 주면 대화상자에 이유를 나열하고 영향을 받는 홉을 강조하며, 취소하거나 「그래도 저장」할 수 있습니다:

- 경로 위 규칙, 수신, 사이트의 포워딩 관련 설정 변경(이름, 그룹, 메모만 바꾸는 것은 제외), 끄기나 삭제, 사이트를 다른 수신으로 이동;
- 경로가 거치는 모듈 끄기(모듈 전체 스위치 또는 「기능 모듈」 설정);
- 사용 중인 관리 화면 수신 주소 변경;
- 외부에서 접속 중에 「내부망 전용」 켜기, HTTP로 접속 중에 「HTTPS 강제」 켜기.

경고와 별개로 위의 확인과 자동 롤백은 그대로 적용되므로, Gately가 알 수 없는 경로(예: 바깥쪽의 다른 리버스 프록시)도 보호됩니다. API는 `GET /api/system/access-path`와 `POST /api/system/access-path/check`입니다.

### 일괄 변경: 여러 곳을 함께 바꾸기 {#changeset}

여러 곳을 함께 바꿔야만 동작하는 변경이 있습니다. 예를 들어 프로토콜 라우팅이 웹 서비스로 보내는 포트를 18081로 바꾸고, 웹 서비스 수신도 18081로 옮기는 경우입니다. 첫 번째만 저장하면 현재 접속이 끊겨 두 번째를 바꿀 수 없게 됩니다. 이럴 때 일괄 변경을 씁니다:

1. 저장 전 경고에서 「보류하고 나중에 함께 적용」을 고르거나, 「설정 → 접근 제어」의 「현재 접속 경로」 카드에서 「일괄 변경 시작」을 누릅니다;
2. 이후 포트 포워딩, 프로토콜 라우팅, 웹 서비스의 저장은 설정에만 기록됩니다. 페이지에는 새 내용이 보이지만 실행 중인 규칙과 수신은 그대로이며 현재 접속 경로를 계속 쓸 수 있습니다. 페이지 위쪽 배너에 보류된 규칙과 수신이 나열되며, 이 동안에는 저장 전 경고가 나오지 않습니다;
3. 모두 바꾼 뒤 배너의 「모두 적용」을 누르면 보류된 변경이 저장 순서대로 한 번에 적용되고, 단일 저장과 마찬가지로 새 연결로 확인합니다. 확인되지 않으면 일괄 변경 시작 전 설정으로 통째로 롤백합니다;
4. 그만두려면 「변경 취소」를 누르세요. 일괄 변경 시작 전 설정으로 복원하고 Gately를 재시작합니다.

「모두 적용」 전에 Gately는 보류된 규칙과 수신의 수신 주소를 이 기기에서 쓸 수 있는지 확인하고, 쓸 수 없으면 시스템이 알려 준 원인과 함께 먼저 보여 주고 결정하게 합니다. 저장 전 경고도 새 수신 주소를 쓸 수 없음을 알려 줍니다. 적용 후 확인되지 않거나 롤백되면 대화상자와 롤백 알림에 그동안 모듈이 보고한 오류(수신 시작 실패 등)가 나열됩니다. macOS는 기본으로 127.0.0.1만 설정되어 있으므로 127.0.0.2 같은 루프백 주소를 쓰려면 먼저 `sudo ifconfig lo0 alias 127.0.0.2`를 실행하세요. Linux에서는 127.0.0.0/8 전체를 그대로 쓸 수 있습니다.

전역 설정 변경은 일괄 변경 대상이 아니며 평소처럼 즉시 적용됩니다. 일괄 변경 중 Gately가 재시작되면 새 설정으로 시작하고 단일 저장처럼 시간을 재며 확인을 기다립니다. API는 `POST /api/system/changeset/begin`, `/apply`, `/discard`입니다.

### 명령줄 롤백 {#rollback-cli}

관리 화면에 이미 접속할 수 없다면 서버에서 `gately rollback`을 실행합니다(Docker: `docker exec -it gately gately rollback`). 확인 대기 중인 변경과 최근 설정 저장을 나열하며, 번호를 입력해 취소하거나 옵션을 쓸 수 있습니다:

| 명령 | 동작 |
| --- | --- |
| `gately rollback -list` | 나열만 하고 바꾸지 않음 |
| `gately rollback -last` | 가장 최근 저장을 취소: 그 설정을 저장 이전 내용으로 복원 |
| `gately rollback -pending` | 확인 대기 중인 설정 변경을 즉시 롤백 |
| `gately rollback -config portforward -version <버전>` | 설정을 지정한 기록 버전으로 복원(버전은 `-list` 참고) |

실행 전에 `yes`를 입력해 확인합니다(스크립트에서는 `-y`). Gately가 실행 중이면 Gately가 처리하고 재시작하며, 실행 중이 아니면 설정 파일을 직접 다시 써서 다음 시작 때 적용됩니다. 이전 내용도 [설정 기록](/ko/docs/guide/audit)에 보관되므로 롤백 자체도 취소할 수 있습니다. 설정 디렉터리가 기본 위치가 아니면 `-c`로 지정합니다.

## 백업 및 복원

「설정」에서 설정 백업과 복원을 제공하며 Lucky 설정을 가져오는 진입점도 여기에 있습니다.

복원할 때 「현재 관리자 계정 유지」(API 매개변수 `keepAccount=1`)를 선택하면 백업의 `account.json`, `tokens.json`과 시스템 설정의 서드파티 로그인은 무시되고 현재 계정, 비밀번호, 2단계 인증, 읽기 전용 사용자, API 토큰, 관리 화면의 서드파티 로그인이 그대로 유지되며 나머지 설정은 백업에서 가져옵니다. `account.json`이 없는 백업도 복원할 수 있어 다른 인스턴스의 설정을 옮길 때 적합합니다. 기본 비밀번호를 사용하는 동안에는 복원이 거부되므로 먼저 비밀번호를 변경하세요.
