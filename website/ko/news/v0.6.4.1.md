# Gately v0.6.4.1 출시

2026년 11월 4일

[다운로드 v0.6.4.1](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4.1)

## Tailscale 다중 인스턴스

- 인스턴스마다 독립된 tailscaled가 실행되며 상태 디렉터리, 제어 소켓, WireGuard 포트가 모두 다릅니다. 한 장치가 여러 tailnet에 동시에 참여할 수 있습니다(예: 커널 모드로 원격 Headscale, 사용자 공간 모드로 로컬 Headscale).
- 기존 상태 디렉터리를 그대로 써서 노드 ID와 주소를 유지할 수 있습니다. 이전 단일 인스턴스 설정은 업그레이드 시 `tailscale`이라는 인스턴스가 되며 실행 인자는 이전과 같습니다.
- 동시에 켤 수 있는 커널 모드 인스턴스는 하나뿐입니다(tailscaled의 라우팅 테이블과 방화벽 마크가 고정). 상태 디렉터리, 제어 소켓, 포트 충돌은 저장하거나 켤 때 알려 줍니다. 인스턴스를 수정하면 해당 인스턴스만 다시 시작합니다.
- API 변경: `/api/tailscale/secrets`, `/restart`, `/logout`이 인스턴스별 `/api/tailscale/instances/{key}/…`로 옮겨졌고 `PUT /api/tailscale/settings`는 프로그램 경로만 저장합니다. 이전 API를 쓰는 스크립트는 수정이 필요합니다.

## NetBird 다중 인스턴스

- Tailscale과 같은 방식입니다. 데몬, 상태 디렉터리, 제어 주소, WireGuard 포트가 각각 독립되며 이전 설정은 `netbird`라는 인스턴스로 이전됩니다.
- 충돌 검사는 WireGuard 포트(0은 기본값 51820으로 간주)와 사용자 공간 인스턴스의 SOCKS5 주소(비우면 `127.0.0.1:1080`으로 간주)도 포함합니다.
- 별도로 설치한 NetBird 서비스가 커널 모드로 실행 중이면(`wt` 인터페이스가 있거나 시스템 제어 소켓이 커널 인터페이스로 연결됨을 보고하면) 커널 모드 인스턴스는 함께 실행되지 않고 이유를 표시합니다.
- API 변경: 인스턴스는 `/api/netbird/instances` 아래에 있으며 상태, 재시작, 로그아웃, 설정 키는 인스턴스별로 제공됩니다.

자세한 내용은 [터널과 네트워크](/ko/docs/modules/tunnels)를 참고하세요.

## 알림에 서버 이름 표시

알림 제목이 `[Gately · 서버 이름] 이벤트 제목`이 되고 본문에 「서버」 줄이 추가되어, 여러 서버의 알림을 같은 메일함이나 그룹에서 받아도 구분할 수 있습니다. 이름은 「알림 설정」에서 입력하며 비우면 호스트 이름을 사용합니다. Webhook 템플릿에서는 `{server}` 변수를 쓸 수 있습니다. 자세한 내용은 [알림 센터](/ko/docs/modules/notify#server-name)를 참고하세요.

## 기타 개선과 수정

- 프로토콜 분기 경로를 일시적으로 끌 수 있습니다. 설정은 유지되고 연결은 더 넓은 경로나 기본 대상으로 넘어가며, 전환해도 다른 연결은 끊기지 않습니다.
- DNSPod 수정: dnsapi.cn이 `DDNS Client`가 포함된 User-Agent를 거부하기 시작해 DNSPod 레코드 동기화와 DNS-01 인증서 검증이 모두 실패했습니다.
- ipw.cn이 더 이상 해석되지 않아 기본 공인 IP 조회 주소를 `ipv4.ddnspod.com`과 `ipv6.ddnspod.com`으로 바꾸었고, 저장된 ipw.cn 주소는 시작할 때 자동으로 교체합니다.
- 백업 페이지를 열어 두는 동안 몇 초마다 민감 접근 감사 기록과 알림이 생기지 않습니다. 백업 파일을 내려받을 때만 기록합니다.
- 읽기 전용 계정에는 그룹 이름 변경 버튼이 표시되지 않습니다.
