# Gately v0.6.2.1 출시

2026년 11월 1일

[v0.6.2.1 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.2.1)

## 신뢰할 수 있는 프록시 뒤의 방문자 실제 IP (#50)

웹 서비스 "전역 설정"에 "방문자 실제 IP"가 추가되었습니다. CDN, WAF 등 신뢰할 수 있는 프록시의 원본 서버 방향 주소나 범위를 입력하고, 실제 IP 헤더를 순서대로 고릅니다(`CF-Connecting-IP`, `X-Forwarded-For`, `X-Real-IP`, `True-Client-IP` 또는 사용자 지정 이름). 이 헤더는 직접 연결한 상대가 신뢰할 수 있는 프록시일 때만 읽으며, 직접 접속한 방문자가 보낸 헤더는 무시합니다. `X-Forwarded-For`는 오른쪽에서 왼쪽으로 읽으며 신뢰할 수 있는 프록시를 건너뜁니다. 얻은 주소는 접근 로그, IP 목록, LAN 전용 접근, 국가 필터, 차단, 통계, 백엔드로 보내는 헤더에 쓰입니다. Cloudflare를 쓴다면 `CF-Connecting-IP`를 권장합니다. 자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## 사이트별 실시간 연결 (#51)

사이트 목록의 각 도메인 행에 처리 중인 요청 수가 표시되고, "연결" 창은 2초마다 새로 고쳐집니다.

- 실시간 목록에는 출발지 주소, 프로토콜(h1 / h2 / h3, WebSocket은 따로 표시), 메서드와 경로(쿼리 문자열 제외), 지속 시간, 양방향 트래픽이 표시되며 IP로 검색할 수 있습니다.
- 기록에는 1초 이상 지속되었거나 수동으로 끊은 요청을 사이트마다 최근 200개까지 메모리에만 보관합니다.
- 요청 하나를 끊을 수 있고(HTTP/2와 HTTP/3는 해당 스트림만 재설정), 끊으면서 출발지 주소를 차단할 수도 있습니다. 이때 모든 사이트에서 그 주소의 요청도 함께 끊깁니다. 현재 자신이 쓰는 주소, 루프백 주소, 신뢰할 수 있는 프록시는 차단할 수 없습니다.

## 출발지 IP 접근 제어 (#49)

포트 포워딩, 프로토콜 라우팅, STUN 내장 전달, frps 인스턴스마다 허용 목록 또는 차단 목록을 쓸 수 있습니다. 목록은 직접 입력한 IP / 서브넷과 웹 서비스의 구독 IP 목록으로 구성되며, 구독 목록이 갱신되면 규칙을 다시 시작하지 않아도 바로 적용됩니다.

- 침입 방지의 차단을 먼저 확인한 다음 목록을 확인합니다.
- 규칙 카드에 접근 모드와 거부 횟수가 표시되고, IP 목록 페이지에는 그 목록을 참조하는 규칙이 표시됩니다. 참조 중인 목록은 삭제할 수 없습니다.
- frps 목록은 frpc가 로그인할 때 확인되어 바인드 포트를 보호합니다.
- Lucky에서 포트 포워딩과 STUN 규칙을 가져오면 안전 모드가 출발지 IP 접근 제어로 변환됩니다(같은 가져오기에서 `lucky_ipfilter.lkcf`를 함께 업로드하세요).

자세한 내용은 [포트 포워딩](/ko/docs/modules/portforward)과 [Tailscale / frp / cloudflared](/ko/docs/modules/tunnels)를 참고하세요.

## 사이트 링크 (#52)

사이트 목록의 구체적인 도메인은 각각 새 탭에서 열 수 있고, 옆의 버튼으로 스킴과 포트를 포함한 전체 URL을 복사할 수 있습니다. 방문자가 프로토콜 라우팅, 포트 매핑, frp, CDN을 거쳐 들어오는 경우 리스너에 외부 접근 주소를 지정할 수 있습니다. frpc의 http / https 프록시, File Browser 접근 URL, Cloudflare 빠른 터널 주소, Tailscale 로그인 링크도 같은 방식으로 열고 복사할 수 있습니다. 도메인은 브라우저가 보내는 형태(소문자, 국제화 도메인은 punycode)로 저장되며, 포트나 경로가 들어 있는 등 절대 일치할 수 없는 값은 거부됩니다.

## 동적 DNS

- 레코드 메모(비어 있으면 작업 메모)를 Alibaba Cloud, Cloudflare, Tencent Cloud, DNSPod, Huawei Cloud에 기록합니다.
- 레코드나 작업을 삭제할 때 "DNS 제공업체에서도 삭제"를 고를 수 있으며 14개 제공업체가 지원합니다. 값이 Gately의 마지막 동기화 결과와 같은 레코드만 삭제합니다. 값을 알 수 없거나, 콘솔에서 바뀌었거나, 레코드 세트에 다른 값이 있으면 삭제하지 않고 이유를 보여 줍니다.
- 모듈 스위치가 "전역 설정"으로 옮겨졌고, 여기서 삭제 체크박스의 기본값도 정할 수 있습니다.

## 기타 개선

- Docker 페이지에서 Gately 자신이 실행 중인 컨테이너를 업그레이드할 수 있습니다. 먼저 새 이미지를 받고, 새 버전이 있을 때만 임시 보조 컨테이너가 컨테이너를 다시 만들며, 새 컨테이너가 시작되지 않으면 이전 컨테이너를 복원합니다. 웹 터미널의 로컬 셸이 Gately 컨테이너 안에서 실행될 때는 이 작업을 안내합니다.
- 휴대폰에서 웹 터미널을 약 0.5초 길게 누르면 선택 모드가 되어 시스템의 선택 핸들과 복사 메뉴를 쓸 수 있고, 자동 줄바꿈된 줄은 복사할 때 한 줄로 합쳐집니다. 키 바에 붙여넣기 키가 추가되어 HTTP 접속에서는 붙여넣기 패널이 열리며, 이 탭에서 최근 복사하거나 입력한 텍스트 10개를 다시 보낼 수 있습니다. 원격 프로그램이 브래킷 붙여넣기를 켜지 않았을 때 여러 줄을 붙여넣으면 먼저 확인합니다.
- 인증 사용자 페이지에서 공유 사용자로만 인증하는 사이트를 해제할 수 있으며, 그 사이트들의 인증을 끄기 전에 확인합니다.
- 프로토콜 라우팅 규칙을 수정해도 프로토콜, 도메인, ALPN이 그대로인 라우트는 적중 횟수를 유지합니다.
- 네트워크 진단의 속도 테스트가 요청마다 50 MB를 요청하도록 바뀌어 Cloudflare의 HTTP 403이 해결되었고, Vultr, Hetzner, OVH 테스트 노드가 추가되었으며, 작업 제목에는 현재 도구의 대상만 표시됩니다.
- 목록 밖 방문자의 연결을 끊는 기본 사이트에서 일어난 거부는 웹 경로 탐색에서 444로 집계됩니다(#53).
- 보안 진입 경로를 설정해도 iOS 홈 화면 아이콘이 글자 자리표시자로 표시되지 않습니다.

## 수정 및 강화

- 웹 터미널이 붙여넣은 텍스트에서 제어 문자를 제거하므로, 끼워 넣은 브래킷 붙여넣기 종료 시퀀스로 여러 줄 확인을 건너뛸 수 없습니다. 시스템 클립보드에서 직접 읽은 텍스트는 클립보드 기록에 추가하지 않으며, 로그아웃하거나 세션이 만료되면 기록을 지웁니다.
- 요청이 끝나는 순간에 끊어도 같은 연결의 다음 요청에 영향을 주지 않습니다.
- Gately 자신의 업그레이드가 진행 중일 때 시작한 두 번째 업그레이드는 거부됩니다. 업그레이드 보조 컨테이너는 익명 볼륨과 함께 삭제되며, 한 Docker 호스트의 여러 Gately는 각자 자신의 보조 컨테이너만 처리합니다.
- 동적 DNS 작업을 편집하면서 "DNS 제공업체에서도 삭제"를 켜고 레코드를 지우면, 저장할 설정을 먼저 검증하고 검증에 실패하면 제공업체에서는 아무것도 삭제하지 않습니다. Tencent Cloud 동기화는 호스트 레코드를 정확히 일치시켜 찾습니다.
- 페이지를 떠나면 연결 창과 통계 창이 폴링을 멈춥니다. 차단에 실패하면 차단 대화상자가 열린 채로 남습니다. frp 하위 도메인은 IPv6 주소를 거부합니다. 차단 목록 모드의 Lucky 규칙을 가져올 때 목록이 없으면 경고합니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. Docker 소켓을 마운트했다면 Gately의 Docker 페이지에서 Gately 자신을 업그레이드할 수도 있습니다. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하세요. fnOS는 앱 센터에서 새 `.fpk`를 직접 설치하세요. 그 밖의 설치 방식은 "시스템 설정"에서 온라인 업그레이드할 수 있습니다.
