# Gately v0.6.8.2 출시

2026년 11월 18일

[v0.6.8.2 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.2)

## 포트 노킹: 사람마다 키 하나

- **신원**: 규칙에 신원을 추가할 수 있습니다. 신원(사람 또는 기기)마다 암호화 키와 HMAC 키가 따로 있고, 개별로 비활성화하거나 다시 생성할 수 있습니다. 규칙 하나에 신원을 최대 64개까지 둘 수 있습니다. 로그, 알림, 허용 기록에 어느 신원이 노크했는지 표시되며, 한 사람의 키를 비활성화하거나 교체해도 그 사람의 허용만 취소됩니다.
- **공유 키 비활성화**: 모두 신원으로 전환한 뒤에는 규칙의 기존 공유 키를 끌 수 있습니다.
- **한 번에 주소 하나만 허용**: 같은 신원이 새 주소에서 노크하면 이전 주소의 허용을 취소합니다. 휴대전화가 여러 네트워크를 오갈 때 알맞습니다.
- 위조 패킷을 검증할 때 HMAC 계산 객체를 재사용해 신원 64개일 때 패킷당 비용이 약 절반으로 줄었습니다. 출처 테이블이 가득 차면 가장 오래 쓰지 않은 대역부터 내보내며, 정상적인 첫 노크가 공격 트래픽과 같은 오버플로 버킷을 쓰지 않습니다.

## 포트 포워딩 / 프로토콜 라우팅

- **출처별 한도를 적용하지 않을 출처**: 전역 설정에 IP / CIDR 목록이 추가되었습니다. 앞단에 공인 중계나 프록시가 있어 모든 방문자가 같은 출처로 보일 때 여기에 넣으면 「출처별 최대 연결 수」에 막히지 않습니다. 다른 출처는 기존대로 한도가 적용됩니다.
- 출처별 한도에 걸린 로그에는 집계된 출처(IPv6는 /64)와 한도가 적히고, 규칙의 출처별 한도를 올리거나 제외할 출처를 추가하라는 안내가 나옵니다.
- 수정: 대상 주소를 입력하고 포커스를 옮겨도 「targetAddresses는 필수입니다」라는 안내가 계속 뜨던 문제.

## 웹 서비스

- **다른 Gately로 리버스 프록시**: v0.6.8부터 이 인스턴스의 관리 콘솔이 아닌 사이트로 리버스 프록시할 때 `gately_token`, `gately_entry`, `gately_login_nonce`를 모두 제거했습니다. 백엔드가 다른 Gately이면 로그인 직후 401이 나오고, 보안 진입 경로를 설정한 관리 콘솔이 계속 404가 되며, 바깥 사이트를 거친 서드파티 로그인에서 「브라우저가 일치하지 않습니다」가 표시되었습니다. 이제 이 인스턴스가 발급했고 아직 유효한 쿠키만 제거하고, 백엔드 Gately 자신의 같은 이름 쿠키는 그대로 전달합니다.
- **두 겹 Gately의 관리 콘솔 로그인 시 인증 생략**: 「Gately 로그인 쿠키 전달」을 켠 사이트는 이 인스턴스가 검증할 수 없는 `gately_admin`을 전달하므로 안쪽 Gately의 「관리 콘솔 로그인 시 인증 생략」이 동작합니다. 이 인스턴스가 발급한 쿠키는 여전히 전달하지 않습니다.
- **421 수정**: v0.6.8.1부터 앞단에 리버스 프록시(다른 Gately, Caddy, Traefik)가 있고 HTTP/2 연결에서 SNI는 백엔드 호스트 이름, Host는 방문자 도메인일 때, 기본 사이트로 떨어진 요청이 421을 받아 페이지가 열리지 않았습니다. 이제 SNI가 이 리스너의 어느 사이트 도메인일 때만 421을 반환하며, 브라우저가 연결을 재사용하는 경우는 기존대로 처리합니다.
- **같은 주소의 동시 로그인**: 같은 IP에서 올바른 로그인이 동시에 여러 번 들어와도 실패가 너무 많다며 거부하지 않습니다. 실제 실패만 한도에 포함하고 진행 중인 검증은 대기열에서 기다리며, 틀린 비밀번호는 여전히 최대 10번까지만 시도할 수 있습니다. 5초를 넘게 기다리거나 대기열이 가득 차면 429를 반환합니다.
- **관리 콘솔 로그인 시 인증 생략**: v0.6.8.1의 상위 도메인을 넘나드는 핸드셰이크(「관리 콘솔 진입 주소」)를 없앴고, 이 옵션은 다시 싱글 사인온 도메인 안에서만 동작합니다.

## 내비게이션 패널(#104)

- **드래그 정렬**: 패널 편집 중 링크의 드래그 핸들을 누른 채 다른 링크의 앞뒤나 그룹 제목 위로 끌어 놓습니다. 마우스와 터치 모두 가능하며, 가장자리에 가까워지면 자동으로 스크롤되고 Esc로 취소합니다. 「선택」 모드에서는 링크 여러 개를 한 번에 옮길 수 있습니다.
- **패널 목록 그룹**: 패널에 그룹을 지정할 수 있고, 목록에서 그룹 접기, 이름 / 제목 / 그룹 / 비고 검색, 간단히 보기, 「정렬 및 일괄 작업」을 쓸 수 있습니다(일괄 삭제 시 사이트에서 쓰는 패널은 삭제되지 않습니다).

## 성능

- 같은 리스너에서 같은 백엔드를 가리키고 연결 설정이 같은 사이트는 백엔드 연결 풀을 공유하며, 리버스 프록시가 요청마다 요청 사본을 만들지 않습니다.
- 사이트의 24시간 분 단위 통계를 시간 단위 블록으로 필요할 때 할당합니다. 사이트 1000개일 때 최대 메모리가 463 MiB에서 225 MiB로 줄고, 처리량은 37,423 req/s입니다.
- GC 비율이 0이면 사용 가능한 메모리가 1 GiB 이상일 때 기본값 200(리버스 프록시 부하 테스트 처리량 약 10% 향상)을 쓰고, 그 외에는 기존대로 100입니다. 환경 변수 `GOGC`가 설정되어 있으면 환경 변수를 따릅니다.
- 침입 방지의 로그 추적이 파일에 기록되는 즉시 읽는 방식으로 바뀌었고(Linux는 inotify, 다른 시스템은 기존대로 폴링), 차단의 방화벽 기록은 250 ms마다 묶어서 처리하되 단일 차단은 계속 즉시 적용됩니다.

## 기타

- 직접 편집했거나 스크립트로 만든 설정 파일에 항목이 빠져 있으면 웹 서비스, DDNS, STUN, SSL, WAF, 침입 방지, 네트워크 깨우기, 알림, File Browser, 웹 터미널, 성능 모니터링이 불러올 때 저장할 때와 같은 기본값으로 채웁니다(이전에는 빈 수신 네트워크 때문에 리스너가 시작되지 않거나 상태 확인 간격이 0이라 헛돌았습니다).
- 알림 Webhook 채널의 변수 목록에 `{server}`를 추가했습니다.
- 공식 사이트에 [성능 비교](/ko/docs/guide/benchmarks) 페이지를 추가했습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만듭니다. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치합니다. fnOS는 앱 센터에서 새 `.fpk`를 직접 설치합니다. 그 밖의 배포 방식은 「시스템 설정」에서 온라인으로 업그레이드할 수 있습니다.
- v0.6.8.1의 「관리 콘솔 진입 주소」로 싱글 사인온 도메인 밖의 사이트를 인증 생략으로 쓰던 경우, 업그레이드 후 해당 사이트는 일반 사이트 인증으로 돌아갑니다.
- 다른 Gately로 리버스 프록시할 때의 쿠키 문제는 바깥쪽(리버스 프록시를 맡은 쪽)만 업그레이드하면 됩니다.
