# Gately v0.6.4 출시

2026년 11월 3일

[v0.6.4 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4) · [온라인 사용자 지정 빌드](https://build.gately.cn)

## 사용자 지정 빌드

포트 포워딩, Web 서비스, SSL 인증서 세 가지 핵심 모듈을 제외한 나머지 22개 모듈은 컴파일할 때 뺄 수 있고, UI 언어도 중국어 간체만 남기거나 중국어 간체·중국어 번체·영어 세 가지만 남길 수 있습니다.

- [build.gately.cn](https://build.gately.cn)을 열고 모듈과 언어를 고르면("Core only", "Router", "NAS" 프리셋에서 시작할 수도 있습니다) 페이지가 크기를 실시간으로 추정하고, Linux / Windows / macOS / FreeBSD 바이너리, OpenWrt와 fnOS 설치 패키지, 또는 amd64·arm64·arm/v7 멀티 아키텍처 Docker 이미지를 온라인으로 생성합니다. 같은 옵션의 산출물은 재사용되므로 다시 빌드할 필요가 없습니다.
- linux/arm64 기준으로 전체판은 33.6 MB, 핵심만 남기면 약 19.9 MB, Router 프리셋에 중국어 간체를 더하면 약 21.2 MB입니다. Router 프리셋에 중국어 간체를 더한 Docker 이미지는 받는 크기가 약 18.7 MB(전체 이미지 51.9 MB)이며, Docker 관리를 포함하지 않은 이미지에는 docker-cli와 compose가, 침입 방지와 STUN을 포함하지 않은 이미지에는 nftables가 들어가지 않습니다.
- 컴파일에 포함하지 않은 모듈의 설정 파일은 그대로 유지되고, 설정의 스위치와 API 토큰 권한도 계속 유효합니다. 해당 API는 404를 반환하며 이 빌드에 포함되지 않았다고 알려 주고, UI는 관련 페이지와 옵션을 숨깁니다. 전체판으로 돌아가면 다시 나타납니다.
- "정보" 페이지에 이 빌드에서 뺀 모듈 목록과, 같은 옵션으로 빌더를 여는 링크가 표시됩니다. 사용자 지정 빌드는 온라인 업그레이드를 제공하지 않습니다(온라인 업그레이드는 전체판을 내려받기 때문입니다). 새 버전이 나오면 같은 옵션으로 다시 생성한 뒤 업그레이드 패키지를 업로드하세요.
- 직접 컴파일할 때는 `no_<모듈>`과 `lang_zh` / `lang_cjken` build tag, 프런트엔드의 `GATELY_LOCALES`, 또는 Dockerfile의 `GATELY_TAGS` 등 빌드 인수를 사용합니다. `tools/custombuild`가 선택 내용을 이 매개변수로 변환해 줍니다.

자세한 내용은 [모듈 개요 · 사용자 지정 빌드](/ko/docs/modules/#custom-build)와 [소스에서 빌드](/ko/download#custom-build)를 참고하세요.

## 관리 포트 숨기기

"설정 → 접근 제어"에 "미승인 접근 응답"이 추가되었습니다. 차단된 출처, 내부망 전용 접근을 켰을 때의 외부 접근, 보안 진입 경로를 거치지 않은 요청에 적용됩니다.

- 기본 안내 페이지, 일반 404, 빈 페이지, 연결 끊기, 시간 초과까지 응답 안 함, 또는 사용자 지정 HTML 페이지(상태 코드 지정 가능) 중에서 고를 수 있습니다.
- 연결 끊기와 응답 안 함은 연결을 맺을 때 출처로 판단하므로 HTTPS는 인증서도 보내지 않습니다. 신뢰할 수 있는 프록시를 거친 요청은 자동으로 일반 404로 바뀌어 앞단 프록시가 오류 페이지를 드러내지 않게 합니다. 대기 중인 연결에는 시간과 개수 상한이 있습니다.
- 숨기는 방식에서는 응답에 관리 콘솔 고유의 보안 응답 헤더를 붙이지 않으며, 사용자 지정 페이지는 스크립트와 외부 리소스를 금지한 샌드박스에서 표시됩니다.

포트 자체는 스캔으로 여전히 발견될 수 있으므로 완전히 숨기려면 방화벽을 함께 사용해야 합니다. 자세한 내용은 [보안 강화 가이드](/ko/docs/guide/hardening)를 참고하세요.

## 사이트 오류 페이지

- Web 서비스 사이트의 "오류 페이지" 탭에서 Gately가 생성하는 404와 5xx 페이지에 기본 스타일, 10가지 내장 스타일(미니멀, 터미널, 네온, 별하늘, 신문, 브루탈리스트, 오로라, 픽셀, 청사진, 상태 체인), 또는 페이지 라이브러리의 사용자 지정 페이지를 고를 수 있습니다. 스타일마다 썸네일과 데스크톱 / 모바일 미리보기가 있습니다.
- 페이지 라이브러리에는 HTML을 업로드하거나 붙여 넣을 수 있고 서버의 `.html` 파일을 참조할 수도 있습니다. 저장할 때 스크립트, 이벤트 속성, 폼 등을 검사해 제거하고, `{code}`, `{title}`, `{host}`, `{path}` 등의 자리표시자를 지원하며, 출력에는 스크립트와 외부 리소스를 금지하는 CSP를 붙입니다.
- 리버스 프록시 사이트는 백엔드의 특정 상태 코드(예: `404, 500-599`)를 가로채 브라우저가 페이지를 여는 요청만 교체하고, API 요청은 그대로 둡니다.
- 기본 사이트의 설정은 어떤 사이트와도 일치하지 않는 요청에도 쓰이며, "정렬 및 일괄"에서 오류 페이지 스타일을 일괄 설정할 수 있습니다.

자세한 내용은 [웹 서비스 · 오류 페이지](/ko/docs/modules/web#error-pages)를 참고하세요.

## 기타 개선

- 동적 DNS 검색이 레코드 단위로 걸러집니다. 작업의 이름, 그룹, 메모 또는 서비스 제공자가 일치하면 모든 레코드를, 그렇지 않으면 일치하는 레코드만 보여 주며, 검색하는 동안 접힌 작업과 그룹을 자동으로 펼칩니다. Web 서비스 검색에서는 접힌 리스너를 자동으로 펼칩니다.
- 설정 페이지의 긴 라벨이 자동으로 줄바꿈되어 독일어, 러시아어 등에서 입력란과 겹치지 않습니다.
- 관리 콘솔 요청이 JSON이 아닌 응답을 받으면(예: 세션 만료 후 보안 진입 경로에 막힌 경우) 새로 고치거나 보안 진입 경로를 다시 열라고 안내합니다.
- 기본 오류 페이지의 "새로 고침"을 일반 링크로 바꿔 스크립트를 금지하는 CSP에서도 동작합니다.
- 진단 패키지와 `GET /api/status`, `GET /api/system/info`에 빌드 정보(사용자 지정 빌드 여부, 포함된 모듈과 언어)가 담깁니다.
- CI에 프리셋 build tag 조합 검사를 추가했습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. Docker 소켓이 마운트되어 있으면 Gately의 Docker 페이지에서 Gately 자체를 업그레이드할 수도 있습니다. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동으로 설치합니다. 그 밖의 배포 방식은 "정보" 페이지에서 온라인으로 업그레이드할 수 있습니다.
- 전체판 사용자는 아무것도 하지 않아도 되며, 설정 형식은 바뀌지 않았습니다.
