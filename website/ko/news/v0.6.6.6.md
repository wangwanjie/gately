# Gately v0.6.6.6 출시

2026년 11월 15일

[다운로드 v0.6.6.6](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.6.6)

## 탐색 패널(#97)

- **검색**: 방문자 페이지 상단의 검색창에서 검색 엔진을 고를 수 있습니다(최대 12개, 자주 쓰는 프리셋 내장, 주소에서 검색어는 `{q}`로 표시). Enter를 누르면 새 탭에서 검색하고, 입력하는 동안에는 페이지의 링크도 계속 걸러집니다. 기본 검색 범위도 설정할 수 있습니다.
- **로그인 후에만 표시**: 링크를 로그인 후에만 보이도록 설정할 수 있습니다. 로그인하지 않은 방문자에게 내려가는 페이지에는 이름과 주소가 포함되지 않으며, 로그인 후에는 자물쇠 표시와 함께 나타납니다. 사이트에서 웹 인증을 켜고 「아래에서 「인증 필수」로 표시한 경로에만 인증을 적용하고, 나머지 경로는 공개합니다」를 선택해야 합니다. 공유 링크로 들어온 방문자는 로그인한 것으로 보지 않습니다.
- **배경 이미지**: 이미지 주소를 입력하거나 이미지를 업로드(1 MB 이내)하고 흐림과 오버레이를 조절할 수 있습니다. 업로드한 이미지는 별도 경로로 제공되며 캐시할 수 있습니다. 방문자도 페이지 설정에서 자신만의 배경, 흐림, 오버레이로 바꿀 수 있습니다.
- **카드와 그룹**: 링크 카드는 큰 크기와 작은 크기가 있고 제목과 설명 표시를 선택할 수 있습니다. 그룹은 접을 수 있으며 「자주 사용」 그룹을 켤 수 있습니다.
- **페이지 정보**: 탭 제목, 탭 아이콘, 페이지 설명, 푸터를 사용자 지정할 수 있습니다.
- **방문자 언어와 사용자 메뉴**: 방문자가 페이지에서 언어를 바꿀 수 있습니다(쿠키에 저장). 로그인 후에는 사용자 메뉴가 표시되고 로그아웃 전에 확인을 거칩니다.

자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## 동적 DNS

- **DNS 제공자 추가**: Tencent Cloud EdgeOne, Alibaba Cloud ESA, Baidu Cloud, Volcano Engine, DNS.LA, Rainyun, HiPM DNSMgr, Eranet / Tnet.hk, Vercel, NameSilo, Dynadot(기존 레코드 업데이트만), Spaceship, Name.com, Gcore, ClouDNS, deSEC. 이 중 Tencent Cloud EdgeOne은 인증서 DNS 검증과 제공자 레코드 삭제도 지원합니다.
- **TTL**: TTL을 0으로 두면 새 레코드는 제공자 기본값을 쓰고, 업데이트할 때는 제공자에 따라 기존 TTL을 유지하거나 기본값을 씁니다. 기존 레코드의 TTL이 바뀌는 일은 없습니다.
- **Cloudflare**: 추가 필드 「프록시 상태」에 true / false를 입력하면 기존 레코드의 프록시 상태를 동기화하고, 비워 두면 관리하지 않습니다. 프록시를 켠 레코드의 TTL은 자동으로 고정됩니다. 이름과 유형이 같은 레코드가 여러 개이면 하나만 남겨 목표 값으로 바꾸고, 이전 값을 가진 나머지 레코드는 삭제합니다.
- **기타**: `com.ar`, `org.br` 같은 다단계 공개 접미사 아래의 도메인은 공개 접미사 목록에 따라 분리합니다. 사용자 지정 콜백은 `{timestamp}` 변수를 지원하며, TTL이 설정되지 않았을 때 `{ttl}`은 600입니다. dynv6은 zone을 통해 루트 도메인 주소를 업데이트합니다. Alibaba Cloud는 라인을 지정하지 않으면 기본 라인만 처리합니다.

자세한 내용은 [동적 DNS](/ko/docs/modules/ddns)를 참고하세요.

## 침입 방지

- **신뢰 소스**: 모듈이 등록한 신뢰 소스는 미끼 포트와 포트 스캔 탐지의 대상이 되지 않습니다(nftables와 iptables 백엔드 모두 지원). 로그 규칙, 수동 차단, 접근 제어는 그대로 적용됩니다.
- **frps**: 올바른 토큰으로 로그인한 frpc의 소스 주소가 신뢰 소스가 됩니다. 같은 가정용 광대역 출구에 있는 다른 기기가 TCP 홀 펀칭을 해도 포트 스캔으로 판정되어 frpc까지 함께 차단되는 일이 없습니다. 로그인 후 10분 동안 또는 frps와 연결이 유지되는 동안 유효하며, 연결이 끊기면 다시 로그인해야 적용됩니다. frps가 중지되거나 토큰 또는 수신 포트가 바뀌면 취소됩니다.

자세한 내용은 [침입 방지](/ko/docs/modules/guard)를 참고하세요.

## 웹 서비스

- **상위 도메인을 넘나드는 관리 콘솔 로그인 인증 생략**: 관리자가 사이트에서 `/__gately_auth/admin-start`(`?next=/경로`를 붙일 수 있음)를 열어 일회용 티켓 핸드셰이크를 시작하는 방식으로 바뀌었습니다. 일반 방문자가 관리 콘솔 입구 주소로 리디렉션되는 일은 없습니다. 이 주소를 북마크해 두기를 권장합니다.
- **응답 캐시**: Gately 자체 로그인 쿠키만 가진 요청을 다시 캐시할 수 있습니다. 이전에는 싱글 사인온 도메인이나 웹 인증을 켜면 로그인한 요청이 모두 쿠키를 가져 캐시가 계속 비어 있었습니다. 그 밖의 쿠키, 다른 인스턴스가 발급한 세션 쿠키, 인증 요청 헤더가 있으면 여전히 캐시하지 않습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동으로 설치하며, 그 밖의 배포 방식은 「시스템 설정」에서 온라인으로 업그레이드할 수 있습니다.
- 상위 도메인을 넘나드는 관리 콘솔 로그인 인증 생략을 쓰는 관리자는 업그레이드 후 사이트에서 `/__gately_auth/admin-start`를 한 번 열어 핸드셰이크를 완료해야 합니다.
- Cloudflare 동적 DNS 작업에서 이름과 유형이 같고 이전 값을 가진 여러 레코드는 다음 동기화 때 하나로 합쳐집니다.
