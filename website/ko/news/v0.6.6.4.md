# Gately v0.6.6.4 출시

2026년 11월 14일

[다운로드 v0.6.6.4](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.6.4)

## 관리 콘솔 로그인 보안

- **비밀번호 규칙**: 새 비밀번호는 10~72바이트입니다. 흔한 약한 비밀번호(흔한 변형 포함), gately나 사용자 이름이 들어간 비밀번호, 연속되거나 반복되는 문자, 문자 종류가 너무 적은 비밀번호는 거부합니다(16자 이상이면 완화). 입력하는 동안 강도를 실시간으로 표시합니다.
- **강제 변경**: 기본 비밀번호나 약한 비밀번호로 로그인하면 닫을 수 없는 비밀번호 변경 대화상자가 뜨고, 변경을 마칠 때까지 서버가 다른 쓰기 작업을 거부합니다. 기존의 약한 비밀번호는 다음 비밀번호 로그인 때 감지합니다.
- **점증 잠금**: 같은 출처가 반복해서 잠기면 잠금 시간이 매번 두 배로 늘어나며 최대 24시간입니다.
- **낯선 주소 실패 예산**: 한 번도 로그인에 성공한 적 없는 주소들의 비밀번호 로그인 실패 합계가 10분 안에 한도(기본 20, 「시스템 설정」에서 조정하거나 끌 수 있음)에 이르면, 낯선 주소의 비밀번호 로그인은 잠시 429를 반환하고 알림을 보냅니다. 자주 쓰는 주소와 Passkey 로그인은 영향을 받지 않습니다.
- **비밀번호 로그인 끄기**: Passkey를 등록한 뒤에는 비밀번호 로그인을 끄고 Passkey나 서드파티 로그인만 쓸 수 있습니다. `gately reset-password`를 실행하면 다시 켜집니다.
- **보안 점수**: 「시스템 설정 → 계정 및 보안」 상단에 관리 화면 보안 점수를 표시하며, 7가지 점검 항목마다 점수와 설정으로 가는 입구를 보여 줍니다.

자세한 내용은 [보안 모델 및 개인정보 약속](/ko/docs/guide/security)을 참고하세요.

## 우선 차단 목록(#95)

IP 접근 제어에 「우선 차단 목록」이 추가되었습니다. 주소와 대역을 직접 입력하거나 구독한 IP 목록(예: 악성 IP 위협 정보)을 참조할 수 있습니다. 일치한 출처는 항상 거부됩니다. 허용 목록과 차단 목록보다 먼저 판단하고, 접근 제어 모드와 관계없이 적용되며, 경로 규칙으로도 덮어쓸 수 없습니다. 즉 언제나 차단이 먼저입니다. 웹 사이트, 포트 포워딩, 프로토콜 라우팅, STUN 내장 포워딩, frps 인스턴스(frpc 로그인 검사)에서 쓸 수 있습니다. 구독 목록은 갱신 즉시 반영되며, 참조 중인 목록은 삭제할 수 없습니다. 자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## 웹 서비스

- **노크 입장 제한과 로그인 후 허용**: 사이트는 출처가 [포트 노킹](/ko/docs/modules/knock) 규칙의 유효한 허가를 가지고 있을 때만 접근을 받도록 할 수 있습니다. 사이트를 허용 입구로 쓸 수도 있습니다. 방문자가 사이트 인증을 통과하면 그 출처 IP(IPv6는 기본적으로 /64 단위)에 허가가 등록되고, 해당 규칙을 참조하는 사이트, 포트 포워딩, 시스템 방화벽이 바로 통과시킵니다. 입구 페이지 `/__gately_knock`에서 허용을 확인하고 취소할 수 있으며, 듀얼 스택 탐지로 IPv4와 IPv6을 모두 허용합니다. 로그아웃, 사용자 삭제, 비밀번호 변경 시 자동으로 취소됩니다. 노크 규칙에서 방화벽 차단을 켜지 않으면 포트를 비워 둘 수 있고, 이때 규칙은 웹 로그인 허용에만 쓰입니다.
- **관리 콘솔 로그인 시 인증 생략**: Gately 관리 콘솔에 로그인한 관리자는 이 옵션을 켠 사이트에서 기본 인증이나 웹 인증을 거치지 않아도 됩니다. 같은 상위 도메인 아래에서는 통합 로그인 도메인을 통해 적용되고, 사이트와 관리 콘솔의 상위 도메인이 다르면 「관리 콘솔 진입 주소」를 입력한 뒤 관리자가 사이트에서 `/__gately_auth/admin-start`를 열면 일회용 티켓 리디렉션으로 핸드셰이크합니다(일반 방문자는 리디렉션되지 않습니다). 자격 증명은 관리 콘솔 세션에 묶여 로그아웃, 모든 기기에서 로그아웃, 비밀번호 변경 시 즉시 무효가 되며 백엔드로 전달되지 않습니다.
- **공유 사용자 Passkey 로그인**: 켜면 공유 사용자는 사이트의 `/__gately_auth/passkey` 페이지에서 Passkey를 등록하고, 이후 로그인 페이지에서 클릭 한 번으로 로그인할 수 있어 비밀번호와 일회용 코드를 입력할 필요가 없습니다. 사이트의 정확한 도메인과 OIDC 발급자 도메인에서만 제공됩니다. 관리자가 사용자의 비밀번호나 TOTP 비밀 키를 바꾸면 그 사용자의 Passkey도 함께 삭제됩니다.
- **평문 HTTP/2 백엔드**: 사이트 옵션 「http:// 백엔드에 평문 HTTP/2(h2c) 사용」은 평문 포트에서만 수신하는 gRPC 서비스(NetBird 관리/시그널 등)를 위한 것입니다. gRPC 스트리밍과 트레일러는 그대로 전달되고, 같은 포트의 WebSocket 요청은 자동으로 HTTP/1.1을 사용합니다.

## 침입 방지

커널 수준의 미끼 포트와 포트 스캔 탐지가 차단할 때 차단 사유, 로그, 알림에 일치한 포트가 표시됩니다. 커널이나 nftables가 포트 기록을 지원하지 않으면 자동으로 건너뛰고 나머지 규칙은 그대로 동작합니다. 자세한 내용은 [침입 방지](/ko/docs/modules/guard)를 참고하세요.

## 기타 개선

- 대화상자, 확인 상자, 드로어를 연 상태에서 스크롤해도 아래 페이지가 움직이지 않습니다. 오버레이 안의 터미널과 편집기는 평소처럼 스크롤됩니다.
- 카드와 그룹 목록, 정렬 바, 탭 사이의 간격을 통일했습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동으로 설치하며, 그 밖의 배포 방식은 「시스템 설정」에서 온라인으로 업그레이드할 수 있습니다.
- 관리자 비밀번호가 약하면 업그레이드 후 다음 비밀번호 로그인 때 비밀번호 변경을 요구합니다. 이후 「시스템 설정 → 계정 및 보안」에서 보안 점수를 확인할 수 있습니다.
- 낯선 주소 실패 예산은 기본으로 켜져 있으며(10분에 20회), 한 번도 로그인에 성공한 적 없는 주소에만 영향을 줍니다.
