# Gately v0.6.8 출시

2026년 11월 17일

[다운로드 v0.6.8](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8)

## 보안 수정

이번 버전은 v0.6.6.6 이하에 영향을 주는 다음 문제를 수정합니다. 가능한 한 빨리 업그레이드하세요.

- **쓰기 토큰으로 설정 디렉터리를 읽을 수 있던 문제(높음)**: `storage:write`, `webservice:write` 같은 토큰으로 설정 디렉터리를 스토리지나 정적 사이트로 마운트한 뒤 `account.json`을 읽어 관리자 세션을 위조할 수 있었습니다. 이제 스토리지 마운트, 정적 사이트, WebDAV/FTP/SMB는 설정 디렉터리와 그 하위 경로를 거부합니다. 설정 디렉터리를 포함하는 상위 디렉터리는 그대로 공유되며 설정 디렉터리만 숨겨집니다. EasyTier/Tailscale/NetBird 프로그램 경로와 백업 암호는 로그인 세션에서만 변경할 수 있고, 토큰 편집기에는 서버 파일을 읽고 쓸 수 있는 모듈이 표시됩니다.
- **사이트 서드파티 로그인 리디렉션 주소를 Host로 조작할 수 있던 문제(높음)**: 와일드카드 또는 기본 사이트에서 로그인 티켓이 공격자의 도메인으로 전송될 수 있었습니다. 이제 로그인은 이 인스턴스를 가리키는 주소에서만 시작됩니다.
- **32비트 빌드에서 SMB 인증 전 파싱이 패킷 하나로 충돌하던 문제(높음)**: 오프셋과 길이를 64비트로 판정하고, panic이 발생하면 해당 연결만 끊습니다. 로그인하지 않은 연결에는 타임아웃, 요청 크기, 연결 수 상한을 추가했습니다.
- **기타(중간/낮음)**: fnOS 게이트웨이 모드에서 같은 호스트의 다른 포트 페이지가 관리자 쿠키로 요청을 보낼 수 있던 문제, 관리 콘솔 쿠키가 같은 호스트 이름의 사이트로 전달되던 문제, 읽기 전용 계정에 일부 자격 증명이 보이던 문제, WebDAV/FTP가 공유 범위 밖을 가리키는 심볼릭 링크를 따라가던 문제, 위조 가능한 단일 SYN으로 미끼 포트/스캔 탐지가 차단하던 문제, Webhook/PushPlus에 이스케이프되지 않은 방문자 텍스트가 들어가던 문제, 사이트 사용자 비밀번호가 평문으로 저장되던 문제(bcrypt로 변경), 관리 콘솔에 CSP 추가 및 HTTPS에서 Secure 쿠키, 교차 출처는 사이트 자체 도메인만 허용, Passkey 로그인 챌린지를 출처별로 제한, 진단 번들 마스킹 보강.
- **릴리스 서명**: `checksums.txt`를 minisign으로 서명하며(`checksums.txt.minisig`), 온라인 업그레이드는 서명을 먼저 검증한 뒤 SHA-256을 확인합니다. v0.6.8 이후 버전 중 서명 파일이 없는 릴리스는 온라인 업그레이드가 거부됩니다.

## 관리 콘솔

- **탐색 정리**: 관련 페이지를 탭이 있는 페이지로 합쳐 사이드바가 39개에서 27개 항목으로 줄었고, 이전 주소는 자동으로 이동합니다. 모바일 드로어의 그룹은 접을 수 있습니다.
- **전역 검색**: Ctrl/⌘+K로 페이지, 탭, 사이트 도메인, 포트 포워딩 규칙, DDNS 레코드, 인증서를 검색합니다.
- **첫 사용**: 새로 설치한 뒤 비밀번호를 바꾸면 사용 목적(사이트 게시, 포트 포워딩/홀 펀칭, 동적 DNS, 메시 네트워킹, 파일 공유, VPS 진입점 또는 전체)을 선택하고, 목적에 맞는 모듈이 켜집니다. 개요 상단의 「시작하기」 체크리스트는 실제 설정에 따라 항목이 체크됩니다.
- **빠른 사이트 마법사**: 세 단계로 사이트를 게시합니다. 도메인, 백엔드 주소(연결 테스트와 Home Assistant, Jellyfin, Emby, Vaultwarden, Nextcloud, Immich, Proxmox VE, Synology, fnOS 등의 템플릿 제공), HTTP 또는 HTTPS(즉석에서 인증서 신청) 순서입니다.
- **빈 목록 템플릿**: 포트 포워딩과 DDNS의 빈 목록에 흔한 시나리오 템플릿을 제공합니다.
- **기타**: HTTPS 사이트 행에 해당 인증서의 남은 일수 표시, 저장 전 필수 항목 확인, 목록 로드 실패 시 원인과 다시 시도 표시, 모바일 버튼과 상단 바 개선 및 현재 페이지 이름 표시, 페이지 제목에서 공식 문서로 링크, 상태 색상 대비와 접근성 개선.

## 가져오기

- **Nginx Proxy Manager**: nginx 가져오기가 NPM 설정을 직접 읽고, `set` 변수를 `proxy_pass`와 리디렉션 대상에 대입하며, Force SSL, Cache Assets 등을 Gately 설정으로 매핑합니다.
- **Sun-Panel**: 탐색 패널에 Sun-Panel 1.x(.sun-panel.json)와 2.x(.zip) 내보내기 파일을 가져와 새 패널로 만들거나 기존 패널에 병합할 수 있습니다.

## 탐색 패널

- **레이아웃**: 패널마다 링크 스타일을 카드 또는 데스크톱 앱 아이콘 중에서 고를 수 있고, 아이콘 크기, 한 줄당 개수(와이드 화면과 모바일 별도), 간격, 콘텐츠 너비를 조절할 수 있습니다. 방문자는 스타일을 바꿀 수 있습니다.
- **주소 선택기**: 다른 접속 방법이 있는 링크를 클릭하면 주소 선택기가 나타납니다(데스크톱은 팝오버, 모바일은 하단 시트, 키보드 지원). 사용할 수 없는 주소는 취소선으로 표시됩니다.
- **스위치**: 그룹별 개수와 다중 주소 배지(둘 다 기본값은 꺼짐). 「로그인하여 더 많은 링크 보기」는 페이지가 원래 비어 있을 때만 표시됩니다.

## 침입 방지와 접근 제어

- 미끼 포트와 스캔 탐지는 TCP 핸드셰이크를 완료한 소스만 집계해 차단하므로, 위조된 소스 주소의 SYN 때문에 잘못 차단되지 않습니다.
- 관리자 로그인에 성공한 뒤의 차단 면제는 미끼 포트와 포트 스캔에만 적용됩니다. 로그 규칙, 경로 탐색, TLS, 노크, 파일 서비스 차단은 그대로 적용됩니다.
- WebDAV/FTP/SMB 로그인 실패 시 `fileauth.failed` 이벤트를 발행하며 규칙 템플릿이 제공됩니다.
- 차단 테이블은 최대 32768개입니다. 가득 차면 만료된 항목과 가장 오래된 임시 자동 차단부터 제거하며, 영구 차단과 수동 차단은 제거하지 않습니다.

## 포트 포워딩과 프로토콜 분기

- TCP 포트마다 단일 소스(IPv4 주소 또는 IPv6 /64)의 동시 연결을 제한합니다. 기본값은 포트 상한의 절반이며 규칙별과 전역 설정에서 조정할 수 있습니다. 루프백과 사설망 소스는 제한하지 않습니다.
- 첫 데이터 타임아웃(기본 60초) 안에 양쪽 모두 데이터를 보내지 않는 TCP 연결은 닫힙니다.
- 대상 주소를 host:port 형태로 입력하면 화면에서 바로 알려 줍니다.

## frp, DNS, WAF

- frps가 UDP 포트에서 KCP와 QUIC을 수신할 수 있고, frpc/frps에서 QUIC 매개변수를 조정할 수 있으며, frps가 방화벽을 자동으로 열 수 있습니다.
- 사용자 지정 DNS: 우선 서버가 1초 안에 응답하지 않거나 실패하면 다음 서버를 병렬로 조회해 가장 먼저 돌아온 결과를 사용합니다.
- 동적 DNS: 호스트 레코드를 소문자로 통일하고, Porkbun에서 레코드를 찾지 못하면 전체 도메인 목록 조회로 대체합니다(#99). A/AAAA는 주소로 비교하므로 확장 표기 IPv6가 변경으로 간주되지 않습니다.
- WAF: 정규식 사전 필터가 기본으로 켜집니다(끌 수 있음).

## 로그와 성능

- 로그 수준 설정이 추가되었습니다(기본 info, `GATELY_LOG_LEVEL`로도 지정 가능). 포트 포워딩과 프로토콜 분기의 연결별 기록은 기본적으로 더 이상 기록되지 않습니다.
- 로그, 번역, 리버스 프록시, 차단 테이블, DNS 조회, 포트 포워딩 등의 핵심 경로에서 메모리 할당과 락 경합을 줄였습니다. 관리 콘솔은 컴포넌트와 언어 팩을 필요할 때 불러와 첫 화면이 더 가벼워졌습니다.

## 기타

- 데모 모드: `-demo` / `GATELY_DEMO=1`로 읽기 전용 공개 인스턴스를 시작합니다. 한 번의 클릭으로 읽기 전용 로그인이 가능하고 데이터는 매시간 초기화됩니다(`deploy/demo`).
- 사용 관련 질문은 먼저 GitHub Discussions의 Q&A에 올려 주세요. Telegram 그룹은 실시간 대화용입니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동으로 설치하며, 그 밖의 배포 방식은 「시스템 설정」에서 온라인으로 업그레이드할 수 있습니다.
- 사이트 사용자 비밀번호는 bcrypt 해시로 저장되며 API는 마스킹된 값만 반환합니다. 이전 버전에서 저장된 평문 비밀번호도 그대로 사용할 수 있고, 해당 리스너를 다음에 저장할 때 변환됩니다.
- 로그 수준 기본값은 info입니다. 포트 포워딩의 연결별 기록이 필요하면 설정에서 debug로 바꾸세요.
- 설정 디렉터리 자체 또는 그 하위를 가리키는 스토리지 마운트, 정적 사이트, 파일 서비스 디렉터리는 업그레이드 후 더 이상 제공되지 않으며 로그에 목록이 남습니다.
