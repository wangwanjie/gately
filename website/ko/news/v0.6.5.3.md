# Gately v0.6.5.3 출시

2026년 11월 10일

[v0.6.5.3 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.5.3)

## 보안 수정: 응답 캐시

지금까지 메모리 응답 캐시를 켜고 "기본 유지 시간"을 0보다 크게 설정한 리버스 프록시 사이트는 `X-Emby-Token`, `X-Api-Key`, `X-Plex-Token` 같은 자격 증명 요청 헤더나 `api_key`, `token`, `access_token` 같은 쿼리 매개변수가 포함된 요청의 응답을 캐시했고, 이후 같은 주소를 요청한 다른 방문자가 그 응답을 받을 수 있었습니다. 또한 사이트에서 교차 출처와 캐시를 함께 켜면 특정 출처용 교차 출처 응답 헤더까지 캐시에 저장되어 다른 출처의 교차 출처 요청이 실패했습니다. 이번 릴리스에서는:

- 흔히 쓰이는 자격 증명 요청 헤더나 자격 증명 쿼리 매개변수가 있는 요청은 `Authorization`, `Cookie`와 마찬가지로 어떤 모드에서도 캐시하지 않습니다.
- 캐시 항목에는 Gately가 방문자 출처에 따라 쓰는 교차 출처 헤더를 저장하지 않고, 캐시 적중 시 해당 요청에 맞게 다시 생성합니다. 백엔드의 `Vary`에 `Accept-Encoding`(사이트에서 교차 출처를 켠 경우 `Origin` 포함) 외의 요청 헤더가 있으면 캐시하지 않습니다.
- 경로에 `;`, `\`, `%2F`, `%5C`가 포함된 요청은 캐시를 거치지 않습니다.

응답 캐시를 사용하는 사이트는 가능한 한 빨리 업그레이드하는 것을 권장합니다.

## 내비게이션 패널(#78)

왼쪽 메뉴의 "Web → 내비게이션 패널"에서 패널 라이브러리를 관리합니다. 자주 쓰는 서비스의 링크를 그룹별로 한 페이지에 모은 뒤, Web 서비스에서 유형이 "내비게이션 패널"인 사이트를 추가하고 패널을 선택합니다.

- 각 링크에는 이름, 그룹, 설명, 외부 주소와 선택 사항인 내부망 주소, 아이콘과 색상이 있습니다. 내부망 방문자(루프백, 사설, 링크 로컬 주소 또는 패널에 추가한 내부망 범위)는 자동으로 내부망 주소를 사용하며, 페이지에서 직접 전환할 수도 있습니다.
- 각 링크에 "다른 접속 방식"을 최대 8개 더 추가할 수 있습니다. 예: IPv6 직접 연결, frp, STUN 통과, Cloudflare 터널.
- 내장 아이콘 110개(Gately 각 모듈, 자주 쓰는 앱, 시스템과 네트워크 장비, 일반 아이콘)를 제공하며, emoji, 이미지 주소, 업로드한 이미지도 쓸 수 있습니다.
- 주소에 `{host}`, `{port}`, `{1}`과 STUN 변수를 쓸 수 있고 "Web 서비스 사이트에서 추가"할 수 있습니다. 페이지는 검색과 라이트·다크 테마를 지원합니다.
- 페이지는 서버에서 생성되며 무작위 nonce가 붙은 내장 스타일과 스크립트만 실행합니다. 사이트 인증, IP 접근 제어, 국가 필터, WAF는 평소대로 적용됩니다.

내부망과 외부의 구분은 방문자의 직접 연결 주소로 판단합니다. 외부 방문자가 로컬 frpc, cloudflared, Docker 포트 매핑을 거쳐 들어오는 경우 리스너에서 PROXY 프로토콜을 켜거나 신뢰할 수 있는 프록시를 설정하세요. 자세한 내용은 [웹 서비스 · 내비게이션 패널](/ko/docs/modules/web#nav-panel)을 참고하세요.

## 방문자 감사

"Web → 방문자 감사"는 모든 사이트의 접속을 방문자 주소별로 집계합니다. 첫 접속과 최근 접속, 일별 요청 수와 차단 수, 상태 코드 분포, 차단 사유, 접속한 사이트, 경로, 사용자, User-Agent를 보여 줍니다. 오늘, 7일, 30일 또는 전체 보존 기간으로 집계할 수 있고, 차단됨, 인증됨, 관리자, 차단 중, 스캐너형으로 필터링하고 검색할 수 있으며, 상세 화면에서 해당 주소를 바로 차단하거나 액세스 로그를 볼 수 있습니다.

방문자별 집계 수치만 저장하고 경로는 경로 부분만 기록하며, 쿼리 문자열, 요청 본문, Cookie, 자격 증명은 전혀 기록하지 않습니다. 데이터는 압축되어 설정 디렉터리에 저장되고(설정 백업에는 포함되지 않음), 보존 일수(기본 30일)와 방문자 수 상한(기본 10000)을 조정하거나 기능을 끌 수 있습니다. 자세한 내용은 [웹 서비스 · 방문자 감사](/ko/docs/modules/web#visitor-audit)를 참고하세요.

## 네트워크 토폴로지 재생

네트워크 토폴로지에 "재생"이 추가되었습니다. 기록을 켜면 5초마다 전체 토폴로지의 스냅샷을 메모리에만 저장하며, 용량(기본 8 MB) 안에서 최신 데이터를 유지하므로 트래픽이 적을 때는 더 긴 시간을 담습니다. 타임라인은 트래픽을 영역 차트로 보여 주고, 리스너 시작 실패나 백엔드 이상이 있던 구간을 빨간색으로 표시합니다. 드래그로 위치를 정하고, 한 단계씩 이동하고, 1×부터 60×까지 재생하며 유휴 구간을 건너뛸 수 있고, 재생 중에도 일곱 가지 레이아웃, 필터, 마스킹, 활동 포커스를 그대로 쓸 수 있습니다. 기록은 기본적으로 꺼져 있으며, 기록을 끄면 데이터가 지워집니다.

## 경로별 캐시 규칙(#77)

리버스 프록시 사이트의 응답 캐시에 경로별 규칙을 설정할 수 있습니다. "캐시 안 함", 별도의 유지 시간, 또는 "강제 캐시"(백엔드의 `no-store`, `no-cache`, `max-age`를 무시하되 `private`는 존중)입니다. 더 구체적인 규칙이 우선합니다. "트래픽" 탭에는 현재 캐시된 항목 수와 사용량이 표시되며, 전체 캐시나 특정 규칙 경로 아래의 캐시를 비울 수 있습니다. 강제 캐시된 응답은 모든 방문자가 공유하므로 방문자 신원과 무관한 콘텐츠에만 사용하세요.

## Web 터미널: 키 유형별 호스트 지문 확인

서버에는 보통 ECDSA, RSA, Ed25519 등 여러 호스트 키가 함께 있습니다. 이제 Web 터미널은 지문과 함께 키 유형을 기록하고(`ECDSA SHA256:...`처럼 표시) 그 유형의 키만 협상합니다. 유형이 없거나 맞지 않으면 다른 유형을 하나씩 시도하고, 기록된 지문과 일치하는 키만 받아들입니다. `ssh-keyscan` 같은 도구로 얻은 어떤 유형의 지문이든 바로 쓸 수 있으며, "호스트 키가 변경되었습니다"라는 잘못된 경고가 더 이상 나오지 않습니다. 호스트 키 확인은 여전히 인증 전에 이루어지며, 지문이 모두 맞지 않으면 비밀번호를 보내지 않습니다.

## 로그 패널

로그 영역 아래의 드래그 막대로 높이를 조절할 수 있고(방향키도 지원), 더블클릭하면 기본값으로 돌아가며, 높이는 브라우저별로 기억됩니다. 도구 모음에 "전체 화면" 버튼이 추가되었고 Esc로 나갑니다. 이전 로그를 보는 동안 새 로그가 화면을 맨 아래로 끌어내리지 않으며, "최신으로 이동" 버튼에 그사이 새로 들어온 항목 수가 표시됩니다.

## 문제 수정

- IPv6 주소로 접속할 때 리디렉션과 경로 재작성 규칙의 `{host}`가 대괄호를 유지합니다. 경로 재작성 규칙에서 `{host}`를 대입할 때도 리디렉션 변수와 같은 방식으로 문자를 검사하며, 잘못된 문자가 포함된 Host에는 400을 반환합니다.
