# Gately v0.6.5.2 출시

2026년 11월 8일

[v0.6.5.2 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.5.2)

## Synology DSM 등 nf_tables가 없는 커널

Synology DSM 커널에는 nf_tables가 없어, 지금까지 침입 방지는 방화벽 규칙 기록에 실패하고 1분마다 다시 시도했으며 방화벽 자동 허용도 효과가 없었습니다. 이번 버전에서는:

- 커널에 nf_tables가 없거나 nft 명령이 없으면 침입 방지가 iptables(legacy)와 ipset을 사용합니다. 규칙은 mangle 테이블의 Gately 전용 체인에 기록되어 Synology 방화벽과 Docker 규칙보다 먼저 처리됩니다. 수동 차단, 영구 차단, 미끼 포트, 포트 스캔 탐지가 모두 커널에서 적용되며, 남은 시간이 약 24일을 넘는 차단은 만료 전에 자동으로 다시 기록됩니다.
- 포트 포워딩, 웹 서비스, 프로토콜 라우팅의 "방화벽 자동 허용"은 Gately 전용 iptables 체인을 사용하고 점프 규칙을 INPUT 맨 앞에 둡니다. Synology 방화벽을 다시 불러와도 30초 안에 복구됩니다. Docker와 직접 설치 모두 해당됩니다.
- Docker 이미지에 iptables-legacy와 ipset을 포함했습니다. nftables를 쓸 수 있는 시스템의 동작은 그대로입니다.
- 둘 다 사용할 수 없으면 침입 방지가 이유와 함께 "사용 불가"로 표시하고 주기적으로 다시 시도하지 않습니다.

Docker 배포에는 host 네트워크와 `cap_add: NET_ADMIN`이 필요합니다. 자세한 내용은 [침입 방지](/ko/docs/modules/guard)를 참고하세요.

## 웹 사이트 첫 레이블 와일드카드

사이트 도메인의 첫 레이블에 `*`를 하나 쓸 수 있습니다. `api-*.example.com`은 `api-1.example.com`, `api-test.example.com`과 일치하고 더 깊은 하위 도메인과는 일치하지 않습니다. 일치 순서는 정확한 도메인, 와일드카드, `*`입니다. 첫 레이블 와일드카드가 `*.example.com`보다 우선하며, 길이가 같은 와일드카드는 목록에서 앞에 있는 사이트가 사용됩니다. 리디렉션에서는 `{1}`로 `*`에 일치한 부분을 쓸 수 있습니다. 인증서는 여전히 `*.example.com`으로 신청합니다. 자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## 포워드 인증: 401 리디렉션

포워드 인증에 "401 리디렉션" 스위치가 추가되었습니다. Casdoor처럼 401 응답의 `Location`에 동적 로그인 주소를 주는 인증 서비스용입니다. 켜져 있고 "로그인 리디렉션"이 비어 있으면 Gately가 방문자를 그 주소로 302 리디렉션하고 `Set-Cookie`와 `Cache-Control`을 함께 전달합니다. 상대 주소, `javascript:` 등은 401을 그대로 반환합니다. 기본값은 꺼짐입니다.

## 수정 사항

- 백엔드가 요청 본문을 다 읽기 전에 응답하면(예: LAN에서 Home Assistant iOS 앱으로 로그인) HTTP/2 요청으로 Gately 프로세스가 종료되었습니다.
- 끝에 점이 붙은 도메인(`example.com.` 등)이 점 없는 도메인과 같은 사이트에 일치합니다.
- 진단 패키지가 호스트 이름을 단어 단위로, 대소문자 구분 없이 바꿉니다. gate처럼 짧은 호스트 이름 때문에 gately가 `<hostname>ly`로 바뀌지 않으며, `nas-backup` 같은 복합 이름 속 호스트 이름은 계속 바뀝니다.
- 네트워크 토폴로지의 마스킹이 첫 레이블 와일드카드 도메인에도 적용됩니다. 사이트 공유 링크를 복사할 때 첫 번째 구체적인 도메인을 사용하고 모든 와일드카드 형식은 건너뜁니다.
