# Gately v0.6.3.5 출시

2026년 11월 3일

[v0.6.3.5 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.3.5)

## 보안 수정

- 읽기 전용 계정과 읽기 전용 API 토큰이 Tailscale 상태 API와 모듈 로그에서 로그인 대기 중인 로그인 링크를 볼 수 있었고, 링크를 얻으면 이 게이트웨이를 자신의 tailnet에 등록할 수 있었습니다. 이제 로그인 링크는 Tailscale 쓰기 권한이 있는 ID에만 반환되고, 로그에는 링크의 호스트 부분만 남습니다(새 NetBird 모듈도 로그인 링크와 장치 코드를 같은 방식으로 처리합니다).
- Web 터미널의 "연결 테스트"는 저장된 연결을 테스트하거나 저장된 비밀 값을 합치거나 인증 프리셋을 참조할 때도 사용자 약관과 2단계 인증 확인을 먼저 통과해야 합니다. 이런 요청은 저장된 비밀번호를 요청에 지정된 호스트로 보내기 때문입니다.

## NetBird 네트워크 연결 (#69)

공식 클라이언트를 관리하는 NetBird 모듈이 추가되었으며, 사용법은 Tailscale 모듈과 같습니다.

- Gately가 `netbird service run`을 직접 관리하거나(상태는 설정 디렉터리에 저장) 시스템에 이미 설치된 NetBird 서비스를 넘겨받을 수 있습니다.
- 설정 키 또는 로그인 링크 / 장치 코드로 로그인할 수 있고, 직접 운영하는 관리 서버 주소, 호스트 이름, 라우트, DNS, 인바운드 차단, 사용자 공간 네트워크와 "로컬 서비스 접근", SOCKS5 프록시를 설정할 수 있습니다.
- 관리 모드에서는 Gately가 연결을 맡아 데몬이 재시작되면 자동으로 다시 연결하고, 실패하면 10초에서 5분까지 백오프하며 다시 시도합니다.
- 페이지의 "온라인 설치"에서 NetBird를 다운로드, 업데이트, 롤백, 제거할 수 있고, "기본 설정 복원"은 로그아웃하고 로그인 상태를 지웁니다.

자세한 내용은 [연결 및 터널링 · NetBird](/ko/docs/modules/tunnels)를 참고하세요.

## 자동 업데이트 확인과 보안 알림 (#68)

- 기본적으로 12시간마다 GitHub의 릴리스 목록과 보안 권고를 익명으로 조회합니다("업데이트 프록시"를 거치며, 읽기만 하고 아무것도 보내지 않습니다). "정보" 페이지나 "설정"에서 끌 수 있습니다.
- 새 버전이 있으면 관리 화면 상단에 알림이 표시되어 업데이트 내용을 보거나 이 버전을 건너뛸 수 있습니다. 현재 버전이 공개된 보안 문제의 영향을 받으면 빨간색 알림으로 권고 번호, 심각도, 수정 버전을 보여 줍니다.
- 새 버전이나 보안 문제를 발견하면 `system.update` / `system.security` 이벤트를 발생시키고, 알림 센터에 "업데이트" 규칙 템플릿이 추가되었습니다. frp, cloudflared, Tailscale, NetBird, File Browser의 온라인 설치 카드에 "업데이트 확인"이 추가되었고, Docker 정기 확인에서 새 이미지를 발견할 때도 알림을 보냅니다.

자세한 내용은 [설치 및 배포 · 자동 업데이트 확인과 보안 알림](/ko/docs/guide/install#update-check)을 참고하세요.

## 항목 복사 (#65)

모든 목록에서 기존 항목을 바탕으로 사본을 만들 수 있습니다. 편집 창은 원래 항목을 템플릿으로 열고 이름에 자동으로 "사본"을 붙입니다. 비밀번호와 비밀 값은 서버에서 원래 항목의 값을 그대로 쓰므로 평문이 브라우저를 거치지 않습니다. 인증서 사본은 다시 발급하거나 다시 읽어 오며, 원래 인증서의 파일을 덮어쓰지 않도록 배포 대상은 기본적으로 사용 안 함 상태입니다. 웹 사이트 사본은 다른 리스너에 둘 수 있고, 리스너 사본은 사이트를 함께 복사할지 선택할 수 있습니다. API는 범용 `POST <경로>/{key}/copy`입니다.

## 웹 사이트 이동 (#63)

- 사이트 편집 창의 "소속 리스너"를 편집할 때도 바꿀 수 있으며, 저장하면 사이트가 새 리스너로 옮겨집니다.
- "정렬 및 일괄" 모드에 "리스너로 이동"이 추가되어 리스너를 넘나들며 선택한 여러 사이트를 한 번에 옮길 수 있습니다.
- 사이트를 다른 리스너의 사이트나 그룹 위로 끌어다 놓아도 옮겨집니다.

대상 리스너에 같은 도메인이 있으면 이동을 거부합니다. 성능 모니터링 경보 규칙과 공유 링크의 사용 횟수는 사이트를 따라 옮겨지며, 로그인 상태는 리스너와 사이트별로 구분되므로 이동 후 방문자는 다시 로그인해야 합니다. 로그인이 필요한 사이트를 HTTPS에서 평문 HTTP로 옮기면 위험을 경고합니다.

## 알림과 프록시 (#67)

- 알림 센터에 "알림 설정"이 추가되어 전역 알림 프록시(사용 안 함 / 전역 업데이트 프록시 사용 / 사용자 정의)를 설정할 수 있고, 채널마다 따로 선택할 수도 있습니다. `http://`, `https://`, `socks5://`, `socks5h://`를 지원하며, 메일이 프록시를 거칠 때는 터널 안에서 STARTTLS / SSL을 수행합니다.
- DDNS / STUN의 Webhook, 예약 작업의 HTTP 요청, 구독 IP 목록과 GeoIP 데이터베이스 다운로드에도 프록시를 설정할 수 있습니다.
- 카드와 오류 메시지에서 프록시 비밀번호를 숨깁니다.

## 기타 개선

- 페이지 헤더와 목록 도구 모음이 스크롤해도 계속 보입니다. 모듈 헤더는 상단에 고정되고 제목이 스크롤되어 사라지면 작업 표시줄만 남습니다. 카드 안의 도구 모음은 헤더 아래에 고정됩니다. 대화 상자는 제목, 탭 표시줄, 하단 버튼이 고정되고 양식은 가운데에서 스크롤됩니다(#64).
- Docker의 pull, push, 빌드, 업데이트 확인, Compose, 일괄 업그레이드 같은 백그라운드 작업을 중단할 수 있으며, Compose에는 먼저 인터럽트 신호를 보내 스스로 정리하게 합니다(#67).
- 네트워크 토폴로지의 사이트, 백엔드, 활성 IP에서 바로 접근 로그를 볼 수 있고, 사이트, 백엔드, 리스너는 토폴로지 화면에서 바로 편집할 수 있습니다. 웹 서비스 사이트 행에 "로그" 버튼이 추가되었습니다(#67).
- 이미지가 Docker Hub의 `vanjayak/gately`에도 게시됩니다. GHCR과 같은 멀티 아키텍처 이미지이며 마찬가지로 cosign 서명이 있습니다(#67).
- 새 API 토큰을 만드는 창에 `/api/openapi.json` 호출 예시가 추가되었습니다(#67).
- 웹 서비스의 수동 차단과 "끊고 차단"에 "영구" 옵션이 추가되었습니다.
- "차단된 출처 숨기기"는 아직 차단 중인 출처가 차단되기 전에 보낸, 차단을 일으킨 요청도 함께 숨깁니다.
- 읽기 전용 계정의 사이드바에 감사 로그, 설정 기록, API 토큰, 설정이 더 이상 표시되지 않습니다. 이 페이지를 직접 열면 개요로 돌아가며, 화면에서 관리자 API를 요청하지 않습니다.

## 수정 및 강화

- 항목 일괄 추가를 잠금을 유지한 채 검증하도록 바꿔, 웹 서비스 리스너와 IP 목록을 새로 추가할 때의 데이터 경합을 수정했습니다.
- 사이트를 연달아 옮기면 순서대로 실행되어, 성능 모니터링 경보 규칙이 이미 없는 사이트에 남지 않습니다.
- 수동 차단은 루프백 주소, 지정되지 않은 주소, 신뢰할 수 있는 프록시 주소를 거부하고(침입 방지의 수동 차단은 루프백과 지정되지 않은 주소를 거부), 아주 큰 차단 초 값이 오버플로되어 영구 차단이 되는 일이 없어졌습니다.
- Docker 정기 확인은 확인이 실패하거나 컨테이너가 멈춘 동안에도 알림 기록을 유지하므로 같은 새 이미지를 중복으로 알리지 않습니다.
- NetBird와 Tailscale이 데몬을 관리할 때 기존 사용자 지정 상태 디렉터리의 권한을 더 이상 바꾸지 않습니다. NetBird 0.75 미만의 사용자 공간 SOCKS5가 항상 0.0.0.0에서 수신 대기하면 경고하고, SOCKS5가 이 장비 밖에서 접근 가능한 주소에서 수신 대기하면 화면에서 알려 줍니다.
- 토폴로지 화면에서 이름이 있는 기본 사이트의 접근 로그를 보면 해당 사이트로 필터링됩니다. 이름이 없는 기본 사이트에는 모든 사이트의 로그가 섞이는 진입점을 더 이상 제공하지 않습니다.
- 실행 로그 출처 필터의 지우기 버튼이 다시 정상적으로 동작합니다. 읽기 전용 계정이 관리자 페이지를 새로 고쳐도 403 요청이 더 이상 생기지 않습니다.
- 프록시 비밀번호에 인코딩되지 않은 `@`, `/`, `:`가 있어도 완전히 숨깁니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만드세요. Docker 소켓이 마운트되어 있으면 Gately의 Docker 페이지에서 Gately 자체를 업그레이드할 수도 있습니다. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동으로 설치합니다. 그 밖의 배포 방식은 "설정"에서 온라인으로 업그레이드할 수 있습니다.
- 업그레이드 후 자동 업데이트 확인은 기본적으로 켜져 있으며, 필요 없으면 "정보" 페이지에서 끌 수 있습니다.
