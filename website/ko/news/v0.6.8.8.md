# Gately v0.6.8.8 출시

2026년 11월 25일

[v0.6.8.8 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.8)

## 도메인 임의 구간 와일드카드(#118)

- 사이트 도메인의 `*`가 더 이상 첫 번째 구간에만 쓸 수 있는 것이 아닙니다. `audiobook.*.example.com`에서는 중간 구간 전체의 `*`가 한 구간과 일치하고, `audiobook.*`에서는 끝 구간 전체의 `*`가 한 개 이상의 구간(`audiobook.example.com`, `audiobook.home.lan`)과 일치하며, `a.api-*.example.com`처럼 구간 안의 `*`는 해당 구간 안에서만 일치합니다.
- 도메인마다 `*`는 여전히 하나만 쓸 수 있고, 리디렉션의 `{1}`에는 일치한 부분이 들어갑니다. 고정 부분이 IP가 되는 형식(`192.168.1.*`, `10.*` 등)은 거부됩니다.
- `audiobook.*`처럼 끝에 오는 와일드카드는 다른 사람이 등록한 도메인(`audiobook.attacker.com` 등)과도 일치하므로, 서드파티 로그인 반환 주소, 자격 증명을 포함한 교차 출처 요청, 노크 허용 확인에서는 이를 사이트 자체의 도메인으로 보지 않습니다. 이 기능이 필요하면 접미사가 고정된 도메인을 입력하세요.
- `*`가 첫 번째 구간이 아닌 곳에 있는 사이트는 실제로 접속한 도메인별로 인증서를 일치시키며, 인증서가 없다고 잘못 알리지 않습니다.
- 라우팅 우선순위는 그대로입니다. 정확히 일치하는 도메인이 먼저, 그다음 가장 길게 일치하는 와일드카드, 마지막이 `*`입니다. 네트워크 토폴로지의 마스킹과 별칭도 이러한 도메인에 적용됩니다.

## 탐색 패널

- **그룹 로그인 후 표시**: 링크 목록의 그룹 제목에 잠금 버튼이 추가되었습니다. 켜면 그룹 전체가 로그인한 방문자에게만 표시되고, 이후 그룹에 추가하는 링크에도 자동으로 적용되므로 하나씩 선택할 필요가 없습니다.
- **그룹 이름 변경(#122)**: 그룹 제목에 이름 변경 버튼이 추가되었습니다. 그룹 안의 링크가 함께 이름이 바뀌고 순서가 유지됩니다. 이미 있는 그룹 이름으로 바꾸면 확인 후 병합됩니다. "로그인 후 표시" 설정은 새 이름을 따라가며, 공개 그룹으로 병합할 때는 그룹 안의 링크마다 "로그인 후 표시"가 선택되므로 이름을 바꿔도 로그인하지 않은 방문자에게 노출되지 않습니다. 휴대폰에서 그룹 제목이 한 글자씩 줄바꿈되던 문제도 사라졌습니다.
- **아이콘 사이트와 여백 제거(#120)**: 링크 아이콘 입력줄에 "아이콘 사이트" 메뉴(Dashboard Icons, selfh.st/icons, Seeklogo, Iconify)와 "여백 제거" 버튼이 추가되었습니다. 투명하거나 단색인 여백을 잘라내고 아이콘을 가운데에 꽉 차게 표시합니다. SVG는 viewBox만 조정하여 벡터로 유지되고, 비트맵은 정사각형 PNG로 변환되며, 이미지 주소는 먼저 내려받은 뒤 내장하여 저장합니다.

## 개요에서 공인 IP 조회

- DDNS 작업이 없거나 DDNS가 한 가지 주소 체계만 다루는 경우, 관리자는 개요의 네트워크 카드에서 "공인 IP 조회"를 눌러 공인 IPv4 / IPv6를 한 번 조회할 수 있습니다. DDNS가 이미 제공하는 주소 체계는 DDNS 값을 그대로 쓰고, 찾지 못한 주소 체계는 "확인되지 않음"으로 표시되며 마우스를 올리면 이유를 볼 수 있습니다. 결과는 메모리에만 저장되고 페이지를 새로 고쳐도 유지되며, 네트워크 자가 점검에서 찾은 주소도 여기에 기록됩니다. 읽기 전용 계정에는 이 버튼이 표시되지 않습니다.
- 새 엔드포인트: `POST /api/system/public-ip`(로그인 세션 전용)와 `GET /api/system/public-ip`(`status:read`, 외부 요청을 보내지 않음).

## 업로드와 다운로드 방향 통일(#117)

- 전체 화면에서 Gately 자신의 관점으로 통일했습니다. 업로드는 Gately가 보낸 데이터, 다운로드는 받은 데이터이며 개요의 네트워크 속도와 일치합니다. 네트워크 토폴로지에서 Gately, 리스너, 사이트 노드는 방문자에게 보낸 응답을 업로드로, 방문자의 업로드를 다운로드로 계산하고 백엔드 노드는 반대입니다. 도구 모음, 상세 패널, 트래픽 그래프, 실시간 연결, 포트 포워딩, 프로토콜 분기, STUN 규칙 카드도 같은 규칙에 맞게 바뀌었습니다.
- API 필드(`bps`, `upBps`, `bytes`, `up`, `bytesIn`, `bytesOut`)는 바뀌지 않으며, API 문서에 방향을 명시했습니다.

## 수정

- **리버스 프록시**: 방문자의 쿼리 문자열을 백엔드에 그대로 전달합니다. 이전에는 세미콜론이나 잘못된 퍼센트 이스케이프가 포함된 매개변수가 버려지고 나머지 매개변수의 순서가 바뀌었습니다(예: `?filters=and;(user_id;eq;123)`). 경로 규칙의 접두사 제거와 실패 시 재시도도 해당됩니다(#116).
- **리버스 프록시**: 방문자가 HTTPS를 사용할 때 백엔드가 같은 호스트와 같은 포트를 가리키는 절대 주소 `http://` 리디렉션을 반환하면 `https://`로 바꿔 줍니다. `X-Forwarded-Proto`를 무시하는 oci-start 같은 앱이 로그인 후 http로 되돌아가던 문제가 해결되었으며, 다른 호스트, 포트, 상대 경로 리디렉션은 그대로입니다.
- **개요**: CPU, 메모리, 디스크 링의 발광 효과와 호스트 아이콘의 그림자를 제거하여, 일부 브라우저에서 링 끝에 네모난 얼룩이 생기지 않습니다(#121).

## 업그레이드 안내

- Docker는 새 이미지를 받아 컨테이너를 다시 만들고, OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치하고, fnOS는 앱 센터에서 새 `.fpk`를 수동 설치하며, 그 밖의 환경은 "시스템 설정"에서 온라인으로 업그레이드할 수 있습니다.
