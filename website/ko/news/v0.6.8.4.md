# Gately v0.6.8.4 출시

2026년 11월 19일

[v0.6.8.4 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.4)

## 보안 수정

- **알림 채널 키가 전송 오류에 나타날 수 있었습니다(낮음)**: Telegram Bot Token, Bark 기기 키, ServerChan SendKey 등은 요청 주소에 들어 있습니다. 연결에 실패하면 오류 메시지에 전체 주소가 포함되어 알림 모듈 로그와 「최근 전송」 기록에 남았고, 읽기 전용 계정과 알림 읽기 권한만 가진 API 토큰에서도 볼 수 있었습니다. 이제 오류 메시지의 채널 키는 `***`로 바뀝니다. v0.6.8.2 이하 버전이 영향을 받습니다. 「최근 전송」은 메모리에만 저장되어 업그레이드 후 재시작하면 지워집니다. 실행 로그에는 이전 기록이 남아 있을 수 있으므로, 전에 전송에 실패한 적이 있는 채널은 키를 교체하세요(GHSA-p368-wcp9-rv4q).

## 설정을 바꿔도 접속이 막히지 않습니다

- **저장 후 확인, 시간이 지나면 자동 롤백**: 관리 화면에서 포트 포워딩, 프로토콜 라우팅, Web 서비스, 전역 설정을 저장하면 페이지가 새 연결로 관리 화면에 계속 접속할 수 있는지 확인합니다. 확인할 수 없으면(예: 관리 화면이 거치는 수신 포트를 잘못 바꾼 경우) 기본 90초 뒤 변경 전 설정으로 자동 복원됩니다. 확인에 실패하면 카운트다운이 표시되며 바로 롤백할 수도 있습니다. 확인 없이 3번 재시작해도 롤백됩니다. 「시스템 설정 › 접근 제어」에서 이 기능을 끄거나 대기 시간(30~600초)을 조정할 수 있습니다. 롤백하면 「설정 변경」 알림이 전송됩니다.
- **저장 전 접속 경로 안내**: 관리 화면은 현재 접속이 어떤 포트 포워딩, 프로토콜 라우팅, Web 사이트를 거치는지 추적합니다. 저장하려는 변경이 이 경로에 영향을 주면(포트 변경, 비활성화, 삭제, 이 기기에서 수신할 수 없는 주소로 변경 등) 먼저 이유를 설명하고 영향을 받는 구간을 강조합니다. 「시스템 설정 › 접근 제어」에서 현재 접속 경로를 볼 수 있습니다.
- **일괄 변경을 함께 적용**: 여러 곳을 같이 바꿔야 동작하는 경우(예: 프로토콜 라우팅을 먼저, Web 리스너를 그다음에 변경) 「보류하고 나중에 함께 적용」을 선택할 수 있습니다. 상단 배너에 보류 중인 규칙과 리스너가 나열되며, 「모두 적용」을 누르면 묶음 전체를 확인하고 실패하면 전체를 롤백합니다. 「변경 취소」로 버릴 수도 있습니다. 모두 적용하기 전에 시작할 수 없는 리스너를 먼저 보여 줍니다.
- **명령줄 롤백**: `gately rollback`은 확인 대기 중인 변경과 최근 설정 저장 15건을 나열하며, 번호로 되돌리거나 `-last`, `-pending`, `-config`를 `-version`과 함께 쓸 수 있습니다. Gately가 실행 중이면 2초 안에 복원하고 재시작하며, 실행 중이 아니면 설정 파일을 직접 다시 씁니다.
- 설정 파일을 삭제하기 전에 설정 기록에 사본을 먼저 저장하므로, 삭제도 설정 기록에서 되돌릴 수 있습니다.

## 알림: 실패 시 재시도와 재전송

- 전송에 실패하면 10초, 30초, 60초 뒤에 재시도합니다(기본 3회, 0~10으로 설정). 그래도 실패한 메시지는 재전송 대기열에 들어가 채널이 복구되면 시간순으로 전송되며, 재시작 후에도 이어집니다(기본 24시간 보관, 0~168로 설정, 0은 끔, 채널당 최대 100건).
- 채널에 재전송을 기다리는 메시지가 이미 있으면 새 메시지는 한 번만 시도하고, 실패하면 밀린 메시지 뒤에 줄을 섭니다. 하나씩 재시도를 기다리지 않습니다.
- 「최근 전송」에는 「재전송 대기」, 「재전송됨」과 시도 횟수가 표시됩니다. 위쪽 배너에는 채널별 재전송 대기 건수가 표시되며 비울 수 있습니다.

## 인증서: fnOS 시스템 인증서 사용(#105)

- 인증서 출처에 「fnOS 시스템 인증서」가 추가되었습니다. fnOS가 이미 관리하는 인증서에서 도메인을 고르면 Gately가 30분마다 최신 인증서를 읽어 fnOS의 갱신을 따라갑니다(전체 체인이 있으면 전체 체인 사용). 변경되면 자동으로 불러와 배포합니다.
- 인증서는 fnOS의 「설정 → 보안 → 인증서」에서 관리합니다. fnOS 네이티브 앱(fpk)은 바로 읽을 수 있습니다. Docker 배포에서는 `/usr/trim/etc/network_cert_all.conf`와 `/usr/trim/var/trim_connect/ssls`를 같은 경로 그대로 컨테이너에 읽기 전용으로 마운트하고, 컨테이너를 root로 실행해야 합니다(공식 이미지의 기본값). 자세한 내용은 [SSL 인증서](/ko/docs/modules/ssl)를 참고하세요.

## 저장소 사용량

- 「시스템 설정 › 네트워크 및 실행」에 저장소 사용량 카드가 추가되었습니다. 설정 디렉터리가 있는 파티션의 용량, 설정 디렉터리 전체 크기, 그리고 실행 로그, 방문자 감사, 설정 기록, 백업, 인증서, 관리 프로그램, 알림 재전송 대기열, File Browser 데이터 등 용도별 사용량과 경로를 보여 줍니다.

## 수정

- **침입 방지**: 관리 포트는 모듈이 시작되기 전에 열린 포트로 등록됩니다. 이전에는 미끼 포트 범위에 관리 포트가 포함되면 Gately 자신의 미끼 리스너가 먼저 그 포트를 차지해 관리 화면 수신에 실패하고 재시작할 때마다 종료되었습니다. 모듈을 시작하는 동안에는 미끼 포트를 설정하지 않습니다. frps, EasyTier, FTP 패시브 포트 등 모듈이 등록한 포트는 아직 수신 중이 아니더라도 미끼로 쓰지 않습니다. 미끼 포트는 포트 변경에 따라 다시 계산됩니다. 인증서를 신청할 때 쓰는 임시 HTTP-01 리스너가 미끼 포트에 막히지 않습니다.
- **Web 서비스**: 사이트의 백엔드가 같은 인스턴스의 다른 Web 리스너인 경우(예: 443 사이트 → 이 기기의 444 리스너 → 관리 화면) 관리 화면의 로그인 Cookie가 그대로 전달되어 로그인 직후 401이 나오지 않습니다.

## 업그레이드 안내

- Docker는 새 이미지를 받은 뒤 컨테이너를 다시 만듭니다. OpenWrt는 새 `.apk` / `.ipk`를 덮어 설치합니다. fnOS는 앱 센터에서 새 `.fpk`를 직접 설치합니다. 그 밖의 배포 방식은 「시스템 설정」에서 온라인으로 업그레이드할 수 있습니다.
- 저장 후 확인은 기본으로 켜져 있습니다. 스크립트나 API 토큰으로 설정을 저장하는 경우는 영향이 없으며, 확인 요청 헤더가 붙은 관리 화면 세션의 저장만 확인이 필요합니다.
