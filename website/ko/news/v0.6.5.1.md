# Gately v0.6.5.1 출시

2026년 11월 7일

[v0.6.5.1 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.5.1)

## 부팅 시 자동 시작: gately service

바이너리로 설치한 경우 Gately를 바로 시스템 서비스로 등록할 수 있습니다: `sudo ./gately service install`(Windows는 관리자 터미널에서 `.\gately.exe service install`). Linux는 systemd 서비스, macOS는 launchd 데몬(`-user`로 sudo 없이 로그인 항목), Windows는 시스템 서비스로 등록되며, 설치 후 바로 시작하고 비정상 종료 시 자동으로 다시 시작합니다. 이후 `gately service uninstall|start|stop|restart|status`로 관리하며, 제거해도 설정 디렉터리는 남습니다.

- Windows의 기본 설정 디렉터리 `%ProgramData%\Gately`는 SYSTEM과 관리자만 접근할 수 있습니다.
- 프로그램이나 설정 디렉터리를 root 외의 사용자가 수정할 수 있으면(예: 프로그램이 아직 다운로드 폴더에 있음) 설치 시 경고합니다.

[부팅 시 자동 시작](/ko/docs/guide/install#service)을 참고하세요.

## 긴 목록 페이지 표시

침입 방지 차단 목록, Web 서비스 전역 설정의 관리 화면 차단, 스토리지 마운트와 Docker 컨테이너의 파일 목록, Web 터미널 SFTP 파일 관리가 페이지로 나뉘어 표시되며, 페이지당 20 / 50 / 100 / 200개를 목록별로 기억합니다. 차단 4000개 페이지의 렌더링이 약 2.6초에서 0.23초로 줄었습니다. 검색은 먼저 걸러낸 뒤 페이지를 나누고, 주기적 새로 고침과 차단 해제 시 현재 페이지를 유지합니다. SFTP 머리글 체크박스는 현재 페이지에만 적용되어 보이지 않는 파일을 실수로 삭제하지 않습니다.

## DDNS 레코드 일괄 추가

작업 편집 창의 「레코드」 탭에 「일괄 추가」가 추가되었습니다. 한 줄에 도메인 하나를 쓰며, 전체 도메인이나 호스트만 쓰고 뒤에 유형과 값을 덧붙일 수 있습니다(예: `cdn.example.com CNAME target.example.net`). 추가하기 전에 추가할 레코드, 건너뛸 중복, 잘못된 줄을 미리 보여 주며 잘못된 줄은 고친 뒤에 추가할 수 있습니다. 국제화 도메인 이름은 punycode로 변환됩니다. [레코드 일괄 추가](/ko/docs/modules/ddns#batch)를 참고하세요.

## 크래시 기록 crash.log

Gately는 Go 런타임 크래시(panic, fatal error)의 내용과 스택을 설정 디렉터리의 `crash.log`에 기록하고, 프로세스가 강제 종료되면(메모리 부족에 따른 OOM 등) 마지막으로 살아 있던 시각을 기록합니다. 다음 시작 시 시스템 로그로 알리고, 진단 패키지에는 마스킹하여 포함합니다. Docker, LXC, fnOS 등에서 재시작 후 표준 오류 출력이 남지 않을 때 원인 파악에 도움이 됩니다. [진단 패키지](/ko/docs/reference/diagnostics)를 참고하세요.

## 기타 개선

- macOS 바이너리는 Developer ID 인증서로 서명되고 Apple 공증을 받아 다운로드 후 바로 실행할 수 있습니다. 확인 방법은 [릴리스 산출물 검증](/ko/docs/guide/verify)을 참고하세요.
- 기능 요청 템플릿에서 버전과 시스템·아키텍처를 반드시 적도록 했습니다.
