# Gately v0.6.8.8 released

November 25, 2026

[Download v0.6.8.8](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.8)

## Wildcard on any domain segment (#118)

- The `*` in a site domain is no longer limited to the first segment: in `audiobook.*.example.com` a middle `*` segment matches one segment, in `audiobook.*` a trailing `*` segment matches one or more segments (`audiobook.example.com`, `audiobook.home.lan`), and in `a.api-*.example.com` a `*` inside a segment matches only within that segment.
- Each domain still allows only one `*`, `{1}` in redirects receives the matched part, and patterns whose fixed part forms an IP (such as `192.168.1.*`, `10.*`) are rejected.
- A trailing wildcard such as `audiobook.*` also matches names anyone can register (such as `audiobook.attacker.com`), so third-party sign-in return addresses, credentialed cross-origin requests and knock-grant probes do not treat it as the site's own domain; use a domain with a fixed suffix when you need these features.
- Sites with a `*` outside the first segment match certificates by the domain actually requested, so they no longer report a missing certificate by mistake.
- Routing priority is unchanged: exact domains first, then the longest matching wildcard, then `*`. Topology masking and aliases cover these domains too.

## Navigation panel

- **Groups visible after sign-in**: the group title in the link list has a new lock button. When enabled, the whole group is shown only to signed-in visitors, and links added to the group later follow automatically, with no need to tick each one.
- **Rename groups (#122)**: the group title has a new rename button. Links in the group are renamed together and keep their order; renaming to an existing group's name merges after confirmation; the visible-after-sign-in setting follows the new name, and when merging into a public group the links are ticked "Visible after sign-in" one by one, so renaming never exposes them to signed-out visitors. On phones the group title is no longer squeezed into one character per line.
- **Icon sites and Trim margins (#120)**: the link icon bar has a new "Icon sites" menu (Dashboard Icons, selfh.st/icons, Seeklogo, Iconify) and a "Trim margins" button that cuts transparent or solid-color margins and centers the icon to fill the frame. SVG only gets its viewBox adjusted and stays vector; bitmaps become square PNG; an image address is downloaded first and then saved embedded.

## Public IP lookup in the overview

- When there is no DDNS task, or DDNS covers only one address family, administrators can click "Look up public IP" on the overview network card to look up the public IPv4 / IPv6 once. Address families DDNS already provides keep the DDNS value, and one that cannot be found shows "Not found" with the reason on hover. The result is kept in memory only and survives page reloads; addresses found by the network self-check are recorded here too. Read-only accounts do not see the button.
- New endpoints: `POST /api/system/public-ip` (login sessions only) and `GET /api/system/public-ip` (`status:read`, sends no external request).

## Consistent upload and download direction (#117)

- The whole UI now uses Gately's own point of view: upload is data Gately sends and download is data it receives, matching the overview network rates. In the network topology, the Gately, listener and site nodes count responses sent to visitors as upload and visitor uploads as download, and backend nodes are the reverse; the toolbar, detail panel, traffic chart, live connections and the port forwarding, protocol sniffing and STUN rule cards follow the same rule.
- API fields (`bps`, `upBps`, `bytes`, `up`, `bytesIn`, `bytesOut`) are unchanged, and the API docs now state the direction.

## Fixes

- **Reverse proxy**: the visitor's query string is forwarded to the backend as is. Before, parameters containing semicolons or invalid percent escapes were dropped and the rest reordered (such as `?filters=and;(user_id;eq;123)`); prefix stripping on path rules and failure retries are covered as well (#116).
- **Reverse proxy**: when the visitor uses HTTPS, an absolute `http://` redirect from the backend pointing to the same host and port is rewritten to `https://`, fixing apps such as oci-start that ignore `X-Forwarded-Proto` and redirect back to http after sign-in; other hosts, ports and relative redirects are unchanged.
- **Overview**: removed the glow on the CPU, memory and disk rings and the shadow under the host icon, so square smudges no longer appear at the ring ends in some browsers (#121).

## Upgrade notes

- Docker: pull the new image and recreate the container; OpenWrt: install the new `.apk` / `.ipk` over the old one; fnOS: install the new `.fpk` manually in the App Center; other deployments can upgrade online from System settings.
