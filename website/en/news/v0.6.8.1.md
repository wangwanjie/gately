# Gately v0.6.8.1 released

November 17, 2026

[Download v0.6.8.1](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.1)

## Web services

- **Adding or editing a site failed**: in v0.6.8, adding, editing, copying, enabling or disabling a site on the Web services page, or editing an HTTPS listener, failed with a `siteCerts` format error. The cause was the site certificate information added in v0.6.8 (the remaining certificate days shown on site rows), which the UI submitted together with the configuration and the save API did not recognise. The UI now strips it before submitting; the save API also ignores the read-only fields that the list API outputs itself (runtime state, statistics, certificate matching and so on), so pages left open across the upgrade and scripts that read the configuration and submit it back as a whole can save as well. Other unknown fields are still rejected. The quick site wizard was not affected.
- **"Site not found" on a reused connection**: when several domains resolve to the same IP and one certificate covers them all (for example a `*.example.com` wildcard certificate), the browser puts requests for a new domain on an HTTP/2 connection that is already open. If an SNI-based protocol router in front sends some of those domains to another Gately, that connection actually leads to the other one, so the visit shows "Site not found" (or lands on that instance's default site) until the browser is closed and reopened. Now, when the domain of an HTTP/2 or HTTP/3 request differs from the TLS SNI and this listener has no site for that domain, `421 Misdirected Request` is returned and the browser opens a new connection for that domain and retries automatically. HTTP/1.1 and requests without SNI (visits by IP) are handled as before.

## Upgrade notes

- Docker: pull the new image and recreate the container; OpenWrt: install the new `.apk` / `.ipk` over the old one; fnOS: install the new `.fpk` in the App Center; other installs can upgrade online from System Settings.
- The reused-connection fix works completely only when both ends of the SNI routing are upgraded: whichever Gately receives the request has to return the 421.
