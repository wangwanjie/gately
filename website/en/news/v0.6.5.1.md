# Gately v0.6.5.1 released

November 7, 2026

[Download v0.6.5.1](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.5.1)

## Start at boot: gately service

Binary installs can register Gately as a system service directly: `sudo ./gately service install` (on Windows, `.\gately.exe service install` in an administrator terminal). Linux gets a systemd unit, macOS a launchd daemon (`-user` registers a login item without sudo) and Windows a system service; Gately starts right away and is brought back after a crash. Manage it afterwards with `gately service uninstall|start|stop|restart|status`; uninstalling keeps the config directory.

- On Windows the default config directory `%ProgramData%\Gately` is accessible only to SYSTEM and Administrators;
- install warns when the binary or the config directory can be modified by users other than root, for example a binary still in Downloads.

See [Start at boot](/en/docs/guide/install#service).

## Paged long lists

The intrusion prevention ban list, the admin bans in Web Services global settings, the file lists of storage mounts and Docker containers and the web terminal SFTP file manager are now paged, with 20 / 50 / 100 / 200 rows per page remembered per list. A page with 4000 bans renders in 0.23 s instead of about 2.6 s; search filters before paging, and the periodic refresh and unbanning keep the current page. The SFTP header checkbox only affects the current page, so files you cannot see are not deleted by accident.

## Bulk adding DDNS records

The Records tab of the task editor gets **Bulk add**: one domain per line, either a full domain or just the host, optionally followed by a type and value (such as `cdn.example.com CNAME target.example.net`). Before adding, it previews the records to add, the skipped duplicates and the invalid lines, which must be fixed first; internationalized domain names are converted to punycode. See [Bulk adding records](/en/docs/modules/ddns#batch).

## crash.log

Gately writes Go runtime crashes (panic, fatal error) with their stacks to `crash.log` in the config directory, and records the last time a process was alive when it was killed, for example by the OOM killer. The next start notes it in the system log, and the diagnostics bundle includes it, redacted. This helps on Docker, LXC and fnOS, where standard error is gone after a restart. See [Diagnostics bundle](/en/docs/reference/diagnostics).

## Other improvements

- macOS binaries are signed with a Developer ID certificate and notarized by Apple, so they run right after download; see [Verifying release artifacts](/en/docs/guide/verify).
- The feature request template asks for the version and the system and architecture.
