# Gately v0.6.4.1 released

November 4, 2026

[Download v0.6.4.1](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4.1)

## Multiple Tailscale instances

- Each instance runs its own tailscaled with its own state directory, control socket and WireGuard port, so one machine can join several tailnets at once, for example a kernel-mode instance for a remote Headscale and a userspace instance for a local one.
- An existing state directory can be reused to keep the node identity and address; an old single-instance configuration becomes an instance named `tailscale` on upgrade, with the same command line as before.
- At most one kernel-mode instance can be enabled at a time (tailscaled uses a fixed routing table and firewall mark); conflicting state directories, control sockets and ports are reported when saving or enabling. Editing an instance restarts only that instance.
- API change: `/api/tailscale/secrets`, `/restart` and `/logout` move to the per-instance `/api/tailscale/instances/{key}/…`, and `PUT /api/tailscale/settings` now only saves program paths; scripts using the old endpoints need updating.

## Multiple NetBird instances

- The same approach as Tailscale: separate daemons, state directories, daemon addresses and WireGuard ports, and the old configuration migrates to an instance named `netbird`.
- Conflict checks also cover WireGuard ports (0 counts as the default 51820) and the SOCKS5 address of userspace instances (empty counts as `127.0.0.1:1080`).
- When a separately installed NetBird service runs in kernel mode (a `wt` interface exists, or the system daemon socket reports a connected kernel interface), a kernel-mode instance does not run next to it and shows why.
- API change: instances live under `/api/netbird/instances`, with status, restart, log out and setup key per instance.

See [Tunnels and networking](/en/docs/modules/tunnels).

## Notifications include the server name

Notification titles become `[Gately · server name] Event title` and the body gains a Server line, so notifications from several servers sent to the same mailbox or chat are easy to tell apart. Set the name in Notification settings; when empty the hostname is used, and Webhook templates can use the `{server}` variable. See [Notifications](/en/docs/modules/notify#server-name).

## Other improvements and fixes

- Protocol routing routes can be disabled temporarily: settings are kept, connections fall through to broader routes or the default target, and toggling does not interrupt other connections.
- DNSPod fix: dnsapi.cn started rejecting User-Agents containing `DDNS Client`, which broke every DNSPod record sync and DNS-01 certificate validation.
- ipw.cn no longer resolves: the default public IP lookups now start with `ipv4.ddnspod.com` and `ipv6.ddnspod.com`, and saved ipw.cn addresses are replaced on startup.
- With the backup page open, a sensitive access audit entry and notification are no longer recorded every few seconds; only downloading a backup file is recorded.
- Read-only accounts no longer see the group rename button.
