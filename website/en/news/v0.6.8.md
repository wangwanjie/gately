# Gately v0.6.8 released

November 17, 2026

[Download v0.6.8](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8)

## Security fixes

This release fixes the following issues affecting v0.6.6.6 and earlier; upgrading is recommended.

- **Write tokens could read the config directory (high)**: tokens such as `storage:write` or `webservice:write` could expose the config directory as a mount or static site, read `account.json` and forge an admin session. Mounts, static sites and WebDAV/FTP/SMB now refuse the config directory and anything inside it; directories containing it still work with the config directory hidden. Managed program paths (EasyTier/Tailscale/NetBird) and the backup passphrase are session-only, and the token editor marks modules whose write access reaches server files.
- **Site third-party sign-in redirect controlled by Host (high)**: on wildcard or default sites the sign-in ticket could be sent to an attacker's host; sign-in now only starts from addresses that point to this instance.
- **SMB pre-auth crash on 32-bit builds (high)**: offsets and lengths are checked in 64-bit arithmetic, a panic only drops its connection, and unauthenticated connections get timeouts, a request size limit and connection caps.
- **Also (medium/low)**: fnOS gateway same-host cross-port requests using the admin cookie; admin cookies forwarded to same-host sites; partial credentials visible to read-only identities; WebDAV/FTP following symlinks outside the share; decoy/scan bans on a single forgeable SYN; unescaped visitor text in Webhook/PushPlus payloads; site user passwords stored in plain text (now bcrypt); CSP for the admin UI and Secure cookies over HTTPS; cross-origin access limited to the site's own domains; per-source Passkey challenge limits; more redaction in diagnostics bundles.
- **Release signing**: `checksums.txt` is signed with minisign (`checksums.txt.minisig`); online upgrades verify the signature before the SHA-256, and releases of v0.6.8 or later without a signature are refused.

## Admin UI

- **Leaner navigation**: related pages are merged into tabbed pages and the sidebar goes from 39 to 27 entries; old addresses redirect. Sidebar groups fold in the phone drawer.
- **Global search**: Ctrl/⌘+K searches pages, tabs, site domains, port forwarding rules, DDNS records and certificates.
- **First run**: after the password change a fresh install asks what Gately will be used for (publishing sites, port forwarding / hole punching, dynamic DNS, mesh networking, file sharing, VPS entry point, or everything) and turns on the matching modules; a Getting started checklist on the overview ticks steps off from the actual configuration.
- **Quick site wizard**: publish a site in three steps: domain, backend address (with a reachability test and templates for Home Assistant, Jellyfin, Emby, Vaultwarden, Nextcloud, Immich, Proxmox VE, Synology DSM and fnOS), then HTTP or HTTPS with a certificate requested on the spot.
- **Empty-list templates**: port forwarding and DDNS offer common scenario templates when empty.
- **Also**: HTTPS site rows show the remaining days of the matched certificate; forms check required fields before saving; lists show the failure reason with a Retry button; better phone buttons and a top bar with the current page name; page headers link to the docs; contrast and accessibility fixes.

## Import

- **Nginx Proxy Manager**: the nginx import reads NPM configs directly, substitutes `set` variables into `proxy_pass` and redirect targets, and maps Force SSL, Cache Assets and other NPM options to Gately settings.
- **Sun-Panel**: navigation panels import Sun-Panel 1.x (.sun-panel.json) and 2.x (.zip) exports into a new panel or an existing one.

## Navigation panel

- **Layout**: per panel, links as cards or desktop-app icons, icon size, links per row (wide screens and phones separately), spacing and content width; visitors can switch the style.
- **Address chooser**: links with other ways to open show an address chooser on click (a popover on desktop, a bottom sheet on phones, keyboard friendly), with unavailable addresses struck through.
- **Switches**: group counts and an address-count badge (both off by default); the "sign in to see more" hint only shows on an otherwise empty page.

## Intrusion prevention and access control

- Decoy ports and scan detection count only sources that complete the TCP handshake, so forged SYNs no longer cause bans.
- A successful admin sign-in now exempts the address only from decoy-port and port-scan bans; log rules, web probing, TLS, knock and file-service bans still apply.
- WebDAV/FTP/SMB sign-in failures publish a `fileauth.failed` event with a rule template.
- The ban table is capped at 32768 entries; when full, expired and the oldest temporary automatic bans are evicted first, never permanent or manual ones.

## Port forwarding and protocol routing

- Each TCP port limits concurrent connections from a single source (IPv4 address or IPv6 /64), by default half of the port's limit, adjustable per rule and globally; loopback and private sources are exempt.
- TCP connections where neither side sends data within the first data timeout (60 seconds by default) are closed.
- The form warns right away when a target address is written as host:port.

## frp, DNS and WAF

- frps can listen for KCP and QUIC on UDP ports, frpc/frps get QUIC tuning, and frps can open the firewall automatically.
- Custom DNS: when the preferred server fails or gives no answer within 1 second, the next one is queried in parallel and the first answer wins.
- Dynamic DNS: host records are lower-cased and Porkbun falls back to listing the whole domain when a record is not found (#99); A/AAAA values are compared as addresses, so an expanded IPv6 no longer counts as a change.
- WAF: the regex pre-filter is on by default (can be turned off).

## Logs and performance

- New log level setting (default info, also `GATELY_LOG_LEVEL`); per-connection records of port forwarding and protocol routing are no longer written by default.
- Fewer allocations and less lock contention on the logging, translation, reverse proxy, ban table, DNS and port forwarding hot paths; the admin UI loads components and language packs on demand for a smaller first load.

## Also

- Demo mode: `-demo` / `GATELY_DEMO=1` starts a read-only public instance with one-click read-only sign-in and hourly data reset (`deploy/demo`).
- Usage questions go to GitHub Discussions Q&A first; the Telegram group is for chat.

## Upgrade notes

- Docker: pull the new image and recreate the container; OpenWrt: install the new `.apk` / `.ipk` over the old one; fnOS: install the new `.fpk` in the App Center; other installs can upgrade online from System Settings.
- Site user passwords are stored as bcrypt hashes and the API only returns masks; plaintext passwords saved by earlier versions keep working and are converted the next time their listener is saved.
- The log level defaults to info; set it to debug in Settings to get per-connection port forwarding records.
- Storage mounts, static sites and file service directories pointing at the config directory itself or inside it stop being served after the upgrade and are listed in the logs.
