# Gately v0.6.4.1 リリース

2026年11月4日

[ダウンロード v0.6.4.1](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.4.1)

## Tailscale の複数インスタンス

- インスタンスごとに独立した tailscaled が動作し、状態ディレクトリ、制御ソケット、WireGuard ポートはすべて別々です。1 台のマシンで複数の tailnet に同時に参加できます（例：カーネルモードでリモートの Headscale、ユーザー空間モードでローカルの Headscale）。
- 既存の状態ディレクトリを引き継いでノードの ID とアドレスを保てます。旧来の単一インスタンス設定はアップグレード時に `tailscale` という名前のインスタンスになり、起動引数は以前と同じです。
- 同時に有効にできるカーネルモードのインスタンスは 1 つだけです（tailscaled のルーティングテーブルとファイアウォールマークは固定）。状態ディレクトリ、制御ソケット、ポートの競合は保存・有効化時に通知されます。インスタンスを編集すると、そのインスタンスだけが再起動します。
- API の変更：`/api/tailscale/secrets`、`/restart`、`/logout` はインスタンス単位の `/api/tailscale/instances/{key}/…` に移り、`PUT /api/tailscale/settings` はプログラムのパスだけを保存します。旧 API を使うスクリプトは修正が必要です。

## NetBird の複数インスタンス

- Tailscale と同じ方式です。デーモン、状態ディレクトリ、制御アドレス、WireGuard ポートはそれぞれ独立し、旧設定は `netbird` という名前のインスタンスに移行します。
- 競合チェックは WireGuard ポート（0 は既定の 51820 とみなす）とユーザー空間インスタンスの SOCKS5 アドレス（空欄は `127.0.0.1:1080` とみなす）も対象です。
- 別途インストールした NetBird サービスがカーネルモードで動作している場合（`wt` インターフェースがある、またはシステムの制御ソケットがカーネルインターフェースで接続中と報告する場合）、カーネルモードのインスタンスは同時に動作せず、理由を表示します。
- API の変更：インスタンスは `/api/netbird/instances` にあり、状態、再起動、ログアウト、セットアップキーはインスタンスごとに提供されます。

詳しくは[トンネルとネットワーク](/ja/docs/modules/tunnels)をご覧ください。

## 通知にサーバー名

通知のタイトルは `[Gately · サーバー名] イベントのタイトル` になり、本文に「サーバー」の行が加わります。複数のサーバーの通知を同じメールボックスやグループで受け取っても区別できます。名前は「通知設定」で設定し、空欄の場合はホスト名を使います。Webhook テンプレートでは `{server}` 変数を使えます。詳しくは[通知センター](/ja/docs/modules/notify#server-name)をご覧ください。

## その他の改善と修正

- プロトコル振り分けのルートを一時的に無効化できます。設定は保持され、接続はより広いルートか既定の宛先に流れ、切り替えても他の接続は中断しません。
- DNSPod の修正：dnsapi.cn が `DDNS Client` を含む User-Agent を拒否するようになり、DNSPod のレコード同期と DNS-01 証明書検証がすべて失敗していました。
- ipw.cn が名前解決できなくなったため、既定の公開 IP 取得先を `ipv4.ddnspod.com` と `ipv6.ddnspod.com` に変更し、保存済みの ipw.cn のアドレスは起動時に自動で置き換えます。
- バックアップ画面を開いている間、数秒ごとに機密アクセスの監査記録と通知が発生しなくなりました。バックアップファイルのダウンロードだけを記録します。
- 読み取り専用アカウントにはグループの名前変更ボタンを表示しません。
