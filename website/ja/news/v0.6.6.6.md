# Gately v0.6.6.6 リリース

2026年11月15日

[ダウンロード v0.6.6.6](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.6.6)

## ナビゲーションパネル（#97）

- **検索**：訪問者ページ上部の検索ボックスで検索エンジンを選べます（最大 12 件、よく使うプリセットを内蔵、アドレス中のキーワードは `{q}` で表します）。Enter で新しいタブで検索し、入力中はページ上のリンクも引き続き絞り込まれます。既定の検索範囲も設定できます。
- **ログイン後のみ表示**：リンクをログイン後のみ表示に設定できます。未ログインの訪問者に送るページには名前とアドレスが含まれず、ログイン後は鍵マーク付きで表示されます。サイトで Web 認証を有効にし、「下で「認証必須」にしたパスのみ認証を有効にし、それ以外のパスは公開します」を選ぶ必要があります。共有リンクで訪れた訪問者はログイン済みとは見なされません。
- **背景画像**：画像のアドレスを入力するか画像をアップロード（1 MB 以内）し、ぼかしとオーバーレイを調整できます。アップロードした画像は専用のパスで配信され、キャッシュできます。訪問者もページ設定で自分用の背景、ぼかし、オーバーレイに変更できます。
- **カードとグループ**：リンクカードは大小 2 種類のサイズがあり、タイトルと説明の表示を選べます。グループは折りたたみ可能で、「よく使う」グループを有効にできます。
- **ページ情報**：タブのタイトル、タブのアイコン、ページの説明、フッターをカスタマイズできます。
- **訪問者の言語とユーザーメニュー**：訪問者はページ上で言語を切り替えられます（Cookie に保存）。ログイン後はユーザーメニューが表示され、ログアウト前に確認します。

詳しくは [Web サービス](/ja/docs/modules/web) を参照してください。

## ダイナミック DNS

- **DNS プロバイダーの追加**：Tencent Cloud EdgeOne、Alibaba Cloud ESA、Baidu Cloud、Volcano Engine、DNS.LA、Rainyun、HiPM DNSMgr、Eranet / Tnet.hk、Vercel、NameSilo、Dynadot（既存レコードの更新のみ）、Spaceship、Name.com、Gcore、ClouDNS、deSEC。Tencent Cloud EdgeOne は証明書の DNS 検証とプロバイダー側レコードの削除にも対応します。
- **TTL**：TTL を 0 にすると、新規レコードはプロバイダーの既定値を使い、更新時はプロバイダーに応じて既存の TTL を維持するか既定値を使います。既存レコードの TTL が書き換えられることはなくなりました。
- **Cloudflare**：追加フィールド「プロキシ状態」に true / false を入力すると既存レコードのプロキシ状態を同期し、空欄なら管理しません。プロキシを有効にしたレコードの TTL は自動に固定されます。同名・同タイプのレコードが複数ある場合は 1 件を残して目標値に変更し、古い値の残りのレコードは削除します。
- **その他**：`com.ar`、`org.br` などの複数階層のパブリックサフィックス配下のドメインは、パブリックサフィックスリストに従って分割します。カスタムコールバックは `{timestamp}` 変数に対応し、TTL 未設定時の `{ttl}` は 600 になります。dynv6 は zone 経由でルートドメインのアドレスを更新します。Alibaba Cloud は回線を指定しない場合、既定の回線だけを操作します。

詳しくは [ダイナミック DNS](/ja/docs/modules/ddns) を参照してください。

## 侵入防御

- **信頼する送信元**：モジュールが登録した信頼する送信元は、おとりポートとポートスキャンの検出の対象外になります（nftables と iptables の両方のバックエンドに対応）。ログルール、手動ブロック、アクセス制御は従来どおり有効です。
- **frps**：正しいトークンでログインした frpc の送信元アドレスは信頼する送信元になります。同じ家庭用ブロードバンドの出口にある別のデバイスが TCP ホールパンチングを行っても、ポートスキャンと判定されて frpc が巻き込まれてブロックされることはなくなりました。ログインから 10 分間、または frps との接続が続いている間は有効で、接続が切れると再ログインするまで無効になります。frps の停止、トークンや待ち受けポートの変更時には取り消されます。

詳しくは [侵入防御](/ja/docs/modules/guard) を参照してください。

## Web サービス

- **親ドメインをまたぐ管理画面ログインの認証免除**：管理者がサイトで `/__gately_auth/admin-start`（`?next=/パス` を付けられます）を開き、ワンタイムチケットのハンドシェイクを開始する方式に変更しました。一般の訪問者が管理画面の入口アドレスにリダイレクトされることはなくなります。このアドレスをブックマークしておくことをおすすめします。
- **レスポンスキャッシュ**：Gately 自身のログイン Cookie だけを持つリクエストが再びキャッシュできるようになりました。以前は、シングルサインオンドメインや Web 認証を有効にすると、ログイン済みのリクエストがすべて Cookie を持つため、キャッシュが常に空でした。その他の Cookie、他のインスタンスが発行したセッション Cookie、認証リクエストヘッダーがある場合は引き続きキャッシュしません。

## アップグレードの注意

- Docker は新しいイメージを pull してコンテナを再作成します。OpenWrt は新しい `.apk` / `.ipk` を上書きインストールします。fnOS はアプリセンターで新しい `.fpk` を手動インストールします。その他の環境では「システム設定」からオンラインでアップグレードできます。
- 親ドメインをまたぐ管理画面ログインの認証免除を使っている管理者は、アップグレード後にサイトで `/__gately_auth/admin-start` を一度開いてハンドシェイクを完了する必要があります。
- Cloudflare のダイナミック DNS タスクにある、同名・同タイプで古い値を持つ複数のレコードは、次回の同期で 1 件にまとめられます。
