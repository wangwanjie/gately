# Gately v0.6.8.2 リリース

2026年11月18日

[v0.6.8.2 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.2)

## ポートノッキング：1 人 1 つの鍵

- **ID**：ルールに ID を追加できます。ID（人または機器）ごとに専用の暗号鍵と HMAC 鍵を持ち、個別に無効化・再生成できます。1 つのルールに最大 64 件の ID を登録できます。ログ・通知・許可の記録にはどの ID がノックしたかが記載され、特定の人の鍵を無効化または交換しても、その人の許可だけが取り消されます。
- **共有鍵の無効化**：すべて ID に切り替えたあと、ルール本来の共有鍵をオフにできます。
- **一度に許可するアドレスは 1 つ**：同じ ID が新しいアドレスからノックすると、古いアドレスの許可を取り消します。スマートフォンがネットワークを切り替える場合に適しています。
- 偽造パケットの検証で HMAC の計算オブジェクトを再利用し、64 件の ID でのパケットあたりの負荷がおよそ半分になりました。送信元テーブルが満杯になると最も長く使われていないネットワークから削除し、正当な初回ノックは攻撃トラフィックとオーバーフロー用バケットを共有しなくなりました。

## ポート転送 / プロトコル振り分け

- **送信元ごとの上限を適用しない送信元**：グローバル設定に IP / CIDR のリストを追加しました。公開側の中継や前段プロキシがあり、すべての訪問者が同じ送信元に見える場合はここに登録すると、「送信元ごとの最大接続数」で止められなくなります。ほかの送信元は従来どおり上限で制限されます。
- 送信元ごとの上限に達したときのログには、カウント対象の送信元（IPv6 は /64）と上限が記載され、ルールの上限を上げるか除外する送信元を追加するよう案内します。
- 修正：接続先アドレスを入力してフォーカスを外しても、「targetAddresses は必須です」と表示される問題。

## Web サービス

- **別の Gately へのリバースプロキシ**：v0.6.8 以降、このインスタンスの管理画面ではないサイトへのリバースプロキシでは、すべての `gately_token`、`gately_entry`、`gately_login_nonce` を削除していました。バックエンドが別の Gately の場合、ログイン直後に 401 になる、セキュア入口を設定した管理画面が 404 のままになる、外側のサイト経由のサードパーティログインで「ブラウザーが一致しません」と表示される、といった問題が起きていました。今後は、このインスタンスが発行して有効な Cookie だけを削除し、バックエンド Gately 自身の同名 Cookie はそのまま転送します。
- **2 層の Gately での管理画面ログインで認証免除**：「Gately のログイン Cookie を転送」を有効にしたサイトは、このインスタンスで検証できない `gately_admin` を転送するため、内側の Gately の「管理画面ログインで認証免除」が有効になります。このインスタンスが発行したものは引き続き転送しません。
- **421 の修正**：v0.6.8.1 以降、前段にリバースプロキシ（別の Gately、Caddy、Traefik）があり、HTTP/2 接続で SNI がバックエンドのホスト名、Host が訪問者のドメインのとき、デフォルトサイトに到達したリクエストが 421 を返し、ページが開けませんでした。今後は SNI がこのリスナー上のいずれかのサイトのドメインである場合にのみ 421 を返し、ブラウザーが接続を再利用する場合は従来どおり処理します。
- **同一アドレスからの同時ログイン**：同じ IP から正しいログインが同時に複数来ても、失敗が多すぎるとして拒否されなくなりました。上限に数えるのは実際の失敗だけで、処理中の検証は順番待ちになり、間違ったパスワードを試せるのは引き続き最大 10 回です。待ち時間が 5 秒を超えるかキューが満杯の場合は 429 を返します。
- **管理画面ログインで認証免除**：v0.6.8.1 の親ドメインをまたぐハンドシェイク（「管理画面の入口アドレス」）を削除し、このオプションはシングルサインオンのドメイン内でのみ有効に戻りました。

## ナビゲーションパネル（#104）

- **ドラッグ並べ替え**：パネルの編集中にリンクのドラッグハンドルを押したまま、ほかのリンクの前後やグループ名の上にドロップします。マウスもタッチも使えます。端に近づくと自動でスクロールし、Esc で取り消せます。「選択」モードでは複数のリンクをまとめて移動できます。
- **パネル一覧のグループ**：パネルにグループを設定でき、一覧ではグループの折りたたみ、名前 / タイトル / グループ / 備考での検索、コンパクト表示、「並べ替えと一括操作」を使えます（一括削除では、サイトで使用中のパネルは削除されません）。

## パフォーマンス

- 同じリスナー上で同じバックエンドを指し、接続設定も同じサイトは、バックエンド接続プールを共有します。リバースプロキシはリクエストごとにリクエストのコピーを作らなくなりました。
- サイトの 24 時間分の 1 分単位統計を、1 時間ごとのブロックで必要なときに確保するようにしました。1000 サイトでのピークメモリは 463 MiB から 225 MiB に下がり、スループットは 37,423 req/s です。
- GC のパーセンテージを 0 にした場合、利用可能なメモリが 1 GiB 以上なら既定で 200（リバースプロキシのベンチマークでスループットが約 10% 向上）を使い、それ以外は従来どおり 100 です。環境変数 `GOGC` が設定されている場合はそちらを優先します。
- 侵入防御のログ追跡は、ファイルへの書き込みを検知して読み込む方式に変わりました（Linux は inotify、その他の OS は従来どおりポーリング）。ブロックのファイアウォールへの書き込みは 250 ms ごとにまとめられ、単発のブロックは引き続き即座に反映されます。

## その他

- 手動編集やスクリプトで生成した設定ファイルに項目が足りない場合、Web サービス、DDNS、STUN、SSL、WAF、侵入防御、ネットワークウェイクアップ、通知、File Browser、Web ターミナル、パフォーマンス監視は、読み込み時に保存時と同じ既定値で補います（以前は空のリッスンネットワークでリスナーが起動できない、ヘルスチェックの間隔が 0 で空回りするなどの問題がありました）。
- 通知 Webhook チャンネルの変数リストに `{server}` を追加しました。
- 公式サイトに[パフォーマンス比較](/ja/docs/guide/benchmarks)ページを追加しました。

## アップグレードの注意

- Docker は新しいイメージを取得してコンテナーを再作成します。OpenWrt は新しい `.apk` / `.ipk` を上書きインストールします。fnOS はアプリセンターで新しい `.fpk` を手動でインストールします。その他の環境は「システム設定」でオンラインアップグレードできます。
- v0.6.8.1 の「管理画面の入口アドレス」で、シングルサインオンのドメイン以外のサイトを認証免除にしていた場合、アップグレード後はそれらのサイトも通常のサイト認証に戻ります。
- 別の Gately へリバースプロキシする際の Cookie の問題は、外側（リバースプロキシ側）のインスタンスだけをアップグレードすれば解消します。
