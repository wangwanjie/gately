# Gately v0.6.8 リリース

2026年11月17日

[ダウンロード v0.6.8](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8)

## セキュリティ修正

このリリースでは、v0.6.6.6 以前に影響する次の問題を修正しています。早めのアップグレードをおすすめします。

- **書き込みトークンで設定ディレクトリを読み取れる問題（高）**：`storage:write`、`webservice:write` などのトークンで設定ディレクトリをストレージや静的サイトとして公開し、`account.json` を読み取って管理者セッションを偽造できました。ストレージのマウント、静的サイト、WebDAV/FTP/SMB は設定ディレクトリとその配下を拒否するようになりました。設定ディレクトリを含むディレクトリは従来どおり共有でき、設定ディレクトリだけが隠されます。EasyTier/Tailscale/NetBird のプログラムパスとバックアップのパスフレーズはログインセッションのみ変更可能になり、トークンエディターにはサーバー上のファイルを読み書きできるモジュールが表示されます。
- **サイトのサードパーティログインの戻り先を Host で操作できる問題（高）**：ワイルドカードまたはデフォルトサイトで、ログインチケットが攻撃者のドメインに送られる可能性がありました。ログインはこのインスタンスを指すアドレスからのみ開始されます。
- **32 ビットビルドで SMB の認証前パースが 1 パケットでクラッシュする問題（高）**：オフセットと長さを 64 ビットで判定し、panic は該当接続のみ切断します。未ログインの接続にはタイムアウト、リクエストサイズ、接続数の上限を追加しました。
- **その他（中/低）**：fnOS ゲートウェイモードで同一ホストの別ポートのページが管理者 Cookie を使ってリクエストできる問題、管理画面の Cookie が同一ホスト名のサイトに転送される問題、読み取り専用アカウントに一部の認証情報が見える問題、WebDAV/FTP が共有外を指すシンボリックリンクをたどる問題、偽装可能な単一の SYN によるおとりポート/スキャン検知のブロック、Webhook/PushPlus へのエスケープされていない訪問者テキストの埋め込み、サイトユーザーのパスワードが平文で保存される問題（bcrypt に変更）、管理画面への CSP 追加と HTTPS での Secure Cookie、クロスオリジンはサイト自身のドメインのみ許可、Passkey ログインのチャレンジを送信元ごとに制限、診断バンドルのマスキング拡充。
- **リリース署名**：`checksums.txt` を minisign で署名し（`checksums.txt.minisig`）、オンラインアップグレードでは署名を検証してから SHA-256 を照合します。v0.6.8 以降で署名ファイルがないリリースへのオンラインアップグレードは拒否されます。

## 管理画面

- **ナビゲーションの整理**：関連するページをタブ付きページに統合し、サイドバーを 39 項目から 27 項目に削減。旧アドレスは自動でリダイレクトされます。スマートフォンのドロワーではグループを折りたためます。
- **グローバル検索**：Ctrl/⌘+K でページ、タブ、サイトのドメイン、ポートフォワードルール、DDNS レコード、証明書を検索できます。
- **初回利用**：新規インストールではパスワード変更後に用途（サイト公開、ポートフォワード/ホールパンチ、ダイナミック DNS、メッシュネットワーク、ファイル共有、VPS の入口、またはすべて）を選び、用途に合わせてモジュールを有効にします。概要上部の「はじめに」チェックリストは実際の設定に合わせてチェックされます。
- **クイックサイトウィザード**：3 ステップでサイトを公開します。ドメイン、バックエンドアドレス（疎通テストと、Home Assistant、Jellyfin、Emby、Vaultwarden、Nextcloud、Immich、Proxmox VE、Synology、fnOS などのテンプレート付き）、HTTP または HTTPS（その場で証明書を申請）の順です。
- **空リストのテンプレート**：ポートフォワードと DDNS の空のリストに、よくある用途のテンプレートを表示します。
- **その他**：HTTPS サイトの行に該当する証明書の残り日数を表示、フォームは保存前に必須項目をチェック、リストの読み込み失敗時は理由と再試行を表示、スマートフォンのボタンとトップバーを改善しトップバーに現在のページ名を表示、ページ見出しから公式ドキュメントへリンク、状態色のコントラストとアクセシビリティを改善。

## インポート

- **Nginx Proxy Manager**：nginx インポートが NPM の設定を直接読み込み、`set` 変数を `proxy_pass` とリダイレクト先に展開し、Force SSL や Cache Assets などを Gately の設定に対応付けます。
- **Sun-Panel**：ナビゲーションパネルに Sun-Panel 1.x（.sun-panel.json）と 2.x（.zip）のエクスポートをインポートでき、新しいパネルの作成も既存パネルへの統合も可能です。

## ナビゲーションパネル

- **レイアウト**：パネルごとにリンクの表示をカードまたはデスクトップアプリ風アイコンから選べ、アイコンサイズ、1 行あたりの数（ワイド画面とスマートフォンで別々）、間隔、コンテンツ幅を調整できます。訪問者はスタイルを切り替えられます。
- **アドレス選択**：他のアクセス方法があるリンクはクリックするとアドレス選択を表示します（デスクトップはポップオーバー、スマートフォンはボトムシート、キーボード操作に対応）。利用できないアドレスは取り消し線で表示されます。
- **スイッチ**：グループ内の件数と複数アドレスのバッジ（どちらも既定でオフ）。「ログインして他のリンクを見る」はページが空の場合のみ表示されます。

## 侵入防御とアクセス制御

- おとりポートとスキャン検知は TCP ハンドシェイクを完了した送信元のみをカウントするため、偽装した送信元アドレスの SYN による誤ブロックが起きなくなりました。
- 管理者ログイン成功後のブロック免除は、おとりポートとポートスキャンのみが対象です。ログルール、パスプローブ、TLS、ノック、ファイルサービスのブロックは従来どおり適用されます。
- WebDAV/FTP/SMB のログイン失敗で `fileauth.failed` イベントを発行し、ルールテンプレートを用意しました。
- ブロックテーブルの上限は 32768 件です。満杯になると、期限切れと最も古い一時的な自動ブロックから削除し、永久ブロックと手動ブロックは削除しません。

## ポートフォワードとプロトコル振り分け

- TCP ポートごとに、単一の送信元（IPv4 アドレスまたは IPv6 /64）からの同時接続を制限します。既定はポートの上限の半分で、ルールごとと全体設定で調整できます。ループバックとプライベートの送信元は対象外です。
- 最初のデータのタイムアウト（既定 60 秒）内にどちらからもデータが送られない TCP 接続は閉じられます。
- 宛先アドレスを host:port の形で入力すると、画面ですぐに警告します。

## frp、DNS、WAF

- frps が UDP ポートで KCP と QUIC を待ち受けられます。frpc/frps では QUIC のパラメーターを調整でき、frps はファイアウォールを自動で開放できます。
- カスタム DNS：優先サーバーが 1 秒以内に応答しない、または失敗した場合は次のサーバーを並列に問い合わせ、最初に返った結果を使います。
- ダイナミック DNS：ホストレコードを小文字に統一し、Porkbun でレコードが見つからない場合はドメイン全体の一覧取得にフォールバックします（#99）。A/AAAA はアドレスとして比較するため、展開形の IPv6 が変更と見なされなくなりました。
- WAF：正規表現のプレフィルターが既定で有効になりました（無効化も可能）。

## ログとパフォーマンス

- ログレベル設定を追加しました（既定は info、`GATELY_LOG_LEVEL` でも指定可能）。ポートフォワードとプロトコル振り分けの接続ごとの記録は、既定では書き込まれなくなりました。
- ログ、翻訳、リバースプロキシ、ブロックテーブル、DNS 問い合わせ、ポートフォワードなどの処理で、メモリ確保とロック競合を減らしました。管理画面はコンポーネントと言語パックを必要に応じて読み込み、初回表示が軽くなります。

## その他

- デモモード：`-demo` / `GATELY_DEMO=1` で読み取り専用の公開インスタンスを起動します。ワンクリックで読み取り専用ログインでき、データは 1 時間ごとにリセットされます（`deploy/demo`）。
- 使い方の質問はまず GitHub Discussions の Q&A へお願いします。Telegram グループはチャット用です。

## アップグレードの注意

- Docker は新しいイメージを pull してコンテナを再作成します。OpenWrt は新しい `.apk` / `.ipk` を上書きインストールします。fnOS はアプリセンターで新しい `.fpk` を手動インストールします。その他の環境では「システム設定」からオンラインでアップグレードできます。
- サイトユーザーのパスワードは bcrypt ハッシュで保存され、API はマスクのみを返します。以前のバージョンで保存された平文のパスワードも引き続き使え、そのリスナーを次に保存するときに変換されます。
- ログレベルの既定は info です。ポートフォワードの接続ごとの記録が必要な場合は、設定で debug に変更してください。
- 設定ディレクトリそのもの、またはその配下を指すストレージのマウント、静的サイト、ファイルサービスのディレクトリは、アップグレード後は提供されなくなり、ログに一覧が出力されます。
