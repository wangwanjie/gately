# Gately v0.6.8.8 リリース

2026 年 11 月 25 日

[v0.6.8.8 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.8.8)

## ドメインの任意のセグメントのワイルドカード（#118）

- サイトのドメインの `*` は先頭セグメントに限られなくなりました。`audiobook.*.example.com` では途中のセグメント全体の `*` が 1 セグメントに、`audiobook.*` では末尾のセグメント全体の `*` が 1 つ以上のセグメント（`audiobook.example.com`、`audiobook.home.lan`）に一致し、`a.api-*.example.com` のようにセグメント内の `*` はそのセグメント内だけで一致します。
- 1 つのドメインに指定できる `*` は引き続き 1 つだけです。リダイレクト内の `{1}` には一致した部分が入ります。固定部分が IP になる書き方（`192.168.1.*`、`10.*` など）は拒否されます。
- `audiobook.*` のような末尾のワイルドカードは、他人が登録できるドメイン（`audiobook.attacker.com` など）にも一致します。そのため、サードパーティログインのリダイレクト先、認証情報付きのクロスオリジンリクエスト、ノック許可の確認ではサイト自身のドメインとして扱われません。これらの機能が必要な場合は、末尾が固定されたドメインを指定してください。
- `*` が先頭セグメント以外にあるサイトは、実際にアクセスされたドメインごとに証明書を照合し、証明書がないという誤った報告をしなくなりました。
- ルーティングの優先順位は変わりません。完全一致のドメイン、最も長く一致するワイルドカード、`*` の順です。ネットワークトポロジーのマスクとエイリアスもこれらのドメインに対応します。

## ナビゲーションパネル

- **グループをログイン後のみ表示**: リンク一覧のグループ見出しにロックボタンを追加しました。有効にするとグループ全体がログイン済みの訪問者にだけ表示され、後からグループに追加したリンクにも自動で適用されるため、1 件ずつチェックする必要がありません。
- **グループの名前変更（#122）**: グループ見出しに名前変更ボタンを追加しました。グループ内のリンクはまとめて名前が変わり、順序も保たれます。既存のグループ名に変更すると、確認後に統合されます。「ログイン後に表示」の設定は新しい名前に引き継がれ、公開グループに統合する場合はグループ内のリンクごとに「ログイン後に表示」がチェックされるため、名前変更でログインしていない訪問者に公開されることはありません。スマートフォンではグループ見出しが 1 文字ずつ折り返されることがなくなりました。
- **アイコンサイトと余白を削除（#120）**: リンクのアイコン欄に「アイコンサイト」メニュー（Dashboard Icons、selfh.st/icons、Seeklogo、Iconify）と「余白を削除」ボタンを追加しました。透明または単色の余白を自動で切り取り、アイコンを中央に枠いっぱいに表示します。SVG は viewBox だけを調整してベクターのまま保ち、ビットマップは正方形の PNG に変換されます。画像のアドレスは先にダウンロードしてから埋め込みで保存されます。

## 概要でグローバル IP を取得

- DDNS タスクがない場合、または DDNS が片方のアドレスファミリーだけを扱う場合、管理者は概要のネットワークカードで「グローバル IP を取得」をクリックして、グローバル IPv4 / IPv6 を一度取得できます。DDNS がすでに提供しているアドレスファミリーは DDNS の値を使い、見つからないものは「取得できません」と表示され、ポインターを合わせると理由が表示されます。結果はメモリ上にのみ保持され、ページを再読み込みしても残ります。ネットワーク自己診断で見つかったアドレスもここに記録されます。読み取り専用アカウントにはこのボタンは表示されません。
- 新しいエンドポイント: `POST /api/system/public-ip`（ログインセッションのみ）と `GET /api/system/public-ip`（`status:read`、外部リクエストは送信しません）。

## 上り・下りの方向を統一（#117）

- 画面全体で Gately 自身の視点に統一しました。上りは Gately が送信したデータ、下りは受信したデータで、概要のネットワークレートと一致します。ネットワークトポロジーでは、Gately、リスナー、サイトのノードは訪問者に返した応答を上り、訪問者のアップロードを下りとして数え、バックエンドのノードはその逆です。ツールバー、詳細パネル、トラフィックグラフ、リアルタイム接続、ポート転送、プロトコル振り分け、STUN ルールのカードも同じ規則に合わせました。
- API のフィールド（`bps`、`upBps`、`bytes`、`up`、`bytesIn`、`bytesOut`）は変わりません。API ドキュメントに方向を明記しました。

## 修正

- **リバースプロキシ**: 訪問者のクエリ文字列をそのままバックエンドへ転送します。以前は、セミコロンや不正なパーセントエスケープを含むパラメーターが破棄され、残りの順序が入れ替わっていました（例: `?filters=and;(user_id;eq;123)`）。パスルールのプレフィックス除去と失敗時の再試行も対象です（#116）。
- **リバースプロキシ**: 訪問者が HTTPS を使っている場合、バックエンドが返した同じホスト・同じポートを指す絶対 URL の `http://` リダイレクトを `https://` に書き換えます。`X-Forwarded-Proto` を無視する oci-start などのアプリでログイン後に http へ戻る問題を修正しました。他のホスト、ポート、相対リダイレクトは変わりません。
- **概要**: CPU、メモリ、ディスクのリングの発光とホストアイコンの影を削除し、一部のブラウザーでリングの端に四角い汚れが出なくなりました（#121）。

## アップグレード

- Docker は新しいイメージを取得してコンテナを再作成、OpenWrt は新しい `.apk` / `.ipk` を上書きインストール、fnOS はアプリセンターで新しい `.fpk` を手動インストール、その他の環境は「システム設定」からオンラインで更新できます。
