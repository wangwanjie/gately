# Gately v0.6.5 リリース

2026年11月6日

[ダウンロード v0.6.5](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.5)

## バックエンドのタイムアウト、訪問者のタイムアウトと自動再試行

- リバースプロキシサイトの「トラフィック」タブに「バックエンドのタイムアウト」が加わりました。接続、TLS ハンドシェイク、レスポンスヘッダー待ちの 3 項目で、既定値はそれぞれ 10 秒、10 秒、無制限です。レスポンスヘッダー待ちのタイムアウトは 504 を返し、その後のダウンロードや WebSocket、SSE などの長時間接続には影響しません。
- バックエンドに接続できない場合（接続拒否、到達不能、接続タイムアウト）、同じリクエストをすぐに次のバックエンドへ回します。1 つのリクエストで試すバックエンドは最大 3 つです。この時点ではリクエストはまだ送信されていないため、POST などのリクエストでも安全です。
-「訪問者のタイムアウト」はリクエスト本文の読み取りとレスポンスの書き出し中のアイドル時間を制限し（既定 60 秒）、送受信が極端に遅い訪問者を切断します。リクエスト本文の読み取りタイムアウトは 408 を返します。
- nginx 設定のインポートで、`proxy_connect_timeout` と `proxy_read_timeout` はサイトの接続タイムアウトとレスポンスヘッダー待ちタイムアウトに変換されます。

詳しくは [バックエンドのタイムアウト](/ja/docs/modules/web#backend-timeouts) と [訪問者のタイムアウト](/ja/docs/modules/web#client-timeouts) を参照してください。

## バックエンドへ ID 情報を渡す

これまでの「ユーザー名を渡す」と「メールアドレスを渡す」は 1 つの「ID 情報を渡す」リストにまとまりました。各行はログインユーザーの 1 項目（ユーザー名、メールアドレス、表示名、グループ）を 1 つのリクエストヘッダーに書き込みます。Firefly III のようにメールアドレスをアカウントとして使うアプリは `Remote-Email` をそのまま読めます。訪問者が送った同名のヘッダー（ハイフンの代わりにアンダースコアを使った表記を含む）は認証前に削除されるため偽造できず、`Connection` ヘッダーでこれらのヘッダーを削除させることもできません。既存の設定はアップグレード時に変換されます。詳しくは [ID 情報を渡す](/ja/docs/modules/web#identity-headers) を参照してください。

## ファイアウォールの自動開放

Web サービスのリスナー、ポート転送とプロトコル振り分けのルールに「ファイアウォールを自動で開放」スイッチが加わりました。実際に待ち受けているポートだけをローカルのファイアウォール（nftables、iptables、ip6tables）で許可し、IPv6 とポート範囲に対応し、連続するポートは 1 つのルールにまとめます。HTTP/3 を有効にしたリスナーは同じ番号の UDP ポートも開放し、リスナーがループバックアドレスだけの場合は開放不要です。リスナーの停止や削除でルールは取り消されます。詳しくは [ファイアウォールを自動で開放](/ja/docs/modules/web#auto-firewall) を参照してください。

## 実行ログ

- Web サービスのアクセスログは日ごとに分割・圧縮され、保持日数と合計サイズの上限を設定できます。過去のアクセスも引き続き検索でき、「以前のログを読み込む」はアーカイブも探します。
- ログのツールバーに「エクスポート」が加わり、現在のフィルター条件に合うすべてのログ（ログファイルとアーカイブ内の履歴を含む）を CSV（Excel 向けに BOM 付き UTF-8、数式インジェクション対策済み）または JSON Lines でダウンロードできます。読み取り専用アカウントのエクスポートでは、表示と同じくアドレス中のパスワードとトークンが隠されます。
-「設定 → ネットワークと実行」に「ログディレクトリ」が加わり、実行ログを外付けディスクなど別のディレクトリに置けます。
- 「ソース」フィルターはすべてのソースを一覧表示します。同じ名前の IPv4 と IPv6 のリスナーのログは混ざらなくなり、サイトの「ログ」ウィンドウにはそのサイトのリスナーの訪問者だけが表示されます。
- 書き込み待ちのログが 256 KB に達するとすぐにディスクへ書き込むため、アクセスの多いサイトでもアクセスログが失われなくなりました。スマートフォンでログを開くと再び最新のエントリーが表示されます。

詳しくは [実行ログ](/ja/docs/guide/configuration#log-export) を参照してください。

## 侵入防御：IPv6 厳格モード

ポートスキャン検出に「IPv6 厳格モード」が加わりました。IPv6 の接続元は開放ポート（リスナーのポートと追加の開放ポート）にのみ接続でき、それ以外のポートへの最初の接続で /64 単位でブロックされます。IPv4 は引き続きしきい値で検出します。一時的にリッスンを止めたポートも 30 秒間は開放扱いになり、FTP サービスのパッシブポート範囲は自動的に開放ポートに含まれます。詳しくは [侵入防御](/ja/docs/modules/guard) を参照してください。

## 管理対象プロセスのリソース

概要ページに「管理対象プロセス」カードが加わり、パフォーマンス監視ページには Gately が管理する外部プログラム（frpc / frps、tailscaled、NetBird、cloudflared、File Browser）ごとの CPU とメモリが表示されます。プロセスが再起動してもグラフは途切れません。詳しくは [パフォーマンス監視](/ja/docs/modules/perf) を参照してください。

## その他の改善と修正

- サイトのリンク：リスナーにプロトコル振り分けまたはポート転送経由でしか到達できない場合、サイトのリンクはルールの入口ポートを使います。例えば 4433 の SNI ルールから 4435 のリスナーに入る場合、リンクは 4433 になります。手動で設定したアクセスポートが引き続き優先されます。
- ネットワークトポロジーに「アクティブのみ」が加わり、直近 60 秒にリクエストまたはアクティブな IP があるサイトとバックエンドだけを表示します。アクティブなノードは「ほか N 件」にまとめられなくなりました。
- ネットワーク自己診断：ローカル DNS がたまにタイムアウトしても、正しく解決される DDNS レコードを未解決と報告しなくなりました。公開 DNS で再確認します。
- DDNS：タスクの停止や再起動で取り消された同期は、エラーを記録せず、レコードを失敗扱いにしなくなりました。
- スキャナーによる TLS ハンドシェイクの失敗はデバッグレベルで記録され、実行ログを埋め尽くさなくなりました。リダイレクト先に `{host}` などの変数を使うリダイレクトサイトは、Host ヘッダーのないリクエストに 400 を返します。
- 侵入防御のブロック表はコンパクトな形式で書き込まれ、期限切れになっただけのブロックでは書き直しが発生しなくなりました。
- インポートしたリバースプロキシ設定で、リスナーの HTTP/3 設定が保持されます。
- ログインページに既定のアカウントとパスワードリセットのヒントが表示されなくなりました。
- Web ターミナル：ファイルマネージャーのエディターを X または Esc で閉じた後も再び開けます。スマートフォンの選択モードで、選択範囲を画面上端より上までドラッグした後もコピーできます。
- UI：タブレットや小型ノート PC でサイト行のドメインが細い列に押し込まれなくなりました。IPv6 のリスナーアドレスは `http://[::1]:18951` の形で表示されます。
