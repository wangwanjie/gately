# ファイルと運用ツール

## WebDAV

サイドバーの「ファイルサービス」グループにある「WebDAV サービス」で設定します。

| フィールド | デフォルト値 | 説明 |
| --- | --- | --- |
| `enable` | オフ | サービスを有効にします。有効にするには少なくとも 1 人のユーザーが必要です |
| `listenIp` | 空 | 待ち受けアドレス。空欄ですべてのアドレスを待ち受けます |
| `port` | 18800 | 待ち受けポート |
| `tls` | オフ | HTTPS を有効にします。証明書は [SSL 証明書](/ja/docs/modules/ssl) モジュールが SNI に応じて提供します |
| `users` | なし | 複数ユーザー。各ユーザーは `name`、`password`、`root`（絶対パスのディレクトリ）、`readOnly` を持つか、`mounts` で複数のディレクトリをマウントします |
| `sharedUsers` | オフ | [共有ユーザー](#shared-users)がこのサービスにログインできるようにします |

各ユーザーには、1 つのディレクトリをマッピングすることも、複数のディレクトリをマウントすることもできます。

- **単一のディレクトリ**：`root` と `readOnly` を入力します。ログイン後のルートがそのディレクトリになります。
- **複数のディレクトリ**：画面で「複数のディレクトリをマウント」を押すか、`mounts` に複数の項目を入力します。各項目は `name`（表示名。`/` を含められず、同じユーザー内で重複不可）、`path`（絶対パス）、`readOnly` で構成されます。ログイン後のルートには各ディレクトリが名前順に表示され、ルート自体には書き込めず、ディレクトリ間でファイルを移動することもできません。

## FTP

「ファイルサービス」グループの「FTP サービス」で設定します。FTP と FTPS に対応しています。

| フィールド | デフォルト値 | 説明 |
| --- | --- | --- |
| `enable` | オフ | サービスを有効にします。有効にするには少なくとも 1 人のユーザーが必要です |
| `listenIp` | 空 | 待ち受けアドレス。空欄ですべてのアドレスを待ち受けます |
| `port` | 2121 | 待ち受けポート |
| `passiveStart` / `passiveEnd` | 0 | パッシブモードのデータポート範囲。どちらも 0 の場合はシステムがランダムに割り当てます。入力する場合は 1 ≤ 開始 ≤ 終了 ≤ 65535 を満たす必要があり、ファイアウォールとポートマッピングでこの範囲を許可してください |
| `publicHost` | 空 | パッシブモードで外部に通知する IP。NAT の内側にある場合は、グローバル IP または転送後の IP を入力します。IP アドレスのみ指定でき、空欄の場合は接続先のアドレスが自動で使われます |
| `tlsMode` | 0 | 0 は平文と FTPS の両方を許可、1 は明示的 FTPS（`AUTH TLS`）を必須にする、2 は暗黙的 FTPS（接続時点で暗号化）です。0 以外の場合、証明書は [SSL 証明書](/ja/docs/modules/ssl) モジュールが SNI に応じて提供します |
| `idleTimeout` | 900 | 接続が何秒アイドル状態になったら切断するか |
| `connectionTimeout` | 30 | データ接続を確立する際のタイムアウト秒数 |
| `disableActiveMode` | オフ | パッシブモードのみを使います。NAT 環境に適しています |
| `users` | なし | 複数ユーザー。フィールドは WebDAV と同じ：`name`、`password`、`root`、`readOnly` または `mounts`。ユーザー名は重複できません |
| `sharedUsers` | オフ | [共有ユーザー](#shared-users)がこのサービスにログインできるようにします |

## SMB

「ファイルサービス」グループの「SMB サービス」で設定し、ローカルのディレクトリを Windows エクスプローラー、macOS Finder、Linux、スマートフォンやテレビの SMB クライアントと共有します。プロトコル実装は Gately に内蔵されており（[gosamba](https://github.com/ahmetozer/gosamba) ベース）、SMB 2.0.2 ～ 3.1.1、NTLMv2 認証と署名に対応し、SMB 3 暗号化を必須にできます。SMB 1 には対応していません。Linux と macOS でのみ利用できます。

| フィールド | デフォルト値 | 説明 |
| --- | --- | --- |
| `enable` | オフ | サービスを有効にします。有効にするには少なくとも 1 人のユーザーが必要です |
| `listenIp` | 空 | 待ち受けアドレス。空欄ですべてのアドレスを待ち受けます |
| `port` | 445 | 待ち受けポート。Windows は 445 にしか接続できません。fnOS や Synology などの NAS に付属する Samba が 445 を使用している場合は別のポートにしてください。macOS、Linux と多くのプレーヤーはアドレスでポートを指定できます |
| `requireEncryption` | オフ | すべての接続に SMB 3 暗号化を要求します。SMB 2 のみ対応の古い機器や一部のテレビは接続できなくなります |
| `mdns` | オフ | Bonjour でサービスを告知し、macOS Finder の「ネットワーク」に表示します。Docker では host ネットワークの場合のみ機能します |
| `users` | なし | 複数ユーザー。フィールドは WebDAV と同じ `name`、`password`、`root`、`readOnly` または `mounts` で、ユーザー名は大文字小文字を区別せず重複できません |
| `sharedUsers` | オフ | [共有ユーザー](#shared-users)がこのサービスにログインできるようにします |

共有はユーザーごとに分かれ、ログインしたユーザーは自分の共有だけを表示・接続できます。

- **単一ディレクトリ**：共有名はユーザー名です。例えばユーザー `alice` のアドレスは `\\192.168.1.2\alice` です。
- **複数ディレクトリ**：各ディレクトリが 1 つの共有になり、`name` が共有名です（同じユーザー内で大文字小文字を区別せず重複不可）。それぞれ読み取り専用にできます。別のユーザーが同名の共有を持ち、それぞれ自分のディレクトリを指すこともできます。

ユーザー名と共有名には `" / \ [ ] : ; | = , + * ? < >` を含められず、`.` で始めたり終えたりすることもできません。NTLM 認証には平文のパスワードが必要なため、bcrypt ハッシュでパスワードが保存されているユーザーは再設定してください。ファイルは Gately プロセスの権限で読み書きされます。

ページ下部の「接続先アドレス」に、保存済みの設定から各共有のアドレスが表示されます。

- Windows：エクスプローラーのアドレスバーに `\\ホスト\共有名` を入力するか、`net use Z: \\ホスト\共有名 /user:ユーザー名` を実行します
- macOS：Finder の「移動 → サーバへ接続」で `smb://ホスト:ポート/共有名` を入力します（445 の場合ポートは省略可）
- Linux：`mount -t cifs //ホスト/共有名 /mnt -o username=ユーザー名,port=ポート`

クライアントが接続できない、認証に失敗する場合は、環境変数 `GATELY_SMB_DEBUG=1` を設定して Gately を再起動すると、プロトコルのデバッグログが実行ログに書き込まれます。調査が終わったら変数を外してください。

## 共有ユーザー {#shared-users}

WebDAV、FTP、SMB は 1 つの「共有ユーザー」リストを共用します。項目は各サービスのローカルユーザーと同じ（ユーザー名、パスワード、`root` と `readOnly` または `mounts`）で、設定ディレクトリの `fileusers.json` に保存されます。共有ユーザーはサイドバー「ファイルサービス」グループの「ファイル共有ユーザー」ページでまとめて管理し、保存すると 3 つのサービスに同時に反映されます。各サービスのローカルユーザーはそのままです。ページ上部には各サービスが共有ユーザーを許可しているかと、ローカルユーザーと同名の共有ユーザーや SMB で使えない共有ユーザーが表示されます。

- 共有ユーザーを受け付けるかはサービスごとに決めます。サービスページの「共有ユーザー」カードで「共有ユーザーのログインを許可」（フィールド `sharedUsers`）をオンにして保存すると、共有ユーザーがそのサービスにログインできます。カードには保存済みの共有ユーザーも表示され、「共有ユーザーを管理」で「ファイル共有ユーザー」ページに移動します。
- ローカルユーザーと同名の場合はローカルユーザーとして照合します（SMB は大文字小文字を区別しません）。
- 共有ユーザー名は大文字小文字を区別せず重複できず、コロンも使えません。
- 共有ユーザーの変更はすぐに反映されます。WebDAV は次のリクエストから新しい設定で照合し、FTP と SMB はサービスを再起動するため、接続中のクライアントは再接続が必要です。
- スイッチがオンで共有ユーザーが 1 人以上いれば、ローカルユーザーがなくてもサービスを有効にできます。
- 共有ユーザーだけで有効にしているサービスでは、変更後もログインできる共有ユーザー（SMB では SMB で使えるもの）が残っている必要があり、そうでなければ保存を拒否します。
- `fileusers.json` を手作業で壊した場合（パスワードが空、ディレクトリが絶対パスでないなど）は共有ユーザーが誰もログインできなくなり、画面に警告が出ます。修正して保存すると復旧します。
- SMB は平文のパスワードのみ受け付け、ユーザー名と共有名は SMB の文字制限に従う必要があります。条件を満たさない共有ユーザーは「ファイル共有ユーザー」ページ、SMB ページ、実行ログで通知されてスキップされますが、WebDAV と FTP では引き続き使えます。

API は `GET` / `PUT /api/fileusers` で、API トークンには `fileusers:read` / `fileusers:write` 権限が必要です。読み取り結果の `services` に各サービスの利用状況が含まれます。以前の各サービスの `GET` / `PUT /api/<サービス>/shared-users` は非推奨ですが引き続き使え、同じリストを読み書きします。読み取りはそのサービスの読み取り権限、変更には `webdav:write`、`ftp:write`、`smb:write` のすべてが必要です。

**パスワードのセルフ変更**：「ファイル共有ユーザー」ページで「パスワードのセルフ変更」をオンにして保存すると、共有ユーザーは Web 認証が有効な任意の Web サービスサイトの `https://サイトのドメイン/__gately_auth/password` で、ユーザー名・現在のパスワード・新しいパスワード（8〜128 文字）を入力して自分のパスワードを変更できます。WebDAV、FTP、SMB はすぐに新しいパスワードを使います（FTP と SMB は再起動するため、接続中のクライアントは再接続が必要です）。平文のパスワードは平文のまま、bcrypt ハッシュはハッシュのまま保存されます。現在のパスワードの誤りは Web ログインと同じレート制限・自動ブロックの対象です。スイッチは `fileusers.json` の `selfService` に保存され、API のフィールド名も同じです。Web ログインの共有ユーザーについては [Web サービスのパスワードのセルフ変更](/ja/docs/modules/web#self-service-password)を参照してください。

## File Browser {#filebrowser}

「ファイルサービス」グループの「File Browser」で設定します。Gately は [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser) をホストします。画像・動画・文書のプレビュー、アップロードとダウンロード、共有リンクの作成ができ、独自のユーザーと権限管理を持つ Web ファイルマネージャーです。元の filebrowser/filebrowser は 2026 年にアーカイブされセキュリティ修正が行われなくなったため、保守が続いている Quantum フォークをホストします。

プログラムは Gately に同梱されていません。ページ下部の「オンラインインストール」カードは GitHub から FileBrowser Quantum を設定ディレクトリの `bin/filebrowser` にダウンロードします。更新、バージョンを指定したインストール、個別のダウンロードプロキシ、ロールバック、アンインストールに対応し、更新やロールバックの後は有効なインスタンスが自動で再起動します。詳しくは [オンラインでのインストール・更新・ロールバック](/ja/docs/modules/tunnels#install) を参照してください。ページヘッダーの「デフォルト設定に戻す」はすべてのインスタンスとそのデータを削除します。詳しくは [デフォルト設定に戻す](/ja/docs/modules/tunnels#reset) を参照してください。プログラムを自分で配置してパスを入力することもできます。プログラムは、入力したパス、設定ディレクトリの `bin/`、`PATH` の順に探します。見つかったプログラムが Quantum でない場合（`PATH` にある元の版など）はページに警告が出ます。

インスタンスごとに独立した File Browser プロセスが動きます。

| フィールド | 既定値 | 説明 |
| --- | --- | --- |
| `listenIp` | 空 | 待ち受けアドレス。空欄ですべての IPv4 アドレス。Web サービスのリバースプロキシ経由でのみアクセスする場合は `127.0.0.1` |
| `port` | 8080 | 待ち受けポート |
| `baseUrl` | `/` | アクセスパス。Web サービスでパス単位にリバースプロキシする場合（例 `/files`）は同じパスを入力 |
| `accessUrls` | 空 | アクセス URL。複数指定でき、Web サービスでリバースプロキシした `https://files.example.com/` などをインスタンスカードに表示します。空の場合は待ち受けアドレスとポートから推測します。最初の URL のスキーム・ホスト・ポートは File Browser の `http.externalUrl` に書き込まれ、共有リンクに使われます |
| `sources` | なし | 共有ディレクトリ。各項目に `path`（絶対パス）、`name`（表示名、空欄でディレクトリ名）、`readOnly`。新しいユーザーは既定ですべてにアクセス可能 |
| `authMethod` | `password` | サインイン方式。`password` はパスワード、`proxy` はリバースプロキシが渡すユーザー名ヘッダーを信頼、`noauth` はサインイン不要 |
| `proxyHeader` | `Remote-User` | `proxy` 方式でユーザー名を読むヘッダー。存在しないユーザーは自動作成 |
| `adminUser` | `admin` | 管理者ユーザー名 |
| `adminPassword` | なし | 管理者パスワード。8 文字以上、`password` 方式では必須 |
| `trustProxyHeaders` | オフ | `X-Forwarded-*` と `X-Real-IP` を信頼。リバースプロキシの背後でオン |
| `disableWebDav` | オフ | File Browser 組み込みの WebDAV インターフェースをオフ |
| `locale` | 空 | 新しいユーザーの既定の表示言語（`ja` など）。空欄は英語 |
| `tokenHours` | 2 | セッション有効期間（時間） |

- 管理者パスワードは起動のたびに File Browser に同期され、Gately の設定が優先されます。ほかのユーザー、共有リンク、個人設定は File Browser で管理し、インスタンス自身のデータベースに保存されます。
- 設定ファイル、データベース、キャッシュは設定ディレクトリの `filebrowser/<インスタンス key>/` に保存され、設定ファイルの権限は 0600 です。管理者パスワードは環境変数でプロセスに渡され、ファイルには書き込まれません。インスタンスを削除するとこのディレクトリも削除され、共有ディレクトリ内のファイルはそのまま残ります。
- 共有ディレクトリが存在しないインスタンスは起動せず、カードに理由が表示されます。
- 外部からのアクセスには、[Web サービス](/ja/docs/modules/web) で `http://127.0.0.1:ポート` を指すリバースプロキシサイトを追加し、HTTPS とアクセス制御で保護したうえで「プロキシヘッダーを信頼」をオンにすることをおすすめします。`proxy` 方式では Web サービスのフォワード認証でユーザー名をヘッダーに入れる必要があり、File Browser のポートは外部に公開しないでください。公開するとヘッダーを偽装してサインインされます。
- ファイルは Gately プロセスの権限で読み書きされます。

## ストレージマウント

「ファイルサービス」グループの「ストレージマウント」でマウントポイントを追加し、ページ内でオンラインにファイルを管理します。

| フィールド | 説明 |
| --- | --- |
| `name`、`remark`、`enable` | 名前、メモ、有効化スイッチ |
| `type` | `local`（ローカルディレクトリ）、`webdav`（リモート WebDAV）、`smb`（SMB 共有）のいずれか |
| `path` | ローカルディレクトリ。存在する絶対パスである必要があります（`local` で使用） |
| `url`、`username`、`password` | リモートのアドレスとアカウント。パスワードは画面上でマスクされます（`webdav`、`smb` で使用）。WebDAV のアドレスは `http://` または `https://` で始まり、SMB のアドレスは `smb://ホスト[:ポート]/共有名[/サブディレクトリ]` の形式です。SMB2/3 に対応し、ユーザー名が空欄の場合はゲストとして接続します |
| `skipVerify` | HTTPS 証明書の検証をスキップします（`webdav` で使用） |
| `domain` | SMB 認証に使うドメインまたはワークグループ。通常は空欄（`smb` で使用） |
| `readOnly` | 読み取り専用でマウントします。ファイル管理はあらゆる書き込み操作を拒否します |

オンラインのファイル管理では、ディレクトリの閲覧、ファイルのダウンロード、ストリーミングアップロード（ファイル全体をメモリに読み込みません）、ディレクトリの作成、名前の変更、削除ができます。マウントポイントはバックアップタスクの保存先にでき、バックアップファイルはマウントポイント内の指定ディレクトリに書き込まれ、保持ポリシーに従って古いファイルが整理されます。

## Wake-on-LAN

「Wake-on-LAN」でデバイスを管理し、デバイスにマジックパケット（6 バイトの `0xFF` の後に MAC を 16 回繰り返したもの）を送信します。

| フィールド | デフォルト値 | 説明 |
| --- | --- | --- |
| `name` | なし | デバイス名。必須 |
| `macs` | なし | MAC アドレス。1 行に 1 つで少なくとも 1 つ必要です。同じデバイスに複数指定できます |
| `broadcastIps` | 空 | IPv4 のブロードキャストアドレス。空欄の場合は `255.255.255.255` と、有効な各 NIC のブロードキャストアドレスに送信します |
| `port` | 9 | 宛先の UDP ポート |
| `repeat` | 3 | 各 MAC に繰り返し送信する回数。上限は 20 |
| `checkAddr` | 空 | オンライン確認のアドレス。形式は `ホスト:ポート`（例：`192.168.1.10:3389`）で、空欄の場合は確認しません |
| `shutdownMode` | 空 | リモートシャットダウンの方式：`agent`（デバイス上のエージェント）、`ssh`（SSH コマンド）、`http`（HTTP リクエスト）。空ならシャットダウンなし |
| `shutdownConn` | 空 | `ssh` 方式で使う [Web ターミナル](/ja/docs/modules/terminal)の SSH 接続 |
| `shutdownCommand` | なし | `ssh` 方式のシャットダウンコマンド、1 行（例：`shutdown -h now`、`shutdown /s /t 0`） |
| `agentToken` | 自動生成 | `agent` 方式のエージェント用トークン。API ではマスク表示 |
| `shutdownHttp` | 空 | `http` 方式のリクエスト：`method`、`url`、`headers`、`body`、`insecure` |
| `bemfaTopic` | 空 | Bemfa トピック。空なら音声操作なし、他のデバイスと重複不可 |
| `remark` | 空 | メモ |

デバイス一覧で「起動」を押すとマジックパケットが送信され、`checkAddr` に基づいてデバイスがオンラインかどうかが表示されます。

### リモートシャットダウン

デバイスの「リモートシャットダウン」で方式を選ぶと、デバイスカードにシャットダウンボタンが表示されます。API は `POST /api/wol/devices/{key}/shutdown` で、リクエストボディは省略できます。`{"action": "reboot"}`、`{"action": "sleep"}` で再起動やスリープも行えます（エージェント方式のみ対応）。同じデバイスでは同時に 1 つだけ実行し、最長 30 秒です。シャットダウンまたはスリープに成功すると、Bemfa のスイッチ状態をオフに書き込みます。

| 方式 | 適した場面 | 対応する操作 |
| --- | --- | --- |
| エージェント | Windows、Linux、macOS、OpenWrt。デバイス側でポートを開放したり SSH を有効にしたりする必要はありません | シャットダウン、再起動、スリープ |
| SSH コマンド | SSH サービスが有効で、Web ターミナルに保存済みのホスト | シャットダウン |
| HTTP リクエスト | Home Assistant、スマートプラグ、デバイス上の既存のシャットダウンツールなど、HTTP インターフェースを提供するサービス | シャットダウン |

#### エージェント {#agent}

操作対象のデバイスでエージェントスクリプトを実行します。エージェントは自分から Gately に接続してロングポーリングで指示を取得し、受け取ると本機でシャットダウン、再起動、スリープを実行します。エージェントはこの 3 つの固定操作だけを受け付け、Gately から他のコマンドを実行させることはできません。デバイス側でポートを開放する必要はなく、Gately もデバイスのログイン認証情報を保存しません。

1. デバイスのシャットダウン方式を「エージェント」にして保存すると、Gately がデバイス用のトークンを生成してインストール手順を開きます（その後はデバイスカードの「エージェント」からもう一度開けます）；
2. 「Gately のアドレス」がデバイスから到達できる管理画面のアドレスであることを確認します（既定はブラウザで現在開いているアドレスで、fnOS 統一ゲートウェイ経由でアクセスしている場合は直接接続のアドレスに変更します）。Gately が自己署名証明書を使っている場合は「証明書を検証しない」をオンにします；
3. デバイスの OS を選び、インストールコマンドをコピーしてデバイスで実行します：

| OS | 実行場所 | インストール形態 | ログ |
| --- | --- | --- | --- |
| Windows | 管理者として実行した PowerShell | SYSTEM アカウントの起動時タスク「Gately Agent」 | `C:\ProgramData\GatelyAgent\agent.log` |
| Linux | ターミナル（sudo と、curl または wget が必要） | systemd または OpenRC のサービス `gately-agent` | `journalctl -u gately-agent` または `/var/log/gately-agent.log` |
| macOS | ターミナル（管理者パスワードが必要） | launchd デーモン `cn.gately.agent` | `/var/log/gately-agent.log` |
| OpenWrt | SSH（root）。curl またはシステム標準の wget を使用 | procd サービス `gately-agent`。システムアップグレード時も設定を保持 | `logread -e gately-agent` |

インストールコマンドは Gately からスクリプトをダウンロードし（インストール手順から直接ダウンロードすることもできます）、まず SHA-256 を検証します（Linux と OpenWrt は `sha256sum`、macOS は `shasum -a 256`、Windows は `Get-FileHash`）。Gately が示すチェックサムと一致しない場合は `gately-agent: checksum mismatch` と表示して中止し、一致した場合は検証済みのそのスクリプト自体をインストールします。トークンはリクエストボディと環境変数で渡され、URL にもどのプロセスのコマンドライン引数にも現れません。curl と wget は `mktemp` で作成した一時ファイルからトークンを読み取り、sudo は `--preserve-env` で環境変数を引き継ぎます。そのため平文の HTTP や「証明書を検証しない」でダウンロードしても改ざんされたスクリプトは実行されません。ただしトークンは平文で送られるため、HTTPS のアドレスを使うことをおすすめします。エージェントが接続するとデバイスカードがオンライン表示になり、エージェントが報告するホスト名、OS、接続元アドレスも表示されます。エージェント方式のデバイスではオンライン確認のアドレスを入力する必要はありません。

- トークンはそのデバイスの電源スイッチに相当します。設定ファイルは root（Windows では SYSTEM と管理者）だけが読み取れます。同じトークンは 1 台のデバイスでしか使えず、別のマシンが同じトークンで接続すると拒否され、ログに表示されます；
- 指示は発行から 10 秒間だけ有効です。エージェントが先に確認し、Gately が応答してから実行します。エージェントがオフラインのときはすぐにエラーとなり、次にオンラインになるまで待機して実行されることはありません；
- トークンを「再生成」するか、シャットダウン方式を別の方式に変更すると、古いエージェントはすぐに切断され、新しいコマンドで再インストールする必要があります；
- エージェントは 25 秒ごとにポーリングし、切断後は 5 秒から最長 60 秒の間隔で再接続します；
- インストール先：Linux は `/usr/local/bin/gately-agent`、macOS は `/Library/Gately/gately-agent`（`/usr/local/bin` は Homebrew によって一般ユーザーの所有になっていることが多いため）、OpenWrt は `/usr/bin/gately-agent` です。インストール先のディレクトリは root が所有し、ほかのユーザーが書き込めない必要があり、そうでない場合はインストールを拒否します。Windows は `C:\ProgramData\GatelyAgent` で、ディレクトリの権限は SYSTEM と管理者だけがアクセスできるよう丸ごと置き換えられます。このディレクトリが既に存在し、リンク（ジャンクションまたはシンボリックリンク）であるか所有者が SYSTEM・管理者以外の場合はインストールを拒否し、確認のうえ削除するよう案内します；
- アンインストール：インストール手順からアンインストールコマンドをコピーします。Windows は `powershell -ExecutionPolicy Bypass -File "$env:ProgramData\GatelyAgent\gately-agent.ps1" uninstall`、Linux は `sudo sh /usr/local/bin/gately-agent uninstall`、macOS は `sudo sh /Library/Gately/gately-agent uninstall`、OpenWrt は `sh /usr/bin/gately-agent uninstall` です；
- スリープ：Windows はメモリへのサスペンド（スリープを無効にしたマシンでは失敗し、ログに表示されます）、Linux は `systemctl suspend`、macOS は `pmset sleepnow` を使います。スリープ中のデバイスを Wake-on-LAN で起こすには、ネットワークアダプターまたは OS で Wake-on-LAN を許可してください。

エージェント用インターフェースは `/api/wol/public/agent/` 以下にあり、ログインは不要でデバイスのトークンだけで認証します。セキュリティエントランスを設定している場合も、有効なトークンを付けたリクエストはアクセスできます。「内部ネットワークのみ」とブロックリストは通常どおり適用されます。管理用インターフェース `GET /api/wol/agent-scripts` は各エージェントスクリプトの SHA-256 をファイル名ごとに返します。

#### SSH コマンド

Web ターミナルの SSH 接続を選び、シャットダウンコマンドを入力します：

- その接続は Web ターミナルで一度接続してホスト鍵を記録済みである必要があります。Gately は無人で未知のホストを信頼しません；
- シャットダウンのたびに新しい SSH 接続を作り、終了後に閉じるため、デバイス再起動前の無効な接続は使われません；
- シャットダウンにより終了コードが返る前に SSH 接続が切れることが多く、その場合はシャットダウン開始とみなします；
- フォームには Linux（`shutdown -h now`）、Windows（`shutdown /s /t 0`）、macOS（`sudo -n shutdown -h now`）のよく使うコマンドがあります。Windows では OpenSSH サーバーを有効にしてください。Linux の非 root ユーザーは `sudo -n shutdown -h now` を使い、このコマンドにパスワードなし sudo を設定してください。

#### HTTP リクエスト

リクエスト URL（`http://` または `https://`）、メソッド、ヘッダー、ボディを入力します。レスポンスのステータスコードが 2xx なら成功とみなし、レスポンスの内容は結果に表示されます。メソッドを「自動」にすると、ボディがあれば `POST`、なければ `GET` を使います。ボディが `{` または `[` で始まり `Content-Type` が指定されていない場合は JSON として送信します。認証情報（`Authorization: Bearer …` など）はヘッダーに入れます。読み取り専用アカウントには値がマスクされて表示され、ログのアドレスにはクエリパラメーターが含まれません。接続先が自己署名証明書を使っている場合は「証明書を検証しない」をオンにできます。

API トークンでデバイスの追加・編集・複製やシャットダウンを行うには、`wol:write` に加えて `webterminal:write` が必要です（SSH 方式は SSH 接続で実行するコマンドを設定または実行できます）。選択可能な SSH 接続の一覧には `wol:read` と `webterminal:read` が必要です。エージェントのトークンの表示（`GET /api/wol/devices/{key}/secrets`）と再生成（`POST /api/wol/devices/{key}/agent-token`）には `wol:write` が必要です。

### Bemfa 音声操作 {#bemfa}

[Bemfa](https://cloud.bemfa.com) と連携すると、Xiao AI、Xiaodu、Google Assistant などの音声アシスタントでデバイスをオン・オフできます：

1. Bemfa コンソールの MQTT デバイスクラウドで、名前が `001`（コンセント）または `006`（スイッチ）で終わるトピックを作成します（例：`pc001`）；
2. デバイスに同じトピックを入力し、「Wake-on-LAN → Bemfa」でコンソールのユーザー秘密鍵を入力して有効にします；
3. Mi Home（Xiao AI）、Xiaodu などのアプリで Bemfa アカウントを連携し、デバイスを同期します。

以降「オン」でデバイスを起動、「オフ」でリモートシャットダウン（設定が必要）し、成功するとオン・オフ状態を Bemfa に書き戻します。Gately は MQTT 3.1.1 over TLS で `bemfa.com:9503` に接続して証明書を検証します。秘密鍵はクライアント ID としてこの暗号化接続でのみ使い、API ではマスク表示します。切断後は 5 秒から最長 5 分間隔で再接続します。購読時にサーバーが再送する前回の状態（保持メッセージと購読後 3 秒以内に届いたメッセージ）は実行せず、10 秒以内に繰り返された同じ指示は 1 回だけ実行します。画面や API から起動・シャットダウンに成功した場合も状態を書き戻します。同じ秘密鍵でオンラインにできるクライアントは 1 つだけで、別のプログラムや別の Gately が同じ秘密鍵で接続すると互いに切断し合います。

## スケジュールタスク

cron 式に従って、コマンドの定期実行や HTTP リクエストの送信を行います。

- `spec` は、標準の 5 フィールドの式、オプションの秒フィールド（6 フィールド。例：`*/30 * * * * *`）、`@every 10m`、`@daily` などの記述子に対応しています。
- `type` が `command` の場合は、`sh -c`（Windows では一時的な `.bat`）で `command` を実行し、環境変数に `taskName` と、`GATELY_` 接頭辞付きの同名の大文字変数を注入します。
- `type` が `http` の場合は、`http` の設定に従ってリクエストを送信します。フィールドは `url`、`method`（GET、POST、PUT、PATCH、DELETE）、`headers`（各項目は `Key: Value`）、`body`、`successContent`（レスポンスボディにこのうちのいずれかが含まれていれば成功とみなす。空の場合は 2xx のみ確認）、`timeout`、`insecureSkipVerify`、`proxy`（空欄はプロキシなし、`update` はグローバル更新プロキシ、または `http://`、`https://`、`socks5://` のプロキシアドレス）です。
- タスクは有効化・無効化でき、ページに次回の実行日時が表示され、手動ですぐに実行することもできます。
- 同じタスクの前回の実行がまだ終わっていない場合、今回のトリガーはスキップされます。
- 各タスクには直近 20 回の実行履歴が保持されます。開始日時、所要時間、成否、手動トリガーかどうか、出力（最大 4000 文字の要約を保持）が含まれます。
- 作成フォームには、式の構文チェックがあります。

## 概要とシステムログ

- 「概要」ページには、ホスト情報が表示されます。CPU のモデル、使用率、負荷、メモリ、ディスク、NIC のアドレスとリアルタイムの速度、グローバル IPv4 と IPv6（クリックでコピー）、各モジュールのサービス状態、さらに Gately プロセスのバージョン、コミット、ビルド日時、起動日時、PID、CPU、常駐メモリ、Go ヒープとゴルーチン数です。
- Gately が外部プログラム（frp、Tailscale、NetBird、Cloudflare トンネル、File Browser）を管理しているときは、「概要」ページに「管理対象プロセス」カードも表示され、各プロセスのモジュールとインスタンス、プログラム名、PID、稼働時間、再起動回数、CPU、常駐メモリを一覧し、カードの見出しに合計を表示します。行をクリックすると該当モジュールを開きます。集計はプロセス自体のみで、そのプロセスが起動した子プロセスは含まず、パスと起動引数も表示しません。
- 「システムログ」ページには、各モジュールのログがまとめて表示され、Docker、FTP、スケジュールタスクなどのモジュールの実行記録も含まれます。

## テーマ

画面には 15 のカラーパレットがあり、Gately オリジナル（エメラルド、オーシャン、フレッシュ、サクラ、サンセット、ミッドナイト、パンク）とクラシック（GitHub, Nord, Dracula, Catppuccin, Tokyo Night, Gruvbox, Rosé Pine, Solarized）の 2 グループに分かれ、どのパレットにもライトとダークがあります。モードはライト、ダーク、システムに従うから選べ、システムに従う場合は現在のパレットのライト版またはダーク版を使います。どのパレットでもアクセントカラーを 10 色のプリセットまたはシステムのカラーピッカーで変更でき、ロゴとログイン画面のグラデーションもそれに合わせて変わります。パレットを選び直すとカスタムアクセントは解除されます。角丸は直角、パレットに従う、丸めから選べます。テーマ設定はブラウザのローカルに保存されます。
