# ポート転送

ローカルで待ち受けているポートを、別のデバイスやサービスへ転送します。

## 機能

- TCP と UDP
- IPv4 と IPv6。v4 と v6 の間で相互に転送できます
- ポート範囲と複数ポート
- 複数ターゲットとフェイルオーバー
- 接続数制限
- トラフィック統計と実行ログ
- 転送先への PROXY プロトコル（v1 / v2）の送信。実際のクライアントアドレスを下流に渡せます
- ドメインやプロトコルに応じて複数のサービスで 443 などの 1 つのポートを共用するには、[プロトコル振り分け](/ja/docs/modules/protoroute)を使います

## PROXY プロトコル

ポート転送は TCP を中継するだけなので、下流からはデフォルトで Gately 自身のアドレスしか見えません。ルールで「PROXY プロトコル」を v1 または v2 に設定すると、Gately は転送先に接続した直後に PROXY ヘッダーを送信します。下流は実際のクライアントアドレスを取得でき、ログ、レート制限、アクセス制御に利用できます。

転送先では対応する受信オプションを有効にする必要があります。有効でない場合、接続は拒否されます。例：

- haproxy：`bind 192.168.1.8:4434 accept-proxy`
- nginx：`listen 4435 ssl proxy_protocol;`
- Gately Web サービス：リスナーで「PROXY プロトコルを受信」を有効にし、送信元を信頼する PROXY 送信元に追加します

このオプションは TCP にのみ作用し、UDP の転送には影響しません。

## 典型的な利用シーン

- NAS のサービスポートを共通の入口にまとめて公開する
- IPv6 と IPv4 の間で相互接続できるよう転送する
- 1 つのサービスに主系・待機系の 2 つのバックエンドを設定する

## デプロイのヒント

ポート転送はホストのポートを直接待ち受けるため、Docker でデプロイする場合は `--network host` を推奨します。

## グループと並べ替え

ルールには「グループ」（最大 64 文字）を設定できます。一覧はグループごとに折りたためるセクションで表示され、グループは最初に現れた順に並び、グループなしのルールは最後になります。折りたたみ状態はブラウザに保存されます。ページ上部の検索ボックスでは名前・グループ・待ち受けポート・転送先で絞り込めます。

「並べ替え」で並べ替えモードに入ります。矢印でルールを上下に移動したり、グループごと移動したりできます。複数のルールにチェックを入れてそのどれかをドラッグするとまとめて移動し、別グループのルールや見出しにドロップするとそのグループに入ります。ツールバーではチェックしたルールを指定グループへ一括で移動でき、名前を空欄にするとグループから外します。順序とグループは一覧の表示にだけ影響し、変更しても転送は再起動されず、確立済みの接続も維持されます。

グループ見出しにマウスを合わせて鉛筆ボタンを押すと、グループ名を変更できます。グループ内の項目もまとめて新しい名前になり、位置と順序は変わりません。既存のグループと同じ名前にすると、確認のうえ 2 つのグループが統合されます。
