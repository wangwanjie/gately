# 侵入防御

fail2ban のような侵入防御です。ログからブルートフォース攻撃を見つけ、使っていないポートにおとりを置き、ポートスキャンを数え、悪意のある IP をブロック一覧に追加して、システムファイアウォール（nftables）に同期し、カーネルでその通信をすべて破棄します。

## 機能

- **ログルール**：ログファイル、systemd ジャーナル、コマンド出力（OpenWrt の `logread -f` など）、Docker コンテナのログを読み、正規表現で失敗記録を見つけ、集計期間内に回数に達した IP をブロックします。SSH、Dropbear、Nginx、Vaultwarden、Home Assistant、Proxmox VE などのテンプレートを内蔵し、ルール編集時にログのサンプルを貼り付けてテストできます；
- **Gately イベント**：管理画面のログイン失敗と WAF のブロックもルールのソースにでき、正規表現は不要です；
- **Web パス探索**：Web サービスが処理したリクエストをリスナー、パス、ステータスコードで直接数え、ログは読みません。`/.env`、`/.git` などのおとりパスにアクセスしたり、未知のドメインを繰り返しスキャンしたりする送信元をブロックします；
- **おとりポート**：このホストで使っていないポート（既定は 23、135、1433、3389、5900、6379 など）におとりを置き、接続してきた送信元をすぐにブロックします；
- **ポートスキャン検出**：同じ送信元が 1 分間にこのホストの開いていないポートへしきい値を超えて接続するとブロックします；
- **統一されたブロック一覧**：手動ブロック（CIDR ネットワークと永久ブロックに対応）と Web サービスの認証失敗による自動ブロックをここで管理します。本機を経由して転送された接続はすべてループバックアドレスとして表示されるため、手動ブロックにループバックアドレスは含められません。ブロックは保存され、再起動後に復元されます；
- **段階的ブロック**：同じアドレスが 30 日以内に再びブロックされると期間が倍になります（上限あり）；
- **ホワイトリスト**：LAN、ループバック、100.64.0.0/10（Tailscale）、このホストのインターフェースがある IPv6 /64 は既定で無視します（ブロックは /64 単位のため、同じ LAN のグローバル IPv6 機器が巻き添えになりません）。IP やネットワークを追加でき、ホワイトリストの単一の IPv6 アドレスはその /64 全体を保護します。

## 適用範囲

| 環境 | ブロックの効果 | おとりポート | ポートスキャン検出 |
| --- | --- | --- | --- |
| Linux（root または `CAP_NET_ADMIN`、nftables をインストール済み） | SSH、他のプログラム、Docker コンテナや LAN 機器へ転送される通信も含め、すべてカーネルで破棄 | カーネルで処理し、SYN だけのスキャンも検出 | 利用可 |
| Docker（host ネットワーク + `cap_add: NET_ADMIN`） | 同上。ルールはホストに書き込まれます | 同上 | 利用可 |
| fnOS パッケージ、OpenWrt 22.03 以降 | 同上（root で動作し、nftables は標準搭載） | 同上 | 利用可 |
| その他（Windows、macOS、FreeBSD、nftables や権限のない Linux） | Gately 自身のサービス（ポート転送、Web サービス、STUN、WebDAV、FTP、SMB、frps ログイン、管理画面）にのみ適用 | Gately が待ち受け、ハンドシェイクを完了した接続のみ検出 | 利用不可 |

ページ上部にファイアウォール同期の状態が表示され、利用できない場合は原因と対処方法が表示されます。

## ファイアウォールルール

「システムファイアウォールに同期」をオンにすると、Gately は nftables に専用の `inet gately` テーブルを作成し、システム既存のルール（fw4、Docker、ufw など）は変更しません：

- `prerouting` チェーン（優先度 -190、コネクショントラッキングの後、宛先 NAT の前）でブロック中のアドレスから届くパケットを破棄します。このホスト宛ても、コンテナや LAN 機器への転送も破棄されます。このホストから開始した接続（DNS やパッケージミラーへのアクセスなど）の応答は、相手のアドレスがブロックされていても通常どおり通します。IPv6 は /64 単位でブロックします；
- `input` チェーンはこのホスト宛ての新しい接続だけを見て、おとりポートとスキャン検出に使います。ホワイトリストのアドレスは対象外です；
- 同期をオフにするか Gately を停止するとテーブルごと削除されます。他のプログラムに削除された場合は 10 秒以内に書き直します。

ページの「ルールを表示」で現在のルール全体を確認できます。

::: tip Docker でのデプロイ
ルールをホストに書き込むには `network_mode: host` と `NET_ADMIN` の付与が必要です：

```yaml
    network_mode: host
    cap_add:
      - NET_ADMIN
```

付与しない場合も、ブロックは Gately 自身のサービスに適用されます。ホストのログを読むにはログのディレクトリをコンテナにマウントします。例えば `- /var/log:/var/log/host:ro` とし、ルールには `/var/log/host/auth.log` と入力します。systemd ジャーナルのソースはコンテナ内では使えません。
:::

## ログルール

| ソース | 入力内容 | 説明 |
| --- | --- | --- |
| ログファイル | ファイルパス（1 行に 1 つ） | ファイル末尾から追加分を読み、ローテーション（名前変更や切り詰め）に追従 |
| systemd ジャーナル | `ssh.service` などのサービスユニット | `journalctl -f` で読み取り |
| コマンド出力 | `logread -f` などのコマンド 1 つ | 終了すると自動で再起動 |
| Docker コンテナ | コンテナ名 | Docker 管理モジュールの接続先 Docker から読み取り |
| Gately イベント | 管理画面のログイン失敗 / WAF ブロック | イベントに送信元 IP が含まれるため、フィルターは不要 |
| Web パス探索 | リスナー（空欄可）とパスルール | Web サービスのリクエストを数えます。後述 |

フィルターは Go の正規表現（RE2 構文）で、1 行に 1 つ、`<HOST>` が送信元アドレスを表します。例：

```
Failed password for (?:invalid user )?\S* ?from <HOST>
```

「除外」に一致した行は数えません。集計期間、失敗回数、ブロック期間はルールごとに設定でき、ブロック期間は既定・カスタム・永久から選べます。

## Web パス探索

ソースに「Web パス探索」を選ぶと、ルールはログを読まずに Web サービスが処理したリクエストを直接数えます：

- **リスナー**：1 つ以上選べます。空欄ですべてのリスナー；
- **パスルール**：1 行に 1 つ、空欄ですべてのパス。`*` は `/` を含む任意の文字に一致し、パス全体を大文字小文字を区別せずに照合します。例えば `*/.env` は `/.env` と `/api/.env` に一致します。`~` で始まる行は Go の正規表現です。`//.env` や `/a/../.env` のような書き方も正規化後のパスで一致します；
- **除外パス**：書き方は同じで、一致したリクエストは数えません；
- **集計対象**：既定では 404 と 444（存在しない内容へのアクセス、または「接続を切断」サイトによる切断）だけを数えるため、存在するページへのリクエストは数えません。「任意のステータスコード」をオンにするとすべての応答を数えます。シングルページアプリはどのパスにも 200 を返すため、おとりパスに向いています。任意のステータスコードはパスルールか「未知ドメインのみ」と組み合わせる必要があり、そうでない場合は保存できません；
- **アクセス制御による拒否**：サイトの「拒否時の動作」が「接続を切断」のとき、ブロック、IP アクセス制御、国フィルターで拒否されたリクエストは、通常のサイトでは 403 として数え（リスト外の正規の訪問者を誤ってブロックしないため）、デフォルトサイトでは「接続を切断」タイプのデフォルトサイトと同じく 444 として数えます。デフォルトサイトをリバースプロキシと許可リストにして自分の IP を通しても、未知のドメインのスキャンは引き続き集計されます；
- **未知ドメインのみ**：ドメインがどのサイトにも一致しないリクエスト、つまり既定サイトが処理するか、既定サイトがないときにリスナーが 404 を返すリクエストだけを数えます。

テンプレートは 3 つあります：

| テンプレート | 条件 | 説明 |
| --- | --- | --- |
| Web おとりパス | `/.env`、`/.git`、`wp-login.php`、`phpinfo.php`、`phpmyadmin` など、任意のステータスコードで 1 回 | 1 日ブロック。サイト自体が WordPress や phpMyAdmin などの場合は該当行を先に削除してください |
| 未知ドメインのスキャン | 未知ドメインのみ、1 分以内に 5 回 | 1 日ブロック。既定サイトの「接続を切断」と組み合わせると、スキャナーは数回の 444 の後にブロックされ、ファイアウォール同期をオンにしていればその後の接続は破棄されます |
| Web 404 探索 | すべてのパス、1 分以内に 10 回 | favicon、robots.txt、`.map` などブラウザーが自動で要求するパスは除外済み。リバースプロキシのバックエンドが返す 404 も数えるため、ギャラリーのサムネイル欠落や存在しない API のポーリングでも発動することがあります。有効にする前にアクセスログを確認し、必要なら回数を上げるか除外パスを追加してください |

Web サービスのリスナーカードで「探索ブロック」を押すとこのページが開き、そのリスナーを選んだ状態でおとりパスのテンプレートが適用されます。ルールの保存と実行は侵入防御が担います。ルール編集時にリクエストパスを貼り付けてパスルールをテストできます。

::: warning ブロックの範囲
どのリスナーで発動しても、ブロックは同じブロック一覧に入り、すべてのリスナー、サイト、Gately のほかのサービスに適用されます。ファイアウォール同期がオンなら、システムファイアウォールでもそのアドレスの通信をすべて破棄します。
:::

送信元アドレスはアクセスログと同じで、PROXY プロトコルでのみ復元されます。CDN 経由で、実 IP をリクエストヘッダーで渡すサイトでは CDN ノードがブロックされるため、そのようなリスナーではパス探索を使わないでください。Gately が同じホスト上の別のリバースプロキシの後ろにある場合、送信元はループバックアドレスになり、「LAN アドレスを無視」がオンならブロックされませんが、ルールも効きません。

## ポートスキャン検出のトレードオフ

スキャン検出が数えるのは、**このホストで待ち受けていないポート**への新しい接続です。待ち受け中の TCP ポートは 10 秒ごとに更新され、開放扱いになります。他のファイアウォールルールで転送されるポートは `input` チェーンを通らないため数えません。しきい値の既定は毎分 12 回です。通常のクライアントが閉じたポートを再試行するのは毎分約 5 回なので、10 未満にはしないでください。

おとりポートのうち待ち受け中のものは自動で除外され、正規の訪問者をブロックしないようにしています。

## Web サービスとの関係

Web サービスの「認証失敗時のブロック」によるブロックも同じブロック一覧に入るため、ファイアウォール同期をオンにするとホスト全体に適用され、Web サイトだけに限られなくなります。「LAN アドレスを無視」がオンなら LAN のアドレスは自動でブロックされません。

Web サービスと WAF が実際のクライアントアドレスを知る手段は PROXY プロトコルだけです。CDN 経由で実 IP をヘッダーで渡すサイトでは、認証失敗ブロックと「WAF ブロック」ルールが CDN のノードをブロックしてしまうため、そのようなサイトでは有効にしないでください。

## 通知

ブロックすると「侵入防御：IP をブロックしました」イベントが発生し、[通知センター](/ja/docs/modules/notify)で購読できます。おとりポートとスキャン検出が同じチェックでブロックした複数のアドレスは 1 件の通知にまとめられます。

## 検証

fnOS（Debian 12、nftables 1.0.6）と iStoreOS 24.10（nftables 1.1.1）の独立したネットワーク名前空間で検証しました。おとりポートとスキャン検出（IPv4 と IPv6）はカーネルでブロックしてブロック一覧に取り込まれ、ログファイル（ローテーションを含む）、systemd ジャーナル、Docker コンテナのログ、管理画面のログイン失敗のいずれでもブロックが発動しました。手動のネットワーク・永久ブロック、解除、段階的な期間、再起動後の復元、外部から削除されたテーブルの書き直し、停止時のルール削除も期待どおりでした。`NET_ADMIN` のない Docker コンテナは権限不足と判定され、ユーザー空間のおとりポートに切り替わります。
