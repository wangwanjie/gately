# セキュリティモデルとプライバシーの約束

Gately はネットワーク境界で動作し、DNS プロバイダーのキー、証明書の秘密鍵、各種認証情報を扱います。そのため、セキュリティと透明性を最優先の設計目標としています。

## プライバシーの約束

- **プロジェクト側のサーバーには接続しない**：端末情報を送信せず、リモートからの設定配信も行いません。デフォルトで 12 時間ごとに GitHub のリリース一覧とセキュリティアドバイザリーを匿名で読み込みますが、新しいバージョンとセキュリティ更新を知らせるためだけで、無効にできます。詳しくは[自動更新チェック](/ja/docs/guide/install#update-check)を参照してください。
- **外部アドレスを確認・変更可能**：公開 IP の照会先や STUN サーバーなどのアドレスはすべて画面に表示され、変更や無効化ができます。
- **外部ログインは自己管理**：GitHub、Google、QQ、OIDC のログインには自分で取得した OAuth アプリを使い、中継サービスは一切経由しません。
- **アップグレードは自分の判断で**：プログラムがバックグラウンドで自身をダウンロードしたり置き換えたりすることはありません。Linux バイナリ導入のオンラインアップグレードは管理者がクリックしたときだけ実行され、リリース署名を検証してから SHA-256 を照合し、旧バージョンを残します。アップグレードのタイミングはあなたが決めます。

## データ保護

- 設定は平文の JSON でパーミッションは 0600。監査とロールバックができます。
- 機密フィールドは API 出力でマスクされます。画面の目のボタンを押すと保存済みの平文を取得でき、書き込み権限が必要です。bcrypt ハッシュで保存された Web ユーザーのパスワード、OIDC クライアントシークレット、秘密鍵は返されません。2 段階認証を有効にした共有ユーザーは QR コードを再表示できます。Docker コンテナの環境変数、起動コマンド、プロセスのコマンドラインも同様に扱い、Docker の書き込み権限がない場合は `********` で表示します。
- cloudflared のトークンは環境変数で渡されるためプロセス一覧に現れません。frp と Tailscale のトークンやキーはパーミッション 0600 で保存されます。

## 認証とアクセス制御

- bcrypt によるパスワードハッシュと、HMAC 署名付きのセッショントークン
- セッションの失効：ログアウトすると現在のセッショントークンがサーバー側で失効し、漏えいしたトークンはすぐに使えなくなります。「設定 > アカウントとセキュリティ > ログインセッション」の「すべてのデバイスからログアウト」で、すべての管理画面セッションが無効になります（API トークンには影響しません）。パスワードの変更、2 段階認証の有効化と無効化、パスワードのリセットでもすべてのセッションが無効になります。失効の記録はアカウントファイルに保存され、再起動後も有効で、トークンの期限切れとともに削除され、件数にも上限があります。
- 外向きリクエストの制限：「設定 > ネットワークと実行」の「外向きリクエストの制限」は既定で無効です。有効にすると、管理者が設定した外向きリクエスト（Webhook、通知、IP リストの購読、DDNS のコールバックと IP 取得 URL、更新確認とプログラムのダウンロード、サードパーティログインなど）は、ループバック、プライベート、リンクローカル（クラウドのメタデータアドレス 169.254.169.254 を含む）、ULA のアドレスへの接続時に拒否され、名前解決の結果とリダイレクトにも適用されます。リバースプロキシの上流、Wake-on-LAN、ストレージのマウントなど内部ネットワーク向けの機能には影響しません。
- 低速リクエストへの対策：管理ポートはリクエストボディの読み取り速度を制限します。通常のエンドポイントは 60 秒以内にボディを受け取る必要があります。大きなファイルを扱うエンドポイント（バックアップの復元、アップグレードパッケージ、ファイルのアップロード）は合計時間の上限はありませんが、最低平均速度（毎秒 4 KiB）で送信し続ける必要があり、低速な送信で接続を占有するクライアントは切断されます。
- パスワードの規則：管理者パスワードは 10～72 バイトで、よく使われる脆弱なパスワード（前後に数字や記号を付けたもの、`p@ssw0rd` のような文字の置き換えなどの変形を含む）、gately やユーザー名を含むもの、連続した文字（`123456`、`qwerty` など）、同じ文字や断片の繰り返し、1 種類の文字だけのパスワードを拒否します（16 文字以上のパスフレーズは文字の種類の要件を緩和）。入力中に強度をリアルタイムで表示します
- パスワード変更の強制：デフォルトのパスワード `gately.cn` は公開されています。管理者がデフォルトのパスワードまたは強度不足のパスワードを使用している間は、ログイン後に閉じられないパスワード変更ダイアログが表示され、変更するまで使い続けられません。それまでの間、ログインセッションによる書き込み操作は、パスワードの変更、表示言語の切り替え、すべてのデバイスからのログアウトを除いてサーバー側ですべて拒否されます。API トークンは引き続き呼び出せますが、アカウント、2 段階認証、パスキー、追加アカウント、API トークン、システム設定、Web ターミナルのセキュリティ設定は変更できません（バックアップからの復元や、システム設定・Web ターミナルの履歴バージョンへのロールバックもできません）。新しいパスワードにデフォルトパスワードは使えず、変更後に戻すこともできません
- リセット：パスワードを忘れたときや 2 段階認証アプリを紛失したときは、サーバー上で `gately reset-password` / `gately reset-totp` を実行してリセットするしかありません（設定ディレクトリの読み書きと、`yes` の入力による確認が必要）。リセット後はすべてのセッションが無効になり、監査ログに記録されます。詳しくは [パスワードと 2 段階認証のリセット](/ja/docs/guide/install#reset) を参照してください
- Passkey（WebAuthn）によるログイン：公開鍵のみを保存し、ユーザー検証（指紋、顔、PIN）を必須とし、署名カウンターで複製を防ぎます。ドメイン名と HTTPS（または localhost）でのアクセスが必要です
- 2 段階認証（TOTP。RFC 6238 のテストベクターで検証済み）
- 読み取り専用アカウント：状態と設定を閲覧できますが、変更、バックアップのダウンロード、シークレットの読み取り、ターミナルの起動はできません。パスワードのリセットや削除を行うとセッションは即座に無効になります; 読み取り専用アカウントと読み取り権限だけの API トークンが設定を読み取る場合、サイト共有ユーザーのパスワード、共有リンクのトークン、リクエスト／レスポンスヘッダーの値、各種シークレット、URL 内のパスワードとクエリの値は `********` と表示されます「監査ログ」「設定履歴」「API トークン」「設定」は管理者専用で、読み取り専用アカウントのサイドバーとメニューには表示されず、リンクを直接開くと概要に戻ります；
- 読み取り専用アカウントと読み取り権限のみの API トークンには、コマンドとスクリプト、管理対象プログラムの追加起動引数と環境変数、Webhook などの HTTP リクエストのボディ、DNS プロバイダーの認証情報のうちエンドポイントやリクエストメソッドといった設定以外の追加フィールド（カスタムコールバックのヘッダーとボディなど）も表示されません。
- ログイン失敗のレート制限と段階的なロックアウト：同じ接続元からの連続した失敗が上限に達するとロックされ、ロックが繰り返されるたびにロック時間が 2 倍になります（最長 24 時間）
- 未知のアドレスの失敗上限：10 分間に、ログインに成功したことのないすべてのアドレスのログイン失敗の合計が上限（「設定 → アカウントとセキュリティ」の「未知のアドレスの失敗上限」、設定項目 `loginGlobalLimit`、既定 20、-1 で無効）に達すると、未知のアドレスからのパスワードログインは一時的に 429 を返し、「認証: 分散型の総当たり攻撃の疑い」通知イベントを発行します。ログインに成功したことのあるアドレスは影響を受けません。多数のアドレスに分散した総当たり攻撃への対策です。Passkey ログインは接続元ごとの独立したレート制限を使い、パスワードの失敗や未知のアドレスの失敗上限の影響を受けません
- パスワードログインの無効化：Passkey を登録すると、「設定 → アカウントとセキュリティ」の Passkey カードでパスワードログインを無効にできます。以降、管理者アカウントは Passkey またはサードパーティログインでのみログインでき、パスワードを総当たりで破られることはなくなります（読み取り専用アカウントは影響を受けません）。無効の間は最後の Passkey を削除できません。すべての Passkey を紛失した場合は、サーバーで `gately reset-password` を実行するとパスワードログインが再び有効になります
- セキュリティスコア：「設定 → アカウントとセキュリティ」上部のセキュリティスコア（`GET /api/system/security`）は現在の設定から 7 項目を確認し、0～100 点で評価します：管理者パスワード（35 点）、2 段階認証（TOTP または Passkey、20 点）、セキュアエントリー（15 点）、ログイン失敗ロックアウトの設定（10 点）、HTTPS（10 点）、未知のアドレスの失敗上限（5 点）、管理者ユーザー名が admin などの一般的な名前でないこと（5 点）。管理画面がインターネットに公開されていない場合（LAN 内からのみ許可、またはループバックアドレスのみで待ち受け）は、セキュアエントリー、HTTPS、ユーザー名の 3 項目を満点とみなします。高リスクの問題や強化の推奨がある場合は管理画面の上部に表示され（強化の推奨は 7 日間表示しないようにできます）、「強化する」をクリックすると該当する設定に移動します
- ローカルのリバースプロキシ：管理画面を同じホスト上の nginx、haproxy、Gately Web サービスの背後に置いた場合、このホストのアドレスから届いた `X-Real-IP` / `X-Forwarded-For` だけを信頼します。LAN 内からのみ許可、ログイン失敗のレート制限、監査ログはこれをもとに実際の接続元を取得します。「設定 → アクセス制御」で無効にしたり、信頼するプロキシを追加したりできます; 2 つのヘッダーが食い違う場合はプロキシが追加した `X-Forwarded-For` を優先し、一方が内部アドレスでもう一方がパブリックアドレスのときはパブリックアドレスを採用するため、内部アドレスを偽装しても内部ネットワーク限定アクセスは回避できません。プロキシでは両方のヘッダーを設定してください（nginx：`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`）
- セキュアエントリー、LAN 内からのみ許可、管理画面の HTTPS。ログイン不要のモジュール API（`/api/<モジュール>/public`、例：[Wake-on-LAN のエージェント](/ja/docs/modules/tools#agent)）は有効なデバイス認証情報があればセキュアエントリーを通過できます。ブロックと LAN 内からのみ許可の制限は引き続き適用されます
- 未認可アクセスへの応答：ブロックされた接続元、LAN 内からのみ許可のときの外部からのアクセス、セキュアエントリーを経由しないリクエストに対し、通常の 404、空白ページ、接続を切断、タイムアウトまで応答しない、カスタムページのいずれかを返すようにでき、管理ポートの特徴を隠せます。詳しくは [ハードニングの推奨事項](/ja/docs/guide/hardening) を参照してください
- fnOS 統一ゲートウェイ：fnOS パッケージに fnOS 統一ゲートウェイ経由でアクセスする場合は fnOS がアクセスを制御し、fnOS 管理者だけが開けます。「fnOS のログイン状態で自動ログイン」は既定で無効です。有効にすると、fnOS にログイン済みの管理者は Gately の管理者として（2 段階認証を省略して）入れます。一般の fnOS ユーザーは引き続きログインが必要です。詳しくは [fnOS ネイティブアプリ](/ja/docs/guide/install#fnos) を参照してください
- fnOS 統合ゲートウェイ経由では、状態を変更するリクエストと WebSocket 接続は管理画面自身のページからのものだけを受け付けます。ブラウザーが同一オリジンと示している場合（`Sec-Fetch-Site: same-origin`）、またはページのオリジンが管理者セッションや管理者のパスワード・Passkey ログインによって確認済みの場合です。同じ NAS の別ポートのページが管理者のログイン状態を借用することはできません。非常に古いブラウザーは `Sec-Fetch-Site` を送信しないため、初回は管理者パスワードで一度ログインしてください。ゲートウェイ経由のログイン制限は fnOS ユーザーごとに数えます。
- コンテンツセキュリティポリシー：管理画面のページは自身のスクリプトだけを読み込み、他のサイトに埋め込むことはできません。API レスポンスはリソースを一切読み込みません。ログイン Cookie には `HttpOnly` と `SameSite=Strict` が付き、HTTPS でアクセスした場合（信頼済みプロキシや fnOS 統合ゲートウェイが終端する HTTPS を含む）は `Secure` も付きます。
- モジュールのオン／オフ：「設定 → 機能モジュール」で無効にしたモジュールはサービスを起動せず、管理 API も提供しないため、攻撃対象領域を減らせます。[カスタムビルド](/ja/docs/modules/#custom-build)なら使わないモジュールをコンパイル時に取り除けます
- 複数トークンの API：各トークンには作成時に選択したモジュールの読み書き権限のみが付与され、有効期限を設定でき、最後に使われた接続元 IP が記録されます。アカウント、2 段階認証、トークン管理、さらにバックアップ、復元、再起動、システム設定のエンドポイントはログインセッションからのみ利用できます。詳しくは [API トークンと OpenAPI](/ja/docs/reference/api) を参照してください
- サイトのアクセス制御：認証失敗時の自動ブロック、GeoIP による国フィルター、パスルール。詳しくは [Web サービス](/ja/docs/modules/web) を参照してください
- 設定バックアップは暗号化（scrypt + AES-GCM）に対応しています。詳しくは [設定バックアップ](/ja/docs/modules/backup) を参照してください

## 監査と追跡可能性

監査ログはログイン、設定変更、機密アクセスを記録し、設定履歴は各設定ファイルが上書きされる前のバージョンを保持してワンクリックのロールバックに対応します。詳しくは [監査ログと設定履歴](/ja/docs/guide/audit) を参照してください。リリース成果物には cosign 署名、ビルド来歴の証明（provenance）、SBOM が付属します。検証方法は [リリースの検証](/ja/docs/guide/verify) を参照してください。

## 高リスク機能のデフォルト値

ローカルシェルのターミナルはデフォルトで無効です。SSH ターミナルは「初回信頼（Trust On First Use）」方式でホスト鍵のフィンガープリントを記録します。

## セキュリティ問題の報告

脆弱性は GitHub リポジトリの Security ページから非公開で報告し、公開 Issue に詳細を書かないでください：<https://github.com/wangwanjie/gately/security>

その他の実践的な推奨事項は [ハードニングの推奨事項](/ja/docs/guide/hardening) を参照してください。
