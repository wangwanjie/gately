# 設定と起動オプション

## コマンドラインオプション

| オプション | 説明 |
| --- | --- |
| `-c` | 設定ディレクトリ。環境変数 `GATELY_CONFIG_DIR` でも指定できます |
| `-listen` | 管理画面の待ち受けアドレスを上書きします。例：`:16680` |
| `-apply` | 宣言的設定のディレクトリ。環境変数 `GATELY_APPLY_DIR` でも指定できます。後述 |
| `-version` | バージョン情報を出力します |

| 環境変数 | 説明 |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | 初回起動時の管理者の初期パスワード（8 文字以上）。未設定の場合はデフォルトのパスワード `gately.cn` になります。アカウントが既に存在する場合は効果がありません |

## 設定ディレクトリ

すべての設定は設定ディレクトリに保存されます。モジュールごとに 1 つの `<name>.json` 平文ファイルで、アトミックに書き込まれ、ファイルのパーミッションは 0600 です。そのため次のことができます。

- テキストエディターでそのまま内容を確認できます
- ディレクトリを git に入れ、diff で変更を監査し、いつでもロールバックできます
- バックアップはディレクトリをコピーするだけで完了します

::: warning 注意
`ssl.json` には証明書の秘密鍵が含まれています。バージョン管理に入れる前に、リポジトリがプライベートであることを確認するか、このファイルを除外リストに追加してください。
:::

## 宣言的設定

`-apply <ディレクトリ>` を指定すると、起動するたびにそのディレクトリ内の `<名前>.json` を設定ディレクトリへ上書きします。内容が同じファイルは書き直しません。設定を git リポジトリ、Kubernetes の ConfigMap、デプロイスクリプトでまとめて配布する用途に向いています。

- 書き込む前に正しい JSON かを検証し、無効なファイルが 1 つでもあれば起動を拒否します
- `account.json` と `tokens.json` は上書きできません。アカウントとトークンは管理画面でのみ管理できます
- 上書きされた古い内容は [設定履歴](/ja/docs/guide/audit) に保存され、いつでもロールバックできます

## 外部プログラムのディレクトリ

Tailscale、frp、cloudflared、File Browser は公式の外部プログラムを管理し、次の順序で実行ファイルを探します。

1. モジュール設定に入力したパス
2. 設定ディレクトリ配下の `bin/` サブディレクトリ
3. `PATH`

各モジュールページからオンラインでインストール、更新、ロールバックできます。プログラムは `bin/` に、旧バージョンは `bin/.versions/` に保存されます。詳しくは [オンラインでのインストール・更新・ロールバック](/ja/docs/modules/tunnels#install) を参照してください。バイナリを自分で設定ディレクトリに置くこともできます（Docker でデプロイする場合の例：`./gately-data/bin/frpc`）。Tailscale には `tailscale` と `tailscaled` の両方が必要です。

## 実行ログ

システムと各モジュールの実行ログは、既定で設定ディレクトリの `logs/` に書き込まれます。再起動やアップグレードの後も「システムログ」と各モジュールのページで確認できます。

- 出力元ごとに 1 つの JSON Lines ファイル：`logs/<モジュール ID>.log`、システムログは `logs/gately.log`。起動時に「ログの保持行数」の分だけ最新のログをファイルから復元します
- 新しいログは最大 1 秒遅れてまとめて書き込まれます。ファイルが上限（既定 2 MB）を超えると `.1` にローテーションし、その 1 世代だけを残すため、出力元ごとの使用量は最大で上限の 2 倍です
- Web サービスのアクセスログは量が多く後から見返すことが多いため、日単位で別にアーカイブします。現在のファイルが日をまたぐ（または合計サイズの 4 分の 1、最大 16 MB を超える）と `logs/webservice.<開始時刻>.log` に名前を変え、バックグラウンドで `.log.gz` に圧縮します。「アクセスログ保持日数」（既定 7 日）と「アクセスログ合計サイズ (MB)」（現在のファイルとすべての圧縮アーカイブの合計、既定 32 MB、ログのあるパーティション容量の 5% まで）に従って古いアーカイブから削除します
- 各モジュールは現れたログの出力元を `logs/<モジュール ID>.sources` に記録し、再起動後も保持します
- 「設定 → ネットワークと実行 → 実行パラメーター」で「ログを永続化」をオフにしたり、「ログファイル上限」「アクセスログ保持日数」「アクセスログ合計サイズ (MB)」を変更したり、「ログディレクトリ」を別の絶対パス（外付けディスク上のディレクトリなど。存在しなければ Gately の実行ユーザーだけがアクセスできる状態で自動作成）に変えたりでき、すぐに反映されます。ログディレクトリを変更すると新しいログは新しいディレクトリに書き込まれ、元のディレクトリのファイルはそのまま残ります。永続化をオフにするとログはメモリ上にのみ保持され、再起動で消去されます
- 画面でモジュールのログを消去すると、対応するファイル、ローテーション済みファイル、圧縮アーカイブ、出力元の記録も削除されます
- 設定のバックアップには `logs/` と操作監査ログ `audit.log` は含まれません

### 表示と絞り込み {#log-filter}

「システムログ」ページと各モジュールページ下部のログカードは同じログビューアーを使います。次の条件を組み合わせて絞り込めます。変更はすぐに反映され、新しいログも条件に一致するものだけが追加されます。

- レベルとソース（ドロップダウンにはモジュール設定にあるすべてのソースとログに現れたソースが並びます。たとえば Web サービスのすべてのリスナーで、まだアクセスのないものやログがファイルにしかないものも含みます。直接入力も可能）
- キーワード：スペース区切りはすべてを含む、二重引用符でフレーズ、先頭の `-` で除外（例：`GET "timeout" -debug`）。一致した部分は強調表示されます。画面が他の言語のときは、画面に表示される訳文で検索できます
- 「除外」：いずれかの語を含むログを非表示にし、キーワードと同時に適用されます。書き方はキーワードと同じ（スペース区切り、二重引用符でフレーズ）で、例：`debug "health check"`。`-` で始まる語そのものを除外するには `"-v"` のように二重引用符で囲みます
- 「詳細フィルター」の IP：完全なアドレス、範囲（`10.0.0.0/8` など）またはアドレスの一部。複数はカンマ区切り。IP が個別に記録されていないログは本文からアドレスを認識するため、ログイン失敗や侵入防御のログにも使えます。先頭に `!` または `-` を付けると除外になり、`!1.2.3.4, !10.0.0.0/8` でそれらの送信元を非表示にできます。含める項目と組み合わせることもできます（`10.0.0.0/8, !10.0.0.5`）
- 「詳細フィルター」の期間：過去 15 分から 7 日まで、または任意の開始・終了時刻
- Web サービスのツールバーには表示用のスイッチが 2 つあり、表示のみに影響します（ログは保存され、選択はブラウザーに記憶されます）。「禁止された送信元を隠す」は送信元が禁止されているため拒否されたリクエストを非表示にします（CDN の背後ではカーネルの禁止が CDN からの接続に効かず、禁止された訪問者は Web 層で拒否されて 403 / 444 の記録が残ります）。現在も禁止中の送信元のリクエストは、禁止のきっかけになったものも含めてすべて非表示になります（禁止の解除または期限切れ後に再び表示されます）。「管理画面のリクエストを隠す」はこのインスタンスの管理画面ログインセッションを持つリクエスト（Web サービスのサイト経由で管理画面を開いたときのログページのポーリングなど）を非表示にし、既定でオンです。これらのログ行末には「ブロック理由=禁止済み」「管理画面ユーザー=…」タグが付き、API パラメーターは `hideBanned=1`、`hideAdmin=1`（管理者セッションのみが対象で、読み取り専用アカウントは含みません。ブロックされたリクエストには管理画面ユーザーのタグは付きません） です
- Web サービスはサイト名またはドメイン、ステータスコード（`404`、`4xx`、`500-599`、複数はカンマ区切り）でも絞り込めます。WAF ファイアウォールはドメインで絞り込め、検知ログにはドメインとルール ID が記録されます

ログ内のソースや、行末の「サイト=…」「ドメイン=…」などのタグをクリックすると、その値で絞り込みます。Web サービスのログで「サイト=…」をクリックするとサイト名の完全一致で絞り込まれ、ツールバーに削除できる「サイト：…」タグが表示されます（API パラメーター `site`）。名前の似たサイトが混ざることはありません。API は `listener` パラメーター（リスナーのキー、完全一致）も受け付けます。2 つのリスナーが同じ名前のとき、ログのソース名には待ち受けアドレスが付きます（例: `HTTPS (0.0.0.0:443)` と `HTTPS ([::]:443)`）。名前が重複しないリスナーはそのままです。メモリ内のログで足りない場合、「以前のログを読み込む」はログファイルに残っている履歴（Web サービスの圧縮アーカイブを含み、期間で絞り込むと期間外のアーカイブは読み飛ばします）まで遡るため、ログの永続化を有効にしていれば絞り込める範囲は「ログ保持件数」に制限されません。`GET /api/logs` と `GET /api/<モジュール>/logs` も同じ絞り込みパラメーターに対応しています。[API リファレンス](/ja/docs/reference/api-reference)を参照してください。

### エクスポート {#log-export}

ログツールバーの「エクスポート」は、現在の絞り込み条件に一致するすべてのログを、ログファイルと圧縮アーカイブに残っている履歴も含めて古い順に書き出し、ブラウザーで直接ダウンロードします。

- CSV（表計算ソフト）：BOM 付き UTF-8 で、Excel でそのまま開けます。列は時刻、レベル、ソース、メッセージと、IP、ドメイン、サイト、ステータスコードなどのフィールドです。`=`、`+`、`-`、`@` で始まるセルには先頭に単一引用符を付け、訪問者が送ったパスを表計算ソフトが数式として実行するのを防ぎます
- JSON Lines：1 行に 1 件のログで、フィールドはログ API と同じです
- メッセージは画面の言語で出力されます。読み取り専用アカウントや読み取り権限だけの API トークンもエクスポートでき、表示時と同じくアドレス中のパスワードとトークンは伏せられます
- API は `GET /api/logs/export` と `GET /api/<モジュール>/logs/export` で、`format` に `csv` または `jsonl` を指定し、その他の絞り込みパラメーターはログの表示と同じです。ソース一覧の API は `GET /api/logs/sources` と `GET /api/<モジュール>/logs/sources` です
