# 設定と起動オプション

## コマンドラインオプション

| オプション | 説明 |
| --- | --- |
| `-c` | 設定ディレクトリ。環境変数 `GATELY_CONFIG_DIR` でも指定できます |
| `-listen` | 管理画面の待ち受けアドレスを上書きします。例：`:16680` |
| `-apply` | 宣言的設定のディレクトリ。環境変数 `GATELY_APPLY_DIR` でも指定できます。後述 |
| `-version` | バージョン情報を出力します |

| 環境変数 | 説明 |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | 初回起動時の管理者の初期パスワード（8 文字以上）。未設定の場合はデフォルトのパスワード `gately.cn` になります。アカウントが既に存在する場合は効果がありません |

## 設定ディレクトリ

すべての設定は設定ディレクトリに保存されます。モジュールごとに 1 つの `<name>.json` 平文ファイルで、アトミックに書き込まれ、ファイルのパーミッションは 0600 です。そのため次のことができます。

- テキストエディターでそのまま内容を確認できます
- ディレクトリを git に入れ、diff で変更を監査し、いつでもロールバックできます
- バックアップはディレクトリをコピーするだけで完了します

::: warning 注意
`ssl.json` には証明書の秘密鍵が含まれています。バージョン管理に入れる前に、リポジトリがプライベートであることを確認するか、このファイルを除外リストに追加してください。
:::

## 宣言的設定

`-apply <ディレクトリ>` を指定すると、起動するたびにそのディレクトリ内の `<名前>.json` を設定ディレクトリへ上書きします。内容が同じファイルは書き直しません。設定を git リポジトリ、Kubernetes の ConfigMap、デプロイスクリプトでまとめて配布する用途に向いています。

- 書き込む前に正しい JSON かを検証し、無効なファイルが 1 つでもあれば起動を拒否します
- `account.json` と `tokens.json` は上書きできません。アカウントとトークンは管理画面でのみ管理できます
- 上書きされた古い内容は [設定履歴](/ja/docs/guide/audit) に保存され、いつでもロールバックできます

## 外部プログラムのディレクトリ

Tailscale、frp、cloudflared、File Browser は公式の外部プログラムを管理し、次の順序で実行ファイルを探します。

1. モジュール設定に入力したパス
2. 設定ディレクトリ配下の `bin/` サブディレクトリ
3. `PATH`

各モジュールページからオンラインでインストール、更新、ロールバックできます。プログラムは `bin/` に、旧バージョンは `bin/.versions/` に保存されます。詳しくは [オンラインでのインストール・更新・ロールバック](/ja/docs/modules/tunnels#install) を参照してください。バイナリを自分で設定ディレクトリに置くこともできます（Docker でデプロイする場合の例：`./gately-data/bin/frpc`）。Tailscale には `tailscale` と `tailscaled` の両方が必要です。

## 実行ログ

システムと各モジュールの実行ログは、既定で設定ディレクトリの `logs/` に書き込まれます。再起動やアップグレードの後も「システムログ」と各モジュールのページで確認できます。

- 出力元ごとに 1 つの JSON Lines ファイル：`logs/<モジュール ID>.log`、システムログは `logs/gately.log`。起動時に「ログの保持行数」の分だけ最新のログをファイルから復元します
- 新しいログは最大 1 秒遅れてまとめて書き込まれます。ファイルが上限（既定 2 MB）を超えると `.1` にローテーションし、その 1 世代だけを残すため、出力元ごとの使用量は最大で上限の 2 倍です
- 「設定 → ネットワークと実行 → 実行パラメーター」で「ログを永続化」をオフにしたり「ログファイル上限」を変更したりでき、すぐに反映されます。オフにするとログはメモリ上にのみ保持され、再起動で消去されます
- 画面でモジュールのログを消去すると、対応するファイルも削除されます
- 設定のバックアップには `logs/` と操作監査ログ `audit.log` は含まれません

### 表示と絞り込み {#log-filter}

「システムログ」ページと各モジュールページ下部のログカードは同じログビューアーを使います。次の条件を組み合わせて絞り込めます。変更はすぐに反映され、新しいログも条件に一致するものだけが追加されます。

- レベルとソース（表示されたことのあるソースを選ぶか、直接入力）
- キーワード：スペース区切りはすべてを含む、二重引用符でフレーズ、先頭の `-` で除外（例：`GET "timeout" -debug`）。一致した部分は強調表示されます。画面が他の言語のときは、画面に表示される訳文で検索できます
- 「除外」：いずれかの語を含むログを非表示にし、キーワードと同時に適用されます。書き方はキーワードと同じ（スペース区切り、二重引用符でフレーズ）で、例：`debug "health check"`。`-` で始まる語そのものを除外するには `"-v"` のように二重引用符で囲みます
- 「詳細フィルター」の IP：完全なアドレス、範囲（`10.0.0.0/8` など）またはアドレスの一部。複数はカンマ区切り。IP が個別に記録されていないログは本文からアドレスを認識するため、ログイン失敗や侵入防御のログにも使えます。先頭に `!` または `-` を付けると除外になり、`!1.2.3.4, !10.0.0.0/8` でそれらの送信元を非表示にできます。含める項目と組み合わせることもできます（`10.0.0.0/8, !10.0.0.5`）
- 「詳細フィルター」の期間：過去 15 分から 7 日まで、または任意の開始・終了時刻
- Web サービスのツールバーには表示用のスイッチが 2 つあり、表示のみに影響します（ログは保存され、選択はブラウザーに記憶されます）。「禁止された送信元を隠す」は送信元が禁止されているため拒否されたリクエストを非表示にします（CDN の背後ではカーネルの禁止が CDN からの接続に効かず、禁止された訪問者は Web 層で拒否されて 403 / 444 の記録が残ります）。禁止のきっかけになったリクエストは表示されたままです。「管理画面のリクエストを隠す」はこのインスタンスの管理画面ログインセッションを持つリクエスト（Web サービスのサイト経由で管理画面を開いたときのログページのポーリングなど）を非表示にし、既定でオンです。これらのログ行末には「ブロック理由=禁止済み」「管理画面ユーザー=…」タグが付き、API パラメーターは `hideBanned=1`、`hideAdmin=1` です
- Web サービスはサイト名またはドメイン、ステータスコード（`404`、`4xx`、`500-599`、複数はカンマ区切り）でも絞り込めます。WAF ファイアウォールはドメインで絞り込め、検知ログにはドメインとルール ID が記録されます

ログ内のソースや、行末の「サイト=…」「ドメイン=…」などのタグをクリックすると、その値で絞り込みます。メモリ内のログで足りない場合、「以前のログを読み込む」はログファイルに残っている履歴まで遡るため、ログの永続化を有効にしていれば絞り込める範囲は「ログ保持件数」に制限されません。`GET /api/logs` と `GET /api/<モジュール>/logs` も同じ絞り込みパラメーターに対応しています。[API リファレンス](/ja/docs/reference/api-reference)を参照してください。

## バックアップと復元

「設定」には設定のバックアップと復元があり、Lucky の設定をインポートする入口でもあります。
