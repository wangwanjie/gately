# 設定と起動オプション

## コマンドラインオプション

| オプション | 説明 |
| --- | --- |
| `-c` | 設定ディレクトリ。環境変数 `GATELY_CONFIG_DIR` でも指定できます |
| `-listen` | 管理画面の待ち受けアドレスを上書きします。例：`:16680` |
| `-apply` | 宣言的設定のディレクトリ。環境変数 `GATELY_APPLY_DIR` でも指定できます。後述 |
| `-gateway-socket` | この Unix ソケットでも管理画面を提供します（fnOS 統合ゲートウェイなどで使用） |
| `-gateway-prefix` | ゲートウェイ経由でアクセスするときのパスのプレフィックス。例：`/app/gately` |
| `-api-docs` | API ドキュメント（`openapi.json` と `API.md`）を指定ディレクトリに書き出して終了します |
| `-version` | バージョン情報を出力します |

| 環境変数 | 説明 |
| --- | --- |
| `GATELY_INITIAL_PASSWORD` | 初回起動時の管理者の初期パスワード（8 文字以上）。未設定の場合はデフォルトのパスワード `gately.cn` になります。アカウントが既に存在する場合は効果がありません。10 文字未満または強度が不足している場合は、初回ログイン時に変更を求められます |
| `GATELY_LANG` | サーバー言語が「システムに従う」のときに最初に参照される言語コード。続いて `LC_ALL`、`LC_MESSAGES`、`LANG` の順に参照されます |
| `GATELY_LOG_LEVEL` | 記録する実行ログの最低レベル：`debug`、`info`、`warn`、`error`。設定の「ログレベル」が「デフォルト」のときに有効で、未設定の場合は `info` |

## 設定ディレクトリ

すべての設定は設定ディレクトリに保存されます。モジュールごとに 1 つの `<name>.json` 平文ファイルで、アトミックに書き込まれ、ファイルのパーミッションは 0600 です。そのため次のことができます。

- テキストエディターでそのまま内容を確認できます
- ディレクトリを git に入れ、diff で変更を監査し、いつでもロールバックできます
- バックアップはディレクトリをコピーするだけで完了します

::: warning 注意
`ssl.json` には証明書の秘密鍵が含まれています。バージョン管理に入れる前に、リポジトリがプライベートであることを確認するか、このファイルを除外リストに追加してください。
:::

「設定 → ネットワークと実行 → ストレージ使用量」には、設定ディレクトリがあるパーティションの容量、設定ディレクトリの合計サイズ、用途別の使用量（実行ログ、訪問者監査、操作監査ログ、設定履歴、設定バックアップ、防御データ、通知の再送キュー（`notify/`）、ネットワークデータ、IP リスト、証明書、GeoIP データベース、管理プログラム（`bin/`）、File Browser データ（`filebrowser/`）、設定ファイル（Docker Compose プロジェクト `compose/` を含む）、その他）が表示され、ディスクを何が占めているかを確認できます。サイズのみを集計し、シンボリックリンクはたどりません。「ログディレクトリ」が設定ディレクトリ外にある場合は別に表示し、設定ディレクトリの使用量には含めません。タブを開いたときに集計し、「更新」で再集計します。

## 宣言的設定

`-apply <ディレクトリ>` を指定すると、起動するたびにそのディレクトリ内の `<名前>.json` を設定ディレクトリへ上書きします。内容が同じファイルは書き直しません。設定を git リポジトリ、Kubernetes の ConfigMap、デプロイスクリプトでまとめて配布する用途に向いています。

- 書き込む前に正しい JSON かを検証し、無効なファイルが 1 つでもあれば起動を拒否します
- `account.json` と `tokens.json` は上書きできません。アカウントとトークンは管理画面でのみ管理できます
- 上書きされた古い内容は [設定履歴](/ja/docs/guide/audit) に保存され、いつでもロールバックできます

## 外部プログラムのディレクトリ

Tailscale、frp、cloudflared、File Browser は公式の外部プログラムを管理し、次の順序で実行ファイルを探します。

1. モジュール設定に入力したパス
2. 設定ディレクトリ配下の `bin/` サブディレクトリ
3. `PATH`

各モジュールページからオンラインでインストール、更新、ロールバックできます。プログラムは `bin/` に、旧バージョンは `bin/.versions/` に保存されます。詳しくは [オンラインでのインストール・更新・ロールバック](/ja/docs/modules/tunnels#install) を参照してください。バイナリを自分で設定ディレクトリに置くこともできます（Docker でデプロイする場合の例：`./gately-data/bin/frpc`）。Tailscale には `tailscale` と `tailscaled` の両方が必要です。

## 実行ログ

システムと各モジュールの実行ログは、既定で設定ディレクトリの `logs/` に書き込まれます。再起動やアップグレードの後も「システム → ログ」ページの「システムログ」タブと各モジュールのページで確認できます。

- 出力元ごとに 1 つの JSON Lines ファイル：`logs/<モジュール ID>.log`、システムログは `logs/gately.log`。起動時に「ログの保持行数」の分だけ最新のログをファイルから復元します
- 新しいログは最大 1 秒遅れてまとめて書き込まれます。ファイルが上限（既定 2 MB）を超えると `.1` にローテーションし、その 1 世代だけを残すため、出力元ごとの使用量は最大で上限の 2 倍です
- Web サービスのアクセスログは量が多く後から見返すことが多いため、日単位で別にアーカイブします。現在のファイルが日をまたぐ（または合計サイズの 4 分の 1、最大 16 MB を超える）と `logs/webservice.<開始時刻>.log` に名前を変え、バックグラウンドで `.log.gz` に圧縮します。「アクセスログ保持日数」（既定 7 日）と「アクセスログ合計サイズ (MB)」（現在のファイルとすべての圧縮アーカイブの合計、既定 32 MB、ログのあるパーティション容量の 5% まで）に従って古いアーカイブから削除します
- 各モジュールは現れたログの出力元を `logs/<モジュール ID>.sources` に記録し、再起動後も保持します
- 「設定 → ネットワークと実行 → 実行パラメーター」で「ログを永続化」をオフにしたり、「ログファイル上限」「アクセスログ保持日数」「アクセスログ合計サイズ (MB)」を変更したり、「ログディレクトリ」を別の絶対パス（外付けディスク上のディレクトリなど。存在しなければ Gately の実行ユーザーだけがアクセスできる状態で自動作成）に変えたりでき、すぐに反映されます。ログディレクトリを変更すると新しいログは新しいディレクトリに書き込まれ、元のディレクトリのファイルはそのまま残ります。永続化をオフにするとログはメモリ上にのみ保持され、再起動で消去されます
- 「ログレベル」は、どの実行ログを記録するかを決めます。デフォルトは「情報以上」で、デバッグレベルのログは記録されず、ログページ、ログファイル、標準エラー出力のいずれにも出力されません。ポート転送とプロトコル振り分けの接続ごとの記録、クライアントの切断、無関係なドメインの TLS ハンドシェイク失敗などはデバッグレベルです。確認したいときは「ログレベル」を「デバッグ以上（すべて）」に変更します。保存するとすぐに反映され、接続が多いと負荷が目立って増えます。Web サービスのアクセスログは情報レベルで、「警告以上」または「エラーのみ」にすると記録されなくなります。環境変数 `GATELY_LOG_LEVEL` でも指定でき、設定で具体的なレベルを選んだ場合は設定が優先されます
- 実行ログは標準エラー出力（`docker logs` や `journalctl` で見える内容）にもサーバー言語で出力されます。この出力はバックグラウンドでまとめて書き出され、プロセスの正常終了や再起動の前に書き終えます。標準エラー出力が詰まっているか遅く、未出力分が 1 MB を超えると、新しい行は破棄され、その行数を知らせる 1 行が出力されます。ログページとログファイルには影響しません。Docker の既定のログドライバーはコンテナログのサイズを制限しないため、デプロイ例 [docker-compose.yml](https://github.com/wangwanjie/gately/blob/main/deploy/docker-compose.yml) では `logging.options` の `max-size` と `max-file` で上限を設定しています
- 画面でモジュールのログを消去すると、対応するファイル、ローテーション済みファイル、圧縮アーカイブ、出力元の記録も削除されます
- 設定のバックアップには `logs/` と操作監査ログ `audit.log` は含まれません

### 表示と絞り込み {#log-filter}

「ログ」ページの「システムログ」タブと各モジュールページ下部のログカードは同じログビューアーを使います。次の条件を組み合わせて絞り込めます。変更はすぐに反映され、新しいログも条件に一致するものだけが追加されます。

- レベルとソース（ドロップダウンにはモジュール設定にあるすべてのソースとログに現れたソースが並びます。たとえば Web サービスのすべてのリスナーで、まだアクセスのないものやログがファイルにしかないものも含みます。直接入力も可能）
- キーワード：スペース区切りはすべてを含む、二重引用符でフレーズ、先頭の `-` で除外（例：`GET "timeout" -debug`）。一致した部分は強調表示されます。画面が他の言語のときは、画面に表示される訳文で検索できます
- 「除外」：いずれかの語を含むログを非表示にし、キーワードと同時に適用されます。書き方はキーワードと同じ（スペース区切り、二重引用符でフレーズ）で、例：`debug "health check"`。`-` で始まる語そのものを除外するには `"-v"` のように二重引用符で囲みます
- 「詳細フィルター」の IP：完全なアドレス、範囲（`10.0.0.0/8` など）またはアドレスの一部。複数はカンマ区切り。IP が個別に記録されていないログは本文からアドレスを認識するため、ログイン失敗や侵入防御のログにも使えます。先頭に `!` または `-` を付けると除外になり、`!1.2.3.4, !10.0.0.0/8` でそれらの送信元を非表示にできます。含める項目と組み合わせることもできます（`10.0.0.0/8, !10.0.0.5`）
- 「詳細フィルター」の期間：過去 15 分から 7 日まで、または任意の開始・終了時刻
- Web サービスのツールバーには表示用のスイッチが 2 つあり、表示のみに影響します（ログは保存され、選択はブラウザーに記憶されます）。「禁止された送信元を隠す」は送信元が禁止されているため拒否されたリクエストを非表示にします（CDN の背後ではカーネルの禁止が CDN からの接続に効かず、禁止された訪問者は Web 層で拒否されて 403 / 444 の記録が残ります）。現在も禁止中の送信元のリクエストは、禁止のきっかけになったものも含めてすべて非表示になります（禁止の解除または期限切れ後に再び表示されます）。「管理画面のリクエストを隠す」はこのインスタンスの管理画面ログインセッションを持つリクエスト（Web サービスのサイト経由で管理画面を開いたときのログページのポーリングなど）を非表示にし、既定でオンです。これらのログ行末には「ブロック理由=禁止済み」「管理画面ユーザー=…」タグが付き、API パラメーターは `hideBanned=1`、`hideAdmin=1`（管理者セッションのみが対象で、読み取り専用アカウントは含みません。ブロックされたリクエストには管理画面ユーザーのタグは付きません） です
- Web サービスはサイト名またはドメイン、ステータスコード（`404`、`4xx`、`500-599`、複数はカンマ区切り）でも絞り込めます。WAF ファイアウォールはドメインで絞り込め、検知ログにはドメインとルール ID が記録されます

ログ内のソースや、行末の「サイト=…」「ドメイン=…」などのタグをクリックすると、その値で絞り込みます。Web サービスのログで「サイト=…」をクリックするとサイト名の完全一致で絞り込まれ、ツールバーに削除できる「サイト：…」タグが表示されます（API パラメーター `site`）。名前の似たサイトが混ざることはありません。API は `listener` パラメーター（リスナーのキー、完全一致）も受け付けます。2 つのリスナーが同じ名前のとき、ログのソース名には待ち受けアドレスが付きます（例: `HTTPS (0.0.0.0:443)` と `HTTPS ([::]:443)`）。名前が重複しないリスナーはそのままです。メモリ内のログで足りない場合、「以前のログを読み込む」はログファイルに残っている履歴（Web サービスの圧縮アーカイブを含み、期間で絞り込むと期間外のアーカイブは読み飛ばします）まで遡るため、ログの永続化を有効にしていれば絞り込める範囲は「ログ保持件数」に制限されません。`GET /api/logs` と `GET /api/<モジュール>/logs` も同じ絞り込みパラメーターに対応しています。[API リファレンス](/ja/docs/reference/api-reference)を参照してください。

ログ領域の高さは変更できます。下のバーをドラッグ（タッチ画面では押したままドラッグ）し、バーのダブルクリックで既定の高さに戻します。バーにフォーカスがあるときは矢印キーでも調整できます。ページ内のログカードとサイトログのダイアログはそれぞれの高さを現在のブラウザーに別々に記憶します。ツールバー右端の全画面ボタンでログをウィンドウ全体に表示し、もう一度押すか Esc で終了します。履歴をさかのぼってスクロールしている間も新しいログは追加されますが、表示位置は下に戻されません。ログ領域の右下に「最新へ移動」が表示され、その間に届いたログの件数も示されます。下までスクロールするかボタンを押すと自動スクロールが再開します。

### エクスポート {#log-export}

ログツールバーの「エクスポート」は、現在の絞り込み条件に一致するすべてのログを、ログファイルと圧縮アーカイブに残っている履歴も含めて古い順に書き出し、ブラウザーで直接ダウンロードします。

- CSV（表計算ソフト）：BOM 付き UTF-8 で、Excel でそのまま開けます。列は時刻、レベル、ソース、メッセージと、IP、ドメイン、サイト、ステータスコードなどのフィールドです。`=`、`+`、`-`、`@` で始まるセルには先頭に単一引用符を付け、訪問者が送ったパスを表計算ソフトが数式として実行するのを防ぎます
- JSON Lines：1 行に 1 件のログで、フィールドはログ API と同じです
- メッセージは画面の言語で出力されます。読み取り専用アカウントや読み取り権限だけの API トークンもエクスポートでき、表示時と同じくアドレス中のパスワードとトークンは伏せられます
- API は `GET /api/logs/export` と `GET /api/<モジュール>/logs/export` で、`format` に `csv` または `jsonl` を指定し、その他の絞り込みパラメーターはログの表示と同じです。ソース一覧の API は `GET /api/logs/sources` と `GET /api/<モジュール>/logs/sources` です

## 保存後の確認と自動ロールバック {#confirm}

ドメイン経由でリモート管理しているとき、ポート転送・プロトコル振り分け・Web サービス・グローバル設定を変更すると、管理画面自身のアクセス経路が切れることがあります。そのため、これらを保存した後、管理画面は新しく張った接続でまだアクセスできるかを確認します：

- アクセスできればバックグラウンドで自動的に確認し、操作を妨げません；
- 確認できない場合はカウントダウンのダイアログを表示し、アクセスが戻れば自動的に確認されます。Gately にまだ接続できるときは「今すぐロールバック」を選べますが、接続できないときはその要求も届かないため、カウントダウン終了を待つか、サーバーで `gately rollback -pending` を実行します；
- 期限までに確認されなければ、Gately は再起動し、起動時に変更前の設定を復元します。変更後の版は[設定履歴](/ja/docs/guide/audit)に保存されます。サービス復旧後にページは自動で再読み込みされ、どの変更が戻されたかを表示します。

確認には WebSocket を使います。ブラウザーは必ず新しい接続を作るため、変更後の転送と待ち受けを通ります。変更前に張られた長い接続はホット更新後も古い宛先につながっており、新しい設定が使えることの証明になりません。

再起動後に有効になる設定（管理画面の待ち受けアドレス、機能モジュールのオン／オフ）は、管理画面から再起動したときに記録され、再起動後に計時を始めます。確認されないまま 3 回続けて起動した場合（新しい設定でプログラムが正常に動かないなど）もロールバックします。未確認の変更がある状態で新しいアドレスから管理画面を開くと、「変更を保持」か「今すぐロールバック」かを尋ねるダイアログが出ます。

期限は「設定 → アクセス制御 → 管理画面の待ち受け」の「保存後の確認」で変更でき（30～600 秒、既定 90 秒）、無効にもできます。管理画面からの保存にのみ適用され、API トークンやスクリプトによる変更は対象外です。API は `GET /api/system/confirm` です。

### 保存前の警告：現在のアクセス経路 {#access-path}

Gately は、管理画面へのアクセスが自身のどの転送を通っているかを識別できます。ポート転送とプロトコル振り分けはこのマシン上の宛先に接続するときにホップを記録し、Web サービスは管理画面へ中継するときに署名付きの経路情報を付けます（外部から偽造できません）。「設定 → アクセス制御」上部の「現在のアクセス経路」カードに、例えば `訪問者 → プロトコル振り分け「vps-443」 → Web サービス「main」 › サイト「admin.example.com」 → 管理画面` のように表示されます。frp や Cloudflare Tunnel などこのマシン上のプログラムは「このマシン」と表示されます。

保存の前に、管理画面はこの変更が経路に影響するかサーバーに確認します。影響する場合はダイアログで理由を示し、影響を受けるホップを強調します。キャンセルするか「それでも保存」を選べます：

- 経路上のルール・待ち受け・サイトの転送に関わる設定の変更（名前・グループ・備考だけの変更は対象外）、無効化や削除、サイトの別の待ち受けへの移動；
- 経路上のモジュールをオフにする（モジュールの全体スイッチまたは「機能モジュール」設定）；
- 使用中の管理画面の待ち受けアドレスの変更；
- 外部からアクセス中に「LAN のみ」をオン、HTTP でアクセス中に「HTTPS を強制」をオン。

警告とは別に、上記の確認と自動ロールバックはそのまま有効なので、Gately から見えない経路（さらに外側の別のリバースプロキシなど）も保護されます。API は `GET /api/system/access-path` と `POST /api/system/access-path/check` です。

### 一括変更：複数箇所をまとめて変える {#changeset}

複数箇所を一緒に変えないと使えない変更があります。例えば、プロトコル振り分けが Web サービスへ転送するポートを 18081 にし、さらに Web サービスの待ち受けも 18081 に移す場合です。最初の箇所だけ保存すると現在のアクセスが切れ、2 か所目を変更できなくなります。このときは一括変更を使います：

1. 保存前の警告で「保留して後でまとめて反映」を選ぶか、「設定 → アクセス制御」の「現在のアクセス経路」カードで「一括変更を開始」を押します；
2. 以降、ポート転送・プロトコル振り分け・Web サービスの保存は設定に書き込むだけです。ページには新しい内容が表示されますが、実行中のルールと待ち受けは変わらず、現在のアクセス経路を使い続けられます。ページ上部のバナーに保留中のルールと待ち受けが表示され、この間は保存前の警告は出ません；
3. すべて変更したらバナーの「すべて反映」を押します。保留した変更が保存順にまとめて反映され、単独の保存と同様に新しい接続で確認されます。確認できなければ一括変更を始める前の設定にまとめて戻ります；
4. 取りやめる場合は「変更を破棄」を押すと、一括変更を始める前の設定に戻して Gately を再起動します。

「すべて反映」の前に、Gately は保留中のルールと待ち受けの待ち受けアドレスがこのマシンで使えるかを確認し、使えないものがあればシステムの理由とともに示して判断を求めます。保存前の警告も、新しい待ち受けアドレスが使えないことを指摘します。反映後に確認できない場合やロールバックした場合は、その間にモジュールが報告したエラー（待ち受けの起動失敗など）をダイアログとロールバック通知に表示します。なお macOS の既定では 127.0.0.1 しか設定されていないため、127.0.0.2 などのループバックアドレスを使うには先に `sudo ifconfig lo0 alias 127.0.0.2` を実行してください。Linux では 127.0.0.0/8 全体がそのまま使えます。

グローバル設定の変更は一括変更の対象外で、これまでどおり即時に反映されます。一括変更中に Gately が再起動した場合は新しい設定で起動し、単独の保存と同様に計時して確認を待ちます。API は `POST /api/system/changeset/begin`、`/apply`、`/discard` です。

### コマンドラインからのロールバック {#rollback-cli}

管理画面にもうアクセスできない場合は、サーバーで `gately rollback` を実行します（Docker では `docker exec -it gately gately rollback`）。未確認の変更と最近の設定保存を一覧表示し、番号を入力して取り消せます。オプションも使えます：

| コマンド | 内容 |
| --- | --- |
| `gately rollback -list` | 一覧表示のみで変更しない |
| `gately rollback -last` | 直近の保存を取り消し、その設定を保存前の内容に戻す |
| `gately rollback -pending` | 未確認の設定変更を今すぐロールバック |
| `gately rollback -config portforward -version <バージョン>` | 設定を指定した履歴バージョンに戻す（バージョンは `-list` で確認） |

実行前に `yes` と入力して確認します（スクリプトでは `-y`）。Gately が実行中ならそれが処理して再起動し、実行していなければ設定ファイルを直接書き換えて次回起動時に有効になります。書き換え前の内容も[設定履歴](/ja/docs/guide/audit)に保存されるので、ロールバック自体も取り消せます。設定ディレクトリが既定の場所でない場合は `-c` で指定します。

## バックアップと復元

「設定」には設定のバックアップと復元があり、Lucky の設定をインポートする入口でもあります。

復元時に「現在の管理者アカウントを保持」（API パラメーター `keepAccount=1`）をオンにすると、バックアップ内の `account.json`、`tokens.json` とシステム設定のサードパーティログインは無視され、現在のアカウント、パスワード、2 段階認証、読み取り専用ユーザー、API トークン、管理画面のサードパーティログインはそのまま残り、その他の設定はバックアップから復元されます。`account.json` を含まないバックアップも復元できるため、別のインスタンスの設定を移すときに便利です。デフォルトパスワードのままの場合は復元が拒否されるので、先にパスワードを変更してください。
